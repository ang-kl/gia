## §0.9.0 NEW CONTENT

### 1. New modules

| File | Role |
| :--- | :--- |
| `vault.js` | Runtime Vault. `queryVault(redis, lat, lng, radius)` returns enriched hits sorted by distance. `verifyOpenNow(placeId)` calls Place Details with a tight FieldMask (`currentOpeningHours.openNow,businessStatus,googleMapsUri,rating`). `fetchOpenVaultPicks(redis, lat, lng, radius, count)` orchestrates both. |
| `sync-vault.js` | One-shot importer (CLI). Concurrency 5, exp backoff on 429/503/ETIMEDOUT (max 3). Hardcoded URL list at top of file (14 entries from Human Lead instruction). |

### 2. Redis schema (new keys)

| Key pattern | Type | Writer | Reader | TTL |
| :--- | :--- | :--- | :--- | :--- |
| `gia:vault` | sorted set (geo) | `sync-vault.js` `vaultUpsert` via `GEOADD` | `vault.js` `queryVault` via `GEOSEARCH FROMLONLAT BYRADIUS m ASC WITHCOORD WITHDIST` | none (curated permanent) |
| `gia:place:<placeId>` | hash | `sync-vault.js` `vaultUpsert` via `HSET` | `vault.js` `queryVault` via `HGETALL` | none |
| `gia:vault:cleanup` | list | `sync-vault.js` `logSkip` via `LPUSH` | manual: `LRANGE gia:vault:cleanup 0 -1` | none (audit log) |

### 3. Place Details FieldMask used

**Sync (`sync-vault.js fetchPlaceDetails`):**
```
id,businessStatus,regularOpeningHours,location,displayName,formattedAddress,primaryType
```

**Runtime open-now verify (`vault.js verifyOpenNow`):**
```
currentOpeningHours.openNow,businessStatus,googleMapsUri,rating
```

Tight masks per spec §1 to minimize cost/latency.

### 4. Concurrency control

`sync-vault.js withConcurrency(items, 5, worker)` is a hand-rolled semaphore (no `p-limit` dependency added). Five workers pull from a shared cursor; each worker awaits its task before claiming the next.

### 5. Retry / back-off

`sync-vault.js retry(fn, label)`:
- Max 3 attempts.
- Backoff `1000 ms × 2^attempt` (1s, 2s, 4s).
- Triggers on HTTP 429, 503, or `ETIMEDOUT` / `ECONNRESET`.
- Other errors propagate immediately.

### 6. Runtime decision tree (`index.js runFlow`)

```
runFlow(chatId, lat, lng, category):
    if category in {food, drink}:
        vaultPicks = fetchOpenVaultPicks(redis, lat, lng, 300, 3)
        if vaultPicks.length >= 3:
            deliverPicks(chatId, label, vaultPicks)
            return
    {meal, venues} = pickValidated(lat, lng, 3, [], {category})
    deliverPicks(chatId, meal.label, venues)
```

If Vault has <3 open hits OR a Vault query throws, the function falls through to `pickValidated` (the v0.8.1 fail-fast pipeline). No silent degradation: vault errors are logged with `[Vault] runtime query failed; falling through to pickValidated:`.

### 7. Cost / quota

| Path | Calls per `/eat` invocation | Approx cost |
| :--- | :--- | :--- |
| Vault hits ≥3 | 1 GEOSEARCH (free) + N Place Details (where N = vault hits, capped at 3) | ~$0.05 (3 × $0.017) |
| Vault hits <3 → fallback | 1 GEOSEARCH + (vault hit count) Place Details + 1 Gemini + up-to-5 Places searchText + 1 Routes Matrix | ~$0.10–0.15 worst case |
| Fallback only (`/groceries` or no vault hits) | 1 Gemini + 1-5 Places searchText + 1 Routes Matrix | ~$0.05 |

At single-user scale negligible. Documented for monitoring.
