## New

### [HDR] #200 | 22:30:00 SGT 16-05-26 | v0.60.232 — Build E 5e: real LTA line geometry — fetcher + /api/transport/line-paths + map rewire | 5 files | 1 PR | 1 build |

- **[INTENT]** PR #482 (Build E 5a) drew one polyline per line by ordering stations on their codes — straight station-to-station segments, not the real route shape. Operator chose "fetcher + replace polylines": ingest the LTA "MRT/LRT Line (GEOJSON)" dataset and have the Train TMA map draw its real geometry. Because this build environment cannot reach `api-open.data.gov.sg` (egress proxy `403`s every data.gov.sg host), the data file itself can't be produced here — so the rewire is built to **fall back** to the v0.60.230 derived polylines whenever the real geometry is absent. No regression today; the real shape lights up the moment `data/mrt-line-paths.json` is committed.

- **[DELTA]**
  - **`scripts/fetch-mrt-lines.js`** — NEW one-shot fetcher (sibling of `scripts/fetch-station-exits.js`). data.gov.sg `poll-download` flow (retries while `code !== 0`), parses `LineString` / `MultiLineString` geometry, reads attributes from flat properties *and* the HTML `<table>` in `properties.Description`, and maps each feature to a soleat line code (`NSL`/`EWL`/…) by name substring → explicit code token → LTA hex-palette fallback. Output `data/mrt-line-paths.json` — `{ "_meta": {...}, "<LINECODE>": [ [ {lat,lng}, ... ], ... ] }`. Flags: `--dry`, `--from-file`, `--raw-out`.
  - **`web/transport/src/data/line-paths.js`** — NEW exported `resolveLinePaths(fetched, stations)`: returns the fetched LTA geometry when it's present and has at least one well-formed segment (≥2 finite points), else `buildLinePaths(stations)`. `_meta` and malformed segments are stripped.
  - **`index.js`** — NEW `GET /api/transport/line-paths`. Reads `data/mrt-line-paths.json` once at boot, caches, serves `{ paths }`. A missing file (`ENOENT`) is not an error — it returns `{ paths: null }` so the TMA falls back. Sits directly after `/api/transport/stations`, mirroring its cache pattern.
  - **`web/transport/src/components/MrtMapPanel.jsx`** — fetches `/api/transport/line-paths` once into `linePathsRef` + `linePaths` state (best-effort; any failure leaves it null). `renderPolylines` now calls `resolveLinePaths(linePathsRef.current, list)` instead of `buildLinePaths(list)`; the render effect gains `linePaths` as a dependency so the polylines redraw when the geometry arrives.
  - **`__tests__/transport-line-paths.test.js`** — +4 tests for `resolveLinePaths`: uses fetched geometry when valid (and strips `_meta`), falls back on null, falls back when no usable segments, drops malformed segments while keeping valid lines.
  - `package.json` `0.60.231 → 0.60.232`; this Journal entry (#200); `doc/.serial-state.yml` bumped + re-anchored.
