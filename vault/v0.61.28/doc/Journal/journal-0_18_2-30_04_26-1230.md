## New

### [HDR] #28 | 12:30:00 SGT 30-04-26 | v0.18.2 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead doc upload — switch real-time weather endpoints to data.gov.sg v2 (`api-open.data.gov.sg/v2/real-time/api`), enrich `/weather` reply with humidity / rain / wind, update `/ver` probe to hit the v2 endpoint.
- **[DELTA]**
  - **`weather.js`** — full rewrite of fetcher layer:
    - Generic `fetchV2Realtime(endpointPath)` handles the v2 response shape (`{code, errorMsg, data: {stations, readings, readingType, readingUnit}}`).
    - Five v2 endpoints called in parallel: `/air-temperature`, `/rainfall`, `/relative-humidity`, `/wind-direction`, `/wind-speed`.
    - 2-hour forecast still on v1 (`api.data.gov.sg/v1/environment/2-hour-weather-forecast`) since v2 spec for forecast wasn't in the upload.
    - All calls send `x-api-key` header when `DATA_GOV_SG_API_KEY` is set.
    - `summary(lat, lng)` returns 12 fields: temp, humidity, rain, wind dir, wind speed, plus station names, plus the existing forecast triplet, plus timestamp.
    - `Promise.allSettled` so one endpoint failing doesn't kill the rest.
  - **`index.js runWeatherCommand`** — chat reply now multi-line:
    ```
    ☀️ Singapore weather
    Temp: 28.4°C @ Marina Gardens Drive
    Humidity: 78% @ Newton
    Rain: 0.4 mm @ Pasir Panjang
    Wind: 6 kt, 270°
    Next 2h in Outram: Light Rain (until 14:00)
    ```
    Lines only render when their reading is present + finite; absent fields silently skipped.
  - **`ver.js`** — `checkDataGov` now calls v2 `/air-temperature` endpoint instead of v1. Note text `"NEA v2 ok (auth)"` / `"NEA v2 ok (no key)"`.
  - **`package.json`** — version → 0.18.2.
- **[NOTE ON v2 BASE]** v2 spec uses **`api-open.data.gov.sg`** (not `api-production`). The dashboard guide we earlier saw (`api-production`) appears to be a different surface — possibly the metadata catalogue. Real-time data lives at `api-open` per the OpenAPI specs in `data/gov_sg/`.
- **[RISK]** Low–Medium —
  - **5 → 6 outbound calls per `/weather`** (5 v2 + 1 v1 forecast). All <500 ms typical. `Promise.allSettled` isolates failures.
  - v2 endpoints are documented as having **rate limits**, with the `x-api-key` header bumping the per-key tier. At single-user scale unlikely to hit.
  - 2-hour forecast still on v1; if NEA deprecates the v1 environment endpoints, that single line will fall through silently and the rest of the `/weather` reply still renders.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. `/ver` → `🟢 data.gov.sg ... NEA v2 ok (auth)` (with key) or `... NEA v2 ok (no key)` (without).
  2. `/weather` from CBD → multi-line reply with temp/humidity/rain/wind/forecast.
  3. If any single v2 endpoint times out → that line is omitted; rest still renders.
- **[NEXT]** When the v2 2-hour-forecast spec is uploaded to `data/gov_sg/`, swap the v1 forecast call. Tranche B remainder unchanged.
