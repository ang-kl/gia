- **[INTENT]** The Michelin hint was national-only ("N more to explore (M in total)"). When the user picks a city (e.g. Seoul), the hint should lead with that city's remaining count and give the national list as context. Also: v0.61.350 added a country-aware `michelinSummary.label` but never wired it into the TMA's `michelinRemaining` state, so the subtitle was still showing the static "Michelin Singapore 2025" — fixed here.

- **[MECHANISM]**
  - **City resolution:** the handler maps `searchCenter` → a curated city via `place-search-variance.nearestCityForAnchor` (distance-guarded **≤ 25 km**, and the resolved city must actually appear in this country's pool) → `michSelectedCity`. SG and no-match cases skip it.
  - **City-first ordering:** when a city resolves, the tier-ordered country pool is reordered so the city's venues come first (tier order preserved within the city block + the remainder). The walk/slice then surfaces the city's venues first — so "Explore N more in <City>" is meaningful.
  - **Counts:** after `recordWalk`, `cityRemaining` = (city venues in the pool) − (city venues already seen + served this batch); `total` = the national pool size. The handler returns `michelinSummary.{city, cityRemaining, countryName, countryFlag}` (flag derived from the ISO-2 via regional-indicator codepoints).
  - **TMA hint:** App.jsx builds `📚 Explore {cityRemaining} more in {city} · {total} across {flag} {country}` (en/fr) when the city fields are present, else the national hint. `setMichelinRemaining` now carries `label` + the city fields (the v0.61.350 fix).
