- **[ROOT CAUSE]** Places `searchText` `regionCode` only **biases**, it does not **restrict**. For a
  short name in a low-Google-coverage country (China especially), the best text match was a
  data-rich SG/MY venue, not the real overseas one. Verified live (Places by-id): `kr-sel-subaru`
  → "Subaru Leng Kee Showroom" (SG car dealer), `tw-new-taipei-shang-hao` → a SG kopitiam, etc.

- **[DELTA — `scripts/build-michelin-meta.mjs`]**
  - **`locationBias`** a 50 km circle around the venue's **city centroid** (`city-centroids.js`;
    geocode-once fallback for the 11 uncovered CN/TW cities) — soft pull toward the right metro.
  - **HARD GEO GUARD**: reject any match **outside the venue's country bbox** OR **>150 km from the
    city centroid** → returns `null` (unresolved) instead of storing a wrong placeId. *Better blank
    than wrong.* Logs every rejection (`✗ … rejected — match "X" … outside <CC> bbox` / `Nkm from
    <city>`). The 150 km / wide-bbox thresholds never false-reject a same-metro venue (the leaks
    were 250–13,000 km away).
  - **`--countries=CC,…`** and **`--ids=…`** flags run in **MERGE mode**: load the existing snapshot,
    re-resolve only the selected ids, keep everything else, and **purge** entries that now fail the
    guard. Lets us fix CN/KR/TW without re-spending on the good ~1,800.

- **[DELTA — `michelin-meta.json`]** Re-ran `--countries=CN,KR,TW` (788 venues, merge): **resolved
