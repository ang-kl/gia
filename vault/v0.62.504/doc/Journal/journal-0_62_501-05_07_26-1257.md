# Journal — soleat v0.62.501 (all TMAs: prefer DEVICE locale over Telegram-APP locale) — French-on-Samsung locale fix

> Operator: a French native user on a Samsung S22 sees English pills/wording across different TMAs — "why? investigate first". After the trace, chose fix 1: "prefer navigator.language when supported; treat language_code as a weak hint".
> Read as: the app should follow the PHONE's language, not the Telegram app's UI language.

## New

### [HDR] #855 | 12:57 SGT 05-07-26 | v0.62.501 — device-locale precedence across 5 TMAs | 5 web files + 3 doc/meta | PR #(pending) |

- **[INTENT].** French user, French phone, **English Telegram app** → all Mini Apps showed English.

- **[ROOT CAUSE] (traced, shared by all 5 TMAs).** `getActiveLocale` precedence was
  `localStorage 'gia.locale'` → **Telegram app `language_code`** → `navigator.language` → `'en'`,
  short-circuiting on the first truthy SUPPORTED hit. `initDataUnsafe.user.language_code` is the
  Telegram **client UI** language, *not* the phone's language. A French user whose Telegram app is
  English sends `language_code: "en"`, so the `||` chain stopped at `"en"` and **never consulted**
  `navigator.language` (`fr-FR` → `fr`). The region-tag hypothesis was **refuted** — every resolver
  already `slice(0,2)`-normalises `fr-FR`→`fr` and `'fr'` is in every SUPPORTED set. Pure precedence.
  - **Amplifier checked + cleared:** `GET /api/cuisine/user-language` uses `getUserLang` (explicit-only,
    returns `null` when unset), **not** `resolveLang`, so `hydrateFromServerOnce` cannot clobber the
    device detection — **no server change needed**.

- **[DELTA] (5 code files, `getActiveLocale` only).** Prefer the **device** locale over the **Telegram
  app** locale, keeping the supported-or-skip fall-through (an unsupported device locale still falls
  back to the Telegram hint, then `'en'`).
  - `web/cuisine/src/v2/lib/i18n.js`, `web/menu/src/i18n.js`, `web/transport/src/i18n.js`:
    `detectFromTelegram() || detectFromNavigator()` → `detectFromNavigator() || detectFromTelegram()`.
  - `web/hawker/src/i18n.js`: inline `navigator` block moved **above** the Telegram block.
  - `web/clipboard/src/lib/i18n.js`: reads `navigator` directly (supported-check) **before** the
    Telegram-first `getLanguage()` fallback.
  - `localStorage 'gia.locale'` (explicit in-app toggle pick) stays **highest** in every TMA.

- **[VERIFICATION (sandbox)]** `node --check` clean on all 5; cuisine+menu+hawker+transport TMA build in CI.

- **[STATUS]** PROD — all TMAs redeploy on merge (Railway).

- **[TEST]** `node --check` + TMA build via CI (behavioural precedence change; no unit harness for detection).

- **[KNOWN GAPS]** Trade-off (accepted with fix 1): a user on an English phone who deliberately set their
  **Telegram** app to French now gets English UI on first load — they can pick French via the in-app 🌐
  toggle (persists to `gia.locale`, wins thereafter). Standing: MRT CCL6 flip (task #17, 12 Jul);
  `index.js:5739` hard-coded-SGT bot line.
