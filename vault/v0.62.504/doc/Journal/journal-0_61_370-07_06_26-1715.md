### [HDR] #570 | 17:15 SGT 07-06-26 | v0.61.370 — SG tiles gated by coords, not stale region | 1 code file | 1 PR | 1 build |

- **[INTENT]** Re-enable the SG-only tiles (Hawker / Train / Incidents / Bus stops / Weather) when the anchor is actually in Singapore, even if the stored region is a stale `OTHER` from a prior overseas session.

- **[ROOT CAUSE]** The tile gating (`isMy` + `regionUnresolved`) trusted the **stored** `anchor.region`. A Bukit Merah anchor carrying a stale `region='OTHER'` (leftover from Hanoi) made `isMy` true → the SG tiles greyed, even though the coords are in SG. Same stale-data root as the v0.61.369 flag.

- **[MECHANISM]** (`web/menu/src/App.jsx`) — new `anchorInSG = coordsToCountry(anchor) === 'SG'`. `isMy` is now `anchor && !anchorInSG && (region JB|MY-PUT|OTHER)`; `regionUnresolved` is now `anchorLoading || (anchor && !anchor.region && !anchorInSG)`. A coords-in-SG anchor therefore overrides both disables. Coords are the ground truth — same principle as the flag fix.

- **[SAFETY]** Stateless / display-only: `isMy` + `regionUnresolved` are used **only** for the tile + `TrainPanel` disable styling (App.jsx 698 / 699 / 726). **No** search, persistence, or state change — a reactive region-reconciliation effect was deliberately avoided after today's gate-timer churn lessons (v0.61.365–368).
