## New

### [HDR] #407 | 14:45 SGT 28-05-28 | v0.61.206 — coarse-gate region stamp at setUserLocation (+ defensive read) | 4 files | 1 PR | 1 build |

- **[INTENT]** End the "device-GPS bypass" variant of the region
  auto-flip bug. Any anchor outside the 120 km SG coarse gate
  ends up cached with `region: 'OTHER'` regardless of how it was
  set (share-pin / quick-pick / chat /location / TMA pick).

- **[DELTA]**

  - **`location-cache.js setUserLocation`** (~15 lines added):
    after the existing payload build, if no `region` was passed
    AND the coarse gate trips (`!coarseGate({ lat, lng })`),
    stamp `payload.region = 'OTHER'` and
    `payload.regionInferredFromCoords = true`. The require for
    `./location-mode` is lazy + wrapped in try/catch so a hot
    path that fails to load the module silently skips the stamp
    (matches the existing defensive style).

    ```js
    if (!payload.region && Number.isFinite(lat) && Number.isFinite(lng)) {
      try {
        const { coarseGate } = require('./location-mode');
        if (!coarseGate({ lat, lng })) {
          payload.region = 'OTHER';
          payload.regionInferredFromCoords = true;
        }
      } catch { /* non-fatal */ }
    }
    ```

  - **`index.js` GET `/api/cuisine/user-location`** (~15 lines):
    when the cached anchor has no `region` field (legacy anchors
    written before v0.61.206 and still within the 24h TTL), the
    response runs the same coarse-gate check and sets
    `payload.region = 'OTHER'` + `payload.regionInferred: true`.
    Distinct flag name from the write-time
    `regionInferredFromCoords` so analytics can see which path
    fired. The TMA's existing v0.61.203 auto-flip then picks
    this up via the same code path that handles explicit
    region writes.

  - **`package.json`** — `0.61.205 → 0.61.206`.
  - **`doc/.serial-state.yml`** — commit 418 → 419, build 208 →
    209, journal 406 → 407; re-anchored 28-05 '26 14:45 SGT.

- **Decision: only stamp OUTSIDE the gate.** Anchors INSIDE
  the 120 km gate are SG/JB ambiguous from coords alone. Stamping
  them as SG by default would be wrong for JB pins (Johor Bahru
  is well within 120 km of SG centroid). Distinguishing SG↔JB
  requires a reverse-geocode call (~$0.005 each) which we can't
  afford to pay on every share-pin. The v0.61.157 drift-prompt
  already covers that case at chat time when the user's stored
  location changes meaningfully.

## Amendments

- **`setUserLocation(redis, chatId, lat, lng, opts)`** — was: if
  no region opt was passed, the cached payload had no region
  field. Now: also runs the coarse gate and stamps `'OTHER'`
  + `regionInferredFromCoords: true` when the gate trips.
- **`/api/cuisine/user-location` payload builder** — was:
  `if (cached.region) payload.region = cached.region;` then move
  on. Now: same plus an `else` branch that runs the coarse gate
  on the cached coords for legacy unstamped anchors. Sets
  `payload.region` + `payload.regionInferred: true` when the
  gate trips.
