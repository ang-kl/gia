  - **23** cite `https://vertexaisearch.cloud.google.com/grounding-api-redirect/…`

- **New `scripts/curate-dish-sources.mjs`** — walks the existing overlay,
  classifies each `source` field as `broken` / `weak` / `banned` / `unknown`
  / `ok-tier1` / `ok-tier2` / `ok-wiki`, and re-curates the bad ones via
  Gemini grounded with Google Search. The grounding prompt enforces a strict
  tier order:
  - **Tier 1 (best)** — official tourism boards: `visitsingapore.com`,
    `stb.gov.sg`, `malaysia.travel`, `jnto.go.jp`,
    `english.visitkorea.or.kr`, `tourismthailand.org`,
    `discoverhongkong.com`, `macaotourism.gov.mo`, `vietnam.travel`,
    `wonderfulindonesia.com`/`indonesia.travel`, `philippines.travel`,
    `taiwan.net.tw`, `tourism.australia.com`, `newzealand.com`.
  - **Tier 2 (good)** — authorised food-media / encyclopedia / archive:
    `guide.michelin.com`, `tasteatlas.com`, `gastroobscura.com`,
    `atlasobscura.com`, `eater.com`, `bbcgoodfood.com`, `britannica.com`,
    `eresources.nlb.gov.sg`/`nlb.gov.sg`, `scmp.com`, `straitstimes.com`,
    `channelnewsasia.com`, `nytimes.com`, `theguardian.com`,
    `seriouseats.com`.
  - **Tier 3 (fallback)** — `en.wikipedia.org` only with a concrete article
    URL (no soft-redirects, no disambiguation pages).
  - Banned list explicitly forbids: youtube, facebook, quora, reddit,
    steemit, pinterest, tiktok, instagram, lemon8, blogspot, wordpress,
    blog (any path), grokipedia, AND any `vertexaisearch…grounding-redirect`
    URL (post-filter backstop in case the model emits one).
  - The dish **explanation** (`note.en`) is preserved verbatim — only
    `source` is rewritten — so re-curation is safe to run after the English
    copy has been operator-reviewed.
  - **Idempotent**: entries already on a tier-1/2/wiki host are left alone.
  - **Modes**: `SAMPLE=N` dry-run (no API call, no write — prints first N
    classifier candidates), `REGION=<slug>` filter (e.g. `REGION=singaporean`
    restricts to one cuisine), `CURATE_BATCH_SIZE=6`, `CURATE_MAX_BATCHES=8`.
  - **Test seam**: `curateBatch(apiKey, batch, _fetchFn)` — unit tests pass a
    stub instead of `global.fetch`, so no key + no network needed at test time.

- **New `__tests__/curate-dish-sources.test.js`** (21 tests):
  - `classifySource` — broken (vertexaisearch redirect), banned by name
    (Grokipedia, blog), banned by host (youtube/facebook/reddit/pinterest/
    tiktok), weak (empty, bare label), tier-1 (5 tourism boards), tier-2
    (5 food-media), tier-3 wiki, unknown food-blog URL.
  - `buildWorkList` — picks up broken/weak/banned/unknown, skips
    ok-tier1/2/wiki, skips entries with empty notes, region prefix filter
    is case-insensitive and only matches the exact `slug::` anchor.
  - `curateBatch` — clean response → returns `{source}` per key; post-filter
    backstop drops banned URL, drops vertexaisearch redirect, drops bare
    label, drops non-URL; cascades to next model on HTTP 404; throws when
    entire chain fails.
  - `serialize` — sorted keys, entries-count header, round-trips via
    `Function`-eval of the emitted CJS.

- **Codex P2 findings folded in before merge** (chatgpt-codex-connector[bot]
  on PR #1429):
  - **scripts/curate-dish-sources.mjs:269** — post-filter now gates on
    `classifySource(source) ∈ {ok-tier1, ok-tier2, ok-wiki}`, not just
    "not banned / not broken / is a URL". An off-tier URL (e.g.
    `diversivore.com`) the model occasionally grounds on would otherwise
    be classified `unknown` AND written back — then the next run would
    re-classify it as `unknown` and try to re-curate it again, a
    non-convergent loop. Two new tests cover (a) off-tier-URL is dropped
    and (b) ok-wiki URL is accepted as the tier-3 fallback.
  - **.github/workflows/curate-dish-sources.yml:70** — push step now
    appends to an existing `bot/curate-dish-sources` branch instead of
    `git checkout -B` + force-pushing it. The "iterate region-by-region;
    each dispatch produces one reviewable PR" recommended flow only worked
    if every prior PR was merged before the next dispatch — otherwise the
    force-push wiped the prior batch. New step uses
    `git ls-remote --exit-code --heads` to detect the existing branch,
    fetches it, and replays this run's overlay on top so batches stack.
