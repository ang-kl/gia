- **[F1 — device key shadowed /rating (CONFIRMED)]** The chat `/rating` wrote only `rating-pref:<chatId>` while the TMA GET + the search floor seam read the **365-day `:dev:` key first** — one TMA Save permanently shadowed every later chat-side `/rating` change on that device. **Fix:** the per-device layer (copied from country-pref in v0.61.426) is **removed**; rating is a per-CHAT preference, one chat-level key serves every surface; old `:dev:` keys are no longer read and age out via TTL.

- **[F9 — Redis-down default marked authoritative (CONFIRMED)]** `getUserRatingPref` swallowed Redis errors and returned `'3.7'`, so GET `/api/cuisine/rating-pref` answered **200 {ratingPref:'3.7'}** during an outage → the TMA set `ratingLoaded=true` and forwarded the default on every search, overriding the user's real pref after Redis recovered. **Fix:** Redis **operation errors now propagate** (a genuinely-unset key still returns the authoritative default) → the GET route 500s → `fetchRatingPref` returns null → `ratingLoaded` stays false. The bot/search seams catch locally and default — delivery never blocks.

- **[F4 — criteria hash excluded the rating mode (CONFIRMED)]** All three `computeCriteriaHash` call sites shared one seen-set across rating modes; 'No rating' searches (whose guarded fallback can serve established venues) burned placeIds into the bucket a later ≥3.7 search read — pagination pollution, lost first-batch behaviour, phantom `exhausted`. **Fix:** the route resolves **`effRatingPref` once up front** (request override → Redis → guarded default), includes it in the hash (`ratingPref` field — each mode gets its own bucket), and reuses it at the floor seam (second Redis read removed). Deploy note: adding the field rotates all existing hash buckets once (12 h TTL — harmless).

- **[F3 — free-text marked pre-floor venues as seen (CONFIRMED)]** `deliverPicks` floors internally but returned nothing; the free-text caller `addSeen`'d the whole pre-floor batch and computed `exhausted` from it — venues the user never saw were permanently hidden from "🔍 Search for more". **Fix:** `deliverPicks` **returns the delivered (post-floor) picks** (`[]` on the no-results path); the free-text caller marks only those as seen, and `exhausted` uses the pre-floor **fetch** count (a floor drop ≠ a dry pool).

- **[F8 — pref ignored on nl-query / warm-start / fan-outs (sweep)]** The floor lived only in `deliverPicks` + `/api/cuisine/search`, while `/rating`'s reply claims "applies to every eatery search". **Fix:** new shared **`applyChatRatingFloor(chatId, venues, label)`** seam (also de-duplicates the read-pref/apply/log block — review cleanup); wired into:
