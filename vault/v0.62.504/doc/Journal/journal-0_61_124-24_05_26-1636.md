    `{ kind: 'precinct', name, lat, lng, radius: 600, source: 'stb-precinct', precinctId, polygon }`

    `runNearbyAlternatives` can do polygon-based exclusion. New
    ladder order: precinct → MRT → hawker → geocoded. (Item 2.)

      (Items 1 + 7 prerequisite.)
    - `/api/cuisine/search` (~10612) — reads cached location, clamps
      `searchRadius` to `cached.radiusCapM`. Logs
      `[Cuisine-TMA] D777 clamping radius <X>m → <cap>m`. (Item 1.)

      SG-default 20 km / JB-default 30 km. (Item 1.)

      - "showing X of Y" copy when `shown < total`, falling back to
        the existing `"found N"` when the full set fits. (Item 4.)

        when present. (Item 2 prerequisite.)

      - Polygon exclusion when `anchor.polygon` is set

      - Header + empty-state copy switch to `place.outsideHeader` /

      (Item 2.)
    - `locpick:` callback (~2232) — appends a follow-up message with
      `🔍 See eateries here` inline button (callback_data
      `locsearch:<precinctId>`). (Item 6.)

## Amendments

### Amends journal #322 (v0.61.121) — "outside the zone" + count format + auto-suggest

The v0.61.121 entry (`runPlaceAnchoredSearch` + `runNearbyAlternatives`
+ inline-button nearby fan-out) listed three deferrals in `[KNOWN
GAPS]`:

> *"`"better outside the precinct"` polygon exclusion not yet wired
> — the nearby button uses a wider radius without excluding in-zone
> venues."*
>
> *"`"# of #"` count format (operator spec) not in this entry —
> header reads `"found N eateries here"`, not `"showing X of Y
> eateries"`."*
>
> *"No auto-suggest when the place is weak; opt-in button only."*

**Amendment (v0.61.124, № 325):** all three closed. Polygon exclusion
fires when `anchor.polygon` is set (STB precinct anchors only — the
helper was added in v0.61.122 but not consumed until now); count
format switches to `"showing X of Y"` when `shown < total`; auto-
suggest fires when `total < 5 OR avgRating < 4.0` (≥ 3 ratings).
The original `[KNOWN GAPS]` lines stand as a record of what was
deferred; this entry corrects forward per Recipe AU-7.

### Amends journal #323 (v0.61.122) — Cuisine TMA region/cap + outside-zone exclusion

The v0.61.122 entry (precincts.js + `/location` quick-picks) listed
two deferrals:

> *"Cuisine TMA does NOT yet honour `cached.region` or
> `cached.radiusCapM` — picking JB in chat doesn't auto-flip the
> TMA's region toggle nor clamp `/api/cuisine/search`."*
>
> *"'Outside the zone' exclusion using the retained STB polygons
> not yet wired."*

**Amendment (v0.61.124, № 325):** both closed.
`/api/cuisine/user-location` now surfaces `region` + `radiusCapM`;
`/api/cuisine/search` + `/warm-start` clamp the radius; the Cuisine
TMA's `tryServerCache` auto-flips `state.region` to `'JB'` when the
cached anchor is JB/MY-PUT. Outside-the-zone exclusion wired via
`anchor.polygon` flowing through `runPlaceAnchoredSearch` →
`runNearbyAlternatives`.

### Amends journal #324 (v0.61.123) — Menu TMA autocomplete + disabled-tiles note

The v0.61.123 entry listed two deferrals:

> *"LocationFieldMenu free-text has NO autocomplete; just text →
> geocode."*
>
> *"Anchor summary doesn't mention which tiles got disabled."*

**Amendment (v0.61.124, № 325):** both closed. LocationFieldMenu
gained debounced Google Places Autocomplete via the existing
`/api/cuisine/place-autocomplete` endpoint; summary appends

`' (Hawker, Train, Incidents, Arrêts de bus, Météo désactivés)'` (fr)
when the anchor's region is `'JB'` or `'MY-PUT'`.
