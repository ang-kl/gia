## 1. Disclaimer (user-facing copy in `/legal`)

> _(reproduced verbatim from `legal-0_58_45-05_05_26-1200.md` — see §7 for the v0.60.132 amendment that extends it)_

> **soleat is a personal, non-commercial side project run from Singapore.** It surfaces public data (Google Places, LTA DataMall, NEA, data.gov.sg) and AI-mediated content (Anthropic Claude, Google Gemini) inside Telegram for **informational use only**. Listings, ratings, opening hours, and award statuses can be wrong, stale, or fabricated by the underlying LLMs despite our verification rules — please confirm critical details (open/close, halal certification, dietary safety) directly with the venue before acting. soleat does not collect, sell, or share personal data; see `/privacy` for retention. soleat is not affiliated with Google, Anthropic, the Singapore Government, or any of the rating bodies it references. Use at your own risk.

## 3. Jurisdiction & Privacy

> _(reproduced verbatim from `legal-0_58_45-05_05_26-1200.md`; the v0.60.132 addition — the identity-free free-text search-term log — is appended as the final bullet of this section and cross-referenced in §7.)_

- **Jurisdiction:** Singapore. Bot serves SG-specific data sets and complies with Singapore-side terms (LTA / NEA data licences, HDB carpark licence, IMDA Model AI Governance Framework alignment for AI-mediated output).
- **PDPA Section 13(c) / GDPR Article 17 alignment:** users can wipe every chatId-keyed Redis entry on demand via `/forgetme`. Returns a deletion summary so the user has a record.
- **No personal data sent to third parties.** Chat IDs are sha256-hashed before being used as Redis keys for location / processing state. Telegram user IDs are visible only to the LLM providers when their APIs are called, and only as the bot's own request initiator (not as user attribution).
- **AI-mediated content disclaimers:**
  - `/hidden` results are generated by Google Gemini with Google Search grounding. Despite explicit "do not fabricate" prompt rules + post-process safeguards (e.g. `rewriteFabricatedPlaceUrls` rejects fabricated Place IDs), the model can still return inaccurate or stale facts about restaurants, opening hours, or social-media coverage. Verify before acting.
  - Tell-Gia (cuisine NL) uses Anthropic Claude to map free-text to cuisine slugs. Misclassifications happen; the user can always pick cuisines manually in the TMA.
  - `/recognised` award lists are LLM-fetched (Anthropic Claude) and grounded with web search; year-scoped and 24 h cached. Authoritative source remains the original award body's website.
- **Free-text search-term log (added v0.60.131; retention raised to 90 days v0.60.132).** The food / dish / cuisine words a user types into chat free-text or the Cuisine Mini App's "Tell me" box are recorded in Redis (`freetext:log` — a capped list of the last 5 000 entries; `freetext:log:<YYYY-MM-DD>` — per-day lists) **with no chat ID, Telegram user ID, or any other user identifier** — each entry is `{ q (search text, ≤ 80 chars), ts, src ('chat' | 'cuisine-tma'), chip (was a cuisine chip active), m (which guard/table matched, if any), n (result count) }`. It is a corpus of *what is searched*, never *who searched*. Purpose: extend the misrepresented-dish / cooking-method / dessert-drink reference tables, tune the question-shaped-query guard, and surface recurring search failures. **Not exported off-platform; sent to no third party; not covered by `/forgetme`** (there is nothing chatId-keyed to delete — by construction it holds no identity). Both the capped list and the per-day lists carry a 90-day Redis TTL refreshed on each write, so the corpus self-clears after 90 days of inactivity, consistent with the `/privacy` retention promise. An operator-only `/ftlog [N]` command (gated by `TELEGRAM_OWNER_CHAT_ID`, like `/ver`) dumps recent entries; a silent no-op for everyone else.

## 4. Retention summary (canonical: `/privacy`)

> _(reproduced verbatim from `legal-0_58_45-05_05_26-1200.md`, then extended below the rule. Stale TTLs are corrected in §7 rather than edited in place, per AU-7.)_

- `loc:<sha256>` — 24 h
- `recent-picks:<sha256>` — 24 h
- `proc:<sha256>` — short-lived (per-request)
- `cuisine:search:*` — 30 min
- `cuisine:warmstart:*` — 60 s
- `revgeo:*` — 1 h (was 24 h before v0.58.27)
- `place-reviews:*` — 24 h
- `tell-gia:rl:*` — 1 h (rolling window)
- `buddy-optin:*` — 30 d (rolls forward on activity)
- `buddy-blocks:*` — 90 d (rolls forward on activity; the only persistent slot)

`/forgetme` deletes every key derived from the user's chat ID and returns a count.

— additions since v0.58.45 (see §7) —

- `freetext:log` — 90 d (capped to the last 5 000 entries; TTL refreshed on each write) — **identity-free**, not chatId-keyed, not deleted by `/forgetme`
- `freetext:log:<YYYY-MM-DD>` — 90 d per-day list — **identity-free**, as above
- `cuisine:search:*` — **30 s** since v0.59.35 (the "30 min" line above is superseded; see §7)

> _(reproduced verbatim from `legal-0_58_45-05_05_26-1200.md`.)_

- **v0.58.38 → v0.58.40 reverted address-sanitiser** (which was redacting Singapore floor-unit notation `#08-123` / `31-02 Marina Blvd` from displayed labels for privacy). Reverted because it caused a `/hidden` loop in production. **Until reintroduced (Register O-1), users may see floor-unit numbers in `/location current` echoes and other reverse-geocoded labels.** This is not a regression of any prior privacy promise — the promise has always been "no personal data sent to third parties", and the floor-unit labels never leave the bot's reply to the user themselves. But it is a UX-level privacy concern flagged by Human Lead and is owed a fix on next attempt.
