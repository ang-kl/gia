## New features in this arc

### Cuisine TMA · Michelin Places fan-in: parallel + 24-h Redis cache (v0.60.150 — PR #390)

- **What** — `handleMichelinSearch` ran 12 × Places `searchText` lookups in a serial `for-await` loop, each with a 6 s axios timeout — worst case 72 s. Later ▶ taps (which dipped into the slower-indexed Bib Gourmand tier) routinely breached Telegram's 30 s webhook ceiling → Railway returned `HTTP 502` to the TMA. v0.60.150 parallelizes the 12 calls via `Promise.allSettled(slice.map(resolveEntryPlace))`, drops the per-call timeout 6 s → 4 s, and adds a per-entry **`michelin:place:<slug(entry.name)>` Redis cache** (24-h TTL; negative-cache marker `{ __null: true }` for Places-returned-nothing entries so dead venues don't get re-hit). Plus a `[Michelin] handler ms=… cacheHits=… cacheMisses=… venues=…` warn log fired when `ms > 10000` so the next regression of this class is visible in Railway logs.
- **Why** — Operator: *"Later Michelin List — HTTP 502. Investigate."*
- **Where** — `index.js handleMichelinSearch` (inline `slugify` + `resolveEntryPlace`); new `__tests__/michelin-cache.test.js` (9 tests pinning slug invariants + negative-cache marker shape).

### Cuisine TMA · `/clipboard` per-clip controls — 📋 Copy / ✏️ Rename / 🗑 Remove (v0.60.151 — PR #391)

- **What** — Each clip row in `/clipboard` now has 4 actions instead of 1: `N: 📤` (existing Resend, rich HTML body + map button), `📋` (new — re-send the body as **plain text**; strip `<b>/</b>`, unescape entities, no `parse_mode`, no map button — Telegram preserves the message for tap-hold → Copy into other apps), `✏️` (new — Telegram `force_reply` prompt *"What name for clip N? (Reply to this message — 60 chars max.)"*; the next message-handler reply matches the pending `clip:rename-pending:<chatId>` Redis key, 5-min TTL, and applies `renameClip` so the listing header shows the user-supplied name instead of the auto-cuisines label), `🗑` (new — confirm gate then `removeClip` using the idiomatic Redis "LSET sentinel + LREM 1 sentinel" delete-by-index pattern; rest of the list intact). The existing 🗑 Clear all row stays at the bottom.
- **Why** — Operator: *"Feature: /clipboard — 'remove' button for individual list stored. 'rename' the individual list. 'copy'."* Clarified via Q&A: Copy = re-send as plain text.
- **Where** — `clip-store.js` new `removeClip` + `renameClip`; `index.js` new callback branches `clip:copy:N`, `clip:rename:N`, `clip:remove:N:{ask,yes,no}` + pre-route hook in `bot.on('message', …)` for the rename force-reply; `runClipCommand` listing prefers `name` (HTML-safe escape) + one row per clip with the 4 actions; `__tests__/clip-store.test.js` +8 tests; `__tests__/redis-stub.js` extended with `lIndex` / `lSet` / `lRem`.

### Cuisine TMA · distance gate widened 80 km → 120 km (v0.60.152 — PR #392)

- **What** — Two coupled constant bumps so `/cuisine` and `/s` chat free-text dish search agree on reach: `index.js:9227` `venues.filter((v) => v.distanceM == null || v.distanceM <= 80000)` → `<= 120000` (PR #125's hard gate) and `free-text-search.js:15` `MAX_DISTANCE_M = 80000` → `120000`. The JB region-mode `formattedAddress` filter for `"Johor Bahru"` still pins JB-mode results to actual JB venues (no Iskandar / Kulai / KL bleed). The existing 80 km drop test rewritten to 120 km; new companion test pins the widened band (a venue ~100 km is kept; 80000 < distanceM ≤ 120000).
- **Why** — Operator: *"PR #125, gate to 80 KM. Increase to 120."*
- **Where** — `index.js` + `free-text-search.js` + `__tests__/free-text-search.test.js`.

### Cuisine TMA · Michelin: same-first-12 dedup fix + force-warm enrichment + "Curating" UI (v0.60.153 — PR #393)

- **What** — Three coupled Michelin refinements after operator bug + ask: *"still load the same first 12 after tapping search FAB"* / *"Check for the latest review and 2 or more dishes to try for first 12 pull and store in the server. Refresh each time the same ChatID search Michelin or Combo Search Michelin"* / *"UI: Asking user to be patience, to curate the list with review."*
  1. **Bug fix — drop `radius` from the Michelin `criteriaHash`**. Michelin is a curated-list-based, location-agnostic flow; TMA slider drift between consecutive 🔍 Search taps was changing the hash → fresh seen-set → same first 12 served again. The fix strips `radius` from the Michelin criteriaHash (cuisines + combo + filters + prices + freeText + region remain). Consecutive 🔍 taps now reliably rotate through the curated ~130 entries.
  2. **Diagnostic log** at handler entry: `[Michelin] tap chatId=… hash=<8-char> seen=N combo=[…]` — one line per tap, fires on every Michelin search; surfaces the dedup state to Railway logs for future regression triage.
  3. **Force-warm enrichment cache** — new `michelin:enrich:<slug>` Redis key, 7-day TTL (distinct from v0.60.150's `michelin:place:<slug>` Places cache). Five-step flow in `handleMichelinSearch`: (1) review-extract from `places.reviews` (existing); (2) cache READ — fills missing `dishes`/`recentReview`/`vibe`/`signatureDish` from prior sessions; (3) narrate runs only on the SUBSET still missing `vibe` or with `dishes.length < 2` (saves Gemini cost on cache HITs; refreshes on misses); (4) force-fill — guarantees `dishes.length ≥ 2` (cuisine-label fallback) + non-empty `recentReview` (Michelin-tier boilerplate stand-in) so cards never ship empty; (5) cache WRITE refreshes the enrichment per search (so the next Michelin tap of the same chatId has the fields ready instantly).
  4. **"Curating Michelin list" loading copy** — new optional `loadingHint` prop on `ResultPanel`. `App.jsx` passes the Michelin-specific message *"🎩 Curating the Michelin list — fetching the latest reviews and signature dishes. Hang on…"* (EN + FR) when `state.cuisines.includes('michelin')`. Replaces the generic "Loading…" until the response lands.
- **Why** — Operator bug + ask (above).
- **Where** — `index.js handleMichelinSearch`; `web/cuisine/src/v2/components/ResultPanel.jsx` (`loadingHint` prop); `web/cuisine/src/v2/App.jsx` (pass the Michelin copy).
