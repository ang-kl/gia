## 3. Performance notes (this arc)

- **`enrichSlow` is a sequential chain** (open item O-45). Phases run one-after-another with `await`: crowd-signal → review translation (LLM) → review-cache dish extraction → **Gemini dish-extraction** → review finalise → **travel times (Routes)** → **sanctuary/vibe-summary (Claude)** → **BestTime footfall**. The sum can exceed the **20s `D706` deadline** → degraded-200 / client "Load failed". Candidate fix: parallelize the independent phases (`Promise.all` with per-step timeouts) and gate BestTime to SG (O-46).
- **BestTime** (`footfall-signal.js`): `REQUEST_TIMEOUT_MS=6000`, concurrency 4; `resolved=0/N` for MY venues (coverage gap) — wasted latency on non-SG searches.
