## Train TMA (new since v0.60.41)

**Surfaces** — `/transport train` (chat) and `/app/transport` (TMA).

### Data layer
- `data/mrt-coords.json` — 206 stations (177 operational + 29 future). Schema: `{ lat, lng, codes: [LTA codes], lines: [line codes], status: 'operational'|'future', opensYear: number }`. Generated once via `scripts/fetch-mrt-coords.js`; output committed.
- `mrt-lines.js` — canonical line table (`LINES`), interchange lookup (`LINES_BY_CODE`), station → line codes (`STATION_LINES` — extended at v0.60.100 to cover 35 LRT-only stops across BPLRT, SKLRT, PGLRT), `linesForStation()`, `networkHeadwayRange()`, `parseStatusByLine()`.

### Server
- `index.js runTransportTrain()` — composes:
  1. Top-level network status (from LTA `TrainServiceAlerts`, parsed via `mrtLines.parseStatusByLine`).
  2. Nearest-3 stations enrichment with per-station crowd badge (from LTA `PCDRealTime` via `fetchPlatformCrowdAll`).
  3. Line-emoji prefix per station via `linesForStation()` (e.g. `🟥 NSL · 🟪 NEL Dhoby Ghaut`).
  4. Affected lines breakdown + engineering closures (next 7 days from `data/mrt-engineering-closures.md`).
  5. Static headway footer (`networkHeadwayRange`).
- `transport.js nearestMrtStations()` — Google Places `searchNearby` with `includedTypes: ['subway_station', 'light_rail_station']` (LRT support added at v0.60.100).
- `index.js GET /api/transport/stations` — serves `data/mrt-coords.json` as JSON to the TMA. Cached in memory after first read.
- `index.js GET /maps-key` — exposes Google Maps JS API key + Map ID for `AdvancedMarkerElement` rendering.

### TMA (`web/transport/`)
- `src/App.jsx` — Hitachi-style composition (status panel + map + ticker + nearest stations + engineering list). Default view `mapView = 'png'`; one-shot `useRef` flips to `gmap` on the first line-chip tap.
- `src/components/SystemMap.jsx` — static PNG with focused-line dim.
- `src/components/MrtMapPanel.jsx` — interactive Google Map. Per-line color pins from `LINES_BY_CODE[code].hex`. Future stations desaturated grey. InfoWindow renders per-station live status (Normal/Delay/Disrupted) when `statusByLine` is passed.
- `src/components/AffectedTicker.jsx` — horizontal-scroll chip row. `⇆ All lines` reset chip at start; optional status icon per chip (⚠️/⛔/🚧).
- `src/components/LocationCard.jsx` + `EngineeringList.jsx` — auxiliary panels.
- `src/i18n.js` (new at v0.60.106) — minimal EN/FR module mirroring `web/menu/src/i18n.js`. Shared `gia.locale` localStorage key.
- `src/components/BackFab.jsx` — bottom-left FAB, smart `back` vs `end` detection, aqua bg (#7FDBDB).

## Checkpoint cameras (`/checkpoint`)

### Server
- `transport.js CHECKPOINT_BBOXES` — replaces the v0.60.72 4-camera allow-list at v0.60.103. Two lat/lng boxes (~3 km each) around Woodlands Causeway centre (1.4471, 103.7682) and Tuas Second Link centre (1.3454, 103.6356). Any camera LTA places inside either bbox is included.
- `transport.js fetchCheckpointTraffic()` — LTA `Traffic-Imagesv2` GET, filter by `checkpointLabelFor(lat, lng)`, sort by `label.localeCompare()`.
- `transport.js fetchIcaCheckpointStatus()` (new at v0.60.104) — best-effort scrape of ICA's public `trafficupdates` page. cheerio + regex heuristics for `Woodlands | Tuas` × `Departing | Arriving` × `Smooth | Healthy | Light | Moderate | Heavy | Congested | Closed`. 60 s in-process cache. Returns null on parse failure (chat reply degrades to camera-only).
- `index.js runTransportCauseway()` — sends header + camera count breakdown + (optional) italic ICA queue block, then one photo per camera.

## Cuisine TMA — combo search

- `index.js POST /api/cuisine/search` — at v0.60.82 → v0.60.84 added a multi-cuisine AND/OR path:
  1. **Phase A** (AND): join cuisine names into one Google `searchText` query (`"Italian Cantonese restaurant Singapore"`).
  2. **Validation** (v0.60.84): require ≥1 returned venue whose lowercased `name + primaryType + (types || []).join(' ')` haystack contains EVERY selected cuisine keyword. If validated, surface as primary; `comboInfo.matched = true`.
  3. **Phase B** (OR fallback): per-cuisine `pipeline.discover()` calls fanned out, merged round-robin (`italian[0], cantonese[0], italian[1], cantonese[1], …`) with placeId dedupe, capped at 30.
  4. Banner rendered above results when `comboInfo.attempted && !comboInfo.matched` ("No exact cuisine combination found. Showing separate eateries for each selected cuisine.").

## Telegram chunking helper

`index.js runTransportTrafficIncidents()` — when `lines.join('\n').length > 3500`, splits on newline boundaries into chunks ≤3500 chars and sends each as a separate Telegram message. Inline keyboard (map button + Back) only rendered on the LAST chunk so it doesn't repeat and isn't lost mid-thread.
