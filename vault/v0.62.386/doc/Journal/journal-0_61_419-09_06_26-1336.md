## New

### [HDR] #619 | 13:36 SGT 09-06-26 | v0.61.419 — per-city radius = half the nearest-sibling distance (no overlap) | cities.js (×2) + LocationField.jsx + test | 1 PR | 1 build |

- **[INTENT]** Two curated OTHER-cities' search circles must **not overlap**. KL and Putrajaya are ~24 km apart but both got a **flat 40 km** cap → heavy overlap (a search at either bled into the other).

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/cities.js`** (mirrored in **`web/menu/src/cities.js`**) — `cityRadiusCapM(cityOrName, countryCode)` now takes the city **object** + country code and returns **half the distance to the nearest sibling** in that country, clamped **[8 km floor, 40 km]**. Because every radius ≤ half its nearest-neighbour distance, for **any** pair `radius(A) + radius(B) ≤ separation` → the circles touch at most, **never overlap**. Isolated cities keep 40 km; **Johor** stays a 120 km whole-state cap; the floor keeps ultra-dense district lists (HK ~2 km, Brunei) usable (a small overlap is accepted there).
  - **`web/cuisine/src/v2/components/LocationField.jsx`** — the 2 callers (auto-pick `:992`, `onCityPick` `:1050`) now pass `(city, country.code)`.
  - **Klang Valley result:** KL **10 km** / Putrajaya **12 km** / Shah Alam **10 km** / Seremban **17 km**. KL↔Putrajaya 23.7 km, radii sum 22 km → no overlap; KL↔Shah Alam 20.1 km, sum 20 km → touch. *(Better than a flat ~12 km, which would still overlap KL↔Shah Alam at 20 km.)*
  - **`__tests__/city-radius-cap.test.js`** — 5 cases incl. the **all-countries no-overlap invariant**.
  - **`package.json`** `0.61.418 → 0.61.419`; **`doc/.serial-state.yml`** commit 631 → 632, journal 618 → 619, **build 399 → 400**; re-anchored 13:36 SGT.
