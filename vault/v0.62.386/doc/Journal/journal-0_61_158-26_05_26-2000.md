### [HDR] #359 | 20:00 SGT 26-05-26 | v0.61.158 — Carpark outside SG via Places 5 km radius + dispatcher (PR 4/5) | 5 files | 1 PR | 1 build |

- **[INTENT]** Rule §2.8 + the backend half of §2.9. Today the
  LTA `CarParkAvailabilityv2` feed is the sole data source, and
  it covers SG only. PR 4 makes the carpark layer mode-aware:
  - **SG** mode → LTA (unchanged, live `availableLots`).
  - **JB / OTHER** mode → Google Places New API
    `places:searchNearby` with `includedTypes: ['parking']` +
    5 km radius (no live lots, but at least a list of public
    carparks near the user / eatery).

  Wired into the chat per-venue carpark button, the `/carpark`
  command, and the `/api/geo/carpark` endpoint. The TMA map
  LAYER toggle stays SG-only in PR 4 — threading the locale
  mode through `createOverlayController` is a PR 5 task that
  also lands the Putrajaya UI button + train-line default.

- **[DELTA]**
  - **`carpark.js`** — two new exports:
    - `nearestPlaces(lat, lng, count = 5, radiusM = 5000)` —
      Google Places New API POST `places:searchNearby` with
      `includedTypes: ['parking']`. Returns `[]` for non-finite
      coords, missing `GOOGLE_MAPS_API_KEY`, empty Places
      response, or HTTP failure. Result shape mirrors the
      existing `nearest()`: `{ id, development, agency,
      lat, lng, distanceM, availableLots, lotType }` — but
      `agency === 'Places'`, `availableLots === null` (Places
      doesn't expose occupancy), and `lotType === ''`. Body
      clamps `maxResultCount` to `[1, 20]` and `radius` to
      `[1, 50_000]`.
    - `nearestForMode(mode, lat, lng, count = 5, opts)` —
      dispatcher. `mode in {'JB', 'OTHER'}` → `nearestPlaces`
      (5 km default, override via `opts.radiusM`). Anything
      else → `nearest()` (existing LTA path). Defaulting to
      LTA preserves the pre-v0.61.158 behaviour for callers
      that pass `null` / `undefined` mode (no userlocale yet).
  - **`index.js`** — three integration sites:
    1. Chat per-venue carpark button (around line 911 of
       `deliverPicks` body):
       - Reads `userlocale.mode` via `getUserLocale(redis, chatId)`.
       - Uses `carpark.nearestForMode` instead of
         `carpark.nearest`.
       - Builds the button label without "(N lots)" when
         `availableLots` is null.
       - Skips the SG path when `LTA_ACCOUNT_KEY` is missing
         (preserves prior behaviour); Places path runs even
         without LTA key (uses `GOOGLE_MAPS_API_KEY` only).
    2. `runCarparkCommand`:
       - Reads `userlocale.mode`.
       - `LTA_ACCOUNT_KEY` requirement is now gated on
         `cpMode === 'SG'` (JB / OTHER don't need it).
       - List rendering: when `availableLots == null`, render
         the row as `"N. <name> · <distance>"` (no i18n
         `carpark.row` template lookup — that template embeds
         `{lots}` and would print "null").
    3. `/api/geo/carpark` endpoint:
       - Accepts optional `?mode=JB|OTHER&lat=…&lng=…`.
       - When mode is JB/OTHER + lat/lng finite, switches to
         `nearestPlaces(lat, lng, 20, 5000)` and returns the
         response under a SEPARATE Redis cache namespace
         (`geo:carpark:places:<mode>:<lat3>:<lng3>`, 5 min
         TTL) so SG and non-SG don't poison each other's
         cache.
       - SG path (no params, or `mode=SG`) unchanged.
  - **`__tests__/carpark.test.js`** (NEW, 14 tests across 2
    `describe` groups):

    - `nearestForMode`: SG falls through to `nearest()` (LTA),
      JB → Places (default 5 km radius), OTHER → Places,
      null / unknown mode default to SG, `opts.radiusM`
      override respected.

    crowd-signal LTA-cluster heuristic) is NOT wired
    through `nearestForMode`. The crowd signal is SG-only
    by design (it derives crowd density from LTA carpark
    occupancy); making it cross-locale is a separate
    feature.
  - **Places-cache TTL = 5 min.** Carparks rarely move,
    but Place attributes (open hours, name changes) can.
    The TTL is conservative enough to refresh weekly-ish
    without hammering Places. Operator can tune via
    `EX: 300` in the endpoint.
  - **Cost.** Each non-SG `/carpark` invocation makes one
    Places `searchNearby` call. ~$0.005 each. Cached for
    5 min per rounded grid (~110 m × 110 m), so a typical
    JB user re-tapping `/carpark` within a session pays
    once.
