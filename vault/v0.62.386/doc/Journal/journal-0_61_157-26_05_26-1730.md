- **[INTENT]** Rule §2.7. When a NEW location fix falls outside
  the user's registered locale's boundary, prompt ONCE with
  Accept (swap anchor) / Decline (suppress for 24 h). The
  boundary is the operator's Answer-4 contract: admin-area name
  AND radius from the anchor.

- **[DELTA]**
  - **`location-boundary.js`** (NEW, ~110 lines). Three primitives:
    - `DEFAULT_RADIUS_M = { SG: 60_000, JB: 30_000, OTHER: 15_000 }`.
      SG = 60 km (full SG bbox + Sentosa + Tuas-side queue). JB
      = 30 km (the existing precincts.js cap). OTHER = 15 km
      (the operator's Putrajaya cap — "extend to 30 km when no
      results" is a SEARCH-radius concern that lives in PR 4).
    - `deriveMatchKey({ mode, adminAreaLevel1 })` — stable
      string. `'SG'` for any SG fix (collapses sub-regions so
      Bishan → Sentosa doesn't re-prompt). `'JB|johor'` for any
      Johor fix. `'OTHER|<lowercased trimmed admin>'` for
      everything else.
    - `computeBoundary({ mode, adminAreaLevel1, lat, lng, radiusM? })`
      → `{ matchKey, radiusM, anchorLat, anchorLng }`.
    - `isInsideBoundary(candidate, boundary)` → true iff same
      matchKey AND haversine distance ≤ `radiusM`. Defensive
      when the boundary has no anchor coords (legacy
      synthesized) or the candidate has no coords (trust the
      matchKey).
  - **`location-locale.js`** (extended):
    - `setUserLocale` now sanitizes a structured `boundary`
      field (validates matchKey + radiusM > 0; drops invalid).
    - `isSameLocale` delegates to `deriveMatchKey` so SG
      sub-region fixes collapse to a single locale (was: direct
      admin comparison in PR 2).
    - New `DRIFT_SUPPRESS_TTL = 24 * 60 * 60` + Redis-Set-
      backed helpers: `getDriftSuppress` / `isDriftSuppressed`
      / `addDriftSuppress` / `clearDriftSuppress`. Key
      `drift-suppress:<chatHash>`; members are matchKeys.
      `addDriftSuppress` refreshes the 24 h TTL each call.
  - **`location-classify.js`** (rewritten):
    - `classifyAndPersist` now returns
      `{ record, prev, candidate, changed, drift, mode, gated, geocoded }`.
    - `drift` is one of:
      - `'none'` — first registration (no prev). Persisted.
        `changed=true`.
      - `'inside'` — prev exists AND new fix is inside its
        boundary. Silent reuse. NOT persisted. `changed=false`.
      - `'outside'` — prev exists AND new fix is outside.
        Caller should send the §2.7 prompt. NOT persisted; the
        Accept-callback writes the candidate. `changed=false`.
      - `'suppressed'` — prev exists, outside boundary, BUT the
        candidate matchKey is in the drift-suppress set.
        Silent. NOT persisted. `changed=false`.
    - When the persisted record's `boundary` is missing (legacy
      v0.61.156 entry), synthesize one from `mode` + admin +
      lat/lng so the inside check still works.
  - **`index.js`** (3 wiring blocks):
    1. `bot.on('location')` — when `result.drift === 'outside'`,
       stash the candidate under `drift-pending:<chatId>` (10 min
       TTL) and send a bilingual EN/FR inline-keyboard prompt:
       "You're now near `<newPlace>`. Your registered location
       is `<prevPlace>`. Update?" with Yes / No buttons.
    2. `bot.on('callback_query')` — handles `drift:accept`
       (calls `setUserLocale(candidate)` + `clearDriftSuppress`,
       confirms with "Location updated to X"). Handles
       `drift:decline` (calls `addDriftSuppress(matchKey)`,
       confirms with "Kept your registered location. No further
       prompt for 24 h").
    3. The classifyAndPersist log line now also surfaces `drift`.

## Amendments

- **`isSameLocale` (rule §2.6) — semantics change.** PR 2's
  implementation compared `adminAreaLevel1` directly; this
  would have re-prompted on every SG sub-region cross
  (Bishan → Sentosa would have classified as different locales).
  v0.61.157 delegates to `deriveMatchKey` so SG collapses to
  a single key. Behaviour: SG-internal crosses are now silent
  (which matches the rule §2.6 intent); JB and OTHER mode
  semantics preserved.
- **`classifyAndPersist` return shape** — extended with
  `candidate` (the would-be record on prompt branches) +
  `drift` (one of `'none' | 'inside' | 'outside' | 'suppressed'`).
  PR 2's return fields (`record`, `prev`, `changed`, `mode`,
  `gated`, `geocoded`) are preserved.
