# Journal — soleat v0.61.311 (region-flip on LocationField pick)

> Operator (01-06 '26 ~11:16 SGT) screenshot + Railway trace: launched Cuisine TMA at *"Taman Melodies"* (lat 1.4912, lng 103.7665 — a JB suburb in Skudai / Mt Austin area). Map rendered correctly on JB landmarks, server log `D700 region=JB center=1.4927,103.7414`, but the LocationField pill showed 🇸🇬 instead of the Johor flag. Quote: *"I launch Cuisine TMA, it recognises the location is Taman Melodies, but Taman Melodies is in Johor Bahru and the flag is showing Singapore. it it be Johor Bahru mode?"*
>
> Root cause: `onLocationSelect` in `web/cuisine/src/v2/App.jsx` updates `locationAnchor` + `searchCenter` on a pick but never touches `state.region`. The v0.61.186 visibility-refresh hook (lines 798–833) DID flip region from the server's response, but only on viewport flip — so the pill stayed stale until the user navigated away and back. First-paint of the picked anchor showed the prior region's flag.
>
> Fix: flip region synchronously inside `onLocationSelect` based on the picked coords, using the existing `coordsToCountry` + `isJbCoords` helpers (already imported, already used elsewhere in this file).
>
> Commit 525 / journal 512 / build 314, on branch `claude/v0.61.311-region-flip-on-pick` off `main` at v0.61.310.

## New

### [HDR] #512 | 11:20 SGT 01-06-26 | v0.61.311 — region-flip on pick | 3 files | 1 PR | 1 build |

- **[INTENT]** Make the Cuisine TMA's region pill flag follow the picked anchor immediately, not on the next viewport flip. Eliminates the cross-country-jump first-paint inconsistency where the flag and the map disagree.

- **[DELTA]**

  **1. `web/cuisine/src/v2/App.jsx`** — surgical addition inside `onLocationSelect(p)` (line ~1661):
  - After the existing `setLocationAnchor` + `setSearchCenter` calls, compute `coordsToCountry({lat, lng})` (returns `'SG'` / `'MY'` / `null`) and `isJbCoords({lat, lng})`.
  - Branch:
    - `'SG'` → `setState((s) => s.region === 'SG' ? s : { ...s, region: 'SG' })`.
    - `'MY'` → set `region` to `'JB'` (if `isJbCoords`) or `'OTHER'` (anywhere else in Malaysia). On `'OTHER'` also set `countryPref: 'MY'` so the OTHER-region search-by-country narrows correctly.
    - `null` (e.g. user picked Bangkok) → no region change; preserves manual OTHER + countryPref the user already configured.
  - **`noSyncRegion` opt-out**: pass `{noSyncRegion: true}` from callers that already know the right region for their pick (e.g. JB focus-point chips at `LocationField.jsx:483`). Prevents region ping-pong when picking inside a region the user is already on.
  - **Persist payload alignment**: the `saveUserLocation` payload now prefers the coords-inferred region over `state.region` for the bot's `/api/cuisine/set-location` write. Closes the cross-country first-pick gap where the bot would persist the stale prior region (this was the v0.61.306 "Mid Valley Southkey tagged SG" symptom).
