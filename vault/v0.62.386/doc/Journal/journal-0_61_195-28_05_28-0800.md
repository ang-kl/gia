> Closes the chat-side mirror of v0.61.191/192. The TMA OTHER picker

## New

### [HDR] #396 | 08:00 SGT 28-05-28 | v0.61.195 — /location country picker | 4 files | 1 PR | 1 build |

- **[INTENT]** Give chat users the same country-aware location search
  the Cuisine + Menu TMAs gained in v0.61.191/192. A new `/lcountry`
  command opens a 17-button picker (SG + 16 OTHER countries). The
  selection persists in Redis (`country-pref:<chatId>`, 365 d TTL).
  `/location <text>` then routes geocoding through the chosen country
  — SG keeps the legacy Geocoding-API path; non-SG goes through Places
  (New) `searchText` with `includedRegionCodes:[<cc>]`, returning the
  top match and saving the resulting anchor with `region: 'OTHER'`.

- **[DELTA]**
  - **NEW `country-pref.js`** (~115 lines, CommonJS):
    1. **`OTHER_COUNTRIES`** — frozen array of 16 entries, identical
       to `web/cuisine/src/v2/lib/countries.js` (ASEAN-9 + Oceania-2
       + N-Asia-5). Bot lives on CommonJS Node, can't directly import
       the TMA ESM module that's bundled by Vite — so this is the
       parallel server-side mirror. The drift policy is "when the TMA
       list changes, mirror it here"; the two files have lived in
       sync since v0.61.191.
    2. **`ALL_COUNTRIES`** — 17 entries (SG prepended). The bot
       includes SG because chat `/location` was always SG-anchored
       and SG remains the most common pick; the TMA OTHER picker
       omits SG since SG has its own region pill.
    3. **`DEFAULT_COUNTRY = 'SG'`** — preserves the legacy `/location
       <text>` behaviour for everyone who never opens the picker.
    4. **`buildCountryPickerKeyboard()`** — returns an
       `inline_keyboard` shape: row 1 = SG alone (clearly the "I'm
       in Singapore" anchor), rows 2-5 = 4 OTHER buttons each
       (`<flag> <CODE>`), row 6 = `✖ Cancel`.
    5. **`getUserCountryPref(redis, chatId)`** — reads
       `country-pref:<chatId>`, validates against `ALL_CODES`,
       falls back to `'SG'`. Defensive: returns `'SG'` on closed
       Redis / read errors so the geocode never fails for picker
       reasons alone.
    6. **`setUserCountryPref(redis, chatId, code)`** — validates +
       SETEX with 365 d TTL. Returns boolean.

  - **NEW `__tests__/country-pref.test.js`** (13 tests):
    - List shape: 17 with SG first, 16 OTHER sans SG, ASEAN-9 +
      Oceania-2 + N-Asia-5 coverage.
    - Validators: `isValidCountry` accepts case-insensitively;
      rejects `'US'` / `''` / `null` / `undefined`. `findCountry`
      returns entry or `null`.
    - Keyboard: SG alone in row 1; rows 2-5 each ≤ 4 cols with
      `cp:<CODE>` data; cancel row at the end.
    - Redis stub: default `'SG'` when nothing stored; round-trip
      lower-case `'my'` → `'MY'`; rejects `'US'`; falls back to
      `'SG'` when stored value is corrupt (`'NOPE'`).

  - **`index.js`** (3 edits):
    1. **Top requires** (~line 40) — destructures
       `ALL_COUNTRIES` / `findCountry` / `isValidCountry` /
       `buildCountryPickerKeyboard` / `getUserCountryPref` /
       `setUserCountryPref` from `./country-pref`.
    2. **NEW `/lcountry` / `/lc` handler** (just before the
       `/location` handler) — sends the picker keyboard with the
       current pref shown as a `_Current: <flag> <name>_` italic
       line above. Plain `safeSend` with the inline keyboard.
    3. **NEW `cp:<CODE>` / `cp:cancel` callback branch** (right
       before the existing `v:` branch in `callback_query`):
       - `cancel` → deletes the picker message (non-fatal on
         failure).
       - `<CODE>` → validates via `isValidCountryPref`, calls
         `setUserCountryPref`, then `bot.editMessageText`
         in-place to a confirmation (`✅ Search country set:
         <flag> <name>`) with the next-step hint. Falls back to
         `safeSend` if edit fails (e.g. the picker message was
         already deleted).
    4. **`/location <text>` geocode block restructured**:
       - Reads `getUserCountryPref(redis, chatId)` (defaulting to
         `'SG'` on failure).
       - **SG branch** — unchanged Geocoding-API path with
         `components=country:SG`. Error message now suggests
         `/lcountry` as a fix.
       - **Non-SG branch** — Places (New) `searchText` POST with
         `regionCode: <cc>`, `includedRegionCodes: [<cc>]`,
         `pageSize: 5`, `languageCode: 'en'`, minimal field mask.
         Picks the first result with valid coords. On no match:
         `Could not resolve "<text>" inside <flag> <name>. Try a
         more specific name (street, mall, landmark), or change
         country with /lcountry.`
       - On success: persists via
         `setUserLocation(redis, chatId, lat, lng, { region:
         'OTHER', label })` — `region: 'OTHER'` matches v0.61.185
         so the Cuisine TMA's auto-flip picks up the anchor on
         next mount.

  - **`package.json`** — `0.61.194 → 0.61.195`.
  - **`doc/.serial-state.yml`** — commit 407 → 408, build 197 →
    198, journal 395 → 396; re-anchored 28-05 '26 08:00 SGT.
