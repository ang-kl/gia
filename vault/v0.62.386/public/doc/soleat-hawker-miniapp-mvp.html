Hawker mini-app — rework MVP

A per-centre detail view for the Hawker mini-app — the landing target when a 🍜 hawker centre is tapped in the "Local food picks" plate, surfacing specialities + ✴️ Michelin/Bib stalls that already live in our data but are never shown today.

Mockup only — NOT built · example centre: ABC Brickworks Food Centre (real data) · sources: data/hawker-centres.json, data/hawker-stalls.json, SG-michelin.js

1 The gap today

The Hawker mini-app is region pills → a multi-pin map → external Google-Maps buttons. Tapping a pin opens a small InfoWindow (name, stall count, address, transit, "Open on Google Maps ↗"). There is no per-centre page, and the data we already hold — each centre's speciality tags and the Bib Gourmand stalls located inside it — is never surfaced. So a tap from "Local food picks" has nowhere meaningful to land.

4 How the deep-link works

  • The 🍜 chip in "Local food picks" links to the Hawker mini-app with a centre param, e.g. /app/hawker?centre=<name|postal> (the same key the InfoWindow already uses: name|postal).
  • On load with that param the Hawker app pre-selects the centre's region, opens this detail view, and centres/zooms the map on its pin.
  • No new data — the detail view reads the same centres array the map already has, joined with the stall count + Bib lookups.
