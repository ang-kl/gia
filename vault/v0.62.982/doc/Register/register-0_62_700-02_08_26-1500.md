## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-71 | **A constant that describes the data belongs to the data.** `{ "'26": 2, "'25": 1 }` and `KEYS = [2026, 2025]` read as configuration and behaved as an assumption — correct until the dataset moved, then wrong with no symptom, no error and a green suite. Where a value mirrors a fact about the data, derive it from the data. The general form: **if adding a row to a dataset requires editing code, the code is holding a copy of the dataset.** | v0.62.700 |
| D-72 | **A fail-open guard must be measured against what is actually reachable.** The "all ticks off → return everything rather than nothing" guard tested a hardcoded pair of booleans instead of the editions a country has. In the two single-edition countries (SG, PH) that meant the guard never fired and the blank screen it exists to prevent shipped anyway. A guard written in terms of a fixed set silently stops guarding when the set stops describing reality. | v0.62.700 |
| D-73 | **Two questions need two inputs.** Building the tick list from the country's own editions would have been simpler and would have **deleted a feature** — Singapore's greyed, explained 2026 tick (D-65) would silently vanish, since SG's per-country list is `["'25"]`. *Which ticks exist* now comes from the cross-country union (`allYears`); *which are live* from the per-country list (`availableYears`). Collapsing them because they usually agree is how the feature would have been lost. | v0.62.700 |

## Note

O-124 was filed as "latent, ~20 lines". It was latent, and it was not 20 lines — not because the fix
was hard, but because the constant had been copied further than the item recorded. Five sites were
known; the sixth, `michelin-sort.js`'s `YEAR_RANK`, was found only by following the value rather than
the ticket. That one mattered most: the filter sites would have *dropped* a `'27` venue, which is at
least the kind of wrong someone notices, while the sort would have quietly ordered newest-last.

The more useful finding is the one nobody asked for. Running the old predicate beside the new one
across all 96 country × tick combinations was meant to prove *nothing changed*. It proved 94/96 —
and the two exceptions turned out to be a blank screen reachable in Singapore, on main, today, by
tapping two ticks. That path had been there since v0.62.676 and was invisible to the whole suite,
because a test can only fail on a case someone thought to write.

D-72 is the general lesson: the guard was not missing and not wrong; it was phrased in terms of a
fixed pair, so it stopped guarding the moment a country's data did not match the pair. That is the
same shape as D-62's compiled-CSS grep and D-68's specificity loss — a check that reads as a
guarantee while actually asserting something adjacent to what it claims.
