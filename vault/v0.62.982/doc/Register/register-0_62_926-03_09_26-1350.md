## ⚠ Corrections (new this entry) — C-2 of № 222 was itself wrong

№ 222 retracted three false claims in № 221. **Its own correction row C-2 carried a fourth.**

**Quoted verbatim from `register-0_62_925-03_09_26-1301.md` (AU-7):**

> "The folder covers **O-1 … O-229 and O-301 … O-349, contiguously**, across 177 snapshots.
> `O-230 … O-300` were never *allocated*: **D-202** in № 196 records that ids are issued above the
> **global** maximum, and the old global max was O-304. Exactly **one** real id had never reached
> the folder — **D-204**"

**What is true:**

| # | № 222 asserted | Measured, by script, from the files |
| :--- | :--- | :--- |
| C-4 | Exactly **one** real id had never reached the folder — **D-204** | **Four** had. D-204, plus **D-4, D-5 and D-6** — three operator directives named in a single sentence of `journal-0_60_190-15_05_26-1407.md`: *"D-1 Meta Llama only / D-2 zero edits to root / D-3 separate repo / D-4 Journal per PR / D-5 `gia-preflight` / D-6 hold until access lands"*. Their siblings D-1, D-2 and D-3 do appear here; the last three of the sentence never did |

**Everything else in C-2 holds, and was re-derived rather than re-read.** The `O-` space really is
complete: 204 `O-` ids appear in `doc/Journal/` and 281 in `doc/Register/`, and the only `O-` absent
is `O-999`, a defect **planted in a mutation table** in `journal-0_62_798-26_08_26-2019.md`. The
177-snapshot figure is right — that is the folder as it stood before № 221 and № 222 were added
(`git ls-tree af66b826 doc/Register/` → 177).

### The claim was also not well posed, which is the part worth keeping

`D-` ids are **not globally unique**. Counted across `doc/Journal/` and `doc/Register/`, the low
numbers carry several unrelated definitions each:

| Id | Distinct defining texts | Examples |
| :--- | ---: | :--- |
| D-1 | 3 | *"Meta Llama only"* (operator directive, 15-05) · *"hawker `tg.js` `history.length` heuristic"* (12-07) |
| D-2 | 2 | *"zero edits to root"* · *"hawker `BackFab.jsx`"* |
| D-3 | 2 | *"separate repo"* · *"CJK U+3000-vs-U+3040"* |
| D-4 | 2 | *"Journal per PR"* · *"`LocationField` as a shared **hook** not component"* |
| D-6 | 2 | *"hold until access lands"* · a durability note in `journal-0_62_531` |

So "did D-4 reach the folder" has no single answer without naming an era, and **D-202's rule —
issue ids above the *global* maximum — has no single maximum to read for `D-`.** Filed as **O-351**.

### How it was found, and how it was not

Not by review. **By the verification pass on #1859**, which is the merge that shipped № 222: a
check re-derived the id union from the files instead of reading the sentence, and disagreed with it.
Third time in this arc that the right answer came from two measurements disagreeing rather than from
one being trusted — and the first where the disagreement was with a document written to correct a
disagreement.

Two things did **not** find it:

- **№ 222's own guard passed.** `__tests__/register-current.test.js` checks the predecessor,
  the budget, the owed-records section and the guarded-items table. None of them enumerates ids,
  so C-2's claim about a *set* was outside everything the file measures.
- **CI was 4/4 green** on #1859 and the claim merged, deployed, and rendered on soleat.net.

That is **O-350 a second time in a row**, and it is now the pattern rather than the incident.

### The check that would have caught it

`register-current.test.js` gains an **absent-id census**: the newest snapshot must *enumerate* the
ids that appear in `doc/Journal/` and not in `doc/Register/`, and the test derives that set and
demands exact equality in both directions. Prose describing a set is not checkable; a list is.

Two things make it honest rather than decorative:

- **Being listed as absent is not being filed.** The census section is stripped from every snapshot
  before ids are harvested — otherwise writing an id into the census would file it, the derived set
  would empty, and the check would collapse to `∅ === ∅` at the exact moment it was first satisfied.
- **When it fails, the fix is a census row or a real filing, never a narrower scan.** An id
  allocated in a journal and not yet in the Register is precisely what this folder exists to track.
