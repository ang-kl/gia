## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-86 | **A missing Tailwind class is not a missing element, and nothing in this repo's check suite can see one.** The drag handle rendered 0px tall while `node --check`, `vite build`, ~4,000 unit tests and the render smoke were all green — because the node *existed*, it was merely unstyled, and the render smoke counts nodes. This is the third silent-drop in this family (v0.62.648's opacity-modifier-on-a-var, the v0.62.678 JIT checks, now the content glob), and the pattern is that Tailwind fails by omission and every downstream check reads the wrong artefact. Where a build step can silently drop output, assert its **inputs** — a config guard, not another output check. | v0.62.706 |
| D-87 | **When a new guard fails something, check the guard before the code.** Its first run failed `oversight`, which imports exactly one thing from `_shared` — `lib/safe-area.js`, a pure module with no markup — and renders no shared components at all. Adding the glob there would have scanned files the app never renders, protected nothing, and left the guard permanently over-strict on a rule nobody would revisit. The guard was narrowed to "reaches a shared file containing class strings", which is both correct today and self-maintaining if markup is later added to a lib. A guard's first red is evidence about the guard as much as about the code. | v0.62.706 |

## Note

The uncomfortable part of this entry is not the config line. It is that v0.62.704 shipped with a
**verification section listing eight kinds of check**, including a compiled-CSS grep — and the handle
was still 0px tall on the operator's device.

The grep was real, but it checked the classes *I had just written* in `styles.css` and in the new
components. It never occurred to me to check the classes inside the shared component I was newly
consuming, because I had not written them and they worked everywhere else. That is the shape of
D-86: the check was pointed at the code I had touched, and the defect was in the code I had merely
started using.

D-87 is smaller but worth keeping. The new guard's first run went red on `oversight`, and the
instinct was to add the glob and move on — a one-line change that would have looked like diligence.
`oversight` was innocent. Had I "fixed" it, the guard would have carried a wrong rule forever, and
the next person to read it would have inherited the belief that any `_shared` import needs the glob.
A guard's first failure is evidence about the guard.
