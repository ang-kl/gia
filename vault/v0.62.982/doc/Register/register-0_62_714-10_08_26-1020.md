## Completed (new this entry)

| # | Item | Shipped | PR(s) |
| :--- | :--- | :--- | :--- |
| C-206 | **Fixed the sanctuary redundant Places-Details-fetch leak.** `cuisine-enrich.js`'s `enrichSlow` deleted `v.reviews` in its finalise loop, then called `ctx.enrichSanctuaryRead` several steps later — which re-fetched the exact same `reviews` field from Places Details it had just discarded. `delete v.reviews` deferred to a standalone pass at the end of `enrichSlow` (after sanctuary runs); `vibe-summary.js`'s `fetchReviewText`/`getOrCacheSummary` gain an optional `preFetchedReviews` param so sanctuary reuses the in-memory reviews instead of paying for a second call. Every OTHER caller (Michelin, nation-iconic, cooking-method) doesn't carry `v.reviews` and is unaffected — falls through to the unchanged live-fetch path. | v0.62.714 | (draft, not yet opened) |
| C-207 | **11 new tests** — 3 in `__tests__/cuisine-enrich.test.js` pinning the reorder (sanctuary sees `v.reviews` at call time, it's gone after; a throwing sanctuary callback doesn't block the deferred delete; a reviews-less venue is untouched), 8 in `__tests__/vibe-summary-reviews.test.js` (NEW) covering `formatReviewsForSummary`'s recency/cap/fallback behaviour and `fetchReviewText`'s `preFetchedReviews` short-circuit — proven with no `GOOGLE_MAPS_API_KEY` set, so a non-empty result is only possible via the in-memory path. Both fix-halves mutation-checked (reverted, confirmed red, restored). | v0.62.714 | (this PR) |

## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-101 | **A reorder fix and a data-reuse fix can each be individually necessary but only jointly sufficient — ship them together, not as separate incremental PRs.** Deferring `delete v.reviews` alone would have let `enrichSanctuaryRead` see the data but not use it (no parameter existed to receive it); adding `preFetchedReviews` alone would have been dead code (nothing left alive to pass, since the delete ran first). Neither half fixes the leak without the other. | v0.62.714 |
| D-102 | **When a new unit test needs to exercise a function that calls several real, unmocked sub-modules, read each sub-module's own early-exit guard before trusting the test won't hit the network.** `enrichSlow`'s new reorder tests call the REAL `crowd-signal`/`cuisine-review-language`/`travel-times`/`gemini-client`/`footfall-signal` modules rather than injecting mocks — verified safe only after confirming each one's own API-key gate fires before any `axios`/SDK call, and confirming none of the relevant env vars are set in this sandbox. Chose this over mocking every sub-module because it exercises the real failure-mode branches, closer to production behaviour than a hand-rolled ctx would give. | v0.62.714 |
