## New

### [HDR] v0.62.582 — Cuisine: re-measure `headerBottom` so the picker dropdown drops flush under the tabs

- **[INTENT]** Operator (IMG_0748/0749, **landscape** tablet, deployed v0.62.580): *"Up to now still
  have [not] resolve the alignment."* — the "tab-criteria dropdown don't align" report (Defect 2),
  first raised in portrait (IMG_0745/0746) and now shown in landscape.

- **[DELTA]** The landscape shots made it legible: the folio picker dropdown opened **over** the
  header — its top covered the "Click to change" line and the folio **tabs** instead of sitting flush
  **below** them (a **vertical** overlap, ~30 px too high — not the horizontal offset I'd earlier
  ruled out). **Root cause:** `headerBottom` (the fixed dropdown's `top: headerBottom`) was measured
  **stale** — the `ResizeObserver` seeded it at first paint when `venues` was still `0` (header =
  title + the single "Cuisine & filters" tab), then results arrived and the "Set location is …"
  collapsed line + the second tab grew the header ~30 px, but RO didn't re-fire, so the dropdown
  anchored ~30 px too high. **Fix** (`web/cuisine/src/v2/App.jsx`): imported `useLayoutEffect` and
  added an effect that re-measures `headerBottom = headerRef.getBoundingClientRect().bottom` on
  `[cuisinePickOpen, classicOpen, regionExpanded, modePeek, venues.length]` — before paint, so no
  flash — so the dropdown always drops flush under the tabs. (Same root cause as the portrait
  complaint; the overlap simply read as "don't align".)
