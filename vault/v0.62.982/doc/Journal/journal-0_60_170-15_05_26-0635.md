# Journal — soleat v0.60.170

> Operator bug report with Railway log evidence (`log/Depoly_0620_15-May.MD`): "Cuisine TMA, isn't the same as Google map. start at Vivocity, set new location Takashimaya, Google Map still shows Vivocity, search Japanese results across both, search European results focus on Vivocity."

**Root cause**: v0.60.166 fixed the "LocationField pick auto-fires search" bug by removing the `runSearchAt(...)` call from the LocationField `onSelect` and replacing it with `setLocationAnchor(...)` only. The `setSearchCenter(...)` side-effect that `runSearchAt` implicitly used to perform was also dropped. Result: picking a new place updated `locationAnchor` but left `searchCenter` stuck at the original GPS-resolved warm-start coords. Two downstream effects:

1. **Map** — the MapPanel renders from `searchCenter`. It kept showing Vivocity.
2. **Search payload** — the criteria-card Search button calls `runSearch(state)` *without* an explicit anchor argument; `runSearch` falls back to `searchCenter` for the `center` field of the `/api/cuisine/search` body. The Railway logs confirmed `center=1.2647,103.8232` (Vivocity) on every search after the user picked Takashimaya.

**Fix**: re-add `setSearchCenter({ lat, lng })` to the LocationField `onSelect` immediately after `setLocationAnchor(...)`. This restores the pick-updates-the-map behaviour while preserving v0.60.166's no-auto-fire contract (still no `runSearch` call from the onSelect).
