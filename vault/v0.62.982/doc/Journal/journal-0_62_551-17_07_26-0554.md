## New

### [HDR] #908 | 05:54 SGT 17-07-26 | v0.62.551 — urgent: bus-stop pill tap shows the stop on the map | 3 files | PR #(pending) |

- **[ROOT CAUSE].** The v0.62.549 pill-tap wired both station + bus-stop pills to `highlightLoc`,
  which only **panned + drew a faint hollow halo** — it never dropped an actual bus-stop MARKER, and
  the Bus Stop overlay layer is OFF by default, so there was nothing at that point to see. Two ways it
  read as "nothing appeared": (a) no labelled bus-stop pin was ever added; (b) in the phone/stacked
  layout the map sits ABOVE the card list, so the pan happened off-screen (the known no-auto-scroll
  gap flagged in #906/#908 KGs).

- **[FIX].**
  - `web/hawker/src/lib/mapOverlays.js` — new controller method **`showBusStop(code, lat, lng, desc)`**:
    drops a **labelled bus-stop pin** (`busPinNode`) + opens its live-arrivals bubble (`openBusInfo`) +
    pans + zooms (≥16) + flashes a 3 s halo. The pin rides the `venueTransitPins` bucket so a tap on the
    empty map (`closeInfo → clearVenueTransit`) clears it.
  - `web/hawker/src/components/HawkerMapPanel.jsx` — new global **`window.__giaHawkerShowBusStop`**; and
    a shared **`revealMap()`** (`containerRef.scrollIntoView`) now runs on `__giaHawkerFocusStation` /
    `__giaHawkerShowBusStop` / `__giaHawkerHighlight` so the map scrolls into view first (fixes the
    off-screen pan on phones; no-op when already visible).
  - `web/hawker/src/App.jsx` — `handlePillTap(id, show, url)` now takes a **show callback**: the STATION
    pill calls `__giaHawkerFocusStation(code)` (drops the station marker + card, as its InfoWindow link
    already did) and the BUS pill calls `__giaHawkerShowBusStop(code, lat, lng, desc)`. Two-tap unchanged
    (1st = show on map + pale toggle; 2nd = external Google Maps + un-toggle).
