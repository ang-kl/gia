### [HDR] v0.62.642 — "where is the drawer overlay in all three TMA" — audit + the Hawker half of the answer

- **[INTENT]** Operator: *"Where is the drawer overlay effect while Google map is behind in all three TMA."*

- **[AUDIT — the honest state before this PR]** Only **two** of the three had a real `BottomSheet` drawer, and
  neither had it everywhere:
  | TMA | Drawer over the map? | Detail |
  |---|---|---|
  | **Transport** | ✅ yes | LIST mode is a `BottomSheet` over a full-bleed map (v0.62.639); phone-portrait carousel mode uses one too. |
  | **Hawker** | ⚠️ phone only | `drawerLayout()` fired only for `deviceClass === 'mobile'`; a **tablet in portrait** fell through to `portraitTabletPanel()` — a static **two-panel** split where the map is a fixed block **above** the list, not behind it. |
  | **Cuisine** | ❌ none | It never imports `web/_shared/components/BottomSheet.jsx`. The component *named* `ResultDrawer` is misleading — it is a **horizontal snap card strip** docked above the footer. The vertical list (`ResultPanel`) is **page-flow** markup gated by `drawerMode === 'vertical'`, sitting **below** a `sticky z-20` map rather than over it. |

- **[DELTA — shipped, Hawker, 1 file]** `web/hawker/src/App.jsx` layout dispatch: **portrait on ANY device**
  now returns `drawerLayout()` (was mobile-only), so a tablet in portrait gets the draggable sheet over the
  full-bleed map exactly like the phone. Inside the drawer the centre list lays out `grid-cols-2 items-start`
  when `isWide` and a single column on a phone. `portraitTabletPanel()` is intentionally **left defined but
  unreferenced**, so the two-panel can be restored in one line if the operator prefers it.

- **[NOT DONE — deliberately deferred, flagged]** **Cuisine** needs a real **restructure** to get the same
  effect: its root is a scrolling page (header + sticky map + flow list), so turning the vertical list into a
  drawer means making the map a **fixed full-bleed layer** and moving `ResultPanel` into a `BottomSheet` —
  touching the app's whole layout spine. That is the highest-risk file in the repo and the app that just had
  the iPad-mini freeze (v0.62.635), so it gets its **own focused PR** rather than riding along with a one-line
  dispatch change.
