Operator: *"the place is in Japan → Japanese; English because the device language is English; if the device is French then French; if the location is Seoul then Korean."* So: **`<place language> (<device language>)`**.

- **[ROOT — 3 bugs in v0.61.382]**
  1. **Wrong target** — translated into the en/fr **app locale** → romaji/pinyin, not the place's language.
  2. **Country-gate** (`localLangForCountry` + RULE B) would skip a ja-device user even though the **name** is Chinese (foreign *in* Japan). Gating must be by the **name's script**, not the country's assumed script.
  3. **`isValidReading` rejected all CJK** output (built for romaji) → a Japanese/Korean reading would be discarded.

- **[DELTA]**
  - **`translate-name.js`** (rewrite) — reading is now **two-part** `<place lang> (<device lang>)`, e.g. `シルクロード 新疆料理 (Silk Road Xinjiang Cuisine)`. First part = `LOCAL_LANG_BY_CC[searchCountry]` (JP→ja, KR→ko, CN/TW/HK/MO→zh, TH→th); bracket = the **device language**. NEW `nameScriptLang()` (Hangul→ko, Thai→th, kana→ja, bare-Han→zh, Latin→null) gates **per name-script** — translate only when the name's script ≠ the place's language (Chinese name in Japan ✓; Japanese name in Japan ✗); also skip when `nameLocal` is already set. `isValidReading` is now **target-aware** (a ja reading may carry kana/kanji/Latin; reject only hangul/thai — and the analogues for ko/zh/th; Latin/Tamil targets must be romanised). `translateName` gains `localLang` + `glossLang` (single-part when device lang == place lang); cache key `v1 → v3`.
  - **`web/cuisine/src/v2/lib/api.js`** — NEW `deviceLang()` (the primary subtag of `navigator.language`, e.g. `en-GB → en`), injected into every `postJson` body beside `deviceRegion`.
  - **`index.js`** — parses `req.body.deviceLang` (`^[a-z]{2,3}$`) at the cuisine `/search` (13688) + `handleMichelinSearch` (9434), passing it to `attachNameReadings` as the **gloss** (replaces `csLang`). Null → gloss defaults to English (graceful).
  - **`__tests__/translate-name.test.js`** (rewrite, 12) — `nameScriptLang`; target-aware `isValidReading`; two-part `translateName` + Latin→null + echo→null; `attachNameReadings` (Chinese-in-JP → ja+en, Japanese-name skip, `nameLocal` skip, Chinese-in-KR → ko, Latin-country FR skip).
