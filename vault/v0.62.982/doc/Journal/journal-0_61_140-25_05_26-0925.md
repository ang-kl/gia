## New

### [HDR] #341 | 09:25 SGT 25-05-26 | v0.61.140 — Wake 2-step: request_location → rich comparison + 3 buttons | 4 files | 1 PR | 1 build |

- **[INTENT]** Rewrite `promptLocationOnWake` (the v0.61.84 wake-
  from-idle prompt) to the operator's richer flow. The v0.61.84
  version sent a single message with two inline buttons (*"Stay
  here"* / *"New location"*) — it neither compared the cached
  anchor against the device's current GPS nor offered a 3-way path.
  Operator spec also asked for a `/l <place>` helper line in the
  message body.

- **[FLOW]**
  1. **Wake detected** — `promptLocationOnWake(chatId, msg)` fires
     on the first chat message after the IDLE_WAKE_MS (6 h) gap.
     Reads the cached location; bails if none. Stamps
     `wake:pending:<chat>` = `'1'` in Redis (10-min TTL). Sends
     `wake.intro` text + the existing `LOCATION_REQUEST_KEYBOARD`
     (one_time_keyboard:true).
  2. **User shares GPS** — `bot.on('location')` checks the
     `wake:pending` flag at the top of the handler. If set, deletes
     it, calls `handleWakeLocationResponse(chatId, lat, lng, msg)`,
     and `return`s early — the cached anchor is NOT overwritten.
  3. **Rich comparison** — `handleWakeLocationResponse`:
     - Reverse-geocodes the new GPS via `reverseGeocodeAddress`,
       preferring `name` over `formatted` (operator: *"street name
       not full address"*). Falls back to `lat, lng` coords if
       reverse-geocode fails.
     - Reads the cached anchor; composes the display label from
       v0.61.139's `street`/`building`/`postal` triple if present,
       falling back to the legacy `label` field.
     - Stashes `{lat, lng, street}` in `wake2:offer:<chat>` (10-min
       TTL) so the *"Use current location"* button can apply it.
     - Sends a single HTML message with `wake2.body` (substitutes
       `{deviceStreet}` and `{anchor}`) + a 3-button inline
       keyboard. Helper text (`/l Orchard Road` / `/l IOI City Mall`)
       lives in the message body as italic copy.
  4. **Button outcomes** (all edit-message-reply-markup-clear-then-ack):
     - `wake2:current` → reads `wake2:offer`, calls
       `setUserLocation(redis, chatId, offer.lat, offer.lng)`,
       deletes the offer key, sends `wake2.currentApplied` with
       the street interpolated.
     - `wake2:keep` → no-op; sends `wake2.kept`.
     - `wake2:another` → sends `wake2.anotherHint` + the
       `LOCATION_REQUEST_KEYBOARD` so the user can either type
       `/l <place>` or share fresh GPS.

  **Functional walkthrough (not yet run live):**
  - First message after 6+ h idle, cached location present →
    `wake.intro` + request_location keyboard. ✓ logic check.
  - User shares GPS within 10 min → `handleWakeLocationResponse`
    fires, sends `wake2.body` + 3 buttons. Cached anchor preserved.
  - User taps "Use current location" → `setUserLocation` updates
    the anchor to the device GPS; offer key cleared.
  - User taps "Keep earlier location" → ack, no Redis write.
  - User taps "Set another location" → hint + request_location
    keyboard for either a `/l <place>` type or fresh GPS share.
  - User waits >10 min then taps "Use current location" → the
    `wake2:offer` key has expired; user sees `wake2.offerExpired`
    and is told to `/l`.
