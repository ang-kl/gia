- **[DELTA]**

  **`index.js` `handleMichelinSearch`** — three subtractive edits.

  *(a) Places-cache removal* (line ~6225). The whole `cacheKey = michelin:place:${slug}` Redis read/write block in `resolveEntryPlace` is gone. Each entry now resolves with a fresh `axios.post(PLACES_URL, …)`. Side effects:
  - DF-90 0–24 h rollover window for new FIELD_MASK additions is **eliminated** — every tap sees the latest fields immediately.
  - Per-tap Places cost rises by ~12 `searchText` calls (worst case; cuisine combo filters may slice fewer). Daily cost rises proportional to Michelin tap volume.
  - `cacheHits` / `cacheMisses` counters retained (always 0 / 12 now) for the legacy `[Michelin] handler ms=…` log shape.
  - The negative-cache marker (`{__null: true}`) is gone too — Places lookup failures are best-effort silent.

  *(b) Seen-set removal* (line ~6038). Stripped:
  - `criteriaHash = computeCriteriaHash(...)` — no longer needed.
  - `if (req.body?.resetSeen === true) await resetSeenSet(...)` — explicit client reset is moot.
  - `const seen = await readSeenSet(...)` — no walk-through state to read.
  - `vlogMichelin.vlogTtl(redis, csChatId, 'cuisine:seen:…')` — no Redis key to inspect.
  - Candidate filter no longer excludes `seen.has(dedupKey)` — every entry is a candidate.
  - "If everything has been seen, reset" branch removed — `didReset` retained as `const = false` for the legacy log line below.
  - `appendSeenSet(...)` after slice — gone. Nothing to remember.
  - The v0.60.187 (DF-80) `michelinDedupKey` field is still attached to each venue object by the construction loop (harmless dead code; deleted by the `for (const v of filteredVenues) delete v.michelinDedupKey;` cleanup before the response). Left in place to keep the v0.60.187 patch self-contained.

  *(c) Response payload* — `exhausted = filteredVenues.length < 3` (was `didReset || filteredVenues.length < 3`). `michelinSummary` is shipped with `remaining: 0` — this is intentional:
  1. The TMA's `michelinRemaining` state goes truthy → v0.60.194's `&& !michelinRemaining` guard continues to suppress the cuisine-chip `<12` auto-reset + visible hint for combo searches that yield <12 (e.g. Michelin + Korean = 4 starred entries). Without this sentinel the TMA would loop the hint forever.
  2. The "📚 N more to explore — Tap 🔍 for next batch of 12" indicator auto-hides (only renders when `remaining > 0`).
  - `pageStackDepth` dropped from the response (no pagination to track).

  **No App.jsx change required**: the TMA's state-update logic (`setMichelinRemaining({remaining: 0, ...})` → truthy state) handles the new payload shape unchanged. v0.60.194's gates are preserved.
