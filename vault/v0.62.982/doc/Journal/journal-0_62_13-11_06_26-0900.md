- **[BUG 1 — spurious first-tap zero (root cause, 2 Explore agents)]** A **stale per-criteria seen-set**
  `cuisine:seen:<chatId>:<hash>` (30-day TTL) survives from a prior session. On tap 1 the dedup
  (`index.js:~15827` `unseenInCriteria = venues.filter(!seen.has)`) removes **every** venue → `trulyUnseen=[]`
  → `top=[]` → 0, even with no cuisine/filter. Tap 2 works (seen-set refreshed → 17). The TMA already has a
  zero-result auto-retry (`App.jsx:~1960`, `resetSeen:true`) for exactly this, but it wasn't recovering for
  the operator. Per the operator's choice (**surface the reason**, not auto-recover):
  - **`index.js`** (before the response payload, ~16314): classify **`zeroReason`** when `top.length===0` —
    `no-venues-nearby` / `no-match-criteria` (pool empty; criteria present or not), **`all-seen-criteria`**
    (pool HAD venues but the per-criteria seen-set emptied it — the stale-seen case → *evident it's NOT the
    criteria*), `all-seen-session`, `filtered`. Added to the payload + a `[Cuisine-Search] ZERO reason=…
    pool=… unseenCrit=… trulyUnseen=… seen=…` log.
  - **`web/cuisine/src/v2/App.jsx`**: new `zeroReasonKey` state; on a **persistent** zero (the resetSeen
    retry also empty, OR the retry budget for this signature was spent) set the notice key from
    `r.zeroReason`; a retry-pending zero shows nothing yet (the retry usually recovers); cleared on any
    non-zero. Render a calm notice above the result panel.
  - **`lib/i18n.js`**: `zero.allSeen` ("No new places to show here — tap 🔍 again to refresh."),
    `zero.noMatchCriteria` ("… try removing a filter or a cuisine."), `zero.noVenuesNearby` (en + fr).

- **[BUG 2 — city pick didn't persist to chat (root cause)]** Picking a city hits the **`cityPreview`
  early-return** in `App.jsx onLocationSelect` — it only set `selectedCityLocation` + flew the map and
  `return`ed, **skipping `saveUserLocation()`**. So a city pick never reached the bot's `loc:<chatId>` /
  `addRecentLocation`, and Telegram drifted back to "set location." Fix (**persist, keep preview**):
  - **`web/cuisine/src/v2/App.jsx`** (cityPreview branch): on the **same 350 ms fly debounce** (so rapid
    city-flips only persist the final city), now call `saveUserLocation({ lat, lng, label, notify:true,
    region, country, radiusCapM })` → server `/api/cuisine/set-location` → `setUserLocation` +
    `addRecentLocation` (the location drawer). region/country inferred from the picked coords
    (`coordsToCountry`/`isJbCoords`) with the OTHER-picker `countryPref` fallback. **Stays a preview** — it
    does NOT set `explicitPickRef`, does NOT move the search anchor, and does NOT auto-search (respects the
    no-auto-fire + v0.61.354 rules). The map fly is unchanged.
