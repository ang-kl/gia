## New

### [HDR] #447 | 11:35 SGT 29-05-29 | v0.61.246 — Open closing + reopen | 6 files | 1 PR | 1 build |

- **[INTENT]** Today the venue card surfaces the raw
  `weekdayDescriptions[today]` string (e.g.
  *"Monday: 11:00 AM – 3:00 PM, 6:00 PM – 10:00 PM"*) when a
  restaurant is currently open. The operator wants to see, at a
  glance, **when the venue closes next** and (if applicable)
  **when it reopens** — without having to mentally parse the
  comma-separated schedule. This PR adds a first-class
  *"Open · Closes 3:00 PM · Reopens 6:00 PM"* line, mirroring the
  v0.61.219 *"Closed now · Opens today 11:30 AM"* idiom for the
  closed case.

- **[DELTA]**

  **1. `open-hours.js`** — new exported `currentOpenString(periods, now)`:

  ```js
  // Returns:
  //   single same-day period   → "Open · Closes 10:00 PM"
  //   split (lunch + dinner)   → "Open · Closes 3:00 PM · Reopens 6:00 PM"
  //   24-hour venue            → "Open · 24 hours"
  //   period crosses midnight  → "Open · Closes Tue 2:00 AM"
  //   no current period        → null
  ```

  Algorithm:
  1. Find the active period — one whose `[open, close]` interval
     contains `now` in SGT minutes. Three shapes handled:
     same-day, opened-today-closing-tomorrow, opened-yesterday-
     closing-today.
  2. When the active period closes same-day, look for another
     period starting *after* its close (the lunch+dinner split
     pattern); take the earliest one as the "reopen".
  3. Format the close time via the existing `fmtTime`; emit a day
     label only when the close crosses to a different SGT
     weekday.

  **2. `index.js`** — both venue-payload assembly sites:
  - `/api/cuisine/search` (line ~14394): the existing
    `closedTodayString` import gains `currentOpenString`. When
    `v.openNow === true`, attach
    `v.openClosingLabel = currentOpenString(v.regularPeriods)`.
  - `/api/cuisine/nl-query` (line ~14863): same mirror.

  **3. `venue-templates.js` `formatHoursLine`** — prefer
     `p.openClosingLabel` ahead of the raw
     `weekdayDescriptions[today]` fallback. Order of precedence
     becomes: `closedTodayLabel` → `openClosingLabel` →
     `weekdayDescriptions[today]` → bare *"Open now"* / *"Closed"*.

  **4. `web/cuisine/src/v2/components/ResultCard.jsx`** — when
     `venue.openNow === true`, surface
     `venue.openClosingLabel` (falling back to the localised
     *"Open now"* when missing). Inline comment notes the
     operator quote.

  **5. `web/cuisine/src/v2/components/ResultPanel.jsx`** — extend
     the Copy-All / per-card data pipe to include
     `openClosingLabel` so the same string travels via
     `copyAllToChat` / `copyOneToChat` into the chat-rendered
     venue blocks.

  **6. `__tests__/open-hours.test.js`** — 8 new tests pinning the
     algorithm:
     - `null` / empty inputs return `null`
     - currently before open returns `null`
     - single-session: `"Open · Closes 10:00 PM"`
     - lunch+dinner split mid-lunch: `"Open · Closes 3:00 PM · Reopens 6:00 PM"`
     - lunch+dinner split mid-dinner: `"Open · Closes 10:30 PM"` (no reopen)
     - 24-hour venue: `"Open · 24 hours"`
     - midnight-crosser, opened yesterday: `"Open · Closes 3:00 AM"`
     - midnight-crosser, opens today / closes tomorrow:
       `"Open · Closes Tue 2:00 AM"`
     - three-session venue mid-breakfast: picks lunch as the
       reopen.
     File total now 23 tests, all green locally.

  **7. `package.json`** — `0.61.245 → 0.61.246`.

    2:00 AM`) but a user reading the card late at night might
    still be surprised by "Tue 2:00 AM" when the wall clock says
    Mon. Acceptable — the day label disambiguates.
  - The `regularPeriods` field is stripped from the v0.61.246
    `/nl-query` payload before send (existing code at line
    ~14870 `delete v.regularPeriods`); the `openClosingLabel`
    is computed BEFORE that delete, so the label travels but
    the periods don't.
  - No FR-localised strings. The new label is en-only;
    `closedTodayLabel` was also en-only at v0.61.219 ship time.
    Future PR could move both to i18n keys.
