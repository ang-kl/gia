## New

### [HDR] #444 | 09:50 SGT 29-05-29 | v0.61.243 — GPS auto-detect | 5 files | 1 PR | 1 build |

- **[INTENT]** Make the TMA infer region / country / cityCode from
  the device GPS on mount, snap to the nearest real IATA city,
  re-anchor the map at the GPS location, and load 5 venues — all
  before the user lifts a finger. Falls back to Gemini for GPS
  outside the v0.61.242 ASEAN / Asia / AU-NZ / Oceania table footprint.

- **[DELTA]**

  **1. `web/cuisine/src/v2/App.jsx`** — new `autoDetect` useEffect.
     Declared immediately above the v0.58.4 warm-start effect so it
     runs first in React's commit order. One-shot via
     `autoDetectedRef`. Skips when `initialOverrides.location` is
     set (the bot's `/cuisine` handler deep-linked an anchor). When
     it runs, it CLAIMS `initialSearchDone.current = true` so the
     warm-start effect immediately below short-circuits — auto-detect
     owns the first venue load on this mount.

     Algorithm:
     ```
     1. Ask navigator.geolocation for a FRESH reading (separate from
        userLoc, which may have come from tryServerCache and be stale
        by 100s of km). Fall back to userLoc when GPS denied.
     2. nearestIataCity(target) from the v0.61.242 348-entry table.
        Trust the table when distance < 2000 km.
     3. Otherwise fire iataSnap(target) → /api/cuisine/iata-snap →
        Gemini for the nearest real IATA city globally. G4 pre-
        approved by operator via the AskUserQuestion answer
        "Always fire Gemini for unknown GPS" (recorded in the
        v0.61.242 journal). Last-ditch fallback: distant local
        entry even if >2000 km.
     4. Region routing:
        - detected.countryCode === 'SG' → region 'SG'
        - countryCode === 'MY' AND iata === 'JHB' → region 'JB'
        - else if country is one of the 16 OTHER_COUNTRIES (MY/ID/TH/
          VN/PH/BN/KH/LA/MM/AU/NZ/JP/KR/CN/HK/TW) → region 'OTHER' +
          countryPref = detected.countryCode
        - else (e.g. detected in India / Pakistan / UAE) → leave
          region + countryPref alone (CountryDropdown can't render
          a country it doesn't know — flipping would silently fall
          back to MY). Anchor + map + 5-place load still fire.
     5. setLocationAnchor({ lat, lng, name }) where lat/lng = GPS
        coords (per operator: "move my google view to my location")
        and name = canonical IATA-table name (so LocationField's
        cityPick sync picks the right code).
     6. setSearchCenter, saveUserLocation, saveCountryPref (fire-
        and-forget).
     7. runSearch({...state, ...stateDelta}, target) — explicit
        snapshot so we don't race the queued setState.
     ```

     Each step logs `[Cuisine-TMA-v2] auto-detect: …` so we can
     trace exactly which path fired on prod.

  **2. `web/cuisine/src/v2/components/LocationField.jsx`** — new
     useEffect inside `OtherLocationPicker` that syncs the local
     `cityPick` state from the incoming `anchor.name` prop. When
     App.jsx's auto-detect sets `anchor.name = "Kuala Lumpur"`,
     `citiesForCountry('MY').find((c) => c.name === 'Kuala Lumpur')`
     returns the entry with `code: 'KUL'` and the CityDropdown
     now displays "KUL" instead of "— —". Operator: *"city code
     to Kuala Lumpur"*.

  **3. `web/cuisine/src/v2/lib/api.js`** — new `iataSnap({lat,lng})`
     client. POSTs `/api/cuisine/iata-snap`, returns the parsed
     payload (or null on error so the caller can fall back to the
     local distant nearest).

  **4. `index.js`** — new `app.post('/api/cuisine/iata-snap', …)`
     endpoint. Auth via the existing `requireInitDataFromBodyOrHeader`
     middleware applied at `/api/cuisine/*`. Rate-limited at
     cap=200 per chat per window.

     The Gemini call:
     - Model: `gemini-2.5-flash` (same model family the rest of
       the bot uses; cheap + fast for a one-shot classification).
     - `thinkingConfig.thinkingBudget = 0` — disable the 2.5
       thinking phase (we want the IATA lookup back in <2 s).
     - `responseMimeType: 'application/json'` — Gemini emits
       valid JSON directly instead of a Markdown-fenced blob.
     - `temperature: 0.1`, `topP: 0.8`, `maxOutputTokens: 256`.
     - Per-call timeout: 15 s.
     - Prompt explicitly forbids invention ("Return ONLY a real,
       registered IATA code … If you cannot confidently identify a
       city with a real IATA code within 5000 km, return
       `{\"iata\": null}`. Do NOT guess."). Multi-airport metro
       rule baked in (TYO not HND/NRT, SEL not ICN, BJS not
       PEK/PKX, LON not LHR, NYC not JFK, OSA not KIX).
     - Response validation: regex-tests `iata` against `/^[A-Z]{3}$/`
       and `countryCode` against `/^[A-Z]{2}$/`; bails to `{iata:null}`
       on parse failure or shape mismatch.
     - Cache: 24h Redis, key `iatasnap:v1:<lat>:<lng>` with lat/lng
       rounded to 0.1° (~11 km cells). Steady-state cost ≈ zero
       once the popular cells warm up.

- **[KNOWN GAPS]**
  - **First-launch Gemini-call cold start**: the Gemini API can be
    slow on cold start (~3-5 s p99 on flash). For users physically
    in Europe / Americas / Africa, the first-ever launch may show
    "Locating you…" longer than usual. Subsequent launches hit the
    Redis-cached 0.1° cell and are instant.
  - **GPS denied + cache miss**: auto-detect falls through to userLoc
    (which itself fell through to SG centroid). Result: SG region,
    SG centroid anchor, generic 5-venue load. Correct fallback.
  - **Mid-session GPS change**: the autoDetectedRef pins the effect
    to a single fire per mount. If the operator walks from KL to
    Singapore inside the same session, the TMA won't auto-re-detect
    until next launch. Acceptable — the LocationField + region pill
    remain manual.
  - **Gemini quality**: the prompt forbids invention but Gemini Flash
    *can* still hallucinate a real-looking code. Server-side regex
    validation (`/^[A-Z]{3}$/`) catches malformed output but not a
    plausibly-shaped fake. v0.61.244+ could cross-check the returned
    code against the OpenFlights master list.
  - **Out-of-cities.js country**: when Gemini returns e.g.
    `countryCode: 'GB'`, the OTHER picker's country dropdown is
    limited to the 16 countries in `countries.js`. The pill flips
    to OTHER but the user can't see GB in the dropdown — the anchor
    works, but switching country manually is locked. Expanding
    `countries.js` to match `iata-cities.js`'s 40-ish ISO codes is
    a future PR.
