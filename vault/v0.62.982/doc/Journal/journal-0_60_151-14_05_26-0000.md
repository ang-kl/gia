## New

### [HDR] #116 | 00:00:00 SGT 14-05-26 | v0.60.151 | n/a kb | 1 PR

- **[INTENT]** Operator: *"Next build. Feature: /clipboard — 'remove' button for individual list stored. 'rename' the individual list. 'copy'."* Clarified by Q&A: **Copy = re-send as plain text** (no `<b>/</b>`, no map button; clean tap-hold → paste into other apps).

- **[DELTA]**

  **`clip-store.js`** — two new helpers:
  - `removeClip(redis, chatId, index)` — deletes one entry by its list index using the idiomatic Redis "`LSET` sentinel + `LREM 1 sentinel`" pattern. Atomic-as-Redis-gets; returns `true` when a clip was removed.
  - `renameClip(redis, chatId, index, rawName)` — stamps a user-supplied `name` field onto the clip's JSON record (`LINDEX` → mutate → `LSET`). Trim + newline-collapse + 60-char cap; empty/whitespace-only names rejected. Returns the saved name or `null`.

  **`index.js`** — three new callback-query branches under the `clip:*` namespace:
  - `clip:copy:<idx>` — fetches the clip, strips `<b>/</b>`, unescapes `&amp; &lt; &gt;`, sends without `parse_mode`. Telegram preserves the message so the user can tap-hold → Copy into other apps with clean line breaks.
  - `clip:rename:<idx>` — sets ephemeral `clip:rename-pending:<chatId>` Redis key (5-min TTL) to the target index, sends a Telegram `force_reply` prompt *"What name for clip N? (Reply to this message — 60 chars max.)"* (EN + FR).
  - `clip:remove:<idx>:ask` / `:yes` / `:no` — confirms inline, then `removeClip(redis, chatId, idx)`. Same confirm gate the existing `clip:clear:*` uses.

  **`index.js` `bot.on('message', …)`** — new pre-routing check: if `msg.reply_to_message` matches the rename prompt copy *and* a `clip:rename-pending:<chatId>` value exists in Redis, apply `renameClip` to the typed text and report success (or "clip no longer exists" failure) before the rest of the message-routing pipeline. The pending key is `del`'d after a single application so a stale reply doesn't get applied later.

  **`index.js` `runClipCommand`** — the listing now:
  - **Shows the user-supplied `name` when present**, falling back to the auto-cuisines label (`escapeHtmlForTelegram`'d so an `&` in a clip name doesn't break `parse_mode: 'HTML'`).
  - **Renders one row per clip with 4 buttons**: `N: 📤` (Resend, existing) · `📋` (Copy as plain text, new) · `✏️` (Rename, new) · `🗑` (Remove, new). The existing 🗑 Clear all button stays on its own row at the bottom. The previous single-row "📤 1 📤 2 …" strip is replaced.

  **`__tests__/clip-store.test.js`** — extended the fake-Redis stub with `lSet` / `lRem`; +8 tests:
  - `removeClip` — removes the right entry by index, compacts; out-of-range / invalid / missing-redis no-ops.
  - `renameClip` — stamps `name`, leaves `body` untouched; trims + collapses newlines + caps at 60; rejects empty/whitespace; null for OOR / missing-chat.
  - Module-surface check: `removeClip` and `renameClip` exported.
  - `__tests__/redis-stub.js` — added `lIndex` / `lSet` / `lRem` matching node-redis v4 semantics (count > 0 = head-to-tail, count < 0 = tail-to-head, count === 0 = remove all).

Future copy edits to that prompt must update the regex. (Or: switch to a sentinel field; logged but not done — low risk for two-locale strings.)
