# Journal — v0.62.694–695 (Hawker: the active card had no border; the card was 30 % air; glass → 40 %)

_(№ 1,034 — 01-08 '26 18:15 SGT)_

## New

### [HDR] v0.62.694 — Hawker carousel: accent border on the centred card, measured height

- **[INTENT]** Operator, on an iPhone 15 Pro Max screenshot of Hawker at v0.62.693:
  *"where is the border for active card in Hawker TMA. you see that the edge cards should be 70%
  glass-effect? also the card can be shorter, can you shorten it down by 15% until the pill to
  'details'"*.

- **[MEASURED FIRST, THEN FIXED]** All three points were checked against the running app (headless
  Chromium at 430×932, centres API mocked) before touching anything, reading each card's computed
  style:

  | | before |
  |---|---|
  | height | applied **128px** (`h-[8rem]`), natural content **90px** → **38px slack, 30 %** |
  | glass (edge cards) | `rgba(…/0.6)` + `backdrop-filter: blur(12px) saturate(1.4)` — **working** |
  | glass (centred card) | opaque, `backdrop-filter: none` — as designed |
  | border | **all five cards identical grey** `tg-border`; no accent anywhere |

- **[BORDER — confirmed, and the cause]** `cardOn = activePill === \`${c.name}|card\`` (`:511`) is set
  only by an explicit card **tap**. Scrolling the carousel updates `centeredIdx`, but that never
  reached the card — so the card the user had scrolled to carried the same grey border as the peeking
  ones, and nothing read as active. The operator's question had a factual answer: there was no border
  to find.
  `CentreCarousel` now passes `centred = !isWide && i === centeredIdx`, and the card takes the accent
  border on that. A **tap** still adds the stronger `ring-1 + shadow-xl + z-10`, so "scrolled to" and
  "selected" stay distinguishable rather than collapsing into one state. Wide layouts are untouched —
  there is no single centred card when several are in focus at once.

- **[HEIGHT — measured, not nudged]** The operator asked for 15 %; the measurement says the real slack
  is **30 %** (128px box, 90px of content). Rather than substitute one constant for another, the
  v0.62.693 Cuisine approach (D-63) is ported: `CentreCarousel` reads every collapsed card's natural
  height in a `useLayoutEffect` and pins them all to the tallest. `height:auto` is applied momentarily
  during the read, because once a height is set the content stops overflowing and `scrollHeight` would
  simply echo the applied value back. `h-[8rem]` / `h-[5.5rem]` remain the first-paint fallback.
  This lands the card exactly on the ▸ details pill, which is what *"until the pill to details"* asks
  for — the 15 % was the operator's estimate of the same target, and measuring hits it precisely
  instead of approximately. **Closes the structural half of O-109**: Cuisine and Hawker now use the
  same mechanism, so their heights can no longer drift apart by constant-tuning.

- **[GLASS — measured, question asked, then answered]** The edge cards **are** glass and always were:
  `background: rgba(…/0.6)` with `backdrop-filter: blur(12px) saturate(1.4)`, verified per-card; the
  centred card is deliberately opaque with no backdrop filter. That was the same 60 % Cuisine used, so
  the apps already matched.
  **"70 %" was ambiguous in the direction that matters** — it can mean *more glass* (fill 60 % → 30 %
  opaque, more map showing through) or *more opaque* (60 % → 70 % fill), and the two look opposite. It
  was left at 60 % and returned to the operator with the measured numbers rather than guessed.
  The operator resolved it: *"the glass - change all to 40% fill"* — so **more glass**, and **"all"**
  read as all three carousel card surfaces, keeping Cuisine / Hawker / Transport in lockstep as they
  already were. Shipped as **v0.62.695** in this same arc (`bg-tg-card/60` → `/40` in `ResultCard.jsx`,
  Hawker `App.jsx`, `StationCard.jsx`). Deliberately NOT applied to the other glass surfaces — the
  pills (`bg-tg-bg/90`), the footer dock (`liquid-glass-dock`, fixed at 75 % by an earlier operator
  decision) and the FABs (`/85`, `/75`) are different surfaces with their own settled values.
  Verified: emitted `.bg-tg-card/40` in all three compiled bundles, and measured at runtime as
  `color(srgb … / 0.4)` with the blur intact. **O-123 closed.**

- **[VERIFICATION (sandbox)]** Same harness, after the change:

  | card | height | natural | border |
  |---|---|---|---|
  | 0 (centred) | **90** | 90 | **`rgb(43,194,106)`** — accent |
  | 1–4 (peeking) | **90** | 90 | grey `tg-border` |

  Zero slack on every card, uniform across the strip, accent on exactly one. Hawker build green; full
  `npm test -- --run` **156 files / 3901 tests** green.

- **[KNOWN GAPS]**
  - The probe runs in the **dark** palette (`rgb(28,28,31)` card fill) while the operator's screenshot
    is light. The mechanism is palette-independent — alpha and `backdrop-filter` are the same rule
    either way — but the *appearance* of 60 % glass over a light map is not something this harness
    judged.
  - Fixture centres, not the live NEA dataset; row combinations were modelled on the screenshot.
  - The measurement re-runs on `[items, isShort, basisClass]` — same caveat as O-122 on the Cuisine
    side: a field arriving late without changing a dependency would not re-trigger it.
  - `centred` is phone-only by construction. If the operator wants an active border on wide layouts
    too, that needs a different rule, since several cards are "in focus" simultaneously there.
