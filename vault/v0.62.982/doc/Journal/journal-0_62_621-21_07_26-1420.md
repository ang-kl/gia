## New

### [HDR] v0.62.621 — a desktop side panel + Google-Maps place-details on the station card

- **[INTENT]** Operator, on **Telegram Desktop**, asked two things:
  1. *"I am using the desktop version of Telegram, should you auto-expand to take advantage of the HD
     aspect ratio?"*
  2. A **Google-Maps "Drawer/slide"** spec: *"implement a sliding bottom sheet (on mobile) or a side
     panel (on desktop) that displays place details"*, listing the standard Maps UI elements (grab handle,
     hero/carousel, primary metadata, action row, detailed info).

  Confirmed scope via **AskUserQuestion**: the side panel should kick in on **Desktop + landscape
  tablet**; add **all four** applicable card elements — **action row (Directions · Save · Share)**,
  **distance + walking time**, **collapsible today's hours**, **category + interchange chip**. Hero
  photo / reviews / **Call** were **omitted** — MRT stations carry no photo, review or phone data.

- **[DELTA]**
  1. **Desktop auto-expand — already wired, confirmed no change.** `web/transport/src/tg.js` (v0.62.617)
     already calls `requestFullscreen()` on `tdesktop`/`macos` so the Mini App opens wide. Answer to (1):
     **yes, and it does.** Caveat surfaced: `useViewport` desktop = `!coarse && width ≥ 1024`, so a
     Telegram window narrower than 1024 still falls to the phone/tablet layout.
  2. **Side panel (Slice A).** `web/transport/src/App.jsx` — new `wideLandscape` branch
     (`deviceClass === 'desktop' || (tablet && landscape)`) renders a fixed left `<aside>`
     (`w-360 / min-[1280px]:w-420`, header + scrolling station list / focused details + secondary panels)
     beside a right `<main>` holding the **live, interactable** map. Phone keeps the draggable bottom
     sheet; the two-panel LIST toggle still wins when `viewMode === 'list'`. A best-effort one-shot
     `navigator.geolocation` populates `userLoc`, threaded to every `StationCard`.
  3. **Station-card place details (Slice B).** `web/transport/src/components/StationCard.jsx` —
     (a) **category chip** in the name strip (`Interchange` / `MRT station`), translucent so it reads on
     both the coloured and white strips; (b) **action row** — **Directions** (Google-Maps directions
     deep link), **Save** (localStorage favourite toggle, `gia:tr:saved`), **Share** (Telegram share of
     the map location); (c) **distance + walking time** (haversine + ~80 m/min) flush-right when `userLoc`
     is known; (d) **collapsible "Train times"** toggle — Maps hours-dropdown style, collapsed to a today
     first/last summary and expanding to the full per-direction detail.
  4. **Pure helpers.** `web/transport/src/lib/station-card-utils.js` — `directionsUrl`, `shareUrl`,
     `haversineM`, `walkMinutes`, `todaySummary` (all React/DOM-free, unit-tested).
  5. **i18n.** `web/transport/src/i18n.js` — EN/FR keys `mrt.cat.*`, `mrt.act.*`, `mrt.walk`,
     `mrt.trainTimes` (other locales degrade to EN via `t()`).
  6. **Tests.** `__tests__/station-card-utils.test.js` — **+10** tests for the new helpers.
