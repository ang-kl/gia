## New

### [HDR] #91 | 13:30:00 SGT 03-05-26 | v0.44.2 | n/a kb | n/a lines

- **[INTENT]** Three real-world bug reports from v0.44.1 deploy:
  1. **`/p d` returns HTTP 404** — the CKAN `package_search` endpoint chosen in v0.44.1 was dead in production. data.gov.sg migrated off the CKAN platform; the old endpoint exists in name only.
  2. **`/p m` URLs open in Apple Maps on iPhone** instead of Google Maps. The v0.44.0 code used `places.googleMapsUri` (cid-based URL) which iOS Universal Links inconsistently route — sometimes to Google Maps app, sometimes to Safari which then opens Apple Maps.
  3. **`/p g` (and `/p c`) lack temporal grounding.** User asked something date-dependent; Gemini replied "As an AI, I don't have a real-time concept of today/tomorrow." The model can't ground in real-time data without us telling it the current time.

- **[DESIGN]**

  1. **`/p d` rewritten as dual-mode** in `prompt-query.js`:
     - **PATH MODE** (recommended): if input matches `/^\/?v\d+\//i` (e.g. `v2/real-time/api/2-hour-weather-forecast`, `/v1/transport/carpark-availability`) → GET `https://api-open.data.gov.sg/<path>` and return pretty-printed JSON. This hits the LIVE-DATA API the bot's weather/carpark modules already use successfully — proven stable.
     - **SEARCH MODE** (free text): tries `https://api-production.data.gov.sg/v2/public/api/datasets/search-datasets?query=<q>`. Defensive parsing of multiple possible response shapes (the v2 catalog API is undocumented). On error/empty, returns helpful message pointing user at PATH mode + the data.gov.sg website.
     - The CKAN endpoint is removed entirely — no fallback to the dead URL.
     - Path mode is the workhorse; search mode is best-effort.

  2. **`/p m` URL fix** — request `places.googleMapsLinks` field (not just `places.googleMapsUri`). Use `googleMapsLinks.placeUri` (the explicit `?q=place_id:ChIJ...` deep-link format) as primary, fall back to `googleMapsUri`, then to a synthesised `https://www.google.com/maps/place/?q=place_id:<id>` from the `places.id` we already have.
     - Also added `places.id` to the field mask so the synthesised fallback always has source material.
     - Why `placeUri` works on iOS: it carries the explicit `place_id`, which iOS Universal Links resolves directly to the Google Maps app (if installed). The cid-based `googleMapsUri` is sometimes interpreted by iOS as a generic location-query URL and routed to Apple Maps.
     - **Scope cut:** this fix is in `/p m` only. The same issue affects `/cuisine`, `/surprise`, `/eat`, `/drink`, `/recognised`, `/heritage-food` — all those venue cards use `googleMapsUri` too. Sweep deferred to v0.45.0 to keep this PR small.

  3. **SGT temporal grounding** — new `withSgtContext(prompt)` helper prepends:
     ```
     Current Singapore time: YYYY-MM-DD (DayOfWeek) HH:MM SGT.

     <original prompt>
     ```
     - Applied to `viaClaude` and `viaGemini` (both pass through). Not applied to `/p s` (search), `/p m` (places), or `/p d` (data) — those are deterministic API calls that don't need temporal context.
     - With this, "What's tomorrow in Singapore?" returns an actual date instead of "I don't know what tomorrow is."

  4. **HELP text expanded** — explains the dual-mode for `/p d` with concrete path examples (2-hour-weather-forecast, air-temperature, rainfall, carpark-availability), the SGT auto-context note for `c`/`g`, and the iOS Maps deep-link note for `m`.

- **[REUSED]**
  - `withFooter()` — both new dual-mode handlers wrap their successful responses with the v0.44.1 no-cache footer.
  - `axios` — same dep, no SDK additions.
  - The existing weather.js `api-open.data.gov.sg/v2/real-time/api/...` URL pattern.
