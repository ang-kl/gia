### [HDR] #233 | 00:20:00 SGT 19-05-26 | v0.61.29 — Cuisine LocationField moved above the map | ~3 kb | 3 files | 1 PR | 1 build |

- **[INTENT]** On the Cuisine TMA the editable `LocationField` was rendered inside the
  **collapsed** *Search criteria* section, so the search anchor could not be changed
  without first expanding that section — and the Google map itself has no text input.
  Above the map sat only a static `📍 <place> · N places nearby` status banner. The
  operator asked to move the editable field above the map. (Originally one of three
  changes in PR #499 / v0.61.13, which was closed unmerged — 16 versions stale,
  `mergeable_state: dirty`; this re-does just the location-field move against `main`.)

- **[DELTA]**
  - **`web/cuisine/src/v2/App.jsx`** — the static location-status banner IIFE above the
    map is replaced by `!userLoc ? <Locating…> : <LocationField …>`. The place count /
    search status (`locating` / `no match` / `N places nearby`) now rides as a `suffix`
    prop. The pick handler is hoisted out of the JSX into a named `onLocationSelect`
    callback (the v0.60.166 commit-anchor-only + v0.60.170 setSearchCenter contract is
    preserved verbatim in behaviour). The `LocationField` is removed from the collapsed
    *Search criteria* section (a comment marks the move).
  - **`web/cuisine/src/v2/components/LocationField.jsx`** — new optional `suffix` prop;
    when set it renders as a `· <suffix>` span between the resting label and the
    "tap to change" hint.
  - **`package.json`** — version `0.61.28` → `0.61.29` (PATCH).
