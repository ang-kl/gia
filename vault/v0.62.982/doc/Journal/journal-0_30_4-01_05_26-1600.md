## New

### [HDR] #62 | 16:00:00 SGT 01-05-26 | v0.30.4 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead "Nothing return when i ask @soleat … Create a 'log on' switch to show what it is doing per steps". Two strands:
  1. **Real-time per-step verbose mode** — toggle via `/log on` / `/log off` so the user sees exactly where the NL pipeline stalls or returns empty without me asking for Railway log paste-backs.
  2. **`GROUNDING_ENABLED` env flag** — defensive switch in case v0.30.3's Google Search grounding is the regression cause for "nothing return". Default ON; `GROUNDING_ENABLED=false` reverts to no-tools behaviour.
- **[DELTA]**
  - **NEW** `verbose-log.js` — Redis-backed per-chat verbose flag (`verbose:<chatId>`, 24 h TTL). Helpers `enable / disable / isEnabled / say(redis, chatId, sendFn, text)`. `say()` is no-op when verbose is off so call-sites need no guards.
  - **`index.js`** —
    - + `/log on|off|status` slash handler with copy: `🔍 Verbose mode ON. Every step of the NL pipeline will be mirrored back to this chat for the next 24 h.`
    - + `verbose.say()` peppered through `bot.on('message')` NL branch and `runNLFlow`:
      - `🔍 D750 received text (lang=en, 230 chars). Classifying intent…`
      - `🔍 D751 intent=food confidence=0.95 cuisines=[Peranakan, Indonesian, Korean] qualifier="Michelin-starred" lang=en`
      - `🔍 runNLFlow start lat=1.3025 lng=103.8347 …`
      - `🔍 Calling searchCuisine pipeline (~12-15 s typical)…`
      - `🔍 searchCuisine returned N venues in <ms> ms. Delivering now…` (or warning when 0)
      - `🔍 D752 runNLFlow EXCEPTION: <err.message>` (catch path)
    - + `setMyCommands` row `log — Verbose mode on/off — stream NL pipeline trace to chat`.
  - **`pipeline.js#reason`** —
    - `GROUNDING_ENABLED` env flag default true. When `false`, omits `tools` from the model config — same as pre-v0.30.3 behaviour. Logs `[Pipeline-Reason] grounding=ON|OFF model=… prompt_len=…`.
    - Flash-fallback wrapper now mirrors the tools setting (parity with primary call).
    - JSON-parse hardening: explicit try/catch around `JSON.parse`. On parse failure, logs `head` + `tail` snippets of the raw text and emits structured `D612` diag with `{err, head, tail}` so the next failure is debuggable from the trace alone. Same for the non-array case (logs `type` + `keys`).
- **[VERIFICATION (sandbox)]**
  ```
  node --check on index.js, pipeline.js, verbose-log.js → OK
  cd web/cuisine && npm run build → vite v5.4.21 ✓ in 2.91s
  ```
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[OPERATIONAL]**
  Two debugging paths now available:
  1. **In-chat real-time trace.** Send `/log on` → re-send the failing prompt → bot mirrors every step to the chat. Screenshot the trace.
  2. **Disable grounding.** If the trace shows reason returns `0 candidates`, set `GROUNDING_ENABLED=false` in Railway → redeploy. If reason then returns candidates, grounding was the regression. We then either fix the schema/parser or keep grounding off.
- **[KNOWN GAPS]**
  - Verbose-log messages are sent serially via `safeSend` — adds ~100 ms per message. For a happy-path search, total trace messages ≈ 5, so ~500 ms latency cost. Acceptable for a debug-only mode.
  - `/log` autocompletes for ALL users now. If we ever ship to public Telegram, restrict to admin user IDs via env allowlist. Acceptable for current single-user pilot.
  - Verbose mode is per-chat, not per-user. In a group chat, anyone toggling affects everyone. Group support is out of primary scope.
