  - Row visibility condition expanded to fire when ANY of the four chips is set (was just price + pet).

  **(5) Michelin walk-through slug→entryKey fix (P0).** Root cause: `michelin-2025.js` curated entries have schema `{ name, address, postal?, category, cuisine?, vegetarian?, halal? }` — no `slug` field. v0.60.198's filter did `walkState.seen.has(e.slug)` which is `has(undefined)` → always false; `recordWalk` got `slice.map((e) => e.slug).filter(Boolean)` which is `[]`. Seen-set NEVER grew. Every tap returned slice 1-12 forever.

  Fix:
  - **`michelin-walk.js`** — new exported helper `entryKey(entry)` returns `\`${entry.name}|${entry.address || ''}\`.toLowerCase()`. Same format as the legacy `michelinDedupKey` we stripped in v0.60.200 (now repurposed cleanly into the walk module).
  - **`index.js`** — handler swaps `e.slug` → `michelinWalk.entryKey(e)` in both the filter and the `newKeys` map.
  - **`__tests__/michelin-walk.test.js`** — 4 new tests for `entryKey` including a round-trip through `recordWalk` / `readWalkState`.
