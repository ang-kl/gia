- **[INTENT]** Delete the `SG_ONLY_SLUGS` whitelist module and remove its two consumer gates. Durian / Durian Pastry / Fruits chips become selectable in every region — including MY (KL/Penang/JB), ID, TH, VN, PH, JP, KR, etc. The country bias is now fully handled by the v0.61.271 `countryCode` plumbing and the v0.61.267 OTHER-mode Places `regionCode` filter.

- **[DELTA]**

  **1. Deleted** `web/cuisine/src/v2/lib/sg-only-slugs.js` (was 33 lines, defined `SG_ONLY_SLUGS`, `isSgOnlySlug`, `stripSgOnly`).

  Rationale: the v0.61.193 whitelist was justified at the time by Places' SG-biased data set and the curated `cuisines-vault` `searchQuery` strings hardcoding " Singapore". v0.61.267 closed the first half of that gap (OTHER picker uses autocomplete + Places `regionCode`); v0.61.271 closed the second half (server-side `regionSuffix` no longer defaults to ' Singapore', and request-body `countryCode` is forwarded end-to-end). The whitelist is now obsolete.

  **2. `web/cuisine/src/v2/App.jsx`** — the v0.61.193 SG-only strip useEffect (~6 lines) is gone. The import is replaced with an inline comment documenting the deletion. Region flips no longer mutate `state.cuisines`.

  **3. `web/cuisine/src/v2/components/CuisineCategoryDrawer.jsx`** — the `sgOnly` / `regionLocked` / "Singapore-only — switch region to SG" tooltip logic is gone. Chips are selectable in every region, governed only by the existing `maxSelected` cap. The `region` prop is still threaded through for future per-country UX hooks.

  **4. `package.json`** — `0.61.271 → 0.61.272`.

  **5. `doc/.serial-state.yml`** — commit 484→485, build 274→275, journal 472→473; re-anchored 30-05 '26 08:10 SGT.
