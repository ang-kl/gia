## New

### [HDR] #468 | 20:45 SGT 29-05-29 | v0.61.267 — OTHER picker unified with JB autocomplete | 3 files | 1 PR | 1 build |

- **[INTENT]** Make the OTHER-region picker (countries other than SG/JB) use the exact same autocomplete-on-keystroke flow that the operator likes in JB mode. Country dropdown drives `countryCode`, city dropdown drives the location bias, free-text input streams suggestions on every keystroke. The pre-v0.61.267 "type + 🔍 button + confirmation panel" model is removed.

- **[DELTA]**

  **1. `index.js`** — `/api/cuisine/place-autocomplete` accepts `countryCode`

  Pre-v0.61.267 the server hardcoded a two-way region→country mapping (`region === 'JB' ? 'MY' : 'SG'`). That's the wall the OTHER picker hit — it couldn't reuse this endpoint because the country code wasn't pluggable.

  Now the endpoint accepts an optional `countryCode` (ISO 3166-1 alpha-2) and uses it for both `regionCode` and `includedRegionCodes`. The legacy region→country shorthand is preserved as a fallback for chat-bot callers and pre-v0.61.267 TMA bundles.

  Cache key bumped from `placeauto:v1:${region}:…` to `placeauto:v2:${effectiveCountry}:…` so a "MY autocomplete biased near KL" doesn't share a slot with "MY autocomplete biased near JB" (different cities, different bias circles).

  **2. `web/cuisine/src/v2/lib/api.js`** — `placeAutocomplete` helper extended

  Accepts an optional `countryCode`; spreads it into the POST body only when truthy so the wire format stays backwards-compatible for callers that don't pass it.

  **3. `web/cuisine/src/v2/components/LocationField.jsx`** — `OtherLocationPicker` rewrite

  - **Removed**: `results` / `setResults` / `searching` / `noMatch` / `errorMsg` state; `doSearch` (placeSearchByCountry); `pickResult`; `cancel`; the confirmation results panel JSX; the explicit 🔍 search button on the expanded form; the `placeSearchByCountry` import.
  - **Added**: `suggestions` / `suggestionsQuery` / `loading` state; `debounceRef`; a `useEffect` that fires `placeAutocomplete({ input, lat: cityCentroid.lat, lng: cityCentroid.lng, countryCode })` on every keystroke (250 ms debounce, min 2 chars); `handlePick(s)` that calls `placeResolve` → `onSelect`; `handleKey(e)` that picks the top suggestion on Enter.
  - **Bias semantics**: the city dropdown's centroid is the autocomplete bias point. So typing "Pavilion" with KUL selected finds Pavilion KL; switching the city to BKK without retyping refetches with the new bias. Falls back to the anchor's lat/lng when no city is picked, then `undefined` (no bias) — the server treats no bias as "country-only, no circle".
  - **Pick semantics**: still `noAutoFire: true` (operator's v0.61.244 rule — OTHER picks set the anchor but wait for the explicit search gesture). The user picks a suggestion → anchor + collapse to compact pill → tap 🔍 on the pill to fire.
  - **City-pick semantics (operator's #6)**: unchanged. Picking a city from the dropdown still commits as anchor at that city's centroid with `noAutoFire`, so "country + city + no street → tap 🔍 → search at city centre" still works.
  - **Display guards (v0.61.265)**: kept verbatim. `_safeLabel(primaryText, secondaryText, typedFallback)` filters 'Unnamed' / country-only from every suggestion row. `_isCountryOnly` guards the resting label.
  - The 6 s idle reminder now reads *"Type to search"* / *"Tapez pour rechercher"* (was *"Tap 🔍 to search"*) — matching the new keystroke-driven UX.

  **4. `package.json`** — `0.61.266 → 0.61.267`.
