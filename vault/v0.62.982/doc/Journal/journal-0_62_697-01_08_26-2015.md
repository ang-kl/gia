## New

### [HDR] v0.62.697 — the "Other" Australia city list, grouped and foldable

- **[INTENT]** Operator, on a screenshot of the current 9-city Australia dropdown:
  *"Can you expand the 'Others' for Australia with its 6 states, each state having up-to-5 cities to
  search. fill in those cities that are not in present list … with a lite-thin hollow line separation
  by state and the state now in 2 font size smaller in the middle of the hollow line (1 character
  spacing before and after the state name)"*. Then, mid-build:
  *"can you make each state separation with … right-pointing (▸ / ▶) for collapsed states and
  down-pointing (▾ / ▼) for expanded states"* — so the divider became the control.

- **[DELTA — data]** `CITIES_BY_COUNTRY.AU` goes **9 → 33 cities**, each carrying a new `state` field,
  ordered so a group is contiguous. Mirrored into `web/menu/src/cities.js`, which the file header
  requires be kept in sync.

  | group | cities |
  |---|---|
  | ACT | Canberra |
  | NSW | Sydney, Newcastle, Wollongong, Coffs Harbour, Ballina |
  | VIC | Melbourne, Geelong, Bendigo, Mildura, Warrnambool |
  | QLD | Brisbane, Gold Coast, Sunshine Coast, Cairns, Townsville |
  | SA | Adelaide, Mount Gambier, Port Lincoln, Whyalla, Kingscote |
  | WA | Perth, Broome, Kalgoorlie, Geraldton, Karratha |
  | TAS | Hobart, Launceston, Devonport, Burnie |
  | NT | Darwin, Alice Springs, Uluru |

- **[SIX STATES, AND THE TWO THAT AREN'T]** The operator said "6 states". Australia has exactly six —
  NSW, VIC, QLD, SA, WA, TAS — and **Canberra is in none of them**: it is the Australian Capital
  Territory. Darwin and Alice Springs are Northern Territory. Canberra was already first in the list
  and is the national capital, so dropping it would be a regression, and filing it under NSW would be
  wrong. ACT and NT are therefore their own groups; the six that are states are grouped as asked.
  Flagged rather than silently decided.

- **[DELTA — the divider is the control]** `CityDropdown` draws a group row wherever `state` changes
  between consecutive entries: a hairline (`h-px bg-tg-border/60`) either side of the label, the label
  at `text-[11px]` against the rows' `text-[13px]` — two steps smaller — and a literal ` ` before
  and after it, because *"1 character spacing"* is one character, not a padding value that resembles
  one. The row is a `<button>` carrying **▸ (U+25B8) collapsed / ▾ (U+25BE) expanded**, the same pair
  v0.62.684 standardised on the carousel cards.
  **Default is every group EXPANDED**, so a list that previously showed its cities immediately still
  does; the triangles exist to fold 33 rows down to 8 headings. The group holding the **current pick
  is forced open** regardless of its fold state, so the selected city can never hide behind a fold.
  Countries with no `state` field (every one except AU today) render exactly as before — no group rows.

- **[A BUG THE FOLD WOULD HAVE INTRODUCED]** Arrow-key navigation walks `itemRefs` by index and calls
  `itemRefs.current[next]?.focus()`. A collapsed group leaves **null holes** in that array, and `?.`
  would have swallowed the miss and stranded the focus mid-list. Replaced with a `step()` that walks
  to the next ref that actually exists (and `edge()` for Home/End). This was reasoned about before it
  could be observed — a fold-and-arrow test is not something the current harness runs.

- **[THE SUITE CAUGHT ME — and it was right to]** `__tests__/iata-cities.test.js` enforces the
  operator's own v0.61.242 rule: *"must be country code and city code by IATA, non inventive"* —
  every code in `cities.js` must exist in `web/_shared/lib/iata-cities.js`. The first build failed on
  `"Wollongong" has code "WOL" which is NOT in iata-cities.js`.
  **This matters more than the fix.** The guard checks *cross-file consistency*, not real-world IATA
  validity — adding the 15 new codes to the canonical table makes the test pass whether or not the
  codes are correct. So the test cannot vouch for them, and neither can this sandbox: **WOL, BNK, GEX,
  BXG, MQL, WMB, MGB, PLO, WYA, KGC, GET, KTA, DPO, BWT, AYQ are asserted on my knowledge alone** and
  are called out in the PR for spot-checking. Recorded as **O-126** rather than left implicit.

- **[VERIFICATION (sandbox)]** Dropdown driven in headless Chromium against the real component:
  - default render — **8 group headers**, all `aria-expanded=true`, 33 cities in the stated order;
  - after collapsing QLD — that header alone flips to `▸ QLD` / `aria-expanded=false` and its 5 cities
    disappear (42 → 37 rows); every other group untouched;
  - no page errors.
  Cuisine + Menu builds green; full `npm test -- --run` **156 files / 3901 tests** green.

- **[KNOWN GAPS]**
  - **The 15 new IATA codes are unverified against any external source** (O-126). This is the one
    thing in this change that could be wrong in a way nothing here would notice.
  - `CityDropdown` had to be **temporarily exported** to drive it in the probe; the export was
    reverted and its absence re-checked (`grep -c "^export function CityDropdown"` → 0) before commit.
    A fifth argument for O-120: a permanent harness would not need to touch source at all.
  - Group headers are reachable by Tab and Enter but are **not** in the ↑/↓ option cycle — arrow keys
    still walk cities only, matching the listbox role. Not verified with a screen reader.
  - Only Australia carries `state` today. Malaysia's 15-entry list is already state-capital-shaped and
    is the obvious next candidate if the operator wants the pattern spread.
