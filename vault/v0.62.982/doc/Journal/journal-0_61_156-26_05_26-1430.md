## New

### [HDR] #357 | 14:30 SGT 26-05-26 | v0.61.156 — Set-location persistence + feature gate (PR 2/5) | 8 files | 1 PR | 1 build |

- **[INTENT]** Ship the three rules that turn the v0.61.155 pure
  classifier into a live, user-affecting system:
  - **§2.4 set_location with placeName.** A new fix coming in via
    `bot.on('location')` is reverse-geocoded to a human-readable
    placeName (e.g. "Raffles Place", "Johor Bahru City Square",
    "IOI Resort City"). The persisted record stores the placeName,
    never raw lat/long (the prior location-handler bug).
  - **§2.5 Feature gate for non-SG.** When the registered locale's
    mode is not 'SG', the SG-only commands (`/weather`, `/hawker`,
    `/recognised`) refuse with a bilingual EN/FR "this is SG-only"
    reply. TMA toggles + transport sub-modes will be wired in
    PR 5 with the UI changes.
  - **§2.6 Per-chatId persistence (no nagging).** A second fix
    that classifies to the SAME locale (same mode + same
    `administrative_area_level_1`) is reused silently — no
    "Location set to X" prompt. The boundary radius dimension
    arrives in PR 3.

- **[DELTA]**
  - **`location-locale.js`** (NEW, ~110 lines). Redis-backed
    persistence layer. Key shape: `userlocale:<chatHash>`
    (30-day TTL). Record:
    ```
    { mode, placeName, country, adminAreaLevel1, lat, lng,
      boundary, registeredAt }
    ```
    `boundary` is `null` here; PR 3 populates it.
    `setUserLocale` sanitizes the input shape (drops blank
    strings, non-finite numbers; coerces unknown mode → 'OTHER';
    defaults `registeredAt` to `Date.now()`).
    `clearUserLocale` deletes the record.
    `isSameLocale(prev, next)` — rule §2.6 predicate: same mode
    AND same `adminAreaLevel1` (case-insensitive trim).
  - **`location-classify.js`** (NEW, ~75 lines). Single-call
    orchestrator. `classifyAndPersist({ chatId, lat, lng, redis,
    reverseGeocodeFn, now?, radiusM? })`:
    1. `classifyLocation` (v0.61.155) → mode + country + admin
       + placeName + gated/geocoded flags.
    2. `getUserLocale` for prior record.
    3. If `isSameLocale(prev, candidate)`, return
       `{ changed: false, record: prev }` — DOES NOT bump
       `registeredAt` (silent reuse).
    4. Otherwise `setUserLocale(candidate)`, return
       `{ changed: true, record: candidate, prev }`.
    Returns `{ record, prev, changed, mode, gated, geocoded }`.
  - **`location-mode.js`** — adds `FEATURE_KIND` enum
    (`HAWKER` / `WEATHER` / `RECOGNISED` / `TRANSPORT_*` /
    `TMA_*` / `CUISINE_SEARCH` / `FREETEXT_SEARCH` /
    `MICHELIN_SEARCH` / `CARPARK` / `TRANSPORT_DRIVE` /
    `LOCATION`), the `ALWAYS_ALLOWED` set, the `SG_ONLY` set,
    and `isFeatureAllowed(mode, feature)` (positive list with
    defensive deny for unknown features). Exported. Used by
    PR 5 TMA toggles + by the new `isSgOnlyCommandAllowed`
    helper in index.js.
  - **`__tests__/location-locale.test.js`** (NEW, 18 tests
    across 3 `describe` groups) — round-trip, hashed
    per-chat keys, mode coercion, blank-string drop,
    non-finite drop, default `registeredAt`, 30-day TTL,
    closed-Redis no-op, clear, corrupt-JSON read; full
    `isSameLocale` coverage incl. case-insensitive +
    Selangor-vs-Wilayah-Persekutuan-Putrajaya, both-null-admin,
    cross-mode, null inputs.
  - **`__tests__/location-classify.test.js`** (NEW, 9 tests)
    — fresh SG / JB / Batam (within gate) / Putrajaya
    (gate-skipped — no geocode call); rule §2.6 no-nag silent
    reuse with `registeredAt` preservation; admin change still
    triggers `changed=true`; mode-flip; geocode-throws
    defensive OTHER; non-finite lat/lng.
  - **`__tests__/location-mode.test.js`** — +5 tests for
    `isFeatureAllowed`. Now 30 tests in this file.
  - **`index.js`** (5 edits):
    - `reverseGeocodeAddress`: cache key bumped
      `revgeo:addr` → `revgeo:addr:v2` so the new `country` +
      `adminAreaLevel1` fields aren't masked by stale v0.61.139
      `{ name, formatted }` entries. New fields populated from
      `findComp('country')` + `findComp('administrative_area_level_1')`.
      Backwards-compat: callers reading the old fields are
      unaffected.
    - `bot.on('location')` calls `classifyAndPersist` AFTER
      `setUserLocation` succeeds. Best-effort; failures log and
      fall through to the existing reverse-geocode reply. The
      `reverseGeocodeFn` arg adapts the existing
      `reverseGeocodeAddress` to the
      `{ country, adminAreaLevel1, placeName, formatted }` shape
      the orchestrator expects.
    - New `isSgOnlyCommandAllowed(chatId, command, lang)`
      helper next to `safeSend`. Reads
      `getUserLocale`; if mode is not SG, sends a bilingual
      EN/FR "this command is only available in Singapore"
      reply with the registered placeName and returns `false`.
      Conservative default — no userlocale record yet → returns
      `true` (preserves the v0.61.155 "unclassified user gets
      the SG experience" principle).
    - `/weather`, `/hawker`, `/recognised` each gain one line:
      `if (!(await isSgOnlyCommandAllowed(...))) return;`. Short-
      circuits the SG-only commands when the registered locale
      is JB / OTHER.
