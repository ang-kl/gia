> Operator spec (verbatim in-session, 10-06 '26): when the visible Michelin Star / Bib Gourmand
> batch spans multiple cities (MY example: KL + Georgetown), group the **visible cards** into city

### [HDR] #651 | 21:01 SGT 10-06-26 | v0.62.6 — Michelin city-grouped display: awardCity sections, city-jump rows, set-city/fit-bounds map rule | index.js + web/cuisine ×4 + lib/michelin-city-groups.js (new) + tests | 1 PR | 1 build |

- **[INTENT]** Operator: group visible Michelin cards by `awardCity` so users understand why some
  awardees sit outside the set location. Case A (set city has ≥1 visible card): map stays centred
  on the set city (pins visible), set-city cards first with **no** row, every other city group
  preceded by a city-jump row. Case B (zero in the set city, e.g. Putrajaya): country-level
  fit-bounds (≈ zoom 10 fallback), **every** group gets a row. Row copy exact:
  *"{cityGroupCount} Michelin picks in {city}"* — count is batch-local (**never** `8/12`, `8/67`,
  `8 of 67`); only `{city}` styled blue + italic + underlined + tappable; tap pans/fits the map to
  that city's visible pins with **no** reload / new search / setLocation change / order or
  pagination change.

- **[DELTA — server, annotation only]** `index.js` Michelin venue mapping — added
  `awardCity: entry.city || null` to the success object (~9566) **and** the Places-fail fallback
  object (~9610). Pure post-curation annotation: `entry.city` already exists on every non-SG
  curated entry (allEntries mapping ~9260); SG entries carry none → `null` → grouping no-ops.
  No change to which venues are returned, their order, or the walk.

- **[DELTA — shared display helper]** New **`web/cuisine/src/v2/lib/michelin-city-groups.js`**
  (pure ESM): `groupByAwardCity(venues, setCity)` → `{ caseA, groups:[{city, venues, isSetCity}] }`
  (first-appearance order, curated order preserved per group, set-city group hoisted, no-awardCity
  venues fold into a leading unlabelled group); `groupNeedsJumpRow(group, caseA)` (every labelled
  group except the set-city group in Case A); `initialFitPins(grouped)` (Case A → set-city pins;
  Case B → all visible pins); `pinsOf(venues)`.

- **[DELTA — TMA]**
  - **`App.jsx`** — new `fitPins` state (`{pins, token}`); effect recomputes per visible batch
    (Case A → set-city pins, Case B → all pins; cleared on non-Michelin pages); passes
    `michelinCity` (= `michelinSummary.city`, already in `michelinRemaining`) + `onCityJump(group)`
    to ResultPanel and `fitPins` to MapPanel. Jump tap → `fitPins` with a fresh token so repeated
    taps re-fit.
  - **`ResultPanel.jsx`** — card list branches: batches carrying `awardCity` render city sections
    (row via `tn('michelin.cityJump.before')` + a blue/italic/underline tappable city `<span>`,
    then that group's ResultCards with unchanged props); all other batches keep the existing flat
    list including the v0.62.5 `recencyBand` divider (mutually exclusive — the Michelin handler
    never stamps `recencyBand`, the cuisine search never stamps `awardCity`). Grouping runs on the
    visible page slice only — pagination ("12 at a time") untouched.
  - **`MapPanel.jsx`** — new `fitPins` prop + effect: `LatLngBounds` + `fitBounds(bounds, 48)`
    keyed on `fitPins.token`; 1-pin fallback `setCenter` + zoom 13; post-fit zoom clamped ≤15 (two
    near-identical pins would over-zoom). Existing centring/zoom for non-Michelin searches
    untouched (this effect simply never fires without `fitPins`).
  - **`lib/i18n.js`** — key `michelin.cityJump.before`: EN `"{count} Michelin picks in "` /
    FR `"{count} choix Michelin à "` (string stops before the styled city span).
