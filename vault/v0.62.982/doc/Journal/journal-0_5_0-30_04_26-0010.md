## New

### [HDR] #7 | 00:10:00 SGT 30-04-26 | v0.5.0 | n/a kb | n/a lines
- **[INTENT]** Bundled feature triad per Human Lead's "Unified iOS & iPadOS Strategy": (A) `gestureHandling: 'greedy'` for iPad single-finger pan, (B) inline keyboard under each Sanctuary read with **📍 Open Map** + **🚗 Directions** buttons, (C) AdvancedMarkerElement-based pins that show the venue name visibly on the map.
- **[DELTA]**
  - **`public/app.js`** — full rewrite of marker layer:
    - Loads Maps JS with `&libraries=marker&v=weekly`; awaits `google.maps.importLibrary('marker')` to grab `AdvancedMarkerElement`.
    - `initMap` adds `mapId: 'GIA_SANCTUARY'` (required by AdvancedMarker) and `gestureHandling: 'greedy'`.
    - New `makePinContent(num, name, isUser)` builds an HTML pin: red numbered disc + white name chip. User-position pin styled blue with "You".
    - Reads `?placeId=` query param; if present, filters venues to that one pin and zooms to z17. Empty/no-match → falls back to full 3-pick view.
  - **`public/index.html`** — adds `.gia-pin`, `.gia-pin .num`, `.gia-pin .name`, `.gia-pin.user` CSS.
  - **`index.js` `deliverPicks`** — Sanctuary read message now sent via `bot.sendMessage(..., { reply_markup: { inline_keyboard: [[...]] } })` with two buttons:
    - **📍 Open Map** → `web_app: { url: https://<domain>/app?placeId=<id> }` (only when `useWebhook === true`).
    - **🚗 Directions** → `url: https://www.google.com/maps/dir/?api=1&destination=<name>&destination_place_id=<id>` (Google's documented Directions URL Schema).
    - When no Sanctuary read text is available but a placeId exists, sends a minimal carrier message (`🌿 <name>`) with the keyboard so the buttons still appear.
  - **`package.json`** — version → 0.5.0.
- **[RISK]** Low–Medium —
  - `mapId: 'GIA_SANCTUARY'` is a placeholder ID; produces a console watermark warning but functions correctly. Future task: register a real Map ID in Cloud Console for cloud-styled basemap (logged in Register).
  - `web_app` inline buttons require HTTPS and only work in private chats from the bot — both already satisfied.
  - AdvancedMarker click event sometimes does not bubble in older Maps versions; pinned to `v=weekly` and uses the supported `addListener('click', ...)` pattern.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]** Manual on iPadOS:
  1. `/eat` → location share → 3 picks arrive.
  2. Each Sanctuary read message shows two inline buttons. Tap **🚗 Directions** → Google Maps opens routing screen to that named place. Tap **📍 Open Map** → TWA opens with that single pin centred.
  3. From the menu button (full 3-pick view) → markers display venue **names** directly on the map without hover. Single-finger pan works.
- **[NEXT]** Phase 4 — GrabID PKCE for live quietness signal (Register Open #6).
- **[ADVICE]** AdvancedMarkerElement with HTML content is the right modern primitive for branded pins. The legacy `Marker.label` is too small and constrained for venue names. The `mapId` requirement is awkward but unavoidable.
