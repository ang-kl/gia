## Amendments

### `cooking-methods.js` — `COMMON_DISH_LEADING_BLOCKLIST` (the `/s` common-word hijack)

> Prior (v0.60.129): the `data/cooking method reference by cuisine.md` UNION-merge added ~3 900 method entries to `COOKING_METHODS`; the matcher's single-token / ordered-prefix rules fired on the *bare leading word* of multi-word entries.
>
> Change (v0.60.131, in PR #367's branch): added `COMMON_DISH_LEADING_BLOCKLIST` — food-component nouns, cooking-state adjectives, common fruit/veg/protein/drink words, and a handful of Western dish names. An entry whose first token is in that set no longer matches via the single-token-substring rule or the ordered-prefix rule (it still matches when the user supplies ALL its tokens, e.g. "/s curry-leaf crackling"). So `/s ramen` / `/s pizza` / `/s chicken` / `/s beef` / `/s fish` / `/s rice` / `/s noodle` / `/s soup` / `/s curry` / `/s egg` / `/s tofu` are no longer hijacked into the cooking-method pivot; distinctive method words (mohinga, tahdig, schnitzel, agemono, tadka, dum, wok hei, flambage, dim sum, …) are untouched. Regression test block in `__tests__/cooking-methods.test.js`. Rationale: the v0.60.129 .md merge made `/s` effectively broken for almost every common query.

### `handleSearchTurn` — resolver ordering (R.E.D first)

> Prior (≤ v0.60.133): order was technique short-circuit → Gemini `classifySearchIntent` (which can flag a dish as `ambiguous` and emit a vaguer clarify than R.E.D's picker) → then the R.E.D `disambiguateTerm` pre-step → then `techEntry` fan-out / nation-overlay / cooking-method pivot / single-query.
>
> Change (v0.60.134): R.E.D `disambiguateTerm` runs first; when it owns the term it pre-empts the Gemini-`ambiguous` path, the technique short-circuit, and (via `!disambigDisclosure` gates) the `techEntry` fan-out and the cooking-method pivot. Rationale: a deterministic, more-specific resolver should win over the LLM step and the looser fallbacks.

### `i18n.js freetext.divider` — quoted prior, then the changes

> v0.60.133: `⇩─ Eateries with similar dishes or cuisine ─ ⇩\n⇩─ not exactly {dish} ─ ⇩` (doubled box-drawing dashes trimmed to one each side — operator: "ugly when separating … wraps"). The `{dish}` placeholder is now HTML-escaped at every call site (v0.60.135 hardening).
