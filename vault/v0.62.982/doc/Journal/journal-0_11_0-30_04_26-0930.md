- **[DELTA]**
  - **`index.js`** — location-share ack copy: `"📍 Got it — looking for X within 200m…"` → `"🌿 Sensing the sanctuary vibe — looking for X within 200m…"`.
  - **`vibe-suggest.js`** —
    - + `RADIAL_EXPANSION_M = [200, 500, 1000]`.
    - `validateWithPlaces(candidate, near, radiusM = SEARCH_RADIUS_M)` — accepts a per-call radius for both `locationBias` and the proximity gate.
    - `pickValidated` — loops candidate 0 through expansion radii, captures `activeRadius`, then validates candidates 1–4 at the same radius. Returns `{meal, venues, activeRadius}`.
    - Afternoon hint widened: `"cafés, bakeries, tea houses, coffee bars, dessert spots"`.
  - **`consultant.js`** —
    - `nearbyAnyOperational` `includedTypes` rebalanced: removed `point_of_interest` (matched ATMs/bus stops); added `coffee_shop` and `tea_house` (real Places New types).
    - `geminiSanctuaryRead` prompt now explicitly enumerates the keyword set per spec: `quiet, coffee, sanctuary, solo-friendly, calm, peaceful, study, work, single-seat, bar-seat, comfortable for one`.
  - **`vault.js`** — + `FUZZY_BUFFER_M = 50`. `queryVault` adds the buffer to the GEOSEARCH BYRADIUS arg (300 m → 350 m by default).
  - **`sync-vault.js`** — refactored to read input from (in priority): `--html=<path>` CLI arg → `data/Saved Places.html` auto-detect → hardcoded fallback. cheerio added; `parseHtmlForMapUrls(filePath)` extracts `<a href>` matching four URL forms (short/goo.gl/full/maps.google).
  - **`package.json`** — + cheerio. version → 0.11.0.
- **[SUPERSESSION]** This release **explicitly supersedes the v0.8.1 fail-fast (interpretation A) decision**. Human Lead's latest spec mandates staggered radial expansion (200/500/1000 m), which is the direct opposite of "max retry 1, no re-polling." The latest instruction wins; v0.8.1 prior-content preserved verbatim by reference; supersession logged in Feature Removed table row #10 and Technical Deprecated row #15 with full audit trail per AU-2.
- **[RISK]** Med —
  - **Cost ceiling raised.** Worst-case `/eat` is now ~$0.15–0.20 (up from ~$0.05–0.10 in v0.10.1). Documented in Technical §5.
  - **Radial expansion masks signal**: a venue accepted at 1000 m may not be a useful sanctuary recommendation. Mitigation: walk-time re-rank (v0.8.0) still surfaces farther venues lower; users see `X min walk` annotation.
  - **Cheerio dep**: established library, ~50 KB minified, no security concerns logged.
  - **Vault buffer** — minor over-inclusion of borderline venues; trade for fewer false negatives.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]** Manual:
  1. Tap 📍 share location → first reply "🌿 Sensing the sanctuary vibe…" within ~1 s.
  2. From a fringe location where the prior 200 m gate would fail → bot now expands to 500 m or 1000 m and may surface picks the prior version returned 0 for.
  3. Hidden Sanctuary still triggers if all radii fail. Reply mentions specifically `quiet`/`coffee`/`solo-friendly` review signals.
  4. Vault check absorbs ~50 m GPS drift — venues at 290–340 m from cached coords still surface.
  5. `node sync-vault.js --html=data/Saved Places.html` (when file is uploaded) parses the HTML and processes those URLs in place of the hardcoded list.
- **[NEXT]** Human Lead to (a) re-export Google Takeout with `Maps (your places)` ticked and upload `Saved Places.html` to `data/`, OR (b) just run the sync with the hardcoded URLs as before. Either path now works.
- **[ADVICE]** Radial expansion is the right escape hatch for sparse-coverage areas, but it introduces Goodhart's-law risk: a venue accepted because we expanded to 1000 m may be a poor recommendation that the user has to walk 12 minutes to. The walk-time annotation we already show should keep this honest.
