### [HDR] #158 | 14:50:00 SGT 15-05-26 | v0.60.191 — Cuisine TMA: in-app card price-range + 🐾 line · first-🔍-tap 6-venue cap (with v0.60.188 auto-reset compatibility fix) | 4 files, ~60 LOC | 1 PR |

- **[INTENT]**
  - **Issue B (in-app card render)** — v0.60.183 wired `priceRangeDisplay` + `allowsDogs` through the response payload AND through the server-side text renderers (`formatVenueBlock` for Copy-All, `formatTechniqueVenueBlock` for /s + /c chat results). But the Cuisine TMA's React in-app `ResultCard.jsx` never picked them up — only the legacy numeric `priceLevel` (1-4) renders as $/$$/$$$$ on a chip. Operator's question *"Where are the pet-friendly and cost range in the results template in (a) Cuisine TMA results, (b) the copy-to/copy, (c) free text?"* surfaced the gap. PR 1 closes (a).
  - **Issue C (first-tap latency)** — Cuisine TMA's initial open already fires `/api/cuisine/warm-start` capped at 5 venues. The user's first 🔍 Search tap then fires `/api/cuisine/search` capped at 12 — and Places-side travel-times + BestTime-footfall enrichment fan out per venue, so the first-tap latency scales linearly. Operator: *"Loading of Cuisine TMA is slow … lower the first 6 to load only."* Cap the first 🔍 tap (empty seen-set for chat × criteriaHash) at **6** instead of 12; subsequent taps keep the 12-cap so the per-criteria walk-through still hits the full pool in ~11 pages.
  - **Codex interaction fix** — pre-merge Codex review on the v0.60.190 attempt flagged a real interaction bug between v0.60.188's `autoResetOnLowCount` (TMA fires `resetSeen=true` when `venues.length < 12`) and the new 6-venue first batch: after tap 1 the TMA sees 6 < 12 → arms `resetSeen` → tap 2 wipes seen-set → server sees `seen.size === 0` again → returns another 6-venue first batch. **Stuck on 6 venues forever.** Fixed by adding a `firstBatch: bool` field to the server response and gating the TMA's auto-reset + visible hint behind a firstBatch-aware threshold (6 when firstBatch, 12 otherwise).
