  ### A. /cuisine Cuisine Picker — UX hardening
  - **v0.58.10** — `/cuisine <args>` copy-syntax tokeniser. `/cuisine thai halal $$ @Raffles_Place radius:5 region:JB` round-trips through a URL-hash that the TMA reads. Recipient pastes the command, picker re-opens with the exact state.
  - **v0.58.16** — Default-OFF Halal/newlyOpened (was ON, polluted blank-state results). Warm-start fallback to highly-rated when narrow seed yields < 3.
  - **v0.58.17** — Tier-1 responsive layout (max-w 640 → 1024). Gives the map breathing room on tablet/desktop.
  - **v0.58.20** — Bounded geolocation resolution (5 s GPS timeout → server cache → SG centroid).
  - **v0.58.21** — 30-min staleness gate on cached location; cuisine TMA ignores stale anchors and asks for a fresh GPS reading.
  - **v0.58.23** — Always-on Share-pin keyboard for `/location`; no-args `/cuisine` location-status banner.
  - **v0.58.26** — **/cuisine zero-coord guard.** Railway-log evidence showed the TMA firing `/api/cuisine/search` with `center=0.0000,0.0000` because every userLoc setter accepted any non-null coord, including `{lat:0,lng:0}` from buggy initData / cache / GPS paths. New `isValidCoord()` rejects zero/NaN/out-of-range across all paths. Server `/api/cuisine/search` now 400s on zero-coord. The bot's `/cuisine` handler now pre-resolves cached location and deep-links it via `#lat&lng` so the TMA opens already anchored.
  - **v0.58.27** — Free-text noise-guard (`looksLikePlaceQuery`) so "hi"/"ok"/emoji-only doesn't trigger a 5-restaurant reply with buddy footer. Reverse-geocode hardening: SG_CENTROID short-circuit, natural-feature filter (`/catchment|reservoir|park|river/`), TTL 24h → 1h. Cuisine "New" chip now auto-re-searches on toggle (was waiting for explicit 🔍 Search).
  - **v0.58.29** — Six Cuisine Picker UI fixes: sub-cuisine drawer full-screen → centered modal popup; search-criteria card subtle accent tint; map "Show your location" 📍 recenter button; auto-collapse search criteria after results; "Collapse ▴ / Edit search ▾" pill; html font-size 16px → 17px (+1pt across the TMA).
  - **v0.58.31** — Shared `venue-filters.js` deny-list. Strips multi-tenant building names (Lau Pa Sat, Maxwell Food Centre, SAFRA, VivoCity, etc.) at the source. Patterns are start-anchored so stalls inside complexes ("Tian Tian @ Maxwell", "JUMBO Seafood — Riverside Point") still pass. Wired into `/cuisine` search + warm-start, NL path, free-text. Replaces three duplicate inline `NON_FOOD_TYPES` Sets.
  - **v0.58.32** — Tell-Me brand passthrough: typing "sushi tei" prepends the verbatim text as the first searchText query when it's brand-like (3-40 chars, ≤ 4 words, contains letters). Inferred cuisines follow as fallback. "japanese food in raffles place" still picks up `["Japanese"]`.
  - **v0.58.41** — Cuisine copy-syntax now accepts bare `/cuisine` (was 400'd when no tokens). Warm-start results are shareable.

  ### B. /hidden — refactored to a single Gemini call (the long arc)
  - **v0.58.22** — *(predates v0.53)* Hidden-gems C1+C3+C4 deterministic evaluator + Claude C2/C5 with webSearch. Replaced rarity-score-only path that surfaced popular places.
  - **v0.58.28** — **Full rewrite to Gemini-with-Google-Search.** Per Human Lead's spec, the entire C1–C4 evaluation, source verification, distance check, and chain blacklist are handled by a single grounded Gemini call. New `gemini-client.js` wraps `@google/generative-ai` with the spec prompt + `tools: [{ googleSearchRetrieval: {} }]`. Anchor verification: cached lat/lng reverse-geocoded; "Singapore" / catchment / reservoir / park results re-prompt the user to type a place name. Output is the spec format verbatim.
  - **v0.58.30** — `/hidden` progress pulses every 12 s with rotating lines so users see life past 20 s during the Gemini-with-Search call.
  - **v0.58.31** — `/hidden` prompt EXCLUDE block expanded with explicit hawker / clubhouse / mall rules. Reported as "too tight" by Human Lead → reverted in v0.58.32 (single "Shopping mall food court chains" line restored). Specific names handled deterministically server-side via `venue-filters.js` for cuisine flows; /hidden trusts Gemini's judgment.
  - **v0.58.33** — `searchToolForModel(model)` picks `googleSearch` (Gemini 2.x) vs `googleSearchRetrieval` (1.x) by version regex. Gemini 2.0 renamed the tool — using the wrong name produces an immediate 400 INVALID_ARGUMENT.
  - **v0.58.34** — 3-step fallback chain. User's GEMINI_MODEL + detected tool → user's GEMINI_MODEL + opposite tool → known-good fallback. `degraded` flag in the response surfaces a one-line "fell back to <model>" hint to the user.
  - **v0.58.35** — Replaced dead `gemini-1.5-pro` fallback with a chain `[gemini-2.5-flash, gemini-2.0-flash, gemini-flash-latest]` after Railway logs showed the previous fallback target itself returning 404 on `v1beta`.
  - **v0.58.36** — `stripMarkdown()` removes `**bold**`, `__italic__`, `*single*`, ATX headings, backticks. Chunker regex relaxed `/(?=\n\d+\.\s+\S)/` so numbered headings starting with `**` (Gemini's emitted Markdown) still trigger a split. Output is now plain text.
  - **v0.58.37** — Tighten "hidden" definition: at-least-2 of {C1, C2, C3, C4} AND must include C1 OR C3. C2+C4 alone (popular + unique) is /cuisine territory. New EXCLUDE rule: > 300 reviews disqualifies unless C1 fires. Three template rows dropped per Human Lead: `Criteria met:`, `Confidence:`, `Sources:` block.
  - **v0.58.41** — Per-attempt deadline (60 s) + overall timeout (240 s); pulse cap at 10 (120 s coverage); "drafting the picks and citing sources" → "drafting the picks"; smart "Gemini overloaded — retry in a minute" / "/hidden timed out after 4 minutes" error messages instead of a debug dump when every attempt is 503.
  - **v0.58.42** — Tool regex now matches `*-latest` aliases as 2.x+. Dead `gemini-2.0-flash` removed from chain (Google retired it for new users). 503 transient retry: 2 s backoff + same-model retry within each attempt.
  - **v0.58.44** — **`thinkingConfig.thinkingBudget: 0`.** Web-research-validated finding from Google's own dev guide: dynamic thinking adds many seconds before the first token; setting it to 0 matches Gemini 2.0 Flash latency. Single biggest user-perceived speed win. Plus tightened `generationConfig` (`temperature: 0.3, topP: 0.8, maxOutputTokens: 3072`) and chain refresh `gemini-flash-latest → gemini-2.5-flash → gemini-2.5-flash-lite` (dropped slow 2.5-pro).
  - **v0.58.45** — Forbid fabricated `https://www.google.com/maps/place/<name>/@lat,lng/data=!1s0x<hex>` URLs (Gemini was inventing Place IDs and coords). Prompt rule + post-process `rewriteFabricatedPlaceUrls()` rewrites any `place/` URL into `…/maps/search/?api=1&query=<name>+Singapore`. Also strips "meets C3 and C4" / "Meeting C2+C4" criteria letters from "Why a gem" prose via `stripCriteriaLeak()`.

  ### C. /location — privacy + UX
  - **v0.58.25** — Keyword routing: `/location current` (and `now`/`here`/`me`/`my`/`gps`/`device`) folds into the no-args path.
  - **v0.58.42 follow-up** — Splits the keyword path: `/location current` now ONLY shows a Share-pin keyboard with "tap to share your current location" copy. Cached display reserved for bare `/location`. Bot can't auto-detect device GPS; the reply makes that the entire conversation, not a footer.
  - **v0.58.38 → v0.58.40 (REVERTED)** — `address-sanitiser.js` to strip Singapore floor-unit notation (`#08-123`, `31-02 Marina Blvd`) from displayed labels for privacy. Reverted in v0.58.40 after Human Lead reported it caused a `/hidden` loop in production. Re-introduction is open in Register; will land with proper guards on the next attempt.

  ### D. Operations + ops UX
