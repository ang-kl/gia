Ship: `/log on|off|status` already existed for the v0.30.4 user-facing NL chat trace; v0.60.161 reuses the same Redis flag (`verbose:<chatId>`, 24-h TTL) to also drive (a) Railway-side debug logging on Cuisine API hot paths + Michelin handler with Redis key TTLs surfaced, (b) Cuisine TMA client-side telemetry (fetch timing + `window.onerror` + `unhandledrejection`) POSTed to a new `/api/vlog` endpoint and surfaced as `[VLOG-CLIENT <chatId>] {…}` Railway logs. The outbound-HTTP-cache-header surface (Places + Gemini response Cache-Control / Expires / Age) is **deferred to a follow-up PR** as DF-40 because those axios calls live in `pipeline.js` / `gemini-client.js` / inside the Michelin Places resolver without a chatId in scope; threading chatId all the way down is a substantial refactor and was outside the scope of this single PR.

- **[DELTA]**

  **`verbose-log.js` extended (v0.30.4 → v0.60.161)** — preserved all existing exports (`enable`, `disable`, `isEnabled`, `say`, `TTL_S`). Added:
  - **`isOn(redis, chatId)`** — cached read (5-s in-process cache via `_cache` Map). The cache is the price gate: without it, every instrumentation call would pay one Redis GET, doubling per-request Redis traffic when verbose is OFF (cache returns false fast) AND when ON (cache returns true fast).
  - **`status(redis, chatId)`** — `{ on, ttlSeconds }` for the `/log status` reply.
  - **`vlog(chatId, payload)`** — direct emit (caller is expected to have gated on `isOn`).
  - **`vlogIf(redis, chatId, payload)`** — gate-and-emit one-shot.
  - **`vlogTtl(redis, chatId, key)`** — looks up `redis.ttl(key)` and emits `{ kind:'redis-ttl', key, ttl }`.
  - **`vlogTime(redis, chatId, label, fn)`** — wraps an async block with start/end timing; always runs the block, only emits when verbose is on; catches + re-throws so caller semantics are unchanged.
  - **`vlogHttp(redis, chatId, label, axiosResponse)`** — extracts `cache-control` / `expires` / `age` / `content-length` headers; not wired at any call site in this PR (DF-40).
  - `enable` / `disable` now invalidate the in-process cache so a fresh `/log on` is visible to the next vlog call immediately (without waiting up to 5s for the cache entry to expire).

  **`index.js` `/log` command (~line 1619)** — same `bot.onText` handler; messaging updated to surface the three new log surfaces the toggle now drives:

  ```
  🔍 Verbose mode ON (24 h auto-off).

  • 🔍 step …   chat messages for NL pipeline runs
  • [VLOG <chatId>] …          Railway logs for /api/cuisine/* + Michelin handler (timing, Redis TTLs, HTTP cache)
  • [VLOG-CLIENT <chatId>] …   Railway logs for Cuisine TMA fetch timing + window errors

  Send /log off to disable, /log status to check TTL remaining.
  ```

  `/log status` now uses the new `status()` helper to surface `~N min remaining` from the Redis TTL.

  **`index.js` new endpoint `/api/vlog` (~line 8030)** — TMA-side telemetry sink. Gates: valid initData → chatId resolved → `isOn(redis, chatId) === true`. Emits `[VLOG-CLIENT <chatId>] {…}` to Railway logs. Caps payload at 4 KB (`String.length > 4096 ? … '…[truncated]'`) so a runaway client can't flood Railway logs. Silent reject (200 ok:false) on any gate fail — the client should not behave differently based on whether the operator has verbose on/off.

  **`index.js` `/api/cuisine/search` instrumented (~line 8780)** — at entry, `vlog.vlogIf` emits `{ kind:'cuisine-search-incoming', lat, lng, cuisines, filters, prices, region, radius, freeTextLen, resetSeen, lang }`. At exit, `vlog.vlogTtl` on `cuisine:session-meta:<chatId>` + `cuisine:session-seen:<chatId>`, then `vlog.vlog` with `{ kind:'cuisine-search-exit', ms, venues, exhausted, sessionFull, pageStackDepth, cached }`. The response body carries `_vlog: true` when verbose is on for that chatId so the TMA can flip its client shim. Error path also emits `{ kind:'cuisine-search-error', error, stack }` (top 6 stack frames).

  **`index.js` `/api/cuisine/copy-one` (~line 8069) + `/api/cuisine/copy-all` (~line 7813)** — entry/exit/error vlog blocks mirroring the search path. Captures `placeId`, `nameLen`, body bytes, `count`, `ms`. The existing v0.60.145 / v0.60.156 plain-text retry markers (`console.warn('[Cuisine] copy-one sendMessage failed (HTML mode)…')`) already exist as ungated warns; left as-is so they show up regardless of `/log` state.

  **`index.js` `handleMichelinSearch` (~line 5692)** — at entry (right after the existing `[Michelin] tap …` line), `vlog.vlogIf` emits `{ kind:'michelin-incoming', hash, seen, combo, isJB, freeTextLen, radius }` + `vlog.vlogTtl` on `cuisine:seen:<chatId>:<criteriaHash>`. At exit (right before the final `res.json`), captures `{ kind:'michelin-exit', ms, handlerMs, cacheHits, cacheMisses, venues, exhausted, reset, remaining }`. The response also carries `_vlog: true` when on. The early-exit "Michelin SG-only" path for JB region also tags `_vlog`.

  **`web/cuisine/src/v2/lib/vlog.js`** — new client-side module. Exports:
  - `setEnabled(on)` / `isEnabled()` — module-level boolean (not React state).
  - `noteServerHint(response)` — inspects `response._vlog === true` and flips on. Called from `lib/api.js` after every fetch.
  - `report(payload)` — fire-and-forget POST to `/api/vlog`. Uses `navigator.sendBeacon` when available (survives page-unload, perfect for error reports), falls back to `fetch({ keepalive: true })`.
  - `timed(label, fn)` — convenience wrapper for async with start/end timing.
  - `installGlobalHandlers()` — idempotent install of `window.addEventListener('error', …)` + `unhandledrejection`. Both serialize the first 4 stack frames to keep the payload compact.

  **`web/cuisine/src/v2/lib/api.js`** — `postJson` + `getJson` both wrapped with timing + `vlog.noteServerHint(json)` + `vlog.report({ kind:'fetch', method, url, ms, ok })` on success/failure. No new endpoints; the existing public helpers (`fetchCatalogue`, `searchCuisine`, `nlQuery`, `warmStart`, `startSession`, etc.) inherit the instrumentation transparently.

  **`web/cuisine/src/v2/App.jsx`** — on mount, dynamically imports `./lib/vlog.js` and calls `installGlobalHandlers()`. Dynamic import keeps the vlog module out of the critical-path bundle.
