## New

### [HDR] #99 | 22:30:00 SGT 03-05-26 | v0.51.0 | n/a kb | n/a lines

- **[INTENT]** Build a Hitachi-style /transport experience. Human Lead's request: "use official MRT schematic but incorporate the picture, by https://www.hitachi.com/rd/research/design/service/travel-information/index.html" + screenshot of JR's Yokohama-Line travel-info card (line badge + name + "Delay" status icon + cause + network map with affected line highlighted). Plain-text Telegram chat can't render a schematic, so the Hitachi-faithful experience lives in a new TMA; the chat message gets a per-line summary + a "🗺 Open MRT map" button.

- **[DESIGN]**

  1. **NEW `mrt-lines.js`** — single source of truth for SG MRT line metadata: code, English name, official LTA hex, emoji, endpoints, parent (for the Changi Branch). Ships a `parseStatusByLine(rawAlerts)` function that takes an LTA `TrainServiceAlerts` payload and returns a per-line `{status, cause, direction, time, raw}` map. `affectedLines(text)` regex-matches synonyms (EWL/East-West Line/east west, NSL/north-south, CCL/circle line, etc.). Most-severe-status-wins across multiple messages for the same line.

  2. **NEW `mrt-engineering.js`** — reads `data/mrt-engineering-closures.md` (committed, Human Lead curates). Schema per row: `date | line | direction | type | time | note`. Exports `upcoming(todayISO, days)` and `todayClosures(todayISO)`. Type vocabulary: `early-closure`, `late-opening`, `closure`, `extension-test`. Module-load memo cache (file is committed, no TTL needed).

  3. **NEW `data/mrt-engineering-closures.md`** — skeleton with 4 example rows (TEL/EWL/NSL/CCL across May–June 2026). Human Lead replaces with real SMRT/SBS-published advisories.

  4. **NEW `data/mrt-system-map.svg`** — hand-authored simplified SG MRT schematic (1000×800 viewbox). 10 lines as polylines (NSL/EWL/CGL/NEL/CCL/DTL/TEL + 3 LRTs) + 30 key interchange/terminal stations as circles + labels. IDs follow `line-<code>` and `stn-<code>` patterns so the TMA can mutate the DOM to highlight the focused line + mute others. Colours match official LTA palette (#009645 for EWL etc.).

  5. **NEW `web/transport/` TMA** — fourth TMA (after cuisine/menu/hawker). React + Vite + Tailwind, same scaffolding as the others. Components:
     - **`LineBadge`** — JR-style coloured letter tile (the "JH" badge in the Yokohama-Line reference).
     - **`SystemMap`** — fetches the static SVG, mutates DOM to flash focused line + mute others. Uses `applyHighlight()` on every focus change (no React-controlled SVG; cheaper).
     - **`LineStatusPanel`** — Hitachi-style side card. Shows: badge + line name + "For \<endpoint\>" direction + endpoints + status icon (▲ delay / ⛔ closure / ✕ disrupted / ✓ normal) coloured by severity + cause line + LTA notice excerpt (collapsible).
     - **`AffectedTicker`** — horizontal-scroll bottom strip of all affected lines. Tap to focus a different line on the map + side panel. Mirrors Hitachi's bottom marquee.
     - **`LocationCard`** — "📍 You are here" with reverse-geocoded address + nearest 3 MRT stations.
     - **`EngineeringList`** — next-7-days closure list with type-emoji prefix (🌙 early / 🌅 late / 🚧 closure / 🔬 extension-test).

  6. **NEW backend endpoints** in `index.js`:
     - `/app/transport` — serves the TMA index.
     - `/app/transport/mrt-system-map.svg` — serves the static schematic with 1h cache.
     - `/api/transport/status` — composes per-line status (LTA TrainServiceAlerts, parsed) + affected codes + upcoming engineering closures + (TODO) reverse-geocoded address. Open endpoint (same pattern as `/maps-key` in v0.46.1; no per-user data).

  7. **MODIFIED `runTransportTrain`** in `index.js` — adds:
     - Per-line breakdown ("⚠️ Affected lines: 🟢 EWL East-West Line — delay (signal fault) / [direction]")
     - "🔧 Upcoming engineering (next 7 d)" summary (top 5)
     - "🗺 Open MRT map (Hitachi-style)" web_app button → opens the new TMA
     - "🔄 Refresh" callback button

  8. **Build pipeline** — `package.json#scripts.build` adds `build:transport`; `postinstall` re-runs `build` so Railway picks it up automatically on next deploy.

- **[KNOWN GAPS / SCOPE CUTS]**
  - **No reverse-geocode in this PR.** `/api/transport/status` returns `address: null` — the LocationCard will hide. Wiring Google Geocoding API in is straightforward (~20 lines) but adds an API call per TMA open. Defer to v0.51.1 or batch with the next /transport iteration.
  - **No first/last-train countdown.** Needs station-level dataset from LTA MRTStation feed; deferred.
  - **The schematic is hand-authored, not the official LTA system map.** Human Lead asked for "official MRT schematic" — I authored a simplified 30-station version that follows the official line colours but omits most stations for legibility on a phone screen. If the official LTA SVG can be sourced (LTA system-map PDF), drop it into `data/mrt-system-map.svg` and the TMA picks it up automatically. The current SVG geometry is approximate; not geographically accurate.
  - **Engineering closures are seeded with 4 example rows.** Real SMRT/SBS advisories need to be transcribed into `data/mrt-engineering-closures.md`. The MD format is human-editable; one row per affected day.
  - **No "Update location" button on the TMA.** TMAs can request location via `Telegram.WebApp.requestLocation()` (newer API). Defer.
  - **AffectedTicker shows top 7 lines as fallback** when nothing's affected — purely so the UI is non-empty. Could be hidden instead; cosmetic.
  - **No CRL/JRL on the schematic** — they're not yet operational (CRL Phase 1 opens 2030, JRL 2027). The lines metadata flags them `future: true` so the chat code can skip them, but the SVG omits them entirely.
