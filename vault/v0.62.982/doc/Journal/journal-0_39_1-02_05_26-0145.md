## New

### [HDR] #80 | 01:45:00 SGT 02-05-26 | v0.39.1 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead — diff for `pipeline.js` supplied directly. Tightens `extractJsonArray` to tolerate top-level object shapes that occasionally drift back from Gemini (`{"venues":[…]}`, `{"candidates":[…]}`, `{"results":[…]}`). Without this, the v0.31.2 lenient parser only recognised top-level arrays; an object-wrapped response forced D612 parse-fail and zero candidates downstream.

- **[DESIGN]**
  1. **Trim once up front.** `candidate = (fenced ? fenced[1] : text).trim()` — was unconditional later. Slight tidying.
  2. **Preferred shape: top-level array.** Same as before — `[…]` slice between first `[` and last `]`.
  3. **NEW fallback: top-level object.** When no array is found, look for `{…}` between first `{` and last `}`. Try `JSON.parse`. Read `obj.venues`, `obj.candidates`, or `obj.results` (in priority order). If any is an array, return `JSON.stringify(arr)` — preserves the existing contract that callers `JSON.parse` the return value.
  4. **Silent fallthrough on object parse failure** so upstream `JSON.parse` still surfaces a useful D612 diagnostic with `head` + `tail` snippets.
  5. **No semantic change for arrays.** Existing top-level-array path is untouched; only adds a second-chance for object shapes.

- **[DELTA]** (per the user's diff)
  - **`pipeline.js#extractJsonArray`** — adds object-shape fallback with `venues` / `candidates` / `results` key lookup.
  - **`package.json` + `web/cuisine/package.json` + `web/menu/package.json` + `web/hawker/package.json`** — version 0.39.0 → 0.39.1.
