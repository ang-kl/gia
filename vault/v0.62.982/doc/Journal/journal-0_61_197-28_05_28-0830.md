## New

### [HDR] #398 | 08:30 SGT 28-05-28 | v0.61.197 — recent-locations drawer | 4 files | 1 PR | 1 build |

- **[INTENT]** The operator (and any user iterating across multiple
  meals/days at the same few spots) re-types Putrajaya / Bangkok /
  Tanjong Pagar repeatedly. A 10-entry recent-locations LRU surfaces
  those repeat anchors as a tappable inline keyboard so the user
  saves the keystroke + the geocoding round-trip.

- **[DELTA]**

  - **NEW `recent-locations.js`** (~110 lines, CommonJS):
    1. **`MAX_ENTRIES = 10`**, **`TTL_S = 180 days`**. Cap means
       stale entries naturally roll off as new ones arrive; the
       TTL is a safety net for accounts that go dormant.
    2. **`listRecentLocations(redis, chatId)`** — reads
       `recent-locations:<chatId>`, JSON-parses, returns `[]` on
       missing/corrupt/closed-redis.
    3. **`addRecentLocation(redis, chatId, entry)`** — validates
       lat/lng, normalises (5-decimal rounding, label trimmed to
       240 chars, optional 2-char uppercase country, optional
       16-char region), **dedups by (lat,lng) within ~11 m** so
       re-saving the same spot bubbles the existing row to the
       top instead of duplicating, then trims to `MAX_ENTRIES`.
    4. **`removeRecentLocationAt(redis, chatId, idx)`** — splices
       the indexed row; auto-DELs the key when emptied.
    5. **`clearRecentLocations(redis, chatId)`** — DEL.

  - **NEW `__tests__/recent-locations.test.js`** (13 tests):
    - Shape (`MAX_ENTRIES === 10`).
    - Add/list: empty → 1 entry → invalid input rejection →
      dedup-bubble → cap-trim (15 in, keeps newest 10) →
      country/region pass-through.
    - removeAt: drop indexed row → out-of-range → negative.
    - clear: list empties.
    - Defensive: null redis → `[]` / `false`; corrupt JSON → `[]`.

  - **`index.js`** (5 edits):
    1. **Top require** — destructures `listRecentLocations` /
       `addRecentLocation` / `removeRecentLocationAtIdx` from
       `./recent-locations`.
    2. **NEW `/lrecent` (alias `/lr`) handler** — renders the LRU
       as an inline keyboard. Each row carries flag + label (or
       `<lat>, <lng>` when label is empty) and callback_data
       `lr:<i>`. Footer row: `🗑 Clear all` / `✖ Close`.
       Empty-list path sends a usage hint instead of an empty
       keyboard.
    3. **NEW `lr:<idx>` / `lr:clear` / `lr:close` callback branch**
       in `callback_query`:
       - **`<idx>`** → looks up the entry, calls
         `setUserLocation` (preserving `region` + `label` opts),
         then bubbles it via `addRecentLocation` so the freshly-
         re-anchored spot moves back to row 1. `editMessageText`
         confirms `"✅ Anchor set: <flag> <label>"`.
       - **`clear`** → `clearRecentLocations` + edit message to
         "🕓 _Recent locations cleared._"
       - **`close`** → deletes the picker message.
    4. **Chat `/location <text>` success paths** all push to
       the LRU fire-and-forget:
       - The coded-location branch (MRT codes / bus-stop numbers
         / station exits) — pushes `{ lat, lng, label: coded.label }`.
       - The SG Geocoding-API branch — pushes
         `{ lat, lng, label: r.formatted_address, country: 'SG' }`.
       - The non-SG Places `searchText` branch — pushes
         `{ lat, lng, label, country: countryCode, region: 'OTHER' }`.
    5. **`/api/cuisine/set-location`** — TMA save-location
       endpoint now also pushes to the LRU (empty label since
       the TMA POSTs only lat/lng; the drawer renders these as
       `<lat>, <lng>` so the row is still tappable).

- **[KNOWN GAPS]**
  - Cuisine TMA save-location POSTs only lat/lng (the endpoint
    doesn't accept a label field). Recent-locations rows from TMA
    picks render as raw coords. A future PR could extend
    `/api/cuisine/set-location` to accept an optional `label`
    (e.g. the displayName of the picked place) so TMA rows look
    as nice as chat rows.
  - The `/lrecent` drawer doesn't yet support per-row delete (only
    clear-all). If row clutter becomes a problem we can add a
    callback `lr:del:<i>` with a confirmation prompt.
  - Recent locations are surface-only — they don't influence
    cuisine-search ranking or "near you" defaults. The drawer is
    a UX shortcut, not a personalisation layer.
