## New

### [HDR] #450 | 13:50 SGT 29-05-29 | v0.61.249 — Menu GPS auto-detect | 4 files | 1 PR | 1 build |

- **[INTENT]** Bring the Menu TMA into line with the v0.61.243
  Cuisine TMA behaviour: on mount, take the device GPS, snap to
  the nearest IATA city, re-anchor (region + country + label) when
  the location differs from the cached anchor — without the user
  lifting a finger. Falls back to Gemini for GPS outside the
  v0.61.242 ASEAN / Asia / AU-NZ / Oceania table footprint.

- **[DELTA]**

  **1. NEW `web/menu/src/iata-cities.js`** — parallel copy of
     `web/cuisine/src/v2/lib/iata-cities.js`. 348 entries +
     `nearestIataCity(lat, lng)` helper, identical to the Cuisine
     TMA version. The two TMAs are separate Vite apps with no
     shared package; this is the same parallel-copy convention used
     for `cities.js` / `countries.js` (see the v0.61.233 header
     comment on cities.js).

  **2. `web/menu/src/App.jsx`** — new `useEffect` declared just
     before the existing `isMy` derivation, after the anchor fetch
     useEffect. One-shot via `autoDetectedRef`. 800 ms wakeup
     delay so the v0.61.123 anchor fetch has a chance to resolve
     first (the drift check needs `anchor.lat / lng`).

     Algorithm (mirrors `App.jsx` v0.61.243 in the Cuisine TMA):
     ```
     1) navigator.geolocation.getCurrentPosition — 5 s timeout,
        60 s maxAge, enableHighAccuracy: false. Skip if denied /
        invalid.
     2) Inside-SG bbox + cached SG / no-anchor → skip outright
        (Menu TMA's home mode handles SG already).
     3) Drift check vs cached anchor: skip when GPS is within
        10 km of `{ anchor.lat, anchor.lng }`.
     4) nearestIataCity(GPS) from the 348-entry local table;
        trust when distance < 2000 km.
     5) Otherwise POST /api/cuisine/iata-snap (the v0.61.243
        Gemini-backed endpoint) for a globally-nearest IATA hit.
        Distant local fallback when Gemini fails.
     6) Gate on OTHER_COUNTRIES ∪ {SG}. Detected India / UAE /
        GB → skip (the Menu TMA's country dropdown can't render
        them, so flipping would emit a confusing half-state).
     7) POST /api/menu/set-location with the detected coords +
        canonical IATA city name + ISO countryCode. setAnchor
        with the server's returned label / region. Fire-and-forget
        /api/cuisine/country-pref sync.
     ```

     Each step logs to `console` so production behaviour can be
     reconstructed from Telegram remote-debug.

  **3. `web/menu/src/App.jsx` imports** — added `useRef`,
     `IATA_CITIES`, `nearestIataCity`, `OTHER_COUNTRIES`.

  **4. `package.json`** — `0.61.248 → 0.61.249`.

  **5. `doc/.serial-state.yml`** — commit 461→462, build 251→252,
     journal 449→450; re-anchored 29-05 '26 13:50 SGT.

- **[KNOWN GAPS]**
  - The 800 ms wakeup is heuristic. On slow networks the anchor
    fetch may still be in flight at 800 ms → first run sees
    `anchor === null` and skips the drift check. Acceptable —
    on a fresh user with no cache, the first auto-detect IS the
    initial anchor.
  - Gemini fallback adds one paid API call per cold launch from
    outside scope (G4 pre-approved by operator on 29-05 '26 via
    the v0.61.242 AskUserQuestion). 24h Redis cache in
    `/api/cuisine/iata-snap` keeps steady-state cost near zero
    once popular 0.1° cells warm up.
  - The drift threshold (10 km) matches Cuisine TMA. May feel
    aggressive for users who commute >10 km within the same
    metro — they'd see re-anchor at every launch. If that bites,
    consider raising to 20-30 km for Menu TMA specifically.
