### [HDR] #57 | 14:45:00 SGT 01-05-26 | v0.29.3 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead diagnostic screenshot — the v0.29.2 Diagnostics panel finally exposed the failure mode: D406 fired at 6 s into a request that legitimately needs 8–15 s end-to-end. The 6 s `searchCuisine` fetch timeout was below pipeline p50 latency, so EVERY happy-path search was tripping the dual-channel fallback, which in turn auto-closed the TMA per Telegram's sendData spec. The user's complaint "/cuisine screen closes so fast" is the visible symptom of this self-inflicted abort.

- **[DELTA]**

  - **`web/cuisine/src/App.jsx`** — banner copy updated from "Sensing the vibe… (this may take 5–10 s)" to "Sensing the vibe… (8–15 s typical — Reason → Fetch → Refine)" so the user mental-models the actual duration. D402 log label updated to `(25s timeout)`.
