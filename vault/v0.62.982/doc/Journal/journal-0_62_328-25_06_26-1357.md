# Journal — soleat v0.62.328 (Clipboard PR #1: storage groundwork — per-card HASH schema, TTL rule, cabinet/drawer/placement primitives, cascade-delete with favourite + ref-count rules)

> Operator: pre-cycle storage slice for the upcoming Clipboard Mini App. **No user-visible
> change** — the chat `/clipboard` flow and the existing `/api/cuisine/copy-{one,all}`
> writes continue to behave exactly as before. What changes is the underneath: clip records
> become per-card Redis HASHes (so a favourite card can carry `PERSIST` while a non-favourite
> catch-all card carries 30-day TTL — one shared LIST TTL couldn't express that), the LIST
> shrinks to a cardId-only index, and a new `clipboard-store.js` adds the cabinet / drawer /
> placement / cascade-delete primitives the next PR will wire to HTTP routes. Lazy migration
> on first read means zero downtime + zero data loss for existing users. Commit 860→861 /
> journal 754→755 / build 515→516.

- **[INTENT]** Per the locked Clipboard plan (`~/.claude/plans/consider-point-3-planner-logical-hamming.md`):
  the v0.7 Clipboard cycle splits into 4 PRs; this is PR #1, the **storage groundwork** that
  ships before any TMA / endpoint code. Operator-locked decisions baked in:
  - Cards become per-card HASHes so favourite cards can `PERSIST` (operator: *"favourite
    card will be kept forever and not be affected by TTL 30 days"*).
  - Cabinets capped at 12 per user; drawers capped at 20 per cabinet (one at a time);
    cards capped at 10 per drawer.
  - Cabinet name ≤ 80 chars; card note ≤ 990 chars.
  - Card duplicates across drawers are **permitted**.
  - Cascade-delete walks every card: keep if favourite; keep if still placed elsewhere;
    otherwise drop the HASH.
  - Drawer location uses the `{ lat, lng, label }` shape so PR #3 can plug the shared
    `LocationField` (cuisine TMA) into the drawer add-sheet without reformatting.

- **[DELTA]**
  - **`clip-store.js`** (rewritten, back-compat surface preserved) — Cards now live in
    `card:<chatId>:<cardId>` HASHes; `clip:<chatId>` is a cardId-only index LIST
    (PERSIST, cap 50). New helpers: `getCardById`, `recomputeCardTtl` (the **single
    source-of-truth** for the TTL rule table: favourite → PERSIST · placed → 1y ·
    catch-all → 30d), `softDeleteCard`, `newCardId`, `cardKey`, `locsKey`. Old-shape
    JSON entries migrate **lazily on first read** via `migrateOldShapeEntry()` so
    existing users see zero change. `listClips` filters dead entries (missing HASH)
    from results and lazy-LREMs by exact value after the iteration completes — never
    mid-loop (mid-iteration mutation would shift snapshot indices and break the
    `listClips → getClip(idx)` round-trip the bot's callback flows depend on).
    `removeClip` now applies the cascade rule: if the removed clip's card is
    favourite OR still placed in any drawer, the HASH survives in catch-all; otherwise
    `softDeleteCard` drops it. Public function signatures (`pushClip`, `listClips`,
    `getClip`, `clearClips`, `removeClip`, `renameClip`) unchanged — `index.js`
    callers at lines 4037-4124 + 7812-7839 keep working byte-identically.

  - **`clipboard-store.js`** (new file) — Cabinet ZSET `cab:<chatId>` (score =
    lastTouched), cabinet HASH `cab:<chatId>:<cabId>`, drawer metadata LIST

    card_locs inverse index SET `card_locs:<chatId>:<cardId>`. CRUD for cabinets +
    drawers + placements; cap enforcement on every write (12 / 20 / 10);
