# Journal — v0.62.706 (three device reports, one build bug and one missing layer)

_(№ 1,045 — 04-08 '26 14:35 SGT)_

## New

### [HDR] v0.62.706 — the handle that was 0px tall, and the controls that were never there

- **[INTENT]** Operator, from a device, on v0.62.704's itinerary map: *"the drawer for the cabinet map
  doesnt have handle like the other TMA. and is block at half layout the map / where are the embedded
  quick buttons and navigation cluster buttons in the map"*.

  Three reports. The first two turned out to be **one build bug**; the third was a genuine omission.

- **[REPORTS 1 + 2 — A TAILWIND CONTENT GLOB, AND IT WAS PROVABLE FROM THE COMPILED CSS]**
  `web/clipboard/tailwind.config.js` read:

  ```js
  content: ['./index.html', './src/**/*.{js,jsx}'],
  ```

  Every other TMA also lists `'../_shared/**/*.{js,jsx}'`. Clipboard did not — and v0.62.704 had just
  made Clipboard a consumer of `web/_shared/components/BottomSheet.jsx`. So Tailwind never scanned
  the shared sheet, and every utility it uses that no `clipboard/src` file *happens* to also use was
  silently absent from this app's stylesheet. Measured, clipboard vs hawker:

  | class | clipboard | hawker | what it does |
  |---|---|---|---|
  | `h-1.5` | **0** | 1 | the drag pill's **height** |
  | `touch-none` | **0** | 1 | `touch-action: none` on the drag band |
  | `cursor-grab` | **0** | 1 | the grab affordance |
  | `fixed`, `w-12`, `rounded-t-2xl` | 1 | 1 | coincidentally used elsewhere in clipboard/src |

  So the grabber rendered **48px wide and 0px tall** — *"doesnt have handle"* — and the band never
  set `touch-action: none`, so the WebView claimed the drag as a page scroll and the sheet would not
  move: *"block at half"*. Two symptoms, one line of config.

  The partial hits are why it looked *nearly* right: the sheet was still `fixed` and still
  `rounded-t-2xl`, because clipboard's own files use those classes for other things. Only the
  utilities unique to the shared file vanished.

- **[AND A GUARD — WHICH FOUND A SECOND CASE ON ITS FIRST RUN]**
  `__tests__/tailwind-shared-content-guard.test.js` walks each app's import graph into `_shared` and
  fails if a reached file carries `className` while that app's `content` omits `../_shared`.

  Its first version asked only *"does the app mention `_shared`?"* and immediately failed
  **`oversight`** — which imports exactly one thing, `_shared/lib/safe-area.js`, a pure module with
  no markup. Adding a glob there would have scanned files the app never renders and protected
  nothing. **The guard was wrong, not `oversight`**, so the guard was tightened to the question that
  actually matters: does the app reach a shared file that *contains class strings*? That also stays
  correct on its own if someone later adds markup to a lib file.

- **[REPORT 3 — THE MAP WAS INSIDE THE SHEET, AND HAD NO CONTROLS]** Two separate mistakes, both mine:

  1. **The map was a 240px box inside the sheet's scrolling content.** Every other TMA puts the map
     full-bleed *behind* and floats the sheet over it — which is the only arrangement in which the
     sheet's snaps mean anything, since the point of dragging the sheet down is to see more map. At
     the half snap the sheet showed the buttons and the layer panel and the map was below the fold.
     The map is now `fixed inset-x-0 top-0 bottom-14` (clearing the z-20 footer) at `z-[14]`, under
     the sheet's `z-[15]`, and goes `inset-0 z-[16]` when expanded.
  2. **Neither control cluster existed.** Added both, matching the other three verbatim: the left
     nav cluster (zoom-readout/Reset · ＋ · ↹ · － · ⇲, `w-7 h-7 rounded-full border shadow-md`,
     `gia-map-btn`) and the shared `MapControls` row + ⋮ overflow.

     One deliberate difference: the other panels' **Reset** returns to a hardcoded city centroid
     (`SG_CENTROID`, zoom 12). Here it returns to the **itinerary's own fitted bounds**, kept in
     `fitRef`. Their map is "Singapore"; this one is "your day", and a reset to Singapore would be a
     reset away from the thing being looked at.

     The map layers (pins / legs / circles / anchors) go to `MapControls`; **which drawers are
     shown stays in the sheet's day panel**, because that is itinerary content, not a rendering
     option.

- **[KNOWN GAPS]**
  - **Still not verified on hardware.** The probe stubs `google.maps`; a real SDK, real tiles and a
    real thumb are all different. This is the second consecutive version whose fix is proven only in
    headless Chromium.
  - **The stub is not the SDK.** It answers `Map`, `InfoWindow`, `LatLngBounds`, `Circle`,
    `Polyline`, `AdvancedMarkerElement` and `event` with the smallest thing that satisfies the
    caller. It proves the components mount and the effect does not throw; it proves nothing about
    what Google actually draws.
  - **The guard checks configuration, not output.** It asserts the glob is present, not that any
    particular class survived into the CSS. A different silent-drop mechanism — the opacity-modifier
    trap of v0.62.648, say — would still pass it.
  - `bottom-14` is a hardcoded clearance for the footer nav. Nothing ties it to the footer's actual
    height, so a footer change would leave a gap or an overlap.
