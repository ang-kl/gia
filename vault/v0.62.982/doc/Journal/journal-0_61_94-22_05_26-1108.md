### [HDR] #294 | 11:08 SGT 22-05-26 | v0.61.94 — overlap resolve | ~6 kb | 6 files | 1 PR | 1 build |

- **[INTENT]** Make the train-overlay station labels stop overlapping.
  v0.61.92 added an overlap-demotion pass, but the operator's screenshot
  showed "City Hall" still sitting on top of the "CC3" chip — the fix
  wasn't actually clearing the collision.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (+ the byte-identical
    `web/hawker/src/lib/mapOverlays.js` and
    `web/transport/src/lib/mapOverlays.js`) — rewrote `demoteByOverlap`.
    - Root cause: v0.61.92's pass kept the marker nearest the result as
      a full named pill and demoted only the rest. A kept pill is wide
      (a long station name → a ~170–220 px box), so it still covered
      its demoted neighbour — the overlap never cleared.
    - New behaviour: symmetric + iterative. Each round, *every*
      non-pinned marker whose box collides with another's is demoted
      one step (named pill → code chip → ~20 % smaller chip, floored at
      0.5×); the loop repeats until no collisions remain (8-round
      safety cap; marker boxes only ever shrink, so it converges). A
      3 px gap is added so markers don't settle edge-touching. A pinned
      (tapped) station is still never demoted. The `ref` argument is
      dropped — there is no nearest-first ordering any more.
  - **`web/transport/src/components/MrtMapPanel.jsx`** — the
    `demoteByOverlap` call site updated to the 3-arg signature; the
    now-unused `ovRef` computation removed.
  - **`__tests__/train-overlap.test.js`** — the `demoteByOverlap`
    suite updated for the symmetric behaviour (both overlapping pills
    demote, not just one) + two new cases: an iterative tight-cluster
    shrink down the chip ladder, and a wide long-named pill that
    overlaps a close neighbour.
  - **`package.json`** — `0.61.93` → `0.61.94` (PATCH).
