## New

### [HDR] #531 | 14:15 SGT 06-06-26 | v0.61.330 — Unified Michelin schema (city/country/year) + EMPTY per-city tables + loader | 13 files | 1 PR | 1 build |

- **[INTENT]** Make the Michelin layer deterministic per city. Today only Singapore is curated (`michelin-2025.js`, 130 entries: 2 three-star + 7 two-star + 32 one-star + 89 Bib Gourmand) and its entries carry no locality. To extend to the regional guides without ad-hoc shapes, every entry must declare WHERE and WHICH edition it belongs to. This PR (a) stamps each SG row with `city:'Singapore', country:'SG', year:2025` additively, (b) creates empty containers for the eight guide countries, and (c) adds a loader that merges + schema-validates the pool and exposes a `hasMichelinData` gate so a follow-up can light the Michelin option only where curated rows exist. **No data is fabricated** — the regional tables are empty by design; the curator fills them.

- **[MECHANISM]** The unified per-entry schema is `{ city, country, name, address, postal?, category, year, cuisine?, vegetarian, halal }` where `category ∈ {three-star, two-star, one-star, bib-gourmand}`, `country` is ISO-2, `year ∈ {2025, 2026}`. Rather than edit 130 curated object literals (risking a byte drift in hand-typed venue data), `michelin-2025.js` stamps the three locality tags **in place** via a single post-declaration loop over `[STARS_THREE, STARS_TWO, STARS_ONE, BIB_GOURMAND]`. The literal entries are byte-unchanged; the tags are applied at module load, so the exported arrays / `ALL` / every helper (`findMichelinMatch`, `getAll`, …) carry the new fields and all existing consumers keep their references. The new `michelin-data.js` loader merges `michelin-2025`'s `getAll()` with the (empty) per-country `ENTRIES`, validates each row (throws on a bad category / missing required field / non-ISO-2 country / bad year), defaults `vegetarian`/`halal` to `false` when unspecified, and builds a populated-set for `hasMichelinData`.
