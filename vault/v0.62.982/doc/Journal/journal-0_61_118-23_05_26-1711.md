# Journal — soleat v0.61.118 (Attractions ⚝ readability fix + cluster threshold/tile tune)

> Operator complaints (this session):
>   1. *"the Attractions icon ⚝ with dark background cannot see"* — the
>      `dotNode` ⚝ rendered in default text colour (black) on the purple
>      attractions dot, near-invisible at z12–13.
>   2. *"trigger the '7 ⚝ around here' at 500 px"* — wants more
>      aggressive clustering at low zoom and a more descriptive label.
>
> After a back-and-forth, the operator chose the tighter shape:
> `"<N> ⚝ here" / "<N> 🅿 here"`, **200 px tile at z<14 + 40 px at z≥14**
> (instead of 500 px constant — which would have flattened the existing
> v0.61.116 street-level grain), and threshold **8 → 7**.

## New

### [HDR] #319 | 17:11 SGT 23-05-26 | v0.61.118 — Attractions ⚝ readability + cluster tune | 1 PR | build 121 |

- **[INTENT]** Make the attractions ⚝ icon legible on the dark-purple
  amenity dot, and tighten the v0.61.116 cluster engine so low-zoom
  attraction-dense areas collapse into a single pill instead of dozens
  of overlapping ⚝ icons. Aligns the cluster pill wording across the
  two clustered layers (`<N> ⚝ here` / `<N> 🅿 here`).

- **[DELTA]**

  **Three byte-identical TMA copies** (`web/cuisine/src/v2/lib/
  mapOverlays.js`, `web/hawker/src/lib/mapOverlays.js`,
  `web/transport/src/lib/mapOverlays.js`):

  - `dotNode` (line 545) — inner glyph `<span>` gets `color:#fff` so
    character glyphs (⚝ on the attractions dot) render in white on
    the purple background. Emoji glyphs (🅿, 🌳, 👮, 🏥, 💊) ignore
    CSS `color` on every major platform and keep their native
    palette, so this change is a no-op for the carpark, parks,
    police, hospital, and clinic dots.
  - `applyClusterAndDrop` (line 1771) — `threshold` for attractions
    lowered 8 → 7. New `TILE_PX = (isAttraction && zoom < 14) ? 200
    : 40`, applied to `TILE_M`. Carpark unchanged (40 px constant).
  - Cluster pill text (line 1827) — attractions `items.length + ' ⚝'`
    → `items.length + ' ⚝ here'`. Carpark `items.length + ' 🅿 here'`
    unchanged. The `clusterW` estimate at line 1854 already uses
    `text.length * 7` so the wider pill self-registers its footprint.

  **`public/app.js`** (the standalone `/app/map` IIFE form, mirror):

  - `runClusterPass` (line 444) — gains `opts.tilePx` (default 40) so
    the same zoom-aware tile size can be wired in by the caller.
  - Attractions caller (line 856) — `threshold: 8` → `threshold: 7`;
    new `tilePx: zoom < 14 ? 200 : 40`; `clusterText: (n) => n + ' ⚝'`
    → `n + ' ⚝ here'`. Carpark caller untouched.

  Not touched: `overlayPin` (`public/app.js:397`). It renders the
  attraction ⚝ as text + drop-shadow with no background, so the
  "dark-on-dark" readability complaint doesn't apply on `/app/map`
  (no purple dot exists there). If a monochrome-mode visibility issue
  ever surfaces on `/app/map`, that's a follow-up.
