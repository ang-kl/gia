## New

### [HDR] #825 | 07:14 SGT 03-07-26 | v0.62.471 — taxonomy incremental checkpoint | 3 files | PR #(pending) |
- **Root cause.** `.github/workflows/draft-dish-taxonomy.yml` runs the git commit+push in a
  **separate step that only executes after `scripts/draft-dish-taxonomy.mjs` exits**. The script
  accumulated all classified dishes in memory and `writeFileSync`'d to the runner disk each batch,
  but disk writes don't persist — so the 6h cancel during the draft step never reached the push
  step and the entire batch (hours of grounded Gemini calls) was **lost**. Branch
  `bot/draft-dish-taxonomy` stayed at the *previous* good commit `5854c4b6` (09:26Z).
- **`scripts/draft-dish-taxonomy.mjs`** — added a `gitCheckpoint(label)` helper that
  commits + `git push --force`es the overlay to `bot/draft-dish-taxonomy` **from inside the batch
  loop**, every `PUSH_EVERY` batches (`DRAFT_PUSH_EVERY`, default 5) plus once at the end. First
  checkpoint makes the commit; later ones `--amend` it (one clean commit, force-pushed each time).
  **CI-only guard**: `CHECKPOINT = GITHUB_ACTIONS === 'true' && TAXONOMY_INCREMENTAL !== '0'` — so
  local runs and vitest keep the old behaviour (write file, no git). Errors in the push are caught
  and logged, never abort the run.
- **Idempotent resume.** The work-list already skips dishes present in the overlay, so a
  re-dispatch after a partial run **continues from the last pushed checkpoint** instead of redoing
  work. `DRAFT_MAX_BATCHES=170` is now safe to run repeatedly.
- **Workflow push step kept as a safety net** — after the script's final checkpoint the tree is
  clean, so its `git status --porcelain` guard prints "nothing to push" and exits 0; if
  CHECKPOINT is disabled or every push failed, it still performs the original end-of-run push.
- **[VERIFICATION (sandbox)]** `node --check scripts/draft-dish-taxonomy.mjs` passes. Guard keeps
  the classifier logic and its unit tests byte-for-byte unchanged outside CI.
- **[STATUS]** TOOLING — affects the manual `workflow_dispatch` taxonomy Action only; no runtime
  bot/TMA surface changes. Deploys on merge (script lives in-repo).
