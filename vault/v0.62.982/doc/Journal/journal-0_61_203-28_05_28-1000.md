# Journal — soleat v0.61.203 (TMA region auto-flip — always, regardless of userLoc source)

> Operator: "set IOI Resort City via chat → Cuisine TMA shows pin
> on Putrajaya but pill stays on 🇸🇬 Singapore → 0 results. this is
> repeated issue." Root cause: only one of the four userLoc-
> resolution paths in the TMA mount reads the `region` field. The
> bot's /cuisine deep-link emitted lat/lng to the hash but not
> region — so the URL-hash path silently lost the operator's
> intent. v0.61.203 closes the hole in 4 places.
>
> Commit 416 / journal 404 / build 206, on branch
> `claude/v0.61.203-tma-region-autoflip-fix` off `main` at
> v0.61.202.

## New

### [HDR] #404 | 10:00 SGT 28-05-28 | v0.61.203 — TMA region auto-flip (belt+braces) | 4 files | 1 PR | 1 build |

- **[INTENT]** End the recurring "pin says Putrajaya, pill says
  Singapore" bug for good. Belt + braces: the deep-link hash
  now CARRIES region, the TMA PARSES it from the hash, AND the
  TMA defensively reads server-cache region on every mount path
  regardless of where userLoc came from.

- **[DELTA]**

  **TMA mount paths** (after v0.61.203):

  | Source | userLoc | Region read |
  |---|---|---|
  | URL hash (bot `/cuisine` deep-link) | hash `lat/lng` | hash `region` (fast) + server fallback |
  | Telegram initData (device GPS via WebApp) | initData coords | server cache |
  | `tryServerCache` | server cache | server cache (inline) |
  | `navigator.geolocation` | browser GPS | server cache |
  | SG centroid fallback | hard-coded | server cache |

  All paths except `tryServerCache` (which already reads region
  inline) now follow up with one `fetchUserLocation()` to apply
  the server's region. The follow-up is idempotent (`setState`
  short-circuits when region already matches).

  - **`index.js`** — `/cuisine` handler (~line 1218):
    - `preResolvedAnchor` shape was `{ lat, lng }`. Now also
      carries `region: cached.region || null`.
    - URL params builder now also sets `region=<...>` when
      present.

  - **`web/cuisine/src/v2/lib/state.js`** —
    `readOverridesFromHash` now also reads the `region` URL
    param. Validates against the four-value enum
    (`JB` / `OTHER` / `MY-PUT` / `SG`). Legacy `MY-PUT`
    normalised to `OTHER` (mirrors v0.61.185).

  - **`web/cuisine/src/v2/App.jsx`** — mount useEffect
    restructured:
    1. **NEW `applyRegionFromAnchor(region)` helper** —
       normalises legacy `MY-PUT`, validates against the four-
       value enum, calls `setState((s) => ({ ...s, region }))`
       (idempotent). Logs the chosen target.
    2. **userLocSource tracking** — each path sets
       `userLocSource = 'hash' | 'initData' | 'serverCache' |
       'gps' | 'centroid'`. (Was: early-`return` per path; now:
       `if/else if` so the function reaches the unified
       follow-up.)
    3. **Hash path immediate region apply** — if the parsed
       hash carries `region`, call `applyRegionFromAnchor` on
       the spot. Faster than waiting for the server round-trip
       (network blip → user sees correct pill anyway).
    4. **Unified follow-up** — at the end of the chain, every
       source EXCEPT `serverCache` triggers one
       `fetchUserLocation()` → `applyRegionFromAnchor(r.region)`.
       This is the defensive guarantee: even if the bot omitted
       region in the hash, even if Telegram pushed device GPS,
       even if the user came in via GPS — the TMA ends up
       agreeing with the server.

  - **`package.json`** — `0.61.202 → 0.61.203`.
  - **`doc/.serial-state.yml`** — commit 415 → 416, build 205 →
    206, journal 403 → 404; re-anchored 28-05 '26 10:00 SGT.

## Amendments

- **`/cuisine` deep-link URL** — was: `#lat=X&lng=Y[&place=Z]`.
  Now: `#lat=X&lng=Y[&place=Z][&region=R]` when the cached
  anchor's region is non-empty.
- **`readOverridesFromHash`** — was: returned
  `{ location: { lat, lng, name } }`. Now: same plus optional
  `location.region` (validated, MY-PUT normalised to OTHER).
- **`App.jsx` mount useEffect** — was: early-`return` after
  each userLoc source set the value. Now: tracks
  `userLocSource`, applies region from hash when present, and
  fires one defensive `fetchUserLocation()` follow-up for every
  source except `serverCache`.
