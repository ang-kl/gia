## New

### [HDR] #32 | 14:30:00 SGT 30-04-26 | v0.20.1 | n/a kb | n/a lines
- **[INTENT]** Patch — Human Lead screenshot showed `/weather` returning the v0.18.0 reply ("Now: 25.7°C at S23") despite `/ver` confirming `soleat v0.20.0` deployed and `data.gov.sg NEA v2 16 stations (auth)` healthy. Root cause: duplicate handler bodies in `index.js` — the slash-command `bot.onText` handlers for `/weather`, `/transport`, `/carpark`, `/status` carried inline copies that drifted behind the unified `runWeatherCommand` / `runTransportCommand` / `runCarparkCommand` functions used by TMA tile taps via `routeMenuCommand`. The slash handlers never picked up the v0.18.2+ humidity/rain/wind block, the v0.19.0+ bus-arrivals block, or the v0.20.0 MRT-stations + network-crowd + 🔄 Refresh button.
- **[DELTA]**
  - **`index.js`** —
    - Replaced the inline `/weather` handler body (`bot.onText(/^\/weather…$/)`) with a one-line delegate `(msg) => runWeatherCommand(msg.chat.id)`.
    - Replaced the inline `/transport` handler body with a one-line delegate to `runTransportCommand`.
    - Added `/status` slash handler (alias) that also delegates to `runTransportCommand`. The pre-existing standalone `/status` handler (lines 494–509, separate from the alias comment in the old `/transport` body) which still emitted the v0.1.x "Gia CBD Pulse" reply was deleted in this same patch — its functionality is now identical to `/transport`.
    - Replaced the inline `/carpark` handler body with a one-line delegate to `runCarparkCommand`.
    - Net change: ~70 lines of duplicate/drifted code removed; four slash entry points now share the same single source of truth as TMA tile taps.
  - **`package.json`** — version 0.20.0 → 0.20.1.
- **[ROOT-CAUSE NOTE]** The drift accumulated across v0.18.2 (humidity/rain/wind enrichment), v0.19.0 (bus arrivals + 24 h location cache + 200 m radial fix), and v0.20.0 (MRT + network crowd + Refresh button). Each of those minors landed `runWeatherCommand` / `runTransportCommand` / `runCarparkCommand` updates and kept the slash `bot.onText` handlers as legacy v0.18.0 stubs because the TMA tile UX was the demo focus. iPadOS users hitting `/weather` directly never saw the new format. Patch policy update implicit in this fix: **slash handlers must always be one-line delegates to a `run*` function**; never inline command bodies again.

## Deleted

(Legacy v0.1.x `/status` handler emitting `Gia CBD Pulse` was removed from `index.js` in this entry. Functionally superseded by `runTransportCommand` since v0.18.0; the dead handler kept firing in parallel because `node-telegram-bot-api`'s `onText` runs all matching listeners. Behaviour change: `/status` now emits the same MRT + bus + crowd + Refresh-button reply as `/transport` rather than the bare three-line MRT-only message. Verbatim removed body preserved here per AU-5 / AU-7:

```js
bot.onText(/^\/status(?:@\w+)?$/, async (msg) => {
  try {
    if (!redis.isOpen) await redis.connect();
    const cached = await redis.get('lta:train_status');
    const data = cached ? JSON.parse(cached) : null;

    const response = data
      ? `Gia CBD Pulse\n\nStatus: ${data.status}\nNotes: ${data.message}\nRefreshed: ${data.updatedAt}`
      : "Gia is still waking up. Try again in 30 seconds.";

    await safeSend(msg.chat.id, response);
  } catch (err) {
    console.error('[Error] /status handler failed:', err.message);
    await safeSend(msg.chat.id, "Sorry, I can't reach my memory right now.");
  }
});
```)
