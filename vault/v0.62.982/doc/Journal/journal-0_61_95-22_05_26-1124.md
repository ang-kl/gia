## New

### [HDR] #295 | 11:24 SGT 22-05-26 | v0.61.95 — coloured monochrome lines | ~9 kb | 7 files | 1 PR | 1 build |

- **[INTENT]** Keep the train-line overlay coloured when monochrome
  mode is on, on all three map TMAs. The monochrome filter greyscales
  the map canvas; on the WebGL-rendered Hawker + Transport maps the
  line polylines composite into that canvas and grey out with it.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (+ the byte-identical
    `web/hawker/src/lib/mapOverlays.js` and
    `web/transport/src/lib/mapOverlays.js`) —
    - New exported `makeTrainColourOverlay(googleMaps)` factory: builds
      a `google.maps.OverlayView` subclass (lazily — `OverlayView` is
      undefined until the Maps script loads) that draws each train-line
      segment as an SVG `<path>` in the map's `overlayLayer` pane. The
      SVG lives in the DOM, outside the greyscaled canvas, so it stays
      coloured. It is `pointer-events:none` — purely decorative.
    - `createOverlayController` now tracks a `monochrome` flag (new
      `setMonochrome` method on the returned API) and a lazily-built
      `colourOverlay`. While monochrome is on, the train branch of
      `applyVisibility` feeds the overlay a coloured copy of every line
      (matching each line's tier opacity + weight) and every
      detail-highlight segment; while off, the overlay is detached. The
      underlying `google.maps` Polylines are left completely untouched
      — they keep handling clicks + the opacity tiers.
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** and
    **`web/hawker/src/components/HawkerMapPanel.jsx`** —
    `applyOverlayLayers` now calls `ctrl.setMonochrome(colour === false)`.
  - **`web/transport/src/components/MrtMapPanel.jsx`** — the Transport
    map renders its own line polylines (`renderPolylines`), not the
    controller's train layer, so it drives its own colour overlay:
    imports `makeTrainColourOverlay`, builds the overlay at map-init,
    `renderPolylines` feeds it segments, and a Colour/Train-Line
    `useEffect` (`syncColourOverlay`) attaches/detaches it.
  - **`package.json`** — `0.61.94` → `0.61.95` (PATCH).

- **[KNOWN GAPS]**
  - **No in-sandbox visual verification** (no Maps webview). The SVG
    overlay's pixel projection (`fromLatLngToDivPixel`) is the standard
    custom-overlay pattern but is unverified on-screen; a misprojection
    would show coloured lines offset from the map — cosmetic, not a
    broken map, and a clean revert. Normal colour mode is untouched on
    all three maps, so the failure mode is bounded to monochrome.
  - On the Cuisine (raster) TMA the base polylines are SVG and already
    escape the greyscale filter, so the overlay is redundant there —
    harmless (a coloured copy over a coloured line).
  - The `OverlayView` is DOM/Maps-dependent, so it is not unit-tested
    (the root Vitest is Node-only, no JSDOM — consistent with the rest
    of the TMA component code).
  - `doc/VibeCodingRecord/` regen still due (carried forward).
