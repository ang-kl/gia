### [HDR] #289 | 06:55 SGT 22-05-26 | v0.61.90 — train overlay: per-TMA zoom tiers | ~6 kb | 8 files | 1 PR | 1 build |

- **[INTENT]** Replace the single shared train-station rule (v0.61.87 —
  code chip below z15, named pill at/above z15) with a per-TMA, per-
  zoom-band matrix — squares / sized code chips / named pills, with
  per-TMA station-count caps and line opacity — plus a tap-to-pill
  behaviour and two map-control tweaks.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (canonical; byte-copied
    to the hawker + transport copies, all three md5-identical) —
    - `createOverlayController(map, googleMaps, opts)` — new third arg;
      `opts.tma` ('cuisine' | 'hawker' | 'transport', default
      'transport') drives the tiers.
    - New `trainTier(tma, zoom)` — resolves `{ station, scale, cap,
      opacity, other, emphasis }` per the operator matrix. Below z12
      all TMAs show small squares at 50% line opacity.
    - New `squareStationNode(hex, small)` — re-introduced (v0.61.87 had
      removed it) for the low-zoom + capped-remainder station marker.
    - `stationPillBase(scale)` / `stationCodeNode(codes, hex, scale)` —
      a `scale` arg (default 1) shrinks gap / padding / font-size so a
      code chip reads progressively smaller as the map zooms out.
    - New `trainStationNode(mode, st)` — marker content for a resolved
      mode ('sq-sm' | 'sq' | 'pill' | 'chip:<scale>').
    - `applyVisibility`'s train branch rewritten: per-tier polyline
      opacity; a nearest-N-to-anchor station set drives the chip cap
      and the Cuisine z15+ line emphasis (touching lines 100%, the rest
      50%); each station's marker mode resolves from the tier, with a
      tapped station forced to the full named pill. The `_mode` cache
      key is now the full resolved mode string.
    - `ensureGreyscaleStyle()` — appended a CSS rule shrinking Google's
      camera (pan/tilt/rotate) widget to 70% (scaled from bottom-left).
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** — pass
    `{ tma: 'cuisine' }` to `createOverlayController`; the bottom-right
    zoom readout restyled to a white-grey corner chip (`bg-black/55`
    → `bg-gray-200/90` + border, `bottom-3 right-14` → `bottom-1
    right-1`).
  - **`web/hawker/src/components/HawkerMapPanel.jsx`** —
    `{ tma: 'hawker' }`; same zoom-readout restyle (`bottom-3 right-3`
    → `bottom-1 right-1`).
  - **`web/transport/src/components/MrtMapPanel.jsx`** —
    `{ tma: 'transport' }`.
  - **`web/hawker/src/lib/mapOverlays.js` ·
    `web/transport/src/lib/mapOverlays.js`** — byte-copies of the
    canonical cuisine file.

- **[KNOWN GAPS]**
  - "Nearest to the result / focused centre" uses the map viewport
    anchor (`setAnchor`) — no venue/centre coordinates are wired into
    the controller; the viewport centre is taken as "what the user is
    looking at". Confirmed acceptable for Hawker (operator answer);
    applied to Cuisine by the same reasoning.
  - The camera-widget 30% shrink is a best-effort CSS rule
    (`.gm-style div:has(>button[aria-label*="ilt"])`) — Google's
    control DOM is not a public API. It no-ops safely if the selector
    misses; needs visual confirmation.
  - No in-sandbox browser verification (no Maps webview) — covered by
    `node --check` + the 5-TMA build + the test suite.
  - This intentionally re-introduces the `square` marker and the per-
    zoom station caps that v0.61.87 had removed.
  - `doc/VibeCodingRecord/` regen still due (carried forward).
