- **[DELTA]**

  - **Cabinet sort UI** (`web/clipboard/src/components/CabinetGrid.jsx`)
    - 4 sort chips: **newest** (default, by `modifiedAt`) · **A–Z** (by `name`) ·
      **location** (alpha by `location`, empty-locations sort last) · **trip date**
      (by `dateStart` with `dateEnd` fallback, then `modifiedAt` for cabinets with
      no dates).
    - Surfaced only when `cabinets.length > 1` (a single cabinet doesn't need
      sorting).
    - Sort is client-side over `state.cabinets` via `useMemo`; active key held in
      component state (**not persisted** — deliberately. Operator hasn't asked for
      a per-user pref and the 12-cap keeps re-sort cheap).
    - Sort chips use the existing `bg-tg-accent/20` + `border-tg-accent` active
      treatment, hint colour when inactive; horizontal-scroll on narrow viewports
      (no-scrollbar utility).

  - **Drawer manual reorder** (`web/clipboard/src/components/DrawerRow.jsx`,
    `CabinetView.jsx`, `App.jsx`)
    - Explicit `▲ ▼` arrows in the drawer header, stacked compact to the left of
      the segment emoji.
    - `canMoveUp` / `canMoveDown` computed against `totalDrawers` prop; arrows are
      visually dimmed (`text-tg-border`) when not actionable; `aria-label="Move up"`
      / `"Move down"` for accessibility; clicks are `stopPropagation`'d so they
      don't bubble into the collapse-toggle button next to them.
    - `onMove(from, to)` callback plumbed up: `DrawerRow → CabinetView →
      App → api.updateDrawer(cabId, from, { moveTo: to })` which hits **PR #2's
      PATCH /cabinet/:id/drawer/:n** endpoint. That handler re-keys
      `card_locs:<chatId>:<cardId>` server-side so the inverse index stays
      consistent across the shift (covered by PR #2's test
      `"PATCH moveTo reorders drawers AND keeps card_locs consistent"`).
    - Long-press drag of the whole drawer header **deferred** — arrows cover the
      common "move up one slot" intent and avoid fighting the existing card-drag
      long-press recogniser inside the drawer body.

  - **`cb.*` analytics events** (`clipboard-routes.js`)
    - NEW `track(redis, chatId, event, fields)` helper that wraps
      `vlogIf(redis, chatId, { ns: 'cb', event, ...fields })`. Never throws
      (analytics must not affect the user-facing response).
    - Emitted on the success path of seven handlers:

      | Event | Where fired | Notable fields |
      |---|---|---|
      | `cb.add_cabinet` | POST `/cabinet` | `cabId`, `hasLocation`, `hasDates` |
      | `cb.delete_cabinet` | DELETE `/cabinet/:id` | `cabId` |
      | `cb.add_drawer` | POST `/cabinet/:id/drawer` | `cabId`, `segment`, `hasLocation` |
      | `cb.place_card` | POST `/card/:id/place` | `cardId`, `cabId`, `drawerIdx`, `alreadyPresent` |
      | `cb.move_card` | POST `/card/:id/move` | `cardId`, `from`, `to` |
      | `cb.share_drawer` | POST `/cabinet/:id/drawer/:n/share` | `cabId`, `drawerIdx`, `cardCount` |
      | `cb.fork_drawer` | POST `/shared/:token/fork` | `token`, `forkedCount`, `intoCabinet` |

    - Gated by the per-chat verbose flag — `vlogIf` is a no-op when off; the
      Redis cost on the no-op path is at most one GET per request (the
      `isOn` cache TTL is 5s). Lights up as `[VLOG <chatId>] {...}` JSON lines in
      Railway logs only when the operator runs `/verbose on` for that chat.
