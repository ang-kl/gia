## New

### [HDR] #452 | 14:15 SGT 29-05-29 | v0.61.251 — Nearest cities.js by haversine | 4 files | 1 PR | 1 build |

- **[INTENT]** v0.61.250 made the city dropdown default to the
  country's capital on country change (or anchor-name match).
  That left two known gaps in the GPS auto-detect path:

  - **Hong Kong**: detected city "Hong Kong" (canonical IATA name
    for HKG in `iata-cities.js`) doesn't match any
    `cities.js[HK]` entry — all eight HK entries use district
    names (Tsim Sha Tsui / Central / Causeway Bay / Mong Kok /
    Wan Chai / Sha Tin / Aberdeen / Tung Chung), all with
    `code: 'HKG'` post-v0.61.242. v0.61.250 fell through to
    branch (b) "first entry = capital" → TST. Wrong city
    surfaced, even though they all carry the same IATA code.

  - **Sibu (East Malaysia)**: GPS auto-detect resolves to SBW
    (Sibu, real IATA in `iata-cities.js`). `cities.js[MY]`
    has 15 state capitals but no Sibu entry. v0.61.250 fell
    through to KUL (the capital, ~1000 km away on the other
    side of the South China Sea). Bad UX.

  This PR adds branch (b) **nearest cities.js entry by haversine**
  between the existing (a) name-match and the new (c) capital
  fallback.

- **[DELTA]**

     new module-scope `haversineKm(lat1, lng1, lat2, lng2)` helper


- **[KNOWN GAPS]**
  - No distance threshold on branch (b). If an anchor for some
    reason carries coords inside a country whose `cities.js`
    list is sparse + far (Hawaii anchor with country=NZ?), the
    nearest entry could be hundreds of km away. We accept this
    because (a) GPS auto-detect already gates by country, so
    cross-country drift shouldn't happen in normal flows, and
    (b) the alternative (silently falling back to the capital)
    is what v0.61.250 already did and what the operator wants
    closed.
  - The HK dropdown after auto-detect will show the specific
    district (e.g. "Causeway Bay") even when the user is in a
    DIFFERENT district. Their `HKG` code matches; visual label
    might surprise. Operator can manually pick another district
    from the dropdown.
  - Performance: 15-entry max (MY) brute-force per render is
    negligible (~30 floating-point ops). No optimisation needed.
