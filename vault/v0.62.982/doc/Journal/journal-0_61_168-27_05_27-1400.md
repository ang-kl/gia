## New

### [HDR] #369 | 14:00 SGT 27-05-27 | v0.61.168 — Carpark TMA map LAYER non-SG wiring | 4 files | 1 PR | 1 build |

- **[INTENT]** Close the v0.61.158 [KNOWN GAPS] entry. v0.61.158
  taught the `/api/geo/carpark` endpoint to accept
  `?mode=JB|OTHER&lat=&lng=` and fall back to Google Places (5 km
  radius). But the TMA's `createOverlayController` hadn't been
  told about the region, so `fetchCarpark` always hit the SG-only
  endpoint and the carpark toggle stayed `disabled: isNonSg` in
  `MapPanel.jsx`. v0.61.168 wires the mode through:
  - **Controller opt + setter**: `createOverlayController({..., regionMode})`
    + new `controller.setRegionMode(mode)`.
  - **fetcher rewrite**: `fetchCarpark({mode, lat, lng})` with a
    per-(mode, lat3, lng3) cache key.
  - **MapPanel**: passes the current region at init + `useEffect`
    that calls `setRegionMode` on region change.
  - **Toggle**: carpark row no longer carries `disabled: isNonSg`;
    `effectiveLayers` no longer force-offs carpark in non-SG.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (4 edits):
    1. `fetchCarpark` rewritten as `fetchCarpark(opts)` accepting
       `{mode, lat, lng}`. SG mode (or missing coords) hits the
       legacy `/api/geo/carpark`; JB/MY-PUT/OTHER + finite coords
       hits `/api/geo/carpark?mode=…&lat=…&lng=…`. Cache key
       collapses adjacent (~110m) anchors via 3-dp rounding.
    2. New `_invalidateCarparkCache()` helper.
    3. `createOverlayController` accepts `opts.regionMode`,
       stored in a mutable `regionMode` var (default `'SG'`).
    4. `ensureLayer('carpark')` passes the current `regionMode`
       + `anchor` into the fetcher.
    5. New `setRegionMode(mode)` method on the controller:
       updates `regionMode`, invalidates the carpark cache, drops
       the cached carpark layer entry (and its markers) so the
       next setLayer-on rebuilds with the new mode's data.
    6. `setAnchor` also invalidates the cache when
       `regionMode !== 'SG'` so anchor-pan in non-SG re-fetches
       the 5km radius around the new centre.
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** (4 edits):
    1. `createOverlayController(..., { tma: 'cuisine', regionMode: region || 'SG' })`.
    2. New `useEffect([region])` that calls
       `controller.setRegionMode(region || 'SG')` on every region
       change. Invalidates the carpark layer + cache so the next
       toggle-on re-fetches.
    3. `effectiveLayers` no longer zeroes `carpark` in non-SG.
       Comment notes the v0.61.168 reason: Places fallback works
       outside SG.
    4. `applyOverlayLayers` in non-SG passes through
       `{ carpark: layers.carpark }` instead of `{}` so the user-
       toggled carpark state survives the region switch.
    5. Carpark `rowToggle` entry drops the `disabled: isNonSg`
       flag (still in `disabled` for train + busstop since those
       feeds remain SG-only).
  - **`package.json`** — `0.61.167 → 0.61.168`.

- **[KNOWN GAPS]**
  - **Other SG-only layers still gated** (train, busstop, exits,
    taxis, parks, attractions, clinics, hospitals, police) —
    correct, those feeds genuinely lack JB/MY-PUT coverage.
    Carpark is special because Places has worldwide coverage.
  - **No automated test** — the wiring is React-state-driven UI
    that's hard to unit-test without React Testing Library +
    Google Maps mocks. Operator smoke covers it.
  - **No "loading…" indicator** while the Places fetch is in
    flight after a region switch. The first toggle-on in a new
    region waits ~500-2000 ms for the fetch; the layer renders
    silently. Acceptable for an owner-grade overlay; if users
    complain, a spinner is a future ~10 line addition.
  - **Places fallback cost** — each non-SG carpark fetch is a
    Google Places `places:searchNearby` call (~$0.005). Cache
    keyed by 3-dp anchor rounding (~110 m) keeps repeat-toggle
    cheap. At a typical JB session (one anchor + one toggle on)
    cost is negligible.
