## New

### [HDR] #843 | 10:12 SGT 04-07-26 | v0.62.489 — next-open always names the weekday | 1 code file + 1 test + 3 doc/meta | PR #(pending) |

- **[INTENT].** Kill the "whose today?" ambiguity in the 🕛 timing row. Instead of "Opens today
  11:30 AM" / "Opens tomorrow 11:00 AM" (both relative to the **venue's** local day), always show
  the **weekday**: "Opens Sat 11:30 AM" — unambiguous in any time zone.

- **Root cause (traced).** `open-hours.js` `nextOpenInfo` computed the next-open text as
  `P.opensToday(t)` for `delta === 0` and `P.opensTomorrow(t)` for `delta === 1`, where `delta`
  is measured against `localNow(now, offsetMin)` — **venue-local** time (`offsetMin` =
  `utcOffsetMinutes`). A user in another zone reads "today"/"tomorrow" against **their** clock,
  so a venue-local "today" can be the user's yesterday or tomorrow (the Wellington report).

- **[DELTA] (1 code file + 1 test).**
  - `open-hours.js` — `nextOpenInfo` now **always** builds the text via
    `P.opensDay(dayLabel(best.day, lang), time)`. The `delta` field is still returned, so
    `closedTodayString` keeps its "Closed now" (delta 0) vs "Closed today" (delta 1) prefix logic.
    The `opensToday`/`opensTomorrow` phrase keys are kept (now unused by `nextOpenInfo`) to avoid
    churn. All **8 locales** already carry `opensDay` + a `DAY_LABELS` row (en/fr/id/ru/de/zh/ja/es),
    so the change is fully i18n-safe.
  - `__tests__/open-hours.test.js` — **14 assertions** updated from today/tomorrow to the weekday
    form (Mon/Tue and their id/fr/ru/de labels: Sen/Sel, lun., Пн, Mo). Two `it()` titles renamed
    for accuracy ("returns weekday label …", "EN output — weekday form").

- **[VERIFICATION (sandbox)]** `node --check` clean on `open-hours.js`; a standalone node harness
  re-ran all 14 changed cases → **14/14 pass** (incl. the pre-existing >1-day "Opens Thu" case,
  unchanged). Full vitest + web build in CI (`web/cuisine` reads the same
  `openClosingLabel`/`closedTodayLabel` fields).
