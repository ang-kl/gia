## New

### [HDR] #66 | 17:00:00 SGT 01-05-26 | v0.30.8 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead "Fix H" — voice input via Gemini Flash audio. Item H from the open-list close-out: Telegram delivers OGG/Opus voice notes; Gemini 2.5 Flash supports inline audio input. Single-call transcribe + classify intent + extract cuisines / special_request / location_override / lang / ack_text — same JSON shape as text NL classifier so the rest of the pipeline doesn't need a separate code path.
- **[DELTA]**
  - **NEW** `voice-input.js` — `classifyVoice({bot, voice, redis})`:
    - `downloadVoice(bot, fileId)` — `bot.getFileLink` → axios `arraybuffer` → Buffer (8 s timeout, voice notes are tiny so OK).
    - Hard cap `MAX_DURATION_S = 90` to keep Gemini payloads bounded; longer clips return `{error: 'clip_too_long'}` and the user gets a clean message.
    - Prompt asks for `transcript` first (so we can mirror it back), then the same intent/cuisines/special_request/location_override/lang/ack_text fields as `nl-intent.classifyIntent`.
    - Cached per `voice.file_unique_id` (24 h) — re-sends are free.
    - Reuses `withRetry` + `makeFlashFallback` so Pro→Flash auto-fallback applies, with audio inline-data carried through both paths.
    - Console logs `[Voice]` prefix per transcribe.
  - **`index.js`** —
    - + `bot.on('voice', async (msg) => { … })` handler. Sequence:
      1. Send "🎙 Heard you — transcribing…" ack immediately.
      2. Call `classifyVoice`.
      3. Mirror `transcript` back as `📝 _Heard:_ "<text>"` so user can sanity-check the transcription.
      4. Branch on intent same as the text-NL handler:
         - `update-location` → drop pending state + `LOCATION_REQUEST_KEYBOARD`.
         - `food`/`drinks`/`groceries` (confidence ≥ 0.6) → geocode `location_override` if present, else cached GPS, else location-share keyboard. Then `runNLFlow` with extracted hints.
         - `other` → polite decline.
      5. Verbose-log emits new diag codes:
         - **D760** voice received (chat_id + duration + mime)
         - **D761** classify error
         - **D762** classify ok (intent + confidence + cuisines + qualifier + override + lang)
    - Existing `bot.on('message')` already guards `if (!msg.text) return` so voice messages don't double-process.
- **[VERIFICATION (sandbox)]**
  ```
  node --check on index.js, voice-input.js → OK
  node -e "require('./voice-input')" → exports {classifyVoice, MIN_CONFIDENCE, MAX_DURATION_S}
  ```
  Live audio round-trip not exercised in sandbox (no audio file or Telegram bot context).
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. After redeploy, hold-to-record a voice message in the bot chat. Say something like *"Find Korean food near Tanjong Pagar MRT"*.
  2. Bot replies "🎙 Heard you — transcribing…" within ~2 s.
  3. Bot mirrors `📝 _Heard:_ "Find Korean food near Tanjong Pagar MRT"` (so you can verify ASR was correct).
  4. With `/log on`: trace shows D760 → D762 → D708 (geocode) → D709 → runNLFlow → searchCuisine → 5 picks.
  5. Total round-trip ~15-20 s (3-5 s ASR + 12-15 s pipeline).
- **[KNOWN GAPS]**
  - Telegram's `voice` events don't include language hint — Gemini detects language from audio. Works well for major languages (en/zh/ms/ta/ja/ko/ar/fr/es), less reliable for very short clips.
  - 90 s cap is conservative. Could raise to 5 min if needed.
  - Voice → Gemini audio billing is per-second of audio. ~$0.001 per voice clip on average — negligible.
  - Mirror-transcript adds one extra Telegram message per voice; could be suppressed with a `/log off` user preference if it gets noisy.
