## New

### [HDR] #506 | 18:30 SGT 31-05-31 | v0.61.305 — in-TMA recents drawer + LRU cap 20 + auto-fire flip | 6 files | 1 PR | 1 build |

- **[INTENT]** Close the "typed text reverts to existing anchor" UX gap by giving the operator a fast in-TMA way to recover the prior anchor: the recent-locations LRU surfaced inside the LocationField, opened by tapping 📍 (icon swaps to 🧭). With easy revert, auto-fire on autocomplete pick becomes safe even outside SG.

- **[DELTA]**

  **1. `recent-locations.js`** — single constant change with comment rewrite. `MAX_ENTRIES = 10 → 20`. The TTL (180 days) is unchanged; cap doubling means stale rows roll off more slowly but the LRU dedup-by-coord-prefix (5 decimals, ~11 m) keeps the drawer's signal-to-noise stable.

  **2. `index.js`** — three additions:
  - **Import**: destructured `MAX_ENTRIES as RECENT_LOCATIONS_MAX` from `./recent-locations` so user-facing format strings stay in sync if the cap changes again.
  - **`POST /api/cuisine/recent-locations`**: verifyInitData → user.id → `listRecentLocations(redis, userId)` → JSON `{ items, max }`. Pattern mirrors `/api/cuisine/user-location` (12960+).
  - **`POST /api/cuisine/recent-locations/clear`**: same auth, calls `clearRecentLocations(redis, userId)` → `{ ok: true }`.
  - **`/lrecent` chat formatter**: hard-coded "10 most-recent" / `(${list.length}/${10})` replaced with `${RECENT_LOCATIONS_MAX}` template var.

  **3. `web/cuisine/src/v2/lib/api.js`** — two new exports:
  - `fetchRecentLocations()` returns `{ items, max }`; falls back to `{ items: [], max: 20 }` on any error (empty drawer renders).
  - `clearRecentLocationsRemote()` → POST clear; returns null on error (silently fails, drawer stays as-is).

  **4. `web/cuisine/src/v2/components/LocationField.jsx`** — the meat:
  - **State**: `drawerOpen`, `recents`, `recentsMax`, `recentsLoading`. Lazy fetch on first `openDrawer()` call.
  - **Handlers**: `openDrawer()` (clearIdleHint, close typing input if open, fetch), `handleRecentPick(entry)` (close drawer + `onSelect({lat, lng, label})` — no `noAutoFire`, so auto-fires), `handleClearRecents()` (clear server then local state).
  - **Render**: existing closed/open conditional wrapped in `{drawerOpen ? <drawer> : <existing-row>}`. Drawer JSX has three regions:
    - Pinned header: `🧭 Recent (N/20) ✕`
    - Scrollable body: `max-h-[280px] overflow-y-auto` — renders ~7 rows visible, scrollbar handles the rest of the 20.
    - Pinned footer: `🗑 Clear all` (hidden when `recents.length === 0`).
  - **📍 tap-zone**: the existing static `<span>📍</span>` becomes a `<button onClick={openDrawer}>📍</button>`. The label-text button still opens the typing input — two distinct tap targets (operator-chosen option (a) from the mockup discussion).
  - **Auto-fire flip**: in `handlePick`, drops `noAutoFire: region !== 'SG'` from the `onSelect` payload — all regions now auto-fire on autocomplete pick.
  - **Row content**: flag (via `findCountry(e.country)?.flag`, fallback 🌍), label (truncated, full in `title`), ✓ marker on the row whose coords match the current anchor (1e-4 tolerance, same as `handlePick`'s `same` check).

  **5. `web/cuisine/src/v2/lib/i18n.js`** — `loc.recent` (en: "Recent locations", fr: "Emplacements récents"), `loc.close` (en: "Close", fr: "Fermer").

  **6. `package.json`** — `0.61.304 → 0.61.305`.

  **7. `doc/.serial-state.yml`** — commit 518→519, build 307→308, journal 505→506; re-anchored 31-05 '26 18:30 SGT.
