### [HDR] #284 | 20:57 SGT 21-05-26 | v0.61.86 — cuisine map: fix tap-twice / re-centre on eatery pin tap | ~2 kb | 2 files | 1 PR | 1 build |

- **[INTENT]** A tap on a Cuisine venue pin should open that pin's popup
  in place — no map re-centre, no second tap.

- **[DELTA]**
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** — tapping a venue pin
    set `focusedPlaceId`, which was a dependency of the `syncMarkers`
    effect. That forced a full marker rebuild + `fitBounds` + `panTo` on
    every pin tap: the map re-centred and the just-tapped marker was
    destroyed before its popup could open, so the pin needed a second
    tap. `focusedPlaceId` is dropped from the `syncMarkers` dependency
    list; a dedicated focus-pan effect now pans only for **result-card**
    taps, skipping pin-originated focus changes via a new `pinFocusRef`
    so a pin tap opens its popup in place. A result-card tap still pans
    the map to bring the venue into view.
  - **`package.json`** — `0.61.85` → `0.61.86` (PATCH).
  - The Hawker + Transport maps were not touched — only the Cuisine TMA
    has the result-card ↔ pin focus split that produced the bug.
