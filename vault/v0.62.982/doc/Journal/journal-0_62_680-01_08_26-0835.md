- **[O-91 — SORT half resolved]** The FILTER half (year/Bib ticks) was already resolved by O-94/C-82;
  the SORT half was scoped out of every prior pass pending a decision. Re-read the original spec,
  `instr/GIA_Michelin_Footer_Pagination_AI_Prompt.md` §2, which already specifies the exact algorithm
  (never built): sort in order (1) newest applicable SELECTED award year, (2) Michelin category rank
  (3★→2★→1★→Bib Gourmand), (3) alphabetical fallback. Built `michelin-sort.js` (new module,
  `sortMichelinPool(entries, selectedYears)` + `effectiveYearRank` helper), wired into
  `index.js`'s `handleMichelinSearch` in place of the old pipeline that sorted star tiers by a
  `TIER_ORDER` constant and then Fisher-Yates **shuffled** the Bib Gourmand bucket (the shuffle
  existed only to vary which bib entries surfaced on repeat taps). The new sort is fully
  deterministic — every entry, star or bib, now sorts by the same three-key comparator, so the same
  criteria always produce the same order; the randomness the old pipeline relied on for bib variety
  is intentionally gone, per the spec. Removed the now-dead `TIER_ORDER` constant and updated two
  stale comments that referenced the old construction. Downstream pinning steps (free-text match,
  city-scope narrowing, cuisine-tag pin) all operate on `ordered` by partition-and-reconcatenate —
  unaffected by the change in base ordering. Added `__tests__/michelin-sort.test.js` (9 tests):
  year-before-category ranking, category tiebreak, alphabetical tiebreak, "only SELECTED years count
  toward newest," empty-selection fail-open, no-mutation, and null/undefined-input handling.

- **[O-92 — pager/Back-End button hit-area overlap, resolved]** Root cause (found via Explore):
  the Michelin pager's `‹`/`›` buttons (`web/cuisine/src/v2/App.jsx`, footer row) used the
  omnidirectional `.gia-hit` class (P1-f, `styles.css`), which extends their invisible clickable
  `::after` box 8px outward on **every** side — including horizontally, toward the very next grid
  cell in the same slim footer row, which holds the Back/End button. `styles.css`'s own P1-f comment
  already documents the fix for exactly this shape of bug: `.gia-hit-y` ("grow vertically only —
  tightly-packed rows"), `inset: -8px -2px`, shrinking the horizontal reach from 8px to 2px while
  keeping the full 8px vertical grow (safe here — no vertical neighbour in this row). The pager was
  the only control in this footer row using the omnidirectional variant; every sibling button
  (Criteria dropdown, list/map toggle, Back/End) uses no hit-extension at all. Changed both pager
  buttons from `gia-hit` to `gia-hit-y`. No layout/spacing/gap change needed — this is purely an
  invisible-hit-box fix, zero visible pixels move.
