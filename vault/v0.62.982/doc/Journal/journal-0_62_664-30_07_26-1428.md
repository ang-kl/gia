# Journal — v0.62.664 (URGENT: Telegram Desktop couldn't close — a same-session regression from v0.62.663, fixed)

## New

### [HDR] v0.62.664 — the fullscreen fix from an hour ago broke the close button

- **[INTENT]** Operator, urgent: *"the Telegram TMA in Desktop version cannot close/end, please check."*

- **[ROOT CAUSE — SELF-INFLICTED, SAME SESSION]** v0.62.663 (this session, ~45 minutes earlier) widened
  Menu's auto-fullscreen gate to include Telegram Desktop, and added a brand-new fullscreen step to Clipboard
  and Oversight, which never had one. All three were missing the other half of a pairing that Cuisine,
  Hawker, and Transport have always shipped together: `requestFullscreen()` hides Telegram's own native
  window chrome on desktop (the standard way a user would otherwise close the Mini App), and Menu's OWN
  v0.60.52 comment already said so in as many words — *"fullscreen takeover with NO CHROME AND NO EASY
  EXIT"* — which is exactly why desktop was excluded from Menu's gate back then. v0.62.663 removed that
  exclusion without also adding what makes it safe on the other three apps: a wired Telegram `BackButton`,
  which is Telegram's own persistent in-app arrow and keeps rendering even when the OS-level window chrome is
  gone. Grepping each app confirmed the gap precisely: Menu had no `BackButton` wiring at all; Clipboard had
  **no close affordance of any kind** — no `BackButton`, no in-app close button, nothing, meaning once
  fullscreen fired there, closing the app was flat-out impossible; Oversight had an in-app ✕ button
  (`closeApp()`) but no `BackButton`, which is a weaker safety net than Telegram's own persistent arrow.

- **[THE FIX]** Ported the exact `BackButton` wiring Cuisine/Hawker/Transport already use — `w.BackButton.show()`
  plus a `backButtonClicked` handler, defensively unregistering any prior handler first — into all three
  apps:
  - **Menu**: full pattern including the "came from another app's referrer → browser-back, else close" logic
    (mirrors Transport's).
  - **Clipboard**: simplified to always close (it had no prior in-app navigation model to preserve).
  - **Oversight**: wired to call the existing `closeApp()` helper (which already retries `w.close()` once
    after 350 ms — "flaky on Telegram Desktop/macOS," per its own comment), so the BackButton gets the more
    robust close path rather than a bare single `w.close()`.

- **[DELTA]** (3 files)
  1. `web/menu/src/tg.js` — new `back-button` init step.
  2. `web/clipboard/src/lib/tg.js` — new `back-button` init step (this app's first close affordance of any
     kind).
  3. `web/oversight/src/tg.js` — new `back-button` init step, calling the existing `closeApp()`.
