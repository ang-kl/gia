## New

### [HDR] #198 | 21:30:00 SGT 16-05-26 | v0.60.230 — Build E 5a–5d: Train TMA line polylines + tiny station dots + polyline click-to-focus | 5 files | 1 PR | 1 build |

- **[INTENT]** The interactive Google Map in the Train TMA (`MrtMapPanel.jsx`) plotted ~206 station pins but drew no line geometry, so the network read as a scatter of dots. Build E 5a–5d: (5a) draw a colour-coded polyline per MRT/LRT line; (5b) replace the `PinElement` teardrop markers with tiny coloured dots; (5c) keep the station-tap InfoWindow and add polyline tap → focus that line; (5d) style the polylines/dots (weight, opacity, future-network treatment).

- **[DELTA]**
  - **`web/transport/src/data/line-paths.js`** — NEW pure helper. `buildLinePaths(stations)` → `{ [lineCode]: Array<segment> }`. Polyline order is derived from the station codes (NS1…NS28, EW1…EW33, …), which already encode the running order — no precomputed path file, no map dependency, no server change. Branch handling: CGL `"CG"` (Tanah Merah) parses as ordinal 0 then CG1/CG2; CCL is a `CC` arc + a separate `CE` spur segment; SLRT/PLRT split into `SE/SW` and `PE/PW` branch segments, each prepended with the loop hub (STC/PTC) so the branch connects; JRL is a `JS` spine + `JE` branch; BPL is a single open BP1→BP13 polyline (documented loop simplification). Duplicate code ordinals (EW1/EW27) are de-duped; gaps (CC18, DT4, TE10/21) just connect to the next station.
  - **`web/transport/src/components/MrtMapPanel.jsx`** — imports `buildLinePaths`; new `polylinesRef`; new `renderPolylines(list)` draws one `google.maps.Polyline` per segment coloured by `LINES_BY_CODE[code].hex`, torn down + redrawn with the markers; called before the marker loop so dots layer on top. New `stationDotNode(bg, isFuture)` (modeled on the Hawker TMA's `hawkerPinNode`) replaces the `PinElement` teardrop — a `DOT_SIZE` 11px coloured dot with a white ring (8px + translucent for future stations). New `onLineSelect` prop: a polyline `click` focuses that line. 5d styling constants (`LINE_WEIGHT` 4 / `LINE_WEIGHT_FOCUSED` 6, `LINE_OPACITY` 0.85 / `FUTURE_LINE_OPACITY` 0.4). When a line is focused only its polyline is drawn, at the heavier weight. Header bumped `v0.60.85 → v0.60.230`.
  - **`web/transport/src/data/lines.js`** — added JRL (`#0099AA`) + CRL (`#97C616`) with `future: true` so 5a polylines can colour the future-line geometry already present in `mrt-coords.json`.
  - **`web/transport/src/App.jsx`** — threads `onLineSelect={(code) => setFocusedCode(code)}` into `MrtMapPanel`, composing with the existing `focusedCode` / `onResetFocus` ("Overview" reset) chrome and the AffectedTicker focus path.
  - **`__tests__/transport-line-paths.test.js`** — NEW. 8 tests: NS ordering, CGL ordinal-0, SLRT two-branch split with hub prepend, future-line JRL, single-station drop, duplicate-ordinal de-dupe, empty/invalid input, non-finite-coordinate skip. (Lives in the root `__tests__/` tree because the root Vitest excludes `web/**`; the module is plain ESM with no Maps dependency, so it runs in the node environment.)
  - `package.json` `0.60.228 → 0.60.230` (0.60.229 held by the in-flight PR #481); this Journal entry (#198); `doc/.serial-state.yml` bumped + re-anchored, counters sequenced after PR #481.
