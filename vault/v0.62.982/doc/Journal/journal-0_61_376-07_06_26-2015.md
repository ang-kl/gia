### [HDR] #576 | 20:15 SGT 07-06-26 | v0.61.376 — deviceRegion reads the iOS Region override | 2 code files + 1 test | 1 PR | 1 build |

- **[INTENT]** Make Option-B currency follow the phone's **Region** setting (the one iOS itself uses for currency), not its **Language**.

- **[ROOT — investigated]** v0.61.361's `deviceRegion()` read only **`navigator.language`** — the **Language** (`en-GB`) → maximized to **GB** → **GBP**. It never saw the iOS **Region** (Singapore). iOS encodes the Region as a Unicode **regional-override** `-u-…-rg-<cc>zzzz` inside the **resolved** locale: `Intl.DateTimeFormat().resolvedOptions().locale` → `"en-GB-u-rg-sgzzzz"`. (Gotcha: `new Intl.Locale("en-GB-u-rg-sgzzzz").region` still returns `GB`, so the `rg` subtag must be **string-parsed**.)

- **[MECHANISM]**
  - **`web/cuisine/src/v2/lib/device-region.js`** (NEW, pure) — `regionFromUnicodeRg` (parses `-rg-<cc>`), `regionFromLanguageTag` (Intl.Locale maximize + substring fallback), `pickDeviceRegion` (**rg override wins**, else the language region).
  - **`__tests__/device-region.test.js`** (NEW) — 10 cases incl. the operator's exact phone (`en-GB` + `rg-sg` → **SG**).
  - **`web/cuisine/src/v2/lib/api.js`** — `deviceRegion()` now feeds `[Intl.DateTimeFormat, Intl.NumberFormat].resolvedOptions().locale` + `navigator.language` into `pickDeviceRegion`.
