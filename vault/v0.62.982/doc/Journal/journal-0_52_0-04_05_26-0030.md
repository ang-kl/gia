- **[DESIGN]**

  1. **`/hawker` menu simplified** (`sendHawkerMenu`):
     - Top-level keyboard reduced to 2 buttons: `🧹 Cleaning info` + `🗺 Browse`.
     - Removed: `🚏 Nearest 3` (was a single-purpose wrapper around `/eat`-style ranking), `👥 Crowd` (no live API; the proxy via carparks was misleading), `🗺 By zone` (replaced by `Browse` which uses the canonical 122-centre vault).
     - `Browse` callback (`hawker:list:menu`) wires to v0.50.0's `runHawkerListMenu` → 5-region picker → alphabetical list with maps URLs.
     - Cleaning-info screen (`runHawkerCleaning`) reduced to 2 buttons: `🧹 Hawker Centre Status` (renamed from "Open closures TMA") + `⬅️ Back`. Dropped: `📅 NEA hawker mgmt` (external link the user called meaningless), `🤖 Live closure list (web search)` (now baked into the TMA endpoint).
     - Callback dispatch in `bot.on('callback_query')` collapsed to 4 cases (was 9): `hawker:menu`, `hawker:cleaning`, `hawker:list:menu`, `hawker:list:region:<R>`.
     - Deleted helper functions: `sendHawkerZonesMenu`, `runHawkerNearest`, `runHawkerZone`, `runHawkerCrowd`, `runHawkerClosureLive`, `runHawkerClosureLiveRefresh`, `carparksNearCentre`, `formatCentreBlock` (~280 lines removed).

  2. **NEW `nea-fetch.js`** — LLM-driven NEA closure fetcher.
     - Uses Anthropic `web_search` (already wired via `llm.generate({ webSearch: true })`).
     - Strict prompt directs Claude to extract two tables from `/our-services/hawker-management` (cleaning, 4 quarters) and `/announcements` (R&R Works), returning JSON.
     - Caches 12 h in Redis (`nea:fetch:v1`).
     - Output shape matches existing `nea-scrape` contract (`{closures: {headers, data}, rnrWorks: {headers, data}}`) so the Hawker TMA renders unchanged.
     - Robust JSON extraction: strips markdown fences + extracts `{...}` from prose-prefixed responses.

  3. **MODIFIED `/api/hawker/closures` endpoint** in `index.js`:
     - Tries `nea-fetch` (LLM) first.
     - Falls back to legacy `nea-scrape` (cheerio) only on LLM error — both will return empty rows in that case, but the TMA renders its diagnostic banner cleanly.

  4. **`/transport` location preload** (`sendTransportMenu`):
     - On every open: read cached location.
     - If absent or older than 5 minutes (`STALE_MS = 5 * 60 * 1000`), fire `LOCATION_REQUEST_KEYBOARD` immediately and exit (per Human Lead: "just refresh current location as preload").
     - When fresh: reverse-geocode via Google Geocoding API (cached 24 h on a 4-decimal-place grid) and prepend the human-readable address to the menu header:
       ```
       🚉 Singapore transport
       📍 Current: 46 Telok Blangah Drive, Singapore 100079
       [🚇 Train] [🚌 Bus]
       [🚖 Taxi/PHD] [🚗 Drive]
       [📍 Refresh location]
       ```
     - New `transport:refresh-loc` callback wipes the location cache + re-prompts.

  5. **NEW shared helper `reverseGeocodeAddress(lat, lng)`** in `index.js` — reused from the existing `/api/reverse-geocode` Express endpoint code path. 24 h Redis cache. Used by `sendTransportMenu`; available for any future menu wanting a "current location" header.

  6. **Removed `/heritage_food`**:
     - `bot.onText(/^\/heritage[-_]?food/)` registration deleted.
     - `runHeritageFoodCommand` function deleted (~70 lines).
     - Menu-router case + `setMyCommands` entry deleted.
     - Orphaned helpers `isHeritageSignal`, `HERITAGE_RADIUS_M` deleted (no remaining callers).

  7. **NEW `michelin-scraper.js`** — SG-only Michelin Guide scraper.
     - Pattern adapted from `NicolaFerracin/michelin-stars-restaurants-api` (cheerio + axios).
     - Targets `https://guide.michelin.com/en/sg-region/restaurants/all-starred` (1★/2★/3★) AND `…/bib-gourmand`.
     - Selectors include both Ferracin's 2019 classes (`.card__menu`, `.card__menu-content--title>a`) AND modern fallbacks (`[class*="restaurant__card"]`, `h3 a`, `article`) to survive Michelin redesigns.
     - Pagination via `<base>/page/<N>`; probes up to 10 pages or until empty.
     - 1.5 s rate-limit between page fetches.
     - Cache 24 h Redis (`michelin:sg:v1`).
     - Dedupes by link (some venues appear on both lists; prefers starred).

  8. **MODIFIED `runRecognisedCommand`**:
     - Drops `recognised-store` (seed-based pre-import).
     - Calls `michelin-scraper.getMichelinSG(redis)` → ~50 venues.
     - For top 25 by name-match (cap to keep cost bounded), resolves each to a Google Place via `pipeline.discover` (1 result, 50 km radius). Skips ones that don't resolve to coords.
     - Sorts by haversine distance to user, keeps top 5, runs `rankByWalkingTime` for walk-min enrichment.
     - Filter args simplified: `michelin` / `bib` / no-arg (was 6+ aliases mapping to award categories that no longer apply).
     - Maps URL via `googleMapsUrl(v)` (v0.48.2 helper) so the iOS Apple-Maps fix carries over.
     - Removed orphans: `RECOGNISED_FILTER_ALIASES`, `venueMatchesCategory` (~30 lines).

  9. **Tests**:
     - `__tests__/michelin-scraper.test.js` — 11 tests on `parsePage` (Ferracin selectors, modern fallbacks, URL synthesis, source labelling) + `venueAsAward` mapping.
     - `__tests__/nea-fetch.test.js` — 11 tests on `tryParseJson` (JSON, fenced, prose-prefixed, invalid) + `normaliseTable` validation + module exports sanity.
     - Total 204 → 225 (+21).
