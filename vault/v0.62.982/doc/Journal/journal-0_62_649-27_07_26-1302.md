## New

### [HDR] v0.62.649 — the palette fix broke more than it fixed, and the operator's screenshot caught it within the hour

- **[INTENT]** Operator, two screenshots (`IMG_3667` the "Finding eateries…" loading overlay, `IMG_3668` the
  Cuisine carousel): *"1. Wrong liquid glass effects on loading / 2. should opaque on active card and the rest
  be liquid glass effects with 60% opaque and the footer be 75% liquid glass effect which is the standard"*

- **[ITEM 1 IS MY OWN REGRESSION — shipped hours earlier in v0.62.648]** The new function-valued palette
  assumed `opacityValue` was either absent or numeric. For the **bare** utility it is **neither**: Tailwind
  calls the colour function with the literal **string** `'var(--tw-bg-opacity)'` so that `bg-opacity-*`
  keeps working. `Number()` of that is `NaN`, so every bare utility emitted

  ```css
  .bg-tg-card{background-color:color-mix(in srgb,var(--tg-card, #1c1c1f) NaN%,transparent)}
  ```

  — invalid CSS, **dropped by the browser**. Confirmed by grepping the shipped Cuisine stylesheet. Net
  effect: v0.62.648 fixed every `/NN` utility and **broke every bare one**, which is far worse. That is
  precisely what `IMG_3667` shows: the loading card has **no fill** (the map blurs straight through it) and
  its `border-tg-accent` frame fell back to `currentColor` — the **black outline** in the screenshot. Text
  lost its colour the same way.

  **Fix:** any **non-finite** opacity now falls back to the plain `var()`. That is the correct rendering,
  because Tailwind sets `--tw-bg-opacity: 1` for the bare utility anyway.

- **[ITEM 2 — the standard, now applied uniformly across the three map TMAs]**

  | Surface | Standard | Before |
  |---|---|---|
  | **Active** card | **opaque** | already correct (Cuisine `bg-white`; Hawker/Transport `bg-tg-card`) |
  | **Peek** cards | `bg-tg-card/60` + `.liquid-glass` | Cuisine `/70`; Hawker + Transport already `/60` but with an ad-hoc `backdrop-blur-md` |
  | **Footer** | `bg-tg-bg/75` + `.liquid-glass-dock` | Cuisine `/80`; Hawker `/80` + `backdrop-blur-md`; Transport `/95` + `backdrop-blur` |

  `.liquid-glass-dock` was **Cuisine-only CSS** — Hawker's own source comment said so, which is why it had
  been standing in with a plain blur. It is now ported verbatim into `hawker` and `transport` `styles.css`,
  so all three share **one** dock treatment.

- **[NOTE — why the operator saw this at all]** These surfaces were *authored* with these opacities long ago;
  the palette bug meant they had **never rendered**. v0.62.648 made them visible for the first time, which is
  what put the numbers up for review.
