## New

### [HDR] #75 | 23:00:00 SGT 01-05-26 | v0.35.0 | n/a kb | n/a lines
- **[INTENT]** Fourth leg of the v0.32-v0.36 roadmap. Ships the user-facing `/recognised` and `/heritage-food` slash commands that consume the `recog:venue:*` curated table populated via the v0.34.0 admin flow. Per the original ask:
  > "Third, construct the /recognised Global Excellence Database. … The /recognised command must perform a geo-spatial search to return the nearest 5 award-winning venues, citing the specific year and award won."
  > "Fourth, implement the /heritage-food precision search. Refine the /heritage-food logic to identify establishments serving historically significant dishes within a strict 2km radius. … Gemini must describe the heritage significance of the dish and its estimated travel time from the user's current location."

- **[DESIGN]**
  1. **`/recognised`** — geo-search via `recog:venues:geo` for nearest 5 within 5 km. Each card surfaces venue name + distance + address + summarised awards (e.g. `MICHELIN 1★ 2024 · Bib Gourmand 2022 · Asia 50 Best #27 2023`). Per-card `📍 Google Maps` button. Empty-state honesty: "no live entries — admin needs to run /admin/seed-recognised + /admin/promote-recognised."
  2. **`/heritage-food`** — geo-search within 2 km, filtered to entries with a heritage signal:
     - `tags` includes `multi-gen`, `heritage`, or `traditional`, OR
     - any award has `category: 'unesco-ich'`, OR
     - any award's `notes` field matches `/heritag|traditional|multi[- ]?gener|legacy|founded.*19[0-9]{2}/i`.
     
     Each surviving venue gets a Gemini-generated 1-2-sentence heritage-significance line (mentions generation count + signature dish + decade founded when known), cached 30 days per placeId.
  3. **Lazy Gemini cache** (`heritage-significance.js`) — `heritage:sig:<placeId>` Redis key, 30 d TTL. Cache hit = instant; miss = ~3-5 s Gemini Flash call. Sigs render in parallel via `Promise.allSettled`. Failures degrade to no-sig-line — never blocks delivery.
  4. **Slash command parsing** — `/heritage-food` accepts `/heritage-food`, `/heritage_food`, and `/heritagefood` (regex `^\/heritage[-_]?food`). `setMyCommands` row uses underscore form (Telegram disallows hyphens in slash command names; underscore is fine).
  5. **No TMA integration in v0.35** — both commands are chat-only. The TMA route would need a new pipeline-task `kind`. Deferred until usage warrants.

- **[DELTA]**
  - **NEW `heritage-significance.js`** — `getOrGenerate(redis, venue)` (cache → Gemini → cache write), `generateSignificance(venue)`, `getCached`, `setCached`. Prompt asks for 1-2 sentences mentioning generation/dish/decade, with explicit "if you don't know, OMIT — do not invent" clause to suppress hallucination on lesser-known venues.
  - **`index.js`** —
    - `bot.onText(/^\/recognised$/)` and `bot.onText(/^\/heritage[-_]?food$/)` slash handlers.
    - NEW `runRecognisedCommand(chatId)` — guard processing lock, location share gate, count check (empty-state honesty), `recogStore.nearestLive(redis, lat, lng, 5, 5000)`, render with `summariseAwards`.
    - NEW `runHeritageFoodCommand(chatId)` — same skeleton; fetches 25 nearby (within 2 km), filters via `isHeritageSignal()`, top 5, parallel Gemini sigs.
    - NEW `summariseAwards(awards)` helper — humanises the awards JSON array (`MICHELIN 1★ 2024 · Bib Gourmand 2022 · …`).
    - NEW `isHeritageSignal(entry)` predicate.
    - `setMyCommands` adds `recognised` + `heritage_food` rows.
    - `routeMenuCommand` adds `'recognised'`, `'heritage-food'`, `'heritage_food'` cases for tile / deep-link parity.
  - **`package.json` + `web/cuisine/package.json` + `web/menu/package.json`** — version 0.34.1 → 0.35.0.

- **[KNOWN GAPS]**
  - **No data → no answers**, by design. The empty-state copy is honest; users see exactly why and what's needed.
  - **Heritage signal heuristic is permissive** — relies on tags + award category + notes regex. If Gemini's seeded notes don't include heritage keywords, a multi-gen venue might be missed. Future refinement could add an explicit `heritage_score` field during promotion, or a richer prompt for the seeder.
  - **`tags` field isn't currently set during promotion** — the v0.34 promote endpoint copies tags from staging (which is empty by default since the seeder doesn't fill tags). Multi-gen detection therefore falls to the notes-regex path until we add a `&tags=` param to the promote endpoint (deferred to v0.35.x).
  - **No travel-time enrichment yet** — the original ask wanted "estimated travel time from the user's current location." Both commands surface haversine distance only (e.g. "1200 m away"), not walking minutes. Adding `rankByWalkingTime` would cost one Routes Matrix call per command; deferred to keep this version focused.
  - **Per-card map button vs. single shared map** — chat-side stays per-card (consistent with pre-v0.32 cuisine). The single shared map link from v0.32 is TMA-only; chat doesn't have a TMA wrapper for /recognised yet.
  - **No `/recognised` filter by award category** yet — e.g. `/recognised michelin` or `/recognised bib`. Could add as `/recognised <cat>` arg in v0.35.x once the live table has enough volume to make filtering useful.
