## New

### [HDR] #628 | 19:17 SGT 09-06-26 | v0.61.428 — rating forwarded as a search criterion + 2-up panel + red/green Save | web/cuisine | 1 PR | 1 build |

- **[INTENT / ROOT CAUSE]** v0.61.426 made the server *accept* `body.ratingPref` (it prefers it over the Redis pref), but the **TMA never sent it** — the pill's value only reached the backend through the **fire-and-forget Save POST** to Redis. So (a) the choice looked cosmetic / "not registered as a search criteria", and (b) tapping 🔍 right after Save raced the un-awaited POST and used the stale value. Plus two layout asks + a Save-button restyle.

- **[DELTA]** (Cuisine TMA only)
  - **`lib/api.js`** — `searchCuisine` gains a `ratingPref` param and forwards `body.ratingPref` (token `'unrated' | 'any' | '1.0'…'5.0'`). The server already prefers it over Redis (v0.61.426 `requestRatingPref`), so the floor now registers on **this** search.
  - **`App.jsx`** — new `ratingLoaded` flag (NOT in `state`). The search forwards `ratingPref` **only when authoritative** — i.e. the mount-fetch succeeded OR the user saved — so the boot auto-load can't override a chat `/rating` value with the `'3.7'` default before the fetch resolves. On fetch failure `ratingLoaded` stays false → the search omits it and the server falls back to its own Redis read. `onRatingSave` sets `ratingLoaded`.
  - **`components/QuickFilters.jsx`** —
    - **Panel compacted to two 2-up rows:** row 1 `No rating | Any rating`, row 2 `≥3.7 | Custom`. Explanations wrapped in a smaller font (`text-[0.65rem] leading-snug`); option dots top-align so a 2-line hint reads cleanly.
    - **Save restyled:** small rounded rectangle (`rounded-md`), **red** (`bg-red-600`) "Save" until tapped → **bright green** (`bg-green-500`) "✓ Saved", then auto-closes (~900 ms). Changing a choice re-arms the red "Save".
  - **`lib/i18n.js`** — `rating.saved` (en "Saved" / fr "Enregistré").
  - **`package.json`** `0.61.427 → 0.61.428`; **`doc/.serial-state.yml`** commit 640 → 641, journal 627 → 628, **build 405 → 406**; re-anchored 19:17 SGT.

- **[ACCESSIBILITY NOTE]** The operator asked for red→green on Save, which is exactly the red-green pair their profile says not to rely on **alone**. Implemented as requested **plus** a label change (**"Save" → "✓ Saved"**) so the state is legible without colour. Flagged to the operator.
