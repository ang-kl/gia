- **[INTENT]** Tackle the three clearest items in the operator's bug list (#1+2 country-only labels, #3 region-clear, #7 'Unnamed' leak) across both TMAs. Items #4 (JB Southkey/CBD alternate) and #5 (OTHER GPS-revert) are deferred to v0.61.266 because they're substantial UX additions (new state, new chip, App.jsx-level anchor flow change) — better landed as a focused follow-up than buried inside this sweep. #6 already works through the v0.61.241 city-pick anchor.

- **[DELTA]**

  **1. `smart-place-label.js` (server)** — fallback 'Unnamed' → ''

  The deep `return deduped.join(', ') || dn || 'Unnamed'` was masking every caller's own `|| text || 'Unnamed'` fallback chain because the literal 'Unnamed' is truthy. With the helper now returning `''`, callers' chains correctly resolve to `formattedAddress` → user-typed `text` → their own placeholder.

  Also added an `_isCountryName(dn)` check so a displayName.text that's *itself* a country ('Singapore' / 'Malaysia' / …) is treated as empty — without it, smartPlaceLabel('Singapore', 'Singapore') used to round-trip the dn back as the result. Test added for that.

  **2. `__tests__/smart-place-label.test.js`** — updated two assertions (the `'', ''` and `null, undefined` cases now expect `''` instead of `'Unnamed'`) and added two new tests for the country-only collapse. All 13 file tests pass; full suite still green.

  **3. `web/cuisine/src/v2/components/LocationField.jsx`** (the big change)

  Added two helpers at module scope: `_isCountryOnly(s)` (regex against 20 country names — SG, MY, ID, TH, VN, PH, BN, KH, LA, MM, JP, CN, HK, TW, KR, AU, NZ, US, UK) and `_safeLabel(primary, secondary, typedFallback)` (picks the first label that is non-empty, not literal 'Unnamed', and not country-only).

  Applied at every display seam:

  - **SG/JB resting label** — `pickedLabel` / `anchorLabel` / `currentLabel` are each filtered through `_isCountryOnly` so a bare country falls through to the i18n placeholder.
  - **SG/JB suggestion dropdown rows** — `s.primaryText` rendered via `_safeLabel(s.primaryText, s.secondaryText, query.trim())` so 'Unnamed' / country-only never reach the eye.
  - **OTHER picker results dropdown rows** — same `_safeLabel` guard, falls back to 'Pinned location' as the ultimate last resort (matches the v0.61.256 string).
  - **OTHER picker compact pill** — `anchor.name` filtered through both `_isCountryOnly` AND a literal `!== 'Unnamed'` check (covers anchors persisted before v0.61.265). When filtered out, the picker stays expanded so the user can re-anchor cleanly.
  - **OTHER picker free-text placeholder** — same `anchorNameSafe` filter.
  - **`pickResult` (OTHER picker)** — already had the v0.61.256 `'Unnamed'` guard; v0.61.265 upgrades it to use `_safeLabel` so the country-only filter applies to picks too, AND it now uses the user's typed query as the final fallback before 'Pinned location'.

  Also added a `useEffect` on `[region]` that resets `query` / `suggestions` / `suggestionsQuery` / `idleHint` / `open` whenever the region prop flips. This addresses operator's #3: switching from SG to JB (or to OTHER) used to leave the SG street name lingering in the input.

  **4. `web/menu/src/components/LocationFieldMenu.jsx`** — mirrored the changes

  - Same `_isCountryOnly` + `_safeLabel` helpers.
  - `composedLabel` (the pill label source) now filters bare country names + literal 'Unnamed' down to '', so the pill falls back to the i18n placeholder instead of showing "Singapore" / "Malaysia".
  - `otherResults` and SG `suggestions` rows both use `_safeLabel` for their primary display row.
  - `pickOtherResult` upgrades the v0.61.256 'Unnamed' guard to use `_safeLabel` + user's typed `textValue` fallback.
  - `updateCountryPref` now clears `textValue` + `suggestions` + `acOpen` on flag flip — the menu TMA's equivalent of cuisine's region-change clear (operator #3 applies here too, since menu's country dropdown is its way of switching effective region).
