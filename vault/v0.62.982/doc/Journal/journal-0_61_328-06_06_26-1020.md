## New

### [HDR] #529 | 10:20 SGT 06-06-26 | v0.61.328 — OTHER-mode geofence Step 1: per-city radius cap (40 km cities / 120 km Johor) | 6 files | 1 PR | 1 build |

- **[INTENT]** OTHER-mode searches could roam the whole country: the map slider widens the search radius up to 100 km, and (pre-this-PR) the OTHER autocomplete / free-text pick path stored **no** `radiusCapM`, so those searches fell through to the 20 km `DEFAULT_RADIUS` but could be dialled out to 100 km with nothing bounding them to the picked city. The fix bounds every OTHER search to a per-city ceiling: 40 km for the curated cities, 120 km for Johor (one row = whole state). SG / JB radius logic must be **byte-unchanged**.

- **[MECHANISM]** The per-anchor `radiusCapM` round-trip **already existed end to end** (chat `/location` quick-pick + Menu TMA already write it; `/api/cuisine/set-location` already destructures + stores it; `/api/cuisine/search` already reads it from Redis and clamps `searchRadius` down to it — `index.js:13708-13721`). What was missing: (a) OTHER **city picks** never *populated* `radiusCapM`, and (b) the OTHER **autocomplete / free-text** pick path stores no cap at all, so a default ceiling was needed. So this PR (a) stamps 40 k / 120 k onto OTHER city picks and round-trips it through `saveUserLocation` → `set-location` → Redis, and (b) adds an **`isOther`-gated** default-40 km ceiling in the cuisine search handler so even cap-less OTHER picks are bounded.
