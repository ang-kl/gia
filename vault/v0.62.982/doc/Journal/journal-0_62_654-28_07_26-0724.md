## New

### [HDR] v0.62.654 — the fullscreen gate was already identical; what was missing was listening for the result

- **[INTENT]** Operator: *"proceed to code to make all three consistent and auto-expand"*, following the
  read-only audit that established the fullscreen **gate** is already byte-identical across Cuisine, Hawker
  and Transport (diffed; only a trailing code comment differs).

- **[1 — AUTO-EXPAND, a real bug]** `useViewport` re-measured on `resize`, `visualViewport` resize,
  `orientationchange` — and **three hard-coded timers at 250 / 700 / 1500 ms**. Those timers are a *guess* at
  when Telegram finishes resizing the webview after `requestFullscreen()`. Telegram announces it **exactly**,
  via `fullscreenChanged` and `viewportChanged`, and nothing was listening. A fullscreen transition slower
  than 1500 ms left the layout stuck on the **pre-expand** classification for the rest of the session, with
  nothing to re-measure until the user resized or rotated. Both events are now subscribed (and unsubscribed)
  in the shared hook, so **all five** TMAs gain it at once.

- **[2 — CUISINE BROUGHT INTO LINE]** Two removals, both the last things keeping it out of step:
  - the v0.62.564 effect that **forced** `drawerMode` by orientation whenever `isWide` (landscape → carousel,
    portrait → list) — so a wide **portrait** device could not stay on the carousel; every rotation reset the
    user's choice;
  - the gate that **hid the list/map toggle in wide landscape**, which left a desktop user with **no route to
    the list at all**.

  All three apps now default to the carousel on every device and orientation, with one explicit toggle.

- **[3 — ONE DEFINITION OF "WIDE"]** `GRID_BREAKPOINTS`, `LIST_GRID_CLASS` and `gridColumnsForWidth` are
  exported from `classify-viewport.js`, and `__tests__/viewport-breakpoints.test.js` asserts both app grids
  carry the declared literal and reintroduce neither `md:` nor `lg:` `grid-cols`.

- **[REGRESSION I CAUSED — AND WHAT CAUGHT IT]** Worth recording in full, because it is the **third** variant
  of the same silent-drop failure this codebase has hit.

  Writing `LIST_GRID_CLASS` as a **template interpolation** put an un-evaluated arbitrary-width variant into a
  file that sits inside every app's Tailwind `content` glob. Tailwind read it as a **mixed-unit `screens`
  config** and **disabled the arbitrary min-width/max-width variants entirely** — silently dropping the
  3-column rule from **all five** stylesheets. The iPad mini and iPad landscape lost their third column, and
  the only visible sign was a single `warn -` line in the build output.

  Caught by the **ten-profile smoke**, not by the unit tests. Fixed to a plain literal — **and then the
  explanatory comment re-triggered it**, because the scanner reads comments too. The note is now written in
  prose, with the offending pattern nowhere in the file.

  Two guards added: the test asserts the declaration line contains **no interpolation**, and the smoke
  measures **computed** columns.
