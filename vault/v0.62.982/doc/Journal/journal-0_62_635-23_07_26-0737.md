## New

### [HDR] v0.62.635 — Cuisine map no longer hangs when zoomed past z15 (train-marker viewport cull)

- **[INTENT]** Operator (P.S. on the v0.62.634 message; symptom confirmed via `AskUserQuestion` = *"Freezes /
  becomes unresponsive"*): *"P.S. Cuisine TMA in iPad mini crash when zoom in more than 15."*

- **[ROOT CAUSE]** Cuisine's default map layers are `colour` (monochrome) + `train` only. At **z ≥ 15**
  `trainTier('cuisine', …)` returns `{ station: 'pill', cap: 0 }`, so **every** one of ~180 MRT stations
  resolves to a heavy **named-pill** DOM `AdvancedMarker` and **all** attach to the map (most off-screen);
  the map's **un-debounced `idle`** listener re-runs `applyVisibility('train')` on every zoom-settle,
  rebuilding all ~180 pills — a **main-thread hang** on the memory-constrained iPad mini. Below z15 a cap of
  5/10/15 + the `sq-sm` "other" mode kept the DOM light, which is why it only bit past 15.

- **[DELTA]** (1 file) `web/cuisine/src/v2/lib/mapOverlays.js` — the `applyVisibility` train branch now
  **viewport-culls at z ≥ 15**: `cullBounds = map.getBounds()`; a station **outside** the bounds (and not the
  pinned/tapped one) gets `marker.map = null` and is skipped — it's not pushed into `items`, so
  `demoteByOverlap` only processes on-screen stations. In-bounds stations attach exactly as before. At a
  street-level zoom the visible set is a handful of stops, not 180; nothing the user can *see* is lost (only
  off-screen pills are dropped).

- **[SCOPE]** Cuisine `maxZoom` left at **20** (the operator's z18/cap-23 request was for the **Train** TMA
  only, shipped in v0.62.634). **Transport is unaffected** — its `renderPins` `detail` mode caps `visibleList`
  to **3** stations (tapped + prev + next), so the v0.62.634 z23 raise can never explode there.
