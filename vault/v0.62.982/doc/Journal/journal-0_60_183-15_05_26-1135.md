- **[INTENT]**
  - **Item 5**: `/s` (technique fan-out, nation-iconic fan-out, cooking-method fan-out, free-text single-query) was rendering venues WITHOUT the `🍽️ <cuisine type>` row that the Cuisine TMA's ResultCard already shows. Same omission on Cuisine TMA's Copy-All pasted output. Root cause: `formatTechniqueVenueBlock` (index.js:5208) skipped `venue.restaurantType` entirely, and the TMA's Copy-All `enriched` payload didn't ship `restaurantType` to the server. Restore both.
  - **Item 6**: add a single line above the travel-time row carrying (a) the venue's price range in its **country currency prefix** ("S$25–40", "M$50–80", "¥1500–2500", …) — operator explicitly rejected the 💲 emoji — and (b) the 🐾 Pet-allowed flag when `allowsDogs === true`. When the user's home country differs from the venue's, append the converted-to-device-currency equivalent in parens to 2 decimal places, e.g. `S$25–40 (US$18.50–29.60)`. FX via the free **Frankfurter API** (ECB-sourced, daily), cached in Redis for 12 h. Graceful degradation when FX unreachable.

  **`currency-format.js`** (NEW, ~140 LOC) — the formatter.

  - `COUNTRY_PREFIX` map: operator-specified `SG → S$`, `MY → M$`, plus `US$ / C$ / HK$ / NT$ / A$ / NZ$ / ¥ / ₩ / ฿ / ₫ / Rp / ₱ / ₹ / £ / € / CHF` covering SEA + global majors. EU-zone codes (DE, FR, IT, …) all → `€`.
  - `CURRENCY_PREFIX` map keyed by ISO-4217 for the secondary lookup. Fallback: `"<CODE> "`.

  - `formatPriceRangeForVenue(priceRange, venueCountry, userCountry, redis)` — orchestrates: pick venue prefix → format `<prefix><start>–<end>` (or single bound) → if cross-border, fetch FX and append `(<userPrefix>start–end)` to 2 dp. Returns `null` when `priceRange` is unusable; returns the native-only string when FX fails or when same-country/unknown-user. **Caller drops the line** when this returns `null`.
