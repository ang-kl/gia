### [HDR] #318 | 15:15 SGT 23-05-26 | v0.61.117 — Carpark popup duplicate "Google Map ↗" link fix | 1 PR | build 120 |

- **[INTENT]** Drop the second of two "Google Map ↗" links that v0.61.116
  inadvertently introduced on the Carpark popup across all three TMA
  maps (Cuisine, Hawker, Transport). The popup was rendering the link
  twice — once inline (the v0.61.116 explicit add) and once via the
  `infoCard(_, f)` auto-tail (the v0.61.31 TMA-wide convention).

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** + the two byte-identical
    siblings (`web/hawker/src/lib/mapOverlays.js`,
    `web/transport/src/lib/mapOverlays.js`): in `carparkInfo` (line
    1530), the explicit `+ gmapsLinkRow(f.lat, f.lng)` is removed from
    the inner-HTML concatenation; `infoCard(inner, f)` keeps the `f`
    2nd arg so the standard auto-tail link still renders. Result: one
    Google Map ↗ row per popup, matching every other map card.
    Comment in `carparkInfo` updated to reflect the auto-tail intent.
  - **`package.json`** — `version` 0.61.116 → 0.61.117.
  - **`doc/.serial-state.yml`** — `commit` 325 → 326, `journal` 317 →
    318, `build` 119 → 120; `last_anchor_*` re-anchored to 23-05 '26
    15:15 SGT; a v0.61.117 comment block added.

  Not touched: `public/app.js` — the embedded `/app/map` builds the
  Carpark popup HTML by hand and always emitted a single link
  (`public/app.js:585` is the only `Google Maps ↗` row in that file).
  Confirmed by an independent agent's read during the audit pass.
