# Journal — v0.62.693 (the carousel card stops guessing its height and measures it)

_(№ 1,033 — 01-08 '26 17:00 SGT)_

## New

### [HDR] v0.62.693 — uniform card height, measured rather than constant

- **[INTENT]** Operator, on two v0.62.691 device screenshots: *"there is lots of white space below."*

- **[WHY v0.62.691 DIDN'T FIX IT]** The spacing pass was correct and insufficient, and the screenshots
  show exactly why. My arithmetic modelled a "typical" card at 8 rows and predicted ~27px slack. The
  operator's cards are **sparser than that model**: *Dirty Supper* has no cuisine type, no price row
  and therefore no `≈` conversion row — about 5 rendered rows sitting in a box sized for ten.

  This is not a tuning error. **D-51 asks for two things a single constant cannot deliver at once:**
  every card in the strip the same height, AND no wasted space. The constant must be sized for the
  tallest card a result set can produce (Michelin row + wrapped name/meta/address), so every card
  lacking those rows pays for them in blank space. D-61 already recorded the other wall — 12rem was
  the FLOOR, because below it the tall cards start clipping. There was no number left to pick.

- **[DELTA — measure instead of guess]** `ResultDrawer.jsx` now measures every collapsed card's
  natural content height in a `useLayoutEffect` and pins them all to the tallest:

  ```js
  for (const el of els) {
    const prev = el.style.height;
    el.style.height = 'auto';          // release the constraint …
    max = Math.max(max, el.scrollHeight);
    el.style.height = prev;            // … and restore before paint
  }
  ```

  `scrollHeight` alone is not enough: once a height is applied the content no longer overflows, so it
  would report the applied height and the strip could never shrink again. Momentarily setting
  `height:auto` inside a **layout** effect makes the read honest and lands before the browser paints,
  so there is no flash. `ResultCard` gains `collapsedHeightPx` (inline, beats the class) and a
  `data-card-root` hook for the query. `h-[12rem]` stays as the first-paint fallback and for any host
  that renders a card outside the drawer.

  Result: **uniform (D-51 holds) and tight (no card is taller than the set actually needs)**.

- **[MEASURED, IN A BROWSER]** Built a throwaway Vite entry that mounts `ResultDrawer` with fixture
  venues and read the real geometry — the first time a card-height claim in this project has been
  anything but arithmetic:

  | Fixture set | Card | applied | natural | slack |
  |---|---|---|---|---|
  | mixed | Dirty Supper (sparse) | 202 | 117 | 85 |
  | mixed | Treasure Paradise (Michelin, wrapped) | 202 | 202 | **0** |
  | **all-sparse** (the operator's case) | Dirty Supper | **117** | 117 | **0** |
  | **all-sparse** | Dusk Restaurant | **117** | 117 | **0** |

  The operator's case drops **192px → 117px**, all slack gone. In a mixed set the short card still
  matches the tall one — that is D-51 working as specified, not a residual bug.

- **[BUG FOUND WHILE MEASURING — the loop clone was never given `isShort`]** The carousel's
  aria-hidden loop clone (`ResultDrawer.jsx:330`) renders a `ResultCard` with its own prop list, and
  it had **never** been passed `isShort`. On phone landscape every real card was the short tier while
  the clone rendered the standard tier — a visible height jump as the strip wrapped around. It now
  receives both `isShort` and the measured height. Found only because the probe printed three rows
  and the third one disagreed with the other two.

- **[NOTED, NOT FIXED — nested `<button>`]** The probe surfaced a pre-existing React warning:
  `validateDOMNesting: <button> cannot appear as a descendant of <button>` — the details toggle sits
  inside the card's own button element. Invalid HTML, and it predates this arc by a long way. Out of
  scope for a white-space fix; recorded as **O-121** rather than folded in silently.

- **[KNOWN GAPS]**
  - Fixture data, not live results. The row combinations were modelled on the operator's two
    screenshots; a real set may contain a card shape neither fixture covers.
  - **The short tier is deliberately excluded** — the operator ruled *"the short tier — phone
    landscape - dont change"*, so `isShort` keeps its 7.5rem constant and its known overrun (O-115).
    The measurement would in fact have fixed that overrun; it is left alone because it was ruled on.
  - The measurement re-runs on `[list, isShort, basisClass, specialMode, dishHints]`. A late-arriving
    field that grows a card *without* changing any of those (e.g. an async enrichment writing into an
    existing venue object) would not re-trigger it. No such path is known, but it is not proven absent.
