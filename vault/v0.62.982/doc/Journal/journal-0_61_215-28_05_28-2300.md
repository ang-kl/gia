- **[DELTA]**

  **Root cause** of the 100% Places fail: v0.61.213's runner
  asked Places (New) `searchText` for `rating`, `userRatingCount`,
  `types`, `primaryType` in `X-Goog-FieldMask`. These are
  **Pro tier** Places New fields. If the project's billing is
  Essentials-only, requesting them returns HTTP 400 every call.

  The **live `/api/cuisine/place-search-by-country` endpoint
  (v0.61.201) asks only for Essentials** (`id`,
  `displayName`, `formattedAddress`, `location`) — which is why
  the production OTHER picker has been working fine.

  **`place-search-variance.js`** (2 edits):
  1. **`fetchPlaces` `X-Goog-FieldMask`** trimmed to match
     v0.61.201: `places.id,places.displayName,places.formattedAddress,places.location`. The result mapper still emits the
     `rating` / `userRatingCount` / `primaryType` / `types`
     fields but they're always `null`/`[]` now (no longer
     requested from Google).
  2. **`summarise()`** — NEW `topPlacesError` /
     `topGeocodeError` fields. For each source, tracks the
     `${status}:${msg}` tuples seen across failed rows and
     returns the most-common one as `{ key, n }`. Empty
     `null` when no fails.

  **`index.js` `ownerPlaceSearchVarianceRun` summary**:
  - New lines appended after `API fails:` when any fail count
    > 0:
    ```
    Top Places error:   <code>status: msg</code> (×N)
    Top Geocoding error:<code>status: msg</code> (×N)
    ```
  - Wrapped via `escapeHtmlForTelegram` so error-body
    fragments don't break the HTML render.

  - **`package.json`** — `0.61.214 → 0.61.215`.
  - **`doc/.serial-state.yml`** — commit 427 → 428, build 217 →
    218, journal 415 → 416; re-anchored 28-05 '26 23:00 SGT.
