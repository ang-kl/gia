- **[INTENT]** Operator: *"/v include menu to select /ver or /oversight or /ftlog 20 or
  /log on or /log off"* — after asking earlier in the session which builder commands exist
  (`/ver`, `/ftlog`, `/oversight` are the owner-gated ones; `/log` toggles per-user verbose
  logging). `/v` is a one-tap hub for them.

- **[DELTA]** — `index.js` only (server-side; no TMA build):
  - Extracted four owner-command action bodies into reusable async helpers —
    `ownerHealthCheck` / `ownerFtlogDump` / `ownerOversightLauncher` / `setVerboseMode` —
    so the typed commands and the new menu buttons share one implementation. The existing
    `/ver` `/ftlog` `/oversight` `/log` handlers are now thin wrappers (owner-gate +
    try/catch + a call to the helper) — behaviour unchanged.
  - New `bot.onText(/^\/v(?:@\w+)?$/)` — owner-gated (`isOwnerChat`, silent no-op for
    non-owners, like `/ver`); not in `setMyCommands` (hidden). Sends an inline keyboard:
    Health check (`/ver`), Oversight (`/oversight`), Free-text log (`/ftlog 20`), Verbose
    ON (`/log on`), Verbose OFF (`/log off`).
  - New `data.startsWith('v:')` block in the `callback_query` handler — re-checks the
    owner gate, dispatches `v:ver` / `v:oversight` / `v:ftlog20` / `v:logon` / `v:logoff`
    to the helpers, wrapped in try/catch with a `safeSend` fallback.
