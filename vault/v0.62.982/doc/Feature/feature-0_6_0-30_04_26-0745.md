### 2. Topic Gatekeeper (§2.1 of `02_Expand.MD`)

The bot now responds to **free-text** messages, not just slash commands.

- New `gatekeeper.js` classifies any non-command, non-keyboard message via Gemini into one of: `food`, `drink`, `groceries`, `transit`, `greeting`, `off-topic`.
- Gemini returns structured JSON `{intent, reply}`; the reply is sent to the user.
- Off-topic messages get the Gia-persona steer-back: *"I'm best with food, groceries, and Singapore transit. What sanctuary can I find for you?"*
- **60-second cache by SHA-256 message hash** mitigates G4 cost on repeated identical messages.

### 3. New commands

| Command | What it does |
| :--- | :--- |
| **`/drink`** | Same engine as `/eat`; Gemini hint focused on bars, coffee bars, tea spots, juice bars. |
| **`/groceries`** | Same engine; hint focused on supermarkets, fresh-market grocers, gourmet food stores. |

Both commands flow through the same location-share keyboard, share the 30-min cached location, and produce the same Sanctuary read + inline keyboard (Open Map · Directions) as `/eat`.

### 4. Walking radius — 300 m (§3.1 of `02_Expand.MD`)

`vibe-suggest.js` `SEARCH_RADIUS_M` reduced from 800 m → 300 m. The user-facing prompt "Looking for X within 800m" updated to "within 300m". Spec-compliant.

The cached cron `vibe.js refreshVibeListings` retains 500 m (it's a backend pre-warm, not user-facing).

### 5. Recent-review filter (§2.2 of `02_Expand.MD`)

`vibe-summary.js` filters `data.reviews` by `publishTime` to the **last 30 days** before sending to Gemini. If zero reviews are recent, the full review pool is used (avoids producing no Sanctuary read for venues with stale Google review listings).

### 6. TWA category param

`/api/sanctuary` now accepts `?category=food|drink|groceries`. The TWA can be opened with `/app?category=drink` and the venue picks come back filtered to that category. Existing `/app?placeId=<id>` focus mode unchanged.
