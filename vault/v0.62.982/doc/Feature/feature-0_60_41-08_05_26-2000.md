## 2. Per-Feature Detail (highlights for net-new pillars)

### Feature F-401 — R.E.D ambiguity spine

`disambiguateTerm({text, ctx})` is the unified entry point for all surfaces (slash + free-text). Returns:

```js
{
  kind: 'ambiguous-dish' | 'parent-cuisine' | 'none',
  chosen: { id, label, cuisine, flag },
  alternatives: [...],
  confidence: 'high' | 'medium' | 'low',
  isTourist: boolean,                            // bare query, no signals, no history
  disclosure: { en, fr },
  searchSpec: { kind, cuisine, dishKey, searchPhrase, wantSpread, stickyKey }
}
```

Decision precedence (deterministic, no LLM):
1. Explicit modifier in user text matches an interpretation's `signals[]` → HIGH confidence.
2. Locale (defaultIn) tiebreaker → MEDIUM.
3. Conversation sticky from prior turn → MEDIUM (overrides locale, never overrides HIGH).
4. Final fallback → LOW (show both, no Places call).

The `language` of the user's text is **never** a nationality signal. A SG user typing "Sautage" wants French food in SG — language affects rendering, not interpretation.

### Feature F-411 / F-412 — /hidden grounding hardening

Two-layer guard against Gemini hallucinations for low-density anchors:

1. **Pre-Places**: regex `\bapprox(?:imately)?\s+(\d+(?:[.,]\d+)?)\s*(km|m)\b` extracts Gemini's claimed distance. Drop if > `radius * 1.2`.
2. **Post-Places**: haversine of resolved coords vs anchor. Drop block if > radius. Strip from delivered text via `dropBlocksByName`. Rewrite "I found N hidden gems" prefix count to match kept survivors.

Address-mismatch salvage: when Gemini fabricates an address near the anchor neighbourhood for a real venue (e.g. "THE BETTER HALF at 1 Bukit Merah Lane 1" vs actual "1 Everton Park"), accept Places' resolved address when name match ≥ 0.7. The 0.5 floor still rejects when name uncertainty + wrong address compound.

### Feature F-418 — HawkerMapPanel embedded map

Slim purpose-built component (~180 LoC) instead of forking cuisine `MapPanel.jsx`. Reuses the pattern (Maps JS load via `/maps-key`, AdvancedMarkers, async script de-dup via `data-gmaps`) but drops cuisine-specific bits (focused-card sync, drift "search here", footfall colours, ratings, travel times, placeId identity). Hawker domain is a deterministic 123-row dataset with no ranking — simpler component is cleaner than lifting + stripping.
