## §0.5.0 NEW CONTENT

### 1. Stack additions

| Component | Technology | Notes |
| :--- | :--- | :--- |
| Map markers | `google.maps.marker.AdvancedMarkerElement` | Replaces legacy `google.maps.Marker`. Loaded via `google.maps.importLibrary('marker')` and `&libraries=marker` script param. |
| Map ID | constant `'GIA_SANCTUARY'` (placeholder) | Required by AdvancedMarker. Currently a non-Cloud-configured ID — produces a console-warning watermark but functions correctly. Future: register a real Map ID in Cloud Console for cloud-styled basemap. |

### 2. Telegram inline keyboard surface

| Button | Type | Telegram constraint |
| :--- | :--- | :--- |
| 📍 Open Map | `web_app: { url }` | Requires HTTPS; only valid in private-chat keyboards from the bot (which is our only delivery context). Skipped when `useWebhook === false` (no public domain). |
| 🚗 Directions | `url` | Standard URL button. Renders a "🔗" indicator. URL points at Google's documented Directions URL Schema `…/maps/dir/?api=1&destination=<name>&destination_place_id=<id>`. |

### 3. TWA query-param control surface

| Param | Behaviour |
| :--- | :--- |
| `placeId=<id>` | If present, the TWA renders only the matching pin (zoom 17). If the matched pin isn't in the returned venue list (rare — user opens an old chat link after picks rotated), the TWA falls back to the full 3-pick view. |

### 4. Module map (delta)

| Module | Change |
| :--- | :--- |
| `index.js` `deliverPicks` | Inline keyboard now attached to each Sanctuary read message. Buttons computed per-pick from `placeId` and `useWebhook`. Falls back to `🌿 <Name>` carrier message when no Sanctuary read text is available. |
| `public/app.js` | Migrated marker creation to AdvancedMarkerElement. Reads `?placeId=` query param. Map options gain `mapId` and `gestureHandling: 'greedy'`. New helper `makePinContent(num, name, isUser)` builds the HTML pin DOM. |
| `public/index.html` | Added `.gia-pin`, `.gia-pin .num`, `.gia-pin .name`, `.gia-pin.user` CSS for the new HTML markers. |
