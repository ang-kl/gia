## §N+1 — New decisions (v0.60.158 → v0.60.172)

### T-164.1 — JB-region geo-fence widening (post-filter regex)

`index.js` post-filter for the JB region toggle relaxed from `/johor bahru/i` (literal "Johor Bahru" substring; matched JB City addresses only) to `/\bjohor\b/i` (word-boundary; matches any Johor state district — Pontian, Desaru, Kulai, Iskandar Puteri, Muar, Mersing, Batu Pahat, Kota Tinggi). KL / Selangor / Pahang still excluded because their addresses don't contain "johor". Plus an `insideSG` bbox helper so JB region toggling without a location pick still falls back to the JB_CBD anchor (vs. picked Johor coords that should be honoured).

**Rationale**: operator chose to widen JB scope across the whole state, not just the immediate city.

### T-165.1 — SG/JB radius defaults rebalanced

`searchRadius` (warm-start) + `DEFAULT_RADIUS` (main search) at the two call sites in `index.js`:

| Region | v0.60.163 | v0.60.165 first-pass | v0.60.166 (final) |
|---|---|---|---|
| SG | 50 km | (unchanged) | **20 km** (near-me focus) |
| JB | 18 km | 30 km | **30 km** |
| Slider max | 100 km | 100 km | 100 km |

**Rationale**: SG is dense — 20 km from any pin covers ~half the island; cross-island reach via slider. JB needs 30 km to cover JB City + Iskandar Puteri + Pasir Gudang + Senai/Kulai edges; far-Johor via explicit LocationField pick (T-164.1).

### T-165.2 — `places.allowsDogs` field-mask addition (Google Places New API)

`pipeline.js DISCOVER_FIELD_MASK` extended with `places.allowsDogs`. Mapped to `venue.allowsDogs` in the candidate payload. Used by the petFriendly post-filter on `/api/cuisine/search`. Strict mode: `v.allowsDogs === true`. Text-query fallback when strict < 3: prepend "pet friendly" to the cuisine modifier list.

**Cost**: one extra boolean per Places SKU response. Per-call billing impact negligible (Places SKUs are per-request, not per-field).

### T-167.1 — `/api/cuisine/*` auth chokepoint

New middleware `requireInitDataFromBodyOrHeader` in `twa-auth.js`. Reads `X-Telegram-Init-Data` header OR `req.body.initData` (accommodates the v2 TMA's `postJson` body-stuffed pattern). Mounted as `app.use('/api/cuisine', …)` once, before all `/api/cuisine/*` route declarations. Constant-time HMAC compare (`crypto.timingSafeEqual`). Dev bypass via `SKIP_INIT_DATA_AUTH=true` env var (strict-string check on `"true"`). 401 with generic body + IP/UA log on reject. 17 new unit tests in `__tests__/twa-auth.test.js`.

The 19 pre-existing inline `verifyInitData(req.body?.initData, …)` calls are preserved as defense in depth (simplification deferred to DF-56).

**Rationale**: operator's top security-hardening priority. Single chokepoint replaces the per-handler-remembering pattern; new routes inherit the gate automatically.

### T-170.1 — LocationField → state-sync contract

After the v0.60.166 / v0.60.170 two-step fix, the LocationField `onSelect` callback's contract is:

```js
onSelect({ lat, lng, label }) {
  setLocationAnchor({ lat, lng, name: label || '' });   // anchor commit
  setSearchCenter({ lat, lng });                         // v0.60.170 — keeps map + runSearch fallback in sync
  if (label.trim()) saveUserLocation({ lat, lng });     // bot /location cache
  // NO runSearch call — user's explicit Search FAB tap fires it
}
```

`runSearchAt(...)` (the helper that BOTH sets the anchor AND fires the search) is reserved for the map's "Search this area" control where immediate fire is expected.

**Rationale**: separates "I picked a place" (commit-only) from "I want to search" (explicit FAB tap) per operator.

### T-171.1 — `/legal` + `/privacy` body i18n migration

`/legal` (v0.60.169) and `/privacy` (already i18n since v0.59.x) bodies live in `i18n.js legal.body` / `privacy.body` (EN + FR). Both bodies fully replaced in v0.60.171 / v0.60.172 with operator-supplied copy + freshly-translated FR. `{operator}` placeholder dropped in both (LinkedIn now inline in the legal takedown paragraph; `OPERATOR_LINKEDIN` env var is a silent no-op for both commands — DF-60 if dynamic swap is later wanted).

**Rationale**: localisation + content control unified under i18n keys.
