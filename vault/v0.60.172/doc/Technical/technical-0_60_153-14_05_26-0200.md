# Technical — soleat v0.60.153 (delta entry)

> Per `doc/CLAUDE.md` §3 + AU-1: supersedes `technical-0_60_141-12_05_26-1530.md` by reference. All prior architecture stands; this entry adds the v0.60.142 → v0.60.153 components — principally the Oversight admin TMA + identity-free usage-tracking layer, the standalone Vibe-Coding Record + hosted Vibe Journal page (with optional shared-key gate), the Cuisine-TMA session-clipboard machinery (80-cap session + ⇠ Prev FAB + multi-cuisine variant escalation + ↻ Recycle), Michelin LLM-narrate parity + dedicated per-entry Redis caches (places + enrichment), and the 80 km → 120 km distance-gate widening.

## New modules in this arc

### `usage-log.js` (v0.60.142 — PR #379)

Redis-only, fire-and-forget, never throws. Per-user entries are one-way `sha256` hashes (`hashChatId` from `location-cache.js` — same scheme as `loc:`/`proc:`), used **only** to de-dup the aggregate counts; nothing else attached.

Keys:
- `usage:users` SET (no TTL; `SCARD` = total users since tracking shipped).
- `usage:dau:<YMD>` / `usage:search:<YMD>` / `usage:searchmulti:<YMD>` SET, 90 d (daily-active / searchers / "frequent ≥ 2 searches that day").
- `usage:cuisine[:<YMD>]` / `usage:criteria[:<YMD>]` HASH (cuisine + criteria popularity; `src:<chat-freetext|cuisine-tma|s|eat|surprise|cuisine-tma-back|cuisine-tma-recycle>`, `filter:<name>`, `price:<n>`, `region:JB`, `freetext`).

Exports `recordUser(redis, chatId)`, `recordSearch(redis, chatId, { cuisines, filters, prices, region, freeText, src })`, `getStats(redis, { date, days })`. Wired at every search call-site (`/api/cuisine/search` 'cuisine-tma' · chat free-text 'chat-freetext' · `runSearchCommand` 's' · `runFlow` 'eat' · `runSurpriseCommand[+WithFreeText]` 'surprise'). `/forgetme` (`user-data.js removeUsageMembership`) SREMs the user's hash from `usage:users` + SCAN+SREM every `usage:dau:*` / `usage:search:*` / `usage:searchmulti:*`.

### `cuisine-session.js` (v0.60.146 — PR #385; `skipCap` opt v0.60.149 — PR #389)

Per-Cuisine-TMA-launch session clipboard in Redis. **Distinct** from `clip:<chatId>` (`clip-store.js` — `/clip` 100-entry recall) and from `cuisine:seen:<chatId>:<criteriaHash>` (`index.js` — long-lived per-criteria dedup). Reset on every TMA mount via `POST /api/cuisine/session/start`.

Keys:
- `cuisine:session-seen:<chatId>` SET, 30 min TTL, cap **80 placeIds**.
- `cuisine:session-pages:<chatId>` LIST (LPUSH at head; LPOP at head), 30 min TTL, cap 10 page JSON blobs.
- `cuisine:session-meta:<chatId>` HASH, 30 min TTL (`started_at`, `last_search_at`, `total_served`).

Exports `startSession`, `recordPage(redis, chatId, payload, opts?)` (opts.skipCap=true for Michelin — page placeIds NOT added to session-seen SET; still LPUSH'd onto the history list), `popPage`, `seenCount`, `getSeen`, `isExhausted`, `depth`.

### `pipeline.narrateMichelinVenues({ candidates, lang })` (v0.60.147 — PR #386; prompt guard v0.60.149 — PR #389)

Narrate-only LLM helper (no re-ranking — `handleMichelinSearch` already filters/sorts its curated list). Returns a placeId-keyed `{ vibe, signatureDish, dishes }` map (defensive: drops hallucinated placeIds; truncates dishes to 3; never throws — failure / `llm.isReady() === false` / parse-fail → empty map for graceful degradation). Prompt explicitly says *"add narration to EVERY one — DO NOT drop any"* + *"reference the Michelin recognition correctly (no hallucination)"*. v0.60.149 tightened: dish fields are NAMES ONLY (`stripDishVerbs` regex strips "Order the …" / "Try the …" / "Have the …" / "Get the …" verb prefixes the LLM occasionally adds despite the prompt rule). FR localisation keeps iconic SG dish names un-translated.

### `web/oversight/` TMA (v0.60.142 — PR #379)

Vite/React/Tailwind scaffolded from `web/transport/` (`base: '/app/oversight/'`, build → `public/oversight/`). Single-screen dashboard at `App.jsx`: fetches `/api/oversight/stats?days=7` (or `?date=`) with `X-Telegram-Init-Data`; 401/403 → "Not authorised" screen; renders StatCards (total users / today active / today frequent), control buttons (This week 7d / Last 14d / 30d / Today only / `<input type=date>`), and bar-list sections (By day, By day of week, Top cuisines, Top criteria/filters, Top free-text words, Recent free-text), plus a `🔚 close` button.

### `doc/VibeCodingRecord/` (v0.60.143 — PR #380; expanded v0.60.144–148)

Regenerable per-PR cross-section — **deliberately NOT one of the eight `doc/` AU templates and NOT under the AU-1 append-only Recipe**. Files: `VibeCodingRecord.md` (schema), `vibe-coding-record.md` (Markdown view), `records.tsv` (TSV source of truth + raw `Title`), `generate.mjs` (pure generator, no network), `data/prs.ndjson` + `data/pr-files.tsv` (committed snapshots). The hosted page at **`/doc/vibe-journal.html`** (self-contained, embeds the full dataset) ships an Insights panel (likely-rework, churn-by-area, churn-by-module, PRs-per-release, category mix, time-based, small / low-effort PRs, indecision-cue PRs, behavioural KPIs, hard-parts) + a "lessons to reduce rework" list + a queryable ledger with full-text search + dropdown filters + sortable columns + per-row GitHub links.

### `vibe-journal-html.js` route gate (v0.60.144 — PR #381)

`/doc` + `/doc/*` honour the **Railway service variable `VIBE_JOURNAL_KEY`**. When set: `?key=<value>` URL query (correct key drops a 30-day `httpOnly` cookie `vibe_key` scoped to `/doc`) OR `X-Vibe-Key: <value>` header; missing/wrong → 401 with a small "🔒 Vibe Journal — enter the access code" form. When unset: public (default-open convention).

### `/api/cuisine/copy-all` hardened (v0.60.145 — PR #384)

Both `bot.sendMessage` call sites wrapped in `try/catch`. On Telegram HTML parse-mode rejection: log the description, retry once with plain-text body (strip `<b>/</b>`, unescape `&amp; &lt; &gt;`), preserve `reply_markup`. A second failure 500s with structured `[Cuisine] copy-all sendMessage retry failed (plain): <description>` Railway log. Separately, `buildMapHashUrl()` returning `null` (every slim venue lacked lat/lng) no longer 500s — drops the inline-keyboard map button, appends a one-line `📍 Map unavailable for this set.` (EN) / `📍 Carte indisponible pour cette sélection.` (FR) footer via the new `pick.mapUnavailable` i18n key.

### `/api/cuisine/search` — session-clipboard outer gate + multi-cuisine variant escalation (v0.60.146 — PR #385)

- `cuisineSearchVariants(cuisineNameOrList)` accepts an array — multi-cuisine joined with `" + "` for the variant prompts (`"good Japanese + Korean restaurant Singapore"` → `"best …"` → `"authentic …"`). Both single- and multi-cuisine now escalate through the 4 phrasings as the pool exhausts.
- Session-seen gate at the head of the handler: `if (await cuisineSession.isExhausted(redis, csChatId)) return res.json({ venues: [], exhausted: true, sessionFull: true })`.
- Replaced the silent fallback at the (formerly) `top = (unseenVenues.length ? unseenVenues : venues).slice(0, 12)` site — the "stuck on the same list" bug. New flow: `trulyUnseen = unseenInCriteria.filter(v => !sessionSeen.has(v.placeId))`; when empty, `top = []` and `exhausted: true` flows naturally.
- Append-page on success: `cuisineSession.recordPage(redis, csChatId, { criteriaHash, venues: top.map(slim), meta: { region, cuisines, filters } })`. Response carries `pageStackDepth` so the ⇠ Prev FAB knows when to render.

### `/api/cuisine/session/*` endpoints (v0.60.146 + v0.60.149)

- `POST /api/cuisine/session/start` — `cuisineSession.startSession(redis, chatId)` (wipes session-seen + page-history + meta). Called by the TMA on mount.
- `POST /api/cuisine/session/back` — double-`popPage` with re-push so depth stays consistent (pop the current head, then pop the prior; re-push the prior so the next "back" can pop again); `usageLog.recordSearch({ src: 'cuisine-tma-back' })`; returns `{ ok, page, pageStackDepth }`.
- `POST /api/cuisine/session/recycle` (v0.60.149 — PR #389) — `cuisineSession.startSession` + `usageLog.recordSearch({ src: 'cuisine-tma-recycle' })`. Fired from the post-80 terminal ↻ Recycle button.

### `handleMichelinSearch` — full LLM-narrate parity + parallel Places + force-warm enrichment (v0.60.147 / .149 / .150 / .153)

- **FIELD_MASK** adds `places.reviews` + `places.editorialSummary` (v0.60.147).
- **Slice cap 40 → 12** (v0.60.149) so the LLM narrate step fits inside Telegram's webhook ceiling.
- **Parallel Places resolution** (v0.60.150) via `Promise.allSettled(slice.map(resolveEntryPlace))` (worst case 72 s → 4 s); per-call axios timeout cut 6 s → 4 s; per-entry `michelin:place:<slug>` Redis cache (24-h TTL; `{ __null: true }` negative-cache marker). Slow-handler warn log `[Michelin] handler ms=… cacheHits=… cacheMisses=…` when ms > 10000.
- **`criteriaHash` drops `radius`** (v0.60.153) — Michelin is curated-list-based, location-agnostic; slider drift no longer resets the seen-set ("same first 12" bug fix).
- **Five-step enrichment** (v0.60.153): (1) review-extract; (2) `michelin:enrich:<slug>` cache READ; (3) narrate subset still missing `vibe` or with `dishes.length < 2`; (4) force-fill (cuisine-label fallback dishes; Michelin-tier boilerplate `recentReview` stand-in); (5) cache WRITE (7-day TTL). Refreshes per search; never ships empty cards.
- **Joins the session clipboard with `{ skipCap: true }`** (v0.60.149) so Michelin walks the full ~130 curated entries without the 80-cap terminating it.

### `/clip` regex + `setMyCommands` menu entry + per-clip callback branches (v0.60.148 / .149 / .151)

- Regex extended to `^\/(?:clip|cl|clipboard)…$` (v0.60.148 — PR #387).
- `setMyCommands` EN + FR arrays gain `/clipboard` between `/search` and `/language` (v0.60.149 — PR #389).
- New callback branches `clip:copy:N` (re-send as plain text — strip `<b>/</b>`, unescape entities, no `parse_mode`), `clip:rename:N` (Telegram `force_reply` prompt + ephemeral `clip:rename-pending:<chatId>` Redis key 5-min TTL), `clip:remove:N:{ask,yes,no}` (confirm gate + `removeClip` via "LSET sentinel + LREM 1 sentinel"). The `bot.on('message', …)` handler gains a pre-route check for the rename force-reply (`renameClip` if `msg.reply_to_message` matches the prompt + pending key exists).
