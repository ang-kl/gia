# Journal — soleat v0.60.157

> Operator reported a silent empty-state in the Cuisine TMA: *"Bug: If results return zero, should refresh the criteria again."* This PR lands a two-layer fix — a one-shot silent auto-retry with `resetSeen: true` when the server returns `venues.length === 0` (handles the most common cause: the per-criteria seen-set accumulating past the dedup pool over a long session), plus a prominent `🔄 Reset filters & retry` CTA panel that surfaces if the retry ALSO comes back empty. In the second case the Search-criteria builder is auto-expanded so the user sees their chips immediately. The retry can't loop (the retry call sets `resetSeen=true`, which the guard inspects) and the per-criteria guard re-arms when any criteria field changes.

  **`web/cuisine/src/v2/App.jsx` state (line ~134)** — added `lastZeroRetrySnapRef` (a `useRef(null)` keyed by `stateSig(snap)`) and a `zeroRetried` boolean state. The ref scopes the retry-budget per-criteria signature: the same signature can never auto-retry twice, and any criteria change implicitly arms a fresh budget. The flag drives the empty-state CTA panel.

  **`web/cuisine/src/v2/App.jsx::runSearch` (line ~554)** — inserted the zero-results decision block immediately after `setQuestionDeclined(false)` and before `setVenues(...)`. Four branches: (1) `isZero && !isRetryCall && lastSig !== currentSig` → set the ref, schedule `runSearch(snap, anchor, { resetSeen: true })` in `Promise.resolve().then(...)` so the current `finally { setLoading(false) }` completes first and the retry's `setLoading(true)` re-fires the spinner cleanly. (2) `isZero && isRetryCall` → the retry itself came back zero: flip `setZeroRetried(true)` + `setCriteriaOpen(true)`. (3) Non-zero result → clear both `zeroRetried` and the ref so a future zero on different criteria gets its own budget. The retry path uses `opts.resetSeen === true` as the recursion-break signal, so the chain can fire at most twice per criteria signature.

  **`web/cuisine/src/v2/App.jsx` CTA render (line ~1248, after the exhausted-note block)** — new `{zeroRetried && !loading && venues.length === 0 && …}` block: rounded `bg-tg-card` panel with the bilingual `result.noMatchAfterRetry` hint + a pill-shaped accent-coloured `🔄 Reset filters & retry` button. The button: re-opens the criteria builder (idempotent), clears `zeroRetried`, clears the ref, and re-fires `runSearch(state, null, { resetSeen: true })`. If the response is still zero, the silent retry guard re-arms and a fresh retry-CTA cycle plays out.
