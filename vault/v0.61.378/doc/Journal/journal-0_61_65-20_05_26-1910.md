- **[INTENT]** (1) Render the in-map station pill with one line-coloured chip per
  station code (CC4 orange · DT15 blue) instead of a single-colour label. (2)
  Investigate the pin/Google-Maps coordinate mismatch and add an accurate
  exit-derived coordinate field without discarding the existing values.

- **[INVESTIGATION — who is right]**
  - `scripts/build-station-info.js` copies each station's `lat/lng` straight from
    `data/mrt-coords.json` — coarse hand-entered 4-decimal values (`_meta` itself
    claims "~10 m typical", optimistic). The **exit** coords come from the LTA MRT
    Station Exit GeoJSON — precise 6-decimal, the dataset Google also uses.
  - Measured each station's stored coord vs the centroid of its own exits (175/180
    have exits): **median 37 m**, 116 within 50 m, **13 stations >200 m** — worst
    Teck Whye 1505 m, Phoenix 903 m, Keat Hong 811 m, Bayshore 675 m.
  - Spot-check confirmed direction: Teck Whye's exit `1.3766,103.7538` sits on the
    real LRT station; the stored `1.3897,103.7503` is the wrong one. Promenade's
    exits cluster at `1.2932,103.8603`; stored `1.2935,103.8612` is ~95 m east —
    exactly the screenshot offset.
  - **Verdict: Google Maps / the LTA exit GeoJSON are right; `mrt-coords.json` is
    the inaccurate source.**

- **[DELTA]**
  - **`scripts/build-station-info.js`** — new `round6()` + `exitCentroidOf(exits)`;
    each station record gains an **`exit_centroid` field** `{ lat, lng, exit_count }`
    (mean of the station's exit coords; `null` when no exits). `lat/lng` are kept
    unchanged for provenance. New `_meta.schemaNotes` entry documents the field.
  - **`data/stations.json`** (regenerated) — 180 stations, **175 with `exit_centroid`**,
    5 without (no exits in source). `lat/lng` untouched.
  - **`index.js`** — new cached `loadStationCentroids()` (name→`exit_centroid` map
    from `stations.json`); `/api/transport/stations` now enriches each served
    station with `exit_centroid`; new `mrtCoordsForGeometry()` feeds the
    exit-centroid coords to `deriveLinePaths()` so derived polylines run through
    the real station positions (consistent with the moved pins).
  - **`web/transport/src/lib/mapOverlays.js`** (canonical) —
    - new `stationPillNode(codes, name, fallbackHex)` — a white pill with one
      line-coloured chip per station code (`codeHex` per code), then
      `<Name> station` (first letter capitalised). Replaces the single-colour
      `amenityLabelNode` label at the zoom-detail pill.
    - `buildTrainStations()` — the station marker now positions at
      `s.exit_centroid` when present, else `s.lat/s.lng`.
  - **`web/hawker/src/lib/mapOverlays.js`** + **`web/cuisine/src/v2/lib/mapOverlays.js`**
    — byte-identical copies (`md5sum` ×3 confirmed equal).
  - **`package.json`** — `0.61.64` → `0.61.65` (PATCH).
