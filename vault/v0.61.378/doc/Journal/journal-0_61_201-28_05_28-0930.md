## New

### [HDR] #402 | 09:30 SGT 28-05-28 | v0.61.201 — dual-API place-search-by-country | 3 files | 1 PR | 1 build |

- **[INTENT]** Make the OTHER picker work reliably on every typed
  query — including venue names ("Times Square Kuala Lumpur")
  AND typos ("Ho Chin Ming" → "Ho Chi Minh"). No more silent
  502s. Up to 6 confirmation candidates (operator's spec).

- **[DELTA]**

  - **`index.js`** — `/api/cuisine/place-search-by-country`
    rewritten (~120 lines around line 11386). New shape:
    1. **Two inner helpers** that each return an array of
       candidates `[{ placeId, primaryText, secondaryText, lat,
       lng, source }, …]` or `[]` on failure:
       - **`runPlacesText()`** — calls Places (New)
         `searchText` with `textQuery`, `includedRegionCodes:
         [cc]`, `pageSize: 6`. **Drops `regionCode` from the
         payload** (was a candidate cause of the v0.61.199-
         logged 400s — `regionCode` + `includedRegionCodes`
         set together is technically valid per docs but the
         clean payload eliminates it as a variable). Logs
         full status + body + request on failure (preserves
         v0.61.199 diagnostic). Catches and returns `[]`
         instead of throwing — failures isolated.
       - **`runGeocoding()`** — calls the legacy Geocoding API
         with `address=<text>&components=country:<cc>`. More
         forgiving on typos by design. Maps each result to
         the same shape (primaryText from formatted_address
         split on first comma). Non-OK status + error_message
         logged.
    2. **`Promise.all([runPlacesText(), runGeocoding()])`** —
       fires both in parallel.
    3. **Merge + dedup** — iterates Places results first
       (sharper on venue names), then Geocoding results.
       Dedup keys: `placeId` (when present) AND a rounded
       `lat|lng` coord key (since Places + Geocoding use
       different `place_id` namespaces, the same venue may
       show up with different IDs).
    4. **`RESULT_CAP = 6`** — up from the previous 5.
    5. **Cache key bump** — `placesearchbycountry:v1:` →
       `:v2:`. Prevents v0.61.191 cached 5-payloads from
       shadowing the new 6-result merged ones.
    6. **No-cache on empty** — operator typos shouldn't lock
       in "no match" for 1 h. Cache only when `merged.length
       > 0`.
    7. **Response shape** — always 200 with `{ results,
       countryCode, cached, notFound }`. `notFound: true`
       when both APIs returned empty AND no network errors.
       TMA continues to use `arr.length === 0 → setNoMatch`,
       so no client change required.
    8. **NEW log line** — `[place-search-by-country] cc=<CC>
       input="<txt>" places=<n> geocode=<n> merged=<n>` so
       the operator can see both branches contributed.

- **[KNOWN GAPS]**
  - If Google's quota / billing has tripped, both Places AND
    Geocoding return [] together. From the TMA perspective
    this is indistinguishable from "no results"; the operator
    would need to check the server log to see the underlying
    failures. We could surface a banner when both fail
    simultaneously with non-zero error counts — defer until it
    matters.
  - The merge is order-preserving: Places hits ranked first,
    then Geocoding. We could rank by "distance from query
    centroid" or by some quality score, but the operator
    didn't ask for that; current order is "venues first,
    addresses second" which matches the use case.
  - `regionCode` removed from the Places payload as part of
    debugging. If we later need it for billing locale (e.g.
    pricing in MYR for MY queries) we can put it back; it
    doesn't affect result constraint when
    `includedRegionCodes` is set.

## Amendments

- **`/api/cuisine/place-search-by-country` implementation** —
  was: single Places `searchText` call; 502 on any non-2xx.
  Now: parallel Places + Geocoding; 200 with `notFound: true`
  when both come back empty.
- **Result cap** — was 5 (`pageSize: 5`). Now 6 across both
  sources (`RESULT_CAP = 6`).
- **Cache versioning** — `placesearchbycountry:v1:` →
  `placesearchbycountry:v2:` because the schema changed
  (added `notFound`, max length 6).
