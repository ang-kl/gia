# Journal — soleat v0.61.324 (Cuisine TMA splash-gate HANG fix)

> Operator (05-06 '26, live on v0.61.323): *"currently is hang"*. The Cuisine TMA stuck on the "Confirming your location…" splash and never loaded results. Railway log after the v0.61.323 deploy shows `/api/cuisine/user-location` fetched + `set-location → SG` twice, but **no `cuisine-search` ever fired**.
>
> Root cause: v0.61.322's splash-gate opener (`App.jsx`) hard-required all three coherence one-shot refs — `coherenceCheckedRef && anchorCoherenceCheckedRef && (region JB ? regionCoherenceCheckedRef : true)` — before opening. But each check `return`s early WITHOUT setting its ref on legitimate "nothing to flag" paths:
> - v0.61.274 coherence: `if (!state.countryPref) return;` and `if (!coordsCountry) return;` (device coords outside the SG/MY bbox — e.g. the user is physically in Japan).
> - v0.61.321 anchor: `if (!a …) return;` (no saved anchor) and `if (!(a.name).trim()) return;`.
> Any unset ref left `ran=false` forever → the gate never opened → splash hung. Benign in v0.61.322 (the boot search had already run underneath), but v0.61.323 deferred the search to the gate, so a never-opening gate = no search at all = the hang.
>
> Commit 538 / journal 525 / build 325, branch `claude/v0.61.324-splash-gate-hang-fix` off main @ v0.61.323.
