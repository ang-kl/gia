- **[INTENT]** The Cuisine TMA map framed the results only on the very
  first data load (v0.61.93's `firstFitRef`); a later search no longer
  re-framed. The operator wants the first load *and* every search to
  zoom-to-fit the results.

- **[DELTA]**
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** — `syncMarkers`:
    `firstFitRef` (a one-shot first-load gate) is replaced by
    `lastFitVenuesRef`, which tracks the `venues` array last fitted.
    `fitBounds` now runs whenever `venues` is a **new array** (the
    first load and every search each produce one); a re-render with
    the **same** `venues` (e.g. `userLoc` resolving) still only
    `panTo`-recenters, so incidental re-renders keep the user's zoom.
  - **`package.json`** — `0.61.106` → `0.61.107` (PATCH).
  - **Scope:** Transport + Hawker keep their v0.61.93 first-load-only
    framing; `/app/map` already re-frames every render — both
    untouched, per the operator's scope ("Cuisine TMA, other TMA
