## New

### [HDR] #292 | 09:18 SGT 22-05-26 | v0.61.92 — train-overlay overlap-aware rendering | ~9 kb | 8 files | 1 PR | 1 build |

- **[INTENT]** Stop train-station labels piling up on top of each other
  (operator screenshots) by adding a screen-space overlap pass that
  demotes colliding markers; retune the Cuisine zoom tiers around an
  "is the result on screen" test; bring the Transport TMA's own MRT map
  (plain coloured dots) onto the same zoom-tier code-chip / named-pill
  rendering; and apply the operator's map-chrome changes (integer
  `📍 <z>` zoom readout, hidden Google text) to all three maps.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (canonical; byte-copied
    to the hawker + transport copies — all three md5-identical) —
    - **New overlap pass.** `metresPerPixelAt(zoom, lat)` (Web-Mercator
      ground resolution) + `demoteByOverlap(items, zoom, ref,
      overlapChip)`: a pure collision pass that estimates each marker's
      px footprint (`markerBoxPx`), walks the stations nearest-`ref`-
      first and demotes any marker whose box overlaps an already-kept
      one — a named pill → a code chip at `overlapChip`, a code chip →
      ~20 % smaller (floored). Pan-invariant (geometry only). Exported
      so the Transport map reuses it.
    - **`trainTier(tma, zoom, inFocus)`** — exported; gains `inFocus`.
      A `CHIP` scale ladder (LG 1.00 / MD 0.87 / SM 0.74 / XS 0.62 —
      "1 size" ≈ one ~13 % rung) documents the operator's loose "by 1/2
      size". Cuisine z12-14 now branches on `inFocus`: result inside
      the viewport keeps the v0.61.91 capRadius/cap behaviour; result
      off-screen → every station a plain code chip (z13 = z14 = SM,
      z12 = XS). z15+ named pills. Each chip/pill tier carries
      `overlapChip`. Transport branch rebuilt (z12-14 MD chip, z15+
      pill). Hawker tiers unchanged from v0.61.91 (+`overlapChip`).
    - `applyVisibility` train branch — computes `inFocus`
      (`map.getBounds().contains(anchor)`), resolves base tier modes,
      then runs `demoteByOverlap`; the tapped station is `pinned`
      (never demoted, processed first). New `idle` listener re-applies
      the train layer on pan (the in-focus state flips while panning).
    - `stationCodeNode` / `stationPillNode` exported (the Transport map
      builds its markers from them).
    - `ensureGreyscaleStyle` — appended CSS hides `.gm-style-cc` (the
      "Map data / Terms" attribution) + the "Keyboard shortcuts"
      button; the Google logo is kept, scaled to 0.4.
  - **`web/transport/src/components/MrtMapPanel.jsx`** — the MRT map's
    stations were plain `stationDotNode` dots with no zoom logic. Now
    `renderPins` resolves a `trainTier('transport', zoom)` mode per
    station, runs `demoteByOverlap`, and `transportStationContent`
    renders a named pill (z15+) / line-coloured code chip (z12-14) /
    dot (z<12 + future stations). A `zoom_changed` listener re-renders
    via a `renderPinsRef` (current-closure handle) with `keepView` so
    the framing block is skipped (no fight with the user's zoom). New
    `zoomLevel` state + the `📍 <z>` readout.
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** +
    **`web/hawker/src/components/HawkerMapPanel.jsx`** — the zoom
    readout restyled: integer (`Math.round`), transparent background,
    `📍 <z>` with a white text-halo for legibility.
  - **`__tests__/train-overlap.test.js`** — 10 new tests for
    `trainTier`, `metresPerPixelAt`, `demoteByOverlap` (demote the
    farther of two overlapping pills, leave separated stations, never
    demote a pinned station).
  - **`package.json`** — `0.61.91` → `0.61.92` (PATCH).
