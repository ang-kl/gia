## New

### [HDR] #285 | 20:58 SGT 21-05-26 | v0.61.87 — train overlay: whole network, always-on station code chip | ~3 kb | 4 files | 1 PR | 1 build |

- **[INTENT]** (1) When the Train Line overlay is on, draw the whole
  MRT/LRT network, not just the stretch near the map centre; (2) a station
  marker should always show its line code — never a bare square.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (canonical copy; byte-copied
    to the cuisine + hawker + transport copies, all three remain
    md5-identical per the KEEP-IN-SYNC header) —
    - **Whole-network draw.** The train layer was radius-clipped to 800 m
      of the map centre (`TRAIN_RADIUS_M`), so only nearby lines/stations
      drew and they re-evaluated on every `setAnchor`. The clip is removed:
      the full network draws when the Train overlay is on. `TRAIN_RADIUS_M`
      is now unused and deleted. (#1)
    - **Always-on code chip.** Station markers had three zoom states —
      bare square (`z < ZOOM_CODE_THRESHOLD = 13`), code chip (`13 ≤ z <
      15`), named pill (`z ≥ 15`). The square state hid the code. The
      square is dropped: a station now always renders the line-coloured
      `stationCodeNode` code chip, expanding to the full named pill at
      `ZOOM_DETAIL_THRESHOLD = 15`. The per-station `_mode` swap in
      `applyVisibility('train')` goes from three states to two
      (`code` ↔ `pill`). `squareStationNode` and `ZOOM_CODE_THRESHOLD`
      are now unused and deleted. (#2)
  - **`web/hawker/src/lib/mapOverlays.js` · `web/transport/src/lib/mapOverlays.js`**
    — byte-copies of the canonical cuisine file (md5-identical).
  - **`package.json`** — `0.61.86` → `0.61.87` (PATCH).
