## New

### [HDR] #475 | 09:10 SGT 30-05-30 | v0.61.274 — coherence modal (Cuisine + Menu) | 6 files | 1 PR | 1 build |

- **[INTENT]** The four-phase arc (v0.61.270 – v0.61.273) closed the SSOT data shape — writer parity, country round-trip, end-to-end countryCode, sentinel default. But it did NOT close the mount-time reconciliation policy. The operator's two screenshots show saved per-user prefs (countryPref / region) leaking across sessions and overriding the freshly-resolved GPS. v0.61.274 adds the policy: coords are canonical at mount; saved prefs that disagree get prompted.

- **[DELTA]**

  **1. `web/cuisine/src/v2/lib/coords-to-country.js`** (new)

  Pure-function coords→country detector. Returns `'SG' / 'MY' / null`:
  - SG bbox 1.15–1.47, 103.55–104.10 (tightened from prior callers' 1.50 cap so JB CBD at 1.49 falls into the JB bbox, not SG)
  - JB extent (Johor state) 1.20–2.55, 102.50–104.50 — covers JB CBD, Pontian, Desaru, Kulai, Mersing
  - Peninsular MY north of Johor 2.55–6.85, 99.50–104.80 — covers KL, Putrajaya, Penang, Selangor, etc.
  - East MY (Sabah + Sarawak) 0.85–7.50, 109.50–119.30
  - Anywhere else → `null` (caller treats as "I don't know — defer to iataSnap / reverse-geocode")

  Exports `coordsToCountry({ lat, lng })` + `isJbCoords({ lat, lng })` (the latter for future region-pill auto-flip on JB-extent coords).

  **2. `web/menu/src/coords-to-country.js`** (new, mirror)

  Identical file copied to the menu TMA's src/ — Vite builds the two TMAs separately and they can't easily share lib files. Operator workflow stays in sync as long as both files are touched in lock-step.

  **3. `__tests__/coords-to-country.test.js`** (new, 26 tests)

  Covers SG mainland (centroid, Tanjong Pagar, Tuas, Changi); MY (JB CBD, Mid Valley Southkey, Pontian, Desaru, KL, Penang, Putrajaya, Kota Kinabalu, Kuching); elsewhere returning null (Bangkok, Jakarta, Tokyo, Sydney, Queenstown NZ — the operator's screenshot trigger); defensive null/NaN/out-of-range handling; isJbCoords subset detector.

  **4. `web/cuisine/src/v2/App.jsx`**

  - New state: `coherenceMismatch` (object `{ saved, coords }` or null) + `coherenceCheckedRef` (one-shot guard).
  - New `useEffect`: fires once after `userLoc` resolves + `state.countryPref` loads. Computes `coordsToCountry(userLoc)`; if non-null AND disagrees with state.countryPref AND the UI is in a path that uses countryPref (region = OTHER / MY-PUT / __NONE__), sets `coherenceMismatch`.
  - New helper `applyCoherenceChoice(useCoords)`: on "Use {coords}" path resets region + countryPref to coords-derived AND persists via `saveCountryPref`; on "Keep {saved}" path leaves state untouched.
  - New JSX: modal rendered above the existing header. EN + FR copy. Two buttons; sticky until user picks.

  **5. `web/menu/src/App.jsx`**

  - `setAnchor` now surfaces `b.country` from `/api/cuisine/user-location` (v0.61.270 already returns this field; pre-v0.61.274 the Menu TMA dropped it).
  - Same coherence-check `useEffect`: compares `anchor.country` against `coordsToCountry(anchor)`. The Menu TMA's authoritative country lives on `anchor`, not on a separate `countryPref` state (the LocationFieldMenu's local `countryPref` is render-only).
  - `applyCoherenceChoice(true)` rewrites the anchor in-memory AND fires a `/api/menu/set-location` POST with the corrected country, so the next session doesn't re-prompt. The JB-vs-OTHER distinction inside MY uses `anchor.lat < 1.55` as a coarse JB check (matches `isJbCoords` semantics without the import).
  - Same modal JSX as cuisine; rendered at the top of the App return.

- **[KNOWN GAPS]**
  - **Single-prompt scope** — the check runs only on mount. If the user changes coords mid-session (rare; would require Telegram WebApp.locationManager continuous-update), the check doesn't re-fire. Acceptable for now.
  - **Bangkok / Jakarta detection** — `coordsToCountry` returns null for coords outside SG/MY. We trust the saved pref (or wait for v0.61.243 iataSnap). If you want the modal to also fire for "you set NZ but coords are now Bangkok", we'd need to wire in iataSnap synchronously, which is a paid API call per mount.
  - **JB inference inside MY** — Menu TMA's `applyCoherenceChoice` uses `anchor.lat < 1.55` as a coarse JB check. Mid Valley Southkey at 1.49 passes; Mersing at 2.43 falls into OTHER. Acceptable approximation.
  - **Race against v0.61.243 GPS auto-detect** — both fire after userLoc resolves. The auto-detect runs first (no awaiting); my coherence check waits for `state.countryPref` to update via the v0.61.196 fetchCountryPref effect. In practice this means the modal sees the FINAL countryPref value, not a transient. Logged at `[Cuisine-TMA-v2] coherence MISMATCH` so prod logs can verify ordering.
