## New

### [HDR] #561 | 12:15 SGT 07-06-26 | v0.61.361 — Option B device currency (Intl region → ~170-nation map) | 2 code files + 1 test | 1 PR | 1 build |

- **[INTENT]** Make the cross-border `(≈…)` conversion land in the currency the traveller **actually spends** — the phone's home currency — across the ~170 nations a user could be from, instead of the location-based country (which for a tourist is the *wrong* currency).

- **[MECHANISM]**
  - **Client (`web/cuisine/src/v2/lib/api.js`)** — NEW `deviceRegion()`: derives the phone's home region (ISO-3166 alpha-2) **once** from `navigator.language` via `new Intl.Locale(lang).maximize().region` (`"en"`→`US`, `"zh"`→`CN`, `"en-SG"`→`SG`), with a fallback to the explicit region substring (`"en-GB"`→`GB`) for older WebViews. `postJson` now injects **`deviceRegion`** into every request body (alongside `initData`); the server validates + ignores it where price conversion doesn't apply.
  - **Server (`currency-format.js`)** — `COUNTRY_TO_CURRENCY` expanded from ~30 → **~170** ISO-3166→ISO-4217 entries (Asia-Pacific incl. the picker neighbours MO/BN/KH/LA/MM the old ECB map omitted, the Americas, full Eurozone, rest of Europe, Middle East, Africa). Added a dozen recognisable `CURRENCY_PREFIX` symbols (MOP$/B$/R$/₽/₺/₪/AED/SAR/R/Mex$/₦); MO/BN added to `COUNTRY_PREFIX`. The long tail still renders cleanly via the `"CODE "` fallback (e.g. `SEK 320`).
  - **Server (`index.js`)** — `enrichPriceRangeDisplay(chatId, venues, deviceCountry)` now **prefers** a valid `deviceCountry` (`^[A-Z]{2}$`) and only falls back to `resolveUserCountry(chatId)` when it's absent. Wired at the **`/api/cuisine/search`** enrich site (`deviceRegion` parsed beside `countryCode`) and inside **`handleMichelinSearch`** (`michDeviceRegion` from `req.body`). The bot-chat enrich sites (Search / Search-FanOut / Nation-Iconic / Cooking-Method — all `safeSend`) stay on the location fallback **by design** (no device there).
