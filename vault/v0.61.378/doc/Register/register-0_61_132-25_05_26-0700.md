## Decisions (append-only)

| # | Decision | Rationale | Date |
|---|---|---|---|
| D-61.129 | **Cuisine TMA `/api/cuisine/search` is now place-aware.** When the Tell-me free-text box typed text names a recognised Singapore place — either standalone or in an `<query> in/near/around/at <place>` pattern — the handler pivots `searchCenter` to that place, tightens `searchRadius` to `place-detector.NEARBY_RADIUS_M` (1500 m, anchorCap-clamped), and strips the matched span from `ftRawIn` so downstream cuisine-query construction is clean. Re-uses the same `place-detector.detectPlaceName` ladder the chat `/s` flow has used since v0.61.119 (STB precinct → MRT → hawker → SG-bbox-clamped Google geocode). Skipped for JB (place-detector data is SG-only). Surfaced as `payload.placeAnchor { name, kind, lat, lng, source }` + `payload.placeAnchorQueryRemainder`. **And, in the same handler:** when Fruits/Durian special-mode searches return fewer than the spec target (8 mode-filtered venues), the handler progressively widens the search radius (2× then 3× the initial radius, capped at `anchorCap` or 30 km hard cap) — per the `scripts/Create_2_buttons.MD` "Fallback behaviour" clause. `searchRadius` itself is NOT mutated downstream (preserves cache keys + the re-tap dedup-slice logic); the widened-from / widened-to metres are surfaced as `payload.specialModeWidened` + `specialModeWidenedFromM` + `specialModeFinalRadiusM`. | Closes Register Open Items O-20 (the only user-facing gap per the v0.61.127 Register) and O-23 (`scripts/Create_2_buttons.MD` "Fallback behaviour" clause; the v0.61.126 PR's `specialModeLimited` flag surfaced the limitation but didn't fix it). | 24-05 '26 |
| D-61.130 | **TMA layer surfaces the v0.61.129 backend fields.** Cuisine TMA's React `App.jsx` renders two new info elements above the result list: (a) a *"📍 Searching near `<place>`"* pill (or *"📍 Showing '`<query>`' near `<place>`"* when `placeAnchorQueryRemainder` is non-empty), with the informational `border-tg-border` style — NOT amber/alert; (b) a *"· widened to N.N km"* caption (text-tg-hint, secondary) appended to the existing amber *"Limited matches nearby"* card when `specialModeWidened` is true. New i18n keys live in `web/cuisine/src/v2/lib/i18n.js`: `anchor.searching`, `anchor.showing`, `special.widened` — EN + FR. Both fields persist on the page-cache `newPage` and are restored by the Back/Forward effect alongside the cached venues. Both are cleared on `questionDeclined` and on the top-level `catch` so a stale pill doesn't sit above an empty result list after a network blip. **And, per the v0.61.131 follow-up:** the place-anchor pill renders FIRST in the info-card stack (above `misrepNote` and the amber `specialModeNotice` card) — *"where am I searching"* outranks the dish-name aside and the limited-matches card because it explains WHERE the visible results come from; the others qualify the WHAT/WHY of those same results. | The v0.61.129 backend surfaced the new payload fields but the React layer didn't render them — feature was silently correct but invisible to the user. v0.61.131 then closed a v0.61.130 KNOWN GAP (pill order — *"a layout call to defer until operator preference"* → operator confirmed *"render first"*). | 24-05 '26 + 25-05 '26 |
