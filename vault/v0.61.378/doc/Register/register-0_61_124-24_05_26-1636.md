| D-61.120 | Chat free-text path gains a deterministic "<cuisine> + <food noun>" whitelist (`freetext-classify.looksLikeCuisineBrowse`) that short-circuits the v0.60.216 Gemini food-relatedness gate. Bypass fires iff the text contains BOTH a cuisine word (catalogue cuisine via `cuisine-family.cuisineFamily` OR an umbrella from `CUISINE_UMBRELLA_WORDS` like `western`/`asian`/`fusion`/`continental`/`international`/`pan asian`/`eclectic`/`global`) AND a food-specific noun (`cuisine`/`food`/`restaurant`/`eatery`/`dining`/`dish`/`menu`/`kopitiam`/`hawker`/`foodcourt`/`nearby`/`near`/`around` + plurals). Bare cuisine words (`italian`) and bare food nouns (`restaurant`) still go through the gate. | Operator-reported defect: `"western cuisine nearby"` returned the food-nudge decline because Gemini's prompt only buckets text as `dish/ingredient/tool/venue/ambiguous` and `"western"` is an umbrella with no family in `cuisine-family.js`. The whitelist is the cheapest fix and reduces Gemini-Flash spend. | 24-05 '26 |
| D-61.121 | Chat free-text gains a place-anchored search path (`runPlaceAnchoredSearch` / `runNearbyAlternatives`). Detection is a deterministic ladder via the new `place-detector.js`: MRT/LRT first (whole-word match against `data/mrt-coords.json`), then hawker (`hawker-vault.findByName` fuzzy), then geocode fallback (`vibe-suggest.geocodeQuery`). Per-kind radii: hawker 150 m / MRT 400 m / geocoded 300 m / nearby button 1500 m. MRT-first ordering chosen because the hawker fuzzy matcher otherwise prefers obscure blocks over obvious stations for queries like `"Tanjong Pagar"`. | Operator request: `"if I type in address or building name or place, you should priority search for that place, mention there are # of # eateries there"`. The deterministic ladder keeps the path cheap (no extra LLM call) while the geocode fallback handles arbitrary places. | 24-05 '26 |

| D-61.123 | The Menu TMA hub adds a `LocationFieldMenu` below the PLAN section heading.
