## New

### [HDR] #192 | 17:10:00 SGT 16-05-26 | v0.60.224 — Map pins: Cuisine white-bg glyph pins + Hawker tiny pins | 3 files | 1 PR | 1 build |

- **[INTENT]** Operator (area D): *"4a Cuisine TMA pins → white background so ✳️ Michelin / 🐾 glyphs are visible; 4b Hawker TMA → custom tiny pins."*

- **[DELTA]**
  - **4a — `web/cuisine/src/v2/components/MapPanel.jsx` `syncMarkers()`.** Venue pins that carry an emoji glyph (`pinGlyphFor` → ✳️ / 🐾 / 🍮) now use `background:'#ffffff'` instead of the green `#34C759` circle. Root cause: `PinElement.glyphColor` has no effect on multi-colour emoji — the emoji renders in its own colours, so on a saturated green circle the symbol washed out. White background restores contrast. Focus is now signalled by an **orange border** (`borderColor:'#FF9500'`) + the existing scale-1.3 bump rather than an orange **fill**, so a focused glyph pin still shows its emoji. Non-glyph pins keep the green fill (focused → orange fill, unchanged) and white glyph dot.
  - **4b — `web/hawker/src/components/HawkerMapPanel.jsx` `syncMarkers()`.** Replaced the default Google teardrop `PinElement` markers (red `🍚` / gold `🆕`, scale 1) with a custom **tiny-dot DOM node** passed as the `AdvancedMarkerElement` `content`. New helper `tinyPinNode(isNew)` builds a 13 px circle, 2 px white border, soft drop-shadow — gold `#f5a623` for the 16 `isNew` centres, red `#e53935` for established. The 🆕 distinction still surfaces in the InfoWindow title. `PinElement` dropped from the `window.google.maps.marker` destructure (now unused).
  - `package.json` `0.60.223 → 0.60.224`; this Journal entry (#192); `doc/.serial-state.yml` (`journal 191→192`, `commit 198→199`, `build 7→8`, `chat_counter 17→18`; re-anchored 17:10 SGT).
