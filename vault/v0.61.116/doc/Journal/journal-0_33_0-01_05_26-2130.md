## New

### [HDR] #72 | 21:30:00 SGT 01-05-26 | v0.33.0 | n/a kb | n/a lines
- **[INTENT]** Per the v0.32-v0.36 roadmap, ship `/hawker` — the second leg after the v0.32.0 foundation. From the original ask:
  > "Second, develop the dedicated /hawker command and state machine. Create a comprehensive NEA API module that powers a new submenu for the /hawker command. The logic must support five distinct filters: find the nearest 3 operational centres, identify centres currently closed or undergoing scheduled cleaning, assess real-time crowd levels, and provide a categorical list of 70 major centres divided into North, South, East, West, and Central zones."

- **[DESIGN]**
  1. **Curated dataset** — `data/hawker-centres.json` ships 33 well-known SG hawker centres with name + address + lat/lng + zone classification. Honest framing: this is a starter subset, not the full ~120-centre NEA registry. Future patch can swap in live NEA API fetch.
  2. **`hawker.js` module** — pure functions: `nearestCentres(lat, lng, count)` (haversine sort), `centresInZone(zone)`, `allZones()`, `googleMapsUrl(c)`. No external API calls; data loaded once at module init.
  3. **`/hawker` slash + 4-button menu** (Train-style sub-menu pattern, mirroring v0.31.1 `/transport`):
     - 🚏 Nearest 3 — sorted by haversine from saved location
     - 🗺 By zone — opens 5-button zone picker (Central/South/East/West/North)
     - 🧹 Cleaning info — explicit disclaimer + link to NEA's authoritative quarterly schedule URL
     - 👥 Crowd — honest "no live API exists; here's carpark availability as a footfall proxy"
  4. **Cleaning schedule honesty** — NEA's quarterly cleaning calendar varies per centre and changes every 3 months. Embedding it inline would rot fast. Every reply ends with "Verify cleaning at <NEA URL> before you go" plus a button that opens the NEA page directly. The user's spec said "ensure no closed locations are recommended" — we honour the spirit (don't pretend to know) by deferring to the source of truth.
  5. **Crowd honesty** — Per Decision #74 in v0.32.0 register, NEA does NOT expose a live hawker-crowd API. The v0.33 reply explicitly says so and offers carpark availability within reach as a proxy. No fake telemetry.

- **[DELTA]**
  - **NEW `data/hawker-centres.json`** — 33 centres, 5 zones (Central 9 / South 5 / East 6 / West 7 / North 6), each with name + address + lat/lng + tags for famous dishes.
  - **NEW `hawker.js`** — `loadData`, `nearestCentres`, `centresInZone`, `allZones`, `totalCount`, `datasetVersion`, `googleMapsUrl`, `formatCentreLine`, `haversineMeters`, `NEA_SCHEDULE_URL` constant.

    - New handlers: `sendHawkerMenu`, `sendHawkerZonesMenu`, `runHawkerNearest`, `runHawkerZone`, `runHawkerCleaning`, `runHawkerCrowd`.
    - `setMyCommands` adds `hawker — Hawker centres — nearest, by zone, cleaning info` row.
    - `routeMenuCommand` adds `case 'hawker'` for tile/deep-link parity.
  - **`package.json`, `web/cuisine/package.json`, `web/menu/package.json`** — version 0.32.0 → 0.33.0.

- **[KNOWN GAPS]**
  - **33 centres is not 120.** NEA's full registry has ~120 centres + markets. Future v0.33.x can either expand the static JSON or fetch the live NEA dataset at boot.
  - **No live cleaning data.** We link to NEA's URL as the source of truth instead of staling the data here. The original ask wanted "cross-reference cleaning schedule database to ensure no closed locations are recommended" — that requires live data we don't have. Documented as a deferred enhancement.
  - **No live hawker crowd API.** Carpark availability is a *cars-not-diners* proxy with known weakness (lunch crowd at Maxwell is overwhelmingly walk-in; carpark availability won't move). Documented honestly.
  - **Zone classification is colloquial,** not Urban Redevelopment Authority planning regions. Some centres straddle zones (e.g. Newton is technically Central North); we used SG colloquial groupings.
