- **[INTENT]** Operator-reported regressions on the v0.60.195-spec Cuisine TMA:
  1. **HTTP 500** on first Michelin tap (full chip or combo). Operator: *"happens before, check past PR"* — recurring intermittent, now made consistent by v0.60.195.
  2. **"🍴 Try · meat"** (Cumi Bali) + **"🍴 Try · chocolates"** (Saint Pierre) on the ResultCard's primaryDish line. Operator: *"It ought to be a dish, a dessert."*
  3. Documentation reference — operator pasted the three render-surface specs (Copy-All Telegram message · `/s` rich card at `index.js:5208` · ResultCard.jsx). No action; filed as cross-reference for future template touches.

- **[ROOT CAUSE — #1]** v0.60.195 deleted the `slugify` const helper as part of removing the `michelin:place:<slug>` 24-h Places cache. But `index.js:6576` **still** uses `slugify(...)` to build the **separate** `michelin:enrich:<slug>` 7-day enrichment-cache key (LLM-narrate output: `vibe` / `signatureDish` / `dishes` / `recentReview`). That line is at top-level of `handleMichelinSearch`, NOT inside try/catch, so the `ReferenceError: slugify is not defined` escapes → `/api/cuisine/search` 500s on every Michelin tap. Operator screenshot timing matches the v0.60.195 deploy. v0.60.194 reference: `grep slugify index.js` had 1 declaration + 2 uses (Places cache + enrich cache); v0.60.195 dropped the declaration and one use, but missed the enrich use.

- **[ROOT CAUSE — #2]** Generic ingredient nouns ("meat", "gravy", "chocolates", "bread", "sauce") pass through two failure points:
  - The review-regex extract at `index.js:6519-6522` requires capitalisation (`[A-Z]…`), so the regex itself wouldn't surface lowercase nouns — but Gemini's `narrateMichelinVenues` does, and its output had no denylist guard. The model picks the lowest-common-denominator noun ("meat") when handed a review snippet listing multiple proper dishes (Beef Rendang, Ayam Sate, Sayur Lodeh).
  - The denylist `MICH_CATEGORY_BLOCK` at `index.js:6518` only covered **structural meal categories** (restaurant / place / food / etc.), not ingredients or beverages.

- **[DELTA]**

  **`index.js` `handleMichelinSearch`** — three precise edits.

  *(1) Restore `slugify`*: top of the handler, just before `resolveEntryPlace`. Same shape as v0.60.194 (lowercase → `[^a-z0-9]+`→`-` → trim → ≤80 ch). Inline comment marks it as enrich-cache-only post-v0.60.195. **The Places cache stays removed** — slugify is now consumed by a single call site (the `michelin:enrich:<slug>` key builder at line 6576).

  *(2) Hoist + extend `MICH_CATEGORY_BLOCK`*: moved out of the Step-1 review-extract try-block to handler scope so Step-3 LLM-narrate can share it. Added denylist tokens: `meat|meats|gravy|gravies|sauce|sauces|chocolate|chocolates|bread|breads|wine|wines|cocktail|cocktails|beer|beers|appetizer|appetizers|entree|entrees|portion|portions|serving|servings|flavor|flavors|flavour|flavours|taste|tastes|texture|textures|ingredient|ingredients`.

  *(3) Apply denylist to LLM-narrate output* (line ~6618 narrate block): new `isUsableDish` predicate gates both `signatureDish` assignment and the `dishes[]` filter. Rejects empty/short (<3 char), long (>40 char), and `MICH_CATEGORY_BLOCK`-matching candidates. If Gemini emits "meat" as `signature_dish`, it's silently dropped → falls through to Step-4 force-fill (tier-aware boilerplate) so the card never ships empty.
