## 0. What this project is

**Soleat** (package name `soleat`; product name *Gia4lunch* / "Gia") is a production Telegram bot + five Telegram Mini Apps (TMAs) + an Express server that helps a solo diner in Singapore decide where to eat — and get there. It spans F&B discovery (cuisine picker, hawker centres, Michelin / Bib Gourmand, hidden gems), free-text and cooking-method search, live transport and traffic, an interactive Google-Maps overlay system, carpark availability, weather, and a bilingual (EN/FR) interface. It is a single-operator project built with AI-assisted development, deployed on Railway, and has reached **v0.61.28** across ~237 numbered commits and ~510 pull requests.

The Builder doc records *how* the project is built — the operating lens, the conceptual framework, and the recurring patterns — distinct from *what* it does (Feature), *what it runs on* (Technical), and *who builds it* (Persona).

## 2. Framework

> The conceptual scaffolding used to organise the work.

| # | Framework concept | Description | Origin | Status |

| FW-1 | **Layered architecture — data → policy → surface** | Data acquisition (Places / Routes / LTA / NEA / Gemini / geo-overlay clients), policy (search classification, plausibility, ranking), and surface (Telegram templates + the five React TMAs). One concern per module. | v0.58 | live |

| FW-3 | **Reason → Fetch → Refine pipeline** | The discovery pipeline: an LLM *reasons* about intent, the server *fetches* and validates candidates against Google Places, the LLM *refines* / narrates. Each phase is independently retried and degradable. | v0.58 | live |
| FW-4 | **Eight-folder documentation system** | Builder / Persona / Feature / Technical / Legal / Journal / Chat / Register — each with a template skeleton and versioned `<type>-<v>-<d>.md` files, governed by the AU authenticity Recipe, serial numbers, time anchors, and Confirmation Gates. A build-time, data-only step — re-run on a source refresh. | v0.61.0 | live |
| FW-7 | **Confirmation Gates G1–G4** | Structured checkpoints for version bumps, destructive actions, new decision rules, and paid API calls — each surfaced with a default and an authority stamp. | doc-system arc | live |

| FW-9 | **Diagnostic-code (D-code) instrumentation** | Server- and TMA-side execution is tagged with D-codes so a screenshot or a log line pinpoints which path produced an output. | v0.29+ | live |
| FW-10 | **Shared overlay controller** | `mapOverlays.js` — one framework-agnostic controller for every map surface: chip-toggled overlay layers (parks / attractions / carpark / exits / taxis), a train-line layer with a station-detail focus mode, and the shared `attachAmenityPins` venue-tap helper.
