## New features in this arc

### Cuisine TMA · `[object Object]` root-cause kill — Michelin + cuisine-chip + free-text paths (v0.60.154 / v0.60.155 / v0.60.156 — PRs #395, #396, #397)

- **What** — A three-PR convergent fix on a recurring operator-reported defect: Michelin cards (and later, cuisine-chip / free-text cards) showed `💬 "[object Object]"` in place of a real review snippet. Each PR addressed one layer until v0.60.156 found the real source:
  1. **v0.60.154 (PR #395)** — first-pass guards in `formatTechniqueVenueBlock` + the Michelin card renderer: `typeof === 'string'` checks before rendering review snippets / dish strings. Also introduced the "Curating Michelin list" loading hint at this point (later folded into v0.60.153's loadingHint contract). Operator screenshot showed the bug *still* appearing → the rendered string was passing `typeof === 'string'` because `String({…})` is itself a valid string.
  2. **v0.60.155 (PR #396)** — defence-in-depth: WRITE sanitize at the `michelin:enrich:<slug>` cache write site + force-fill sanitize at the cache read site + render sanitize at the final formatter. Plus per-criteria seen-set reset on every TMA mount (a follow-up to the v0.60.153 dedup fix). Operator screenshot from a fresh tap STILL showed the literal string → confirmed that some upstream `String(…)` call was producing `"[object Object]"` BEFORE any of these guards saw the value.
  3. **v0.60.156 (PR #397)** — root cause found. Places API v1 returns reviews as `{ text: { text: '…', languageCode: 'en' } }` — a nested-`.text.text` shape, not bare strings. The `index.js` Michelin review-extract did `String(recent[0].text || '').slice(0, 200).trim()` and `recent.map((r) => r.text || '').join(' . ')`. Without unwrapping the inner `.text`, `String({…})` coerces to the seven-character-plus-three-character string `"[object Object]"` which silently passes every downstream `typeof === 'string'` check. The fix introduces a `reviewText(r)` local helper that handles both v1's nested shape and any legacy bare-string response, and applies it at FIVE sites: the Michelin handler (regex pool + `v.recentReview`), and the cuisine-chip path in `extractDishes` (recent filter + allText.map + return-`snippet` + the `v.reviews[0].text` fallback). Bug eliminated at source; the v0.60.154 + v0.60.155 guards stay as belt-and-braces.
- **Why** — Operator screenshots across three sessions: *"💬 '[object Object]' didn't solve."* + *"Issue 2 picture — Copy resulted in 'Couldn't send to chat — try again.'"* (the latter motivated the companion `/api/cuisine/copy-one` hardening below).
- **Where** — `index.js` (the `reviewText` helper + 5 call sites in Michelin handler + `extractDishes`); `web/cuisine/src/v2/components/ResultCard.jsx` (v0.60.154 typeof guards retained); `pipeline.js` `narrateMichelinVenues` (force-fill sanitize retained).

### Cuisine TMA · client-side page history with `⇠ Back` / `⇢ Next` FABs (v0.60.154 — PR #395)

- **What** — Replaces the single-step `⇠ Prev` FAB (v0.60.146) with a two-FAB client-side navigation: `⇠ Back` and `⇢ Next` live in a left-cluster column, fixed bottom-left, mirror of the `🔍 Search` / `↑ Top` right-cluster. Each successful search pushes a Page object (venues + comboInfo + misrepNote + cookMethodPivot + sessionFull + pageStackDepth + michelinRemaining + exhausted + poolCount + criteriaState + freeText + locationAnchor + searchCenter) onto a `pages` array; `cursor` indexes into it. Tapping `⇠ Back` / `⇢ Next` moves the cursor and an effect re-applies every per-field setter — no server round-trip. A search-after-back truncates the forward branch (so back-walks can't orphan stale future pages). Caps: **17 pages** for normal cuisine flows (~200 venues at 12/page), **11 pages** for Michelin (~130 entries). Oldest page is shifted off on overflow so the cap is honored. Per Codex review on PR #395, the page payload now persists the **full criteria/freeText/location snapshot** so that `⇠ Back` not only restores the venue list but also re-applies the chips, the ✳️ Michelin loading-hint trigger, the copy-all heading, and the next 🔍 round-trip — i.e. back-walks no longer described a different search than they showed.
- **Why** — Operator: *"client-side storing of ~130 Michelin … and 200 listing of search Criteria and/or free-text within Cuisine TMA."*
- **Where** — `web/cuisine/src/v2/App.jsx` `pages` + `cursor` state + the cursor effect at lines 168–199; the left-cluster FAB block alongside the existing right-cluster.

### Cuisine TMA · per-criteria seen-set reset on TMA mount (v0.60.155 — PR #396)

- **What** — The long-lived `cuisine:seen:<chatId>:<criteriaHash>` Redis SET (per-criteria dedup across sessions; no TTL until the user explicitly taps ↺ Start over) accumulated indefinitely. Over a multi-week session the same criteria signature would consistently return zero new venues. v0.60.155 adds a one-shot reset call to `POST /api/cuisine/session/start` (which already runs on every TMA mount via the v0.60.146 session-clipboard machinery), wiping any stale per-criteria seen-set entries older than the current mount. The user's "list #1 again" experience now self-heals on every fresh launch without the user having to remember the ↺ button.
- **Why** — Operator: *"After many sessions, the same criteria returns nothing — I want a fresh slate on each open."*
- **Where** — `cuisine-session.js startSession`; `/api/cuisine/session/start` route in `index.js`.

### Cuisine TMA · `/api/cuisine/copy-one` plain-text retry (v0.60.156 — PR #397)

- **What** — Companion fix to the v0.60.145 `/api/cuisine/copy-all` hardening. The single-venue 📋 Copy button (per-card, distinct from the all-12 📋 Copy all) hit *"Couldn't send to chat — try again."* on venues whose HTML body had tricky punctuation (stray `&`, unmatched `<b>`). Wrapped the `bot.sendMessage(chatId, body, htmlOpts)` call in the same try/retry pattern: on HTML parse-mode failure, strip tags + unescape entities and retry as plain text; only 500 if both attempts fail. Log line `[Cuisine] copy-one sendMessage retry failed (plain): <description>` for the latter.
- **Why** — Operator screenshot, same batch as the `[object Object]` issue.
- **Where** — `index.js` `/api/cuisine/copy-one` handler (~line 8024).

### Cuisine TMA · zero-results auto-retry + 🔄 Reset filters & retry CTA (v0.60.157 — PR #398)

- **What** — A two-layer fix for the silent empty-state UX. When `/api/cuisine/search` returns `venues: []`:
  1. **Silent auto-retry** — `runSearch` fires exactly **one** follow-up call with `opts.resetSeen=true`. Handles the most common cause: the per-criteria seen-set having accumulated past the dedup pool over a long session — the reset wipes the exclusion + variant index server-side, so the first ~60 entries come back. Loop-safe via the `opts.resetSeen` recursion-break check; per-criteria scope via a `stateSig`-keyed ref (`lastZeroRetrySnapRef`) so the same signature can never auto-retry twice, but any criteria change re-arms the budget.
  2. **Prominent retry CTA** — if the silent retry ALSO returns zero, a rounded `bg-tg-card` panel renders below the result list with the bilingual *"No matches even after a fresh search. Try widening your criteria above, or tap below to reset filters and try again."* hint + a pill-shaped `🔄 Reset filters & retry` button. The Search-criteria card is auto-expanded in this branch so the user sees their chips immediately without scrolling. Tapping the button re-arms the auto-retry guard and re-fires `resetSeen=true`; if the response is still zero, the panel persists (no flicker).
  - Any non-zero result clears both the flag and the ref so a future criteria-revert can fresh-retry.
- **Why** — Operator (verbatim): *"Bug: If results return zero, should refresh the criteria again."*
- **Where** — `web/cuisine/src/v2/App.jsx` (`lastZeroRetrySnapRef` + `zeroRetried` state at line ~134; the four-branch decision block at line ~554 in `runSearch`; the CTA render block at line ~1249); `web/cuisine/src/v2/lib/i18n.js` two new keys (`result.noMatchAfterRetry` + `btn.resetFiltersRetry`, EN + FR); `__tests__/cuisine-zero-retry.test.js` six vitest cases covering the `decideAutoRetry` truth table.
