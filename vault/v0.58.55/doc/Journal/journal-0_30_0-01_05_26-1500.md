## New

### [HDR] #58 | 15:00:00 SGT 01-05-26 | v0.30.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead "Can I type anything in the bot chat and you search as well? But you can referee if I am not search anything related to cuisine, groceries, food or drinks and it can be multiple languages… Example, show me Michelin star food in Mandarin or Arabic or French". Open up free-text chat as a first-class entry point with multi-language support and intent gating.
- **[DELTA]**
  - **NEW** `nl-intent.js` — `classifyIntent({text, langCode, redis})` calls Gemini Flash with a structured prompt that:
    1. Classifies intent: `food` | `drinks` | `groceries` | `other`
    2. Extracts canonical English cuisines from our 73-entry catalogue (matches `web/cuisine/src/state/cuisines.js`)
    3. Extracts `special_request` (free-form qualifier — "Michelin-starred", "halal", "vegetarian", "kid-friendly", "late-night", "outdoor seating", "budget under $20", etc.)
    4. Detects input language (ISO 639-1)
    5. Generates `ack_text` in the SAME language as input
    Cached per `(langCode, sha1(text))` for 60 s in Redis. Confidence threshold = 0.6 — below that we fall through to the existing gatekeeper.
  - **`index.js`** — new free-text branch in `bot.on('message')` between the pending-meal consume and the gatekeeper:
    1. Skip slash commands + keyboard taps (existing guards).
    2. Call `classifyIntent` (~1.5–2 s).
    3. If intent ∈ {food, drinks, groceries} and confidence ≥ 0.6:
       - Send `ack_text` (in user's language) to chat.
       - If location cached: dispatch `runNLFlow(chatId, lat, lng, {cuisines, specialRequest, intent})`.
       - If no location: stash payload as `nl:<json>` pending state, prompt `LOCATION_REQUEST_KEYBOARD`. Resumes once location arrives.
    4. Else: fall through to existing `gatekeep(redis, text)` (off-topic steering).
  - + `runNLFlow(chatId, lat, lng, payload)` — calls `searchCuisine` with `cuisines` + `specialRequest` + sensible defaults (radius 1km, recency 90d, queue 15min, walk, now). Delivers via `deliverPicks`.
  - + Pending-state extension — `resolvePending` recognises `nl:<json-payload>` prefix, returns `{kind: 'nl', cuisines, specialRequest, intent, lang}`. All three location-resume sites (default-Raffles fallback, location-share keyboard, place-name typed) now branch on `resolved.kind === 'nl'` to call `runNLFlow`.
  - + Diagnostic codes (Railway-side only — `[NL-Intent]` prefix):
    - **D750** received chat=N lang=… bytes=N
    - **D751** dispatching intent=food confidence=0.9
    - **D752** runNLFlow failed (catch path)
    - **D753** falls through (intent=other or low confidence)
  - **`cuisine-search.js`** — `searchCuisine` accepts `specialRequest` (default empty); `buildPrompt` and `geminiCandidates15` and pipeline `runPipeline.query` all thread it through. New prompt line: `Distinctive user qualifier (HONOUR THIS): <special_request>` so Gemini surfaces venues matching the qualifier.
  - **`pipeline.js`** — `buildReasonPrompt` adds the same line when `query.specialRequest` is present.
- **[VERIFICATION (sandbox)]**

  ```
  node -e "require('./nl-intent')" → exports {classifyIntent, MIN_CONFIDENCE, CUISINE_CATALOGUE: 73 entries}
  ```
