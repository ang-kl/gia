## New

### [HDR] v0.62.650 — six numbered Train items and one Cuisine gap, from three screenshots

- **[INTENT]** Operator, with `IMG_3669` (Cuisine carousel) and two Train card crops — Paya Lebar (2 lines,
  tall) and Eunos (1 line, short): *"Can i have 2 px gap between the carousel card and the recommendation bar
  in Cuisine TMA"* plus six numbered Train items.

- **[ONE QUESTION ASKED]** Item 3 was truncated mid-sentence — *"If more than 2 lines in the stations, reduce
  to just "*. The two readings (code chips only vs. smaller full names) meant materially different work, so I
  asked rather than guessed. Operator chose **full names with the font stepped down again**.

- **[DELTA]** (6 files, 1 new test file)

  **Cuisine.** `ResultDrawer.jsx` — the strip's bottom offset becomes `calc(4.5rem|6rem + 2px)`. Worth
  recording *why* the gap was zero: v0.62.277 and v0.62.285 **deliberately** dropped the strip to hug the dock
  (*"no gap"*), so the card's bottom pill ended flush on the "S$xx ~ xx · N gems | ★ …" bar. `calc()` adds the
  2 px without disturbing either previously-tuned offset.

  **Train 1 — disclosure moves back to the name strip.** A right-aligned word + triangle ("details" / "less")
  on the strip; the foot pill is **deleted**. That reclaimed row is where most of the height parity between a
  2-line and a 1-line card comes from. Critically, the strip itself still does **not** toggle — only the
  button does — so a card tap still bubbles to `onTap` and focuses/zooms the map. The v0.62.641 regression
  (the strip swallowing taps) must not come back.

  **Train 3 — line names that actually fit.** The name font now steps with the station's **line count**:
  12 px single · 11 px two · 10 px three-or-more. "East-West", "Downtown", "Thomson-East Coast" fit instead of
  truncating to "East-We…".

  **Train 4 — "Normal service" is gone.** From both the per-line row and the collapsed summary. The coloured
  dot carries it (with a `title` for hover/AT), and the **word appears only when a line is NOT normal**, where
  it is real information. Paired with a **new disruption tab above the card** — the same folder-tab
  construction as the v0.62.646 "future" tab, in the status colour, carrying ⚠ + the word — so the exception
  becomes the loudest thing on the card instead of the quietest. CVD-safe: the word carries the meaning.

  **Train 5 — exits and bus stops as text, not pills.** Operator: *"Bus stop and exit don't use pill; instead
  just letters and user will know it can be hyperlink."* One plain link-coloured line each, which is what lets
  the **description** fit — a pill row could only ever hold the bare code before wrapping. Three new pure
  helpers in `station-card-utils.js`, each earning its place:
  - `exitLabel` — the rich feed says `label`, `data/station-exits.json` says `exit`, **and Paya Lebar's own
    array mixes** prefixed ("Exit A"…"Exit D") with bare ("E", "F"). The card read `.label` only, which is
    exactly why the screenshot showed bare letters.
  - `busStopDesc` — `description` + `roadName`, either of which can be empty.
  - `dedupeBusStops` — the feed repeated `81111` three times in the operator's screenshot.

  **Train 6 — list-mode columns and density.** Grid goes **1 → 2 columns on a phone** and **2/3 → 3 on every
  tablet/desktop in both orientations**. A new `.gia-list-dense` class steps every **absolute** `text-[Npx]`
  inside the drawer grid down by exactly 1 px — necessary because the card's type is absolute, so no rem/em
  scale on an ancestor could reach it. "Independent" columns were already true: each tile is its own
  collapsible card in a CSS grid with `items-start`, so one expanding never stretches its neighbours.

- **[HONEST GAPS — stated, not buried]**
  - **Item 1 is only partly achievable.** Exact pixel-equal height for a 2-line vs a 1-line card is not
    possible while both lines are shown. The foot-pill removal, the one-row line summary and the dropped
    status word close most of the gap, but a 2-line card is still **one row taller**. Saying otherwise would
    be a fabrication.
  - **Bus-stop descriptions render only when the server supplies them.** The empty names in the screenshot
    come from an **unpopulated Redis stop-metadata hash** (`nearestStops` reads `description`/`roadName` from
    `busstop:<code>`), which is an infra/data gap the client cannot fix. The card now renders the description
    the moment it exists.
  - **Exits have no description in the data at all** — `station-exits.json` carries a label and coordinates,
    nothing else. What shipped is the *full, normalised* label ("Exit A", not "A"), which is the honest
    maximum from the current feed.
