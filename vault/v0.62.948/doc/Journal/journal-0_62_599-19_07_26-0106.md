## New

### [HDR] v0.62.599 — Transport StationCard: preserve Sun/PH first trains + stop mislabelling no-timing rows as termini

- **[INTENT]** Two **P2** correctness findings from the Codex automated review of the v0.62.598
  StationCard (merged as #1607). Both valid; fixed here as a fresh PR (a merged PR is finished — the
  branch was restarted from the post-merge `origin/main`).
  1. **Sunday/PH first train dropped.** `trainTimes()` collapsed `first_sat` and `first_sun_ph` into a
     single "weekend" value (`weFirst`), preferring `first_sat`. When Saturday equals the weekday time
     (common), the whole weekend line was hidden and the **distinct Sun/PH first train was never
     shown** — e.g. HarbourFront NEL: weekday/Sat 5:47am but **Sun/PH 6:07am** was omitted.
  2. **No-timing rows mislabelled "Terminates here."** A direction with all-null timings was always
     rendered as a terminus, even when the row's `note` says the data is *unavailable* (TE23–TE29) or
     the station is *not yet open* (TE12/TE13) — mislabelling ordinary TEL stations as termini.

- **[DELTA — util]** `web/transport/src/lib/station-card-utils.js`:
  - `trainTimes(timings)` now keeps **`satFirst`** (`first_sat` / `first_weekend`) and **`sunFirst`**
    (`first_sun_ph`) **separate**, plus `wdFirst`/`wdLast`/`weLast`, and returns **`noTimes`** (all-null)
    instead of a `terminal` flag — the *caller* decides how to label a no-service row.
  - New **`noteIsTerminal(note)`** (`/termin/i`) — true only for real terminus notes.

- **[DELTA — card]** `web/transport/src/components/StationCard.jsx` `DirectionRow`:
  - Renders weekday first/last, then appends **Sat** and **Sun/PH** first-train times **only when they
    differ** from the weekday time (Sun/PH shown separately from Sat), plus a weekend last-train when it
    differs.
  - For a `noTimes` row: shows **"Terminates here"** only when `noteIsTerminal(note)` (or no note),
    otherwise renders the **data note verbatim** ("timings unavailable", "not yet open").

- **[DELTA — i18n]** `+mrt.sat` / `+mrt.sunPh` (en/fr; other locales fall back to en).
