# Journal — v0.62.648 (carousel is the default in Hawker + Train, the list toggle owns the drawer — and the drawer handle was invisible because Tailwind was silently dropping the class)

_(№ 1,172 — 27-07 '26 12:36 SGT)_

## New

### [HDR] v0.62.648 — two answers to one message: no, it wasn't wired; and the handle was never being painted

- **[INTENT]** Operator: *"better experience to have both Hawker TMA and Train TMA in Cuisine's carousel card
  mode. these 2 TMA like Cuisine TMA can toggle to list which is how the drawer effect takes place. did you
  programmed (chat # 2698) all tht i asked? i still didnt see the drawer handle"*

- **[THE HONEST ANSWER TO THE SECOND QUESTION]** **No.** v0.62.647 built the vanilla sheet and deliberately
  wired it into **nothing** — that was my call, stated at the time, and it is exactly why no handle appeared.
  But that alone would not explain the complaint, because the **existing** drawer already had a handle and the
  operator has now reported it missing **twice** (v0.62.620 tried to fix the same complaint by making the bar
  *bigger*). So this pass went looking for the real reason.

- **[ROOT CAUSE — the handle was never painted, and 178 other rules with it]** Every TMA declared the Telegram
  palette in `tailwind.config.js` as **raw strings**:

  ```js
  'tg-hint': 'var(--tg-hint, #98989f)'
  ```

  Tailwind emits `.text-tg-hint` from that quite happily. It **cannot** emit an **opacity variant**: a raw
  `var()` string has nowhere to put the alpha, so Tailwind **discards the utility** — no rule, no warning, no
  fallback. Verified in the built stylesheet: grepping the shipped hawker CSS for `bg-tg-hint/70` returned
  **nothing**. The sheet's grabber was a fully transparent 48×6 box. Enlarging it could never have worked.

  The same silent drop killed **every** `bg-tg-bg/80` glass bar (so the "translucent" header bars over the map
  were in fact 100 % transparent), **every** `border-tg-accent/50` pill outline, and **178** rules in total
  across the five apps.

- **[DELTA]** (11 files, 2 new)
  1. **NEW `web/_shared/lib/tg-colors.js`** — the palette, **function-valued**. `opacityValue` undefined →
     the bare `var()`; otherwise a `color-mix` that carries the alpha. `color-mix` is already a hard
     dependency of these apps (`styles.css` defines `--tg-hint` with it), so this adds no new baseline.
  2. **All five `tailwind.config.js`** spread `...tgColors` instead of inlining the seven strings. Emitted
     opacity rules after the fix: **cuisine 68 · menu 39 · transport 34 · hawker 30 · oversight 7**.
  3. **`BottomSheet.jsx`** — grab zone **26 px → minimum 44 px**; the grabber gains an **inline**
     `backgroundColor` as belt-and-braces so it can never silently vanish again whatever the utility layer
     does; and the release physics gain a **velocity** term shared with the v0.62.647 vanilla component — the
     resting snap is chosen from the position **projected 140 ms forward** by trailing-window velocity, not
     from where the finger stopped, so a fast short flick now travels instead of snapping back.
  4. **Transport** — the phone-portrait **always-on drawer** branch (v0.62.609) is **removed**. Carousel is
     now the default on every device; the footer's ⊿ List toggle is the **one** route into the drawer.
  5. **Hawker** — new `viewMode` (`'carousel' | 'list'`, default `'carousel'`), a `ViewToggleButton`
     mirroring Transport's footer pill in both layouts, and two new i18n keys `layout.list` / `layout.map`.
     The v0.62.642 portrait-auto-drawer is gone: it meant a **portrait iPad never saw the carousel cards at
     all**.
  6. **NEW `__tests__/tg-colors.test.js`** — 10 tests pinning both halves of the palette fix, including a
     per-app assertion that no config has re-inlined a raw `tg-*` string.
