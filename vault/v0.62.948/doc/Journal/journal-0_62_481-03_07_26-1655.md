# Journal — soleat v0.62.481 (Sketchbook TMA now follows the shared app locale)

> Operator (bug report): *"i change the language in MENU TMA to french, but sketchbook UI didn't change"*
> Read as: setting the language in one TMA must propagate to the Sketchbook (Clipboard) TMA too.

## New

### [HDR] #835 | 16:55 SGT 03-07-26 | v0.62.481 — Sketchbook follows shared `gia.locale` | 2 code files + 3 doc/meta | PR #(pending) |
- **[INTENT].** A language pick made in the Menu (or Cuisine, or chat `/language`) TMA did not
  reach the Sketchbook TMA — its UI stayed in the device language.
- **Root cause (traced before editing).** The Cuisine + Menu TMAs write the active locale to
  `localStorage['gia.locale']` (same origin ⇒ shared across every TMA), fire a `gia:locale`
  `CustomEvent`, and mirror it to Redis via `POST /api/cuisine/user-language`. The
  Clipboard/Sketchbook TMA never read that shared key — `web/clipboard/src/App.jsx:26` did
  `const lang = getLanguage()`, i.e. the **Telegram device `language_code` only** (from
  `web/clipboard/src/lib/tg.js`). It was also a plain `const`, so even a cross-tab change
  wouldn't re-render.
- **[DELTA] (2 code files).**
  - `web/clipboard/src/lib/i18n.js` — added `getActiveLocale()` (reads `localStorage['gia.locale']`,
    validated against the 5 `SUPPORTED` locales → falls back to device `getLanguage()` → `en`) and
    the `useLocale()` React hook (seeds from `getActiveLocale()`, subscribes to the `gia:locale`
    `CustomEvent` for in-page reactivity **and** the cross-tab `storage` event). **Mirrored
    verbatim** from the Menu TMA's `i18n.js` (operator's mirror-verbatim rule).
  - `web/clipboard/src/App.jsx` — import `useLocale` from `./lib/i18n.js`; `const lang =
    getLanguage()` → `const lang = useLocale()`; dropped the now-unused `getLanguage` import
    (kept `initData`).
- **Scope kept tight.** No in-app `LocaleToggle` added inside Sketchbook — the report is about
  **following** the shared pref, not setting language from there. (Per "don't over-scope" note.)
- **[VERIFICATION (sandbox)]** `esbuild --bundle --external:* --format=esm` parses both edited
  files clean (JSX + ESM). No behavioural test harness for the hook; relies on the Menu TMA's
  identical, already-shipped implementation.
- **[STATUS]** PROD — Clipboard TMA rebuilds on merge (Railway). Verify on Telegram: set French
  in Menu TMA → open Sketchbook → its UI is French; toggle again → Sketchbook updates live.
- **[TEST]** Full vitest via CI (no unit touches the React hook; parse-checked instead).
- **[KNOWN GAPS]** Sketchbook still honours only the 5 `SUPPORTED_LOCALES` (en/fr/id/ru/de) —
  a Menu pick of zh/ja/es falls back to `en` in Sketchbook until its string tables gain those
  locales (tracked with the wider zh/ja/es locale-infra work). No self-serve language control
  inside Sketchbook (out of scope).
