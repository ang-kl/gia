## New

### [HDR] v0.62.586 — Cuisine: N/S/E/W labels on the outer distance ring + fix "Bbq" → "BBQ"

- **[INTENT]** Operator (IMG_0750/0751, **in Brisbane** on the deployed v0.62.585) asked three things:
  1. *"where is the four corners (north, south, east west) labels of the outer ring distance from
     set location"* — the four-corner labels weren't showing on Brisbane's outer ring.
  2. *"I cannot really see in color mode of the google map, what do you advice?"*
  3. *"look at the Australia classic, any of these are wrong and even wrong abbreviation typography
     (bbq, etc)"*

- **[DELTA — item 1 (fixed)]** `web/_shared/lib/distance-rings.js`. The four-side N/E/S/W labels were
  gated on `radiusM > LARGE_RING_M` (`8000` m). Brisbane's outer ring (the farthest-result ring) is
  **~2.9 km**, so it fell below the gate and drew only the single **north** label — the operator was
  right that the corners were missing. Added a `fourSide` parameter to `drawRing()` and pass it
  **`true` for the OUTER ring** in both region paths (SG reach ring; non-SG farthest-result ring), so
  that ring **always** carries N/E/S/W labels regardless of size. Ring 1 (walk) and ring 2 keep their
  single north label unless they themselves exceed `LARGE_RING_M`.

- **[DELTA — item 3 (fixed)]** `web/cuisine/src/v2/components/ArrivalPlate.jsx` — `titleCaseDish`. The
  "More classics" names are stored **lowercase** in `nation-overlay.js` (`F('australian bbq')`,
  `F('curry laksa kl')`, `F('snags on bread')`, …), and `titleCaseDish` upper-cased only the **first
  letter of each word** → *"Australian Bbq"*. Added a `DISH_ACRONYMS` allowlist
  (`bbq, hk, kl, xo, sg, nz, usa, uk, ny, nyc, kfc`) so those tokens render **fully upper** →
  *"Australian BBQ"*, *"Curry Laksa KL"*, *"HK-Style Milk Tea"*. The match is case-folded, so tokens
  already upper in the source (`SG`) pass through unchanged. **Display-only** — the raw `d.dish` stays
  the search query / aria-label / React key.

- **[item 2 — advice, no code change]** The app already ships a **Colour** toggle in the map controls.
  Turning Colour **off** adds `.gia-greyscale-map`, whose filter (`grayscale(1) contrast(0.8)
  brightness(0.96)`) desaturates the base tiles while leaving the **coloured pins** and **grey distance
  rings** in front — that greyscale mode *is* the intended high-contrast view. Advised the operator to
  toggle Colour off when the coloured base map is too busy to read the rings/pins against.

- **[item 3 — content review, NOT auto-edited]** `NATION_OVERLAY` is **read-only by standing rule**
  (`city-plates.js:5330`), so changing the dish LIST needs an operator decision (G-gate). Flagged the
  two notable candidates for the operator to call: the near-duplicate **"flat white"** vs **"flat white
  australian"**, and the obscure **"barramundi pie"**. Left in place pending confirmation — only the
  **typography** (a display transform) was fixed here.

### [HDR] v0.62.586 (cont.) — non-SG tiered outer rings + classics meal-bucketing for AU/Western dishes

- **[INTENT]** Operator (IMG_0752, tablet, Brisbane) — three follow-ups:
  1. *"Is Tim Tam a dish listed in Australia classic? Shouldn't it be snack? Where are the lunch,
     dinner and snack?"* — the "More classics" sections weren't splitting.
  2. *"Where are the addresses without country name? Wasn't it set canonically set in previous PRs?"*
  3. A tiered outer-ring spec: *"if over 20km, amend third ring where the pins located between 2.1 km
     and 10 km (draw at the … pin within 10km). Add fourth ring where the pins located between 10.1 km
     and 20km (draw at the … pin within 20km). Add fifth ring where the pins located between 20.1 km
     and beyond (draw at the … last pin distance from the set location)."*

- **[DELTA — item 3 (rings, fixed)]** `web/_shared/lib/distance-rings.js`. Added
  `farthestResultDistInBand(lat, lng, results, minM, maxM)` (farthest pin in the half-open band
  `(minM, maxM]`) and reworked the **non-SG** outer-ring path: when the farthest pin exceeds
  `TIER_TRIGGER_M` (**20 km**) the single farthest ring is replaced by up to **three band rings** —
  ring 3 on the farthest pin in `(2 km, 10 km]`, ring 4 in `(10 km, 20 km]`, ring 5 in `(20 km, ∞)`,
  each drawn only if that band holds a pin, all four-sided (N/E/S/W). Below 20 km the single farthest
  ring (ring 3) is unchanged. SG's MRT-stop rings are untouched (this is the non-SG / Cuisine path).

- **[DELTA — item 1 (bucketing, fixed)]** `web/cuisine/src/v2/components/ArrivalPlate.jsx`. The
  "More classics" list flattens `plate.classicGroups` then **re-buckets client-side** via
  `mealCategory`/`MEAL_BUCKETS` (Breakfast / Lunch & Dinner / Snacks & sides / Desserts / Drinks). The
  keyword sets were Asian-tuned, so every Australian classic fell through to `'main'` and jammed into a
  single "Lunch & Dinner" section — hence *"where are the … snack?"*. Extended the regexes: `DRINK_RE`
  += `flat white, long black, latte, cappuccino, shiraz, pinot, chardonnay, wine`; `DESSERT_RE` +=
  `lamington, pavlova, anzac`; `SNACK_RE` += `tim tam, chiko roll, sausage roll, snags, fairy bread,
  dagwood`. Tim Tam now buckets as a **Snack** (operator's call); the AU classics split correctly.

- **[item 2 — address (ASKED, not auto-changed)]** The address renders via `shortenCountry(venue.area)`
  but **only inside the expanded "details, review & links" section** (moved there by **v0.62.124** on the
  operator's own row re-order), and it **shortens** the country to a 2-letter code (**v0.62.151/153**),
  it doesn't drop it. So the ask sits against two prior operator decisions — surfacing the address onto
  the collapsed card reverts v0.62.124, and dropping the country fully reverts v0.62.151. Flagged to the
  operator for a decision (placement + whether to drop the country entirely) rather than guessing.
