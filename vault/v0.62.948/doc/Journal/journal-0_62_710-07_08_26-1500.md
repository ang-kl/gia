# Journal — v0.62.710 (GEMINI_MODEL was an override for one function out of five)

_(№ 1,049 — 07-08 '26 15:00 SGT)_

## New

### [HDR] v0.62.710 — make GEMINI_MODEL override every Gemini call site, not just `/hidden`

- **[INTENT]** Started as a side investigation during the Michelin arc: the operator shared a Railway
  deploy log after changing a Google API credential, which surfaced `[Extract-Dishes] gemini-flash-latest
  failed: per-attempt timeout 6s`. While diagnosing that, the operator changed the `GEMINI_MODEL` env var
  (first to `gemini-1.5-flash-8b`, then to `gemini-2.5-flash`) expecting it to change model selection
  system-wide, and asked directly: *"should follow env.var."*

- **[THE ACTUAL BUG]** `GEMINI_MODEL` only ever fed one constant, `DEFAULT_MODEL` (`gemini-client.js:220`),
  and `DEFAULT_MODEL` was only read by one function: `generateGroundedHiddenGems` (the `/hidden` command).
  The other four Gemini call sites in the same file — `validateAuthenticity`, `classifySearchIntent`,
  `describeCookingMethod`, and `extractDishesFromReviews` (the one that logged the timeout that started
  this investigation) — each had their own hardcoded `model = 'gemini-flash-latest'` default parameter,
  completely independent of the env var. Setting `GEMINI_MODEL` never touched any of them. This was
  confirmed by reading `cuisine-enrich.js:253`'s call to `extractDishesFromReviews({ venues: venuesForLlm
  })` — no `model` override passed, so it always used the hardcoded literal regardless of environment.

- **[A DEAD END RULED OUT ALONG THE WAY]** Before landing on this fix, external advice was pasted into
  the conversation suggesting three changes: bump the per-attempt timeout, switch to a specific model
  name, and cap output tokens. None of it matched this codebase — the timeout constant is named
  `PER_ATTEMPT_MS` (not what the advice called it) and is deliberately bounded by a separate 12s
  `DEADLINE` per a v0.60.226 design comment (a naive timeout bump would silently break that budget); the
  suggested model name doesn't appear anywhere in this file; the suggested SDK call shape (`{contents,
  config}`) doesn't match the `@google/generative-ai` package actually in use here
  (`m.generateContent(prompt)`); and a 256-token output cap risked truncating the dish-extraction JSON
  mid-array for a full batch, which would fail `JSON.parse` and lose every dish in the batch rather than
  just being slow. None of it was applied. The actual root cause (env var not reaching most call sites)
  only surfaced once the operator's own env var change didn't do what they expected.

- **[THE FIX]** Changed the default `model` parameter on all four remaining functions from a hardcoded
  `'gemini-flash-latest'` literal to `DEFAULT_MODEL`, matching the pattern `generateGroundedHiddenGems`
  already used. `GEMINI_MODEL` now reaches every Gemini call site in this file when the caller doesn't
  pass an explicit `model` override. Each function's own fallback chain
  (`SEARCH_INTENT_MODEL_CHAIN` / `FALLBACK_CHAIN`) is left untouched on purpose — those are deliberate
  retry lists for when the *primary* model fails, not the primary choice itself.

- **[DELTA]** (2 files)
  1. `gemini-client.js` — 4 default-parameter changes (`validateAuthenticity`, `classifySearchIntent`,
     `describeCookingMethod`, `extractDishesFromReviews`: `model = 'gemini-flash-latest'` →
     `model = DEFAULT_MODEL`); `DEFAULT_MODEL`'s header comment appended explaining the gap and the fix.
  2. `__tests__/gemini-client.test.js` — new `describe` block (4 tests, one per changed function) with a
     `modelSpyFactory` helper that records which model string each function's first attempt requests when
     no explicit `model` is passed, asserting it equals `DEFAULT_MODEL`; `validateAuthenticity` and
     `extractDishesFromReviews` newly imported into the test file (previously untested at the module
     level, though `extractDishesFromReviews` is exercised indirectly via `cuisine-enrich.js` tests).

- **[KNOWN GAPS]**
  - **Not device-verified**, matching this arc's standing caveat.
  - **Whether `gemini-1.5-flash-8b` (the model the operator initially tried) is still a live model on

    permanently retired `gemini-2.0-flash` in May 2026; `gemini-1.5-flash-8b` is from an older generation
    still. If it's retired, `/hidden`'s existing fallback chain degrades gracefully (this was already true
    before this fix) — but the operator switched to `gemini-2.5-flash` in the same exchange, so this is
    noted rather than acted on.
  - The original `[Extract-Dishes] ... per-attempt timeout 6s` log line that started this investigation is
    **not** addressed by this fix — that's a separate, still-open question (bump `PER_ATTEMPT_MS`/`DEADLINE`
    together, or leave as-is since only one occurrence was observed). Not resolved this entry.
