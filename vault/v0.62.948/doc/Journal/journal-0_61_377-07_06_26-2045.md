### [HDR] #577 | 20:45 SGT 07-06-26 | v0.61.377 — local-locale durian/fruit keywords | 2 files | 1 PR | 0 build |

- **[INTENT]** Stop the durian / fruits / durian-pastry filter from dropping venues named only in **Japanese / Korean / Thai / traditional-Chinese** when searching JP / KR / TH / TW.

- **[ROOT — investigated]** The keyword lists grew from a SG/MY lens — **EN + Malay + simplified Chinese** only. `filterByMode` (a pure `venues.filter(isRelevant)`) requires a core durian/fruit term in the venue's **name/area/address** (strong haystack); a local-script-only name had no matching term → dropped. Worse, the core durian word was duplicated across **three** drift-prone sites: `KEYWORDS[DURIAN]`, the strict-name gate `_nameHasDurian`, and the recency review regex.

- **[MECHANISM]** (`special-mode.js`)
  - **`DURIAN_CORE_TERMS`** (NEW, single source) — `durian, durians, 榴莲, 榴梿, 榴槤, 榴蓮 (zh-trad TW/HK), ドリアン (ja), 두리안 (ko), ทุเรียน (th)`.
  - `KEYWORDS[DURIAN] = [...DURIAN_CORE_TERMS]`; `_nameHasDurian` = `DURIAN_CORE_TERMS.some(...)`; the recency counter uses `DURIAN_CORE_RE` built from the same list — so the three durian-detection sites **can't drift**.
  - `KEYWORDS[DURIAN_PASTRY]` gains the local **core durian** words (NOT generic local "cake/pastry" words — those would over-match non-durian desserts; the bakery/dessert accept-type already constrains "is it a pastry shop").
  - `KEYWORDS[FRUITS]` gains `フルーツ` / `果物` (ja), `과일` (ko), `ผลไม้` (th). (Indonesian "durian"/"buah" + Chinese `水果`/`榴莲` were already covered.)
