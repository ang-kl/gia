# Journal — soleat v0.60.179

> Operator urgent bug report: *"Check the pet friendliness eateries filter as the following list of eateries after selecting pet allowed, may include non-pet friendly"* — pasted a list of ~25 venues returned by the 🐾 Pet allowed filter. Only 2 of them had explicit "Pet-Friendly" in the name; the rest were generic cafes / bistros with no Google-verified pet policy.

## New

### [HDR] #146 | 10:05:00 SGT 15-05-26 | v0.60.179 petFriendly filter: tighten strict-only — drop "< 3 → keep all" fallback; accept allowsDogs=true OR pet-friendly-named only | 3 files, ~20 LOC net | 1 PR |

- **[INTENT]** v0.60.165's design choice was: post-filter `v.allowsDogs === true`, and **if strict yields < 3 venues, keep the full text-query-biased pool** (since Places' `allowsDogs` is sparsely populated outside the densest SG areas). Operator's bug report shows the fallback is too generous: venues like "Tiong Bahru Bakery", "Zorba The Greek Taverna", "Boomarang Bistro" surface alongside the two genuinely pet-friendly ones ("CALI Rochester Park – Pet-Friendly Restaurant & Bar", "The Garden Slug Family Restaurant (Pet-Friendly Seating Available)"). Real-world consequence: users show up with their dogs and get refused. This fix prioritises **accuracy over result count**.

- **[DELTA]**

  **`index.js`** (~line 9846) — `petFriendly` post-filter rewritten:

  *Before* (v0.60.165 → v0.60.178):
  ```js
  if (filters.petFriendly && venues.length > 0) {
    const strictPet = venues.filter((v) => v.allowsDogs === true);
    if (strictPet.length >= 3) {
      venues = strictPet;
    }
    // else: KEEP ALL — the bug. Text-query bias surfaces any "pet friendly"
    // mention in reviews / name as a hit, including generic cafes.
  }
  ```

  *After* (v0.60.179):
  ```js
  if (filters.petFriendly && venues.length > 0) {
    const PET_NAME_RX = /\bpet[-\s]?friendly\b|\bdog[-\s]?friendly\b|\bpet[-\s]?allowed\b|\bpets?\s+welcome\b|\bdogs?\s+welcome\b/i;
    venues = venues.filter((v) =>
      v.allowsDogs === true ||
      PET_NAME_RX.test(v.name || '')
    );
  }
  ```

  - Drops the count threshold entirely. Strict-only: a venue passes iff Google flagged `allowsDogs === true` OR the venue's name contains an explicit pet-friendly signal (covers "CALI Rochester Park – Pet-Friendly Restaurant & Bar" + "The Garden Slug Family Restaurant (Pet-Friendly Seating Available)" + similar).
  - If zero verified venues, the existing v0.60.157 zero-results CTA in the TMA surfaces — better than showing inaccurate matches.
  - The upstream "pet friendly" cuisine-query modifier (line ~9364) stays — it still helps Places' fuzzy text ranking surface candidate venues, but only verified ones pass this post-filter.
  - Log line updated to break down the count: `kept N/M (allowsDogs=true: X, pet-friendly-named: Y)`.
