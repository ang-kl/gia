- **[INVESTIGATION]** There was **no 3.7 floor anywhere**. The main cuisine / `/s` / free-text searches used rating only for **ranking** + a composite `score < 40` drop (index.js:8470); `venue-filters` had none; `/hidden` has its own **≥ 3.9** Gemini-prompt gate; the review **picker** uses > 3.8 (which review to show). A **hard** 3.7 floor would over-compress — it would kill the New pill (new venues are unrated / few-review) and zero durian / sparse / foreign cities (undoing v0.61.416 / v0.61.399).

- **[DELTA]** (server-only, **guarded**)
  - **`venue-filters.js`** — new **`applyRatingFloor(venues, { floor: 3.7, exemptMaxReviews: 5 })`**: drops **rated** venues (≥ 5 reviews) below 3.7, **EXEMPTS** unrated (`rating` null/0) + `< 5`-review venues (so the **New** pill survives), and **NEVER empties** the list (returns the input if all are below — mirrors the v0.61.399 floor). `RATING_FLOOR` exported.
  - Applied at **two chokepoints** covering every eatery surface:
    1. **`deliverPicks`** (index.js:849 — the shared **bot** renderer → `/s`, free-text, sanctuary, cuisine flow) floors `picks`.
    2. **`/api/cuisine/search`** (index.js ~15430) floors the **`venues` pool before pagination**, so `< 3.7` never enters a page **and** the top-N backfills from the qualifying pool.
  - **`/hidden`** is **not** routed here (its 3.9 gate is already stricter). No double-apply (the TMA is the API path; the bot is `deliverPicks`).
  - **`__tests__/venue-filters.test.js`** — +6 cases (drop < 3.7, exempt unrated, exempt < 5-review, never-empty, empty/null).
  - **`package.json`** `0.61.424 → 0.61.425`; **`doc/.serial-state.yml`** commit 637 → 638, journal 624 → 625, **build 404 holds**; re-anchored 17:04 SGT.
