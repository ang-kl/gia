# Journal — soleat v0.62.468 (fix — taxonomy drafter cascades to fallback models on 429)

> Operator: "continue the taxonomy program" — but batches 2+ kept classifying 0 dishes.

## Root cause

Two dispatches a day apart both classified **0 dishes** — every batch (1–10) returned **HTTP 429
on `gemini-flash-latest` from the very first call**. Not a per-minute burst (429 immediately, every
batch) and not fixed by the daily reset. The real issue was in `scripts/draft-dish-taxonomy.mjs`:
after the 429 retry/back-off budget was exhausted it did `cascade = false; break` — only **404/503**
fell through to the next model in `MODEL_CHAIN`. So `gemini-flash-latest` being over quota never
tried `gemini-2.5-flash` / `gemini-2.5-flash-lite`, which are **different models with separate
free-tier quota buckets**.

## Fixed

### [HDR] #823 | 13:30 SGT 02-07-26 | v0.62.468 — cascade on persistent 429 | 3 files | PR #(pending) |
- **`scripts/draft-dish-taxonomy.mjs`** — a persistent 429 now cascades to the next model
  (`if (status === 404 || 429 || 503) break` → try next model), instead of bailing the whole batch.
- **[VERIFICATION (sandbox)]** `node --check`. Re-dispatched the workflow after merge.
- **[STATUS]** Tooling fix. Batch 1's 99 classified dishes are unaffected.
