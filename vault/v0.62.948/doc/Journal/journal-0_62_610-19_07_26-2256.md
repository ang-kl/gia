# Journal — v0.62.610 (Telegram: disable vertical swipes so the drawer drag doesn't dismiss the Mini App)

_(№ 954 — 19-07 '26 22:56 SGT)_

## New

### [HDR] v0.62.610 — the phone drawer's drag-down no longer minimises/closes the Train (and Hawker) Mini App

- **[INTENT]** Operator: *"the drawer runs another session of telegram TMA for train."* On a **phone**, the
  new draggable station-list **drawer's drag-DOWN** (drag-to-collapse) was being **grabbed by Telegram's
  native vertical swipe-to-minimise / close gesture** — dragging the sheet down dismissed the Mini App,
  and reopening it started **another** Train TMA session.

- **[DIAGNOSIS]** A classic Telegram Mini App gotcha: a page with its own draggable/scrollable surface
  must call **`WebApp.disableVerticalSwipes()`** (Bot API 7.7+), or Telegram's webview interprets a
  downward vertical drag as the app-dismiss gesture. Neither `web/transport/src/tg.js` nor
  `web/hawker/src/tg.js` called it — and **both** now host the shared `BottomSheet` drawer (since
  v0.62.609), so both were exposed.

- **[DELTA — 2 files]** `web/transport/src/tg.js` + `web/hawker/src/tg.js` `applyTelegramTheme()`: added a
  `safe('disable-vertical-swipes', () => { if (typeof w.disableVerticalSwipes === 'function')
  w.disableVerticalSwipes(); })` right after `safe('expand', …)`. **Feature-detected** — older Telegram
  clients (< 7.7) are unaffected. Closing the app deliberately still works via the Telegram **BackButton**
  (both TMAs wire it) and the footer **back / end** control. Applied to **both** TMAs since Hawker carries
  the same latent gesture conflict.
