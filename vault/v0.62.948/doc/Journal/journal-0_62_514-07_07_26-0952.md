- **[INTENT].** Operator: *"i said follow!! see your Sketchbook's cuisine tab what happen"*
  (+ screenshot IMG_2716 — the "Cuisine & Filter" drawer showing only 3 category cards, the
  6 world-region groups absent). This is workstream **C** (make the Sketchbook cuisine picker
  *follow* the Cuisine TMA). I read it as a bug report and traced it to source before editing.

- **[ROOT CAUSE].** Not a code bug on `main`.
  - `/api/cuisine/catalogue` (`index.js:12889`) is `(_req, res)` — it **ignores the request**
    and returns **9** categories deterministically: `cuisines-vault.getByCategory()` (7 world-
    region buckets) + synthetic `michelin` + `set-meal`.
  - `web/clipboard/src/components/CuisineGroupPicker.jsx:131` maps the **whole** catalogue
    (`catalogue.map(...)`); it only **greys** groups with no saved card (`availableSlugs`),
    it never **hides** them. `App.jsx` sets `catalogue` straight from `d.categories` — no
    filter, no slice.
  - The **live** deployed bundle (`soleat.net/app/clipboard`, `index-DEhXjZ_w.js`) already
    embeds **v0.62.513** and contains every region label key — so a *fresh* load renders the
    full 9-grid. The operator's 3-card view was the **old v0.62.388-era bundle** Telegram had
    cached. Tell-tale: the served `index.html` diagnostic-boot **comment** still read
    `v0.62.388`, which is what made the served surface look stale.

- **[DELTA].**
  - `package.json` — 0.62.513 → **0.62.514**. This changes the Vite `__BUILD_VERSION__`
    define (`web/clipboard/vite.config.js:20`), so the bundle **content** changes and its
    content hash changes: `index-DEhXjZ_w.js` → **`index-CP2cu7U-.js`** (verified by a local
    build). A new filename forces Telegram to refetch instead of serving the cached bundle.
  - `web/clipboard/index.html` — the diagnostic-boot comment version marker **388 → 514** so
    the SERVED HTML advertises the true version (the comment survives into the served HTML and
    was the misleading "stale" marker that made this hard to diagnose).
