## New

### [HDR] v0.62.623 — remove the desktop auto-fullscreen branch across the TMAs

- **[INTENT]** Operator (Telegram Desktop, Cuisine TMA; two screenshots of the native corner control):
  *"the telegram desktop CUISINE TMA are using the wrong system command to expand to full screen."*

- **[FINDING]** On desktop the fullscreen gate calls `w.requestFullscreen()` (Bot API 8.0), which forces
  a **chromeless OS-fullscreen takeover** — the wrong behaviour for a desktop window. **Telegram Desktop
  already exposes a native corner button (⤢)** to widen / maximise the Mini App window, and there is **no
  WebApp API** to invoke that. So forcing `requestFullscreen()` on desktop was the wrong command. Confirmed
  via **AskUserQuestion**: **stop auto-fullscreen on desktop, use the native button, across all four TMAs.**

- **[DELTA]** Removed the `desktopClient` (`tdesktop || macos`) branch from the fullscreen gate in
  **`web/cuisine/src/api/tg.js`**, **`web/hawker/src/tg.js`**, **`web/transport/src/tg.js`**. The condition
  is now `touchClient && coarse && minScreen >= 700` — **iPad-class touch tablets only** (where Telegram
  letterboxes the WebApp into a narrow column that genuinely benefits). `expand()` (max **height**) still
  always runs. This **restores the v0.60.52 / v0.62.286 desktop exclusion** and reverses the v0.62.617
  re-enable.
  - **`web/menu/src/tg.js`** was **already** iPad-only (`if (platform !== 'ipados') return`) — **no change
    needed**; the "four TMAs" now behave consistently.
  - **`web/oversight/src/tg.js`** has no fullscreen call — untouched.

- **[VERIFICATION (sandbox)]** `node --check` clean on the three edited files; no `desktopClient` reference
  remains. `cuisine + hawker + transport` `vite build` green; full `npm test` **3756/3756 across 148
