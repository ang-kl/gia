> Operator (05-06 '26, live on v0.61.320 per Railway logs): *"the current location is Naka Ward with singapore flag. should you do a check on location first? there was a past PR on this."*
>
> This is the live repro of the BUG 2a stale-name symptom I flagged in v0.61.320 (could not reproduce from static code then). Railway log confirms the server searched **SG** coords: `region=SG center=1.2820,103.8525`. So the displayed **name** ("Naka Ward", a Japanese ward) is stale while region / flag / searched coords are all SG.
>
> Root cause (verified): the banner name is `locationAnchor.name` verbatim (`App.jsx:386`). A `locationAnchor` cached from a prior **overseas** session (name + coords) survived a GPS/region flip to SG — the GPS auto-detect that would have overwritten the anchor is skipped when a cached/deep-link anchor is present (`App.jsx:911-915`), so `searchCenter`/`region` flipped to SG while `locationAnchor` stayed in Japan. The two existing coherence checks miss it because they compare **coords vs region/countryPref** (v0.61.274) and **region=JB vs coords** (v0.61.276); here coords=SG and region=SG *agree* — only the anchor's own country is the orphan.
>
> Operator chose the **modal** fix shape (same UX as the v0.61.274/276 prompts).
>

- **[KNOWN GAPS]**
  - **"Keep" + overseas flag.** Choosing "Keep" leaves `region` as-is; for a non-SG/MY spot we can't derive the country flag from coords (`coordsToCountry` only knows SG/MY), so the flag may stay generic rather than the true country. The common/correct path ("Use my current location") fully reconciles; "Keep" is the rare explicit override and at least aligns the search centre. A future pass could reverse-geocode the kept anchor's country to set the right OTHER flag.
  - **Detection is distance-based**, not name-based: it catches a stale anchor whose *coords* are far away (the actual repro). A pathological anchor with SG coords but a foreign *name* (incoherent within one object) wouldn't trip the distance gate — not observed, and would indicate a different upstream bug.
