## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-74 | **Prefer making a bad state unreachable to choosing what it should do.** O-131 offered fail-open (the tap appears to do nothing — D-69) or empty (a blank screen). Both are answers to a question the user should never be able to ask. Locking the last tick removes the question, keeps D-65's vocabulary (a control that cannot produce a meaningful result is not offered as though it can), and leaves the server guard doing the job its own comment describes instead of standing between a user and an empty screen. | v0.62.701 |
| D-75 | **A sweep without a guard is a fix, not a closure.** O-104 was "fixed" at v0.62.698 and stayed open across ten more inputs, because the fix was an event and the problem is a property. The static guard is what closes it — and it earned its place immediately by flagging `web/_shared/`, a directory my own `web/*/src` sweep never looked at. Corollary, learned the same minute: **a guard must not fail on its own documentation** — the first draft matched inside a JSX comment *explaining O-104*, so it now reads the className value with comments stripped. | v0.62.701 |

## Note

Two of these three were settled without a stated direction, so the reasoning is on the record rather
than the outcome alone.

O-131 is the more interesting. Re-reading it before building revealed the item was **wrong about its
own scope**: it described a Singapore/Philippines edge case, but the underlying behaviour — untick
everything, get everything — was true in all twelve countries. SG and PH were merely where the older
build produced a blank screen instead of a no-op. An item written from a diff is only ever as wide as
the diff that produced it.

O-104 closed with the opposite lesson. The sweep itself was routine; the guard was not. It found
`web/_shared/` — a directory my own `web/*/src` glob had silently excluded — on its first run, which
means the "complete audit" I would have reported was not complete. Then it failed a second time on a
comment *explaining O-104*, which is its own small warning: a check that fires on its own
documentation gets deleted by the next person in a hurry, and then the property it protected is gone
with it.

Both are versions of the thing this Register keeps recording — D-62's compiled-CSS grep, D-68's
specificity loss, D-72's fixed-pair guard. A check reads as a guarantee while asserting something
adjacent to what it claims. The only reliable defence found so far is to make the check fail on
purpose before trusting it, which is why C-155 is mutation-checked rather than merely green.
