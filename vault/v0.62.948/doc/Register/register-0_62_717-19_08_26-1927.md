## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-113 | **Two engines, or the audit is theatre.** The proposal was to have Gemini both translate and audit. A model auditing its own output only catches errors it does not itself share — the small half. Cloud Translation v3 fills `google_translation`; Gemini judges it having never seen its own reasoning. Encoded as a precondition at the top of the prompt file, not a footnote. | v0.62.717 |
| D-114 | **Back-translation is the deliverable; the verdict is the annotation.** The operator does not read any of the six target languages, so a `pass`/`fail` label is unfalsifiable to the only person who has to act on it. `back_translation` is the one field they can check unaided. The prompt says so explicitly and orders the work back-translate-first. | v0.62.717 |
| D-115 | **Owner-facing strings are not translated.** `/hidden` is `isOwnerChat`-gated (`index.js:6908`, `:7114`) and the spend-guard alerts DM `TELEGRAM_OWNER_CHAT_ID`. Both had been listed "Phase 1B, immediate priority". They reach one reader, who reads English. Excluded — and listed in `_manifest.json` with the reason, not silently dropped. | v0.62.717 |
| D-116 | **Legal prose does not go through a machine.** `privacy.body` / `legal.body` are multi-paragraph and are the one class here where a mistranslation has consequences *and* a back-translation spot-check will not reliably surface it. Excluded pending a human translator. | v0.62.717 |
| D-117 | **A generator that loses a key must fail, not shrink.** `build-i18n-audit-jobs.mjs` exits non-zero if any key declared in `i18n.js` is neither batched nor listed in the manifest's exclusions with a reason. Caught its own bug immediately: the first parser silently dropped 28 double-quoted and array-valued keys, which would have shipped as a plausible-looking 243-item set. | v0.62.717 |

## Note

The useful thing in this entry is X-3, and it is uncomfortable. The session told the operator
twice that the six languages were "already done, six times, in your repo" and that the job was
mostly a port. That was inferred from `i18n.js`'s own header comment — *"Mirror of
web/cuisine/src/v2/lib/i18n.js"* — and never checked. One `grep` of the two key sets would have
shown zero overlap before the claim was made rather than after. The file header described an
intent; the code had drifted from it years of versions ago.

The pattern worth carrying: a comment asserting a relationship between two files is a hypothesis,
not evidence. Measure the relationship. The same instinct is what put the accounting assertion into
the generator (D-117), which then immediately caught the parser dropping 28 keys — the assertion
earned its cost on its first run.
