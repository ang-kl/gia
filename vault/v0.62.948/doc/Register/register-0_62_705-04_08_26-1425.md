## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-84 | **When a request has two readings that write different state, ask — and when the operator has said they dislike rework, ask about the shape too.** *"Switchable"* could have meant *set the pinned default* or *navigate without changing it*. Those write different state, and only the first keeps the tab's own label honest — under the second, the label and what the tab opens can disagree. The gesture (hold / tap-when-active / always-picker) was a second, independent choice with no obviously correct answer. Both went up in one round, both were answered, and nothing was built twice. That is the cheap version of the operator's earlier *"I don't want to keep asking you to change"*. | v0.62.705 |
| D-85 | **A gesture needs a non-gesture route.** A press-and-hold cannot be performed by a keyboard, so hold-only would have made this setting unreachable for anyone not on a touchscreen — while the ★ it duplicates stays reachable, which would have made the footer route a second-class copy. The same picker now opens on context-menu (the desktop equivalent of a hold) and on ArrowUp, both announced through ARIA rather than left to be discovered. | v0.62.705 |

## Note

Two small things are worth keeping from this one.

The first is that *"switchable"* was genuinely ambiguous in a way that mattered — not stylistically,
but in which state gets written. Navigate-only would have let the tab's label and the tab's
destination disagree, which is the kind of thing that reads as a bug six weeks later. Asking cost one
round; guessing wrong would have cost a build.

The second is D-85, and it is the sort of gap that is easy to ship. A press-and-hold is invisible to
a keyboard. Had this landed hold-only, the *only* way to reach the setting from the footer would have
required a touchscreen — while the ★ it mirrors stayed reachable by every input. The fix was three
lines and an ARIA attribute; the failure mode was one nobody would have reported, because the people
affected would simply have kept using the old three-screen route and assumed that was the design.
