## Note

The most useful thing that happened here is that **a test stopped me**. `iata-cities.test.js` exists
because the operator set a "non inventive" rule in v0.61.242, and it failed the moment a code was
introduced that the canonical table did not know. That is the guard working.

What it cannot do is the part that actually matters. It checks that `cities.js` agrees with
`iata-cities.js`; it does not — and cannot — check that either agrees with reality. Adding the 15
codes to the canonical table turned the suite green without anyone verifying a single one of them.
That is a green test attesting to internal consistency and nothing more, and it would look identical
if every code were wrong. O-126 exists so that distinction is on the record rather than implied by a
passing build — the same silent-success shape already logged for Tailwind's JIT (D-22…D-28), the PR
listing's `merged` boolean (O-114), and the compiled-CSS grep that vouched for classes in code that
could not run (D-62).

Second, smaller: the fold would have broken arrow-key navigation, because `itemRefs` is positional
and a collapsed group leaves nulls that `?.focus()` swallows silently. Caught by reasoning, not by
running — nothing in the current harness drives a keyboard through a folded list.
