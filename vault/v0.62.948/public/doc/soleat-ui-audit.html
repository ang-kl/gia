1 Verdict

Consistency: the foundation is consistent, the surface is fragmented. All five Mini-Apps share the same Telegram theme tokens (tg-bg / tg-text / tg-accent / tg-card / tg-border / tg-hint); about is intentionally its own showcase design system. On top of that shared base there is real drift — and a mixed flat-vs-skeuomorphic language within single screens.

SKEUOMORPHIC? NO These are Telegram Mini Apps: the platform convention — and your own tg-* system — is flat and theme-adaptive (the UI must recolour to each user's Telegram light/dark theme). Full skeuomorphism fights that — textures, gradients and realistic shadows don't recolour with the theme, cost performance, and hurt accessibility. The right rule is flat-first, with a small, deliberate skeuomorphic accent vocabulary. Today's real problem isn't the style — it's that the choice is made ad-hoc per component.

2 What's already consistent ✅

  • Shared 7-token Telegram theme across the 5 TMAs; ResultCard, LocationCard and most containers are clean (rounded-lg border-tg-border bg-tg-card).

4 Skeuomorphism — the rule to adopt

Flat-first, theme-adaptive base (the existing tg-* system) as canonical. Reserve skeuomorphism for a named, documented accent set where the physical metaphor genuinely aids comprehension:

  • Keep as skeuomorphic accents: the teardrop map pins, the 📜 fact scroll, and the map-control "chrome".
  • Everything else flat: cards, buttons, chips, dropdowns, info-windows, toggles.
  • Why not full skeuomorphism: Telegram theming requires recolouring to the user's light/dark theme — textures/gradients can't follow it; they also add weight and accessibility risk. Consistency matters more than the style label.

5 Recommended fixes (when you're ready)

  • Theme the map controls — use tg-card/tg-text or a dedicated --map-control-* pair so they stop being white-on-dark. (highest impact, low risk)
  • Standardize buttons — one padding scale, one active-pill style; kill the dropdown text-grows-on-open jump.
  • Render info-windows in React/Tailwind (or a shared themed template) instead of inline-styled HTML strings, so they track the theme.
  • Extract a shared tg.js/theme module across the 4 smaller TMAs — fixes the hint_color divergence + hardcoded hexes at the root.
  • Define an emoji-icon contract with text labels / aria-label for the colour-coded states (crowd, status).
  • Document the standard (flat-first + named skeuomorphic accents) in doc/Technical + open items in doc/Register so drift can't recur.
