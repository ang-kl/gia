- **[INTENT]** Replace the legacy 19-row inline `CITY_CENTROIDS` (in `place-search-variance.js`) with the operator's full, authoritative centroid list — the foundation for the location-state / map-handoff refactor and for broader Michelin city-aware-hint coverage.

- **[MECHANISM — why geocode, not Plus Codes]** I implemented an Open Location Code decoder and **proved it correct** (Google HQ `849VCWC8+R9` → 37.422063, −122.084063 exactly; `recover()` round-trips to the same point). But decoding the operator's **short** Plus Codes landed 0.5–5 km off the named stations — e.g. `5PM3+28` ("KL Sentral") resolved ~5 km north of the real KL Sentral, whose actual code is `4MMP+GJ`. So the *codes* (transcription) were imprecise, not the decoder. Per the operator's choice, every station was **geocoded** via the Google Geocoding API (`scripts/geocode-centroids.mjs`, key supplied by the operator) — **139 rows, 0 failures**, spot-checks **0.01–0.31 km** off ground truth.
