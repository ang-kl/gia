## New

### [HDR] #686 | 01:40 SGT 12-06-26 | v0.62.33 — synchronous plate wipe in onLocationSelect + setArrivalPlate on the visibility-refresh path | web/cuisine/src/v2/App.jsx | 1 PR | 1 build |

- **[INTENT]** The "What to try here" card must never show the PREVIOUS city's dishes after a
  switch. Hanoi has no curated plate → the card should disappear, instantly.

- **[ROOT CAUSE — two holes in the v0.62.32 wiring]**
  1. **The visibility-refresh never synced the plate** (`App.jsx` v0.61.186 `refetchAndFlip`): it
     updated anchor / region / countryPref / precinctId from `/api/cuisine/user-location` — but not
     `arrivalPlate`. A city switch the TMA learns about on visibility restore (chat `/location`,
     Menu TMA, or any missed persist response) kept the old card **forever**.
  2. **The wipe was async-only**: `onLocationSelect` cleared the plate only in the persist
     response's `.then`. If that persist failed or never fired (the cityPreview persist rides a
     350 ms debounce that dies if the webview backgrounds first), the stale card stayed — which
     also *reads* as "the city didn't save".

- **[FIX]**
  - `onLocationSelect`: `setArrivalPlate(null)` **synchronously** on every finite-coords pick —
    the card wipes the moment you pick; the persist response re-fills it when the new city is
    curated. A failed persist now leaves the card **empty (honest)**, never stale.
  - visibility-refresh: `setArrivalPlate(r.plate || null)` — mirrors the tryServerCache sync, so
    cross-surface switches (chat / Menu TMA) update or clear the card on return.

- **[NOT touched — deliberately]** The boot gate, the location-reconciliation policy, and the
  v0.62.13 350 ms preview-persist debounce (changing persist timing is reconciliation-zone work —
  ask-first per the standing rule).

- **[VERIFICATION (sandbox)]** Full suite **3386 / 132 files green**; `build:cuisine` green. The
  change is two `setArrivalPlate` calls — no server, no data, no routing.

- **[STATUS]** PR-OPEN → squash-merge via gh REST. Railway redeploys the cuisine bundle.

- **[TEST — operator, deployed]** (1) Set Putrajaya → card shows; switch to Hanoi → card
  disappears **immediately** on the pick. (2) Switch city via chat `/location` or Menu TMA, return
  to the Cuisine TMA → card updates (or clears) on the visibility flip. (3) Sapporo → Hanoi →
  Sapporo: card wipes, then returns with Sapporo dishes from the persist response.

- **[KNOWN GAPS]**
  - **The "didn't save" half is [UNVERIFIED]**: every pick path traces to a persist in the code,
    and the old Railway domain (gia4lunch-production) is gone so the deployed box couldn't be
    probed. If Hanoi still doesn't stick after this deploy, a Railway log paste around the switch
    will show whether `[set-location]` ever arrived — that pins it.
  - Label-less GPS-revert saves return no plate by design — after one, the card stays empty until
    the next visibility refresh / boot fills it. Honest-empty, acceptable.
