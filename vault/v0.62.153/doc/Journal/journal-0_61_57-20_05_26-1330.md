## Deleted

### v0.61.17 / v0.61.26 — train-layer neighbour-detail view (behaviour, not a file)

Removed from `applyVisibility('train')` — the block that, when a station was
selected, kept only that station + its two line-neighbours visible and scoped the
Exits / Taxis chip layers to those three stations:

> ```js
> let keep = null;
> detailStations = [];
> if (detailStation) {
>   const ordered = stationsOnLine(e.stations.map((x) => x.station), lineCodeOf(detailStation));
>   const idx = ordered.findIndex((x) => x.name === detailStation.name);
>   keep = new Set([detailStation.name]);
>   if (idx > 0) keep.add(ordered[idx - 1].name);
>   if (idx >= 0 && idx < ordered.length - 1) keep.add(ordered[idx + 1].name);
>   detailStations = e.stations
>     .filter((it) => keep.has(it.station.name))
>     .map((it) => ({ lat: it.lat, lng: it.lng }));
> }
> ```

Rationale: superseded by the CR6 station info card (operator AskUserQuestion choice,
20-05 '26 — "tap station → card replaces detail view"). `detailStations` is now
always empty, so the marker branch's `stationScoped` path is inert and the chip
layers anchor-clip as for every other overlay. `detailStation` itself is retained
(selected-station marker for the CR5 centre pill + CR4 v2 bus-focus). The
`stationsOnLine` helper is kept — CR5 v2 (deferred prev/current/next polyline
emphasis) will reuse it.
