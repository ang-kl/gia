## New

### [HDR] #340 | 09:10 SGT 25-05-26 | v0.61.139 — Menu TMA anchored-at uses addressComponents (street + building + postal) | 8 files | 1 PR | 1 build |

- **[INTENT]** Make the Menu TMA's *"Anchored at …"* pill carry
  geographic context (street + postal) instead of just the Places
  displayName (which for shop-in-mall queries reads as the shop
  name alone). Operator format: `<street> + <building, if any>
  + (<postal>)`.

- **[DELTA]**
  - **`places-address-parser.js`** (NEW, 45 lines) — pure parser
    `parseAddressComponents(components) → { street, building,
    postal } | null`. Walks the Google Places New-API
    `addressComponents` array (each entry has `{ longText,
    shortText, types:[string], languageCode }`). Picks:
    - `street` = `<street_number> <route>` (or just route)
    - `building` = `premise` → `subpremise` → `establishment` (first match)
    - `postal` = `postal_code`
    Extracted to its own module so the v0.61.139 unit test can
    require it without transitively loading axios — sidesteps the
    O-22 iCloud-corrupted `node_modules/axios/package.json` mode
    that bit during this session.
  - **`vibe-suggest.js`** — `geocodeQueryRegion`:
    - `FIELD_MASK` adds `places.addressComponents`.
    - Imports `parseAddressComponents` from
      `./places-address-parser` and re-exports for back-compat.
    - Return shape adds `street`, `building`, `postal` (each
      nullable — Places may not tag a particular component type).
  - **`location-cache.js`** — `setUserLocation` opts now accept
    `street`, `building`, `postal` strings (each optional). Old
    callers (share-pin handler, precinct picks, manual geocode)
    pass nothing → exactly the legacy payload.
  - **`index.js`**:
    - `/api/menu/set-location` typed-text branch — passes
      `r.street` / `r.building` / `r.postal` through to
      `setUserLocation`, returns them in the response.
    - `/api/cuisine/user-location` — surfaces the persisted
      address parts on cold-load reads so the Menu TMA renders
      the new format without waiting for a re-fetch.
  - **`web/menu/src/App.jsx`** — `setAnchor()` threads
    `street`/`building`/`postal` from the `user-location`
    response into the anchor state object.
  - **`web/menu/src/components/LocationFieldMenu.jsx`**:
    - `onAnchorChange` payload extended with the three new fields
      so the summary line re-renders immediately after a set
      (no App.jsx refetch needed).
    - New pure helper `composeAddressLabel(anchor)` builds
      `<street>[, <building>][ (<postal>)]`. Used when the
      anchor has a `street`; falls back to the existing `label`
      otherwise (precinct picks, pre-v0.61.139 cached anchors,
      addresses where Places didn't return a route).
  - **`__tests__/parse-address-components.test.js`** (NEW, 10
    tests): null/empty inputs, typical SG building address
    (Bugis Junction example), route-without-street_number,
    premise/subpremise/establishment fallback ladder, longText
    vs shortText preference, missing-types skip, duplicate-types
    first-match, road junction, residential address.
  - **`package.json`** — `0.61.138 → 0.61.139`.
  - **`doc/.serial-state.yml`** — commit `351 → 352`, build
    `141 → 142`, journal `339 → 340`; re-anchored 25-05 '26
    09:10 SGT; new comment-history block prepended.
  - **`doc/Journal/journal-0_61_139-25_05_26-0910.md`** — this entry.
