- **[INTENT]** The Michelin result card showed paging **twice**: the v0.61.335 hint above the card (*"94 more to explore (130 in total). Tap 🔍 for the next batch of 12"*) AND the header sub-line *"Showing first 12"*. The operator wants the hint to replace the sub-line.

- **[MECHANISM / LOGIC CHECK]** Michelin paginates **server-side** — `handleMichelinSearch` advances a seen-set walk and returns one 12-venue batch per 🔍 tap; the TMA only ever holds that single batch. So `ResultPanel`'s client pager `page` is **always 1**, and the `panel.line2.first` branch always renders *"Showing first 12"* — even when the user is on the server's 2nd or 3rd batch. The line is therefore not just redundant with the hint, it is **static and misleading** (it never advances). The hint (driven by `michelinSummary.remaining`) is the accurate pager. Fix: for Michelin, suppress the line2 sub-line entirely and let the hint stand.
