### [HDR] #618 | 13:22 SGT 09-06-26 | v0.61.418 — country pick defaults to the capital (Japan → Tokyo) + map flies there, no fire | LocationField.jsx | 1 PR | 1 build |

- **[INTENT]** Selecting a country in the OTHER picker must default to its **capital** (Japan → **Tokyo**) and **fly the map** there — **without** firing a search (the user still taps 🔍).

- **[ROOT CAUSE]** (agent) The auto-pick (`OtherLocationPicker`) tier (b) snapped to the **nearest** `cities.js` city to the anchor by haversine. With a **stale cross-country anchor** (e.g. an SG pin when you switch to Japan) the nearest JP city to SG is **Fukuoka** (southernmost), not the capital **Tokyo** (`JP[0]`). And the auto-pick only set the **dropdown** — it never flew the map / set the anchor, so selecting a country didn't move to the capital.

- **[DELTA]** (`web/cuisine/src/v2/components/LocationField.jsx`)
  - **Distance guard on tier (b)** — use the nearest curated city only when `bestD ≤ NEAREST_CITY_MAX_KM` (**500 km**: clears in-country gaps — HK districts ~2 km, Sibu→Kuching ~150 km — and excludes any cross-country jump — SG→Japan ~4500 km). Else fall through to the **capital** (`list[0]`).
  - **Map fly on a USER country change** — the auto-pick now flies the map to + anchors the pre-selected city via `onSelect({ …, cityPreview: true })`, **only** when the change was user-initiated (`userChangedCountryRef`, set by the `CountryDropdown` `onChange`). **Boot / server-cache hydration does NOT set the ref**, so the v0.61.407 saved set-location is never overridden. `cityPreview` is region-safe (App's preview branch: flies the map, no commit, no search, no region change) — the **same payload the proven `onCityPick` already fires** — so no new loop/region risk. *"Don't fire yet"* preserved.
  - **`package.json`** `0.61.417 → 0.61.418`; **`doc/.serial-state.yml`** commit 630 → 631, journal 617 → 618, **build 398 → 399**; re-anchored 13:22 SGT.
