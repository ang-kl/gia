### [HDR] #313 | 07:29 SGT 23-05-26 | v0.61.113 — Cuisine free-text keep | ~4 kb | 2 files | 1 PR | 1 build |

- **[INTENT]** In the Cuisine TMA, typing a specific dish as free text
  (e.g. `fishball noodle`) inferred a cuisine (Singaporean) and toggled
  that chip — but the typed phrase itself vanished from the search
  criteria, so the search no longer scoped to the dish. The operator
  wants both kept: the inferred cuisine chip **and** the typed dish text.

- **[DELTA]**
  - **`web/cuisine/src/v2/App.jsx`** — `handleNLSubmit(text, opts)`
    inferred cuisines/filters and applied them with `setState(nextState)`,
    but never preserved the typed `text`. Added `setNlText(text)` right
    after `setState(nextState)`. `nlText` is App state already bound to
    the Tell-me input (value) and already fed to `runSearch` as the
    `freeText` qualifier — so the typed dish now stays visible in the
    Search-criteria builder and scopes the next search, alongside the
    inferred cuisine chip. The server side already keeps the literal
    phrase in the venue query (the `/api/cuisine/nl-query` brand-name
    prepend), so no server change was needed.
  - **`package.json`** — `0.61.112` → `0.61.113` (PATCH). Originally
    authored as `0.61.106` → `0.61.108`; renumbered on merge after PRs
    #600/#602/#603/#604 advanced `main` to v0.61.112.
