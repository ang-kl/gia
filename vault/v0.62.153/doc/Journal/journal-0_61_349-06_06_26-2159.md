## New

### [HDR] #549 | 21:59 SGT 06-06-26 | v0.61.349 — "New" pill: ≤150-review proxy → /hidden review-time refute (oldest review ≤ 3 months) | 1 code file | 1 PR | 1 build |

- **[INTENT]** The Cuisine TMA "🆕 New" pill used a crude proxy — keep venues with ≤150 reviews (v0.57.6) — which passed old low-review holes-in-the-wall and rejected genuinely-new-but-popular places. The operator asked it to use `/hidden`'s newness logic instead. Per the chosen option, that means `/hidden`'s **review-time refute** (the sound, Places-only half), not the LLM opening-date inference (which would effectively run `/hidden`'s engine inside the chip search).

- **[MECHANISM]** A Google review can only be posted **after** a venue opens, so a review older than 3 months proves the venue is **not** newly opened (`hidden-verify.js` `oldestReviewMonths` + the v0.61.318 `NEW_CLAIM_MAX_REVIEW_MONTHS = 3` threshold). When `filters.newlyOpened` is set, the handler now fetches each candidate's reviews via **Places Details** (GET `/v1/places/{id}`, `reviews`-only field mask — **gated on the pill**, so the extra Places cost applies only to New searches, mirroring the existing Details calls at `index.js:598`), computes `oldestReviewMonths`, and **drops** venues whose oldest returned review is **> 3 months**. Venues with **no review older than 3 months — or no reviews at all — are kept**, because review-time can only *refute* newness (Places returns ≤5 reviews, so their absence isn't proof of age). The "newly opened" text modifier still biases Google's own recall upstream. A `[Cuisine-New] review-time refute: N → M` log records the cut (no silent drops).
