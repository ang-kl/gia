    - **§4.6** — Plumbing-commit pattern. Full bash recipe:
      `git show origin/main:<path> > /tmp/work/…` (snapshot) →
      Edit → `GIT_INDEX_FILE=/tmp/...` (scratch index) →
      `git read-tree origin/main` → per-file `git hash-object -w`
      + `git update-index --add --cacheinfo` → `git write-tree`
      → `git commit-tree -p origin/main` → `git update-ref` →
      `git push -u origin <branch>` → `gh pr create` →
      `gh pr merge --squash --admin`. Used for every PR #629 →
      #635 in the v0.61.128-134 arc.
    - **§4.7** — Pack-corruption recovery. The
      `pack-… is far too short to be a packfile` failure mode
      observed once at the v0.61.133 → v0.61.134 boundary (both
      local packs were stale; file sizes matched original but
      contents were inconsistent). Recovery is reversible:
      `mv .git/objects/pack/pack-<sha>.{pack,idx,rev}
      .git/objects/pack-broken/` + `git fetch --refetch origin`.
      Fresh packs (different SHAs) replace the broken ones; loose
      blobs written via `git hash-object -w` since the corruption
      are unaffected.
    - **§4.8** — Test-suite under O-21 + O-22. The per-file vitest
      pattern (`npx vitest run __tests__/<file1>.test.js …`) is
      the working substitute for `npm test -- --run`. PR #632's
      33 inline tests across two files ran in 748 ms total.
      Documents that the standing CLAUDE.md root non-negotiable
      *"npm test -- --run 100 % green"* should be read as
      "per-file equivalent" until O-21 closes.
    - **§5** new rows: `D777` (anchor-cap radius clamp), `D780`
