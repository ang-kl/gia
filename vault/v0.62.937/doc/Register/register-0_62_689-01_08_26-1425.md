## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-52 | **A colour emoji cannot be recoloured — build the marker as DOM.** The operator asked for 📍 *"in bold bright orangy-yellow"*; U+1F4CD carries its own font artwork and ignores CSS `color`, and the U+FE0E text-presentation variant renders inconsistently across iOS / Android / desktop WebViews. Three options were surfaced and the operator chose the custom pin. This also matches existing practice — `stationPillNode`, `busTierNode`, `amenityLabelNode` are all styled DOM. | v0.62.689 |
| D-53 | **The inspection overlay is not a search anchor.** A temporary pin draws rings + nearby context and nothing else: it never sets the active region, never re-ranks or re-filters the card list, and never survives a tap-out. Operator-approved as *"inspection overlay only"* before build. This is what keeps the feature additive — no existing flow in either app changes behaviour. | v0.62.689 |
| D-54 | **Nearby-centre pills always show their distance.** In the outer rail network the 3rd-nearest centre can be kilometres from the pin; without the number, the 750 m walk ring drawn alongside it implies walkability it does not have. Flagged before build and built in. | v0.62.689 |

## Note

C-113 is worth reading next to C-111. Both are the same kind of finding: a surface that **looked**
finished and was not wired to anything. The ring layer was absent from Transport, and Hawker's
station field had a handler slot nobody had filled — in both cases the component rendered, the app
built, and every test passed. Neither was reported by a user, because in each case the failure mode
is *nothing happens*, which reads as "not a feature" rather than "a broken feature". They were found
only because this arc had to walk both call sites to add something adjacent.

C-110's history is the more transferable lesson. The single-north-label default had been patched
twice — once by ring size, once by ring role — and each patch was a correct fix to the report in
front of it. The third report would have arrived for whichever ring class the first two had not
covered. Changing the default instead of adding a third exception is what ends the sequence.
