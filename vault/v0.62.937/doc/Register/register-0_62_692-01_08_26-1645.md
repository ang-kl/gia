## Note

The failure itself is a one-line oversight. What it exposes is that **this project's entire
verification stack can be green while the app cannot render a single card**, and every layer failed
for a defensible reason: Vite transpiles rather than analyses, `node --check` parses rather than
resolves, the suite tests pure functions rather than components, and the compiled-CSS grep — the
check specifically invented here to catch Tailwind's silent drops — reads *source text*, so it
happily confirmed both height classes were emitted by code that could never execute.

That last one is the sharpest. `.h-[5.5rem]` and `.h-[8rem]` were reported EMITTED in the v0.62.686
entry, and that was true and meaningless at the same time.

Two further things are worth carrying forward. First, the crash **needed data to appear** — with the
centres API 404ing, the app renders its shell and looks healthy, which is exactly what the first
reproduction attempt showed and why it nearly produced a false all-clear. Second, the headless
harness itself produced a *second* false all-clear: Playwright matches routes **last-registered
first**, so a catch-all `**/api/**` registered before the specific centres mock silently shadowed it,
and the app again rendered an empty, error-free shell. Both near-misses shared the same shape as the
bug — an absence that looks like health.
