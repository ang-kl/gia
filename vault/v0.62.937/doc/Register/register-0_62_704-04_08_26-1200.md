## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-80 | **A mockup's convenience is not a design decision, and it must be named before it ships.** The itinerary mockup drew an SVG because a mockup needs no API key, no async loader and no network — entirely correct for a mockup. Four rounds of operator review then passed over it while refining buttons, badges, circles and checkboxes, and it was one question away from becoming Clipboard's permanent map: the only TMA with no zoom, no pan, no basemap and no controls. Nobody chose that; it was inherited from the prototyping medium. Where a prototype makes a shortcut, the shortcut has to be surfaced as a decision, not left to be ratified by silence. | v0.62.704 |
| D-81 | **Where one attribute can hold several things, colour by the thing, not by its family.** Pins were coloured from `segments.js`'s day-part. That file puts `teaBreak`, `earlyDinner` and `dinner` all in `evening`, so three drawers rendered the identical `#ff6b6b` — and "which drawer is this pin" is the only question a pin colour answers. It survived four review rounds because the demo cabinet had two evening drawers and the pin numbers disambiguated them, which is to say the fixture was hiding the bug. The family is now the day-part and the shade is the ordinal within it, with a test asserting distinctness. | v0.62.704 |
| D-83 | **A module that advertises itself as dependency-free must actually be, and its import graph has to be checked from where CI stands.** `itinerary.js` opens by claiming "no React, no Google Maps, no DOM" and imported `./i18n.js`, which imports React — so the pure module dragged the renderer in behind a name that gave no hint of it. It passed in the sandbox because Vite resolves bare specifiers by walking up from the *importer*, and React lives in `web/clipboard/node_modules`; the root `npm ci` the unit job runs installs no TMA dependencies. Green locally, red on the runner, which is the worst shape a failure takes. The fix was to inject the translator rather than import it, and to add a static guard so the next one fails on the developer's machine. | v0.62.704 |
| D-82 | **A measurement of an animated property is a measurement of a moment, and the moment has to be chosen.** The first browser probe reported the M3 indeterminate state as not applying, while `:indeterminate` matched and the rule was demonstrably in the compiled CSS. Ten minutes went into hunting a minifier bug that did not exist. The cause was reading `getComputedStyle` in the same tick as the property change — t=0 of the box's own 100 ms `background-color` transition. The `:checked` control read correctly only because that input carried `checked` from parse time and had never transitioned. A settle delay fixed it. This is the mirror image of D-79: there, green output was trusted too readily; here, red output was. | v0.62.704 |

## Note

The useful part of this round is not the feature. It is that the operator's last question —
*"is it google map … or is this a svg"* — caught a decision nobody had made.

The SVG was a prototyping convenience. It was correct for a mockup and wrong for the product, and it
had already survived four rounds of detailed review: buttons matched to Sketchbook's exact class
strings, badge semantics narrowed to mappable stops, drawer circles labelled, checkboxes rebuilt to
M3. Every one of those rounds looked closely at the thing and none of them looked at the medium.
That is D-80, and it is uncomfortable in the same way D-79 was: the review process was working
exactly as intended and still would have shipped the wrong answer.

D-81 is the same shape one level down. Colouring pins by day-part was wrong from the first draft, and
it survived because the demo cabinet happened to have only two evening drawers — the fixture was
hiding the defect. It took writing the test, not looking at the map, to see it.

And D-82 is the counterweight to D-79. That entry recorded green output being trusted too readily.
This one records **red** output being trusted too readily: a probe reported a correct M3 rule as
broken, and the reflex was to go looking for a bug in the build toolchain rather than in the probe.
The rule was fine. The probe read the value at t=0 of a 100 ms transition.
