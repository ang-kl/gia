## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-76 | **Writing the invariant down is how you find it violated.** O-130 was filed as documentation — a table so the next port would be checkable. Building it surfaced two `aria-modal` dialogs sitting at their own app's chrome tier, shipped, unreported, and invisible to every review because no artefact existed to compare them against. A stack nobody can see is a stack nobody can check. The corollary for the queue: an item filed as "document X" is not clerical work, and should not be scheduled as if it were. | v0.62.702 |
| D-77 | **A scan's own escape hatches are part of its logic.** Two failures in this one version from the same root. (a) The enumeration regex ended `\|auto)\b` — a `\b` after `]` can never match, so **every** arbitrary `z-[NN]` was silently dropped, including the `z-[35]` values O-130 is about; the first table looked complete and omitted 17 sites. (b) The guard extracted an opening tag *then* stripped comments, so the comment written to explain this very fix — containing `(5591 > 4592)` — truncated the tag at its `>`, the scanner never reached `role="dialog"`, and the guard **passed a mutation it should have caught**. Both produced confident, complete-looking, wrong output. A scanner must be mutation-checked before its silence is read as a result. | v0.62.702 |

## Note

O-130 was the cheapest-looking item left in the queue: write down some numbers. It produced the only
user-facing bug fix of the version.

That is worth stating plainly because of how the item was scheduled. It sat behind O-124 and O-104
because those were "real work" and this was "documentation". But the reason nobody had noticed two
`aria-modal` dialogs sitting at their own app's chrome tier is precisely that **there was no artefact
to notice it against**. Every review of those files saw a plausible `z-30`. The table is what makes
`z-30` a claim rather than a number.

D-77 is the less comfortable one. Both scanning failures in this version were mine, both were silent,
and both produced output that looked complete. The regex dropped 17 sites because of a `\b` that can
never match after `]`. The guard went blind because a comment *I had just written to explain the fix*
contained a `>`. In both cases the tool reported success and I would have believed it.

The only defence that has worked so far, across D-62, D-68, D-72 and now D-77, is the same one: make
the check fail on purpose before trusting its silence. C-160 is mutation-checked for that reason, and
it is the step that caught the blindness — not review, not reading it again.
