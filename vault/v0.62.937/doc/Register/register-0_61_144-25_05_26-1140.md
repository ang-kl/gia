## Decisions (append-only)

| # | Decision | Rationale | Date |
|---|---|---|---|
| D-61.140 | **Wake-from-idle is a 2-step flow.** When the first chat message arrives more than `IDLE_WAKE_MS` (6 h) after the last activity, `promptLocationOnWake` stamps `wake:pending:<chat>` (10-min TTL) and sends the `wake.intro` text + the existing `LOCATION_REQUEST_KEYBOARD` (request_location reply keyboard, one_time_keyboard:true). On share, `bot.on('location')` checks the flag, deletes it, and routes to `handleWakeLocationResponse` — does NOT overwrite the cached anchor. The handler reverse-geocodes the device GPS to a street name (operator: "street only, not full address"), reads the cached anchor (using v0.61.139's street/building/postal composite when present, falling back to the curated `label`), and sends the rich `wake2.body` HTML message with three inline buttons + a `/l Orchard Road` / `/l IOI City Mall` helper text line. New device GPS stashed in `wake2:offer:<chat>` (10-min TTL) for the `wake2:current` button. The v0.61.84 `wake:locationCheck` / `wake.keepBtn` / `wake.newBtn` strings + the `wake:keep` / `wake:new` callback handlers are RETAINED for back-compat (stale messages in users' chat history can still tap them without errors). | Operator screenshot of the v0.61.84 wake message (which displayed *"Gia is still using…"* even after the rebrand; v0.61.138 fixed the brand string but the operator wanted the full UX rewrite). The 2-step shape ("ask for GPS first, then compare") is the only way to surface a *"your device now appears to be near …"* line — Telegram bots cannot read GPS unsolicited. | 25-05 '26 |
| D-61.141 | **Special-mode toggles are catalogue chips, not amber pills.** Fruits / Durian / Durian Pastry now live as regular chips inside the catalogue's "Dessert, Fruits" category card, with the symmetric mutex (special ↔ all other cuisines including Dessert) enforced by `applyChipToggle()` in `web/cuisine/src/v2/lib/cuisine-selection.js`. The v0.61.126 amber-pill row above the catalogue is retired. **Durian narrowed to "durian fruit only"** (pastry terms moved to a new `DURIAN_PASTRY` mode; a `NAME_REJECT_PATTERNS[DURIAN]` regex list catches pastry-named venues that would otherwise sneak in via the bare-word `durian` keyword). **NEW Durian Pastry mode** with its own seeds + keywords (durian puffs / cakes / mochi / etc.). Mutex semantics: tapping a special slug replaces the entire selection with `[slug]` (clears Dessert + every other cuisine); tapping a non-special slug while a special is active also replaces (auto-clear-and-switch UX). | Operator screenshot of the amber-pill row + written spec: *"move fruits and durian into selection for 'Dessert, Fruits' group … when selecting Fruits / Durian / Durian Pastry, other cuisines including dessert cannot be selected or part of search criteria"*. Decision codifies both the catalogue placement AND the mutex semantics so a future special-mode addition (seafood-only, vegetarian-only, …) follows the same recipe: source entry in `doc/Feature/cuisines_js.MD` + slug-aligned `SPECIAL_MODES` constant + KEYWORDS + seeds. | 25-05 '26 |
| D-61.142 | **Per-slug image-asset override for catalogue chips.** Cuisines may opt into a PNG icon instead of the default emoji glyph via `IMG_FLAG_BY_SLUG` in `cuisines-vault.js`. `getByCategory()` attaches an `imgFlag: <filename>` field (or null) to each cuisine entry; `CuisineCategoryDrawer.jsx` renders an `<img src="/app/cuisine/{imgFlag}">` when set, with an `onError` fallback to the emoji `flag` (or default 🍽️). First registered slug: `'durian' → 'durian.png'` (operator-supplied clipart; the v0.61.141 chip previously fell back to 🍽️). Use sparingly — emoji is preferred for performance + theme-respecting glyph rendering; reserve for cases where no Unicode glyph is a close match (durian, … future Sambal/Laksa dish-shaped icons might also fit). | Operator uploaded a 204×192 durian PNG via `data/IMG_2177.png` and said *"use this png for durian"*. Decision establishes the pattern so future per-slug image assets follow the same recipe (drop a PNG in `web/cuisine/public/` + add `'<slug>': '<filename>.png'` to `IMG_FLAG_BY_SLUG`). | 25-05 '26 |
