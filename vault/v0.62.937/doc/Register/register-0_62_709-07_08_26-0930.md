## Note

This is the second time in three sessions the same class of bug has appeared: an array that gained
a lapsed-but-kept historical row, and a `.length` read somewhere downstream that didn't know it now
needed to filter. The first time (v0.62.667, Bib Gourmand) required an operator correction after
shipping to even discover the never-delete pattern was wanted at all. This time the pattern was
already established, and the analogous bug in `STARS_ONE` was caught by deliberately checking every
site that reads `STARS_ONE.length` before shipping — worth noting as the value of an established
pattern: it turned a bug that needed live discovery once into a checklist item the second time.
