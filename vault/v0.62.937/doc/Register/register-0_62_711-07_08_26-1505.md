## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-94 | **When raising an internal timeout/deadline pair, check every outer deadline the function runs inside before picking numbers — a locally-reasonable 2× scale-up can silently violate a budget three levels up.** The first draft of this fix (`DEADLINE` → 20000ms, matching `PER_ATTEMPT_MS`'s 2× ratio) was caught before shipping only because the call chain was traced outward (`extractDishesFromReviews` → `enrichSlow` → the search route's `_SEARCH_DEADLINE_MS`) rather than trusting that the function's own internal ratio was the only constraint that mattered. | v0.62.711 |

## Note

The pattern across this session's last three entries (C-192/C-194/C-196) has been the same shape
each time: infrastructure that looks general-purpose from its own local comment ("GEMINI_MODEL env
var still overrides", `STARS_ONE.length`, a per-attempt timeout tuned in isolation) turns out to have
an unstated dependency on something outside the function it lives in — a sibling function that never
wired up the env var, an array whose length silently grew to include historical rows, a deadline
nested three calls deep inside a stricter one. None of these were caught by the test suite; each was
caught by deliberately tracing the call chain outward before trusting a locally-obvious fix.
