## 3. Jurisdiction & Privacy

- **Jurisdiction:** Singapore. The bot serves SG-specific datasets and complies with Singapore-side terms (LTA / NEA data licences, HDB carpark licence, data.gov.sg open-data licences, CHAS / SPF / NParks / STB / HPB / NLB / URA open-data licences, OneMap / SLA API terms). Default coverage is Singapore; selecting "Johor Bahru" extends search across the state of Johor, Malaysia, where data quality relies on Google Places. The live `/legal` body (§1) asserts governance under Singapore law via the *"to the fullest extent allowed by Singapore law"* no-liability clause.
- **Governance alignment:** the IMDA Model AI Governance Framework continues to inform the project's AI practice (no automated decisions about individuals; AI is best-effort enrichment that never gates a core reply — see §5 / §7). As of v0.61.35 this alignment is **no longer stated in the user-facing `/legal` body** — the operator-supplied rewrite intentionally dropped the explicit IMDA line. It is retained here as the project's standing posture. The prior body's IMDA line is preserved verbatim in §8.
- **Personal data:** Telegram chat IDs (numeric), Telegram user IDs (numeric), language code, and geolocation (only when shared by the user). No persistent identity binding beyond Telegram's own user record.
- **Storage:** Redis only (no SQL database). TTLs — location 24 h, pick cache 60 s, share tokens 7 d, recent picks 24 h, place reviews 24 h, vibe-summary 7 d, enrichment 7 d, station-context 30 min, usage / free-text log 90 d, public holidays 90 d. The map overlay layers and the per-station / per-stop transport datasets are static files or short-lived (24 h) Redis caches of public open data — see the geodata note below.
- **Aggregate usage:** usage counts are kept only as aggregate numbers; per-user entries are one-way sha256 hashes used solely to de-duplicate those counts, removed on `/forgetme` and expiring after 90 days.
- **Retention posture:** no off-platform export; no analytics SDK; no third-party cookies; no advertising IDs; no cross-bot profiling; no sharing with marketers.
- **Geodata note:** the map overlay layers (`geoloc/*.geojson` → `data/geo-*.json`, including `geo-clinics.json`, `geo-police.json`, `geo-hospitals.json`) and the derived transport datasets (`data/stations.json`, `data/bus-services-by-stop.json`, `data/stations_with_nearest_bus_stops.json`, `data/sg_24hr_places.json`, the derived MRT polyline geometry) are static public open data — or, for live bus arrivals / carpark lots, short-lived 24 h Redis caches of public feeds — with no personal-data content. Build-time datasets are processed entirely at build time and served as static files; `GET /api/geo/bus-stops` and similar routes are Redis-cached 24 h.

## 4. Retention summary (canonical surface: `/privacy` + this Legal record)

Stored data expires automatically; the longest retention window is **90 days** of inactivity (search / selection / usage records, the free-text log, the hashed aggregate counters). Location is cached 24 h; recent picks 24 h; share tokens 7 d; station-context 30 min. A manual erasure (`/forgetme`) removes the user's stored data immediately. These windows match the Redis TTLs in §3 and are **unchanged across the v0.61.29 → v0.61.76 arc**. Note that since the v0.61.35 `/privacy` rewrite the explicit 90-day figure is no longer printed in the live `/privacy` body — this Legal record (§3, this section) is the authoritative statement of the retention windows.

## 5. AI provider terms summary

AI-generated content is produced via the Gemini API (Google), subject to Google's Generative AI / Gemini API terms. The bot sends no personal data to the model beyond the user's free-text query and the venue/location context needed to answer it. AI output is **best-effort enrichment** — it never gates a core reply, and is server-verified where it makes factual claims (e.g. `/hidden` venues are checked against Google Places before display).
