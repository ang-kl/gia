## 1. Disclaimer (user-facing copy in `/legal`)

> _(reproduced verbatim from `legal-0_60_132-12_05_26-0830.md` — see §7 for the v0.60.153 amendment)_

> **soleat is a personal, non-commercial side project run from Singapore.** It surfaces public data (Google Places, LTA DataMall, NEA, data.gov.sg) and AI-mediated content (Anthropic Claude, Google Gemini) inside Telegram for **informational use only**. Listings, ratings, opening hours, and award statuses can be wrong, stale, or fabricated by the underlying LLMs despite our verification rules — please confirm critical details (open/close, halal certification, dietary safety) directly with the venue before acting. soleat does not collect, sell, or share personal data; see `/privacy` for retention. soleat is not affiliated with Google, Anthropic, the Singapore Government, or any of the rating bodies it references. Use at your own risk.

## 3. Jurisdiction & Privacy

> _(reproduced verbatim from `legal-0_60_132-12_05_26-0830.md`; the v0.60.153 addition — the aggregate-usage-counts layer added in v0.60.142 — is appended as a new bullet below the search-term-log bullet and cross-referenced in §7.)_

- **Jurisdiction:** Singapore. Bot serves SG-specific data sets and complies with Singapore-side terms (LTA / NEA data licences, HDB carpark licence, IMDA Model AI Governance Framework alignment for AI-mediated output).
- **PDPA Section 13(c) / GDPR Article 17 alignment:** users can wipe every chatId-keyed Redis entry on demand via `/forgetme`. Returns a deletion summary so the user has a record.
- **No personal data sent to third parties.** Chat IDs are sha256-hashed before being used as Redis keys for location / processing / activity-tracking state. Telegram user IDs are visible only to the LLM providers when their APIs are called, and only as the bot's own request initiator (not as user attribution).
- **AI-mediated content disclaimers:**
  - `/hidden` results are generated by Google Gemini with Google Search grounding. Despite explicit "do not fabricate" prompt rules + post-process safeguards (e.g. `rewriteFabricatedPlaceUrls` rejects fabricated Place IDs), the model can still return inaccurate or stale facts.
  - Tell-Gia (cuisine NL) uses Anthropic Claude to map free-text to cuisine slugs. Misclassifications happen; the user can always pick cuisines manually in the TMA.
  - `/recognised` award lists are LLM-fetched (Anthropic Claude) and grounded with web search; year-scoped and 24 h cached.
  - **Michelin cards (Cuisine TMA, v0.60.147+):** `vibe` + `signatureDish` + `dishes` fields are generated by Google Gemini against a curated Michelin Guide 2025 entry list (`michelin-2025.js`). The prompt explicitly says *"reference the Michelin recognition correctly (no hallucination)"* and is hard-grounded to the curated entries' name + tier + cuisine label + (when available) recent Places reviews; v0.60.149 adds a server-side `stripDishVerbs` regex post-process to remove verb-prefixed phrases the LLM occasionally writes despite the prompt rule. v0.60.153 introduces a `michelin:enrich:<slug>` Redis cache (7-day TTL) so subsequent searches reuse the prior narration unless the venue's enrichment fields are missing or stale.
- **Free-text search-term log (v0.60.131; retention 90 days v0.60.132).** _(reproduced from `legal-0_60_132-12_05_26-0830.md` §3 verbatim — see that file for the full clause)_.
- **Aggregate-usage counters (v0.60.142; PR #379).** The bot maintains aggregate-only usage counters in Redis (`usage-log.js`) for the hidden owner-only Oversight admin Mini App (`/app/oversight`, owner-gated). Per-user entries are **one-way `sha256` hashes** of the Telegram chat ID (the same `hashChatId` scheme already used for `loc:<…>` / `proc:<…>` Redis keys per `location-cache.js`), used **only** to de-duplicate the aggregate counts — nothing else is attached to the hash. The hashed keys:
  - `usage:users` SET, no TTL — `SCARD` = total users since tracking shipped.
  - `usage:dau:<YYYY-MM-DD>` SET, 90-day TTL — daily-active hashes.
  - `usage:search:<YYYY-MM-DD>` SET, 90-day TTL — hashes that did ≥ 1 search that day.
  - `usage:searchmulti:<YYYY-MM-DD>` SET, 90-day TTL — hashes that did ≥ 2 searches that day ("frequent").
  - `usage:cuisine[:<YYYY-MM-DD>]` HASH — cuisine-name → count, NOT keyed by user.
  - `usage:criteria[:<YYYY-MM-DD>]` HASH — `src:<chat-freetext|cuisine-tma|s|eat|surprise|cuisine-tma-back|cuisine-tma-recycle>` / `filter:<name>` / `price:<n>` / `region:JB` / `freetext` → count, NOT keyed by user.

  The cuisine + criteria HASHes carry NO per-user attribution by construction. The SETs hold ONLY one-way hashes. **No raw chat IDs, Telegram user IDs, or any other personal data are stored in `usage:*`.** The dashboard surfaces only aggregate counts (total users, today active / searchers / frequent, by-day, by-day-of-week averages, top cuisines / criteria / free-text words, recent free-text from the existing identity-free `freetext:log`). `/forgetme` (`user-data.js removeUsageMembership`) `SREM`s the user's hash from `usage:users` + SCANs every `usage:dau:*` / `usage:search:*` / `usage:searchmulti:*` and `SREM`s it from each. Per-day data self-clears after 90 days of inactivity (TTL). No backfill (tracking started at v0.60.142 deploy).

  Surfaced to users in `/privacy` body bullet (v0.60.142, EN + FR): *"Usage counts — how many people use Soleat, daily-active counts, and which cuisines / filters / search terms are popular — are kept only as aggregate numbers. The per-user entries are one-way sha256 hashes used solely to de-duplicate those counts (nothing else is attached to them); they're removed on /forgetme and expire after 90 days."*

## 4. Retention summary (canonical: `/privacy`)

> _(reproduced verbatim from `legal-0_60_132-12_05_26-0830.md`, then extended below the rule. Stale TTLs are corrected in §7 rather than edited in place, per AU-7.)_

- `loc:<sha256>` — 24 h
- `recent-picks:<sha256>` — 24 h
- `proc:<sha256>` — short-lived (per-request)
- `cuisine:search:*` — 30 min
- `cuisine:warmstart:*` — 60 s
- `revgeo:*` — 1 h
- `place-reviews:*` — 24 h
- `tell-gia:rl:*` — 1 h (rolling window)
- `buddy-optin:*` — 30 d (rolls forward on activity)
- `buddy-blocks:*` — 90 d (rolls forward on activity; the only persistent slot)
- `freetext:log` + `freetext:log:<YYYY-MM-DD>` — 90 d (v0.60.132; identity-free)

| Key | Type | TTL | Identity |
| :--- | :--- | :--- | :--- |
