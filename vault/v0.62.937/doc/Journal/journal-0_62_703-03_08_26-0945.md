_(№ 1,042 — 03-08 '26 09:45 SGT)_

## New

### [HDR] v0.62.703 — O-120 closed: every TMA must paint, in CI, on every PR

- **[INTENT]** Operator: *"do next work"*. Next was **O-120**, which the previous Register called
  *"the strongest remaining candidate, since three of the last four versions built a throwaway
  harness"*. Counting this session, a render harness has been hand-built and deleted **nine** times.
  This is the tenth, and it is committed.

- **[WHAT O-120 SPECIFIED]** From v0.62.692: *"mount each TMA once with a fixture payload and assert
  `#root` is non-empty… needs no new dependency beyond what this repo already has available
  headlessly"*.

  **That last clause was wrong, and it was mine.** Playwright is present in this sandbox because the
  *environment* pre-installs it — it appears in no `package.json` in the repo. In CI there would have
  been nothing to drive. So this does add a dependency: **`playwright-core`**, chosen over
  `playwright` because core downloads no browsers and drives the Chrome that `ubuntu-latest` already
  ships.

- **[DELTA]**
  - **`scripts/render-smoke.mjs`** (NEW) — boots all six built TMAs in headless Chromium, stubs the
    Telegram bridge, serves the app from disk and the API from fixtures, waits for the render to
    settle, and asserts the app painted.
  - **`package.json`** — `playwright-core` devDependency, `npm run test:render`.
  - **`package-lock.json`** — regenerated. **Not optional**: `ci.yml` uses `npm install`, but four
    other workflows use `npm ci`, which fails outright on a package.json/lock mismatch. Adding the
    devDep without the lock would have broken them.
  - **`.github/workflows/ci.yml`** — a `Render smoke` step at the end of the **build** job, where the
    freshly built output already exists; a separate job would have to build everything twice.

- **[NO SERVER]** Each app builds with base `/app/<name>/` but ships to `public/<name>/`, so the
  paths do not line up on disk. Instead of a static server with a rewrite (a port to collide with, a
  process to leak), **every request is intercepted** and fulfilled from disk or from a fixture. One
  handler, dispatching internally — which also sidesteps the Playwright route-precedence trap that
  produced a false all-clear earlier this session (last registered handler wins, so a catch-all after
  a specific mock silently shadows it).

- **[DOES IT CATCH THE THING IT EXISTS FOR? — reintroduced the bug to find out]** The v0.62.692 crash
  was put back verbatim: `isShort` removed from `renderCentreCard`'s signature while still used in
  its body.

  | check | with the bug present |
  |---|---|
  | `vite build` | **green** |
  | `npx vitest run` (161 files / 3,964 tests) | **green** |
  | **`npm run test:render`** | **❌ hawker — `isShort is not defined`** |

  That is the whole case for this file in three lines. Restored, rebuilt, green again.

- **[TWO FALSE GREENS IT PRODUCED ON ITSELF, BOTH FOUND BEFORE COMMITTING]**
  1. **The harness failed two apps for requests the harness was refusing to answer.** Same-origin
     non-asset paths (`/maps-key`, unmatched `/api/…`) fell through to the disk lookup and 404'd,
     surfacing as console errors. Fixed: only `/app/<name>/…` is served from disk; everything else
     same-origin gets a JSON stub.
  2. **Worse — it was smoke-testing the lockout screen.** The stub set `initData: ''`, and every app
     boots through a `hasInitData()` guard that renders *"reopen from Telegram"* when it is blank.
     Cuisine painted **4** nodes, Clipboard **5**, and the harness called both a pass. The crashing
     component in the v0.62.692 case never even mounts on that path, so the harness would have been
     green through the exact bug it was written for. Fixed with a non-empty `initData` (the value is
     never checked client-side — the server verifies the HMAC, and the server is stubbed).

- **[AND THE ASSERTION WAS TOO WEAK ANYWAY]** `#root` gains its first child when the boot spinner
  mounts, so counting there reported Cuisine at 4 nodes even once it was past the guard. The count
  now **settles** — poll until the node count stops changing — and each app carries a **floor**
  (cuisine 40 / hawker 32 / transport 45 / menu 30 / oversight 18 / clipboard 32, all well under the
  observed 95 / 76 / 106 / 71 / 40 / 77). "Something painted" is now "the app painted".

- **[VERIFICATION (sandbox)]** All six apps green after a full `npm run build`; mutation-checked
  against the reintroduced v0.62.692 crash (fails with the right app and the right message, passes
  once restored); full `npx vitest run` **161 files / 3,964 tests** green; `ci.yml` re-parsed as valid
  YAML.

- **[TEST]** Nothing user-facing changed in this version. The check is CI: the **TMA build** job now

- **[THE CI BROWSER PATH — ANSWERED THE SAME DAY]** This was filed as O-140, the one part of the
  change that could not be verified from here: locally the harness uses the sandbox's pre-installed
  Chromium, and on a runner it falls back to `channel: 'chrome'`. PR #1696's own build job settled it:

  ```
  > soleat@0.62.703 test:render
    ✅ cuisine 99 · hawker 76 · transport 106 · menu 71 · oversight 40 · clipboard 77
  All 6 apps rendered.
  ```

  `channel: 'chrome'` resolved on `ubuntu-latest`, six apps in **6.4 s**, and the build job's total
  went **75 s → 72 s** — the step costs nothing measurable. Cuisine reads **99** on the runner against
  95 locally, which is exactly why the floors sit well below observed (O-142). O-140 closed.

- **[KNOWN GAPS]**
  - **First screen only.** No search is performed, no drawer opened, no map loaded (Google Maps needs
    `/maps-key`). A crash that needs a completed search still ships silently.
  - **The floors are hand-maintained numbers**, same shape as the z-stack registry's `chromeTop`. A
    legitimate UI change that removes a lot of nodes will trip them, and the fix is to re-measure —
    which is the point, but it is friction.
  - Fixtures are approximations of the server's shapes. Where one drifts the app renders its empty
    state, which still exercises the render path but proves less than it appears to.
