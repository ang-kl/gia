# Journal — soleat v0.61.293 (unify durian-variance: CLI now delegates to the runner)

> Operator (30-05 '26 22:45 SGT, post-PR-#798 merge): *"3"* — unify the two variance modules so the v0.61.283/.288 divergence-bug class cannot recur.
>
> The two modules pre-v0.61.293:
>
> - `scripts/durian-variance.js` — 278 lines. CLI tool the operator runs locally with `GOOGLE_MAPS_API_KEY`. Has its own copy of REGIONS, SEEDS, placeToVenue, searchText, and the per-region loop.
> - `durian-variance-runner.js` — 264 lines. In-process module the bot's `/ver` flow calls via `runVariance({...})`. Same shape but slightly different defaults (LIMIT 20 vs CLI's 8, RADIUS 25 km vs 8 km, MAX_PAGES 3 vs no pagination), and 4× more SEEDS_DURIAN_PASTRY entries (14 EN vs CLI's 4 — the v0.61.262 operator expansion).
>
> The duplication caused v0.61.275-282's silent placeId loss: v0.61.283 fixed `scripts/durian-variance.js` but missed `durian-variance-runner.js`, leaving the bot's `/ver` path broken for another 5 patches until v0.61.288. **Register O-37** flags this class of risk (iCloud-stale-checkout + silent-divergence-between-duplicates).
>
> v0.61.293 closes it for the variance pipeline specifically:
>
> - **`durian-variance-runner.js` becomes the single source of truth.** All REGIONS / SEEDS / search / classify / loop logic lives here.
> - **`scripts/durian-variance.js` becomes a thin CLI wrapper** (278 → 71 lines, -75% LOC). Parses argv, calls `runVariance({ apiKey, mode, log })`, prints rollup + writes JSON.
> - The runner gains per-query + per-lang + region-end-stats `log` calls (gated on the optional `log` callback). The bot's `/ver` path doesn't pass `log` so its chat surface is unchanged; the CLI passes `console.log` to keep its verbose stdout.
> - Net code: 542 → 356 lines (-34%), 186 lines of duplicate logic eliminated.
>

## Deleted

### Duplicate variance logic in `scripts/durian-variance.js` (~207 lines)

The CLI's own copies of:
- `const REGIONS = [...]`
- `const SEEDS = MODE === 'durian-pastry' ? {...} : {...}`
- `const LIMIT_PER_QUERY = 8`, `const RADIUS_M = 8000`
- `const PLACES_LANG = {...}`
- `async function searchText(...)` (single-page; no pagination)
- `function placeToVenue(p)` (the v0.61.283-fixed version)
- `async function runRegion(region)` (per-region loop)
- The IIFE main `(async () => { ... })()` body's REGIONS loop + report construction

All of the above lived in the runner already (as `REGIONS_DEFAULT`, `SEEDS_DURIAN`, `SEEDS_DURIAN_PASTRY`, `_placeToVenue`, `_searchText`, the inline loop inside `runVariance`). The CLI now delegates to those.

The deleted CLI versions had stale defaults — `LIMIT_PER_QUERY=8` vs runner's `20`, no pagination vs runner's `MAX_PAGES=3`, and only 4 EN durian-pastry seeds vs runner's 14. Post-v0.61.293 the CLI inherits the runner's defaults automatically.
