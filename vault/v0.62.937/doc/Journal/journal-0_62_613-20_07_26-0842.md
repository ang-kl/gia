### [HDR] v0.62.613 — the iPad mini (744 px) fell under the 768 px tablet gate; lower it to 700. And un-cram the Hawker footer's NEA ↗.

- **[INTENT]** Operator (IMG_1106/1107/1109, on an **iPad mini**): *"What is happening after a week worth
  of work to change the aspect ratio. This is iPad mini. Did you gate? I am disappointed. Also the hawker
  TMA nea be at the same row as the footer, looks weird."*

- **[ROOT CAUSE #1 — the gate]** v0.62.612's physical-screen tablet detection used a **≥ 768 px**
  short-edge threshold — but the **6th/7th-gen iPad mini is only 744 px wide**. `744 < 768`, so the mini
  fell **under** the gate and rendered the **phone layout** (the drawer) despite v0.62.612. The gate was
  real, and its cutoff was wrong for the mini.

- **[DELTA — gate, 3 files]** `web/_shared/lib/use-viewport.js`: new exported const
  **`TABLET_MIN_EDGE = 700`** (below the 744 mini, safely above the largest phones — ~480 px short edge —
  so a phone is never mis-promoted); `readViewport`'s tablet test is now
  `coarse && (minDim >= TABLET_MIN_EDGE || screenMin >= TABLET_MIN_EDGE)`. `web/cuisine/src/api/tg.js` +
  `web/hawker/src/tg.js` fullscreen gates: `minScreen >= 768` → **`>= 700`** so the mini also goes
  fullscreen.

- **[ROOT CAUSE #2 — NEA "looks weird"]** v0.62.611 stacked **NEA ↗** directly under the back/end button
  **inside the right control column**, so its bottom edge collided with the centred version line and read
  as *"the same row as the footer."*

- **[DELTA — Hawker footer]** `web/hawker/src/App.jsx` `FooterDock`: NEA ↗ now sits on its **own
  right-aligned line between the controls row and the version tag** (`flex justify-end`, `px-2 py-1`,
  still `text-[11px] font-semibold text-tg-link` — same font as "↩ back"), clearly separated by the
