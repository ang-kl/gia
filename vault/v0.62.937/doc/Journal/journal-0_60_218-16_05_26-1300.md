## New

### [HDR] #186 | 13:00:00 SGT 16-05-26 | v0.60.218 — weather-emoji vocabulary + /w rework | 5 files | 1 PR |

- **[INTENT]** Establish one shared weather-emoji language and rework the `/w` weather output: operator wants °C **and** °F, the `@ <station>` suffix dropped from the temperature + humidity lines, "Temp" spelled out as "Temperature", a `%` humidity sign, and the operator-curated weather emojis used in the result.

- **[DELTA]**
  - **`weather-emoji.js`** (NEW) — the shared module: `WEATHER_EMOJI` (the 17-entry operator-curated vocabulary — ☀️ sunny, 🌤️ mostly sunny, ⛅ partly cloudy, ☁️ cloudy, 🌥️ overcast, 🌦️ sun shower, 🌧️ rain, ⛈️ thunderstorm, 🌩️ lightning, 🌫️ fog/haze, 💨 windy, 🌬️ wind face, 🌀 cyclone, ☔ umbrella, 🌈 rainbow, 🌊 rough sea, 💧 humidity); `forecastEmoji(text)` — maps an NEA forecast string ("Thundery Showers", "Partly Cloudy", "Hazy", "Fair", …) to one emoji, most-severe-first; `toFahrenheit(c)`.
  - **`i18n.js`** — `weather.temp` `Temp: {c}°C @ {at}` → `Temperature: {c}°C · {f}°F` (FR `Température : {c} °C · {f} °F`); `weather.humidity` `Humidity: {pct}% @ {at}` → `Humidity: {pct}%` (FR `Humidité : {pct} %`).
  - **`index.js`** — `runWeatherCommand`: the temperature line now passes `{c, f}` (Fahrenheit via `toFahrenheit`), no `at`; the humidity line passes `{pct}` only; the 2-hour-forecast line is prefixed with `forecastEmoji(w.forecast)`.
  - **`__tests__/weather-emoji.test.js`** (NEW) — 21 tests (NEA-vocabulary → emoji mapping, fallback, `toFahrenheit`). **`__tests__/i18n-chrome.test.js`** — the `weather.temp` interpolation test updated to the new `{c}`/`{f}` shape.
  - `package.json` `0.60.217 → 0.60.218`; this Journal entry (#186); `doc/.serial-state.yml` (`journal 185→186`, `commit 192→193`; re-anchored).

- **[VERIFICATION (sandbox)]**

  ```bash
  $ node --check index.js weather-emoji.js i18n.js   → OK
  $ npm test -- --run                                 → 1889 passed (1889)   # +21 weather-emoji, -0
  ```

- **[STATUS]** STAGED → PROD on next Railway deploy. Server-only (`/w` command) — no `web/` build.

- **[TEST]** Post-deploy: `/w` (or `/weather <area>`) → the temperature line reads `Temperature: 31.4°C · 88.5°F` (no `@ <station>`); humidity `Humidity: 78%`; the 2-hour-forecast line is prefixed with a condition emoji (⛈️ / 🌧️ / ⛅ / ☀️ …).

- **[KNOWN GAPS]**
  - The `/w` title still carries a static `☀️` (`weather.title`); the live condition emoji is on the forecast line. Acceptable — the forecast line is where the actual nowcast condition is.
  - The rain line keeps its `@ <station>` suffix — the operator's instruction named only the Temp + Humidity suffixes.
  - **Next weather PR (v0.60.219):** a TMA-facing weather endpoint + the per-TMA weather summary (3d) across Cuisine / Train / Hawker / Bus-stop / Carpark / Station TMAs, and the Cuisine-title `Nc · Nf` → weather-emoji swap (3a). `weather-emoji.js` is the shared dependency for that work.
