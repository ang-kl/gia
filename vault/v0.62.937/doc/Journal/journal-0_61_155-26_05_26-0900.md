### [HDR] #356 | 09:00 SGT 26-05-26 | v0.61.155 — Location-mode classifier (PR 1/5): 120 km gate + SG/JB/OTHER mapping | 4 files | 1 PR | 1 build |

- **[INTENT]** Ship the pure foundation for the location-mode
  spec. Two rules:
  1. **Rule §2.2 — coarse radius gate.** Great-circle distance from
     a fixed Singapore centroid (`{lat: 1.3521, lng: 103.8198}`). If
     the user-fix exceeds 120 km — the v0.60.152 SG + adjacent-JB
     ceiling already used in `/api/cuisine/search` — classify
     immediately as OTHER and SKIP the geocode call. KL / Putrajaya
     / Bangkok / Hong Kong all gate-skip without burning Google
     Geocode quota.
  2. **Rule §2.3 — country / admin-area classification.** Within
     the gate, reverse-geocode the coord to obtain
     `country` + `administrative_area_level_1`. Mapping:
       - country = "Singapore" → 'SG'
       - country = "Malaysia" AND admin contains "Johor" → 'JB'
       - anything else (Batam / Bintan / Selangor / Wilayah
         Persekutuan Putrajaya / …) → 'OTHER'

  No integration with `set_location` / `/api/cuisine/search` /
  any handler yet — PR 2 wires the injection. PR 1 is the pure
  primitive + its test surface.

- **[DELTA]**
  - **`location-mode.js`** (NEW, ~150 lines). Pure module:
    - `SG_CENTROID` — frozen `{lat: 1.3521, lng: 103.8198}`.
    - `COARSE_GATE_M` — `120_000`. Operator's "Answer 2" pick
      from the v0.60.152 ceiling.
    - `JB_ADMIN_KEYWORDS` — `['johor']`. Substring (case-
      insensitive) so "Johor Darul Ta'zim" still classifies JB.
    - `haversineMeters(a, b)` — m between two `{lat,lng}` points.
      Standard formula; SG-scale (~30 km) is well inside the
      haversine accuracy band. Returns `+Infinity` on malformed
      input so the `coarseGate` defaults to a fail-OUT.
    - `coarseGate({ lat, lng, radiusM = COARSE_GATE_M })` →
      boolean.
    - `classifyByCountry({ country, adminAreaLevel1 })` →
      `'SG' | 'JB' | 'OTHER'`. Pure mapping, no IO. Defensive
      against missing / non-string inputs (→ 'OTHER').
    - `classifyLocation({ lat, lng, reverseGeocodeFn,
      radiusM = COARSE_GATE_M })` → `{ mode, country,
      adminAreaLevel1, placeName, distanceM, gated, geocoded }`.
      Orchestrates rule 1 → rule 2. `reverseGeocodeFn` is
      injectable (PR 2 wires it to a `country`/`admin`-aware
      wrapper around the existing `reverseGeocodeAddress`).
      Conservative on geocode failure / no geocoder: returns
      `OTHER` with `gated=false, geocoded=false` so the
      downstream feature-gate falls OPEN rather than
      false-positive-ing as SG.
  - **`__tests__/location-mode.test.js`** (NEW, ~190 lines,
