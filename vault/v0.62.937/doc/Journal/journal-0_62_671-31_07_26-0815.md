## Amendments

### [AMD] 31-07 '26 08:19 SGT — commit `1ad8aa4` shipped only 1 of its 4 stated changes; the other 3 were silently dropped by a git-add pathspec failure

Quoting [DELTA] item 1 above verbatim (unchanged, still true): *"Deleted `BackFab.jsx`
in cuisine/hawker/transport/menu... confirmed-dead code from the v0.62.213 footer
consolidation, verified via import-statement grep before removal."* That part shipped
correctly in `1ad8aa4`.

Items 2–4 of the same [DELTA] section — the BottomSheet duration reconciliation, the
Widen-switch travel fix, and the MapControls radius fix — **did not ship in `1ad8aa4`
despite the commit message and this Journal entry both stating they had.** Root cause:
the staging command was `git add -A <7 paths>`, one of which was a `BackFab.jsx` path
already removed by an earlier `git rm` (so the pathspec matched nothing on disk). Git's
behaviour when any pathspec in a multi-path `add` matches zero files is to **abort the
entire command** — it does not stage the other, valid paths first. `git status` immediately
after showed the four deletions as staged (`D`) and was read as "the add succeeded"; the
three edited files' leading status column (unstaged) was not checked closely enough. The
build/test verification that followed was run against the **working tree**, which did
contain the three fixes — so it passed — but `git commit` only captured the index, which
did not. The gap sat undetected through the docs pass and the `#1674` PR open.

**Caught by**: the repo's own `stop-hook-git-check.sh`, which flags uncommitted changes on
every turn — not by anything this session verified directly. Diffing HEAD against the
Journal's own claims (`git show HEAD:<file>` vs the described fix) was what confirmed it.

**Fix**: commit `883fda8` stages and lands the three missing edits, re-verified independently
(cuisine + transport builds green, full `npm test` 3840/3840) before committing — this time
checking `git diff --cached --stat` implicitly via a clean `git add <exact 3 paths>` with no
already-deleted path in the same invocation, rather than a mixed multi-path `add -A`.

**Pattern note**: this is the same *failure shape* the Register already has six precedents for
under a different mechanism — D-22 through D-28's "a declaration/selector/class matches
nothing, fails silently, degrades to something indistinguishable from a design choice" — except
the silently-dropped thing here was an entire code change, and the layer was git plumbing, not
Tailwind or a DOM selector. Recorded as O-90 below: no test or build step in this repo's toolkit
currently catches "the commit doesn't contain what its own message says it contains" — that
would need a diff-vs-message check, which does not exist and is out of scope to build reactively
mid-fix.

Confirmation Gates for this amendment: G1 ✅ (no version bump needed — same v0.62.671, code now
matches what was already documented and released as pending); G2 ➖; G3 ➖; G4 ➖.
