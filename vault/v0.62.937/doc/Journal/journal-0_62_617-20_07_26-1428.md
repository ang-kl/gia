## New

### [HDR] v0.62.617 — Telegram Desktop opens the Mini App wide again (reverses v0.62.286 for desktop), so the responsive layout has room

- **[INTENT]** Operator: *"I re-enable auto-fullscreen on Telegram Desktop so the app opens wide"* — an
  explicit go on Option 2 from the prior turn.

- **[CONTEXT]** On **Telegram Desktop for Mac** the Mini App opens in a **narrow, phone-width window**, so
  `useViewport` reads `w < 1024` → the **phone layout**. The app deliberately did **not** auto-fullscreen
  on desktop (v0.60.52 / v0.62.286 — "unwanted full-screen takeover"). The operator now wants it wide, so
  this reverses that for desktop.

- **[DELTA — 3 × tg.js]**
  - `web/cuisine/src/api/tg.js` + `web/hawker/src/tg.js`: the fullscreen gate gains
    `const desktopClient = plat === 'tdesktop' || plat === 'macos'`, and the trigger becomes
    **`if (desktopClient || (touchClient && coarse && minScreen >= 700))`** (was touch-tablets-only).
  - `web/transport/src/tg.js`: had **no** fullscreen gate (v0.62.286 removed it entirely) — a **new**
    `safe('fullscreen', …)` block was **added** with the same desktop-OR-iPad-class logic (Bot API 8.0
    feature-detected, `isFullscreen` guard).
  - **Effect:** on Telegram Desktop / macOS the app calls `requestFullscreen()` → opens wide →
    `useViewport`'s `!coarse && w >= 1024` → **desktop** → the responsive wide layout renders. **Phones
    stay windowed** (not desktop; physical short edge < 700).
