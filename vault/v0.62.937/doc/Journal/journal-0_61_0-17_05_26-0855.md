## New

### [HDR] #203 | 08:55:00 SGT 17-05-26 | v0.61.0 — Singapore GeoJSON overlay layers (parks / attractions / taxi stops) for the Cuisine + Hawker TMAs | 14 files | 1 PR | 1 build |

- **[INTENT]** The new top-level `geoloc/` folder holds official Singapore open-data GeoJSON
  datasets. The operator wants three of them surfaced as opt-in overlay layers on the two food
  maps so users can see nearby parks, tourist attractions and taxi stops as context — and the
  free-text `geoloc/Readme_2026-0517.MD` turned into a maintainable reference table (the
  README's own instruction asked for a table with a File Description column it lacked).

- **[DELTA]**
  - **`scripts/build-geo-overlays.js`** (new) — one parameterized converter. Reads the three
    committed `geoloc/*.geojson` files (no network) and writes slim JSON to `data/`:
    - Point datasets → `{ name, lat, lng }` (6-dp rounding). Attraction names from `PAGETITLE`;
      taxi labels title-cased from `TYPE_CD_DE` ("Taxi Stand" / "Taxi Stop" / …).
    - The 3.0 MB NParks parks file → `{ name, rings }` polygons: outer rings only, tiny rings
      dropped (bbox-area threshold), Douglas-Peucker simplified (~3 m), coords 5-dp. Output
      `data/geo-parks.json` is **183.5 KB** (461 features → 276 after the tiny-ring drop).
    - Outputs: `data/geo-parks.json` (183.5 KB), `data/geo-attractions.json` (7.9 KB, 109),
      `data/geo-taxis.json` (19.9 KB, 371). Each carries a `_meta` block.
  - **`package.json`** — new `"build:geo"` script; version `0.60.234 → 0.61.0` (new feature).
  - **`index.js`** — new `loadGeoOverlays()` (boot-time lazy cache, mirrors `loadMrtLinePaths`)
    + `GET /api/geo/overlays` returning `{ parks, attractions, taxis }`. Public, same posture
    as `/maps-key` (government open data); missing files degrade to empty arrays.
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** + **`web/hawker/src/lib/mapOverlays.js`** (new,
    byte-identical) — `createOverlayController(map, googleMaps)`: fetches `/api/geo/overlays`
    once (module-level promise), builds parks as translucent-green `google.maps.Polygon`
    (`clickable:false` — never steals pin taps), attractions/taxis as `AdvancedMarkerElement`
    dots (amber 🎡 / yellow 🚕). Layers built lazily on first enable; `setLayer()` flips
    visibility; `destroy()` tears down. Header comment marks the two copies "keep in sync".
  - **`web/cuisine/src/v2/components/MapLayerChips.jsx`** + **`web/hawker/src/components/MapLayerChips.jsx`**
    (new) — a 3-chip strip (🌳 Parks / 🎡 Attractions / 🚕 Taxis) reusing the `QuickFilters`
    chip style. (Cuisine/Hawker copies differ only in i18n import + `useLocale` signature.)
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** / **`web/hawker/src/components/HawkerMapPanel.jsx`**
    — new `overlayLayers` prop; the controller is created in the map-init code, a
    `useEffect([overlayLayers])` drives `setLayer(...)`, and `destroy()` runs on unmount. The
    existing venue/hawker `syncMarkers` is untouched (overlays are managed independently).
  - **`web/cuisine/src/v2/App.jsx`** / **`web/hawker/src/App.jsx`** — new `overlayLayers` state
    (`{parks,attractions,taxis}`, all false), `<MapLayerChips>` rendered below the map. The
    state is deliberately kept OUT of the search/snapshot state — it is a map-view toggle only.
  - **`web/cuisine/src/v2/lib/i18n.js`** / **`web/hawker/src/i18n.js`** — `layer.parks` /
    `layer.attractions` / `layer.taxis` EN+FR keys.
  - **`geoloc/Readme_2026-0517.MD`** — rewritten as a GitHub-flavored markdown reference table
    (Filename | Authority | Last updated | File Description | Source), covering all 13 geoloc
    datasets; the three wired overlay datasets are flagged.
  - This Journal entry (#203); `doc/.serial-state.yml` bumped + re-anchored.
