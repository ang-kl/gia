### [HDR] #598 | 16:34 SGT 08-06-26 | v0.61.398 — New filter: OR the language seeds instead of AND-combining them | index.js | 1 PR | 0 build |

- **[INTENT]** The **New** (newly-opened) filter returns **"no results"** in foreign-script OTHER countries — Tokyo, Kyoto (and the logs show Incheon / Seoul / Daejeon). It worked in SG.

- **[ROOT (traced)]** A regression from my own **v0.61.395 Track B**. That change appends a local-language *"newly opened"* seed (`새로 오픈`, `新しくオープン`, …) as a **separate** recall query, so a bare New search has `cuisineQueries = ["newly opened", "<local>"]` (length 2). But `isMultiCuisine` was gated on **`cuisineQueries.length >= 2`** (`index.js:14443`), so that bare search was misread as a **2-cuisine AND-combo**:
  - The combo phase joins the seeds with a **space** → `"newly opened 새로 오픈"`, which Google treats as **require-all** → recall collapses to ~6 mostly-old venues (log `D702a "6 of 6"`).
  - The combo validator `venueMatchesAll` uses `cuisineNames` — **empty** for a no-cuisine search — so `[].every()` is **vacuously true** and the over-constrained set is accepted.
  - The (sound) **3-month review-time refute** then trims `6 → 1`, and **nearby-widen** (distance ≤ 20 km) drops the one far-flung survivor `1 → 0` → **0 venues**.
  - `pipeline.discover` joins multiple cuisines with **` OR `** (`pipeline.js:1018`), so the **single** path would have produced `"newly opened OR 새로 오픈 cuisine restaurant"` = the broad recall Track B intended.

- **[DELTA]** (`index.js`)
  - **`isMultiCuisine = cuisineNames.length >= 2`** (real picks, `cuisineMetas`-derived at `:14172`) instead of `cuisineQueries.length`. The AND-combo's true intent is *"2+ real cuisines served together"* — modifier/language expansion must never trigger it. A bare New search now routes through the single path → `discover` **OR-joins** the seeds → broad recall; the review-refute still decides newness soundly. `comboInfo.attempted` stays false for New (no spurious *"no exact combination"* banner).
  - **`package.json`** `0.61.397 → 0.61.398`; **`doc/.serial-state.yml`** commit 610 → 611, journal 597 → 598, **build held 386** (server-only); re-anchored 16:34 SGT.
