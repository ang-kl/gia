## Amendments

### `index.js` `handleMichelinSearch` `sliceCap`

> Prior (v0.60.42–v0.60.148): `const sliceCap = Math.min(pool.length, 40);` — capped Places-API browse latency at ~10–15 s per click. v0.60.147 added the LLM narrate step on top, which pushed 40-venue calls past Telegram's ~30 s webhook ceiling → the first Michelin tap timed out.
>
> Change (v0.60.149): `Math.min(pool.length, 12)`. Matches cuisine-chip PAGE_SIZE; LLM narrate operates on 12 venues, well within Gemini's retry budget. ~11 ▶ taps walk all ~130 curated entries. The surrounding comment block (`index.js:5680-5693`) records the v0.60.42 → v0.60.147 → v0.60.149 history.

### `cuisine-session.js` `recordPage` — new `opts.skipCap`

> Prior (v0.60.146): `recordPage(redis, chatId, payload)` always SADDs the page's placeIds into `cuisine:session-seen:<chatId>` and reports `capped: true` once the SET passes the 80 cap. Michelin (v0.60.146 wiring) was subject to the same cap — operator's "navigation to list 139 of them" would have hit the 80 ceiling on Michelin.
>
> Change (v0.60.149): the helper accepts an `opts.skipCap` boolean. When true, the SADD is skipped, the page-history LPUSH still runs (so the ⇠ Prev FAB still walks Michelin pages), and `capped` is always reported as `false`. The Michelin caller (`index.js handleMichelinSearch`) passes `{ skipCap: true }`. Cuisine-chip / freetext call sites are unchanged.

### `App.jsx` terminal-note block — `sessionFull` branch

> Prior (v0.60.146): when `sessionFull === true`, the terminal copy said "Close and re-open Cuisine for a fresh session." The existing ↺ Start over button only reset the per-criteria seen-set (`resetSeenSet`) — NOT the 80-cap session SET — so it had no effect when sessionFull.
>
> Change (v0.60.149): the ↺ Start over button is replaced by a ↻ Recycle button on the sessionFull branch. ↻ Recycle calls the new `/api/cuisine/session/recycle` endpoint which wipes the session-clipboard (seen + pages + meta), then re-fires the current search → list #1 again. EN + FR copy updated. The non-sessionFull branch keeps the existing ↺ Start over behavior.
