## New

### [HDR] #839 | 18:20 SGT 03-07-26 | v0.62.485 — Michelin narrate decoupled from response | 1 code file + 3 doc/meta | PR #(pending) |

- **[INTENT].** Stop the Michelin handler timing out on cold cities and make the 🕛 clock +
  Closed corner-tab render fast and reliably, by no longer blocking the response on the slow
  Gemini dish/vibe narration.

- **Root cause (traced — ONE architectural coupling behind BOTH symptoms).**
  `handleMichelinSearch` (`index.js` ~9605) builds one **single `res.json`** response (this
  route is **not** SSE — there is no live-patch channel). Before sending, it `await`ed the
  **Gemini dish/vibe narrate** (`pipeline.narrateMichelinVenues`, ~10512, **~6–18s cold**). The
  cheap **open-hours labels** the clock needs (`openNow` / `closedTodayLabel` /
  `openClosingLabel` / `closingSoonMinutes`, computed early at ~10200) were therefore held
  hostage: when the **20s route deadline D706** (`_SEARCH_DEADLINE_MS`, ~15046) fired mid-narrate
  it answered with an **empty degraded payload** (`{ venues: [], degraded: true }`), so the whole
  card — clock included — never reached the client. A **cold city** (Seoul was never cached; the
  v0.62.484 `v2` key bump also wiped every previously-warm Michelin blob) hit this every tap;
  warm SG taps (1.4s) rendered fine.

- **[DELTA] (1 code file — `index.js`, `handleMichelinSearch`).**
  - **New deferred fn `warmMichelinEnrich(sourceReview)`** (~10515) wraps the Gemini narrate +
    the enrichment-cache **WRITE** (Step 5, moved in from ~10603). It is **fired fire-and-forget
    after** the response is computed (~10643), so it only warms the enrich cache for the **next**
    tap — it never blocks the current response.
  - The **fast path** now ships the card the moment the open-hours labels + the enrich-cache
    **READ** + the force-fill boilerplate are ready: **clock + Closed tab + cached-or-boilerplate
    dishes**, no Gemini wait.
  - **`michSourceReview` snapshot** (~10611): the pre-translate English review is captured
    **before** the `translate-enrich` step mutates `v.recentReview` into the device language, and
    passed into the deferred write — preserving the **v0.61.154** "cache the source language, not
    the translated text" invariant now that the write runs later.
  - The warm is kicked **before** the walk / `headersSent` guards, so it still warms the cache on
    a deadline-degraded (slow, cold) tap — the case that most needs warming.

- **Behaviour (honest).** COLD first tap in a new city: fast card with **real clock** +
  **boilerplate** dishes ("Chef's choice"), **no timeout**. NEXT identical tap: **real** Gemini
  dish/vibe narration from the now-warm cache. WARM tap: `needsNarrate` is empty → **zero**
  Gemini calls, cache write is a cheap refresh. On this non-SSE route, "stream dishes after"
  means "warm for the next tap", not live-patched into the sent card — the pragmatic decouple.
