# Journal — soleat v0.61.196 (TMA <-> chat country-pref sync)

> v0.61.195 added the chat-side `/lcountry` picker writing
> `country-pref:<chatId>` in Redis. The Cuisine TMA's
> `state.countryPref` was still hard-defaulting to `'MY'` (the
> v0.61.191 default) on every mount, regardless of what the user had
> picked elsewhere. v0.61.196 wires both surfaces to the same Redis
> key: TMA reads it on mount; both surfaces write it on change.
>
> Commit 409 / journal 397 / build 199, on branch
> `claude/v0.61.196-country-pref-tma-sync` off `main` at v0.61.195.

## New

### [HDR] #397 | 08:15 SGT 28-05-28 | v0.61.196 — TMA + chat country-pref sync | 3 files | 1 PR | 1 build |

- **[INTENT]** Both UI surfaces should see the same country pref.
  Today: user picks 🇲🇾 Malaysia via chat `/lcountry` → next time
  they open the Cuisine TMA, OTHER region still shows 🇲🇾 because
  state.countryPref was seeded from the v0.61.191 default `'MY'`
  (which happens to match) — but if they had picked 🇯🇵 Japan in
  chat, the TMA would have reverted to 'MY' silently. Same problem
  in reverse: TMA changes never reached chat. The fix is two
  endpoints (GET + POST) and three small TMA edits.

- **[DELTA]**

  - **`index.js`** (+2 endpoints, ~50 lines total, just before
    `/api/cuisine/copy-syntax`):
    1. **`GET /api/cuisine/country-pref`** — initData-gated via
       the `X-Telegram-Init-Data` header (mirrors
       `/api/cuisine/user-language`). Returns
       `{ countryCode }` from `getUserCountryPref(redis, userId)`.
       Rate-limited via `makeRateLimiter` at 300/h.
    2. **`POST /api/cuisine/country-pref`** — initData-gated via
       `req.body.initData` (mirrors `/api/cuisine/set-location`).
       Validates the code against `country-pref`'s ALL_CODES (17
       entries) before calling `setUserCountryPref`. Returns
       `{ ok, countryCode }`. Rate-limited at 100/h. 400 on
       unknown code; 503 if the SET fails.

  - **`web/cuisine/src/v2/lib/api.js`** (+2 helpers):
    1. **`fetchCountryPref()`** — `getJson('/api/cuisine/country-pref')`
       wrapper. Returns `{ countryCode }` on success, `null` on any
       failure (401/network blip/etc).
    2. **`saveCountryPref(code)`** — `postJson` wrapper, returns
       `null` on failure. Designed for fire-and-forget use.

  - **`web/cuisine/src/v2/App.jsx`** (3 edits):
    1. **Imports** — `fetchCountryPref` + `saveCountryPref` added
       to the existing `./lib/api.js` import line.
    2. **NEW mount-only useEffect** (just after the existing
       userLoc resolution useEffect):
       - Calls `fetchCountryPref()` on mount.
       - If response carries a `countryCode` that ISN'T `'SG'`,
         updates `state.countryPref` to it. The `'SG'` skip is
         deliberate: the `state.countryPref` slot is exclusively
         for the OTHER picker, and SG has its own region pill
         with its own anchor — pulling `'SG'` into countryPref
         would just confuse the OTHER picker's flag dropdown.
       - Network failures fall back silently to the v0.61.191
         `'MY'` default (no toast, no console error spam — the
         picker just opens on 🇲🇾).
    3. **`onCountryChange` handler** — was:
       `(code) => setState((s) => ({ ...s, countryPref: code }))`.
       Now wraps that with a `saveCountryPref(code).catch(() => {})`
       fire-and-forget after the local state update, so the chat
       picks up TMA-side changes.

  - **`package.json`** — `0.61.195 → 0.61.196`.
  - **`doc/.serial-state.yml`** — commit 408 → 409, build 198 →
    199, journal 396 → 397; re-anchored 28-05 '26 08:15 SGT.
