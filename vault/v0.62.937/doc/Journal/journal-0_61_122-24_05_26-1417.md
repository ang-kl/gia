## New

### [HDR] #323 | 14:17 SGT 24-05-26 | v0.61.122 — `/location` quick-pick keyboard (10 STB + JB + IOI Putrajaya 15 km cap) | ~10 kb | 6 files | 1 PR | 1 build |

- **[INTENT]** Add an inline-keyboard quick-pick keyboard to the
  Telegram `/location` reply: 10 STB Singapore precincts loaded from
  `geoloc/stb_key_precincts.geojson` + 2 Malaysia anchors (Johor
  Bahru with a 30 km cap, IOI Resort City Putrajaya with a 15 km
  cap). Tap → `setUserLocation` stamped with region + radiusCapM +
  label + precinctId. Backwards-compatible — existing share-pin
  keyboard and `/location <place>` paths untouched.

- **[DELTA]**
  - **`+ precincts.js`** (~150 lines, new module). Single source of
    truth for the curated quick-pick anchors:
    - Loads 10 STB precincts from `geoloc/stb_key_precincts.geojson`
      (memoised); computes each polygon's centroid as the search
      anchor and retains the polygon ring for the future
      point-in-polygon "outside the zone" filter.
    - Hardcodes 2 Malaysia anchors: Johor Bahru (1.4927, 103.7414,
      `radiusCapM: 30000`) and IOI Resort City Putrajaya (2.9742,
      101.7060, `radiusCapM: 15000`).
    - Exports: `getStbPrecincts`, `getMalaysiaAnchors`, `getAll`
      (returns 12), `getById`, `pointInPolygon`, `containingPrecinct`,
      `effectiveRadius(loc, requestedRadiusM)`.
  - **`+ __tests__/precincts.test.js`** (6 describes / 15 specs —
    loader, MY anchors, getAll order, getById, point-in-polygon,
    effectiveRadius clamping).
  - **`location-cache.js`** — `setUserLocation(redis, chatId, lat, lng, opts?)`
    now accepts an optional `opts` object with
    `{ region, radiusCapM, label, precinctId }`. All four fields are
    optional; old callers (share-pin handler, manual geocode handler,
    voice handler) pass nothing and get exactly the legacy payload
    shape `{ lat, lng, setAt }`.
  - **`index.js`**
    - `runLocationCommand` → adds a `sendLocationQuickPicks(chatId)`
      follow-up message after both the cached-location and the
      no-cache replies. The follow-up uses an inline keyboard with
      12 buttons (2 per row), `callback_data: locpick:<id>`.
    - `bot.on('callback_query')` — new `locpick:<id>` branch.
      Resolves the id via `precincts.getById`, stamps the cached
      location, replies with confirmation (`📍 Location set to
      <label>.`) + cap note for Malaysia anchors (e.g. ` Searches
      anchored here are capped to 15 km.`). Logs
      `[/location] D775 locpick id=<id> chat=<chatId> region=<region> cap=<cap>m`.
    - `runFreeTextSearch` — honours `cached.radiusCapM` when calling
      `pipeline.discover` (default SG 50 km clamps to 30 km for JB,
      15 km for IOI). Region code also flips to `'MY'` for the
      JB / MY-PUT anchors so Places returns Malaysian results.
  - **`i18n.js`** — 4 new keys (en + fr): `loc.precinct.prompt`,
    `loc.set.success`, `loc.set.capNote`, `loc.set.unknown`.
  - **`package.json`** — `0.61.121 → 0.61.122` (PATCH).
