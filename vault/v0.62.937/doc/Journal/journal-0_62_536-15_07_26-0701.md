## New

### [HDR] #892 | 07:01 SGT 15-07-26 | v0.62.536 — lib/redis-kv minimal slice | 4 files | PR #(pending) |

- **[INTENT].** Extract only the two Redis pieces that are **verbatim-identical across modules AND
  decoupled from per-caller error logging** — the connection guard and the JSON read.

- **[WHY MINIMAL].** The audit's "no shared redis helper" finding overstated the opportunity: in
  `recent-locations.js` the `setEx`/`del` calls sit **inside per-function `try/catch` blocks that also
  wrap business logic and emit module-specific warn logs** (`[recent-locations] add failed…`) — folding
  them into a wrapper would swallow those logs (a silent change). And `country-pref.js` stores a **raw
  string** (`SG`), not JSON — a JSON wrapper would rewrite `SG` → `"SG"` in Redis, breaking cached prefs.

- **[DELTA].**
  - **NEW `lib/redis-kv.js`** — `ensure(redis)` (the connection guard, mirrors `recent-locations`'s
    `_connect` exactly) + `getJSON(redis, key)` (get + `JSON.parse`; null on miss / error / invalid JSON,
    never throws).
  - `recent-locations.js` — removed the local `_connect` (5 call sites → `kv.ensure`); rewrote
    `listRecentLocations`'s get+parse+`try/catch` → `kv.getJSON` (the caller keeps its own
    `Array.isArray` shape check; behaviour-identical — `getJSON` null → `Array.isArray(null)` false →
    `[]`). The `setEx`/`del` sites are **left as raw redis calls** (they carry module-specific warns).
    Net **−12 LOC**.
  - `package.json` — 0.62.535 → **0.62.536**.
  - `doc/Journal/journal-0_62_536-15_07_26-0701.md` — this entry.
  - `doc/.serial-state.yml` — commit 1009→**1010**, build 635→**636**, journal 891→**892**; re-anchor
    15-07 '26 07:01 SGT (prior 891 anchor demoted verbatim, AU-7).

- **[NOT MIGRATED — by design].** `country-pref.js` (raw-string storage + dev-key fallback + a different
  connect style → no clean JSON-wrapper fit).
