## New

### [HDR] #470 | 21:15 SGT 29-05-29 | v0.61.269 — Menu OTHER autocomplete + endpoint deprecation log | 4 files | 1 PR | 1 build |

- **[INTENT]** Migrate the Menu TMA's OTHER form to the same JB-style autocomplete-on-keystroke flow the Cuisine TMA shipped in v0.61.267, and add a deprecation marker to the legacy `/api/cuisine/place-search-by-country` server route so the v0.61.270 deletion pass has prod-log confirmation that no caller remains.

- **[DELTA]**

  **1. `web/menu/src/api.js`** (new file)

  Extracts the raw `fetch` calls into named helpers. Mirrors the shape of `web/cuisine/src/v2/lib/api.js`:

  - `placeAutocomplete({ input, lat, lng, countryCode })` → `/api/cuisine/place-autocomplete` (server already accepts `countryCode` since v0.61.267).
  - `placeResolve({ placeId })` → `/api/cuisine/place-resolve`.
  - `_postJson(url, body)` automatically attaches `initData` from the Telegram WebApp.

  **2. `web/menu/src/components/LocationFieldMenu.jsx`** — the migration

  - **Removed**: `otherResults` / `otherSearching` / `otherNoMatch` state; `onOtherSearch` (placeSearchByCountry caller); `pickOtherResult`; `cancelOtherSearch`; the `<form onSubmit>` wrapper; the explicit 🔍 search button on the OTHER form; the 5-row confirmation panel JSX + "Cancel" footer; the v0.61.199 friendly-error path (autocomplete failures degrade silently to empty suggestions, matching the JB / cuisine OTHER behaviour).
  - **Added**: `otherSuggestions` / `otherSuggestionsQuery` / `otherLoading` state; `otherDebounceRef`; a `useEffect` keyed on `[textValue, cityPick, countryPref, busy]` that fires `placeAutocomplete` 250 ms after the last keystroke, with `lat/lng = cities.js centroid of the picked city` (falls back to `currentAnchor` coords, then `undefined`).
  - **Added**: `handlePickOther(s)` calls `placeResolve` → `postSetLocation` with resolved coords + `_safeLabel`-filtered label + `country: countryPref`.
  - **Added**: `handleKeyOther(e)` picks the top suggestion on Enter, with the same stale-debounce guard the Cuisine TMA uses (`otherSuggestionsQuery !== textValue.trim()` → no-op).
  - **JSX rewrite**: the OTHER form is now an unwrapped `<div class="relative …">` (no `<form>`), with the input's `onKeyDown={handleKeyOther}`. Suggestions render below as a popover; "no match" hint fires when `textValue.trim().length >= 2 && otherSuggestions.length === 0 && otherSuggestionsQuery === textValue.trim()` (the suggestions-query check distinguishes "no match" from "user is still typing, debounce not fired yet").
  - **Preserved**: city dropdown commits city centroid as anchor via `onCityPick` (v0.61.226 behaviour, unchanged). Country dropdown flip clears `textValue` + `suggestions` via `updateCountryPref` (v0.61.265, unchanged). All `_safeLabel` / `_isCountryOnly` guards (v0.61.265) still apply.

  **3. `index.js`** — deprecation log on `/api/cuisine/place-search-by-country`

  Added inside the route handler, after the input-length guard:

  ```js
  console.warn(`[place-search-by-country] DEPRECATED v0.61.269 — caller cc=${countryCode || '?'} input="${text.slice(0, 40)}"`);
  ```

  The route still works — no behavioural change. The warning surfaces in Railway logs so the v0.61.270 deletion PR can be guarded by a "no non-deprecated callers in ≥ 24 h" criterion.

  **4. `package.json`** — `0.61.268 → 0.61.269`.

  **5. `doc/.serial-state.yml`** — commit 481→482, build 271→272, journal 469→470; re-anchored 29-05 '26 21:15 SGT.
