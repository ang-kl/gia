## New

### [HDR] v0.62.578 — Cuisine: the location editor floats (compact card), stops pushing the map down + keeps the carousel

- **[INTENT]** Operator (IMG_0743, on deployed **v0.62.577**, landscape tablet): *"When I click
  location, it push down and all the carousel cards disappeared."* Same layering complaint as the
  folio pickers, but for the **location editor** (the region folio-tabs + `LocationField`), which was
  NOT floated in #1586.

- **[DELTA]** `web/cuisine/src/v2/App.jsx` (3 edits):
  1. **Header stays translucent when editing.** The `modePeek` state used to flip the whole sticky
     header to a **solid** `bg-tg-bg`; over the full-bleed landscape map that reads as a big black
     band "pushing down". Now the header keeps the same `bg-tg-bg/90 backdrop-blur` bar whether
     editing or not (the resting treatment that already ships).
  2. **Editor constrained to a compact card.** The editor container is now `pickerWidthCls`
     (phone-width, left-aligned) with its **own** solid surface (`bg-tg-bg rounded-2xl border`) while
     staging (`modePeek`), so it floats as a panel over the map instead of a full-width band.
  3. **Carousel stays visible.** Dropped `!regionExpanded` from the `ResultDrawer` gate so the cards
     no longer vanish while re-anchoring (editor floats at the top, cards sit at the bottom — no
     overlap). Still hidden behind a folio picker (which floats over the map centre).

- **[KNOWN GAPS] — ISSUE B (correctness), tracked for the NEXT PR.** In the same screenshot the field
  showed the **city "Brisbane"** instead of the committed street **"16 Thompson Street"**. Root cause
  (traced): there is **no coarse-over-fine guard**. The server `D787` guard
  (`location-cache.js:44-55`) is **ambient-only + label-existence-only** (keeps the existing label
  only when `opts.ambient===true` AND a chat-level label already exists; otherwise it **full-payload
  replaces**), and the only coarseness filter (`_isCountryOnly`, `LocationField.jsx:69`) is client
  **display-only and matches countries, not cities** — so "Brisbane" is never screened. The city
  label arrives via the boot auto-detect ambient write (`App.jsx:2208`, `label = anchorName` = a
  city) and/or a **non-ambient** re-push (`reassertPickAfterSearch`, `App.jsx:2373`), and the field
  visually reverts via the **unguarded** visibility-refetch (`App.jsx:1943`, `setLocationAnchor({name:
  r.label})`, not gated by `explicitPickRef`). This is the **same family** as the SG/Putrajaya
  set-location bugs (v0.61.265 country-only display filter → v0.61.430 explicit-pick-wins → v0.62.31
  D787 server ambient guard) — the next uncovered case (coarse city over finer street). Planned fix:
  upgrade `setUserLocation` to a **granularity comparator** (keep the existing label when it carries
  `street`/`building`/`postal` and the incoming label is a bare city/country, **regardless of
  `ambient`**; also check the per-device key, closing the v0.62.31 gap); generalize `COUNTRY_ONLY_RX`
  → a shared `isCoarseLabel()` incl. city-only; gate the client visibility-refetch behind
  `explicitPickRef` + coarse-vs-fine. Run `gia-preflight` (touches set-location) + add a
  `location-cache` unit test.
