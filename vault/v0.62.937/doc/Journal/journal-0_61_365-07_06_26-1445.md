## New

### [HDR] #565 | 14:45 SGT 07-06-26 | v0.61.365 — 0.3 s settle gate + persist-before-load | 1 code file | 1 PR | 1 build |

- **[INTENT]** Stop the boot venue load from firing **before** a location-mismatch modal can raise (operator's Image-1: "⏳ loading random eateries…" *under* the Location-mismatch modal), and write the resolved location to the table before auto-loading.

- **[ROOT CAUSE]** The v0.61.322 splash-gate opener fired `runInitialLoad` the instant `userLoc` resolved. But the v0.61.274 coherence check depends on **`state.countryPref`**, which loads **async** from the server. On the `userLoc`-resolved commit, `countryPref` was often still `null` → the check returned early (no modal) → the gate opened + the boot load fired → **then** `countryPref` landed, the check re-ran, and the mismatch modal popped over the already-loading body.

- **[MECHANISM]** (`web/cuisine/src/v2/App.jsx`, gate-opener effect)
  - **0.3 s settle** — a `setTimeout(…, 300)` before `setLocationGateOpen(true)`. Gives `countryPref` + the three coherence checks (declared above) a beat to raise a modal first.
  - **Re-check** — inside the timer we re-read `modalPendingRef` and **bail** if a mismatch raised during the settle (the effect re-runs when the modal is dismissed). `state.countryPref` is now in the deps, so a late load **restarts** the timer.
  - **Persist before load** — on the clean no-mismatch path we resolve the confirmed centre via `reverseGeocode` (→ actual **street + building + city**) and `saveUserLocation({lat, lng, label})` **before** `runInitialLoad`. `saveUserLocation` posts to `/api/cuisine/set-location`, which carries the v0.61.363 **device token** (per-device slot) and lets the server resolve the address. Fire-and-forget (mirrors the `apply*` paths) so the boot load is never blocked on the network.
