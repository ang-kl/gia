### [HDR] #438 | 20:35 SGT 28-05-28 | v0.61.237 — auto-fire search on cascade pick | 3 files | 1 PR | 1 build |

- **[INTENT]** A city / JB-place pick should immediately refresh the result list, the same way an SG precinct quick-pick already does — the user shouldn't need an extra 🔍 tap.

- **[DELTA]**

  **`web/cuisine/src/v2/App.jsx` — `onLocationSelect(p)`** gains an auto-fire branch:
  ```js
  if ((p.label || '').trim()) {
    Promise.resolve().then(() => runSearch(state, { lat: p.lat, lng: p.lng }));
  }
  ```
  Key detail: the new anchor is passed to `runSearch` **explicitly** (as the second arg) — `runSearch` reads `const center = anchor || searchCenter || …`, so the explicit anchor wins over any stale state. This sidesteps the v0.60.166 race that motivated removing the auto-fire originally.

  Microtask deferral (`Promise.resolve().then`) lets React commit the `setLocationAnchor` + `setSearchCenter` updates first; the explicit-anchor pattern makes that safety belt-and-braces.

  Guard on `(p.label || '').trim()` so a "× clear" call (empty label) doesn't auto-fire.
