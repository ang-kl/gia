- **[DELTA]**

  **1. `web/cuisine/src/v2/components/LocationField.jsx`** — main file (substantial)

  **#4 — JB focus-point alternates:**

  - New module-scope constant `JB_FOCUS_POINTS = { southkey, cbd }`. Southkey coords are `1.4912 N / 103.7665 E` (the operator's verbatim "Southkey"). JB CBD coords are `1.4927 N / 103.7414 E` (mirrors `index.js:12005`, the existing chat-bot JB CBD centroid).
  - New state in `LocationField`: `jbFocusKey = useState<'southkey' | 'cbd'>('southkey')`. Session-only — no Redis persistence in this PR.
  - The 🔍 button's `onClick` now branches: when `region === 'JB' && !anchorDiffers && !pickedLabel && !query.trim()`, it emits `onSelect({ lat: JB_FOCUS_POINTS[jbFocusKey].lat, lng: ..., label: JB_FOCUS_POINTS[jbFocusKey].name })` instead of the legacy `onSearch?.()`. The pick path auto-fires through `App.jsx:onLocationSelect` because the label is non-empty and `noAutoFire` is unset.
  - New chip UI rendered immediately under the compact pill when `region === 'JB' && !anchorDiffers && !pickedLabel` — two pill-shaped toggles (Southkey · JB CBD) with `aria-pressed` mirroring `jbFocusKey`. Tapping a chip updates state only; no network request. Active styling: `bg-tg-accent text-tg-bg`. Inactive: `bg-tg-card text-tg-text border-tg-border`.

  **#5 — OTHER city-clear → GPS revert:**

  - New state in `OtherLocationPicker`: `userClearedCity = useState<boolean>(false)`. Reset to `false` on every `country.code` mutation (a separate `useEffect`) so the auto-pick can re-run for the newly-selected country.
  - `CityDropdown` extended with an optional `hideClearOption` prop (default `false`). When `false`, the dropdown renders a leading "— Clear —" row that calls `onChange?.('')`.
  - `OtherLocationPicker.onCityPick` now special-cases `name === ''`: sets `cityPick=''`, `userClearedCity=true`, resets the autocomplete query/suggestions. Does NOT emit onSelect directly — the revert is handled by the next effect, idempotently.
  - The v0.61.250 auto-pick effect (`useEffect` keyed on `[country.code, anchor?.name, anchor?.lat, anchor?.lng, userClearedCity]`) now early-returns when `userClearedCity` is true.
  - **New revert-to-GPS effect** keyed on `[cityPick, userClearedCity, country.code, userLoc?.lat, userLoc?.lng]`. Fires when `(cityPick === '' && userClearedCity) || country.code === '__NONE__'` AND `userLoc` is valid. Emits `onSelect({ lat: userLoc.lat, lng: userLoc.lng, label: '', noAutoFire: true })`. The empty label + matching coords trigger the `anchorDiffers === false` path in the resting-label logic, so the pill drops back to the i18n placeholder.
  - `OtherLocationPicker` now receives `userLoc` as a prop; the parent `LocationField` passes it through at the `region === 'OTHER'` branch.

  The audit spec referenced `onLocationSelect (~lines 1456–1470)`. Inspected: the function already handles `!Number.isFinite(p?.lat)` by calling `setLocationAnchor(null)` (line 1514). Empty-label-with-coords-equal-to-userLoc resolves to `anchorDiffers === false` in `LocationField:218`, which is functionally equivalent to a revert. No mutation required.
