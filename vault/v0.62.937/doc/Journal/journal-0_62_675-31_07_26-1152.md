_(№ 1,198 — 31-07 '26 11:52 SGT)_

## New

### [HDR] v0.62.675 — the pager's total-page divisor, 12 → 9

- **[INTENT]** Operator, immediately after the v0.62.674 fix shipped (still pre-merge, PR #1678):
  *"The formula is example the count is 140 based on the criteria of Michelin Star for 2025 count
  +2026 count. 140/9 cards per page = 15 pages."* — a direct correction of the divisor used in
  `michelinTotalPages` (App.jsx :3257), which v0.62.674 had derived from `ResultPanel.jsx`'s own
  fetch-batch `PAGE_SIZE` (12), reasoning it should mirror the actual per-tap batch size.

- **[DELTA]** (`web/cuisine/src/v2/App.jsx`, one line + comment) `michelinTotalPages` denominator
  changed from `12` to `9`: `Math.ceil(michelinRemaining.total / 9)`. This is a **display-only**
  denominator — it does not change how many venues are fetched per tap (still 12, server-side,
  unchanged) or how the pager advances (`cursor` still steps through already-fetched batches per
  D-48). The numerator (`cursor + 1`) therefore counts fetched-batches-of-12 while the denominator
  now counts hypothetical pages-of-9 — a real unit mismatch between the two halves of the same
  counter, disclosed here rather than silently reconciled, since reconciling it properly (e.g.
  making the pager step through virtual 9-card pages instead of 12-card server batches) would
  reopen the D-48 architecture question the operator resolved for v0.62.673 ("'page' is
  already-fetched server batch") and was not asked for in this message.

- **[NOT YET DONE — flagged, not built]** The same operator message also asked for a **Michelin
  year sub-criterion** (2026 / 2025 / Both, default Both) so the total reflects a chosen year (or
  years) rather than always all curated entries. This is real new scope — a new visible control,
  a new request parameter, server-side filtering of the curated pool by `awardYears`, and a
  `walkHash` change so switching years resets the walk — not a one-line fix, and its UI placement
  is a genuine design decision (candidates surveyed: `QuickFilters.jsx`'s rating-pill pattern,
  `CuisineDrawer`'s Michelin sub-cuisine chip area) rather than an obvious slot. Per this session's
  standing rule (visible/structural changes get explicit per-item confirmation, not built on
  spec-guessing), this is being raised to the operator for a placement/default decision before any
  code is written, rather than assumed. Tracked as a new Open item (see Register).
