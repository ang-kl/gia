## New

### [HDR] v0.62.678 — 5-phase plan, fully executed and confirmed per-item with the operator

- **[INTENT]** Operator supplied 3 iPhone-11-Pro screenshots (Hawker/Train/Cuisine) and flagged
  the header/footer text looking small next to Cuisine's category-grid labels and free-text FAB —
  "what else is a challenge? plan first." A plan-mode research pass (3 parallel Explore agents)
  surfaced more than the one visual observation. The operator then answered every open fork
  directly across follow-up messages: *"I like Cuisine's tab labels at 11px... I feel the Cuisine
  groups should be 11px especially for iPhone 11 Pro... For Tablet phone or iPad Mini or bigger,
  12px is minimum"*; *"The card's heights in all 3 [TMA], can we have the details/less like Train
  TMA... What is the height"*; then, via AskUserQuestion, confirmed both the Hawker collapse-
  toggle addition and keeping card height content-sized (not fixed). Full plan:
  `/root/.claude/plans/typed-launching-ripple.md`.

- **[PHASE A — bug fixes, no visible change]**
  - `web/cuisine/src/v2/App.jsx` — removed the dead `text-[12px]` Tailwind utility from both folio
    tab buttons (`className`s at the "Cuisine & filters" / "Pick local classic" tabs). It never
    actually rendered: `web/cuisine/src/styles.css`'s hand-written `.folio-tab{font-size:11px}`
    sits AFTER `@tailwind utilities;` in the same compiled file, so at equal specificity it always
    won the cascade — the tabs have shown 11px the whole time despite the JSX claiming 12px.
    Operator confirmed 11px is the size to keep, so this is a source-accuracy fix (deleted the
    utility, added a comment on the CSS rule explaining why it's intentional and must not be
    "fixed" again by a future pass) — **zero pixel changes**, verified against the compiled CSS.
  - Added the missing iOS auto-zoom guard (`input, textarea, select { font-size: 16px; }`) to
    Cuisine's, Hawker's, and Transport's `styles.css` — mirroring `web/clipboard/src/styles.css`'s
    own v0.62.442 fix for the identical problem, never previously propagated. Closes a real
    usability gap on Cuisine's free-text "Tell me" input (was 14px) and the shared
    `StationLocationField.jsx` search input used by both Hawker and Transport (was 12px).

- **[PHASE B — shared type-scale vocabulary, zero visible change]** New
  `web/_shared/lib/type-tokens.js` (`typeScale`: caption 9px, meta 11px, body 12px, body-lg 13px,
  label 14px, title 16px — naming today's actual de facto sizes, not importing Material's
  numbers, deliberately narrower than Register O-89's "M3 literal type scale" question). Spread
  into `theme.extend.fontSize` in all 6 non-`about` apps' `tailwind.config.js` (cuisine, hawker,
  transport, menu, oversight, clipboard), same convention as `tgColors`/`m3Radius`. Confirmed zero
  `text-type-*` bytes in any of the 6 built CSS files before Phase C consumed the first one.

- **[PHASE D — compact-phone viewport tier]** `web/_shared/lib/classify-viewport.js` gained
  `COMPACT_MAX_WIDTH = 390` and an `isCompact` field on `classifyViewport()`'s return value — true
  only for a `'mobile'`-classed device with a short edge ≤390px (iPhone 11/12/13 Pro, 12/13 mini,
  SE), false for tablet/desktop and for larger phones (14/15/16 Pro, Pro Max). Short-edge check
  (like the existing tablet rule) so it holds in either orientation. `use-viewport.js` re-exports
  `COMPACT_MAX_WIDTH` and includes `isCompact` in its SSR fallback. 5 new tests in
  `__tests__/classify-viewport.test.js`.

- **[PHASE C — confirmed part: Cuisine category-grid responsive size]**
  `web/cuisine/src/v2/components/CuisineDrawer.jsx`'s `CategoryCard` label switches between
  `text-type-meta` (11px, compact phones) and `text-type-body` (12px, everything else — tablet/
  iPad-mini+ automatically gets ≥12px since `isCompact` is never true off the phone tier) —
  exactly the operator's stated rule. `App.jsx` passes `vp.isCompact` down (reusing the
  `useViewport()` call already at the top of `App`, no new subscription). Header-title
  reconciliation and the 12/13/14px primary-card-name-size unification (also part of Phase C in
  the plan) are **NOT done this entry** — those still need a presented option-list decision round,
  per the plan's explicit posture (mirrors the still-open O-88 round).

- **[PHASE E — Hawker card collapse/expand parity, operator-confirmed]**
  `web/hawker/src/App.jsx`'s `renderCentreCard` gained the same two-way disclosure Cuisine
  (`card.detailsMore`/`detailsLess`) and Train (`mrt.detailsMore`/`detailsLess`) already have.
  Collapsed: name + address + stall-count/status (unchanged, always shown). A new
  `expandedCards` Set (keyed by centre name, independent per-card — unlike the existing single-
  value `activePill`) plus a "⌄ details" / "⌃ less" toggle (`btn.detailsMore`/`btn.detailsLess`,
  8 locales) now gates the Bib Gourmand stall links, MRT/bus-stop chips, and the Maps/Copy pills.
  Content-sized height in both states — confirmed with the operator, not reinstating Train's old
  fixed 14rem height (explicitly removed at v0.62.646 in favour of content-sizing "like Cuisine
  and Hawker").

- **[VERIFICATION (sandbox)]** `node --check` on touched `.js`; `npx vite build` for all 6 apps —
  green; grepped every compiled CSS output (not just source) to confirm: `.folio-tab` still 11px,
  the new `input,textarea,select{font-size:16px}` rule present in cuisine/hawker/transport,
  `text-type-*` classes emit ZERO bytes in Phase B alone and exactly the two consumed ones
  (`.text-type-meta`, `.text-type-body`) after Phase C. Full `npm test` **3847/3847 across 152
  files** (5 new — the `isCompact` classifier tests).
