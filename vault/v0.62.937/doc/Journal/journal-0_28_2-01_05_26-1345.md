- **[DELTA]**
  - **`sync-vault.js`** — refactored to expose a callable. The main() CLI entrypoint preserved; module now also exports:
    - `runSync({redis, items?, fenceDisabled?})` — accepts a *connected* Redis client (so we don't open a second connection alongside the bot's). Returns `{imported, skippedClosed, fenced, failed, vaultCount, samples, durationMs, fenceDisabled, inputCount}`. `samples` carries the first 5 imported display-names so the route response previews what landed without dumping the full list.
    - `resolveInputs()` — file-system input resolver (data/Saved Places.json, data/My Maps/*.kmz, fallback to HARDCODED_URLS).
    - `HARDCODED_URLS` — the 14-URL fallback list.
    - CLI-vs-required guard at EOF (`if (require.main === module)`) so requiring the module from the route doesn't auto-run main().
    - Behaviour preserved: `requireEnv('GOOGLE_MAPS_API_KEY')` runs in main() but `runSync` validates it inline so a missing env throws cleanly to the route's catch.
  - **`index.js`** —
    - + `GET /admin/sync-vault?secret=<ADMIN_SYNC_SECRET>` — auth-gated, server-side import.
    - Auth: timing-safe compare (`crypto.timingSafeEqual`) on the secret query param against `process.env.ADMIN_SYNC_SECRET`. Missing env → 503 with hint to set it. Wrong secret → 401.
    - On success: invokes `runSync({redis, fenceDisabled: req.query.fence === 'off'})`, then `vaultIndex.refreshIndex(redis)` so the in-memory snapshot picks up the new venues immediately (no 5-min cron wait). Returns `{ok: true, ...summary}` JSON.
    - Logs `[Admin] /admin/sync-vault triggered by IP=<ip>` on entry, `[Admin] sync-vault complete: <json>` on success, `[Admin] sync-vault failed: <msg>` on error.
- **[VERIFICATION (sandbox)]**
  ```
  node --check on index.js, sync-vault.js → OK
  node -e "require('./sync-vault')"  → exports {runSync, resolveInputs, HARDCODED_URLS}, 14 URLs ✓
  ```
  Live import requires production Redis + Maps key; verified post-deploy by the Human Lead.
- **[STATUS]** PROD — auto-deploys with the next Railway build.

  4. Tail Railway logs concurrently to see per-venue `[Sync]  <name> (<placeId>)` lines.

- **[KNOWN GAPS]**
  - Endpoint is rate-limit-free and synchronous — a long import (e.g. 200 venues with the future Tranche-B dataset) ties up an Express worker for ~1 min. For the current 14-URL fallback this is fine (~10 s end-to-end). If we ever expand, refactor to background-job pattern.
  - Endpoint accepts `?fence=off` to disable the Singapore-fence (mirrors the CLI `--no-fence` flag). Honest documentation: the fence is a safety net to drop accidental out-of-SG entries; don't disable unless you know you're importing non-SG venues deliberately.
  - The sync-vault main() CLI path is unchanged — `node sync-vault.js` still works for local testing.
  - `vault-index.refreshIndex(redis)` runs after sync so `pipeline.reason()` sees new venues immediately. The 5-min cron continues to refresh from any other writes.
