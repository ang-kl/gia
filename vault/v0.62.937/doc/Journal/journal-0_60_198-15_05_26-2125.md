Reproduction in `log/Depoly_2053_15-May.MD`: five Michelin chip taps inside 17 s, all five returning the identical 12 starred venues. v0.60.195 dropped pagination on the explicit "Both" answer to my scoping question; in practice the operator wants the **next** 12 on subsequent taps, not the same 12 again. - **[DELTA]**

  **`michelin-walk.js`** (new, 87 LOC):
  - `computeCriteriaHash({ otherCuisineSlugs, filters, prices, radius, isJB, freeText })` — SHA-256 over a normalised object (sorted arrays, dropped falsy filter flags, case-folded free-text). Combos and quick-filter toggles each change the hash and trigger a reset on the next read.
  - `readWalkState(redis, chatId, currentHash)` — returns `{ seen: Set, reset: boolean }`. Wipes both Redis keys when the stored hash differs from `currentHash`, or when `lastSeenAt` is older than `TTL_SECONDS` (1h). `reset:true` ONLY when a prior walk was actually wiped (first-ever taps return `reset:false`).
  - `recordWalk(redis, chatId, currentHash, newSlugs)` — `SADD` the served slugs, refresh both keys' TTL, stamp `lastSeenAt`. Best-effort: any error swallowed; next tap resumes from the last successful state.
  - Redis keys: `michelin:walk:seen:<chatId>` (SET) + `michelin:walk:meta:<chatId>` (HASH `{ hash, lastSeenAt }`), both 1h TTL.

  **`index.js`** — `handleMichelinSearch`:
  - Imported `michelinWalk` at the top of the handler (line ~6066) alongside the existing `michelin-2025` import.
  - Pulled `req.body?.prices` into `requestedPricesForWalk` early so it can feed the hash (price-tier toggles now reset the walk correctly).
  - Replaced the static `slice(0, 12)` (line ~6175) with:
    ```js
    const ordered = [...stars, ...bib];
    const walkHash = michelinWalk.computeCriteriaHash({...});
    const walkState = await michelinWalk.readWalkState(redis, csChatId, walkHash);
    const unseen = walkState.seen.size ? ordered.filter((e) => !walkState.seen.has(e.slug)) : ordered;
    const sliceCap = Math.min(unseen.length, 12);
    const slice = unseen.slice(0, sliceCap);
    ```
  - After Places resolution, before the response: `michelinWalk.recordWalk(redis, csChatId, walkHash, newSlugs)` appends the just-served slugs.
  - `exhausted` now triggers when (a) Places resolved < 3 venues (legacy v0.60.195 condition) OR (b) `seen.size + newSlugs.length >= ordered.length` (operator's "all N shown" end-state).
  - VLOG payload extended: `mode: walkState.reset ? 'walk-reset' : 'walk-continue'`, plus `walkSeenBefore`, `walkServedNow`, `walkTotal`, `walkHash`. The stale `mode: 'top12-fresh'` console log strings (line ~6075, ~6547) updated to expose `walkSeen` / `walkReset` instead.
