### [HDR] #88 | 04:30:00 SGT 02-05-26 | v0.43.0 | n/a kb | n/a lines

- **[INTENT]** Finish v0.42.0's deferred items: pino sweep across the remaining LLM-touching files, remove the `makeFlashFallback` dead-code factory (no live callers since v0.40.0), and add portable cron via GitHub Actions for vault sync + NEA hawker scrape (replaces the operator-must-remember `/admin/*` curl pattern).

- **[DESIGN]**

  1. **Pino sweep across 9 LLM-touching files** (36 `console.*` calls converted to structured `logger.*` payloads):
     - `pipeline.js` — 13 sites including the GEOSPATIAL_CULINARY_ANALYST diag-trace `[Cuisine-Diag]` line that fires for every D-code.
     - `surprise.js` — 4 sites: enrich failure, place-details failure, soft-fallback notice, refine failure.
     - `prompt-builder.js` — 1 site: Stage A failure → fallback prompt.
     - `nl-intent.js` — 4 sites: cache HIT/read-failed/classified/classify-failed.
     - `gatekeeper.js` — 1 site: Haiku 4.5 classify failure.
     - `vibe-suggest.js` — 5 sites: LLM call failed, review screen, validation, ranking, geocode.
     - `vibe-summary.js` — 2 sites: place details, LLM call.
     - `consultant.js` — 3 sites: searchNearby, reviews fetch, sanctuary read.
     - `heritage-significance.js` — 3 sites: cache read/write, LLM call.
     - All converted to `logger.{info,warn,error}({ context }, 'human-readable label')` so each line in Railway logs is now JSON-shaped with a structured payload. Once the operator searches `"reqId":"<id>"` they get every log line for that request in time order across stages.

  2. **Removed `makeFlashFallback` dead code** from `gemini-retry.js`:
     - The no-op factory was retained in v0.40.0 as a backward-compatibility shim. After the v0.40.x sweep no caller passes it any more.
     - Removed function + comment + export. `withRetry`'s `fallbackFn` parameter remains in the signature so any future code that genuinely needs a per-call fallback can pass one.
     - Updated `__tests__/gemini-retry.test.js` to assert the new export shape (`['isRetryable', 'withRetry']`).

  3. **`.github/workflows/cron.yml`** — portable scheduled admin tasks:
     - `sync-vault` job: daily at 03:00 SGT (19:00 UTC). Hits `${BOT_BASE_URL}/admin/sync-vault?secret=${ADMIN_SYNC_SECRET}`.
     - `scrape-nea-hawker` job: daily at 05:00 SGT (21:00 UTC). Hits `${BOT_BASE_URL}/admin/scrape-hawker?secret=${ADMIN_SYNC_SECRET}`.
     - Both jobs soft-fail (`|| true`) so a transient bot outage doesn't fail the workflow.
     - `workflow_dispatch` trigger lets the operator run jobs on-demand from the Actions UI.
     - Required GitHub secrets: `BOT_BASE_URL` (e.g. `https://gia4lunch-production.up.railway.app`) and `ADMIN_SYNC_SECRET`. If unset, jobs print a skip message and exit 0.
