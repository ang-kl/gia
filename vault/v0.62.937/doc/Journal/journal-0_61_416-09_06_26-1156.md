- **[INTENT]** A durian search in **Brunei** (and any belt country with sparse / oddly-typed listings) returns **0** — even though BN is in the belt. When the strict durian/durian-pastry search finds nothing, **retry with generic terms + a relaxed filter**. Applies to **all seven** belt countries.

- **[ROOT CAUSE]** (from a 3-agent read-only investigation) It's **recall + over-strict filtering**, not the belt gate. BN gets **English-only seeds** (not in `LOCAL_SEED_LANG_BY_CC`), and the post-filter's **accept-type gate** + **strict-name gate** (`_nameHasDurian`) reject the few candidates. The only existing fallback (radius-widen) **explicitly refuses to loosen the filter**.

- **[DELTA]** (server-only)
  - **`special-mode.js`** — `isRelevant(venue, mode, opts)` + `filterByMode(venues, mode, opts)` gain **`opts.relax`**. Relax **skips** the accept-type hard-reject + the strict-name gate, and matches a durian keyword over the **full haystack** (name/area/address/type/review/summary) — but **still requires a durian word** (the name-reject + keyword check stay), so no random food slips in.
  - **`index.js`** `/api/cuisine/search` special-mode block — **after** the strict filter + widen + name-dedup, when `specialMode ∈ {durian, durian-pastry}` **and** `venues.length === 0`, re-run `pipeline.discover` **once** with a bare generic query (`['durian']` / `['durian dessert','durian pastry']`) at `min(2× radius, anchorCap || 30 km)`, `passesVenueFilter`, then `filterByMode(…, { relax: true })` + chain name-dedup. Sets `specialModeRelaxed`. **Fires only on 0** → no regression for working searches. **Fruits excluded** (global + already broad).
  - `payload.specialModeRelaxed` surfaced next to `specialModeWidened`.
