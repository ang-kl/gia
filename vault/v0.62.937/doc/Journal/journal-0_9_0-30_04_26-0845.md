## New

### [HDR] #13 | 08:45:00 SGT 30-04-26 | v0.9.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead Architectural Spec: build a Verified Data Migration to a Redis Vault, then refactor `/eat` and `/drink` to consult the Vault first before falling through to the broad pipeline.
- **[DELTA]**
  - **`vault.js`** (new) — runtime Vault. `queryVault` does `GEOSEARCH FROMLONLAT BYRADIUS m ASC WITHCOORD WITHDIST` + per-hit `HGETALL`. `verifyOpenNow(placeId)` does Place Details with FieldMask `currentOpeningHours.openNow,businessStatus,googleMapsUri,rating`. `fetchOpenVaultPicks(redis, lat, lng, radius=300, count=3)` orchestrates query → verify → drop closed → drop non-OPERATIONAL → return up to `count`.
  - **`sync-vault.js`** (new) — one-shot importer. 14 Google Maps short URLs hardcoded. Concurrency 5 via hand-rolled semaphore (no `p-limit` dep added). Exponential backoff on 429/503/ETIMEDOUT (max 3 retries, 1s/2s/4s). Per URL: follow redirect → parse `/maps/place/<name>/@<lat>,<lng>` → `places:searchText` → Place Details with the spec's exact mask → operational gate → `GEOADD gia:vault` + `HSET gia:place:<id>`. Skips logged to `gia:vault:cleanup` Redis list AND console.
  - **`index.js`** — `runFlow` Vault-first decision tree. `/eat` and `/drink`: query Vault, if ≥3 open hits deliver them; else fall through to existing `pickValidated`. `/groceries` skips Vault (corpus is food/drink-oriented). On Vault query exception, logs `[Vault] runtime query failed; falling through` and continues to `pickValidated` — no silent breakage.
  - **`package.json`** — version → 0.9.0.
- **[RISK]** Med —
  - **Sync prerequisite.** Vault is empty until Human Lead runs `node sync-vault.js`. Until then `runFlow` Vault-check returns 0 hits and falls through to v0.8.1 fail-fast pipeline. **No regression** during the gap.
  - **Place Details cost.** Per-hit verify is the spec'd contract. At Vault size 14 and 300 m radius in CBD, expected hits are 0–3 per query. ~$0.05 per `/eat` when Vault saturates.
  - **Short URL parsing.** Google's `maps.app.goo.gl` short URLs occasionally redirect to non-`/place/` URLs (e.g. `/search/`). The parser tries `/place/` first then `/search/` (no coords); fallback `searchText` still resolves with name+Singapore bias. If a URL lands somewhere truly different, it's logged to `gia:vault:cleanup` with `unparsable_long_url`.
  - **Concurrency 5 + retry on 429.** Conservative; should not overrun any Google quota.
- **[STATUS]** PROD code — auto-deploys with the next Railway build. Vault contents EMPTY until sync is run.
- **[TEST]**

  - Integration (Human Lead): run `railway run node sync-vault.js` (or local with .env). Expect console summary: imported / skipped / failed counts + final `vault size now: N`.
  - Integration: send `/eat` from a CBD location near one of the imported venues. Bot should reply with up to 3 vault picks; otherwise fall through to broad pipeline.
