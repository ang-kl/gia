## New

### [HDR] #69 | 17:45:00 SGT 01-05-26 | v0.31.1 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead "Remove /grocery /drinks /log /very from the menu, instead Hide these command. '/Transport' can have sub-menu like train, bus, taxi/PHD, drive. Can also sub-sub like bus stop around me, when are they arriving, crowd and also route". Two-strand menu hygiene patch: shrink the slash autocomplete to the seven commands a casual user actually wants, and break `/transport` from a "kitchen-sink dump" into a navigable mode-first sub-menu so each reply only carries the signal the user asked for.
- **[DESIGN]**
  1. **Hide-but-don't-break** the four trimmed commands (`/log`, `/drink`, `/grocery`, `/ver`). Same pattern as v0.25.1 `/eat`: drop their rows from `setMyCommands`, leave the `bot.onText` handlers untouched. Reasoning: `/drink` and `/grocery` are subsumed by `/cuisine` (cuisine catalogue covers both food + drink + grocery surfaces); `/log` and `/ver` are diagnostic-only and most users will never need them.
  2. **`/transport` becomes a router, not a dump.** First reply is a 2×2 inline keyboard:
     ```
     [🚇 Train] [🚌 Bus]
     [🚖 Taxi/PHD] [🚗 Drive]
     ```
     Each tap renders a focused panel (≤25 lines) plus an `⬅️ Back` button. Train shows MRT status + network crowd + nearest 3 stations. Drive shows nearest 5 traffic incidents + Google Maps driving deep link. Taxi/PHD shows nearest 3 traffic incidents + Grab/Gojek/CDG-Zig/TADA deep links (no SG aggregator API exists, so the surface is link-out only).
  3. **Bus has its own sub-sub-menu** to honour the user's "sub-sub like bus stop around me, when are they arriving, crowd and also route" line:
     ```
     [🚏 Nearest stops]    [⏱ Arrivals]
     [👥 Crowd / load]     [🗺 Plan a route]
     [⬅️ Back]
     ```
     - **Nearest stops** — `transport.nearestStops(redis, lat, lng, 800, 5)`, listing description + road + distance + stop code.
     - **Arrivals** — `transport.busArrivals(stop.code)` for the nearest 3 stops; up to 4 services per stop with `next` minutes + load label + `next2` minutes when present.
     - **Crowd / load** — aggregates `Load` field across all `next` arrivals at the nearest 3 stops into a Seats / Standing / Limited Standing summary. SG's only live bus-load signal lives inside `BusArrivalv2`; this surfaces it as a standalone view rather than burying it inside the Arrivals listing.
     - **Plan a route** — `https://www.google.com/maps/dir/?api=1&origin=<lat>,<lng>&travelmode=transit` deep link from the saved location. Telegram opens the user's installed Google Maps; they type the destination there. Avoids re-implementing transit routing on our side.

- **[KNOWN GAPS]**
  - Taxi/PHD has no live ETA/surge — SG's PHD operators don't expose a public aggregator API. Surface is intentionally link-out only.
  - Bus "Plan a route" deep link requires the user to type the destination inside Google Maps; we don't accept it inline. A future patch could add a `📍 Type destination` text-prompt flow.
  - Bus crowd aggregation samples only the next-arriving service per route; it doesn't weight by service frequency. Good enough as a quick-glance signal.
  - The legacy `refresh:transport` callback is preserved for any existing chat history that still has the v0.20.0 button, but new messages no longer surface it.
