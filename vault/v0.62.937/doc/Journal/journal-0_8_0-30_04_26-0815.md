## New

### [HDR] #11 | 08:15:00 SGT 30-04-26 | v0.8.0 | n/a kb | n/a lines
- **[INTENT]** Closes Register Open #15. Human Lead confirmed the "Decision Matrix" question was Distance Matrix and instructed "Ship distance matrix". Picks now ranked by actual walking minutes, not Gemini suggestion order or straight-line proximity.
- **[DELTA]**
  - **`vibe-suggest.js`** — new `rankByWalkingTime(userLat, userLng, venues)` calls Google Routes API `distanceMatrix/v2:computeRouteMatrix` with travel mode `WALK`. Parses `duration` ("`<seconds>s`") into `walkSeconds` / `walkMinutes`, `distanceMeters` into `walkMeters`. Returns venues sorted ascending by `walkSeconds`. Failures return the input unchanged (no regression). `pickValidated` invokes the ranker on the final slice before returning.
  - **`index.js`** — `deliverPicks` header now appends `· {walkMinutes} min walk` per row.
  - **`package.json`** — version → 0.8.0.
- **[RISK]** Low–Medium —
  - **Cost.** Routes API ~$0.015 per `/eat /drink /groceries`. At single-user scale negligible; documented in Technical for monitoring.
  - **Failure modes.** Routes API timeout / 4xx / 5xx all caught and silenced; venues render in pre-rank order without walk-minute annotation. The header just omits `· X min walk`.
  - **Sandbox impossible to live-test** — Routes API is blocked. Code is shape-correct vs Google docs and uses the same axios pattern as Places.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]** Manual:

  3. Type a place name like "Marina Bay Sands" → picks centred there with walking-minute rank from MBS as origin.
  4. Tap ⛔ Raffles default → picks centred at Raffles Place with walk minutes from there.
  5. If `GOOGLE_MAPS_API_KEY` is ever rotated/restricted again → picks still render (without walk minutes); look for `[Vibe-Suggest] rankByWalkingTime failed` in logs.
