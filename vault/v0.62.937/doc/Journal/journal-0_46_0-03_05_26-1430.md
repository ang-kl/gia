## New

### [HDR] #94 | 14:30:00 SGT 03-05-26 | v0.46.0 | n/a kb | n/a lines

- **[INTENT]** Apply the v0.41.0 inversion pattern (Google Places-first discovery, Claude as ranker/narrator) to `/eat`, `/drink`, `/groceries`, and the chat-NL flow. v0.41.0 only inverted `/cuisine` (the TMA path). All four chat-side discovery commands remained on the legacy hallucinate-then-validate pipeline — the same one that caused the empty-result reports for `/eat` from non-CBD anchors.
- The Human Lead's report from minutes ago: *"Gia couldn't find a lunch sanctuary within 200m of you right now."* That message comes from `runFlow → pickValidated → geminiCandidates → validateWithPlaces` returning empty when Claude hallucinated 5 venue names that didn't validate. Same failure class as Pasir-Panjang `/cuisine` pre-v0.41.0.

- **[DESIGN]**

  1. **NEW `pickValidatedInverted(lat, lng, count, opts, meal)`** in `vibe-suggest.js`:
     - Calls `pipeline.discover()` (Places-first; from v0.41.0) with category-specific cuisine inputs:
       - `food` → empty cuisines → `searchNearby` with `[restaurant, cafe, bar, meal_takeaway, food_court, bakery]`
       - `drink` → cuisines `['bar', 'coffee', 'tea', 'cocktail']` → `searchText`
       - `groceries` → cuisines `['supermarket', 'grocery store']` → `searchText`
       - `cuisine` → cuisines `[opts.cuisineType]` → `searchText`
     - Then calls `pipeline.rankAndNarrate()` (also from v0.41.0) to pick top N + add vibe/dishes/cost narration.
     - Then `rankByWalkingTime` for the walking-distance enrichment expected downstream.
     - Returns the same `{meal, venues, activeRadius}` shape as the legacy path.
     - Radial expansion: 500m → 1000m → 2000m. The legacy 200m starting radius was the actual bug — unrealistic outside CBD lunchtime hubs. 500m is still "near you" but wide enough that most SG anchors return ≥1 venue.

  2. **`pickValidated` dispatch**:
     - When `process.env.EAT_INVERSION_ENABLED !== 'false'` (default ON), tries the inverted path first.
     - On non-empty result, returns immediately.
     - On empty (extremely rare — would mean Places API returned 0 at 2km radius for the category), falls through to the legacy hallucinate-then-validate path. This preserves the v0.45.x consultant / hidden-sanctuary fallback safety net in `runFlow`.
     - `EAT_INVERSION_ENABLED=false` in Railway env reverts to v0.45.x behaviour byte-for-byte.

  3. **No changes needed to `runFlow` in index.js**:
     - `pickValidated` keeps its return shape unchanged.
     - The vault-first short-circuit (lines 578-589) still runs for `/eat` and `/drink` — vault venues remain authoritative when present.
     - The Hidden Sanctuary fallback at line 599 still runs after `pickValidated` returns empty.

  4. **No changes needed to chat-NL flow (`runNLFlow`)**:
     - That flow goes through `runFlow` → `pickValidated` too, so the inversion automatically applies to NL searches like *"halal food near me"*.

  5. **New diagnostic codes** (added to pipeline-task already; carry through to `/eat` paths automatically):
     - `D710` discover Places start
     - `D711` discover Places ok (n_candidates)
     - `D720` rankAndNarrate Claude start
     - `D721` rankAndNarrate Claude ok (n_picked)
     - Existing `D612` reason gemini fail / etc. remain for legacy path.

- **[REUSED]**
  - `pipeline.discover()` and `pipeline.rankAndNarrate()` — identical functions used by `/cuisine` since v0.41.0. No new code in `pipeline.js`.
  - `rankByWalkingTime` — same walking-distance enrichment used by all venue-card paths.
