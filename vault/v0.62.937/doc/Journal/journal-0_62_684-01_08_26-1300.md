# Journal — v0.62.684 (carousel card spec: one width rule, two height tiers)

_(№ 1,027 — 01-08 '26 13:00 SGT)_

## New

### [HDR] v0.62.684 — the Cuisine carousel card standardised to an approved spec

- **[INTENT]** Operator, from iPad mini portrait/landscape screenshots: *"the portrait mode carrousel
  card is longer than landscape mode. can we standardize based on iPhone width"*, then, after being
  shown the measured table: *"iPhone portrait 15 Pro 278px / iPhone landscape 15 Pro 320px … For
  iPhone 11 Pro: portrait 265px / landscape 320px. All cards height should be uniform … I don't like
  'truncate' effect on Dish-hint italic, Address / area. Address / area - can abbreviate the country
  and state … we will use ▸ (U+25B8) and ▾ (U+25BE)."* Approved after a written spec + summary:
  *"Approve to build."*

- **[DIAGNOSIS — measured, not eyeballed]** Card width is `basis-%` of a track whose content box is
  `(min(viewport,1600) − 8) × 0.88`. The `%` came from a six-rung viewport-width ladder
  (`App.jsx:191`, since v0.62.652), which produced **265 → 609px** across configs and was
  **non-monotonic**: iPad mini portrait (744px) falls 24px under Tailwind's `md` (768px) so it
  inherited the phone's 82% → **531px**, while the same device in landscape took the 44% rung →
  **436px**. That inversion is exactly the operator's report. Phone landscape was worse still at
  **609px** (82% of an 844px track) — wider than the case reported, and previously unnoticed.

- **[WIDTH — one rule]** `basis-[min(82%,20rem)]` replaces the whole ladder. Reproduces the
  operator's stated de facto exactly: phone portraits stay under the cap on their own arithmetic
  (265px @375, 278px @393), every wider surface pins to **320px**. Verified against all 12
  device×orientation configs by computation.

- **[HEIGHT — two tiers, not one]** A single global height is arithmetically impossible: phone
  landscape has 375–393px of viewport TOTAL, iPad mini portrait has 1133. So:
  - **standard `h-[13rem]` (208px)** — phone portrait, all tablet, desktop
  - **short `h-[7.5rem]` (120px)** — new `isShort` flag, viewport height ≤ 500px (phone landscape)
  Collapsed only; `overflow-hidden` makes the height a guarantee rather than a suggestion. EXPANDED
  stays auto-height under the wrapper's `max-h-[60vh]` + scroll — pinning it would clip real content.
  *Deviation from the approved spec, disclosed:* the short tier is **7.5rem, not the 7rem quoted**,
  so a Michelin venue's strip (+18px) still fits without pushing the address out.

- **[`isShort` keys off HEIGHT, deliberately not orientation]** Added to the shared
  `classify-viewport.js` (+`SHORT_MAX_HEIGHT = 500`). Orientation is a *bad* proxy here and the table
  proves it: an iPad mini in landscape is still 744px tall and needs the full card, while a phone in
  landscape has 375px and cannot host one. 500 sits in the gap between the tallest phone-landscape
  height (430) and the shortest tablet-landscape height (744). This is the narrow, height-keyed
  version of the orientation branching I argued against earlier in the session — the earlier argument
  (that orientation is the wrong variable for *width*) still stands and is unchanged.

- **[TRUNCATION removed on the two rows the operator named]** Dish-hint and Address go
  `truncate` → `line-clamp-2` on the standard tier. On the short tier the dish-hint, price/♿/🐾/
  liveness row and Michelin-category row move behind the toggle, and meta/address clamp to 1 line —
  a space-forced exception carried in the approved spec.

- **[ADDRESS abbreviation]** New shared `abbrev-address.js`: drops a trailing postal code, and
  abbreviates a spelled-out state/province/prefecture (AU/MY/NZ tables). Country was **already**
  handled by ResultCard's own `dropCountry()` and is not duplicated. Honest scope note carried in
  the module header: Places usually returns states pre-abbreviated, so the postcode rule does most
  of the work — **the `line-clamp-2` is what actually stops the truncation**, the abbreviation just
  makes one line the common case. The postcode regex is anchored to the string end specifically so a
  STREET number can never be eaten (`495/497 Wellington St` — regression-tested).

- **[GLYPHS ▸ / ▾]** Replaced `⌄`/`⌃`. The glyph was baked into the i18n VALUES across 8 locales
  (16 strings, free to drift); it is now rendered once in `ResultCard` and stripped from all 16
  strings, `aria-hidden` so the accessible name stays the words alone.

- **[VERIFICATION (sandbox)]** All five TMA builds green (cuisine/hawker/transport/menu/oversight —
  `_shared` changed, so all consumers rebuilt). Full `npm test -- --run`: **154 files, 3875 tests**
  green, up from 153/3856 — 19 new across `abbrev-address.test.js` (13) and `classify-viewport.test.js`
  (6). Compiled CSS grepped for every new arbitrary utility — `.basis-[min(82%,20rem)]`, `.h-[13rem]`,
  `.h-[7.5rem]`, `.line-clamp-1` all confirmed EMITTED, the D-22…D-28 silent-drop failure mode this
  repo has been bitten by repeatedly.

- **[TIME ANCHOR]** Sovereign fetch, `api.data.gov.sg/v1/environment/air-temperature`:
  `items[0].timestamp = 2026-08-01T13:00:00+08:00` = **01-08 '26 13:00 SGT** (TF-6/TF-9).

- **[STATUS]** PR pending.

- **[TEST]** Device plan: (1) iPad mini portrait AND landscape — card should now be the same width
  (320px) in both, ending the inversion; (2) iPhone landscape — card should be 320px and SHORT
  (5 rows), leaving the map visible; (3) confirm the address no longer ends in "…" on the standard
  tier; (4) confirm ▸ flips to ▾ on expand.

- **[KNOWN GAPS]**
  - **This reverses v0.62.577**, which removed a `max-w-[22rem]` cap because it gave *"more, flatter
    cards instead of a prominent centre + two glass half-peeks."* At 320px an iPad mini in landscape
    now shows ~3.0 cards where the 44% rung showed ~2.3. Disclosed twice before approval and
    accepted; recorded here as the deliberate cost of one uniform width.
  - **Every height number is arithmetic, not measurement** — row heights derived from font sizes and
    leading, with no render harness to confirm (O-93). 13rem/7.5rem will likely need one tuning pass
    on a real device.
  - One case still overflows 13rem by ~22px: a Michelin venue ALSO matched by free text (Michelin
    strip + category + dish-hint together). `overflow-hidden` clips it rather than breaking the grid;
    dropping the dish-hint in that combination is the follow-up if it shows up in practice.
