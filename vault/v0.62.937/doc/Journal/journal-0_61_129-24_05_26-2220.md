### [HDR] #330 | 22:20 SGT 24-05-26 | v0.61.129 — Cuisine TMA Tell-me place anchor (O-20) + Fruits/Durian radius widening (O-23) | 4 files | 1 PR | 1 build |

- **[INTENT]**
  - **O-20** — wire place-anchor detection into the Cuisine TMA
    Tell-me box so typing *"ramen in Tiong Bahru"* (or just *"Tiong
    Bahru"*) pivots the search centre to that place, tightens the
    radius to a sensible neighbourhood pool, and strips the matched
    place span from the freeText so downstream cuisine-query
    construction sees just *"ramen"*. The chat free-text `/s` path
    has done this since v0.61.119 (via `place-detector.detectPlaceName`);
    the TMA box was the only surface still missing it (per the
    v0.61.124 Register Open Item O-20).
  - **O-23** — when Fruits/Durian special-mode searches return fewer
    than the spec target (8 mode-filtered venues), widen the search
    radius progressively (2x then 3x the initial radius) rather than
    just surfacing the existing *"Limited matches nearby"* amber
    card. Per `scripts/Create_2_buttons.MD` "Fallback behaviour":
    "If fewer than the target number of results are found, widen
    the search radius progressively. Do not weaken the semantic
    intent." (v0.61.127 Register O-23).

- **[DELTA]**
  - **`index.js`** — `/api/cuisine/search` handler:
      - `ftRawIn` is now `let` (O-20 mutates it post-strip);
        `ftRawOriginal` captures the pre-strip text for telemetry.
      - `searchCenter` is now `let` (O-20 may pivot it to the
        detected place).
      - `anchorCap` is lifted out of the radius-clamp try block as
        a handler-scope `let` so O-23's widening pass can reuse it
        without re-reading user-location from Redis.
      - **O-20 place-detection block** (~30 lines, after the
        anchor-cap clamp + before the cv/Michelin branch): runs
        only when `ftRawIn && !isJB && ftRawIn.length >= 3`. Parses
        `<query> in/near/around/at <place>` pattern via a single
        regex; falls back to treating the whole text as a place
        candidate. Calls `place-detector.detectPlaceName(candidate)`.
        On hit: pivots `searchCenter` to `{lat,lng}`, sets
        `searchRadius = min(NEARBY_RADIUS_M=1500m, anchorCap)`,
        replaces `ftRawIn` with the query remainder, and stores
        `detectedPlaceAnchor = { name, kind, lat, lng, source }`.
        Surfaced in the response as `payload.placeAnchor`
        (+ `placeAnchorQueryRemainder`). Skipped for JB since
        place-detector data is SG-only.
      - **O-23 widening block** (~45 lines, after the special-mode
        post-filter + before the cuisine-name validation gate):
        runs only when `specialMode && venues.length < 8`. Tries
        `[startRadius*2, startRadius*3]` deduped + capped at
        `min(anchorCap, 30000)`. Each pass: `Promise.all`
        per-seed `pipeline.discover` at the wider radius, dedup
        against `placeIds` already in `venues`, run
        `venueFilters.passesVenueFilter`, then
        `sm.filterByMode(specialMode)`, then merge until count
        hits 8 or radius hits the cap. `searchRadius` is NOT
        mutated downstream (preserves cache keys, dedup-slice
        re-tap logic); the widened-from / widened-to metres are
        surfaced as `payload.specialModeWidened` +
        `specialModeWidenedFromM` + `specialModeFinalRadiusM`.
      - Two `const ftRaw = String(req.body?.freeText…)` shadow
        declarations (misrep-dish + cooking-method probes) folded
        into the outer `ftRawIn` so the post-strip text flows
        through (e.g. typing *"katong laksa near Outram Park"*
        no longer matches "katong" against the misrep dictionary
        as a dish name — it's already stripped as a place).
      - `chipDisambig` probe text source switched from
        `req.body?.freeText` to `ftRawIn` for the same reason —
        place names should not enter the R.E.D dish-disambig
        probe.
      - `freetext-log.logFreeTextQuery` captures `ftRawOriginal`
        (pre-strip) so telemetry sees what the user actually
        typed; a new `matchedKnownTerm: 'place-anchor'` value is
        emitted when the place anchor fired.
