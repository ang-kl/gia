# Journal — soleat v0.62.477 (Sketchbook picker: localise cuisine category + sub-cuisine names to the set language)

> Operator (4 Sketchbook screenshots; device language French): *"language is French.
> but the sketchbook is English UI."* The Sketchbook (Clipboard TMA) chrome renders in
> French — but the cuisine picker's category tiles ("European", "Southeast Asian") and
> the drill-down sub-cuisine names stayed English, next to the Cuisine TMA's correctly
> French "Européenne" / "Moyen-Orient & Afrique". Operator decision (numbered choice):
> **"it should follow the language set"** — localise the whole Sketchbook, don't force
> English.

## New

### [HDR] #831 | 15:07 SGT 03-07-26 | v0.62.477 — Sketchbook picker localises category + sub-cuisine names | 3 files | PR #(pending) |
- **Root cause.** `/api/cuisine/catalogue` ships **English labels only** (the route
  ignores the request — `app.get('/api/cuisine/catalogue', (_req, res) => …)`; server
  never localises). The **Cuisine TMA** hides this by localising client-side —
  `CuisineDrawer` renders `tr(CATEGORY_LABEL_KEY[cat.id], lang)` for category tiles and
  `cuisineName(cu.slug, cu.name, lang)` for sub-cuisines. The **Clipboard TMA's**
  `CuisineGroupPicker` was deliberately built "self-contained (no cuisine-i18n deps)" and
  rendered the **raw** `cat.label` / `cu.name` → English category + sub-cuisine names even
  when `getLanguage()` returned `fr`, while the surrounding chrome (`t(key, lang)`) was
  French. Mixed-language screen.
- **`web/clipboard/src/lib/cuisine-i18n.js` (NEW).** Verbatim port of the Cuisine TMA's
  `cuisine-i18n.js` — the `NAMES` slug→localised-name overlay (fr for all ~60 slugs, plus
  zh/ja/es) and the pure `cuisineName(slug, fallback, lang)` lookup (falls back to the
  English catalogue label for any slug/locale not covered). Mirror-verbatim per the
  operator's "port the exact TMA source, don't hand-roll" rule.
- **`web/clipboard/src/lib/i18n.js` — add the `cat.*` category keys.** Ported the 11
  category-tile strings (`cat.commonHere` … `cat.dishes`) from the Cuisine TMA i18n:
  region keys carry en/fr/id (ru/de fall back to en — the Cuisine TMA's own overlays do
  the same); the generic tiles (Sweets & Fusion, Michelin · Bib, Set Meal, Dishes) carry
  all five locales.
- **`web/clipboard/src/components/CuisineGroupPicker.jsx` — localise at render.** Added
  the `CATEGORY_LABEL_KEY` id→key map + a `catLabel(cat, lang)` helper (mirrors
  `CuisineDrawer.labelFor`); the category card, the drill-down modal `<h2>`, and its
  `aria-label` now read `catLabel(category, lang)` instead of the raw `cat.label`, and
  sub-cuisine tiles read `cuisineName(cu.slug, cu.name, lang)` instead of the raw
  `cu.name`. Fallbacks keep any uncovered id/slug on the English label — no key is ever
  shown bare.
- **[VERIFICATION (sandbox)]** `esbuild --format=esm` parse of all three files clean
  (exit 0). No behavioural change for `en`; `fr` now localises category + sub-cuisine
  names to match the chrome.
- **[STATUS]** PROD — Clipboard TMA rebuilds on merge (`npm run build:clipboard`). Verify
  on the live Sketchbook with device/set language French: the "🍜 Cuisine & filtre"
  dropdown tiles read "Européenne", "Asie du Sud-Est", etc., and the drill-down header +
  sub-cuisine pills are French — no English-in-French mix.
- **[TEST]** Full vitest via CI (the picker is presentational; `cuisineName` is a pure
  lookup already covered by the Cuisine TMA's suite).
- **[KNOWN GAPS]** ru/de region-category names still fall back to English (matches the
  Cuisine TMA; French was the operator's target this batch). The 🔙-above-Search-FAB
  request (2a/2b) is a **separate PR on the Cuisine TMA** (that surface owns the Search
  FAB + 3-layer drill) — tracked next. HK→Bangladesh re-test still awaiting operator.
