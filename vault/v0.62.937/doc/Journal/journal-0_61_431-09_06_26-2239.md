- **[INTENT]** Operator reported that searching a Singaporean dish while anchored abroad (country = MY / ID / TH, or a Bangkok pin) returns *"no Singapore venues found"* even though Google Maps lists Singaporean restaurants in Bangkok. Generalises to any nation: Indonesian food in Vietnam, Malaysian food in Japan, etc.

- **[INVESTIGATION — the one fan-out v0.61.230 missed]** The v0.61.230 "region-aware `/s`" work threaded `regionCode` into `searchVenuesByDish`, `runTechniqueFanOut`, and `runCookingMethodFanOut`'s *query* — but **`runNationIconicFanOut` (index.js:8668) was never touched**. When a query matches a `NATION_OVERLAY` iconic dish (`chilli crab`, `kaya toast`, `milo dinosaur`, … — ~60 nations, not just SG), it routed here and:
  1. **injected the literal `"Singapore"`** into the Places `textQuery` (8679),
  2. **never passed `regionCode`** → fell back to the `'SG'` default (signature 8212),
  3. **hardcoded the "no Singapore venues" no-results copy** (8692-8694).
  With a Bangkok `locationBias` circle but a "Singapore" query + SG region, Places got **contradictory geo signals** and returned nothing. (Google Maps has no SG lock → finds the restaurants.) The generic *cuisine* path (Cuisine TMA `/api/cuisine/search`) was already region-correct (`searchRegionCode`, 14192-14199) and is **unaffected**. `runCookingMethodFanOut` had an adjacent **half-fix**: built the region-aware suffix (8820) but still forgot to forward `regionCode` to its inner search (8830).

- **[DELTA]**
  - **`region-code.js` (new):** extracted **`resolveRegionCode(loc)`** — single source of truth (ISO alpha-2 country wins; legacy `JB`/`MY-PUT` → `'MY'`; default `'SG'`). Replaces the inline copies in `handleSearchTurn` (was 7807-7812) and the cooking-method callback (was 3253-3255).
  - **`index.js` — `runNationIconicFanOut`:** add `regionCode = 'SG'` param; `placeSuffix = regionCode === 'SG' ? ' Singapore' : ''` (drop the literal word abroad, mirroring 8486/8820); forward `regionCode` to `searchVenuesByDish`; region-neutral no-results copy. Pass `regionCode` at **both** call sites — `/s` (7917, already in scope) and free-text (10385, via `resolveRegionCode(loc)`).
  - **`index.js` — `runCookingMethodFanOut`:** forward the already-resolved `regionCode` to its inner `searchVenuesByDish` (latent half-fix) + de-hardcode its no-results copy.
  - **`__tests__/region-code.test.js` (new):** 5 cases — alpha-2 wins (TH/MY/ID/JP/VN), country beats region, JB/MY-PUT → MY, null/empty/unrecognised → SG, malformed code → SG.
