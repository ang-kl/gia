## New

### [HDR] #508 | 21:30 SGT 31-05-31 | v0.61.307 — /cost + API-spend tracker | 7 files | 1 PR | 1 build |

- **[INTENT]** Give the operator a chat-side visibility into Gemini token usage + Google Maps request counts without leaving Telegram. Triggered by a production incident: the AI Studio prepayment account went to $0, every Gemini call started 429-ing, and there was no way to see spend from inside the bot.

- **[DELTA]**

  **1. `api-cost.js`** *(new, 162 lines)* — minimal tracker module:
  - `recordGeminiUsage(redis, model, usage)` — bumps Redis hash `api-cost:<YYYY-MM-DD>:gemini:<model>` with `count` + `in_tokens` + `out_tokens` + `total_tokens`. 60-day TTL. Fire-and-forget; never throws.
  - `recordMapsCall(redis, endpoint)` — bumps Redis hash `api-cost:<YYYY-MM-DD>:maps:<endpoint>` with `count`. Same TTL + error contract.
  - `getCostSummary(redis, days = 1)` — scans the per-day hashes for the last N days (clamped 1–60), aggregates by provider + model / endpoint, computes USD using a static rate card (Gemini 2.5-flash / flash-lite / pro / flash-latest; Maps searchText / searchNearby / placeAutocomplete / placeDetails / placeResolve / geocode / reverseGeocode).
  - `formatCostSummary(summary)` — Markdown table for Telegram. Handles the empty-window case + the redis-offline case.
  - `PRICES` const exposed so callers / tests can reference the rate card.

  **2. `index.js`** — three additions:
  - **`/cost [days]` handler** (after the `/ver` block, before `/ftlog`). Owner-gated via `isOwnerChat`. Regex `/^\/cost(?:@\w+)?(?:\s+(\d{1,2}))?$/`. Default window 1 day; max 60. Calls `getCostSummary` + `formatCostSummary`, sends Markdown.
  - **`/api/cuisine/place-autocomplete` instrumentation**: after the successful `axios.post(places.googleapis.com/v1/places:autocomplete)`, `require('./api-cost').recordMapsCall(redis, 'placeAutocomplete')`. Cache hits don't bump (no actual API call).
  - **`/api/cuisine/place-resolve` instrumentation**: after the successful `axios.get(places.googleapis.com/v1/places/<id>)`, `recordMapsCall(redis, 'placeResolve')`.

  **3. `social-profiles.js`** — Gemini-grounded social-profile lookup (the prod 429 hotspot per the Railway trace):
  - `callGemini` gains an optional `_onUsage` parameter.
  - Inside the per-attempt loop, after `m.generateContent(prompt)` returns, fires `_onUsage(attempt.model, r.response?.usageMetadata)` (try/catch-wrapped so a recorder error never breaks the underlying call).
  - `getSocialProfiles` (the public entry, which has `redis` in scope) wires the callback: `_onUsage: (model, usage) => recordGeminiUsage(redis, model, usage)`.

  **4. `__tests__/api-cost.test.js`** *(new, 12 tests)* — covers exports + rate card, `recordGeminiUsage` (real usage / missing usageMetadata / null redis / aggregation / USD calc), `recordMapsCall` (counts / empty endpoint / USD calc), and `formatCostSummary` (no-data, both-providers, redis-offline). Uses an in-memory Redis stub with `hIncrBy`, `hGetAll`, `expire`, and a `scanIterator` generator that filters by glob.

  **5. `package.json`** — `0.61.306 → 0.61.307`.

  **6. `doc/.serial-state.yml`** — commit 520→521, build 309→310, journal 507→508; re-anchored 31-05 '26 21:30 SGT.

- **[KNOWN GAPS]**
  - **Partial instrumentation only** — operator-chosen "(A) tight" scope. Sites NOT yet instrumented: `gemini-client.js` (Hidden Gems), `durian-gemini-verifier.js` (D703f cache verifier), `translate-review.js` (review translation), inline Gemini calls in `index.js` (Extract-Dishes — the other 429-ing path in the Railway log), and the many Maps call sites in `cuisine-search.js`, `pipeline.js`, `transport.js`, `carpark.js`, `consultant.js`, `hidden-verify.js`, `surprise.js`, `travel-times.js`, `vault.js`. Add in follow-up PRs as the operator wants more granular numbers; the api-cost module is the same shape for any caller.
  - **Static rate card** — `PRICES` snapshots Google's 2026 public pricing. Real billing on the dashboards may differ (discounts, tier breaks, free-tier credits). Treat `/cost` USD as an *estimate*, not invoice-true.
  - **Cached responses don't track** — by design. The point is to count *actual* API hits. If a TMA pick uses cached place-autocomplete, no counter bumps. This matches what you'd see in the Maps dashboard.
  - **Failed Gemini calls don't track** — the `_onUsage` fires inside the success path only. So the current 429 storm (depleted prepayment) leaves no trace in `/cost`. Once billing is restored, real usage starts accumulating.
  - **No per-chat breakdown** — `/cost` aggregates across all users hitting the bot. Adequate for the operator-only single-bot context; would need keying-by-userId to break out per-user.
  - **No /cost subcommand for clearing** — `/cost clear` isn't wired. If needed, easy follow-up (delete keys matching `api-cost:*`).
