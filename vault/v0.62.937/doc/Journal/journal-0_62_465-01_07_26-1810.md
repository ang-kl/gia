# Journal — soleat v0.62.465 (fix — Michelin free-text search ignored the query)

> Operator: typed "Mee Soto" free-text + selected Michelin in Cuisine TMA; the known Bib Gourmand
> stall for it (Selamat Datang Warong Pak Sapari, per the operator's cited MICHELIN Guide URL)
> never appeared.

## Root cause

`handleMichelinSearch` (`index.js` ~9605) received `freeText` but **never used it to filter or
prioritise** the curated Michelin/Bib Gourmand pool — only for logging its length and as a
pagination cache key. Venue selection was purely **star-tier order** (3★→2★→1★→Bib Gourmand,
shuffled) sliced to 12 per tap; a typed dish name did nothing.

The stall **does** exist in `SG-michelin.js:167` (not a missing-data case) — but its curated
`name` doesn't literally say "mee soto" (unlike most Bib entries, which spell the dish out, e.g.
"Hokkien Fried Mee"), so a plain name-substring match wouldn't have caught it either.

## Fixed

### [HDR] #820 | 18:10 SGT 01-07-26 | v0.62.465 — free-text now filters the Michelin pool | 3 files | PR #(pending) |
- **`index.js`** — before slicing to 12, entries whose `name` **or** `keywords[]` contain the
  typed free text are promoted to the front of the pool (tier order preserved within each half) —
  same precedent as the existing `otherCuisineSlugs` cuisine pre-filter in the same function.
- **`SG-michelin.js`** — added a sourced `keywords: ['mee soto', 'soto']` tag to the "Selamat
  Datang Warong Pak Sapari" entry, citing the operator's MICHELIN Guide URL as provenance. Did
  **not** fabricate keywords for other proper-name stalls — that would need its own sourced audit,
  noted as a natural future extension of the dish-taxonomy program.
- **[VERIFICATION (sandbox)]** `node --check` both files; traced the call site (`freeText:
  ftRawIn`) end-to-end to confirm the real typed query reaches the new filter.
- **[STATUS]** PROD — server rebuild on merge.
