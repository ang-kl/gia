# Journal — soleat v0.62.44 (URGENT: TMA auth guard — clear "open from Telegram" screen on initData 401s)

> Operator (URGENT, with Railway logs): a real iPhone (iOS 18.7) hit `[twa-auth] 401` on EVERY TMA
> mount call — `/catalogue`, `/session/start`, `/country-pref`, `/rating-pref`, `/user-location`,
> `/user-language`, `/search`, `/set-location`. **Diagnosis (read-only): NOT a server regression.**
> `twa-auth.js` HMAC + 24h-expiry verify is unchanged since v0.61.393; no recent PR touched the gate
> (`app.use('/api/cuisine', requireInitDataFromBodyOrHeader)` at index.js:12271). One IP failing
> EVERY call = that client sent **empty or expired `initData`** (opened outside Telegram, or a stale
> >24h launch); a bad bot token would 401 ALL users, not one. The 401s are CORRECT security
> behaviour — so the fix is CLIENT resilience, NOT weakening auth.
