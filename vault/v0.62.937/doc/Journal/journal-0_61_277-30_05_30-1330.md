# Journal — soleat v0.61.277 (JB chip + pill auto-anchor + modal ref reset)

> Operator (30-05 '26 ~12:25 SGT, post-v0.61.276 Railway-log retest):
> *"i switch to Johor Bahru, and confirm my new loc is JB south key as spec. why my loc still in south SG."*
>
> Root cause of the lingering bug, mid-session: v0.61.276 fixed the *mismatch* (modal + server sanity + graceful exit), but the user's natural way of acting on JB ("tap JB pill, tap Southkey chip") never *committed* an anchor in JB — it only toggled UI state. The 🔍 button was the only path that actually moved the anchor, so without a manual tap there, GPS / prior anchor kept winning.
>
> v0.61.277 closes that gap with three coordinated fixes:
> 1. **Chip onClick → anchor commit** — tapping Southkey or JB CBD in LocationField now ALSO calls `onSelect` with the focus-point coords (with `noAutoFire: true` so the 🔍 doesn't fire silently). Matches the operator's mental model: "tap Southkey = location is Southkey".
> 2. **JB region pill → auto-anchor when no JB anchor** — tapping the JB pill in the region row, when the current anchor isn't in JB, immediately commits the active focus point (Southkey by default) as the anchor. The map + label flip to JB instantly instead of staying on GPS.
> 3. **Modal ref reset on region flip + JB-anchor suppression** — the v0.61.276 `regionCoherenceCheckedRef` was one-shot per mount, blocking re-prompts after mid-session JB toggles. New `useEffect` resets the ref when `state.region` leaves JB; the coherence effect also short-circuits when `locationAnchor` IS in JB extent so the modal doesn't fire spuriously after the new auto-anchor.
>
> Plus extraction: the JB focus points (Southkey + JB CBD) are now in a shared lib `web/cuisine/src/v2/lib/jb-focus-points.js` so the LocationField chip and the App-level pill use the same constants.
>
