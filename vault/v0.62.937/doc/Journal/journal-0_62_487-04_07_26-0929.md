## New

### [HDR] #841 | 09:29 SGT 04-07-26 | v0.62.487 — derive the open-hours label when openNow is null | 2 code files + 3 doc/meta | PR #(pending) |

- **[INTENT].** Make the 🕛 timing row appear even when Google omits `currentOpeningHours.openNow`
  (so `venue.openNow` is `null`). Previously the label pass computed a label ONLY for
  `openNow === false`/`=== true`, so a `null` venue got no `openClosingLabel`/`closedTodayLabel`
  and `ResultCard.jsx` rendered `''` — the row vanished (operator: "the clock is not there").

- **Root cause (traced — the deferred v0.62.486 ask #2).**
  - Server: `cuisine-enrich.js` label pass had `if (openNow===false){…} else if (openNow===true){…}`
    with **no `else`** — a `null` `openNow` fell through, so neither `closedTodayLabel` nor
    `openClosingLabel` was set.
  - Client: `ResultCard.jsx` `open` ternary mapped `openNow === null → ''` (no row).
  The weekly schedule (`periods`, already resolved via the v0.62.486 empty-array fallback) was
  available the whole time — just never consulted on the null branch.

- **[DELTA] (2 code files).**
  - `cuisine-enrich.js` — added the `else` branch: when `openNow` is unknown, derive the label
    from `periods` — `currentOpenString` first (→ `openClosingLabel` if it reports open now),
    else `closedTodayString` (→ `closedTodayLabel`). **Deliberately does NOT set `v.openNow`.**
  - `web/cuisine/src/v2/components/ResultCard.jsx` — the `open` ternary's `null` arm now reads
    `venue.openClosingLabel || venue.closedTodayLabel || ''` (still `''` when there's genuinely
    no schedule — no bare word invented).

- **Why it's safe (thrash-sensitive area).** The red **Closed corner-tab** and the open-now
  **filters** both gate on `openNow === false`. Leaving `openNow` at `null` (we only fill the
  informational label) means neither is disturbed — a null venue shows a derived clock line but
  no Closed tab, exactly as before for tab/filter purposes. The v0.62.472/475/476 prefix-strip
  tweaks only fire for `openNow === false`/`=== true`, so the derived label renders verbatim.

- **[VERIFICATION (sandbox)]** `node --check` clean on `cuisine-enrich.js`; `esbuild` JSX parse
  clean on `ResultCard.jsx`. Web build in CI (`web/cuisine` changed).

- **[STATUS]** PROD — bot + TMA redeploy on merge (Railway). Verify on Telegram: a venue whose
  Google record omits live open/closed now shows a 🕛 row ("Open · Closes …" or "Closed today ·
  Opens …") instead of a missing row; venues with genuinely no schedule still show no row (no
  regression), and no spurious red Closed tab appears.
