# Journal — soleat v0.61.297 (anti-repeat variety + FunFactModal stacking fix)

> Operator (31-05 '26 00:23 SGT, screenshot annotation): *"the cuisine facts is blocked"* — image shows the FunFactModal partly readable behind a second "Loading… 🔍 Searching — this takes more than a few seconds." overlay drawn on top.
>
> **Root cause**: the v0.61.285 brief was *"replace the current wait messages while curating results"*. I built the FunFactModal but never *removed* (or gated) the older rotating-titles loading overlay (`'loading.rotating.6'`). Both render at `fixed inset-0 z-50`; the rotating-titles renders later in the App.jsx tree so it draws on top.
>
> v0.61.297 bundles **two fixes** in one PR:
>
> 1. **Anti-repeat variety pass** (the originally-planned content of v0.61.297). Adds a second fact for 12 popular cuisines that previously had only one Phase 1 / Phase 2A entry — laksa / nasi-lemak / satay / roti-prata / teh-tarik / kaya / durian / yong-tau-foo / popiah / nasi-kandar / murtabak / mee-goreng. With the anti-repeat cap at 10 IDs, a single-fact cuisine cycled back to the same fact every search; doubling to two per cuisine means a "/c durian" user sees a different fact on consecutive searches.
>
> 2. **FunFactModal stacking fix** (urgent operator-reported bug). The rotating-titles overlay is now gated on `loading && !funFact` — when a fact has been picked, the FunFactModal takes over as the busy indicator and the older overlay hides. The FunFactModal's backdrop is also upgraded to absorb pointer events (`stopPropagation`) so the page underneath is non-clickable during fact display, matching the rotating-titles overlay's prior behaviour.
>
> Total facts: 52 → **64**.
>
> Commit 511 / journal 498 / build 300, on branch
