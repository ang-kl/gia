# Journal — soleat v0.61.299 (D703e/f extended to 7 Slavic/EE cuisines)

> Operator (31-05 '26 08:35 SGT, post-PR-#804 merge): *"b, a"* — sequenced (b) first (Romanian seeds, v0.61.298), now (a) — extend the v0.61.282/v0.61.294 Gemini-cache D703f path beyond `specialMode` to cover the 7 Slavic / EE cuisines flagged by the variance run.
>
> Why this PR matters: the v0.61.297 variance dump showed Places returning a ~20–30% false-positive rate for Slavic/EE searches (Italian café for "Polish", Georgian restaurant for "Romanian", famous Romanian beer hall for "Bulgarian", etc.). Same precision problem the durian-pastry mode had pre-v0.61.282 (~18%). The fix is the same: cache Gemini's per-venue verdict and drop `unrelated` venues at search time.
>
> Architecture change: the D703e (cache lookup) + D703f (online verify-then-cache) block used to live INSIDE the `if (specialMode)` gate, with the cache key implicitly = `specialMode`. v0.61.299 lifts it OUT into its own scope and computes a `geminiCacheKey` from either:
>
> - `specialMode` (if it's one of `durian` / `durian-pastry` / `fruits`), OR
> - the single-cuisine slug (if `cuisineMetas.length === 1` and the slug is in `GEMINI_CACHE_KEYS`)
>
> Multi-cuisine searches and freetext searches skip the cache — those have looser intent so the raw Places ranking is acceptable.
>
> Net runtime impact: the next single-cuisine search for any of the 7 Slavic/EE cuisines triggers Gemini verification on cache-miss venues; subsequent searches anywhere in the world hitting the same placeIds are free.
>
