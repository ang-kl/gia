## New

### [HDR] #67 | 17:15:00 SGT 01-05-26 | v0.30.9 | n/a kb | n/a lines
- **[INTENT]** Item L from open-list close-out. Cloud Map ID — env var driven since v0.12.1, but with the `'GIA_SANCTUARY'` placeholder default. The placeholder is unregistered; Google Maps JS rejects it and falls back to default raster tiles. No fatal error, just a degraded-but-working map. The fix is documentation + boot-time visibility, since registering the actual Map ID is a Google Cloud Console action only the user can take.
- **[DELTA]**
  - **NEW** `setup-cloud-map-id.md` — top-level repo doc with 6-step Cloud Console walkthrough: create Map ID (JS Vector type), copy string, optionally apply a preset style (e.g. Aubergine), set `MAP_ID` env var in Railway, verify boot log line. ~3 min one-time setup. Free of charge.
  - **`index.js`** —
    - Boot warning: `console.warn('[Boot] MAP_ID env var unset — Sanctuary Map TMA will render with default Google Maps styling…')` when `process.env.MAP_ID` is missing. Otherwise `console.log('[Boot] MAP_ID configured: <first 16 chars>…')`. Surfaces in Railway logs immediately on every redeploy so the operator notices.
    - `/maps-key` route response now carries `mapIdSource` (`'env:MAP_ID'` or `'placeholder'`) and a `warning` field when running on the placeholder. Frontend `public/app.js` already accepts arbitrary `mapId` so no client change needed.
- **[VERIFICATION (sandbox)]**
  ```
  node --check on index.js → OK
  ```
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[OPERATIONAL]**
  After Railway redeploys, check the boot log. Either:
  ```
  [Boot] MAP_ID env var unset — Sanctuary Map TMA will render with default Google Maps styling (no vector branding). Register a Map ID at https://console.cloud.google.com/google/maps-apis/studio/maps and set MAP_ID in Railway. Steps in setup-cloud-map-id.md.
  ```
  …or, once registered:
  ```
  [Boot] MAP_ID configured: a1b2c3d4e5f6g7h8…
  ```
  Three minutes of Cloud Console work closes the gap.
- **[KNOWN GAPS]**
  - Cannot validate `MAP_ID` server-side — Google Maps JS validates client-side at map-load. If a wrong/expired Map ID is set, browser console shows `InvalidMapId` and the map renders blank. Document calls this out in the troubleshooting section.
