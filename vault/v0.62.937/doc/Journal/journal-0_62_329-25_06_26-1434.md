    16 endpoints under `/api/clipboard/*`:
    | # | Method | Path | Notes |
    |---|---|---|---|
    | 1 | GET | `/state` | catch-all count + cabinet list (light) |
    | 2 | GET | `/cabinet/:id` | full cabinet + drawers + cards (heavy) |
    | 3 | POST | `/cabinet` | create (cap-12) |
    | 4 | PATCH | `/cabinet/:id` | rename / emoji / location / dates / sortDirection |
    | 5 | DELETE | `/cabinet/:id` | cascade per operator-locked rules |
    | 6 | POST | `/cabinet/:id/drawer` | add (cap-20, segment + dayTag? + location?) |
    | 7 | DELETE | `/cabinet/:id/drawer/:n` | cascade + reindex |
    | 8 | PATCH | `/cabinet/:id/drawer/:n` | update dayTag/location + optional `moveTo` manual reorder |
    | 9 | POST | `/card/:id/place` | place into drawer (cap-10) |
    | 10 | POST | `/card/:id/unplace` | remove placement |
    | 11 | POST | `/card/:id/move` | unplace+place in one call |
    | 12 | PATCH | `/card/:id` | name / note (≤990) / favourite (toggles PERSIST via `recomputeCardTtl`) |
    | 13 | DELETE | `/card/:id` | hard-drop HASH + walk every placement |
    | 14 | POST | `/cabinet/:id/drawer/:n/share` | mint token → persisted onto drawer meta |
    | 15 | GET  | `/shared/:token` | **PUBLIC** — the token IS the auth |
    | 16 | POST | `/shared/:token/fork` | authed; pickup target cabinet or dump to catch-all |

    Auth model: single chokepoint `app.use('/api/clipboard', requireInitDataFromBodyOrHeader)`
    with the public `GET /shared/:token` registered **before** the gate so Express matches
    it first. Dev-bypass (`SKIP_INIT_DATA_AUTH=true`) falls back to `?chatId=` / body for
    preview/curl. Structured error strings from clipboard-store map to HTTP codes
    (`name-required` / `invalid-segment` / `missing-args` → 400, caps → 409 + cap field,
    `*-not-found` → 404, `redis-failure` → 503). Every handler is wrapped in a small
    `wrap()` helper that surfaces `console.warn` on unhandled rejections and returns 500
    (per the gia-preflight rule "never swallow errors").

    Share payload (kind=`dr_share`): `{ chatId, cabId, drawerIdx, snapshotAt,
    drawer: { segment, dayTag, location }, cards: [...] }` via the existing `share.js`
    helper (7-day TTL, 10-char base64url token). The drawer's `shareToken` field is
    written back onto the metadata entry so the TMA can render "already shared" without a
    re-mint. The owner's `chatId` is stripped from the public `GET /shared/:token`
    response so a forwarded link can't be used to enumerate the owner.

    Fork flow: `pushClip` mints fresh cardIds in the caller's catch-all; if the
    caller specifies a `cabinetId`, `addDrawer` creates a fresh drawer in that cabinet
    (same segment/dayTag/location) and each card is `placeCard`'d into it. Without a
    `cabinetId`, cards just land in catch-all and the caller can organise later.

    PATCH drawer's `moveTo` (manual reorder) is the most involved handler: it
    splice-rebuilds the metadata LIST, then re-LRANGE/re-RPUSH every per-drawer cardId
    LIST at the new index, and re-keys every affected `card_locs` SET tag. O(D·C) per
    reorder; acceptable for the 20-drawer cap.
