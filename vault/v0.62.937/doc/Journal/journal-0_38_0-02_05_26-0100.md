- **[DESIGN]**
  1. **`nea-scrape.js` — defensive cheerio parser.** Fetches `https://www.nea.gov.sg/our-services/hawker-management/announcements`, walks every `<table>` element, classifies by preceding heading text (`closure`/`cleaning` → closures; `r&r`/`repair`/`renovation`/`redecoration` → R&R). Permissive heading-detection looks back through siblings AND up through parents. Best-guess fallback: when no classifier matches, use the largest table as closures and second-largest as R&R so the TMA stays non-empty when NEA changes heading text. Cache key `nea:hawker-scrape:v1`, TTL 6 h.
  2. **`GET /api/hawker/closures` endpoint.** Auth via `requireInitData` (TMA-callable). Returns the cached or freshly-scraped result with structure `{ok, fetchedAt, ms, sourceUrl, hawkerHomeUrl, closures: {headers, data}, rnrWorks: {headers, data}, diagnostics, cached}`. Failure path returns `{ok: false, error}` so the UI can show a "couldn't parse" message without claiming zero closures.
  3. **Hawker NEA TMA at `/app/hawker`.** New Vite + React project at `web/hawker/`. Three tabs: 🧹 Closures (count badge), 🛠 R&R Work (count badge), ℹ About (diagnostics + NEA links). Header carries the soleat logo, last-fetched age ("just now" / "32 min ago" / "5 h 12 min ago"), 🔄 Refresh button, and inline links to NEA. Tables render with Tailwind's `whitespace-pre-wrap break-words` so long centre names + dates wrap cleanly on mobile.
  4. **Per-centre carpark enrichment (chat-side).** `runHawkerNearest` and `runHawkerZone` now fan out 5 carparks per centre via `Promise.all([carpark.nearest(c.lat, c.lng, 5)] × N)`. For nearest-3 view = 15 LTA calls in ~3 s. Each centre block renders as Markdown:
     ```
     *Centre Name* — 250 m (Central)
     1 Address Lane
     🅿️ Nearest carparks (lots available):
       · Plaza Carpark — 87 lots — 120 m
       · …
     ```
  5. **Zone view becomes "nearest 3 in zone."** Was "all centres in zone (all 9)". User has to share location now (gated like nearest). Sort by haversine, slice 3, enrich with carparks. The zone summary line still cites the total count for context.
  6. **`runHawkerCleaning` re-purposed.** Now fetches the scrape (cached), surfaces a count summary in chat (`📊 Currently scraped: 3 closure rows · 2 R&R rows.`), and offers two buttons: 🧹 Open closures TMA (web_app to `/app/hawker`) + 📅 NEA hawker mgmt (external URL). Falls back gracefully when scrape fails.
  7. **Build pipeline extended.** Root `package.json` adds `build:hawker`. `.gitignore` adds `public/hawker/` (regenerated each Railway deploy).

- **[KNOWN GAPS / RISK CALL-OUTS]**
  - **Scrape contract risk.** NEA can change their HTML at any time. Mitigations: (a) heading-text classifier is permissive (matches "closure/cleaning" or "r&r/repair/renovation/redecoration" case-insensitive), (b) best-guess fallback when no classifier matches, (c) explicit fetchedAt timestamp + cached/fresh badge in TMA, (d) About-tab diagnostics row. Monitor Railway logs for `[NEA-Scrape]` warnings.
  - **Carpark enrichment cost.** 15 LTA calls per `/hawker` Nearest 3 (or zone-3) call. ~3 s wall time, free to call (LTA DataMall is free). If usage spikes, add per-chat throttle like `pick-cache.js`.
  - **Zone view now requires location.** Previously listed all centres in a zone without it. New behaviour gates on location share. Acceptable trade — the carpark enrichment needs lat/lng anyway.
  - **NEA fetch can be slow on cold cache** (~5-10 s). Hawker TMA shows a "Fetching from NEA…" placeholder; chat-side `runHawkerCleaning` blocks for that duration. Acceptable for an admin-style screen.
  - **Hawker TMA UI is utility-grade.** Shows raw NEA tables verbatim (column headers vary by NEA's data); no per-cell formatting beyond word-wrap. Future polish: parse common columns (Centre, Date From, Date To, Reason) into a normalised schema.
  - **No in-bot cron** to pre-warm the cache. First user after each 6 h interval pays the cold-fetch latency. Could add a boot-time + 6 h interval timer if cold-fetch UX bites.
