# Journal — soleat v0.60.155

> Cuisine-TMA follow-up to v0.60.154: three operator-reported regressions on the live Michelin path. (1) `💬 "[object Object]"` still surfaces on some cards — the v0.60.154 cache-READ guard prevented NEW corruption from leaking but didn't address the WRITE path that originally poisoned the cache, nor an in-process producer leaking a non-string into `v.recentReview` before the READ guard ran. (2) The 💬 emoji now renders on its own line above the review text instead of inline (block-layout regression). (3) The curated list "doesn't start from the first" entry — root caused to the long-lived 30-day per-criteria seen-set silently filtering out previously-viewed Michelin entries on every fresh TMA mount.

- **[DELTA]**

  **`web/cuisine/src/v2/components/ResultCard.jsx`** (~175–179) — restructured the review line. The previous render placed `💬 "..."` in a single text node inside a plain `<div>` with no flex layout. Long review strings wrapped under the emoji, and the operator perceived 💬 as sitting on its own line. New shape uses `flex items-start gap-1` with `💬` in a dedicated `<span aria-hidden>` and the quoted text in a sibling `<span>` — emoji and text now share the first line and wrap consistently below the emoji on subsequent lines. The same edit also adds a `typeof === 'string' && .trim()` guard around the whole block so the TMA refuses to render any non-string value (defense-in-depth against issue #3).

  **`index.js`** (`handleMichelinSearch` Step 4 force-fill, ~6213–6224) — replaced the `if (!v.recentReview || !String(v.recentReview).trim())` check with `if (typeof v.recentReview !== 'string' || !v.recentReview.trim())`. The old check let a truthy non-string (e.g. `{ corrupt: 'value' }`) pass both branches because `!{ }` is false **and** `String({}).trim() === "[object Object]"` is truthy. The new check explicitly demands a string, so any non-string is immediately overwritten with the tier-aware boilerplate (`"★★★ Michelin Guide 2025 · curated recommendation."` etc.).

  **`index.js`** (`handleMichelinSearch` Step 5 cache WRITE, ~6232–6241) — sanitize every text field before writing to `michelin:enrich:<slug>`. Previously `v.recentReview || ''` would let a truthy non-string fall through; `JSON.stringify` would then serialize the object verbatim and poison the 7-day TTL'd cache for every subsequent session. Now every string field flows through `typeof v.X === 'string' ? v.X : ''` and `dishes` is array-filtered on `typeof === 'string'`. Stops the corruption at its source.

  **`index.js`** (`/api/cuisine/session/start`, ~7907–7935) — wipe every long-lived `cuisine:seen:<chatId>:*` key on TMA mount via `redis.keys()` + `redis.del()`. Previously, only the per-session clipboard (the v0.60.146 `cuisine:session-*` SET/LIST/HASH) was reset on startSession; the per-criteria seen-set (30-day TTL, keyed by criteriaHash) persisted across TMA launches, so the first 12 Michelin entries the user saw in a prior session were silently skipped on the next mount — making the catalogue appear to "start from somewhere in the middle". The operator's mental model is "fresh TMA = fresh list"; this matches it. In-session pagination still works because the seen-set advances normally during the session — it's only the long-lived persistence that's dropped.

  **`__tests__/redis-stub.js`** — added minimal `keys(pattern)` glob support (only the `*` wildcard, matching the production redis client's signature). Needed by the new session/start scan; covers all four backing stores (string / hash / set / list).
