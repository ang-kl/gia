## New

### [HDR] v0.62.698 — the iOS zoom guard was inert, exactly as O-104 predicted

- **[INTENT]** Operator: *"when I tap 'Search a station or road' it should not zoom in and make the
  whole CSS looks like zoom in and make the TMA looks zoom in"*.

- **[THIS IS O-104, REPORTED FROM A DEVICE]** O-104 has been the **oldest undecided item** in the
  Register since v0.62.678 — recorded as "the iOS auto-zoom guard is inert in 4 TMAs" and deliberately
  left unfixed because *"every fix conflicts with the 14px parity"*. It has now produced a user-facing
  symptom, which settles the question.

- **[ROOT CAUSE — a specificity loss, not a missing rule]** The guard is present in every app's
  `styles.css`, and its own comment states the intent:

  ```css
  /* … iOS auto-zooms a focused input whose font-size is below 16px …
     Force >=16px on all text inputs. */
  input, textarea, select { font-size: 16px; }
  ```

  A bare element selector has specificity **(0,0,1)**. The input carried Tailwind's `text-xs`, a class
  at **(0,1,0)**. **The class wins**, the input renders at 12px, and iOS auto-zooms the whole page on
  focus — which is precisely "the whole TMA looks zoom in". No amount of element-selector tinkering
  fixes it: a class beats any number of element selectors.

- **[DELTA]** The size is set where it actually reaches the element — on the input itself, in
  `StationLocationField.jsx`: `text-xs` → `text-[16px]`. Because that component is **shared**, this
  fixes the reported field in **both Hawker and Train** at once. The `styles.css` guard is left in
  place as the backstop for inputs that set no size at all.
  Deliberately **not** `!important` on the guard: that would force *every* input in the app to exactly
  16px, shrinking any that legitimately want to be larger, and it would be a silent app-wide
  restyle in a change reported about one field.

- **[WHY 16px AND NOT A TRICK]** The alternatives are worse. `maximum-scale=1` / `user-scalable=no` in
  the viewport meta suppresses the zoom by **disabling pinch-zoom entirely** — an accessibility
  regression, and Telegram's WebView may override it anyway. A CSS transform to fake a smaller size
  leaves the real font size unchanged, so iOS still zooms. 16px is the platform threshold; meeting it
  is the fix.

### [HDR] v0.62.698 — re-tapping the active zone re-frames it

- **[INTENT]** Operator: *"when I click the zone again, it should be zoom out to 12 in iPhone and 13
  in Desktop/iPad to show the zone selected"*.

- **[WHY IT DID NOTHING]** All three zone-pill call sites ran `onClick={() => setActiveRegion(r.region)}`.
  Re-tapping the **active** pill called `setActiveRegion` with the value it already held, React bailed
  out of the re-render, and nothing moved. The tap was not ignored by design — it simply had no effect.

- **[DELTA]** New `pickRegion(region)` in Hawker's App: a different region still switches as before; the
  **same** region calls a new `window.__giaHawkerFitZone(zoom)` with **12 on phone / 13 on wide**, per
  the operator's numbers. The map global frames the ACTIVE zone's centres (`centresRef` follows the
  `centres` prop) with `panTo(bounds.getCenter())` + `setZoom(z)` — **not** `fitBounds`, which would
  choose its own zoom from the bounds and ignore the two numbers that were the whole request.

- **[VERIFICATION (sandbox)]**
  - **iOS zoom:** the station-search input's **computed** `font-size` is now **16px** on both phone and
    desktop viewports (read from the running app, not from the class list — the class list is exactly
    what misled O-104 for six versions).
  - **Zone re-tap:** with the map global stubbed to record its argument — re-tapping the active zone
    calls `fitZone(12)` at 390×844 and `fitZone(13)` at 1280×900; switching to a *different* zone adds
    **no** call and correctly moves the active pill. So a switch never force-zooms, only a re-tap does.
  - Hawker + Transport builds green; full `npm test -- --run` **156 files / 3901 tests** green.

- **[O-119 ANSWERED]** Operator: *"Hawker actual works"* — confirming Hawker was functional before
  today. That **supports** the v0.62.692 regression window: `isShort` entered `renderCentreCard`'s body
  in v0.62.686, which merged this morning in PR #1682, and the white-screen appeared after it. O-119
  can be closed as confirmed rather than left open.
