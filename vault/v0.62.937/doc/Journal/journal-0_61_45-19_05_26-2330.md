## New

### [HDR] #249 | 23:30:00 SGT 19-05-26 | v0.61.45 — greyscale toggle raster-base-map fix | ~1 kb | 4 files | 1 PR | 1 build |

- **[INTENT]** Make the base-map greyscale toggle work in the Cuisine TMA, where it
  had no effect despite byte-identical code to the working Hawker / Transport TMAs.

- **[DELTA]**
  - **Diagnosis** — the operator confirmed the 🎨 button toggles correctly (React
    state + the v0.61.41 palette both work) but the map stays in colour. So the
    failure is purely the CSS rule not matching the Cuisine base map. The greyscale
    stylesheet only targeted `.gia-greyscale-map canvas` — a **vector / WebGL** base
    map. Transport + Hawker render vector (canvas) and greyed correctly; the Cuisine
    map renders a **raster tile** base layer (`<img>`), which the `canvas` selector
    never matched — exactly the "works in Hawker, not Cuisine" split.
  - **`mapOverlays.js`** (byte-identical ×3) — `ensureGreyscaleStyle` rule now targets
    **both** `.gia-greyscale-map canvas` **and** `.gia-greyscale-map img`, so the
    base-map greyscale applies whichever rendering mode Google hands the map. Marker
    pins are plain `<div>`/`<span>` nodes, so neither selector touches them.
  - **`package.json`** — `0.61.44` → `0.61.45` (PATCH).

- **[VERIFICATION (sandbox)]**
