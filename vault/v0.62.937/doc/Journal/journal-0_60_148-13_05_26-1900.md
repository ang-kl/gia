## Amendments

### ⇠ Prev placement — strip-inline → floating FAB

> Prior (v0.60.146, PR #385): the ⇠ Prev button was inserted into `ResultPanel.jsx`'s existing pagination strip at line ~237, **inside** the `{totalPages > 1 && (…)}` block. The intent was to sit it next to the existing ◀ Page / ▶ Page nav. But `totalPages` is `Math.ceil(venues.length / PAGE_SIZE)` with `PAGE_SIZE = 12`, and the server returns exactly 12 venues per response — so `totalPages = 1` and the surrounding strip never renders for any standard search. The back FAB was effectively invisible.
>
> Change (v0.60.148): the inline-strip branch is removed (a comment block in `ResultPanel.jsx` records the move). The button now lives in `App.jsx`'s fixed-position FAB column, above the 🔍 Search FAB, gated on `pageStackDepth > 0`. Same handler, same styling family as the other FABs. The in-strip ◀ / ▶ page nav (for the rare >12-venue response) stays put.

### `/clip` onText — add `/clipboard` alias

> Prior (v0.59.44+): `^\/(?:clip|cl)(?:@\w+)?(?:\s+(.+))?$` — matched `/clip`, `/cl`.
>
> Change (v0.60.148): `^\/(?:clip|cl|clipboard)(?:@\w+)?(?:\s+(.+))?$` — also matches `/clipboard`. Operator's question implied they expected the natural spelling to work.
