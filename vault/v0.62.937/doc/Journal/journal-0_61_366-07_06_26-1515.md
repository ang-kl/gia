### [HDR] #566 | 15:15 SGT 07-06-26 | v0.61.366 — Menu picker countryPref follows the anchor | 1 code file | 1 PR | 1 build |

- **[INTENT]** Make the Menu OTHER picker show the **detected** country + its capital, not a stale saved country.

- **[ROOT CAUSE]** `LocationFieldMenu`'s `countryPref` is component-internal and **seeded once** from the server (stale `JP`). The `cityPick` effect then picked the **nearest JP city to the Hanoi anchor by haversine = Fukuoka (FUK)** — so both the country *and* the city were wrong. The "default city = capital" the operator expected (`list[0]` = Tokyo for JP, Hanoi for VN) was being overridden by the stale-country + nearest-city path.

- **[MECHANISM]** (`web/menu/src/components/LocationFieldMenu.jsx`) — a new effect syncs `countryPref ← the detected anchor's country` (prefer `currentAnchor.country`, else derive via `nearestIataCity(anchor coords)`) whenever the **anchor** moves. The deps are the anchor fields **only**, so a manual country pick (which changes `countryPref` but not the anchor) is never overridden. SG is excluded (it uses the region-pill path). With `countryPref` following the anchor to VN, the `cityPick` effect resolves **Hanoi** (the capital).
