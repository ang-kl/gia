## Fixed

### [HDR] #814 | 14:20 SGT 01-07-26 | v0.62.460 — cache-busted tile icon URLs | 3 files | PR #(pending) |
- **Investigated first, before touching the asset again.** `web/menu/public/sketchboard_clip_icon.png`
  on `main` **is already the correct v0.62.455 cabinet icon** (102×174, transparent, 32% opaque —
  verified by fetching the raw file from GitHub). The server is serving the right bytes.
- **Real root cause: no cache-busting.** The tile `<img>` references a **literal static path**
  (`/app/menu/sketchboard_clip_icon.png`). Vite hashes JS/CSS filenames on every build, but this raw
  PNG path never changes — so Telegram's WebView (and browsers) keep serving a **stale cached copy**
  under the same URL after every deploy, even though the underlying file changed. That's why the
  "muddled icon" kept resurfacing: the operator was seeing old cached bytes, not a re-introduced bug.
- **Fix:** appended **`?v=${BUILD_VERSION}`** (already in scope — used for the footer version strip)
  to **all four** Menu tile `iconImage` paths (cuisine, train, hawker, sketchbook) so every version
  bump forces a fresh fetch. Pre-empts the same complaint recurring for the other three tiles.
- **[VERIFICATION (sandbox)]** `esbuild` parse OK. No local `web/menu` harness exists yet — CI builds
  + tests menu on the PR.
- **[STATUS]** PROD — Menu TMA rebuild on merge.
