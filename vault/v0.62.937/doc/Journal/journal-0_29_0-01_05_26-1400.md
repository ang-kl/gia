- **[INTENT]** Per Human Lead "Skip this, proceed the next build" — pick a small, concrete, no-input-needed enhancement. Picked: enrich the Refine-pipeline per-cluster context with **nearest MRT stations** so travel advice can anchor on a real station ("3 min walk from Raffles Place MRT") rather than the generic "transit clear" copy. `transport.nearestMrtStations` already existed (since the v0.20.0-era `/transport` work) — it just wasn't wired into the cuisine pipeline.
- **[DELTA — pipeline]**
  - **`pipeline.js#fetchClusterContext`** — `Promise.allSettled` array now includes `transport.nearestMrtStations(lat, lng, 1500, 2)`. Returned cluster context object now carries `mrtStations: [{placeId, name, address, lat, lng}, …]` (max 2 per cluster).
  - **`pipeline.js#summariseClusterCtx`** — refine prompt now sees an extra bracketed segment per venue: `[nearest MRT: Raffles Place, Telok Ayer]` (or `[nearest MRT: no MRT in 1.5 km]` for SBS-only zones). Same `Promise.allSettled` failure tolerance — MRT lookup failure does not block the pipeline.
- **[DELTA — cache-bust + bundle visibility]** Added in response to mid-PR Human Lead "Test why still cannot search… is telegram block ai syntax":
  - **`index.js`** — new `noCacheHtml(res)` helper sets `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` + `Pragma: no-cache` + `Expires: 0` on every TMA HTML response (`/app`, `/app/menu`, `/app/cuisine`, `/app/map`). Vite-built assets remain cacheable (content-hashed filenames). This closes the "Railway redeployed but Telegram still serves the stale bundle" failure mode.
  - **`web/cuisine/vite.config.js`** — + `define: { __BUILD_VERSION__: …, __BUILD_TIME__: … }` injects build-time globals at compile.
  - **`web/cuisine/src/components/Header.jsx`** — title row now shows `Cuisine and Drinks` + monospace `v<version>` directly under it. User can confirm at-a-glance which bundle they're running without opening console or Diagnostics. (Also catches the more pernicious "TMA was opened pre-redeploy and the user thinks the bundle is current" case.)
  - Verified: `grep '0.29.0' public/cuisine/assets/index-*.js` returns 2 hits (the inlined globals).
  - Telegram does **not** block AI-generated content syntactically — there's no such mechanism in the WebApp spec. The "still cannot search" symptom is almost certainly the in-app webview serving a cached pre-v0.26.4 bundle. After this PR ships:
