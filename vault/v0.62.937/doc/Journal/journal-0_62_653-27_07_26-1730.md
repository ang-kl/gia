## New

### [HDR] v0.62.653 — "East-West Line (Changi br…" was the worst of both: the qualifier was there and unreadable

- **[INTENT]** Operator, Telegram Desktop screenshot of the Tanah Merah / Expo / Changi Airport cards:
  *"for Train station card , CG Branch description should second line stations: East-West Line / (Changi
  Airport Branch) … Overall, reduce font size by 1 px if cannot see the whole description for each line"*

- **[SCOPE, CHECKED BEFORE BUILDING]** Grepped `data/stations.json`: **exactly one** line in the LTA feed
  carries a parenthetical qualifier — `"East-West Line (Changi branch)"` — against nine plain names
  (North-South, East-West, Bukit Panjang LRT, Thomson-East Coast, Circle, Downtown, North East, Sengkang LRT,
  Punggol LRT). So this is a one-line-in-ten case, and the fix must leave the other nine visually identical.

- **[DELTA]** (3 files)
  1. **NEW pure helper `splitLineName(name, canonical)`** in `station-card-utils.js` — splits a trailing
     parenthetical into `{ main, qualifier }`. When the caller supplies a canonical name it wins, because
     `data/stations.json` says *"Changi branch"* while `lines.js` — **and the line chip the user just
     tapped** — says *"Changi Airport Branch"*. Matching what is already on screen beats echoing the feed's
     shorthand. Guarded so a canonical name equal to the main name can never render "X (X)".
  2. **`LineSubCard`** renders the qualifier on its **own row** beneath the line name, and every step of the
     font ladder drops **1 px** per the operator's blanket instruction: name **12/11/10 → 11/10/9** by line
     count, qualifier **9 px** (8 px on a 3-line interchange).
  3. **`StationCard`** imports `LINES_BY_CODE` to supply the canonical name.
