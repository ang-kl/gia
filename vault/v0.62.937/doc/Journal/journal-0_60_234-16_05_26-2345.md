# Journal — soleat v0.60.234

> Operator, following up on PR #481's Cuisine TMA map pins: *"I [have a] hard time to click
> the pin inside the Google map of Cuisine TMA, should the pin be larger px and not to change
> colour when selected. Also use white on icons (Michelin, Pet Paw)."* Operator confirmed (via
> the planning prompt) the pin size = **22px** and the selected pin should have **no change at
> all** (the InfoWindow popup is the selection cue).

## New

### [HDR] #202 | 23:45:00 SGT 16-05-26 | v0.60.234 — Cuisine TMA pins: 22px tap target, no selected-state change, white glyph icons | 1 file | 1 PR | 1 build |

- **[INTENT]** PR #481 reduced the Cuisine TMA map pins to an 18px dot, with the focused venue
  enlarged to 24px + recoloured orange, and Michelin/Pet/dessert venues showing a multi-colour
  emoji on a white circle. The operator found the 18px dot **hard to tap**, disliked the
  colour change on selection, and wants the glyph icons rendered white.

- **[DELTA]**
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** — `cuisinePinNode` rewritten:
    - Signature `cuisinePinNode(glyph, focused)` → `cuisinePinNode(glyph)` — the `focused`
      argument is gone; a selected pin is now visually identical to the rest (no colour bump,
      no size bump). The `const focused` line in the `syncMarkers` venue loop is removed; the
      call site passes `glyph` only.
    - Size: a fixed **22px** (was 18px normal / 24px focused) — a larger, easier tap target.
    - Colour: every pin is the standard green `#34C759` dot with the dark `#1c1c1f` border —
      the orange `#FF9500` focused fill/border is dropped.
    - Glyph venues (Michelin ✳️ / Pet 🐾 / dessert 🍮): the emoji is drawn in a child
      `<span>` with `filter:brightness(0) invert(1)`, rendering it as a solid **white
      silhouette** on the green dot (was a multi-colour emoji on a white circle). The filter is
      scoped to the glyph span so the dot's green fill and border are unaffected.
  - `package.json` `0.60.233 → 0.60.234`; this Journal entry (#202); `doc/.serial-state.yml`
    bumped + re-anchored.

- **[VERIFICATION (sandbox)]**

  ```bash
  $ npm run build:cuisine    → vite build OK
  $ npm test -- --run        → 1913 passed (1913)
  ```

  (`cuisinePinNode` is a DOM-builder helper with no unit test, consistent with its prior
  state; the vite build exercises the JSX.)

- **[STATUS]** STAGED → PROD on next Railway deploy. The Cuisine TMA bundle ships in
  `public/cuisine/`.

- **[TEST]** Post-deploy, Cuisine TMA → map: pins are 22px and easier to tap; tapping a pin
  opens its InfoWindow but the pin itself does not change colour or size; Michelin / pet-allowed
  / dessert venues show a white star / paw / pudding silhouette on the green dot.

- **[KNOWN GAPS]**
  - The white-silhouette effect relies on the CSS `filter` trick; it renders correctly in the
    Chromium/WebKit Telegram WebView. Plain (no-glyph) venues are an unmarked green dot, as
    before.
  - This change rides on the same branch/PR as v0.60.233 (the LRT/CCL geometry + map styling
    fixes) — both came out of the same operator map-review session.
