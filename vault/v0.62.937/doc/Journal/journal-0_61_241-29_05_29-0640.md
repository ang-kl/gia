  squeezing the truncated location label ("SPH Me…") on narrow
  Telegram WebView widths; surface the same info as a downward-
  pointing speech bubble above the pill (matches the v0.61.174 🔍

  the OTHER city-dropdown was BOTH resetting itself to "— —" after a
  pick AND auto-firing a search — operator wants the picked code to
  stay visible and the search to wait for an explicit 🔍 tap.

- **[DELTA]**

  **1. `web/cuisine/src/v2/components/LocationField.jsx`** —
     SG/JB resting pill (the non-`OTHER` branch returned from line
     201-onward) now renders the speech bubble as an
     absolutely-positioned sibling above the pill:
     ```jsx
     {!open && suffix && (
       <div aria-hidden="true"
            className="absolute bottom-full left-1/2 -translate-x-1/2 mb-1.5 select-none pointer-events-none z-10">
         <div className="relative bg-tg-accent text-tg-bg text-[10px] font-semibold rounded-2xl px-2.5 py-1 whitespace-nowrap shadow-md">
           {suffix} · {lang === 'fr' ? 'touchez pour changer' : 'tap to change'}
           <span className="absolute left-1/2 -translate-x-1/2 -bottom-1 w-2 h-2 bg-tg-accent rotate-45" />
         </div>
       </div>
     )}
     ```
     The pill's inner button drops the inline `· {suffix}` and
     `tap to change` spans — it now wraps just the location label
     (`{resting}`) inside `flex-1 text-left text-sm truncate`. The
     same bubble is added to the OTHER compact resting pill (the
     `showCompact` branch), wrapped in its own `relative` parent
     so the absolute bubble anchors correctly.

  **2. `web/cuisine/src/v2/components/LocationField.jsx`
     `OtherLocationPicker.onCityPick`** — two changes:
     - Removed the trailing `setCityPick('')` so the closed
       `CityDropdown` keeps showing the picked code (`KUL`, `BKK`,
       `TYO`, …). Previously the dropdown reverted to `— —` after
       a pick because the local `cityPick` state was wiped.
     - The `onSelect` payload now carries `noAutoFire: true`. The
       JB / SG Autocomplete + free-text picks intentionally do NOT
       set this flag, so they continue to auto-fire (their flow
       has an explicit search gesture).

  **3. `web/cuisine/src/v2/App.jsx` `onLocationSelect`** — the
     v0.61.237 `Promise.resolve().then(() => runSearch(state, …))`
     is now gated on `!p.noAutoFire`:
     ```js
     if ((p.label || '').trim() && !p.noAutoFire) {
       Promise.resolve().then(() => runSearch(state, { lat: p.lat, lng: p.lng }));
     }
     ```
     `setLocationAnchor` + `setSearchCenter` + `saveUserLocation`
     still fire — the anchor moves and the bot's /location cache
     is updated; only the search request is held back so the
     operator can tweak filters before tapping 🔍.

     Also wrapped the `<LocationField …/>` in a `<div className="mt-7">`
     so the speech bubble (rendered via `absolute bottom-full mb-1.5`)
     has ~28 px of margin above the pill to overhang into. Without
     this the bubble would collide with the `🇸🇬 SG / MY JB / 🌏
     Others` region pill row, which sits just `gap-2` (8 px) above
     the LocationField in the root flex column.
