  **Sub-arc 1: R.E.D ambiguity spine (v0.59.54 → v0.60.4, captured in `vault/v0.60.41/`)**
  - `gemini-client.js` — new `disambiguateTerm({text, ctx})` deterministic dictionary (no LLM). Returns `{kind, chosen, alternatives, confidence, isTourist, disclosure, searchSpec}`.
  - `gemini-client.js` — new `AMBIGUOUS_DISHES` seed list (≥30 entries): carrot cake (SG savoury vs Western dessert), bak kut teh (Teochew vs Hokkien), goulash (HU/CZ/AT), wonton (Cantonese/Sichuan), laksa (Penang vs SG), satay (MY/ID/SG), etc. Each entry has `{match[], kind, interpretations[]}` with per-interpretation `{id, label, cuisine, flag, defaultIn[], signals[]}`.
  - `index.js handleSearchTurn` — disambig pre-step before classifySearchIntent. HIGH/MEDIUM confidence override `intent.searchTerm` to `disambig.searchSpec.searchPhrase` + prepend disclosure. LOW confidence → render both interpretations, no Places call.
  - `search-conversation.js` — sticky-disambig threading via `setLastDisambig` / `lastDisambig` in conversation state.
  - `__tests__/disambiguate-term.test.js` — 34 tests covering schema, high/medium/low confidence, modifier dominance, locale defaults, sticky, tourist heuristic, language-of-query is NOT a nationality signal.
