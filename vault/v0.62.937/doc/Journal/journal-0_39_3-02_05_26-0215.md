## New

### [HDR] #82 | 02:15:00 SGT 02-05-26 | v0.39.3 | n/a kb | n/a lines
- **[INTENT]** Two user-supplied diffs bundled into one patch release:
  1. `ver.js` — adds a `build <ref>` row to the `/ver` health-check output so we can confirm WHICH commit Railway is actually running, not just the package.json version. The Telegram-webview-cache + Railway-deploy-skip class of bugs (e.g. v0.31.1 → v0.31.2 staleness debacle) becomes diagnosable at-a-glance.
  2. `web/cuisine/src/App.jsx` — `buildPayload()` now includes `lang: getLanguage()` in the request body. The server already accepted `lang` since v0.32.0 (threaded into Stage A `prompt-builder` + NL classifier), but the TMA wasn't sending it. Now it does.
- **[DESIGN]**
  1. **NEW `detectBuildRef()`** in `ver.js`. Reads (in priority order):
     - `process.env.RAILWAY_GIT_COMMIT_SHA` (Railway sets this on every deploy)
     - `process.env.SOURCE_VERSION` (Heroku-style)
     - `process.env.GITHUB_SHA` (CI runner)
     - Falls back to `git rev-parse --short HEAD` via `execSync`
     - Ultimately `'unknown'` if even git fails (e.g. shallow clone with no `.git`)
  2. Slices to 12 chars max so the output stays compact.
  3. **`runHealthCheck`** prepends `build <ref>` line right under `soleat v<version>`. Two-line header now:
     ```
     soleat v0.39.3
     build de653b6
     
     Telegram     ...
     ...
     ```
  4. `child_process` import added at module top.
- **[DELTA]** (per the two user-supplied diffs)
  - **`ver.js`** — `+ require('child_process')`, `+ detectBuildRef()` helper, `+ build <ref>` line in `runHealthCheck` output array.
  - **`web/cuisine/src/App.jsx`** — `+ getLanguage` import from `./api/tg.js`, `+ lang: getLanguage()` field in `buildPayload()`'s `payload` object.
  - **`package.json` + `web/cuisine/package.json` + `web/menu/package.json` + `web/hawker/package.json`** — version 0.39.2 → 0.39.3.

- **[STATUS]** PROD — auto-deploys with the next Railway build. Behavioural change: `/ver` reply gains one new line.
- **[POST-DEPLOY VERIFICATION]**
  1. `/ver` shows `soleat v0.39.3` immediately followed by `build <12-char-sha>`.
  2. The sha should match the head of `main` (or whatever Railway last deployed). Compare against `git log origin/main --oneline | head -1` to confirm.
  3. After a future deploy, the sha changes — confirms Railway actually swapped the running build.

- **[KNOWN GAPS]**
  - **`execSync` is synchronous** — runs at every `/ver` invocation. Fast (~20 ms) but blocks the event loop briefly. Acceptable for a health-check command. Future patch could memoise the result at module load if `/ver` traffic spikes.
  - **`SOURCE_VERSION` is Heroku-specific** — included for portability if the app ever moves off Railway. Harmless on Railway (env not set).
  - **No commit-message preview** — just the SHA. Future patch could add the first 50 chars of `git log -1 --pretty=%s` if the SHA alone isn't enough context.
