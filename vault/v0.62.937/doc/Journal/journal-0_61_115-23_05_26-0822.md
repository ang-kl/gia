# Journal — soleat v0.61.115 (Attractions / Carpark zoom tiers — spec slice 1)

> Operator posted a 2-layer Google Maps UI/UX spec — Attractions (`⚝`
> toggle) and Carpark (`🅿️` toggle) — covering default vs. detailed
> marker states by zoom, collision degradation, a clustering engine
> with `N ⚝` / `5 🅿 here` text elements, and Header / Metadata /
> Transit / Actions card layouts.
>
> Two contradictions / undefined terms were surfaced and confirmed
> back to the operator before any code moved:
>
> 1. **Carpark threshold vs example.** Spec text: "If the density …
>    exceeds 7 markers … collapse … For other numbers exceeding the
>    threshold, dynamically update the count prefix." But the worked
>    example is "exactly 5 carparks … `5 🅿 here`" — 5 is below the
>    declared threshold of 7.
> 2. **Carpark visibility boundary.** Detailed-label state starts at
>    `z >= 15`, but the visibility boundary ("do not uncluster …
>    until zoom 14 or higher") starts at `z >= 14` — a one-level gap
>    where unclustered carparks would be in icon-only mode.
> 3. **"Cluster tile" undefined.** Pixel grid? Map-area? Zoom-
>    dependent? Google's MarkerClusterer default is a 60 px grid but
>    the spec doesn't pin one, and the value decides almost everything
>    about cluster behaviour.
> 4. **"Lower-priority markers" undefined.** Spec calls for dropping
>    "lower-priority" markers on collision in the icon-only band but
>    doesn't define what makes a marker lower priority.
>
> Operator chose **"Implement what's unambiguous now"** over "refine
> spec first" or "save as design doc". This PR lands only the slice
> that has no internal contradiction; the clustering, lower-priority-
> drop, and card layout changes are tracked under `[KNOWN GAPS]`.
>
> This entry is commit 322 / journal 315 / build 118, off `main` at
> v0.61.114 (#606).

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (+ byte-identical
    copies in `web/hawker/src/lib/mapOverlays.js` and
    `web/transport/src/lib/mapOverlays.js`) — the `applyVisibility`
    apply pass gains two rules:
    1. In the existing `it._tiered` branch (shared by Attractions /
       Clinics / Police / Hospitals), the per-layer override
       `if (name === 'attractions' && t === 'dot') t = 'glyph'`
       floors the resolved tier to `glyph` for attractions at every
       zoom below 14. Other amenity layers keep their `z<12 → dot`
       band by operator scope ("Attractions Layer" only). The
       v0.61.97 collision-demote-to-glyph at the `label` tier is
       unchanged.
    2. In the `name === 'carpark'` branch, a new `zoom >= 15` path
       renders `amenityLabelNode('🅿 ' + name, ...)` instead of the
       size-laddered icon. Carpark labels share the `placedLabels`
       pool with attractions, so the two layers don't visually
       overlap each other at `z >= 15`. On overlap with an
       already-placed label the carpark falls through to the
       existing icon path (size ladder + collision-shrink),
       matching the spec's "degrade … back to the isolated 🅿
       icon" rule. The rendered-content signature now keys on
       `label:<name>` vs `icon:<size>` so the apply pass only
       updates `marker.content` when the rendering actually
       changes.
  - **`public/app.js`** — the standalone `/app/map` page is a plain
    IIFE without the ES-module overlay library, so the same logic
    is re-implemented compactly:
    - New `overlayLabel(glyph, name)` — the labeled pill used by
      both layers at the high-zoom tier; mirrors `amenityLabelNode`
      in the TMA mapOverlays.
    - New `pxBetween(a, b, mpp)` — the equator-flattened pixel
      distance helper used by both overlap checks.
    - `renderClippedLayer` (the `key === 'carpark'` arm): at
      `zoom >= 15`, run the overlap check first; on no clash
      record the label in `placedLabels` and use `overlayLabel`,
      else fall through to the existing `carparkPin(carparkSize)`
      icon path with the v0.61.105 size shrink.
    - `renderMenuLayer` (the `attractions` arm): at `zoom >= 14`
      build a `placedLabels` array per-render; on no clash use
      `overlayLabel('⚝', f.name)`, else fall through to the
      existing `overlayPin(L.glyph)` icon.
  - **`package.json`** — `0.61.114` → `0.61.115` (PATCH).

- **[NOT IN THIS PR — DEFERRED]**
  - **Clustering engine.** Spec says "If the density within a
    single cluster tile exceeds 7 markers … collapse into `7 ⚝` /
    dynamically update the count prefix"; the carpark example
    contradicts the threshold (`5` < `7`) and "cluster tile" is
    undefined. Needs operator clarification before any code.
  - **Lower-priority icon drop (z<15 carpark / z<14 attractions).**
    Spec says "dynamically drop lower-priority markers to ensure
    adequate breathing room" but doesn't define priority. The
    v0.61.105 carpark size-shrink-on-collision (4 px down,
    floor 8 px) is retained for `z<15`; the v0.61.97 attraction
    label-demote-to-glyph is retained for `z>=14`. Drop-on-
    collision-in-icon-band is **not** implemented.
  - **Card layouts.** Spec table for Attractions (Header /
    Metadata / Transit / Actions with bare website) is **leaner**
    than the v0.61.109 `attractionInfo` popup (rating, address,
    hours week, contact, wheelchair, two stations, website,
    Instagram) — applying the spec table verbatim would drop info.
    Carpark card spec asks for "Google Maps ↗" action which the
    bare `carparkInfo` popup lacks. Both held until the operator
    confirms the table is additive, not a replacement.
  - **Visibility boundary for Carpark.** The spec's z14 vs z15
    boundary mismatch is left as-is; current `/app/map` carpark
    visibility gate stays at `z >= 14` (with the new label at
    `z >= 15`).
