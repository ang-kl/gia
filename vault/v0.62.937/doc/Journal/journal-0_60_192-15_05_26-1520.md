- **[DELTA]**

  **`index.js`** — three coupled fixes.

  *(a)* `handleMichelinSearch` (line ~6210) — Places FIELD_MASK extended with three v0.60.183-shipped fields:
  ```js
  // v0.60.192 — operator: Michelin Copy-All cards were missing the
  // v0.60.183 price+pet line because the Michelin FIELD_MASK never
  // requested these fields.
  'places.priceRange', 'places.addressComponents', 'places.allowsDogs'
  ```
  Marginal Places New API cost per call (paid fields).

  *(b)* Happy-path venue construction (line ~6311) now passes-through the three normalised fields:
  ```js
  priceRange: require('./pipeline').normalisePriceRange(placesData?.priceRange),
  country:    require('./pipeline').extractCountryCode(placesData?.addressComponents),
  allowsDogs: placesData?.allowsDogs === true,
  ```
  Helpers re-used from `pipeline.js` via the new exports (see below) so the normalisation logic stays single-sourced.

  *(c)* `handleMichelinSearch` post-filter (line ~6570) now calls `enrichPriceRangeDisplay(csChatId, filteredVenues)` immediately after `appendSeenSet`. Mirrors the cuisine-chip search path (line ~10467). Best-effort try/catch — failure strips the price line silently without breaking the rest of the response.

  *(d)* `/api/cuisine/copy-all` (line ~8369) — variant `'detail'` → `'detail-with-sanctuary'` (T1). One-token diff per the v0.60.190 plan; the `🌿 Sanctuary read` block emits only when `venue.sanctuaryRead` is present (sparse today — populated by /api/cuisine/copy-one only; DF-87 will populate it on /api/cuisine/search responses too, after which Copy-All gets the full screenshot-style format automatically).

  **`venue-templates.js`** — `formatVenueBlock` (line ~239) now appends the Michelin annotation row after the maps URL, mirroring `formatTechniqueVenueBlock`'s cross-ref at index.js:5251:
  ```js
  try {
    const michelin = require('./michelin-2025');
    let entry = null;
    if (p.michelinCategory) entry = { category: p.michelinCategory, name: p.michelinName || p.name };
    else entry = michelin.findMichelinMatch(p.name, p.area || p.address || '');
    if (entry) {
      const line = michelin.formatMichelinLine(entry);
      if (line) lines.push(line);
    }
  } catch (err) { console.warn(...); }
  ```
  Upstream-set `venue.michelinCategory` (handleMichelinSearch populates it) short-circuits the lookup. Other call sites without a pre-set category fall back to a name + area cross-ref against the curated michelin-2025.js list — same logic that already drives /s + /c chat results.

  **`pipeline.js`** — `module.exports` now includes `normalisePriceRange` + `extractCountryCode` so index.js's Michelin path can call them without duplicating the body. Single-sourced normalisation = no drift between cuisine-chip and Michelin venue shapes.
