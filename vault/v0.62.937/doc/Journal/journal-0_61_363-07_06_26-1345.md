## New

### [HDR] #563 | 13:45 SGT 07-06-26 | v0.61.363 — per-device cache token (location + country-pref) | 6 code files + 2 tests | 1 PR | 2 builds |

- **[INTENT]** Stop concurrent devices on one Telegram account from clobbering each other's cached location / country. Each device keeps its own server-side slot.

- **[CONFIRMED REAL]** Location was cached at `loc:<hash(chatId)>` and `country-pref:<chatId>` — **per-user, not per-device** — so 5 devices shared one slot (last writer wins). The **live search was already correct** (each request carries its own `lat/lng`); only the persisted **seed** + the OTHER-picker pref clobbered. My own **v0.61.362** sync country-pref write had *amplified* this. Telegram `initData` exposes **no persistent device id**, so the fix needs a client-generated token.

- **[MECHANISM]**
  - **`device-id.js` (NEW, both TMAs)** — a stable per-device token: `crypto.randomUUID()` (charset-safe, ≤32), persisted in `localStorage` (`gia_device_id`), memoised. Sent with every request.
  - **`location-cache.js`** — `sanitizeDeviceId` + `locKey`; `setUserLocation(…, opts.deviceId)` writes **both** the chatId-level key (bot-chat default + new-device seed) **and** `loc:<hash>:dev:<id>`; `getUserLocation(redis, chatId, deviceId)` reads the per-device slot **first**, falling back to the chatId-level key.
  - **`country-pref.js`** — `getUserCountryPref` / `setUserCountryPref` gain a `deviceId` arg with the same dual-write + read-fallback (`country-pref:<chatId>:dev:<id>`).
  - **`index.js`** — `readDeviceId(req)` (JSON body `deviceId` | `X-Device-Id` header | query) threaded into `/api/menu/set-location` (3 writes + the geocode read), `/api/cuisine/set-location`, `/api/cuisine/user-location` read, `country-pref` GET + POST, and the cuisine `/search` cached-region read.
  - **Clients** — Cuisine `postJson` injects `deviceId` in the body and `getJson` adds the `X-Device-Id` header (covers every `api.js` call); Menu's inline fetches (App.jsx set-location / user-location / country-pref ×several + `LocationFieldMenu` country-pref GET header / POST + set-location) each carry it.
  - **Bot-chat** (no device) is unchanged — chatId-level keys. The failure mode degrades to **today's** behaviour (the per-device read falls back).
