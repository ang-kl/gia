## New

### [HDR] #199 | 22:00:00 SGT 16-05-26 | v0.60.231 — Build E 5e: station-exit ingestion script (data.gov.sg poll-download) | 2 files | 1 PR | 1 build |

- **[INTENT]** Build E 5e adds the per-exit point dataset that complements the per-station coords already in `data/mrt-coords.json`. The operator supplied the data.gov.sg OpenAPI `poll-download` sample for dataset `d_b39d3a0871985372d7e1637193335da5`. Goal: a repeatable fetcher that pulls the LTA "MRT Station Exit (GEOJSON)" dataset and converts it to a station-keyed JSON the Train TMA map can join against.

- **[DELTA]**
  - **`scripts/fetch-station-exits.js`** — NEW one-shot fetcher (modeled on `scripts/fetch-hawker-coords.js`). Implements data.gov.sg's two-step `poll-download` flow: `GET /v1/public/api/datasets/<id>/poll-download` → `{ code, data.url }` → `GET data.url` → GeoJSON; retries while `code !== 0` (export still being prepared). Parses both LTA GeoJSON attribute shapes — flat `properties` keys *and* the HTML `<table>` inside `properties.Description` (where LTA actually stores `STATION_NA` / `EXIT_CODE`). Reconciles each feature's station name against `data/mrt-coords.json` keys via a shared `normalise()` so exits join to the right station; unmatched names are title-cased and logged. Output `data/mrt-station-exits.json` — `{ "_meta": {...}, "<Station>": [ { exit, lat, lng }, ... ] }`, stations sorted, exits ordered by label. Flags: `--dry`, `--from-file <path>` (parse a locally downloaded GeoJSON), `--raw-out <path>` (also save the raw GeoJSON).
  - `package.json` `0.60.230 → 0.60.231`; this Journal entry (#199); `doc/.serial-state.yml` bumped + re-anchored.

- **[KNOWN GAPS]**
  - **`data/mrt-station-exits.json` is not in this PR.** This build environment's egress proxy returns `403 / "Host not in allowlist"` for every data.gov.sg host (`data.gov.sg`, `api-open.data.gov.sg`, `api-production.data.gov.sg`) via both `curl` and `WebFetch`, so the dataset cannot be fetched here. The script is the deliverable; the data file lands in a follow-up commit once fetched.
  - The Train TMA map wiring that consumes `data/mrt-station-exits.json` (rendering exit markers) is deferred to that follow-up — it can't be built or verified without the data file.
  - GeoJSON attribute keys (`STATION_NA`, `EXIT_CODE`) are LTA's documented field names; the parser also accepts common aliases, but the exact keys should be confirmed on first real run.
