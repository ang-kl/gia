## New

### [HDR] v0.62.598 — Transport TMA: a rich Google-Maps-style StationCard (first/last train, terminus links, crowd, amenities)

- **[INTENT]** Continuation of the Transport-TMA port. Operator's card spec:
  *"display the station info like the Google map info card + more information … stack two cards into
  one … the current NEL station code NE1 info (along with CC29 information), and bottom card = CC29
  station code (last train, first train, operating status, final stop station code with hyperlink) …
  then exits information, bus stop information, taxi stand etc. all hyperlinks without the underline
  plus nearest hawker centre … The card strip will be the station name with colour of the line as the
  background. If more than one card, then the background be white."* Plus the follow-up:
  *"Include crowd status. Bus Stops, Taxi Stands, hawker centre hyperlinks."* This slice builds that
  card and wires it into the existing layout (the responsive carousel / two-panel reuse is the next
  slice — the card already exposes the `onTap`/`active`/`glass`/`compact` + `data-station-card` hooks
  for it).

- **[DELTA — server]** `transport.js` gains a pure, exported `nearestHawkerCentre(coords, lat, lng)`
  (straight-line nearest over the 122-centre vault coord map). `index.js`
  `/api/transport/station-context` now attaches **`nearestHawker`** (`{ name, lat, lng, distanceM }`)
  to its payload, computed via that helper from `data/hawker-coords.json` — so the card gets exits,
  bus stops, taxi stands **and** the nearest hawker from a single fetch.

- **[DELTA — client]** New **`web/transport/src/components/StationCard.jsx`** + pure
  **`web/transport/src/lib/station-card-utils.js`**:
  - **Name strip** = the line's brand `hex` for a single-line station, **white** for an interchange
    (with a readable-text-colour pick for light future-line hues); shows the per-line code chips.
  - **Stacked per-line-code sub-cards** — one per `station.lines[]` entry: the `station_code` chip
    (line colour), `line_name`, the live **operating-status** swatch + label
    (`statusByLine[line_code]`), and one **first/last-train row per direction** from
    `first_last_train` — the non-uniform `timings` keys are read **defensively**
    (`first_weekday`/`first_mon_sat` … `last_weekend_ph`), a **terminal** direction (all-null timings)
    shows "Terminates here", and a `towards_<slug>` direction resolves to its **terminus** whose CODE
    is an **in-app hyperlink** (focuses that station on the map).
  - **Crowd status** — worst level across the station's platform codes, dot + label.
  - **"Around the station"** — **exits** (from the rich `station.exits`), **bus stops** (context feed,
    with a fallback derived from each exit's `nearest_bus_stop`), **taxi stands**, and the **nearest
    hawker centre** — all as **underline-free** Google-Maps hyperlinks.
  - Wired into `App.jsx`: loads `/api/geo/stations` (rich, keyed by name) + `/api/transport/stations`
    (coarse, for terminus resolution + code→station lookup) + `/api/transport/crowd` once, and
    `/api/transport/station-context` per focused station; renders `StationCard` when a station is
    focused; `handleFocusStationCode` focuses a terminus by its code. `LineStatusPanel` gains a
    `hideStationDetail` prop so its now-duplicated basic selected-station block is suppressed while the
    card is shown (its line status + station picker stay).
  - **i18n**: +18 `mrt.*` keys (first/last train, weekday/weekend, terminus, around-the-station,
    nearest-hawker, station-info, taxi, and the compass/loop direction labels) — **en/fr**; the other
    six locales fall back to `en` (the accepted new-feature pattern, per the v0.62.595 closure tab).
