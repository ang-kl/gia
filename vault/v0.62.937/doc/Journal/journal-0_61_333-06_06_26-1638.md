- **[INTENT]** v0.61.330 (PR #839) had stamped every SG entry with `city`/`country`/`year` and added header notes to `michelin-2025.js`, then v0.61.331 pulled SG through the unified venue loader. The operator wants SG returned to its **original standalone form** and decoupled from the loader, with the regional files reorganised to a flat `{CC}-michelin.js` layout at the repo root and the real Malaysia data finally migrated in. This PR does exactly that and supersedes PR #841 (which had put MY data under `michelin/my.js`).

- **[MECHANISM]** SG content is restored byte-for-byte from the commit BEFORE #839 merged (`baseRefOid 1ba3c9b0`, fetched via the GitHub contents API at that ref) and saved as `SG-michelin.js`; `michelin-2025.js` is deleted. Every code importer of `./michelin-2025` is repointed to `./SG-michelin`. The Malaysia migration is deterministic: the 130 flat rows are grouped by lowercased/trimmed `address`; each group becomes one venue with `id = my-{iata}-{kebab(name)}` (KL→`kul`, George Town→`pen`), current `name`/`address`/`postal`/`cuisine`/`vegetarian`/`halal` taken from the LATEST-year row, and `awards:[{year,category}…]` sorted by year. The one cross-edition rename (Sri Nirwana Maju 2025 → Nirwana 2026, same address) collapses to a single venue named `Nirwana` with `formerNames:['Sri Nirwana Maju']`; `Heun Kee Claypot Chicken Rice (Pudu)` is marked `status:'closed'`. Venues serialise with unquoted keys but values left JSON-escaped (`JSON.stringify(v).replace(/"([a-zA-Z_]\w*)":/g,'$1:')`) so apostrophes in names survive. The loader drops all SG-flat handling and loads only the eight root country tables; `hasMichelinData('Singapore')` is now FALSE from the loader (intended — SG is on its own path).
