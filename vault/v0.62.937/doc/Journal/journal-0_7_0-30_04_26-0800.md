## New

### [HDR] #10 | 08:00:00 SGT 30-04-26 | v0.7.0 | n/a kb | n/a lines
- **[INTENT]** Surface the typed-place path that was implicit in the bot's flow but not advertised in the prompt. Tighten walking radius to 200 m per Human Lead's revised wording. Update prompt copy.
- **[DELTA]**
  - **`vibe-suggest.js`** — added `geocodeQuery(text)` that runs Places `searchText` with `"<text> Singapore"` and a tight FieldMask (id, displayName, location, formattedAddress). Returns `{lat, lng, name, address, placeId}` or null on miss. `SEARCH_RADIUS_M` 300 → 200.
  - **`index.js`** — free-text handler now consumes any pending sanctuary flow BEFORE falling through to the Topic Gatekeeper. On a hit, the user's text is treated as a place query → geocoded → cached as user location → `runFlow(category)` runs. On a miss, the pending flag is restored so the user can retry. Prompt copy updated to "Please tap to share your location, or type a place name and Gia will search within 200 m of it." Location-handler "within X" copy 300 → 200.
  - **`package.json`** — version → 0.7.0.
- **[RISK]** Low —
  - **Geocoding ambiguity.** "Chinatown" hits Places fine; very generic strings ("food", "near me") will geocode to whatever Places thinks is nearest. The 200 m radius then constrains the picks to that geocoded centre. Acceptable; the failure mode is "weird picks but at least real venues."
  - **Pending consumption ordering.** The free-text handler consumes pending BEFORE the Gatekeeper. If a user sends `/eat`, then changes their mind and asks "what's the weather?", the typed text is interpreted as a place lookup ("weather Singapore") rather than a Gatekeeper query. Mitigation: 5-min TTL on pending; user can wait it out or send `/start` to reset.
  - **One additional Places call per typed-place message.** Within existing G4 quota; negligible at single-user scale.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]** Manual:
  1. `/eat` from a fresh chat → prompt now reads "Please tap to share your location, or type a place name and Gia will search within 200 m of it."
  2. Type "Chinatown" → bot replies "Looking up Chinatown…" → "Centred on Chinatown. Looking for lunch within 200m…" → 3 picks.
  3. Type something nonsensical like "asdfgh" → bot replies "I couldn't place asdfgh. Try a building or street name…" → user types again → flow proceeds.
  4. Tap 📍 Share my location → flow proceeds with native GPS as before.
  5. Tap ⛔ Use Raffles Place default → flow proceeds with Raffles default as before.
  6. Send a free-text message WITHOUT a pending flow ("hello", "what should I eat?") → falls through to the Gatekeeper as in v0.6.0.
