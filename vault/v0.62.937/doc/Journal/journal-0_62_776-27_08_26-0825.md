- **[THE FOUR THINGS WORTH REMEMBERING]**

  1. **A silent success is indistinguishable from a silent failure.** `[AMD-42]` shipped three Green
     Star venues that loaded, passed every assertion, and **rendered nowhere** — nothing threw,
     nothing logged. The data was in the dataset and invisible to a reader. #1751's verification
     therefore spanned all four layers the change touched (loader, handler, both card renderers, the
     sort), because a partial merge could land the data and drop the render — or the reverse — and
     every count would still look plausible.
  2. **A blocker can break in a language you did not read.** Shenzhen's Bib sat at 6 of 21 from
     `[AMD-40]` because the release "did not enumerate them". It did — in Chinese.
  3. **Assert absences, not just arrivals.** #1752's check confirmed the Shenzhen entry had **gone**
     from `KNOWN_DELTAS`, not merely that rows had arrived. A merge carrying the rows without the
     removal leaves a gap recorded against data that no longer has one, and every count still reads
     correct.
  4. **A single fetch is a reading, not a fact.** During #1752's merge a `git fetch` nine seconds
     before the squash returned the previous head, which for those nine seconds looked exactly like
     "not merged yet". Reporting from it would have been confidently wrong.
