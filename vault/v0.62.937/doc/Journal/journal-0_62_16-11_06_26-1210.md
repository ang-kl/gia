## New

### [HDR] #662 | 12:10 SGT 11-06-26 | v0.62.16 — derive --tg-border (color-mix, ~3:1) in all 5 TMAs so dark-mode borders are visible | web/{cuisine,hawker,menu,transport,oversight}/src/styles.css | 1 PR | 1 build |

- **[BUG — dark-mode borders invisible (root cause)]** `--tg-border` is **never set** — not by
  Telegram (its `themeParams` carries no border colour) and not in any TMA's CSS. So every
  `border-tg-border` fell back to the Tailwind config default **`#2a2a2e`**, which on the dark card
  `#1c1c1f` / bg `#0e0e10` sits at **~1.2:1 contrast = effectively invisible**. Confirmed across **all
  5 TMAs** (148 `border-tg-border` usages: cuisine 87, menu 21, transport 16, oversight 13, hawker 11).

- **[DELTA — fix (mirrors the v0.57.14 --tg-hint precedent)]** Derive `--tg-border` in each TMA's
  `styles.css` from text + bg via `color-mix`:
  `color-mix(in srgb, var(--tg-text, #f5f5f7) 38%, var(--tg-bg, #0e0e10) 62%)`.
  - **38% text / 62% bg** lands a **quiet ~3:1 grey** (WCAG AA for non-text UI components) against the
    lighter `--tg-card` (the harder case) in **both light and dark** themes.
  - **Colour-blind safe by construction**: the border is **luminance-derived** — it signals by
    lightness, **no hue at all** (no red/green). Honours the operator's deuteranopia/protanopia bar.
  - `cuisine` / `hawker` / `transport` / `oversight`: inserted right after the existing `--tg-hint`
    `:root` line. `menu` had **no `:root` block** → added one. `tg.js` never syncs `--tg-border`, so the
    CSS rule always wins.
