## New

### [HDR] #696 | 08:05 SGT 12-06-26 | v0.62.43 — cuisine "What to order" plate (Phase 1) | dish-food-group.js (new) + index.js + web/cuisine (ArrivalPlate.jsx, App.jsx) + tests | 1 PR | 1 build |

- **[INTENT]** Show the unique dishes of the SELECTED cuisine before the user picks an eatery,
  grouped so a 30-dish (or 164-dish Singaporean) cuisine doesn't jam-pack.

- **[DELTA]**
  - **`dish-food-group.js`** (new, pure) — `foodGroupFor(name, kind)` curated keyword classifier
    (drinks read straight off NATION_OVERLAY's `kind:'drink'`; explicit per-dish OVERRIDES for the
    proof set; 'other' fallback) + `groupCuisineDishes(iconicDishes)` → `{ headliners:[first 3],
    groups:[{group,label{en,fr},dishes}] }` ordered ASCENDING by size, 'other' last. 12-group
    taxonomy (Noodles / Rice / Bread & dumplings / Soups / Grilled / Stews & curries / Seafood /
    Veg / Snacks / Sweets / Drinks / More).
  - **`index.js`** (`/api/cuisine/search`) — when exactly ONE non-Michelin/non-special cuisine is
    selected, build `payload.cuisinePlate = { mode:'cuisine', cuisineSlug, cuisineLabel, flag,
    explainer(touristExplainer), populationLow, headliners, groups }` from `getNationOverlay(slug)`
    + `groupCuisineDishes`. Pure in-memory, fail-open, no Places spend.
  - **`web/cuisine/src/v2/components/ArrivalPlate.jsx`** — new `plate.mode === 'cuisine'` branch:
    header "What to order in 🇬🇪 Georgian", cuisine-level 📜 explainer, optional "few spots here"
    (populationLow), 3 headliner rows (tap → 🔍 find eateries), then food-group sections (ascending)
    of dish chips (tap → same dish search). Reuses the existing row/`onTryDish` machinery.
  - **`web/cuisine/src/v2/App.jsx`** — new `cuisinePlate` state set from `r.cuisinePlate` on the
    search + NL paths; the Arrival-Plate slot renders `cuisinePlate || arrivalPlate` (cuisine takes
    precedence over the geo city plate). Falls back to the geo plate when no/▪combo cuisine.
  - **`__tests__/dish-food-group.test.js`** (new, 11 cases) — classifier (drink flag / overrides /
    keyword / other), grouping (headliner split, ascending order, thin cuisine), and integration
    against real Georgian / Japanese / Singaporean overlays (nothing dropped; <20% 'other').

- **[VERIFICATION (sandbox)]** `node --check` clean (index.js, dish-food-group.js); full suite
  **3404/3404** green (+11); `web/cuisine` build green. Georgian renders: headliners khachapuri
  adjaruli / khinkali / satsivi, then rice·sweet·grilled·stew-curry·bread-dumpling·veg sections.

- **[STATUS]** PR (rides the session branch). Railway on merge.

- **[KNOWN GAPS / Phase 2]**
  - **Names only.** The overlay carries dish NAMES + one cuisine-level explainer — no per-dish
    history or native-script `local`. So v1 has no per-DISH 📜 and no per-group local language
    (operator's earlier "local language + history clip per group" idea). Phase 2 = curate per-dish
    history + native names into the overlay (the city-plates depth), unlocking per-dish fact cards.
  - **Classifier coverage** is curated-keyword + proof-set overrides; long-tail cuisines bucket
    approximately and unmatched dishes land in "More" (operator-accepted). Verified: Georgian,
    Japanese, Malaysian clean; Singaporean 'other' ≈ 10%.
  - Single-cuisine only — a combo (Georgian + Japanese) shows no order-plate (falls back to geo).
