## New

### [HDR] #90 | 13:15:00 SGT 03-05-26 | v0.44.1 | n/a kb | n/a lines

- **[INTENT]** Per Human Lead, two changes on top of v0.44.0:
  1. **Add `/p d`** — search via data.gov.sg API.
  2. **Ensure cache is clear after each search/prompt result** — make the no-caching guarantee explicit in code AND visible in the response so the operator can confirm at a glance that the result is fresh, not stale.

- **[DESIGN]**

  1. **NEW handler `viaDataGovSg(prompt)`** in `prompt-query.js`:
     - Endpoint: `https://data.gov.sg/api/action/package_search?q=<prompt>&rows=5` (CKAN-style; stable; no API key required).
     - Returns up to 5 matching datasets with title, organization, dataset URL (`https://data.gov.sg/datasets/<slug>`), resource count, and a 200-char description snippet.
     - Output footer shows total match count vs displayed count: `(N total, showing top 5)`.
     - Try/catch wrapped — never throws across module boundary; returns `🔴 data.gov.sg error:` on HTTP/parse failure.
     - HANDLERS map updated: `{c, g, s, m, d}`.
     - Parser regex updated: `/^([cgsmd])(?:\s+(.+))?$/i`.
     - HELP text updated to list `d` and example `/p d hawker centre`.
     - Endpoint choice rationale: the v2 portal (data.gov.sg/datasets) lacks a stable public search API at the time of writing. The CKAN `package_search` endpoint is well-documented, returns deterministic JSON, and has been stable for years. If the v2 portal exposes a search API later, swap the endpoint.

  2. **No-cache guarantee — explicit + visible**:
     - **Code-level:** added a CACHE GUARANTEE block at the top of `prompt-query.js` documenting that no Redis lookup, no axios cache, no memoisation is used by any `/p` handler. The bot's `response-cache.js` (which caches `/cuisine` results for 30min) is NEVER touched by `/p` — different codepath entirely.
     - **Output-level:** new `noCacheFooter()` helper appends `\n\n🚫 no cache · <ISO 8601 SGT timestamp>` to every successful response. Operator sees at a glance the result is real-time, not cached. Errors KEEP their `🔴` marker without the footer (an error is its own freshness signal — appending "no cache" to a failure message would be confusing).
     - **Budget-aware:** new `withFooter(body)` helper trims the body before appending the footer so total output stays ≤ `MAX_OUTPUT_CHARS` (3800). Footer is guaranteed to appear even if the upstream response is huge.
     - All four prior handlers (`viaClaude`, `viaGemini`, `viaSearch`, `viaMaps`) updated to use `withFooter()` instead of the old `trim()` helper. The new `viaDataGovSg` uses it from the start.

  3. **NEW exports**: `viaDataGovSg`, `noCacheFooter`, `withFooter` (in addition to v0.44.0's exports).

- **[REUSED]**
  - `axios` (already top-level dep) — no new SDK for data.gov.sg.
  - Same try/catch + `🔴 <provider> error:` pattern as the other four handlers.
  - `MAX_OUTPUT_CHARS = 3800` (Telegram-safe ceiling, unchanged from v0.44.0).

- **[KNOWN GAPS / SCOPE CUTS]**
  - **`/p d` is dataset-metadata search only**, not dataset-content fetch. To pull actual data (e.g. live carpark availability, weather readings), use `weather.js` / `carpark.js` / etc. modules. Future v0.44.2+ could add `/p dr <resource_id>` to fetch a resource's CSV preview, but YAGNI for now.
  - **`/p d` uses the CKAN `package_search` endpoint**, not the new v2 data.gov.sg portal API. The v2 portal lacks a stable public search endpoint. If/when it ships, swap the endpoint.
  - **No-cache footer adds ~50 chars overhead** to every successful reply. Acceptable trade-off for visibility; if it ever becomes a problem, gate behind an env var (`PROMPT_QUERY_FOOTER=on`).
  - **Footer timestamp is SGT (UTC+8)**, not the operator's local time. Bot is Singapore-only so this is fine; future multi-region deploys would need to localize.
  - **Idempotency** — `/p` does NOT use the request-store idempotency added in v0.42.1 for `/api/cuisine-search`. Each `/p` invocation is independent. By design.
  - **Still not admin-gated.** Same caveat as v0.44.0 — "hidden" = not in autocomplete; no chat-ID gate. Defer until abuse observed.
