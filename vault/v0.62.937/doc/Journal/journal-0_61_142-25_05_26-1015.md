# Journal — soleat v0.61.142 (Cuisine TMA — durian chip uses operator-supplied PNG icon)

> Operator (right after PR #642 / v0.61.141 landed): uploaded a
> 204×192 durian clipart PNG via `data/IMG_2177.png` and said
> *"use this png for durian"*. The v0.61.141 PR had moved Durian
> from an amber-pill toggle (which used the 🥥 coconut emoji as a
> placeholder) into a regular catalogue chip — at which point the
> chip fell back to the default 🍽️ plate glyph (no FLAG_BY_SLUG
> entry for `'durian'`). This PR wires up a per-slug image-asset
> override so the durian chip renders the operator's PNG instead.

> `claude/v0.61.142-durian-icon` off `main` at v0.61.141

## New

### [HDR] #343 | 10:15 SGT 25-05-26 | v0.61.142 — Durian chip renders operator PNG via per-slug `imgFlag` override | 5 files | 1 PR | 1 build |

- **[INTENT]** Make the Durian catalogue chip carry the operator-
  supplied visual identity (a green spiky durian with a yellow-flesh
  detail) instead of the placeholder plate emoji. The asset matches
  the visual language the operator was using in the v0.61.126 amber-
  pill row (which used 🥥 coconut as the closest Unicode glyph for
  durian — there's no native durian emoji in Unicode).

- **[DELTA]**
  - **`web/cuisine/public/durian.png`** (NEW; blob reused from
    `data/IMG_2177.png`'s blob `9c3b29c…`, 5,155 bytes, 204×192
    PNG, 8-bit colormap). Served by Vite at `/app/cuisine/
    durian.png` (the cuisine TMA public root).
  - **`data/IMG_2177.png`** — REMOVED. The raw upload path was a
    placeholder; the canonical asset belongs alongside the other
    cuisine TMA visuals (`johor-flag.png` / `soleat-icon.png` /
    `soleat-logo.svg`). The blob itself is preserved in git
    history at `427924c:data/IMG_2177.png`.
  - **`cuisines-vault.js`**:
    - NEW `IMG_FLAG_BY_SLUG = { 'durian': 'durian.png' }` map. Per-
      slug image-asset overrides. Use sparingly — emoji is always
      preferred for performance + theme-respecting glyph
      rendering; reserve for cases where no Unicode glyph is a
      close match.
    - `getByCategory()` now attaches `imgFlag: IMG_FLAG_BY_SLUG[slug]
      || null` to each cuisine entry. Backwards compatible — every
      other cuisine ships with `imgFlag: null` and behaves exactly
      as before.
  - **`web/cuisine/src/v2/components/CuisineCategoryDrawer.jsx`**:
    - Chip renderer now branches: when `cu.imgFlag` is truthy,
      render an `<img src="/app/cuisine/{imgFlag}" width="16"
      height="16" class="w-4 h-4 object-contain">` inside a
      flex-shrink-0 16×16 wrapper, with an `onError` handler that
      hides the broken image and reveals the emoji-fallback
      sibling. When `imgFlag` is null/empty, the original emoji
      `<span>{cu.flag || '🍽️'}</span>` renders unchanged.
    - The `aria-hidden` semantics stay the same — the chip name
      is the only accessible-name; the icon is decorative.
  - **`package.json`** — `0.61.141 → 0.61.142`.
  - **`doc/.serial-state.yml`** — commit `354 → 355`, build
    `144 → 145`, journal `342 → 343`; re-anchored 25-05 '26
