### 4.5 Local working tree on iCloud Drive (O-22)

The repo lives inside iCloud Drive; iCloud's lazy-sync silently corrupts pack files, `node_modules/<dep>/package.json`, and partial-writes objects during fetch. Observed:

- `git diff origin/main` hangs > 60 s cold; subsequent runs fast.
- `git fetch` occasionally produces a pack flagged *"too short to be a packfile"* on next read (twice in this arc — v0.61.133→134 and v0.61.143→144 boundaries).
- `node_modules/rollup/package.json` + `node_modules/axios/package.json` returned `Invalid package config` in two separate sessions (v0.61.139 + v0.61.141).
- `vite build` runs in 2-4 s once `node_modules/` is warm; cold install 10-20× off-iCloud baseline.
- `vitest run` per-file ~700-900 ms; full-suite still hangs per O-21.

### 4.6 Plumbing-commit pattern

Used for **every PR** in the v0.61.128-147 arc (20+ PRs):

```bash
# 1. Snapshot files from origin/main into /tmp.
git show origin/main:<path> > /tmp/work/<basename>
# … edit each one with Edit/Write …

# 2. Build a scratch index on top of origin/main.
export GIT_INDEX_FILE=/tmp/work/index-staging
git read-tree origin/main
PARENT=$(git rev-parse origin/main)

# 3. Hash + stage each modified file.
for src,dst in <pairs>; do
  sha=$(git hash-object -w "$src")
  git update-index --add --cacheinfo 100644,$sha,$dst
done

# 4. Write the tree + commit + ref + push.
TREE=$(git write-tree)
COMMIT=$(git commit-tree "$TREE" -p "$PARENT" -m "<message>")
git update-ref refs/heads/<new-branch> "$COMMIT"
git push -u origin <new-branch>

# 5. PR + merge.
gh pr create … && gh pr merge --squash --admin
```

`git hash-object -w` works for binary files too — used for `web/cuisine/public/durian.png` (v0.61.142, blob `9c3b29c…`) and `web/cuisine/public/durian.jpeg` (v0.61.146, blob `8654d6f…`). For binary deletes, `git update-index --force-remove` removes from the index without touching the working tree.

### 4.7 Pack-corruption recovery (O-22 sub-case)

Symptom: `error: file .git/objects/pack/pack-<sha>.pack is far too short to be a packfile`. Reversible recovery (preserves loose blobs):

```bash
mkdir -p .git/objects/pack-broken
mv .git/objects/pack/pack-<broken-sha>.{pack,idx,rev} .git/objects/pack-broken/
git fetch --refetch origin main
# Fresh packs replace the broken ones; loose blobs written via
# git hash-object since the corruption are unaffected.
```

If two packs are corrupted simultaneously (observed once), repeat `mv` then run `git fetch --refetch` once — it pulls fresh packs containing all referenced objects.
