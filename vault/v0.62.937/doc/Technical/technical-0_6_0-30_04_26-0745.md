### 2. New external API call patterns

| Pattern | Where | Cache |
| :--- | :--- | :--- |
| Gemini structured-JSON classification on free text | `gatekeeper.js classifyAndReply` | 60 s by `sha256(text).slice(0,24)` |
| Gemini structured-JSON candidates with category hint | `vibe-suggest.js geminiCandidates` (when `category !== 'food'`) | none — per-`/drink` or `/groceries` invocation |

Cost note (G4): both are Gemini Flash calls (~50 input + 50–200 output tokens). At single-user scale negligible. The 60-second gatekeeper cache plus Telegram's typical "tap to send" rate keeps this in single-digit calls per day per user.

### 3. Telegram command surface (full)

| command | description |
| :--- | :--- |
| `eat` | Solo-diner food picks for now |
| `drink` | Bars, coffee, tea spots near you |
| `groceries` | Supermarkets and fresh markets near you |
| `status` | CBD train pulse |

Free-text messages fall through to the Gatekeeper.

### 4. Location-share + pending state

The Redis pending-meal key (`loc:pending:<hash>`) now stores `'food'` / `'drink'` / `'groceries'` instead of `'breakfast'` / `'lunch'` / etc. The `bot.on('location')` handler reads the stored category and routes to the appropriate `runFlow` invocation.

Backwards compatibility note: existing pending-meal entries from the v0.5.x deploy will be misinterpreted as `'food'` (default). 5-minute TTL means residual entries flush within minutes of the v0.6.0 deploy.
