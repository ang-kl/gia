## §0.10.0 NEW CONTENT

### 1. New module

`consultant.js` — Hidden Sanctuary engine.
- `nearbyAnyOperational(lat, lng)` — Places `searchNearby` (broader types, OPERATIONAL filter, ranked by distance, top 5).
- `fetchReviews(placeId)` — Place Details with FieldMask `reviews`, top 5.
- `geminiSanctuaryRead(name, reviews)` — Gemini structured-JSON: `{is_sanctuary: bool, reason: string}`.
- `findHiddenSanctuary(lat, lng)` — orchestrator. Returns the first candidate Gemini judges sanctuary-suitable, or `null`.

### 2. Redis schema additions

| Key pattern | Type | TTL | Writer | Reader |
| :--- | :--- | :--- | :--- | :--- |
| `proc:<sha256(chatId).slice(0,16)>` | string | 60 s | `setProcessing` (entry of `runFlow`) | `isProcessing` (re-entry guard) |

`location-cache.js` exposes `isProcessing`, `setProcessing`, `clearProcessing`. The flag is a `setEx` with literal `'1'` value; presence is the signal.

### 3. `validateWithPlaces` extended

In addition to the existing gates (200 m proximity, OPERATIONAL, `openNow !== false`), now performs:

```js
if (await hasNegativeRecentReview(place.id)) return null;
```

`hasNegativeRecentReview(placeId)` calls `Place Details` with FieldMask `reviews`, prefers reviews with `publishTime` within 30 days (falls back to top 5 if none recent), tests each review's text against the negative-keyword regex, returns `true` on first match.

### 4. Negative-keyword regex

```js
/\b(loud music|extremely (?:noisy|loud)|under construction|under renovation|renovation works?|closed for renovation|too crowded|over[-\s]?crowded|packed beyond)\b/i
```

Conservative — narrow set of unambiguous deal-breakers. Does NOT match generic complaints like "service was slow" or "expensive" — those aren't sanctuary-blocking.

### 5. `runFlow` decision tree (full v0.10.0)

```
runFlow(chatId, lat, lng, category):
    if isProcessing(redis, chatId):
        safeSend("⏳ Gia is still working…")
        return

    setProcessing(redis, chatId)         ← 60 s TTL
    try:
        if category in {food, drink}:
            vaultPicks = fetchOpenVaultPicks(redis, lat, lng, 300, 3)
            if vaultPicks.length >= 3:
                deliverPicks(chatId, label, vaultPicks)
                return

        {meal, venues} = pickValidated(lat, lng, 3, [], {category})
        if venues.length:
            deliverPicks(chatId, meal.label, venues)
            return

        hidden = findHiddenSanctuary(lat, lng)
        if hidden:
            safeSend("I couldn't find a standard {meal} sanctuary, but I've
                      identified a 'Hidden Sanctuary' at {name} based on
                      recent reviews mentioning {reason}.")
            deliverPicks(chatId, meal.label, [hidden])
            return

        deliverPicks(chatId, meal.label, [])     # → handleNoResults
    finally:
        clearProcessing(redis, chatId)
```

### 6. Cost budget revision

| Path | Approximate cost / `/eat` |
| :--- | :--- |
| Vault saturated (≥3 hits) | ~$0.05 (3 Place Details verifies) |
| pickValidated success (first candidate gates pass including review check) | ~$0.05 (Gemini + searchText + Place Details for reviews + Routes Matrix) |
| pickValidated success at candidate N (N-1 dropped on review keyword) | ~$0.05 + $0.017×(N−1) extra Place Details calls |
| pickValidated empty → Hidden Sanctuary success | ~$0.10 (broad searchNearby + Place Details for reviews + Gemini analyze + Routes Matrix) |
| Total miss → handleNoResults | ~$0.10 (broader fallback ran but no sanctuary identified) |

Single-user scale: still negligible. At sustained traffic the review-keyword screen is the dominant new cost; it can be relaxed to "screen only when rating < 4.0" if cost matters.

### 7. Public app.js global error swallow

```js
window.addEventListener('error', (e) => {
  e.preventDefault();
  setStatus('Gia hit a snag. Reopen from inside Telegram to retry.', false);
});
window.addEventListener('unhandledrejection', (e) => {
  e.preventDefault();
  setStatus('Gia hit a snag. Reopen from inside Telegram to retry.', false);
});
```

`e.preventDefault()` blocks the browser's default error UI. iPadOS Safari/WebView won't surface the system "An error occurred" modal because we've handled the event.
