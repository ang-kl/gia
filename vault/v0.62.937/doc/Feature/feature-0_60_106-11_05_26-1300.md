## New features in this arc

### Train (transport) TMA — interactive Google Map view
- **What** — `/app/transport` opens with a PNG schematic by default; the user can toggle to a Google Map view with ~206 station pins (177 operational + 29 future). Each pin is line-coloured (LTA palette); future stations are desaturated grey with `Opens 20XX` in the popup. Multi-line interchanges list every line.
- **Why** — Operator wanted a "tap a station to see codes + lines" experience without sending 200 photos to chat. The PNG schematic stays as the friendly first impression; Google Map is the deep-dive opt-in.
- **Where** — `web/transport/src/components/MrtMapPanel.jsx` + `data/mrt-coords.json` + `GET /api/transport/stations`.

### Train TMA — `All Lines` scroll chip + one-shot auto-switch
- **What** — At the start of the affected-lines scroll, a `⇆ All Lines` reset chip clears the current focused line. When the user taps any other chip from the initial PNG view, the map auto-switches once to Google Map. Subsequent taps respect whatever view the user is on.
- **Why** — Lets users browse lines without scrolling back to the view toggle. The one-shot guard (Codex P2 catch) prevents the auto-switch from yanking the user back to Google Map after they explicitly chose Schematic.

### Train TMA — LRT lines first-class
- **What** — BPLRT, SKLRT, PGLRT included in the default scroll. `/transport train` chat-side now surfaces LRT stations as nearest results when applicable (e.g. user near Cove gets `⬜ PLRT Cove`).
- **Where** — `LINES.filter((l) => !l.future)` in `App.jsx`; `light_rail_station` added to `nearestMrtStations` includedTypes; 35 LRT-only stops added to `STATION_LINES` in `mrt-lines.js`.

### Train TMA — InfoWindow per-line live status
- **What** — Tapping a station pin in the Google Map view shows the station name + per-line status rows colored by severity (Normal = green, Delay = orange, Disrupted/Closure = red).
- **Why** — Operator wanted to see at-a-glance whether a station's lines are running normally without going back to the status banner above the map.

### `/traffic` — full incident list
- **What** — Removed the 8-incident cap. `/traffic` now renders every island-wide traffic incident, sorted nearest-first when location is shared. Telegram-chunks to ≤3500-char messages with the map button + Back inline keyboard on the last chunk only.
- **Why** — Operator: "Expand the live traffic incidents to include all incidents."

### `/checkpoint` — bbox-filtered cameras + live count
- **What** — `/checkpoint` now shows every LTA camera within ~3 km of either land checkpoint (Woodlands or Tuas 2nd Link), not just the 4 hardcoded ones. The reply header surfaces the live count: `8 cameras live (Woodlands Checkpoint: 5 · Tuas 2nd Link: 3)`.
- **Why** — Operator: "Query how many camera can you include for /checkpoint." The bbox approach covers approach roads (BKE, AYE) where queues form 1–2 km out at peak.

### `/checkpoint` — best-effort ICA queue scrape
- **What** — Best-effort scrape of ICA's public `trafficupdates` page. When the parse succeeds, the reply includes an italic Markdown block: `Queue estimate (source: ICA · unofficial scrape):` with per-checkpoint Departing/Arriving status keywords (Smooth/Healthy/Light/Moderate/Heavy/Congested/Closed).
- **Why** — Operator: "Can you include data like how many cars or motorcycle waiting" + "scrape ICA's HTML (unofficial, fragile, ToS questionable), indicate source and advisable to be estimated in subtle small font size."
- **Caveat** — LTA's dedicated `WoodlandsTraffic` / `2ndLinkTraffic` endpoints (which used to carry CarsWaiting/MotorcyclesWaiting fields) are 404'd in production; ICA doesn't publish a JSON API. Status keywords are the best signal available. If the scrape fails (page reshape, network issue), the line silently drops and the cameras still send.

### `/causeway` — removed
- **What** — `/causeway` no longer accepted; only `/checkpoint` triggers the camera view. Both dispatched the same handler before v0.60.103.
- **Why** — Operator: "Remove /causeway".

### Cuisine TMA — combo cuisine AND/OR search
- **What** — When a user picks 2+ cuisines, the server first tries a single combined Google query (`"Italian Cantonese restaurant Singapore"`). If at least one returned venue whose name/types/primaryType contain EVERY selected cuisine keyword passes validation, those venues surface as primary results. Otherwise the server falls back to per-cuisine queries merged round-robin, with a banner above the results: "No exact cuisine combination found. Showing separate eateries for each selected cuisine."
- **Where** — `index.js POST /api/cuisine/search` (v0.60.82, validation tightened at v0.60.84).

### Cuisine TMA — criteria preview line
- **What** — Below the "Search criteria" header (when collapsed), a small line lists the actually-selected cuisines + filters + prices separated by ` • ` (e.g. `Japanese • Open now • $$`). Replaces the v0.60.79 `1c · 0f` count badge that was meaningless.
- **Where** — `web/cuisine/src/v2/App.jsx`.

### Cross-TMA navigation standardisation
- **What** — All four TMAs (Cuisine, Hawker, Menu, Train) now share a unified bottom navigation row:
  - **Bottom-left BackFab** — aqua bg (`#7FDBDB`), `⇠ back` or `🔚 end` text label, smart detection of history vs close.
  - **Bottom-right scroll FAB** — aqua bg, `⇡ top` (when at bottom of page) / `⇣ down` (otherwise). `atBottom` flip-state.
  - **Cuisine extra** — Search FAB stacked above scroll FAB (operator: "'Search 🔍' be on top of 'top' / 'down'").
- **Why** — Operator wanted a "feels the same in every TMA" navigation pattern. Multiple iterations led to: aqua over inverse-theme over ice-blue; ⇠ U+21E0 over ⬅; text labels over icon-only; bottom-2 + h-7 + text-[10px] (v0.60.105 shrink).

### Carpark Title Case
- **What** — `runCarparkCommand` now Title-Cases any all-uppercase carpark names from the LTA feed before rendering (e.g. `MARINA SQUARE` → `Marina Square`).
- **Why** — Operator: "can you detect if the carpark assigned title is uppercase and change to proper Title Case."

### FR audit — pass #2
- **What** — Every English string in the four TMAs' visible chrome (BackFabs, scroll FABs, Train TMA header + ticker + view toggle, etc.) now routes through `useLocale()` + `t()`. New `web/transport/src/i18n.js` module mirrors the existing menu/hawker/cuisine modules. The shared `gia.locale` localStorage key means flipping locale in any TMA flips all of them.
