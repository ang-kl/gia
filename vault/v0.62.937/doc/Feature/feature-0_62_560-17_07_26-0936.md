## §J-A · Responsive Hawker TMA — three layout modes (tablet / desktop / phone)

**What the user sees.** The Hawker Centre Mini App now reshapes itself to the device + orientation instead of
rendering the phone layout boxed in the middle of an iPad. Three modes, one shared centre-card renderer:

- **Landscape (tablet/desktop) — full-bleed map + bottom carousel.** The Google map fills the screen; the
  centre cards ride a **bottom-docked horizontal swipe carousel** (Cuisine-style). The middle cards sit
  **in focus (opaque)**; the two "half-seen" cards peeking at each end render **glass** (frosted/translucent).
  **3 cards in focus** on iPad Pro / desktop, **2 on an iPad-mini width**, 1 on a phone aspect. A slim
  translucent **top bar** carries the header (title + weather + locale + NEA) and the region chips.
- **Portrait (tablet/desktop) — anchored map + scrollable list panel.** The map is **anchored at the top**;
  the centre list lives in its **own scrollable panel** below (2-col grid) — the map doesn't scroll away.
  Tapping the map's **⇲ expand** flips the list into the landscape-style carousel; **⇱** collapses back.
- **Phone — unchanged stacked scroll** (inline map on top, single-column list). Provably untouched: the
  tablet wrapper is `display:contents` off-tablet.

The footer carries a device/orientation cue beside the version — `(tablet · landscape)` / `(tablet)` /
`(desktop · landscape)` / `` (phones) — and the tablet **map⇄cards toggle** (🗺 Map / 📋 Cards) sits inside the
FooterNav cluster (beside ⇣ down / 🔚 end).

**Why it needed platform work (not just CSS).** On iPad, Telegram opens the Mini App as a **centered modal**;
the app now requests **fullscreen for touch tablets only** so the layout has the whole screen (§J-D / Technical
Rule N-2). The standardized left map-nav cluster (zoom readout · ＋ · ↹ · － · ⇲) and the quick-toggle row
(Monochrome / Train / Carpark / Bus Stop) drop below the top bar in full-bleed mode so they stay visible.

**Reference:** operator iPad-Pro screenshots across the arc (IMG_0669…IMG_0700).

## §J-B · Cuisine-style centre cards

Every centre card (all three modes) matches the Cuisine result-card look: a numbered name header, `📇` address,
a stall-count + operating-status chip, the nearest MRT as official line-colour (`codeHex`) code chips + station
name, bus stops as pills **carrying the stop description** ("🚌 41129 · Opposite S'pore Bible College"), the
Bib Gourmand row (§J-C), and rounded-pill actions (📍 Maps · Save to chat). Carousel cards use compact padding.
The stall/status row appears only for the ~37/122 centres present in the data.gov.sg stalls GEOJSON.

## §J-C · Michelin Bib Gourmand on Hawker

A hawker centre that contains Michelin **Bib Gourmand** stall(s) takes the Cuisine macaron-red pin (`#C6282D`)
**plus a ✳️ marker** (CVD-safe — colour is never the sole signal), and shows a **`✳️ Bib Gourmand · <stall>`**
row on the card, the map InfoWindow, and the save-to-chat chat card. Each stall name is a **Google-Maps
hyperlink** (accent-coloured, no underline) to that stall within the centre. The mapping reuses the existing
`SG-michelin.js` `BIB_GOURMAND[]` (address = centre name); no new data source. ~19/122 centres tag.

## §J-D · Card ↔ map interaction model (embedded map, both ways)

Taps act on the **embedded** map, not external Google Maps, and the card and pin stay in sync:

- **Tap a centre card** (anywhere except a pill) → highlights its pin (opens the InfoWindow, zooms, draws
  transit + distance rings) with a **3-second pulse**, and rings the card active.
- **Tap a centre pin** on the map → **scrolls the matching card into focus** (centres it in the carousel /
  brings it into the list) + rings it — the "vice versa".
- **Tap a station / bus-stop pill** (card **or** InfoWindow) → drops the labelled marker + pans + flashes on
  the embedded map (bus stops open their live-arrivals bubble); a **second tap** opens external Google Maps.
- **Closing** an info card **no longer changes the zoom** (see Removed row; applied across all embedded-map
  TMAs). The Google InfoWindow chrome is stripped so only the app's rounded card shows (single clean border),
  and a card near the top edge pans the map down so it isn't clipped by the top bar.
