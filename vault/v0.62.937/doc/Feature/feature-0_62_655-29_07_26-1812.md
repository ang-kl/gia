## F-61.1 — One interaction model: Cuisine, Hawker, Train

Before this arc the three map apps behaved differently enough that the operator's own standard
("do it like Cuisine") pointed at an app that did not follow it. All three now share:

| | Behaviour |
|---|---|
| **Default view** | Carousel of cards over a full-bleed map — every device, every orientation |
| **Route to the list** | One footer toggle (**⊿ List** / **◸ Map**), always visible |
| **List presentation** | A drawer floating **over** the map, with a drag handle |
| **Card surfaces** | Active card opaque · peek cards 60 % liquid glass · footer dock 75 % liquid glass |

Nothing forces a view by orientation any more, and no state hides the toggle.

## F-61.2 — The drawer, and its handle

- **A real, visible drag handle.** It had been an invisible box for two releases (see Technical
  T-61.1); it now has a **44 px** grab band — the Apple HIG / WCAG 2.5.8 target floor — and a grabber
  that carries an inline background so it cannot silently vanish again.
- **Velocity-aware release.** The resting snap is chosen from where the sheet is *heading* (position
  projected forward by trailing-window velocity), not where the finger stopped. A fast flick travels.
- **Cuisine opens at 1.5 cards.** The collapsed height is measured from the app's own first rendered
  card (`1.5 × cardHeight + 44 px`), so the half-card cut off at the fold — the "there is more, scroll
  me" cue — is correct on every device rather than on one.

## F-61.3 — Layout that follows the window, not the device

- **List columns: 2 / 3 / 4** at < 700 px / ≥ 700 px / ≥ 1280 px. An iPad mini in portrait (744 px)
  gets three; a desktop gets four; a dragged Telegram Desktop window re-flows live.
- **Carousel card count scales to ultrawide.** Measured: Train at 1440 px went 4.5 → **6.4** cards,
  at 1920 px → **8.1**, at 2560 px → **9.9**; Hawker at 1920 px went 3.3 → **6.0**.

## F-61.4 — Reading a line as a stranger

Operator, as a non-local: *"i wouldn't know how to read the cards if presented in columns for
listing."* Diagnosis: MRT stations are an **ordered sequence**, and a single column encoded that for
free — reading down the list *is* travelling along the line. Multiple columns destroy it, and a
visitor has no reason to know that EW1 → EW2 → EW3 counts along the track.

Restored without giving up the columns:

- a **line-order header** above the grid — line badge, full line name, both termini with a direction
  arrow, and the stop count;
- an **ordinal on every card** ("3/35").

## F-61.5 — Train station card, read-at-a-glance pass

- **Disclosure on the name strip** (right-aligned word + triangle), foot pill removed — which is most
  of what brings a two-line interchange card down toward a one-line card's height.
- **Line names that fit.** Font steps with the station's line count (11/10/9 px), so "East-West Line",
  "Downtown Line" and "Thomson-East Coast Line" read in full instead of truncating.
- **A qualified line takes two rows** — `East-West Line` / `(Changi Airport Branch)` — using the name
  the line chip uses, not the feed's "Changi branch" shorthand.
- **"Normal service" is gone.** The status dot carries it; the word appears only when a line is *not*
  normal, paired with a **⚠ disruption tab above the card** in the status colour. The exception is now
  the loudest thing on the card instead of the quietest. CVD-safe — the word carries the meaning.
- **Exits and bus stops as plain text links**, one per row, so their descriptions fit. Exits are
  normalised to a full label ("Exit A"…"Exit F", including the two Paya Lebar records the feed stores
  bare); repeated bus-stop codes are de-duplicated.
- **Tap a card → the map jumps *and* the station's pin flashes** a ring in the line's colour (Cuisine
  parity). Matters most in list mode, where the drawer covers the lower half of the map.

## F-61.6 — Whole-app polish

- **Glass standard** applied uniformly (60 % peek cards, 75 % footer dock, opaque active card), with
  `.liquid-glass-dock` ported into Hawker and Train — it had been Cuisine-only CSS, so the other two
  had been faking it with a plain blur.
- **Cuisine carousel** sits 2 px clear of the recommendation bar.
- **Auto-expand** now re-measures on Telegram's own `fullscreenChanged` / `viewportChanged` rather
  than on hard-coded timers, so a slow fullscreen transition no longer strands the layout at its
  pre-expand size. All five Mini Apps benefit.

## F-61.7 — New shared component (built, not yet adopted)

`web/_shared/components/bottom-sheet/` — a framework-free, swipe-to-close bottom sheet (HTML + CSS +
vanilla JS) built to a written brief: centred `max-width` on large screens, `dvh` + Visual Viewport
for software keyboards, separate touch and pointer paths for Telegram Desktop, opaque surface with
light-mode shadow / dark-mode hairline for contrast over map tiles, velocity **and** distance release
physics, and background scroll locking. **Not wired into any TMA** — `BottomSheet.jsx` remains the
shipping drawer, and the two now share the velocity helper.
