## New features in this arc

### Hidden owner-only Oversight admin TMA + Redis-only usage-tracking layer (v0.60.142 — PR #379)

- **What** — A hidden Telegram Mini App at `/app/oversight`, launched only via a hidden `/oversight` chat command (owner-gated by `TELEGRAM_OWNER_CHAT_ID`, silent no-op for non-owners — same pattern as `/ver` / `/ftlog`; not in `setMyCommands`). Surfaces an aggregate-only operator dashboard: **total users since tracking shipped**, **today active / searchers / "frequent ≥ 2 searches"**, **by-day** counts (configurable trailing window or a specific date), **by-day-of-week** averages over the window, **top cuisines / top criteria-filters / top free-text terms / recent free-text** (latest 50). All identity-free: per-user entries are one-way `sha256` hashes (`hashChatId` from `location-cache.js`) used **only** to de-dup the counts — nothing else attached to them. Removed on `/forgetme`; per-day data 90-day TTL; no backfill.
- **Why** — Operator: *"Create a hidden admin interface … [ Soleat/oversight ] ties to my ChatID. … statistics like how many use have login since the beginning, frequent users (> 1) by today, date, day, week, day (specify), free-text words use, cuisine, criteria"*.
- **Where** — new `usage-log.js` (Redis-only, fire-and-forget, never throws — `recordUser` / `recordSearch` / `getStats`); new `web/oversight/` TMA scaffolded from `web/transport/` (Vite/React/Tailwind; `src/App.jsx` is the single-screen dashboard with `StatCard` + `BarList` + `Section` components); `index.js` — `require('./usage-log')`, hidden `/oversight` `bot.onText`, `app.use('/app/oversight', express.static(…))` + `app.get('/app/oversight', …)` (no-cache HTML) + owner-gated `app.get('/api/oversight/stats', requireInitData, …)`, plus `usageLog.recordUser` next to `touchActivity` in the message handler and `usageLog.recordSearch({src})` at every search call-site (`/api/cuisine/search` `'cuisine-tma'`, chat free-text handler `'chat-freetext'`, `runSearchCommand` `'s'`, `runFlow` `'eat'`, `runSurpriseCommand[+WithFreeText]` `'surprise'`); `user-data.js` `forgetUserData` strips the user's hash from `usage:users` + SCAN+`SREM` every `usage:dau:*` / `usage:search:*` / `usage:searchmulti:*` (new `removeUsageMembership` export); `i18n.js privacy.body` (EN + FR) — aggregate-usage-counts bullet; `package.json` `build:oversight` added; `.gitignore` `public/oversight/`. New `__tests__/usage-log.test.js` (9 tests); `__tests__/redis-stub.js` gains `sCard` + `hIncrBy`. The web/menu hub is **not** touched — the TMA stays hidden (no tile).

### Vibe Journal optional shared-key gate (v0.60.144 — PR #381)

- **What** — `/doc` and `/doc/*` honour the **Railway service variable `VIBE_JOURNAL_KEY`**. When set: callers must pass it via `?key=<value>` (a correct `?key=` drops a 30-day `httpOnly` cookie scoped to `/doc` so the in-page JSON link + the redirect keep working) or the `X-Vibe-Key: <value>` header; missing/wrong → `401` with a small "🔒 Vibe Journal — enter the access code" form. When unset → public (the default-open convention used by `isOwnerChat` etc.). The key lives only in the Railway variable — never committed; rotate by changing the variable.
- **Why** — Operator: *"Can you create a secret key to prevent people from access this document without this code? The Railway Service variable: VIBE_JOURNAL_KEY."*
- **Where** — `index.js` `/doc` route block — replaced the plain `express.static` with guarded `app.get('/doc', …)` + `app.get('/doc/:file', …)` (whitelisted to `vibe-journal.html` / `vibe-journal.json`).

### Cuisine TMA: `/api/cuisine/copy-all` hardened against Telegram parse-mode rejections (v0.60.145 — PR #384)

- **What** — Both `bot.sendMessage` call sites in `/api/cuisine/copy-all` are wrapped in `try/catch`. On a Telegram HTML parse-mode rejection (a stray `&` / `<` in a venue name that escaped the escape, or an unbalanced tag) the handler retries once with a plain-text body (strip `<b>/</b>`, unescape `&amp; &lt; &gt;`), preserving `reply_markup`. A second failure 500s with a structured `[Cuisine] copy-all sendMessage retry failed (plain): <description>` log line. Separately, `buildMapHashUrl()` returning `null` (every slim venue lacked lat/lng → `buildSlim() === []`) no longer 500s the whole copy — drops the inline-keyboard map button, appends a one-line `📍 Map unavailable for this set.` (EN) / `📍 Carte indisponible pour cette sélection.` (FR) footer.
- **Why** — Operator: *"The copy all button in /cuisine still shows occasionally same error. Check past PR and compare with current source code, first."* Past PRs (#231 / v0.59.26 trim-loop, #234 / v0.59.29 16→12 cap, #200 / v0.58.53 enrichment fields, #202 / v0.58.55 FR i18n) fixed the body **size** but never wrapped the send itself.
- **Where** — `index.js:7383-7475`; `i18n.js` new `pick.mapUnavailable` (EN + FR); `__tests__/copy-all-html.test.js` (new, 5 tests).

### Cuisine TMA: per-session 80-cap clipboard + ⇠ Prev FAB + multi-cuisine variant escalation (v0.60.146 — PR #385; FAB visibility fix v0.60.148 — PR #387)

- **What** — A new **per-Cuisine-TMA-launch session clipboard** in Redis, distinct from `clip:<chatId>` (`clip-store.js` 100-entry `/clip` recall) and from `cuisine:seen:<chatId>:<criteriaHash>` (long-lived per-criteria dedup). Keys: `cuisine:session-seen:<chatId>` SET 30 min TTL cap 80 placeIds; `cuisine:session-pages:<chatId>` LIST 30 min TTL cap 10 page payloads (LPUSH at head; LPOP for "back"); `cuisine:session-meta:<chatId>` HASH 30 min TTL. Wiped on every TMA mount via `POST /api/cuisine/session/start`. Three behavior changes flow from this:
  1. **No more "stuck on the same list".** The silent fallback at `index.js:8915` (`top = (unseenVenues.length ? unseenVenues : venues).slice(0, 12)` — silently re-served already-seen venues when the per-criteria pool exhausted) is replaced by an outer-gate `trulyUnseen = unseenInCriteria.filter(v => !sessionSeen.has(v.placeId))`. Empty → `venues: []` + `exhausted: true` flows naturally; the TMA's existing terminal-note path takes over.
  2. **Multi-cuisine variant escalation.** `cuisineSearchVariants(cuisineNameOrList)` accepts an array (e.g. `['Japanese','Korean']`) and joins with `" + "` for the variant prompts ("Japanese + Korean restaurant Singapore" → "best …" → "authentic …"). Both single- and multi-cuisine now escalate through the 4 phrasings as the pool exhausts.
  3. **⇠ Prev FAB** in the floating action column (above 🔍 Search) — visible when `pageStackDepth > 0`. Tap → `POST /api/cuisine/session/back` (double-pop with re-push so depth stays consistent + `usageLog.recordSearch({ src: 'cuisine-tma-back' })` for Oversight tracking) → previous result list re-renders. Walks back to the first list. (PR #385 originally placed the button inside the in-response pagination strip, which is gated on `totalPages > 1` — never true for the standard 12-venue response — so the FAB was effectively invisible until PR #387 moved it to the floating column.)
- **Why** — Operator: *"When I click 'search icon' FAB says Japanese,Korean cuisines, it will list results and continue to click # , after 3 or 4 click# , it is stuck with same list. Can you check did we lock in the maximum results, … include 'back' to refer 'back' FAB icon to previous list until list #1 and invokes tracking. We should allow up to 120? Be robust … sensitive with Michelin criteria."* Refined via Q&A to **80 per session**, **distinct from `/clip`**, **reset on TMA launch**; server-side Redis history for back-FAB durability.
- **Where** — new `cuisine-session.js`; `__tests__/redis-stub.js` extends with list ops `lPush`/`lPop`/`lRange`/`lLen`/`lTrim`; new `__tests__/cuisine-session.test.js` (10 → 14 tests across v0.60.146/.149); `index.js` — extended `cuisineSearchVariants` for arrays, session-seen outer gate, replace silent fallback, append-page on success, new `POST /api/cuisine/session/start` + `/back` endpoints; `web/cuisine/src/v2/App.jsx` — `startSession()` on mount, `sessionFull` / `pageStackDepth` state + `runBackOnePage` handler; `web/cuisine/src/v2/components/ResultPanel.jsx` — accepts the new props; `web/cuisine/src/v2/lib/api.js` — `startSession()` / `backOnePage()` helpers. The Michelin handler joins the same page-history.

### Cuisine TMA: Michelin full LLM-narrate parity (v0.60.147 — PR #386)

- **What** — Michelin venue cards now match cuisine-chip cards in field count: curated Michelin badge **+** `restaurantType` **+** `dishes` (review-extracted, regex) **+** `recentReview` (first ≤ 200 chars) **+** `vibe` (LLM-generated) **+** `signatureDish` (LLM-generated). `handleMichelinSearch`'s `FIELD_MASK` adds `places.reviews` + `places.editorialSummary`; the venue assembly carries `reviews` until a slim inline `extractDishes` (mirrors the cuisine-chip block at `index.js:9057`) + the new `pipeline.narrateMichelinVenues({ candidates, lang })` step run; then `delete v.reviews` before responding. Narration is **additive** — curated badge always preserved; on Gemini failure / `llm.isReady() === false` / parse-fail, cards still render with the curated badge + review-extracted dishes + recentReview (graceful degradation).
- **Why** — Operator: *"The presented result with Michelin criteria is different from normal search results when cuisine criteria is selected in Search criteria, versus free text criteria"* — Michelin cards previously had curated-badge + `restaurantType` only (vs cuisine-chip's full field set restored by PR #376 / v0.60.140).
- **Where** — new `pipeline.narrateMichelinVenues` (narrate-only LLM helper; defensive: drops hallucinated placeIds, truncates `dishes` to 3, never throws; FR localisation keeps iconic SG dish names un-translated); `index.js handleMichelinSearch` — FIELD_MASK additions, venue-object additions, the two post-`appendSeenSet` blocks; new `__tests__/michelin-narrate.test.js` (6 tests stubbing `llm-client` + `gemini-retry`). Cost: one Gemini call per Michelin search (batched over ≤ 12 venues); reuses the existing key / path; cuisine-chip path untouched.

### Cuisine TMA: Michelin batch 40→12, walk-through indicator, post-80 ↻ Recycle (v0.60.149 — PR #389)

- **What** — Three coupled refinements:
  1. `handleMichelinSearch` `sliceCap` 40 → **12**. PR #386's LLM narrate step on top of 40-venue batches pushed the first Michelin tap past Telegram's ~30 s webhook ceiling (apparent symptom: TMA `loading` hung; cards never rendered — "the rich template is gone" was really "no cards at all"). 12 venues fit comfortably inside Gemini's retry budget; the existing per-criteria seen-set rotates the pool so the user walks through all ~130 curated entries in ~11 ▶ taps.
  2. **Michelin × 80-cap interaction.** `cuisine-session.js recordPage(redis, chatId, payload, opts)` gains `opts.skipCap`. When `true`, page placeIds are NOT added to the session-seen SET (no 80-cap pressure) but the page IS still LPUSH'd onto the page-history LIST so ⇠ Prev still works. Michelin path passes `{ skipCap: true }`. Cuisine-chip / free-text paths keep the 80-cap exactly as before.
  3. **Michelin walk-through banner** — server returns `michelinSummary.{shown, remaining, total}` on every Michelin response; the TMA surfaces **"📚 Curated Michelin list — N more to explore (T in total). Tap ▶ for the next batch of 12."** (EN + FR) above the result list when `remaining > 0`.
  4. **Post-80 ↻ Recycle button.** New `POST /api/cuisine/session/recycle` endpoint — `cuisineSession.startSession(redis, chatId)` (wipes session-seen + page-history + meta) + `usageLog.recordSearch({ src: 'cuisine-tma-recycle' })` for Oversight tracking. The TMA's terminal copy (when `sessionFull === true`) appends a ↻ Recycle button: tap → server clears the session-clipboard, the next search returns list #1 of the fresh session.
  5. **"Order this" → "Try" defense.** Gemini was occasionally writing verb-prefixed phrases ("Order the …", "Try the …", "Have the …") into `signature_dish` / `dishes`, which then rendered as `🍴 Try · Order the brisket`. Two-layer fix in `pipeline.js narrateMichelinVenues`: prompt tightened (dish fields are NAMES ONLY, never verbs) + a server-side strip regex `/^\s*(?:order|try|have|get|grab|enjoy|recommend|sample|taste|sip|pick(?: up)?)\s+(?:the|their|some|a|an)?\s+/i` applied to `signatureDish` + each `dishes` entry.
- **Why** — Operator: *"Reference to PR #386, the first Michelin LLM for 40 as the loading timeout. How to solve this, reduce the list but show navigation to list 139 of them"*, *"after listing the final 80, continue back to first. Is this the best way"*, *"It should use 'Try' rather than 'Order this'."*
- **Where** — `index.js handleMichelinSearch` (sliceCap; `recordPage({skipCap:true})`; `michelinSummary.shown` + `.remaining`; comment refresh); `cuisine-session.js` (`opts.skipCap`); `pipeline.js narrateMichelinVenues` (tightened prompt + `stripDishVerbs` helper); `index.js` new `POST /api/cuisine/session/recycle` near `/api/cuisine/session/start`; `web/cuisine/src/v2/lib/api.js recycleSession()`; `web/cuisine/src/v2/App.jsx` — `michelinRemaining` state + banner above `<ResultPanel>` + ↻ Recycle button when `sessionFull`; `__tests__/cuisine-session.test.js` gains 4 new tests for `recordPage(..., { skipCap: true })`.
