- **[INTENT]** Changing the country in the OTHER picker (Japan → Hanoi) must **not** deselect the OTHER region pill.

- **[INVESTIGATION — 2 passes (agent + self), NOT reproducible from source]** The code does **not** deselect OTHER on a country/city switch: `onCountryChange` (`App.jsx:2661`) only set `countryPref`; the `cityPreview` branch (`onLocationSelect :2187`) **returns at `:2195` before** the region-sync (`:2230`); and a foreign pick (`coordsToCountry(Hanoi) = null`) leaves region untouched (`:2243`). The v0.61.418 `cityPreview`-on-country-change is region-safe (re-verified). So the exact "unhinge" is most likely a transient render or a coincident visibility-refresh (`applyRegionFromAnchor :1315` applies the **server** region — that's intentional set-location sync, not touched here).

- **[DELTA]** (`web/cuisine/src/v2/App.jsx`) — **defensive fix** (the operator's explicit ask). `onCountryChange` now re-asserts `region` in the **same `setState`** as `countryPref`:
  ```js
  setState((s) => ({ ...s, countryPref: code, region: s.region === 'MY-PUT' ? 'MY-PUT' : 'OTHER' }));
  ```
  The country dropdown only ever shows in OTHER mode, so a country switch now **atomically keeps the OTHER pill selected** regardless of any concurrent effect. No-op on the normal path; bulletproofs the reported scenario.
