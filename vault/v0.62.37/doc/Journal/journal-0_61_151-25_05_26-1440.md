## New

### [HDR] #352 | 14:40 SGT 25-05-26 | v0.61.151 — Nationality review-language priority + (<flag> translated) tag | 5 files | 1 PR | 1 build |

- **[INTENT]** When the user picks a nationality cuisine (Italian /
  Japanese / Chinese / Korean / …), surface a high-rated review
  written in that nationality's native language as the venue card's
  `💬 "…"` quote — instead of the default English-first selection.
  Tag the quoted review with `( <flag>  translated)` so the user
  knows the snippet is from a native-language speaker (likely a
  more authentic relevance signal for a cuisine search).

- **[DELTA]**
  - **`cuisine-review-language.js`** (NEW, ~200 lines). Pure module:
    - `SLUG_TO_LANGUAGE` — ~50 nationality slugs → BCP-47 primary
      tag. `italian → 'it'`, `japanese → 'ja'`, all China-regional
      → `'zh'`, `chinese → 'zh'`, etc. Multilingual / generic
      slugs (`eurasian`, `singaporean`, `peranakan`, `australasia`,
      `european`, `dessert`, `fusion`, `african`) are
      intentionally NOT in the map.
    - `SLUG_TO_FLAG` — mirror of `cuisines-vault.FLAG_BY_SLUG`
      restricted to the language-mapped slugs. Kept in-file so
      the chat layer can resolve flag + language without two
      requires.
    - `isNationalityCuisine(slug)` — boolean.
    - `getLanguageForCuisines(slugs)` — returns first matching
      language for multi-cuisine selections; `null` for
      no-match.
    - `getFlagForCuisines(slugs)` — symmetric.
    - `reviewLanguagePrimary(review)` — normalises BCP-47 with
      subtags (`zh-CN` / `zh-Hant` → `zh`).
    - `pickPreferredReview(reviews, language, minRating=3.8)` —
      first review whose primary language matches AND rating
      strictly > minRating. Operator spec uses `> 3.8` (strict).
  - **`__tests__/cuisine-review-language.test.js`** (NEW, 21
    tests in ~165 lines). Coverage: map shape (all majors mapped,
    China-regional all-zh, multilingual exclusions), helper
    functions (true/false/null branches), `reviewLanguagePrimary`
    BCP-47 normalisation, `pickPreferredReview` threshold + custom
    minRating + BCP-47 subtag input.
  - **`index.js`** — `/api/cuisine/search` venue-enrichment loop
    after `extractDishes`:
    - Read nationality language + flag once via
      `getLanguageForCuisines(cuisines)` + `getFlagForCuisines`.
    - For each venue with reviews, call
      `pickPreferredReview(v.reviews, nationalityLang)`.
    - When matched: override `v.recentReview` with the matched
      review text + set `v.recentReviewTranslatedFlag` (the
      nationality flag) + `v.recentReviewLanguage` (the language
      code).
    - Override is INTENTIONAL — an Italian-speaker 4-star
      review beats a generic English snippet for Italian-
      cuisine relevance signal.
  - **`web/cuisine/src/v2/components/ResultCard.jsx`** — the
    `💬 "…"` block now conditionally appends:

    ```
    ( 🇮🇹 translated)
    ```

    when `venue.recentReviewTranslatedFlag` is set, with spaces
    around the flag per operator spec format. Uses
    `className="not-italic"` so the suffix renders upright
    against the italic review text.
