# Journal — soleat v0.60.156

> Hot-follow to v0.60.155: the `💬 "[object Object]"` bug *still* shipped on Michelin cards. Operator screenshot confirms the literal string `"[object Object]"` is being rendered — not the object — meaning a `String()` coercion happened upstream of every guard. Root caused to Places API v1's nested `review.text.text` shape: `String({ text: '…', languageCode: 'en' })` yields the literal seven-character-plus-three-character string `"[object Object]"`, which then passes every `typeof === 'string'` check we added in v0.60.154 + v0.60.155 because it IS a string. Same source affects the cuisine-chip path. Companion fix: harden `/api/cuisine/copy-one` with the v0.60.145 plain-text fallback that copy-all already has — operator hit "Couldn't send to chat — try again." in the same screenshot batch.

- **[DELTA]**

  **`index.js` Michelin review-extract (Step 1, ~6111–6140)** — introduced a `reviewText(r)` local helper that handles both Places v1's nested `{ text: { text: '…', languageCode: '…' } }` shape and any legacy bare-string response. Replaces `r.text || ''` in the regex pool concatenation (`recent.map((r) => r.text || '').join(' . ')`) and `String(recent[0].text || '').slice(0, 200).trim()` for `v.recentReview`. Without this unwrap, `String({…})` coerces to the literal `"[object Object]"` which is a valid string and slips past every downstream guard.

  **`index.js` cuisine-chip path (~9498–9614)** — same `reviewText` helper applied at three additional sites: `extractDishes`'s `recent` filter (was `(r) => r?.text`, now uses the helper), the same function's `allText.map`, the function's return-`snippet` (was `String(recent[0].text).slice(0, 200).trim()`), and the fallback `v.recentReview = String(v.reviews[0].text)…` block at line ~9612. Defined once at outer scope so all four uses share the same implementation.

  **`index.js` `/api/cuisine/copy-one` (~8024–8077)** — wrapped the `bot.sendMessage(chatId, body, htmlOpts)` call in the same try/retry pattern v0.60.145 added to `/api/cuisine/copy-all`. On HTML-mode failure (stray `&`, unmatched `<b>`, etc.), strip tags + unescape entities and retry as plain text; only 500 if both attempts fail. Without this, any malformed HTML in the per-venue detail block surfaced as "Couldn't send to chat — try again." in the TMA toast.
