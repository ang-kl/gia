# Journal — soleat v0.61.320 (Cuisine TMA "Other" mode: map recentre on city pick + never-silent search)

> Operator (05-06 '26) bug report, three related "Other"-mode location-state symptoms:
> 1. **BUG 1** — selecting Country/City (e.g. Malaysia → Putrajaya) does NOT recentre the Google Map on the city.
> 2. **BUG 2a** — the location free-text field stays stale ("Johor Bahru") after picking a city.
> 3. **BUG 2b** — after changing the city again (Japan → Fukuoka), tapping Search silently does nothing — no request, no results, no error, no loading state.
>
> Verified root causes (read the code, did not assume):
> - **BUG 1 (fixed):** `MapPanel.syncMarkers` centres on the **venue centroid** whenever venues exist, falling back to `searchCenter` only when venues is empty (`MapPanel.jsx:580-601`). An OTHER city pick is `noAutoFire` — it updates `searchCenter` but not `venues`, so the camera stayed on the prior area's pins and only jumped after a search repopulated venues.
> - **BUG 2b (fixed):** `runSearch` opened with `if (!userLoc) return` (`App.jsx:1200`) — device GPS was the gate. The only silent exit (the invalid-center guard below it already `setError`s). In OTHER mode the chosen location lives in `searchCenter`/`locationAnchor`, not `userLoc`, so the 🔍 tap returned with no request, no loading, no error.
> - **BUG 2a (NOT fixed — needs live repro):** the editable picker binds the **live** `locationAnchor.name` (compact pill `LocationField.jsx:1113`; expanded placeholder `:1159`), which updates on every `onCityPick → onSelect → setLocationAnchor`. The GPS auto-detect that sets the device anchor is one-shot (`autoDetectedRef`, `App.jsx:904`), so it cannot re-clobber a pick. Static code says the field should track the pick — could not reproduce the stale "Johor Bahru" from the code alone. Not shipping a speculative change (operator rule: no guessing). See KNOWN GAPS.
>
