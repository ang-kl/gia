### [HDR] #553 | 08:05 SGT 07-06-26 | v0.61.353 — map drift tracking + orange "↩ Back to last search area" (flies back, never moves the search anchor) | 2 code files | 1 PR | 1 build |

- **[INTENT]** Begin the aircraft-handoff location model: the map may be directed elsewhere, but the **confirmed search anchor stays under positive control**. Step 1 = track where the map is looking and give a low-weight helper to fly back to the confirmed search area — layered on the existing `userLoc`/`locationAnchor` rather than rewriting the fragile location-init effects.

- **[MECHANISM]**
  - **`mapViewLocation`** — `MapPanel` adds a second `idle` listener that reports the live map centre (`onMapMove({lat,lng})`); App holds it in state. (Separate listener so `handleIdle`'s marker logic is untouched.)
  - **fly-to** — `MapPanel` accepts a `flyTo` prop `{lat,lng,zoom?,_k}`; an effect `panTo`s (and optionally `setZoom`s) when it changes. `_k` (a nonce) forces a re-fly to the same point.
  - **Back button** — rendered below the `LocationField`. The active search anchor = `locationAnchor || userLoc`. The helper shows only when `mapViewLocation` has drifted **> 600 m** (haversine) from that anchor; tapping it sets `flyTarget` → the map flies back; it hides once the map returns (< 600 m). **It never changes the search anchor.** Styled per the operator's accessibility rule: low-weight, small font, **orange outline** (`#f59e0b` border / `#d97706` text), transparent — a helper action, not a primary one.
  - **Search wiring is unchanged** — the search still uses the existing anchor (`searchCenter`/`locationAnchor`), so this PR cannot regress search. It only adds map-view awareness + the fly-back affordance (useful immediately for manual map pans).
