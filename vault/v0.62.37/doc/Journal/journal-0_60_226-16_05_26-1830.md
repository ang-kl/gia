# Journal — soleat v0.60.226

> Operator, on the Cuisine TMA shipped in v0.60.225: *"It is too slow loading results in cuisine TMA."* — and the chosen fix (via AskUserQuestion): **Regex-first + cache Gemini** — the `🍲 Try ·` dish line is filled by the local regex first; Gemini runs only for the venues regex missed; each Gemini result is cached per-venue in Redis so repeat searches make zero Gemini calls.

## New

### [HDR] #194 | 18:30:00 SGT 16-05-26 | v0.60.226 — Cuisine TMA speed: regex-first dish sourcing + per-venue Gemini cache + bounded Gemini latency | 4 files | 1 PR | 1 build |

- **[INTENT]** v0.60.225 (PR #477) added a Gemini dish-extraction call to the `/api/cuisine/search` path that ran on **every** search, batched over **all** result venues, and **blocked** the HTTP response — worst case ~24 s (three 8 s model attempts stacking on timeout). That was the load-time regression the operator reported. Fix: flip Gemini from primary to a gap-only fallback behind the local regex, cache its per-venue output durably in Redis, and cap its latency.

- **[DELTA]**
  - **`index.js` — `/api/cuisine/search` dish block restructured (regex-first).** The review-text regex passes (Pass 1 inline reviews, Pass 2 `place-reviews:` cache) are unchanged and remain **primary**. The v0.60.225 Gemini block — which batched *all* venues and *overrode* the regex — is replaced: it now builds a **gap set** (venues where regex found nothing and that still have inline 4–5★ reviews), reads a new per-venue Redis cache for each gap venue, and sends to Gemini **only** the gap venues with no cache entry at all. Gemini can no longer override a regex dish.
  - **`index.js` — new per-venue dish cache `cuisine-dishes:v1:<placeId>`.** Value `{dishes:[…raw Gemini output…], at:<ts>}`. A cache **hit** (positive or a negative empty array) drops the venue from the Gemini batch. Raw output is stored; the per-request cleaning (`filterDishNames` + venue-name guard + `dropDrinks` → `filterOutDrinks`) is re-applied on read via a local `cleanDishes()` closure, so a drink cached on a Fusion search is still dropped when read on an Italian search. Split TTL: **7 days** for a hit, **24 h** for a negative (so a venue that later accrues review content isn't suppressed for a week). All reads/writes are `redis.isOpen`-guarded and best-effort — Redis down ⇒ every gap venue is simply treated as uncached (degraded but correct).
  - **`gemini-client.js` — `extractDishesFromReviews()` latency bounded.** Per-attempt timeout `8000 → 6000 ms`. The timeout rejection is tagged `err.isTimeout`; on a **timeout** the model chain now **stops** (a timeout means Gemini is slow, not that the model is bad — retrying the next model just stacks another timeout). Model-not-found / parse errors still fall through to the next model. Added a `DEADLINE` (12 s) that bounds the total even across the fall-through path. Worst case per uncached-gap search: one ~6 s call instead of ~24 s.
  - `package.json` `0.60.225 → 0.60.226`; this Journal entry (#194); `doc/.serial-state.yml` (`journal 193→194`, `commit 200→201`, `chat_counter 19→20`; re-anchored 18:30 SGT).

- **[STATUS]** STAGED → PROD on next Railway deploy. `index.js` + `gemini-client.js` ship with the server.

- **[TEST]** Post-deploy: Cuisine TMA → search. **Cold cache:** gap venues exercise one bounded Gemini call; response returns in a few seconds, not tens of seconds. **Warm cache:** immediately re-run the same search — no `[Extract-Dishes]` log line (zero Gemini calls), `🍲 Try ·` lines still populated. A known dishless venue stays dishless on the repeat without a Gemini call (negative cache). A search whose venues are all regex-covered makes zero Gemini calls.

- **[KNOWN GAPS]**
  - Cold-cache first search of brand-new gap venues still incurs one bounded (~6 s) Gemini call. Acceptable per the operator's choice; a progressive/async render was considered and not chosen.
  - A gap venue with no inline `v.reviews` but reviews in `place-reviews:` is not sent to Gemini (Pass 2's regex already covers it). Accepted scope limit.
  - Menu churn within the 7-day hit TTL can show a stale dish — flush by bumping the cache key to `v2:`.
