## 3. Budgets

| Resource | Limit / target |
|---|---|
| Telegram webhook ceiling | ~30 s hard — every handler replies within it |
| Gemini call latency | ~3 s typical; model-fallback on timeout |
| `/cuisine` end-to-end | < 12 s p95 (6 s TMA fetch timeout) |
| Places billable per `/cuisine` | ~15 validates (cap = 15); 30 s per-criteria result cache |
| Michelin per tap | top-12-fresh + a 7-day per-entry enrichment cache |
| Geo-overlay layers | build-time only — zero runtime API cost; served as static `data/geo-*.json` |
| Rate limits (per chatId, 15-min fixed window) | Cuisine hot endpoints 60–200; sized to "catch runaway loops, not real users" |
| Redis TTLs | location 24 h · pick cache 60 s · share tokens 7 d · recent picks 24 h · place reviews 24 h · `vibe:summary:v2` 7 d · enrichment 7 d · station-context 30 min · usage / free-text log 90 d · public holidays 90 d · Michelin seen-set 1 h idle |
| Static TMA bundles | immutable, 1-year `max-age`, content-hashed filenames |

## 6. Architecture decisions — v0.61.0 → v0.61.28 (current state)

> Each remains live unless the Deprecated table says otherwise.

- **T-61.0 — geo-overlay pipeline** — `scripts/build-geo-overlays.js` converts `geoloc/*.geojson` (LTA exits/taxis, URA buildings, NParks parks, STB attractions) into slim `data/geo-*.json`, served at `/api/geo/overlays`. A build-time, data-only step; zero runtime API cost.
- **T-61.7/8 — train-line geometry** — MRT/LRT line polylines derived from OSM/Overpass data, Chaikin-smoothed; line metadata centralised in `mrt-lines.js`.
- **T-61.17 — shared overlay controller** — `mapOverlays.js`, a framework-agnostic controller, duplicated byte-identically across the Cuisine / Hawker / Transport TMAs (no shared package across separate Vite apps; `KEEP IN SYNC` header in every copy).
- **T-61.21 — `attachAmenityPins`** — one shared helper draws venue/hawker-centre surrounding amenity pins (exits / bus / taxi / carpark) on every map TMA; exported from `mapOverlays.js`.
- **T-61.24 — Exit Template** — `geo-exits.json` exit features carry `exitCode`, `station`, `codes`; exit pins are line-coloured; a shared `exitTemplateHtml` renders the popup.
- **T-61.26 — fixed overlay radius + station-scoped chips** — the Nearby↔Details slider was removed; chip layers use one fixed radius; in a train-station-detail view the Exits/Taxis chips clip to the 3 visible stations. The auto-drawn station-context amenity path (`loadAmenities`) was removed.
- **T-61.27 — station codes in `/transport`** — `mrt-lines.codedLinesForStation` pairs `data/mrt-coords.json` `codes` + `lines` index-for-index; the nearest-stations chat rows show the real station code.
- **T-61.28 — geometric exit enrichment** — `build-geo-overlays.js` precomputes each exit's nearby named STB attractions (≤400 m, de-duped, max 3) into the `nearby` field; surfaced in the Exit Template.
- **T-61.25 — `/v` builder menu** — four owner-command action bodies extracted into shared helpers (`ownerHealthCheck` / `ownerFtlogDump` / `ownerOversightLauncher` / `setVerboseMode`), invoked by both the typed commands and the `/v` inline-keyboard callbacks.
