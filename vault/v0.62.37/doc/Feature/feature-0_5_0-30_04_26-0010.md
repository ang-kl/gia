## §0.5.0 NEW CONTENT

### Native-feel mapping triad

Three coordinated additions per Human Lead's "Unified iOS & iPadOS Strategy":

| Surface | What changed | Why |
| :--- | :--- | :--- |
| **TWA map markers** | Migrated from `google.maps.Marker` (numbered badge, name on hover only) → `google.maps.marker.AdvancedMarkerElement` with custom HTML pins. Each pin renders a numbered red disc + the **venue name visibly on the map** in a white chip. User-position pin styled blue with "You" label. | Solves the "anonymous pin" complaint at the source — names are part of the marker, not behind a tap. |
| **TWA map gestures** | Added `gestureHandling: 'greedy'`. | Single-finger pan on iPad without the cooperative two-finger gesture that frustrated touch users. |
| **Chat venue actions** | Each Sanctuary read message now carries an inline keyboard with two buttons: **📍 Open Map** (`web_app` button → `/app?placeId=<id>` opens the TWA focused on that single pin) and **🚗 Directions** (`url` button → Google Maps Directions URL Schema). | Two-tap journey from "I want this one" to either deep-dive or navigate, without going via the persistent menu button. |

### TWA: focus-mode via query param

When the TWA is opened with `?placeId=<id>`, the renderer filters venues to just that pin and zooms to z17. Without the param, the standard 3-pick view loads (unchanged).

This is what `📍 Open Map` from the chat keyboard hits. The same `/app` URL still serves both modes — single endpoint, query-controlled behaviour.
