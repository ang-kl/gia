## New

### [HDR] #60 | 15:30:00 SGT 01-05-26 | v0.30.2 | n/a kb | n/a lines
- **[INTENT]** Four simultaneous Human Lead reports bundled into one PR:
  1. **`/ver` red on Gemini** — `gemini-2.5-pro:generateContent [503 Service Unavailable]`. User had `GEMINI_MODEL=gemini-2.5-pro` set in Railway env; Pro overloaded; bot bricks even though Flash is fine.
  2. **`/surprise` returns "Meaningless outcome"** — strict gates (4-day fresh-review window) too aggressive for SG's review velocity on small venues.
  3. **TMA doesn't show what location it's using** — user wants resolved coords visible in the Header.
  4. **NL classifier mishandles "My location change"** — typed phrase got gatekept as off-topic; classifier needs `update-location` intent.
  5. **15-min staleness reminder missing** — picks just keep using cached location forever silently.
- **[DELTA — Gemini Pro→Flash auto-fallback]**
  - **`gemini-retry.js`** — `withRetry` accepts a new `fallbackFn` option. After exhausting retries on a 429/503, if `fallbackFn` is provided AND the error was retryable (transient), invokes it once. Bubbles non-retryable errors immediately (auth/bad-request/schema — Flash won't fix those).
    + new `makeFlashFallback(genAI, prompt, generationConfig)` helper. Returns `null` when `GEMINI_MODEL` is already `gemini-2.5-flash` (no fallback target makes sense). Otherwise returns a function that calls Flash with the same prompt + generationConfig.
    + `FLASH_MODEL` constant exported.
  - All six Gemini call sites updated to pass `fallbackFn: makeFlashFallback(...)`:
    - `nl-intent.js#classifyIntent`
    - `pipeline.js#reason` (D610)
    - `pipeline.js#refine` (D630)
    - `surprise.js#geminiEnrich`
    - `cuisine-search.js#geminiCandidates15`
    - `vibe-suggest.js#geminiCandidates`
  - When fallback fires, log line: `[<label>] primary model exhausted N retries on transient error; falling back to flash: <err>`. Permanent fallback log: `[<label>] fallback also failed: <err>`.
- **[DELTA — /surprise gate relaxation]**
  - **`surprise.js`** — `RECENT_REVIEW_DAYS` raised from `4` → `30`. Original 4-day gate was below SG's typical review-velocity for hidden-gem (<50-review) venues, so every search returned empty. The original 4-day signal preserved as `STRICT_RECENT_DAYS` constant (unused as a gate, available as a soft-preference signal in future patches).
  - **`findSurprise`** restructured from "return-on-first-pass" to "remember-soft-fallback-then-finalize" — first opening-gate-passing venue is held as `softFallback`. If a later venue passes the (now 30-day) recent-review gate, it overrides. If no venue ever passes, the soft fallback is returned with `isFallback: true` flag.
  - **`index.js#deliverSurprise`** — when `v.isFallback === true`, appends a transparent footer: `💡 Best match in your annulus — no fresh review this week, but rating + price profile fits.` User gets a real venue instead of "no gem".
- **[DELTA — location-update intent + staleness reminder]**
  - **`location-cache.js`** — `setUserLocation` now stamps `setAt: Date.now()` on the stored payload. Backwards-compat for pre-v0.30.2 entries (treats `null` `setAt` as unknown age). New helper `getLocationAgeMinutes(redis, chatId)` returns minutes since the user last shared/typed a location.
  - **`nl-intent.js`** — added new intent `"update-location"`. Prompt examples cover English ("My location change", "I moved to Bishan") + Mandarin ("我换地方了"). Whitelist updated.
  - **`index.js#bot.on('message')`** — new `update-location` branch BEFORE the food/drinks/groceries dispatch. On match, drops any pending state and surfaces `LOCATION_REQUEST_KEYBOARD` with the localised ack text. Diagnostic code **D754** logged.
  - **`index.js#deliverPicks`** — after delivery, if `getLocationAgeMinutes(...) >= 15`, fires a fire-and-forget reminder: `📍 Heads up — your location is N min old. Type "my location changed" or share a new pin to refresh.` So users don't drift on stale coords without realising.
  - **`web/cuisine/src/components/Header.jsx`** — adds a third line under the title showing current resolved location: `📍 1.3030, 103.8364` (or `📍 (location not set)` when null). Re-detect button stays in place. User now always knows what coords Gia is using.

- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[OPERATIONAL — Human Lead's immediate fix path for /ver red]**
  Two options:
  1. **Switch model env**: Railway → `GEMINI_MODEL=gemini-2.5-flash` (or just delete the var; default is Flash). Save → auto-redeploy → /ver green within ~30 s.
  2. **Keep Pro, rely on auto-fallback**: leave `GEMINI_MODEL=gemini-2.5-pro`; v0.30.2 will retry-then-Flash on every 503. Slightly more latency on Pro outages but no env change needed.
- **[KNOWN GAPS]**
  - Auto-fallback adds ~7 s of retry+wait before Flash actually runs. During an outage, every Gemini call pays this. Tunable by shortening `delays` in `gemini-retry.js`.
  - The fallback to Flash uses the SAME prompt that was tuned for Pro. Since Pro and Flash have similar JSON-mode behaviour, this works in practice. If output quality regresses noticeably, consider per-model prompt variants.
  - `/ver` still calls the configured model directly (no fallback wrapper) — by design, so the health probe reports the actual configured-model state, not a softened-via-fallback state.
  - Soft-fallback for `/surprise` may surface venues with stale-ish reviews (>4 days, ≤30 days). Banner discloses the trade.
