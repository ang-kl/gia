## New

### [HDR] #44 | 11:00:00 SGT 01-05-26 | v0.26.2 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead: "default should be google map, and listed only 1 link instead of 3". Reduce the per-pick action row to a single Google Maps button across every Sanctuary read surface.
- **[DELTA]**
  - **`index.js#deliverPicks`** — per-pick keyboard collapsed from `[🚗 Directions, 👋 Send to buddy]` (and historically `[🚗 Directions, 📍 Open Map]` pre-v0.21.1) to a single `[📍 Google Maps]` button. URL resolution order: `p.url` → `https://www.google.com/maps/place/?q=place_id:<pid>` → `p.directionsUri` (last resort). The 👋 share-button block + `saveShare` call are removed from this function.
  - **`index.js#deliverSurprise`** — per-card keyboard collapsed from `[🚗 Directions, 🔍 Google, 👋 Send to buddy]` to a single `[📍 Google Maps]` button. Same URL-resolution waterfall.
  - **`web/cuisine/src/components/VenueCard.jsx`** — per-card link reduced from `🚗 Go` (using `directionsUri`) to `📍 Google Maps` (using `venue.url` with the place_id fallback chain).
- **[PRESERVED, NOT REMOVED]**
  - `share.js` (`saveShare` + `loadShare`) and the v0.25.0 share-link pipeline are intentionally kept on disk. The `/start share_<token>` handler still resolves any deep link a user has already received. We removed the *button* that mints new share tokens, not the underlying capability.
  - The `share:<token>` callback_query handler in `index.js` likewise stays active in case any pre-merge share buttons are still in users' chat history (Telegram inline buttons remain tappable indefinitely).
- **[VERIFICATION (sandbox)]**
  ```

  cd web/cuisine && npm run build → vite v5.4.21 ✓ in 1.55s
    → public/cuisine/assets/index-*.js  164.48 kB (gzip 53.31 kB)
  ```
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. Run `/eat` (or any Sanctuary read) → each pick now shows exactly **one** button, `📍 Google Maps`, opening the venue's Google Maps place page.
  2. Run `/cuisine` → tap Search → results render with one button per card. TMA and Telegram chat both consistent.
  3. Run `/surprise` → single Markdown card now has exactly one inline button: `📍 Google Maps`.
  4. Pre-merge share links (already in users' chat history) still work — tap → bot DMs the buddy the original pick. Verifies the underlying share machinery wasn't broken.
- **[KNOWN GAPS]**
  - The button text says "Google Maps" not "Directions" — tapping lands on the place page, not the route. The user can tap "Directions" within the Google Maps place page in one extra tap. Acceptable per spec ("default should be google map").
  - Removing the per-pick `👋 Send to buddy` button means buddy-share is no longer a discoverable feature. If we want it back, candidate surfaces: (a) a `/share` slash command that lists recent picks, (b) a long-press gesture in the TMA, (c) a separate "Share these picks" button per *message* (one per /eat call rather than one per venue).
  - The 🚗 Directions button text + emoji is gone from all surfaces. If a user prefers directions-by-default we'd flip the URL resolution to `directionsUri` first; trivial one-line change.

  buttons.push({
    text: '🚗 Directions',

  // v0.25.0 Buddy Level 1: pre-generate share token and embed it on

      kind: 'pick',
      mealLabel,

  }
