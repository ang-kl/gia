## New

### [HDR] #29 | 12:45:00 SGT 30-04-26 | v0.19.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead: (1) suppress location prompt when location is cached; cache for longer; (2) "not picking up places around 200 m" — increase 200 m hit rate; (3) richer `/transport` with nearest bus stops + arrivals + crowd levels.
- **[DELTA]**
  - **`location-cache.js`** — `LOC_TTL` 30 min → **24 hours**. Once a user shares location (or types a place), the next 24 hours of `/eat /drink /grocery /cuisine` skip the prompt and use the cached coords. Documented Zero-Server breach extended to 24h; rollback path is one-line revert if user disagrees.
  - **`vibe-suggest.js pickValidated`** — radial expansion behaviour changed (supersedes v0.11.0 first-candidate-only):
    - **Old:** try `candidates[0]` at 200 / 500 / 1000 / 2000 m. First success locks `activeRadius`. `candidates[1..4]` only tried at locked radius.
    - **New:** try **ALL candidates at 200 m**. If any validate, use those — no expansion needed. Only if 0 validate at 200 m do we expand to 500 m, then 1000 m, then 2000 m. This puts hard pressure on the 200 m result and stops candidates[0]'s 1 km hit from forcing the rest of the list to also be ~1 km away.
  - **`transport.js`** (new) —
    - `refreshStops(redis)` — paginated `LTA /BusStops` fetch (~5500 stops). Stores in Redis geo `lta:busstops:geo` (key = lng/lat/BusStopCode) plus per-stop hash `lta:busstop:<code>` (description, road name). Skipped if cache is < 24 h old.
    - `nearestStops(redis, lat, lng, radius=800m, count=3)` — `GEOSEARCH` against the geo cache. Returns enriched stops with metadata + distance.
    - `busArrivals(busStopCode)` — calls `LTA /BusArrivalv2`. Returns up to 4 services per stop, each with next-bus minutes + crowd label (`SEA` seats / `SDA` standing / `LSD` limited).
  - **`index.js runTransportCommand`** — replaces the v0.18.0 thin alias with full transport report:
    - MRT alert status (existing)
    - Nearest 3 bus stops within 800 m of cached user location
    - For each stop: up to 4 services with next-bus minutes + crowd
  - **`index.js` boot** — schedules `transport.refreshStops` on startup + every 24 h when `LTA_ACCOUNT_KEY` is configured.
  - **`package.json`** — version → 0.19.0.

- **[RISK]** Med —
  - **Bus stops cache.** ~5500 GEOADD calls on first boot — ~30 s. Subsequent boots use cached set if < 24 h old. Daily refresh at 24h interval keeps drift acceptable.
  - **Bus arrivals quota.** LTA /BusArrivalv2 throttle is per-key. At ~3 stops × ~10 calls/day = 30 calls/day per user — well under throttle.
  - **24 h location cache** is a Zero-Server-breach extension. Already documented as accepted breach in Decisions #12; bumping the TTL adds ~47 h of additional retention vs the prior 30-min policy, hashed by SHA-256. Rollback is one constant change.
  - **200 m radial change** may surface fewer picks for users in low-density areas (because we no longer auto-expand on first-candidate failure). The Hidden Sanctuary fallback path catches this — when 0 validate at all four radii, the 2 km consultant fires.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
