## New

### [HDR] #151 | 11:55:00 SGT 15-05-26 | v0.60.184 — Emoji map pins across Cuisine TMA + /app/map + /transport (bus stops + carparks) | 4 files, ~85 LOC | 1 PR |

- **[INTENT]** Operator: *"Should replace boring pins in the Google Map for specifics like 🐾 Pins for Pet Allowed or 🍮 for Dessert or ✳️ for curated Michelin list or 🅿️ car park or 🚏 Bus Stop."* Both interactive map surfaces (the Cuisine TMA's `MapPanel.jsx` and the public `/app/map` view at `public/app.js`) use Google Maps JS API `AdvancedMarkerElement` + `PinElement` — the `glyph` parameter accepts an emoji string natively, so this is a single-attribute swap per pin.

- **[DELTA]**

  **`web/cuisine/src/v2/components/MapPanel.jsx`** — Cuisine TMA interactive map.

  - New top-of-file helper `pinGlyphFor(venue)` returning the priority-ordered emoji glyph (Michelin > Pet > Dessert) or `null` for the default coloured circle. Dessert detection via `DESSERT_RX = /dessert|patisserie|p[âa]tisserie|bakery|cafe|caf[ée]|ice ?cream|gelato|sweet|confection/i` so French / English / mixed-case all match.
  - Per-venue loop (line ~248): now passes `glyph: glyph || undefined` into `new PinElement(...)` and bumps `scale` from `1` → `1.15` when an emoji glyph is set (legibility on small screens against the orange/green background).
  - Behaviour unchanged for venues without a matching attribute — they render as before (plain coloured circle).

  **`public/app.js`** — public `/app/map` view (DOM-rendered AdvancedMarker).

  - New `pinGlyphFor(venue)` mirrors the TMA helper and adds `kind: 'busStop'` → `🚏` and `kind: 'carPark'` → `🅿️` for the /transport bus-stop and /carpark map surfaces (those payloads don't have michelinCategory / allowsDogs / restaurantType — they're a distinct kind entirely).
  - `makePinContent(num, name, isUser, venue)` — added the `venue` parameter; when a glyph applies, the inner `<span class="num">` shows the emoji instead of the numeric index.
  - `renderVenues` call site (line ~143) updated to pass `v` into `makePinContent`.

  **`maps-url.js`** — slim payload preservation.

  - `buildMapHashUrl`'s `buildSlim` (around line 188) was previously dropping every venue attribute except name / placeId / area / lat / lng / vibe / url / arrivals / lines. The TMA's deep-link round-trip via `/app/map#venues=<base64>` therefore arrived at the public view with NO glyph metadata. Now preserves `michelinCategory`, `allowsDogs`, `restaurantType`, and `kind` when present so the `/app/map` `pinGlyphFor()` has the inputs it needs.

  **`index.js`** — set the `kind` field at the two transport-map slim sites.

  - Bus-stop slim builder (line ~3013, the `slim.push(...)` for nearest bus stops) now includes `kind: 'busStop'`.
  - Carpark map (line ~3465, `carparksWithName` map): adds `kind: 'carPark'`.
  - These are the two points where /transport's bus-stop list and /carpark's nearest-5 list construct the multi-pin map payload; without the `kind` tag, the maps-url `buildSlim` had nothing to preserve and the public/app.js `pinGlyphFor()` couldn't pick the right emoji.

  **`package.json`** — `0.60.183 → 0.60.184` (PATCH; cosmetic map glyph; no contract change).

  **`doc/Journal/journal-0_60_184-15_05_26-1155.md`** — this entry (#151).

  **`doc/.serial-state.yml`** — `journal 150 → 151`, `commit 157 → 158`, `feature 39 → 40`; re-anchored `15-05 '26 11:55 SGT`.

  Web/cuisine rebuilt via `cd web/cuisine && npm run build` (MapPanel.jsx changed).
