# Journal — soleat v0.61.162 (Cuisine search — `body.anchored` flag bypasses the v0.59.46 lightShuffle gate for empty-cuisine anchored searches)

> Operator (after the v0.61.161 widening shipped): asked *"what is
> next"* and picked **option 4** — debug why yesterday's Hougang
> screenshot showed venues NOT in pure distance order (Labula BBQ
> at position 4 despite being the closest at 16 min walk).
>
> Root cause: `index.js:11564` — the v0.59.46 lightShuffle gate
>
>   ```js
>   const skipCacheForShuffle = cuisineQueries.length === 0 || isDessertPick;
>   ```
>
> skipped BOTH the distance-sort (line 12072) AND the v0.61.161
> widening (line 12086) for empty-cuisine searches. The intent in
> v0.59.46 was to let `pipeline.discover`'s lightShuffle rating-
> tier rotation surface variety on re-tap when the user "just
> wants to see anything". The side effect: anchored empty-cuisine
> searches (user picks Hougang via LocationField, no cuisine chip)
> get the shuffle order instead of distance order.
>
> v0.61.162 threads a `body.anchored` bit from the TMA. When set,
> the gate is bypassed → distance-sort + widening fire even with
> no cuisine. The shuffle UX is preserved for the no-anchor "let
> me see anything" path.
>
> Operator instruction: *"ship"*.
>
> Commit 375 / journal 363 / build 165, on branch
> `claude/v0.61.162-anchored-override` off `main` at v0.61.161
> (commit `b7a5aba`, PR #662).

- **[INTENT]** Fix yesterday's "venues not sorted by distance"
  report. When the user has explicitly picked a LocationField
  anchor in the Cuisine TMA, the search result should be
  distance-sorted + widened around that anchor regardless of
  whether a cuisine chip is selected. The v0.59.46 lightShuffle
  behaviour is preserved for the no-anchor "generic browse" path.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/api.js`** — `searchCuisine` now
    accepts + forwards an `anchored` boolean in the POST body.
    When the caller passes `anchored: true`, the field is added
    to the request payload; otherwise omitted (so the backend
    sees `undefined` and treats it as `false`).
  - **`web/cuisine/src/v2/App.jsx`** — at the `searchCuisine`
    call site, passes `anchored: !!locationAnchor`. The state
    field `locationAnchor` is set by `onLocationSelect` when the
    user picks a LocationField suggestion (committed via the
    🔍 button) and cleared when they tap × to clear the anchor.
    A SG-mode user with no anchor picked sends `anchored: false`
    → existing shuffle behaviour.
  - **`index.js`** —
    - Reads `req.body.anchored === true` into `reqAnchored`.
    - Gate becomes:
      ```js
      const skipCacheForShuffle =
        (cuisineQueries.length === 0 || isDessertPick) && !reqAnchored;
      ```
      So anchored searches NEVER skip the distance-sort + widening,
      regardless of cuisine count or Dessert pick.
    - The existing D700 log line now surfaces `anchored=<bool>
      skipShuffle=<bool>` so we can verify deployment behaviour
      without re-reading code.
  - **`package.json`** — `0.61.161 → 0.61.162`.
  - **`doc/.serial-state.yml`** — `commit 374 → 375`, `build 164
    → 165`, `journal 362 → 363`; re-anchored 27-05 '26 02:00 SGT.

## Amendments

- **v0.59.46 lightShuffle gate (`skipCacheForShuffle`)** — the
  gate originally short-circuited distance-sort for empty +
  Dessert paths to preserve `pipeline.discover`'s lightShuffle
  rotation. v0.61.162 narrows the gate to fire ONLY when the
  user is in generic-browse mode (no anchor); explicit anchor
  picks are now always distance-ordered. The original behaviour
  for no-anchor users is preserved verbatim.
