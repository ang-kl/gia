## New

### [HDR] #361 | 00:30 SGT 27-05-26 | v0.61.160 — LocationField dropdown auto-close removed + idempotent same-coord pick | 3 files | 1 PR | 1 build |

- **[INTENT]** Two scoped UX fixes for the operator's bug report:

  1. **Drop the 2.5 s keystroke-idle auto-close** on the Cuisine
     TMA's `LocationField` dropdown. The v0.61.50 behaviour
     auto-closed the dropdown after 2.5 s of typing inactivity,
     which interrupted users mid-compose. When the dropdown
     closed, the field rendered the `pickedLabel` /
     `currentLabel` and the typed query was effectively lost —
     which the operator perceived as "timeout revert to current
     location."

  2. **Idempotent same-coord pick.** If the user picks a
     suggestion whose resolved coords are within ~10 m of the
     current anchor, the field now does nothing — no
     `setLocationAnchor`, no `setSearchCenter`, no
     `saveUserLocation` server save, no map re-centre.

- **[DELTA]**
  - **`web/cuisine/src/v2/components/LocationField.jsx`** (2 edits):
    - File-header comment block reworded around the v0.61.160

## Amendments

- **`LocationField.jsx` v0.61.50 behaviour** — the 2.5 s
  keystroke-idle auto-close intent was "let the search 🔍
  reappear without the user having to blur the input." In
  practice it interrupted long-query composition. v0.61.160
  removes the auto-close; the right-side icon flip
  (🔍 closed → ✏️ open) is now driven solely by explicit user
  actions (pick / clear / blur / Enter).
