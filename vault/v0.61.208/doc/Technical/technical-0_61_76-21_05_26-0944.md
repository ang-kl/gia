## 6. Architecture decisions — v0.61.0 → v0.61.76 (current state)

> Each remains live unless the Deprecated table says otherwise. T-61.0 → T-61.28 carry over verbatim from Technical #46; T-61.29 onward record the post-v0.61.28 arc.

- **T-61.0 — geo-overlay pipeline** — `scripts/build-geo-overlays.js` converts `geoloc/*.geojson` (LTA exits/taxis, URA buildings, NParks parks, STB attractions) into slim `data/geo-*.json`, served at `/api/geo/overlays`. A build-time, data-only step; zero runtime API cost.
- **T-61.7/8 — train-line geometry** — MRT/LRT line polylines derived from OSM/Overpass data, Chaikin-smoothed; line metadata centralised in `mrt-lines.js`.
- **T-61.17 — shared overlay controller** — `mapOverlays.js`, a framework-agnostic controller, duplicated byte-identically across the Cuisine / Hawker / Transport TMAs (no shared package across separate Vite apps; `KEEP IN SYNC` header in every copy).
- **T-61.21 — `attachAmenityPins`** — one shared helper draws venue/hawker-centre surrounding amenity pins (exits / bus / taxi / carpark) on every map TMA; exported from `mapOverlays.js`.
- **T-61.24 — Exit Template** — `geo-exits.json` exit features carry `exitCode`, `station`, `codes`; exit pins are line-coloured; a shared `exitTemplateHtml` renders the popup.
- **T-61.26 — fixed overlay radius + station-scoped chips** — the Nearby↔Details slider was removed; chip layers use one fixed radius; in a train-station-detail view the Exits/Taxis chips clip to the 3 visible stations. The auto-drawn station-context amenity path (`loadAmenities`) was removed.
- **T-61.27 — station codes in `/transport`** — `mrt-lines.codedLinesForStation` pairs `data/mrt-coords.json` `codes` + `lines` index-for-index; the nearest-stations chat rows show the real station code.
- **T-61.28 — geometric exit enrichment** — `build-geo-overlays.js` precomputes each exit's nearby named STB attractions (≤400 m, de-duped, max 3) into the `nearby` field; surfaced in the Exit Template.
- **T-61.25 — `/v` builder menu** — four owner-command action bodies extracted into shared helpers (`ownerHealthCheck` / `ownerFtlogDump` / `ownerOversightLauncher` / `setVerboseMode`), invoked by both the typed commands and the `/v` inline-keyboard callbacks.
- **T-61.29 — LocationField above the map** — the Cuisine TMA's editable location field moved out of the collapsed Search-criteria section to above the map; a new `suffix` prop carries the place-count / search status. A 🔍 `onSearch` button triggers the search (icon switches ✏️ ↔ 🔍; edit mode auto-closes after 2.5 s of keystroke inactivity).
- **T-61.31 — `Google Map ↗` popup standard** — every map-pin info popup ends with a plain `Google Map ↗` text hyperlink; the Cuisine venue popup's blue `#1a73e8` button was removed. Phase F of the 7-phase map-controls redesign.
- **T-61.32 — POI overlay layers** — `CHASClinics` + `SingaporePoliceForceEstablishments` geojson converted to `data/geo-clinics.json` + `data/geo-police.json`, served by `/api/geo/overlays`, rendered as toggleable marker layers on all 3 map TMAs.
- **T-61.36 — unified in-map controls** — a presentational `MapControls` surface (`⋯`/`⋮` overflow menu + quick-toggle pill row + checkbox dropdown) replaces `MapLayerChips` across the 3 map TMAs; a working 🎨 Colour greyscale toggle ships with it. `MapControls.jsx` is byte-identical ×3.
- **T-61.40 — Hospital overlay layer** — `scripts/fetch-hospitals.js` builds `data/geo-hospitals.json` (67 facilities) from a curated name list merged with Google Places detail; rendered as a 🏥 layer on all 3 map TMAs.
- **T-61.42 — Bus Stop overlay layer** — `transport.allStops` + `GET /api/geo/bus-stops` (Redis-cached 24 h) feed a `busstop` `ensureLayer` branch with 🚏 amenity labels and an `openBusInfo` live-arrivals popup, enabled across all 3 TMAs.
- **T-61.43 — SG abbreviation expansion** — `sg-address.expandSgAbbrev` expands Singapore street/building short-forms (Rd/Ave/Sth/Opp/Blk/St…) at the API boundary (`loadGeoOverlays`, `transport.nearestStops`/`allStops`); source geojson + the Redis cache keep the short forms.
- **T-61.47 — fixed high-contrast popup palette** — `infoPalette` no longer follows the Telegram theme; it returns one white-card high-contrast scheme so map popups stay legible in dark mode.
- **T-61.53 — zoom-aware train layer** — at `map.getZoom() >= ZOOM_DETAIL_THRESHOLD (15)` every visible station becomes a line-coloured `<code> <name> station` pill; base-polyline opacity drops below threshold. A unified per-station `_mode` swap subsumes the centre-only rebuild.
- **T-61.55 — station-info data layer** — `scripts/build-station-info.js` joins `mrt-coords.json` + `station-exits.json` + rule-based URL templates into `data/stations.json` (180 operational stations; 175 with exits; SMRT/SBS `more_info_url` per line). A build-time, offline join — no web scraping, no runtime API cost.
- **T-61.56 — bus services per exit** — `fetch-bus-services-by-stop.js` fetches LTA DataMall `/BusStops` + `/BusRoutes` into `data/bus-services-by-stop.json`; `build-station-info.js` optionally joins it to populate `exits[].nearest_bus_stop` (`BUS_NEAR_M = 80 m`, nearest-with-services selection, graceful fallback when the file is absent).
- **T-61.57 — station info card** — a `/api/geo/stations` route plus `mapOverlays` `stationInfoCardHtml` + `openStationCard`; tapping a station opens the card (replacing the v0.61.17/.26 neighbour-detail view). Exit / Bus№ links pan+zoom via `window.__giaStationFocus`.
- **T-61.58 — selective polyline emphasis** — `trackBetween()` slices the prev→current→next stretch of a selected station's line; base lines mute to opacity 0.25 while a station is selected. Supersedes the Cuisine search-emphasis windows; `buildTrain` stores the line code per polyline.
- **T-61.63 — per-station nearest-bus-stop enrichment** — `scripts/enrich-nearest-bus-stops.js` runs in two stages: Stage A is an offline Haversine triangulation against `stations.json` + `LTABusStop.geojson` (radius 400→800→1000 m, 180 stations / 880 entries); Stage B is an optional OneMap `getNearestBusStops` name pass (`ONEMAP_API_KEY`). Bus-stop codes/coords come only from the LTA GeoJSON; names only from OneMap; anything unavailable is `null`.
- **T-61.65 — exit-centroid coordinate field** — `build-station-info` adds `exit_centroid` (the mean of a station's exit coords) to 175 of 180 records, because `mrt-coords.json` station lat/lng is coarse (median 37 m, worst ~1.5 km off the real station). `/api/transport/stations` serves it; the map station pin and derived polylines now use the exit centroid. `lat`/`lng` are kept.
- **T-61.67 — first/last-train block** — `build-station-info` joins `data/sg_train_timings.json` by station code into `first_last_train[]` (238 entries, 152/180 stations); `stationInfoCardHtml` renders a per-line, per-direction, day-typed block. SK_LRT / PG_LRT have no per-station timings (town-centre departures only).
- **T-61.69 — 24-hour places fetch pipeline** — `scripts/fetch-24hr-places.js` calls Google Places API (New) `places:searchText` per type (Retail / Supermarket / Clinic / Petrol / Restaurant / Fitness / Drink / EV Charging), filters to API-confirmed 24-hour places, and writes `data/sg_24hr_places.json` (scaffold committed empty; operator runs with `GOOGLE_PLACES_API_KEY`). Non-invention: every field is verbatim from the API, missing → `null`.
- **T-61.70 — map UI redesign** — `giaToggleStyle` themes toggles (ON = Singapore blue / OFF = white); `MapControls` is a single no-wrap row, the `⋯` menu a white circle; bus-stop pins are white 🚏 rects (zoom-aware); Cuisine venue pins are numbered result-rank circles; the 🔍 FAB flashes 2 s on result load. `mapOverlays` + `MapControls` byte-identical ×3.
- **T-61.73 — `/transport` nearest-bus-stops layout** — `weatherChatFooter` leads the message; the header carries the live stop count; each stop block leads with the road name + a distance sentence; arrival rows read `🚌 Bus № …`; carpark/bus map buttons carry count-aware labels.
- **T-61.74 — Bus menu title + Train radius fix** — the `/transport` Bus menu carries a proper title; the Train nearest-stations search radius was corrected so MRT-sparse spots still resolve a sensible nearest 3.
- **T-61.75 — Menu hub FAB "End"** — the Menu TMA `BackFab` always renders the "End" label (no longer a context-dependent caption).
- **T-61.76 — station-info normalised-name lookup** — `index.js` `stationMoreInfoUrl` builds a second `_stationInfoByNorm` index keyed on `normStationName` (lowercased, `mrt`/`lrt`/`station` tokens + punctuation stripped). An exact-key miss now falls back to the normalised lookup, so a Places display name (`"Harbourfront"`) resolves against a differently-cased JSON key (`"HarbourFront"`) and the `/transport` Train row still hyperlinks.
