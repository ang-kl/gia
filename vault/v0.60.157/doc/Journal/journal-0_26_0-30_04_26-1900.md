## New

### [HDR] #42 | 19:00:00 SGT 30-04-26 | v0.26.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead long-form spec:
  > "Refactor the Gia sensing pipeline to follow a Reason-Fetch-Refine sequence. Use Gemini 2.5 Flash as the primary generator, followed by targeted API injections to ensure the advice is operationally sound."
  Three phases mandated: Primary Reasoning Layer (vault snapshot + Gemini draft with cost from last 5 reviews), Real-Time Contextual Module (data.gov.sg per destination), Consistency Filter (refine draft against context — heavy rain → shelter, heavy traffic → wait time inflation). Plan-mode confirmations: vault scope **(b)** = aggregate across all venue-knowledge Redis caches; **per-cluster** contextual fetch grouped by 500 m grid.
- **[DELTA]**
  - **NEW** `vault-index.js` — Redis aggregator across `gia:vault` (geo set) + `gia:place:<id>` hashes (existing) + `vibe-summary:<id>` (existing) + `place-reviews:<id>` (NEW, 24 h TTL). Boot SCAN populates an in-memory index; 5-min interval refresh. Exposes `setRedisRef(redis)` for fire-and-forget review caching from vibe-suggest, `refreshIndex(redis)` for boot/cron, `snapshotForLocation(redis, {lat, lng}, radiusM)` returning `{vault: [...30 nearest curated venues], summaries: {placeId → text}, reviews: {placeId → [last-5 reviews]}}`, and `cacheReviews(redis, placeId, reviews)` for write-through.
  - **`vibe-suggest.js#hasNegativeRecentReview`** — refactored to capture the full review array, fire-and-forget `cacheReviews()` on every fetch, then continue with the existing keyword-screen logic. The cost — 0 extra Places calls — leverages the review fetch we already pay for. Each cache write trims to 5 reviews × 500 chars; bounded.
  - **NEW** `pipeline.js` — three pure phases plus orchestrator:
    - `reason({lat, lng, query, snapshot, count})` — Gemini 2.5 Flash with a structured prompt that *quotes* the cached review snippets verbatim and asks for `{name, area, vibe, dishes:[1-3], cost_estimate_sgd:{low,high}, signature_dish, queue_min_estimate, booking_required}`. Vault-grounded; falls back to training when vault is silent for that area.
    - `clusterByGrid(venues, gridM=500)` — groups venues into 500 m grid cells (lat-degrees scaled by `cos(lat)` for longitude), each cluster has center coord. Verified against a 3-point fixture (returns 2 clusters). 
    - `fetchClusterContext(cell)` — per-cluster `Promise.allSettled([weather.summary, transport.fetchTrafficIncidents+nearestIncidents, carpark.nearest])`. Tolerant of any individual upstream failure.
    - `fetchContext(venues)` — orchestrates clustering + cluster-context fetch, returns `{clusters: [...], byVenue: Map<placeId, ctx>}`.
    - `refine({draft, context, query})` — Gemini second pass; receives the draft venues + per-cluster context summary; returns `{placeId, travel_advice, queue_min_estimate, weather_flag, shelter_note, cost_estimate_sgd}` per venue. Heavy rain ⇒ `shelter_note` populated; heavy traffic ⇒ queue minutes inflated.
    - `runPipeline({redis, lat, lng, query, validatedVenues, count})` — orchestrator. Phase 1 always runs (snapshot + reason). If `validatedVenues` provided (i.e. callers have already done place-validation), Phase 2 + 3 run as well. Returns `{candidates, refined, diag: events[]}`.
    - Diagnostic codes D601 (vault snapshot), D610–D612 (reason), D620–D623 (cluster + fetch), D630–D632 (refine), D640 (final emit). All mirrored to `console.log` with the same `[Cuisine-Diag]` prefix as the TMA + `/api/cuisine-search` route, so a TMA screenshot can be matched line-by-line to Railway logs.
  - **`cuisine-search.js`** — `searchCuisine` now optionally takes `redis`. Pipeline default-on via `process.env.PIPELINE_ENABLED !== 'false'`. Phase 1 (reason) runs first when redis is present; falls back to the legacy `geminiCandidates15` path when reason returns empty (no API key, transient Gemini failure, etc.). After Places-validation, Phase 2+3 (fetchContext + refine) decorate the venues with `travelAdvice`, `shelterNote`, `weatherFlag`, refined `queueMinEstimate`, and `costEstimateSgd`. The legacy queue-tolerance + post-filters + sort still run last.
  - **`surprise.js`** — `findSurprise` now takes `redis`. After the Gemini enrich call, optionally runs the pipeline's Refine layer on the single venue (1 cluster, 1 weather/traffic/carpark fetch, 1 Gemini call). Returns `travelAdvice`, `shelterNote`, `weatherFlag` on the surprise card.
  - **`index.js`** —
    - + Vault-index init in the boot IIFE: `vaultIndex.setRedisRef(redis)`, `vaultIndex.refreshIndex(redis)`, then `setInterval` every 5 min.
    - + `redis` plumbed into `searchCuisine` via the `/api/cuisine-search` handler.
    - + `redis` plumbed into `findSurprise` via `runSurpriseCommand`.
    - + `deliverSurprise` now renders 🧭 travelAdvice + ☂️ shelterNote when present.
  - **`web/cuisine/src/components/VenueCard.jsx`** — surfaces `💵 S$<low>–<high>` from refine, `🧭 travelAdvice`, `☂️ shelterNote`. `queueMinEstimate` already shown; refine-adjusted value flows in transparently.

- **[TEST]**
  1. After redeploy, Railway logs should show `[Vault-Index] Refreshed: N review caches, M summaries` at boot.
  2. `/cuisine` → Search → Railway logs emit `[Cuisine-Diag] D601 Vault snapshot ...`, `D610 Reason call start`, `D611 Reason returned candidates`, `D620 Cluster build`, `D621 Context fetch start`, `D622 Context fetch done`, `D630 Refine call start`, `D631 Refine ok`, `D640 Pipeline emit`.
  3. Cards now show `💵 S$<low>–<high>` cost band + `🧭 ...travel advice` + `☂️ shelter note` (only on heavy-rain context).
  4. `/surprise` reply card includes 🧭 + ☂️ lines when conditions warrant.
  5. Set `PIPELINE_ENABLED=false`, redeploy → behaviour reverts to v0.25.1 exactly (legacy path), logs absent of D6xx codes.
- **[KNOWN GAPS]**
  - The 500 m grid uses simple lat/lng floor — no projection correction beyond `cos(lat)`. Adequate for SG (single-degree latitude); no defensive code for cluster spillover at cell boundaries.
  - Refine call adds 1 Gemini round-trip (~1.5–3 s). Latency budget for `/cuisine` rises from ~6 s to ~9–11 s. Acceptable trade for "operationally sound" advice; documented as Decision #56.
  - Vault snapshot bounded to 30 nearest venues × 5 reviews × 300 chars = ~45 KB prompt context. Well within Gemini Flash's 1M token window but worth re-evaluating if the vault grows.
  - `data.gov.sg` outage = empty context per cluster. Refine still runs but with `[traffic clear]`/`[no nearby carpark data]`; results stay sane just less informed. No D6xx error fires unless every upstream fails — `D623 Context fetch had failures` for partial.
  - When `redis` is null (defensive path), pipeline is bypassed completely; behaviour reverts to legacy. This is a degradation surface only — pipeline never blocks.
