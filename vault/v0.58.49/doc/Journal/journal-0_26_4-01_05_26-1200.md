## New

### [HDR] #46 | 12:00:00 SGT 01-05-26 | v0.26.4 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead "I still cannot fire the prompt in TMA". v0.26.3's dual-channel bridge addressed *post-tap* failure modes (HTTP 4xx/5xx, network throw, sendData fallback). It did NOT address three *pre-tap* / *no-feedback* modes that look identical to the user as "nothing happens":
  1. **Geolocation never resolves** → `state.loc` stays null → `onSearch` returns early after `showAlert('Tap 📍 first.')` which may be invisible in some Telegram clients.
  2. **The "Sensing the vibe…" banner** only paints when `state.loading` flips, which requires the early-return check to pass first.
  3. **No fetch timeout** — if HTTPS hangs (slow Gemini, blocked webview, hostile MDM), neither HTTP error nor sendData fallback fires.
- **[DELTA]**
  - **`web/cuisine/src/api/search.js#searchCuisine`** — added `AbortController` with default 6 s timeout. On timeout returns `{status: 0, ok: false, body: null, timedOut: true}` so the App-level fallback path treats it identically to a network failure.
  - **`web/cuisine/src/App.jsx`** —
    - + `CBD_DEFAULT = {lat: 1.2839, lng: 103.8517}` constant. When `state.loc` is null at Search time, we use CBD-centre as a hard default instead of blocking the search. Recorded as `D202 Geolocation unavailable — proceeding with CBD default`.
    - + `searchTaps` counter rendered on the Search button label as `🔍 Search · N` after the first tap. Manifestly visible proof the click handler fired.
    - + `bannerText` state. `setBannerText('🌿 Sensing the vibe… (this may take 5–10 s)')` is the FIRST line of `onSearch` so the user sees feedback BEFORE any state update or async work. Cleared on `searchOk`.
    - + `forceChatDelivery()` — a separate handler that bypasses fetch entirely and pushes the payload via `Telegram.WebApp.sendData()` immediately. Useful for hostile-webview environments. Surfaced as a small `💬 Chat` button next to Search.
    - + `buildPayload()` factored out so both `onSearch` and `forceChatDelivery` use the same payload shape.
    - + Inline geolocation hint copy changed from "Tap 📍 above to share your location." to "📍 unavailable — Search will use CBD default. Tap 📍 above to share your real location." so the user understands the search will *still work* without it.
    - + Timeout branch in `onSearch`: `result.timedOut` records `D406 Fetch timed out (>6s)` and triggers the existing dual-channel fallback (sendData → web_app_data → chat delivery).
  - **`web/cuisine/src/main.jsx`** — `console.log('[Cuisine-Diag] D040 bundle loaded version=0.26.4')` on bundle load. New diag code D040 confirms the freshly-built JS is what the browser is actually executing (vs. a stale cached asset) — closes a "we shipped it but is the user running it?" debugging hole.

- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. Open `/cuisine` → browser console immediately shows `[Cuisine-Diag] D040 bundle loaded version=0.26.4`. Confirms a fresh bundle.
  2. Block location in Settings (don't tap Allow). Tap **🔍 Search** anyway → button label updates to `🔍 Search · 1`, banner appears "🌿 Sensing the vibe…" within ~50 ms, search proceeds with CBD default. Diagnostics records `D202 Geolocation unavailable — proceeding with CBD default`. Picks return based on Raffles Place.
  3. Allow location, tap Search. If HTTPS reaches the server, picks render in the TMA. If the server hangs >6 s, console shows `D406 Fetch timed out (>6s)` → `D063 → D061`, TMA closes, picks arrive in chat.
  4. Tap **💬 Chat** instead — TMA closes within 800 ms, picks arrive in chat. Bypasses fetch entirely.
  5. Tap Search rapidly 5 times in 2 seconds → counter shows `🔍 Search · 5`. Even if all fail, the user has unambiguous proof their taps were received.
- **[KNOWN GAPS]**
  - The 6 s timeout is generous for Reason+Refine pipeline (~5–11 s typical) but tight for slow networks. May abort legitimate slow searches; the sendData fallback catches those, so the user still gets results, just delivered to chat instead of in-TMA.
  - CBD default is hard-coded to Raffles Place. Singapore-only product; acceptable. If we ever expand outside SG, replace with a country-default lookup.
  - The 💬 Chat button is intentionally less prominent than Search (tg-card colour vs accent). Want to keep it as escape-hatch UI rather than a primary affordance.
