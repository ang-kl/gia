## New

### [HDR] #219 | 06:55:00 SGT 18-05-26 | v0.61.17 — Cuisine + Hawker train-overlay station-detail view | ~9 kb | 4 files | 1 PR | 1 build |

- **[INTENT]** Operator: the v0.61.16 Transport station-detail view (tap a station → show only
  it plus the stop before/after on the line, with exit/bus/taxi/carpark amenity pins) should
  also work on the **Cuisine and Hawker** maps' train overlay.

- **[DELTA]**
  - **`web/{cuisine,hawker,transport}/src/.../lib/mapOverlays.js`** (byte-identical ×3) —
    the train-overlay square station markers are now **clickable on every TMA** and no longer
    emphasis-gated: they show whenever the Train layer is on (radius-clipped to 800 m). This
    un-gating is required because the Hawker map never sets `trainEmphasis`, so the markers
    would otherwise never appear there. Tapping a station enters a **station-detail view** —
    `handleStationTap` sets `detailStation`; `applyVisibility('train')` then shows only the
    selected station and its line-neighbours one stop before / after (`stationsOnLine` +
    `parseCode` + `PREFIX_TO_LINE`), and `drawAmenities` draws exit / bus-stop (`№<code>`) /
    taxi / pick-up / carpark (`🅿️`) label markers (`amenityLabelNode`) from
    `/api/transport/station-context`. Re-tapping the selected station, or toggling the Train
    layer off, clears it (`exitStationDetail`); a public `clearStationDetail()` is exposed.
    The selected station gets a larger centre marker; marker content is rebuilt only when the
    selection changes, not on every pan.
  - **`package.json`** — 0.61.16 → 0.61.17.

- **[VERIFICATION (sandbox)]**

- **[STATUS]** DRAFT → PR (base `main`).

- **[TEST]** Cuisine / Hawker TMA, Train overlay on: nearby station squares are tappable;

  or toggling Train off clears it.

- **[KNOWN GAPS]** Detail-view adjacency uses the station's primary line (`lines[0]`); an

  never enables the overlay `train` layer (it draws its own lines), so the code is inert
  there. PR #499's "clickable train-station markers" intent is now delivered by this PR —
  #499 is superseded and can be closed (its editable Cuisine location field, if still
  wanted, would be a separate change).
