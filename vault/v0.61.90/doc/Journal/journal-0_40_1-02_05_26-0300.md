## New

### [HDR] #84 | 03:00:00 SGT 02-05-26 | v0.40.1 | n/a kb | n/a lines
- **[INTENT]** Switch the default LLM model from `claude-opus-4-7` to `claude-sonnet-4-6` per Human Lead. Sonnet 4.6 is the better speed/cost balance for the bot's reasoning workloads (~3× cheaper input, ~1.7× cheaper output) while remaining fully capable for the GEOSPATIAL_CULINARY_ANALYST prompt.
- **[CRITICAL CAVEAT DISCOVERED]** Sonnet 4.6 (and Opus 4.6) reject **assistant-turn prefills** with HTTP 400. The v0.40.0 `llm-client.js` used a prefill of `{` or `[` to force JSON-only output (Anthropic's equivalent to Gemini's `responseMimeType: 'application/json'`). On Opus 4.7 this worked; on Sonnet 4.6 it would 400 every JSON request. Fixed before flipping the default — see DESIGN below.
- **[DESIGN]**
  1. **Default model swap** in `llm-client.js`:
     - `DEFAULT_MODEL` is now `claude-sonnet-4-6` (was `claude-opus-4-7`).
     - New env override `ANTHROPIC_OPUS_MODEL` (default `claude-opus-4-7`) so callers that genuinely need Opus-tier reasoning can opt in explicitly.
     - The 12 callers that pulled `llm.DEFAULT_MODEL` automatically pick up Sonnet 4.6 with no edits required: `pipeline.js` (reason / reasonExecute / refine), `cuisine-search.js`, `surprise.js`, `vibe-suggest.js`, `recognised-seeder.js`. Haiku 4.5 callers (gatekeeper, nl-intent, vibe-summary, consultant, heritage-significance) and the Sonnet 4.6 prompt-builder are unchanged.
  2. **Prefill removal**:
     - Dropped the `messages.push({ role: 'assistant', content: prefill })` block.
     - Tightened the system-prompt JSON instruction to: *"Respond with valid JSON only. No prose, no markdown, no code fences. Begin your response with the opening bracket."*
     - This is the pattern Anthropic recommends for Sonnet 4.6 (the migration guide explicitly lists `output_config.format` as the canonical replacement, but the lighter-weight system-prompt-only approach matches our existing parse safety net and is sufficient).
  3. **Defensive `stripJsonFences()` helper** added in `llm-client.js`. When `json: true`, the wrapper strips ```json fences and prose preamble before returning text. This protects the 5 callers that call `JSON.parse(result.response.text())` directly without their own extractor (gatekeeper, nl-intent, vibe-suggest, consultant, recognised-seeder). The two callers that already have local extractors (`pipeline.js#extractJsonArray`, `surprise.js#extractJsonObject`) are double-protected — harmless overhead.
  4. **Backward compat** — the `jsonShape` parameter on `generate()` is retained in the signature (ignored at runtime) so call sites that pass `jsonShape: 'array'` keep compiling.
- **[DELTA]**
  - **MODIFIED** `llm-client.js`: default model swap, prefill removed, system-prompt instruction tightened, `stripJsonFences()` helper added, new `OPUS_MODEL` export.

- **[KNOWN GAPS / TRADE-OFFS]**
  - **Sonnet 4.6 vs Opus 4.7 quality** — the GEOSPATIAL_CULINARY_ANALYST prompt was tuned against Gemini 2.5 Flash for months, then briefly against Opus 4.7. Sonnet 4.6 should match or exceed Flash quality and is competitive with Opus 4.7 on most tasks; if a specific workload (e.g. recognised-seeder award scouting, where factual recall over 8 years matters) regresses, that single caller can flip back to `llm.OPUS_MODEL` without touching the others.
  - **No `output_config.format` schema** — the canonical Anthropic JSON-enforcement path uses `output_config: {format: {type: 'json_schema', schema: {...}}}` with strict schema validation. We rely on system-prompt instruction + the existing `extractJson*` helpers + the new `stripJsonFences` safety net. Robust in practice, less bulletproof than schema-enforced output. Future patch can introduce per-caller schemas if drift is observed.
