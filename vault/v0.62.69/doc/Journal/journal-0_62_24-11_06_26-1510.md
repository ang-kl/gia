## New

### [HDR] #674 | 15:10 SGT 11-06-26 | v0.62.24 — #root perimeter border (≥600px) framing the centred TMA column | web/{cuisine,hawker,menu,transport,oversight}/src/styles.css | 1 PR | 1 build |

- **[INTENT]** After v0.62.16 gave inner cards a visible `--tg-border`, the **outer TMA shell** still had
  no frame — on tablet/desktop the centred column sat on the letterbox with only a faint bg/card
  contrast, and in dark mode the perimeter was hard to make out.

- **[DELTA]** Appended a uniform rule to **all 5 TMA `styles.css`**:
  ```css
  @media (min-width: 600px) { #root { border: 1px solid var(--tg-border); } }
  ```
  The centred column is now framed by the **same subtle ~3:1, luminance-derived (colour-blind-safe)
  `--tg-border`** used for cards — consistent in **both light and dark**. iPad-mini portrait (744 px) +
  all tablet/desktop widths are ≥600 px → covered.

- **[DELTA — scope choice]** **Mobile full-bleed is intentionally left borderless** (operator's
  "desktop/tablet/iPad-mini" pick): a perimeter line on the phone screen edge would read as clipped
  under Telegram's mobile header and hug the bezel awkwardly.

- **[DELTA — misc]** `package.json` `0.62.23 → 0.62.24`; `doc/.serial-state.yml` commit 690→691,
  journal 673→674, **build 423→424**; re-anchored 15:10 SGT.

- **[VERIFICATION (sandbox)]** `npm run build:cuisine` green; the `#root{border:1px solid var(--tg-border)}`
  rule confirmed in the built CSS; **full suite 3361/3361** green (CSS-only change — no test impact).

- **[STATUS]** PR-**OPEN**, squash-merge via gh REST. Railway redeploys all TMA bundles on merge.

- **[TEST — operator, deployed]** On **tablet / desktop / iPad-mini** in dark mode, the Cuisine / Hawker

- **[KNOWN GAPS]** Mobile perimeter left borderless by design; revisit if the operator later wants a
