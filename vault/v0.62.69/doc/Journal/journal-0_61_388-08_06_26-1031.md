- **[INTENT]** The Option-B currency target must follow the phone's **Region**, never its **Language**. A phone Language=English(UK) / Region=Singapore was resolving to **GB → £**.

- **[INVESTIGATION — traced 100%, read-only]**
  - **FX-1 (the bug):** `device-region.js` `pickDeviceRegion` preferred the iOS Region override (`-u-rg-`) but **fell back to `regionFromLanguageTag(navigator.language)`** when absent → no override in the Telegram WebView ⇒ `en-GB → GB → GBP` = forex keyed off the **language**.
  - **FX-2:** the same-country no-conversion rule **already exists** (`currency-format.js:281` returns native when `userCountry === venueCountry`); it only breaks when FX-1 mis-resolves the region.
  - **DROP (price):** the price line is built only when Google returns a numeric `priceRange` (`currency-format.js:267 → null`); the SG hawker venues simply **have no `priceRange`** from Google (`pipeline.js:885` *does* request it) — a data gap, not a logic drop.
