- **[INTENT]** v0.61.413 added Vietnam to the belt **gate**, but a durian search in Vietnam still returned **0**. Root-cause + fix the search itself.

- **[ROOT CAUSE]** durian / durian-pastry use a **strong haystack** (name + area + formattedAddress + primaryType) **plus** a strict name-gate `_nameHasDurian` (`special-mode.js:483`, enforced at `:697` — `if (!_nameHasDurian(venue)) return false`). Both key off **`DURIAN_CORE_TERMS`**, which listed EN / Malay / Chinese / JP / KR / TH — but **no Vietnamese**. Vietnamese durian sellers are named *"Sầu riêng …"*, so **every one was rejected** → 0 results, even though the v0.61.413 gate now allows VN.

- **[DELTA]** (`special-mode.js`, server-only)
  - **`DURIAN_CORE_TERMS`** += `'sầu riêng'`, `'sau rieng'` (diacritic + bare — Google listings/reviews use either). This one change feeds all three consumers: the keyword loop (`KEYWORDS[DURIAN]`), the strict name-gate `_nameHasDurian`, and the `DURIAN_CORE_RE` review counter.
  - **DURIAN seed** += `'sầu riêng'` so the Places `searchText` surfaces VN-named sellers directly (not just the English `'durian shop'`).
  - **DURIAN_PASTRY** seed += `'bánh sầu riêng'`; keywords += `'sầu riêng'`, `'sau rieng'`, `'bánh sầu riêng'`, `'banh sau rieng'` — gated by the pastry/bakery accept-type, mirroring the v0.61.377 JP/KR/TH local-script additions.
