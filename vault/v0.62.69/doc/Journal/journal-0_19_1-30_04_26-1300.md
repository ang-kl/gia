## New

### [HDR] #30 | 13:00:00 SGT 30-04-26 | v0.19.1 | n/a kb | n/a lines
- **[INTENT]** Fix the `/weather` reply showing only the 2-hour forecast (no temp / humidity / rain / wind). v0.18.2 switched to v2 endpoints (`api-open.data.gov.sg/v2/real-time/api/...`); user's `/weather` output proves the v2 calls are returning empty (or erroring) and `Promise.allSettled` was silently swallowing the failures.
- **[DELTA]**
  - **`weather.js`** — `fetchRealtime(endpointPath, label)` is the new orchestrator: tries v2 first; if the response is empty stations OR throws, falls back to the legacy v1 endpoint (`api.data.gov.sg/v1/environment/...`). Both shapes parsed into the same uniform `{source, timestamp, stations}` envelope. Adds `console.warn` on every fall-through so Railway logs show exactly which endpoint failed and why.
    - `fetchV2Realtime(endpointPath)` — same v2 shape parser as before.
    - `fetchV1Realtime(url)` — new; parses the legacy `{items, metadata.stations}` shape. Direct port of pre-v0.18.2 logic.
    - V2 → V1 mapping table for all five real-time endpoints.
    - `summary` now exposes `tempSource: 'v1' | 'v2' | 'none'` so the chat layer can show which source is live.
  - **`ver.js checkDataGov`** — probe rewritten as a chain:
    - Try v2 first; if `stations.length > 0 && readings.length > 0` report `NEA v2 N stations (auth|no key)`.
    - If v2 returns empty, probe v1 → report `NEA v2 empty → v1 N readings (auth|no key)`.
    - If v2 errors, probe v1 → report `v2 fail → v1 N readings (auth|no key)`.
    - If both fail, the `probe` wrapper marks 🔴 and shows the v2 error.
  - **`package.json`** — version → 0.19.1.
- **[ROOT-CAUSE NOTES]** Three things v2 might be doing:
  1. The base hostname `api-open.data.gov.sg` may not be reachable from Railway egress (e.g. CF rule, region block).
  2. The endpoints might require an API key that we didn't pass (the OpenAPI spec marks the header as `optional`, but real-world enforcement may differ).
  3. The endpoints might have moved or been renamed since the OpenAPI spec was uploaded.
  We don't need to know which — the v1 fallback always was, and remains, free + unauthenticated. Logs will reveal the actual cause when Human Lead next runs `/weather`.
- **[RISK]** Trivial — additive fallback, no behaviour change when v2 succeeds. v1 fallback is what we shipped pre-v0.18.2 and ran successfully for the prior weeks.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. After redeploy, run `/ver` → `data.gov.sg` row tells the story:
     - 🟢 `NEA v2 N stations` → v2 working.
     - 🟢 `NEA v2 empty → v1 N readings` → v2 silently empty; v1 covers.
     - 🟢 `v2 fail → v1 N readings` → v2 errors; v1 covers.
     - 🔴 with error → both failed; investigate.
  2. `/weather` from a CBD location → temp + humidity + rain (when > 0) + wind + 2h forecast.
  3. Watch Railway logs for `[Weather] v2 X failed: ... ; trying v1 fallback` — that's the diagnosis line.
- **[NEXT]** When v2 root cause is known (from the next `/ver` + log line), follow up with a targeted fix (or just stay on v1 if it remains stable).
