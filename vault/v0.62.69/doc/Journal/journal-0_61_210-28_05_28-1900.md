## New

### [HDR] #411 | 19:00 SGT 28-05-28 | v0.61.210 — country-text-match defence | 4 files | 1 PR | 1 build |

- **[INTENT]** Replace the v0.61.207 "trust upstream Places blindly"
  OTHER-region post-filter with a defence layer that drops venues
  whose address text doesn't mention any geographic keyword for the
  user's chosen country. Operator's anchors are typically deep
  inland (Pahang, Putrajaya), so this is belt-and-braces — but
  closes a known gap.

- **[DELTA]**

  **NEW `country-text-match.js`** (~95 lines, CommonJS):
  - **`COUNTRY_KEYWORDS`** — frozen map of ISO 3166-1 alpha-2 code →
    string array of lowercase keywords. 16 countries (matches the
    v0.61.191 OTHER picker set):
    | CC | Keywords (sample) |
    |---|---|
    | MY | malaysia, wilayah persekutuan, kuala lumpur, putrajaya, selangor, johor, pahang, ipoh, kuching, kota kinabalu, … (47 total) |
    | TH | thailand, bangkok, phuket, chiang mai, pattaya, krabi, sukhumvit, silom, sathorn, … (20) |
    | ID | indonesia, jakarta, bali, bandung, yogyakarta, batam, denpasar, ubud, … (24) |
    | JP | japan, tokyo, osaka, kyoto, shibuya, shinjuku, ginza, akihabara, … (23) |
    | … | (covers PH, VN, KR, CN, HK, TW, AU, NZ, BN, KH, LA, MM) |
  - **`hasKeywordsFor(cc)`** — boolean test.
  - **`filterVenuesByCountry(venues, cc)`** — keeps venues whose
    `${v.area} ${v.name}` lowercase text contains ANY keyword.
    Returns input unchanged on unknown/empty cc (fail-open).
    Returns `[]` when venues isn't an array.

  **NEW `__tests__/country-text-match.test.js`** — 14 tests:
  shape (16 codes, expected ISO list), MY operator-failure case
  (Padang Tengku address keeps, Skudai address keeps via "skudai"
  keyword, cross-border Singapore venue drops), TH/ID/JP/HK
  coverage, fail-open paths (unknown cc, empty cc, null venues),
  case-insensitive match.

  **`index.js` cuisine-search OTHER branch** (~20 lines, line
  13254ish):
  - Replaces the v0.61.207 "skipping the SG/JB area-text filter"
    comment-only branch with a real filter call.
  - Reads `ctxCountry = await getUserCountryPref(redis, csChatId)`
    (the same `country-pref:<chatId>` Redis key used by /lcountry
    + the Cuisine TMA OTHER picker + the Menu TMA picker).
  - When `ctxCountry !== 'SG'` AND `hasKeywordsFor(ctxCountry)`,
    applies `filterVenuesByCountry(venues, ctxCountry)`.
  - Logs:
    - `D703d OTHER country-text-filter cc=<CC> <before> → <after>` —
      when filter runs.
    - `D703c OTHER-region: no country-pref ...` — when filter skipped
      (no pref / unknown / no keywords).
  - **Fail-open contract:** if Redis hiccups, country-pref is
    missing, or the country has no keyword set, the filter is
    skipped (same as v0.61.207). The 120 km from-user hard gate
    (line ~13190) is the floor.

  - **`package.json`** — `0.61.209 → 0.61.210`.
  - **`doc/.serial-state.yml`** — commit 422 → 423, build 212 →
    213, journal 410 → 411; re-anchored 28-05 '26 19:00 SGT.

- **[KNOWN GAPS]**
  - Keyword sets are static / curated. New cities or transliteration
    variants need PRs. Easy adds.
  - Filter is keyword-based (substring match). A venue called
    "Singapore Airlines Office, Selangor" in MY would match BOTH
    SG and MY keywords. Current logic: any MY keyword wins — kept.
    But if user is searching from SG and a Selangor venue's name
    contains "Singapore", it'd also keep. Mostly OK in practice.
  - We rely on the country-pref Redis key being current. v0.61.196
    (Cuisine TMA sync) + v0.61.209 (Menu TMA sync) cover both
    TMAs; chat /lcountry covers chat. If a user picks OTHER region
    without setting /lcountry first, pref defaults to SG and the
    filter is skipped (same as v0.61.207). Acceptable.
