## New

### [HDR] #282 | 16:44 SGT 21-05-26 | v0.61.84 — bus-stop name parity + wake-from-idle location prompt | ~3 kb | 5 files | 1 PR | 1 build |

- **[INTENT]** (1) Make the `/transport` nearest-bus-stops chat result lead
  with the same field the "view bus stops" map card shows; (2) on the first
  chat message after a long idle gap, prompt once to keep or change the
  stored location.

- **[DELTA]**
  - **`index.js`** —
    - `runTransportBus` nearest-stops block — the per-stop heading now leads
      with `stop.description || stop.roadName` (was `stop.roadName ||
      stop.description`). The "view bus stops" map pins are built from the
      `slim` array with `name: ${stop.description} …`, and the map's bus
      data carries no `roadName`, so the map already showed the description;
      the chat result now matches it. (#3)
    - New `IDLE_WAKE_MS` const (6 h) + `promptLocationOnWake(chatId, msg)` —
      sends a one-tap "keep / new location" prompt when a location is stored.
    - `bot.on('message')` — calls `touchLastSeen` for every message and
      captures the prior idle gap (`wokeAfterIdleMs`); the text path fires
      `promptLocationOnWake` once when the gap exceeds `IDLE_WAKE_MS`
      (skipped for `/location` / `/l`, which already drive the location flow).
    - `bot.on('callback_query')` — two new handlers: `wake:keep` (edits the
      prompt to the `wake.kept` confirmation) and `wake:new` (clears the
      keyboard, runs `runLocationCommand`). (#2)
  - **`location-cache.js`** — new `touchLastSeen(redis, chatId)`: a per-chat
    `seen:<hash>` marker (30-day TTL) that returns the PRIOR timestamp then
    stamps `now` — one call yields the idle gap and refreshes the marker.
  - **`i18n.js`** (EN + FR) — `wake.locationCheck`, `wake.keepBtn`,
    `wake.newBtn`, `wake.kept`.
  - **`__tests__/location-cache.test.js`** — new file, 5 `touchLastSeen`
    tests (first-call null, prior-timestamp return, per-chat isolation,
    marker refresh, closed-redis reconnect).
  - **`package.json`** — `0.61.83` → `0.61.84` (PATCH).

- **[TEST]** `/transport` → Bus → nearest stops: each stop leads with its
  name (e.g. "Opposite VivoCity"), matching the "Show all N bus stops" map.
  With a location saved, after a >6 h idle gap the first command shows a
  one-time "Welcome back…" prompt — "Stay here" keeps it, "New location"
  opens the `/location` share flow. The prompt does not re-fire on the next
  message and is skipped when the first message is `/location`.

- **[KNOWN GAPS]**
  - The stored location's own TTL is 24 h, so the wake prompt naturally only
    fires in the 6–24 h idle window — past 24 h there is no location to
    re-confirm (the next location-aware feature re-prompts to share one).
  - The bot cannot read device GPS unsolicited — "the device moved" is
    surfaced as a question on idle-wake, not a passive detection.
  - Operator requests #1 (⋯/⋮ button → top-left) and #4 (the
    `CR_Google_Map_Design_1022.MD` spec) were already implemented on `main`
