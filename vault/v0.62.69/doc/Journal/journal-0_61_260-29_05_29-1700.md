- **[DELTA]**

  **1. NEW `durian-variance-runner.js`** — pure-runner module at
     repo root. Exports:

     ```js
     async function runVariance({
       mode,            // 'durian' | 'durian-pastry'
       apiKey,          // required — caller pulls from env var
       regions,         // optional — default 4 cities
       limit,           // optional — default 8
       radiusM,         // optional — default 8000
       onProgress,      // optional callback ({done, total, mode})
       log              // optional per-line logger callback
     })
     ```

     Returns the same JSON report shape that
     `scripts/durian-variance.js` writes via `--json-out`:
     ```json
     {
       "schemaVersion": 1,
       "scriptVersion": "0.61.260",
       "mode": "durian",
       "ranAtIso": "...",
       "durationMs": 184321,
       "apiKey": { "hashSha256First16": "..." },
       "regions": [{ ... }, ...],
       "seeds": { ... },
       "config": { "LIMIT_PER_QUERY": 8, "RADIUS_M": 8000 },
       "totals": { "placesReturned": ..., "kept": ..., "rejected": ..., "precision": ... }
     }
     ```

     No I/O of its own — caller decides whether to write to disk,
     send via Telegram, store in Redis, etc.

  **3. `index.js` — new `dv:` callback flow** mirroring the
     v0.61.213 `psv:` pattern:

     ```
     dv:menu                  → 3 buttons (Durian / Pastry / Both)
     dv:run-<which>           → confirm prompt
     dv:go-<which>            → fire the run
     dv:close                 → dismiss
     ```

     Owner-gated via `isOwnerChat(chatId)`. Handler helpers:
     - `ownerDurianVarianceMenu(chatId, messageId)` — top-level menu
       with cost + ETA preamble.
     - `ownerDurianVarianceConfirm(chatId, messageId, which)` —
       single-tap confirm prompt.
     - `ownerDurianVarianceRun(chatId, which)` — dispatches single
       mode (`durian` / `pastry`) or both sequentially.
     - `_ownerDurianVarianceRunSingle(chatId, mode)` —
       runs `runVariance` via the new module, persists JSON to
       Redis at `dv:latest:<mode>` (60 d TTL), builds + posts the
       cross-region summary to chat, then `sendDocument`s the
       full JSON as a Telegram attachment named
       `<mode>-variance-<YYYY-MM-DD>.json`.

     Progress: 30-second-throttled `🥥 mode: 45/120 (37%)` chat
     pings during the run (mirrors `psv:`'s telemetry).

  **4. `.github/workflows/durian-variance.yml`** — auto-trigger on
     `push: branches: [main]` removed. The workflow remains
     callable via manual `workflow_dispatch` from the Actions tab,
     but no longer fires (and fails) on every relevant merge. Stops
