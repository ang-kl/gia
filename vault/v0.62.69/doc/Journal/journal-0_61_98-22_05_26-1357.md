### [HDR] #298 | 13:57 SGT 22-05-26 | v0.61.98 — station-tap fix | ~1 kb | 2 files | 1 PR | 1 build |

- **[INTENT]** A station tap on the Transport TMA map needed three
  taps before the station info card stayed open. Fix it so one tap
  works.

- **[DELTA]**
  - **`web/transport/src/components/MrtMapPanel.jsx`** — `openStationInfo`
    opened the `InfoWindow` anchored to the tapped marker. A station
    tap makes `renderPins` re-run twice — once for the `focusedStation`
    change, again when the `/api/transport/station-context` fetch
    resolves and bumps `detailCtxTick` — and `renderPins` tears down
    and rebuilds every station marker each time. An `InfoWindow`
    anchored to a torn-down marker silently closes, so the card only
    stuck on a later tap once the context was cached and the
    re-renders had settled. Fix: anchor the `InfoWindow` to the
    station's lat/lng **position** (`setPosition` + `open({ map })`)
    instead of the marker, so it survives the marker rebuilds.
  - **`package.json`** — `0.61.97` → `0.61.98` (PATCH).

    `ctx.taxis` correctly, so an empty taxi/bus result means
    `/api/transport/station-context` is returning those arrays empty.

    index / the 400 m search radius in the endpoint; (2) taxi features
    whose names match neither `/stand/i` nor `/pick ?up/i` are
    classified `kind:'stop'` and filtered out by `attachAmenityPins`.
    Needs a runtime/data check before a fix.
