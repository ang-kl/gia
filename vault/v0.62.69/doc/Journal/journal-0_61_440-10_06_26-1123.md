- **[INVESTIGATION — read-only trace + finder agent]** Both symptoms share **one root: location was excluded from the dedup keys.**
  - **`computeCriteriaHash` (index.js:8967)** built the per-chat seen-set key from `cuisines / filters / prices / radius / region / freeText / ratingPref` — **not lat/lng or country**. `region='OTHER'` is identical for KL, Penang, Bangkok… so **every Others city shared one seen-set**. After a prior Others search consumed that pool, a fresh KL search returned only the **1 residual** unseen venue.
  - That 1-result response sets `finalBatch=true / knownTotal=1`; the **client FAB** (`App.jsx:3553`, `poolExhausted && !dirty`) then stays disabled because `dirty`/`stateSig` (`App.jsx:628`) **also ignore location** — so a new city never re-enables it. (The location-card 🔍 has no `disabled`, which is why only that one worked.)
  - **Michelin (bug 2):** verified there is **NO country filter excluding MY** — `michelin-data` has **69 visitable MY venues**, `michelinCountry` resolves to `MY` correctly. But the Michelin path's own walk-seen-set (`michelin-walk.js:44`) is **also location-blind** (one meta per chat) — the same family of bug.

- **[DELTA]**
  - **`index.js`** — new **`searchLocToken(lat, lng, countryCode)`** = `"<CC>|<lat.toFixed(1)>,<lng.toFixed(1)>"` (~11 km bucket: a stable city anchor keeps its bucket so re-tap "more" still works, while distinct cities separate). Folded into `computeCriteriaHash` as a `loc` field and threaded at all **3** cuisine-search call sites (resetSeen / cuisineSearchHash / dedupHash).
  - **`michelin-walk.js`** — `computeCriteriaHash` gains `loc`; the index.js walk-hash call passes `loc = "<michCC>|<michSelectedCity>"` so switching country (or KL↔Penang) starts a **fresh** Michelin walk instead of paginating past entries "seen" under a different country.
  - **`web/cuisine/src/v2/App.jsx`** — the FAB re-enables on a **previewed city** (`isDisabled = … && !selectedCityLocation`) so a newly-picked Others city is searchable via the FAB; the committed search then returns a fresh non-final batch and clears `poolExhausted` on its own.
  - **`__tests__/michelin-walk.test.js`** — +2 cases (loc separates SG/MY/VN; loc stable for the same city).
  - **`package.json`** `0.61.439 → 0.61.440`; **`doc/.serial-state.yml`** commit 652 → 653, journal 639 → 640, **build 411 → 412**; re-anchored 11:23 SGT.
