## New

### [HDR] #25 | 11:45:00 SGT 30-04-26 | v0.17.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead doc upload (Places API generative summaries). Add `places.generativeSummary` to all FieldMasks; surface Google's Gemini-powered ~100-char place overview in chat replies with required attribution.
- **[DELTA]**
  - **`vibe-suggest.js`** — added `places.generativeSummary` to `validateWithPlaces` FieldMask. New helper `extractGenerativeSummary(place)` handles missing field, region/place-type non-coverage, and the docs' `disclosureText` ↔ `disclaimerText` inconsistency. Each venue now exposes `googleSummary: {overview, disclosure, flagUri}` or `null`.
  - **`vault.js verifyOpenNow`** — Place Details FieldMask + `generativeSummary`. Returns `googleSummary` per pick.
  - **`vault.js queryVault`** — surfaces stored `generativeOverview / generativeDisclosure / generativeFlagUri` from `gia:place:<id>` hash; returns `googleSummary` on each pick.
  - **`vault.js fetchOpenVaultPicks`** — propagates `googleSummary` (live verify wins, falls back to stored).
  - **`consultant.js nearbyAnyOperational`** — added `places.generativeSummary` to FieldMask; Hidden Sanctuary venues carry `googleSummary`.
  - **`sync-vault.js`** — Place Details FieldMask + `generativeSummary`. `vaultUpsert` writes 3 new fields into `gia:place:<id>` hash so Vault hits include the summary on every read.
  - **`index.js deliverPicks`** — Sanctuary read message now appends a `💡 <overview> _(Summarized with Gemini)_` line when Google has a summary for the venue. **Required attribution** per Places API policy is included as part of the line.
  - **`package.json`** — version → 0.17.0.
- **[REGION LIMITATION]** Per Places (New) docs, `generativeSummary` is currently supported only in **English, India + United States**. Singapore is **not** in the supported region list. The plumbing works regardless — the field will simply be absent on most/all SG places, and the `extractGenerativeSummary` helper returns `null` cleanly. The moment Google extends regional coverage to SG, soleat picks up the summaries automatically with no further code change.
- **[ATTRIBUTION COMPLIANCE]** When the field IS populated (US/India places, or SG places once region opens), every chat reply includes `_(Summarized with Gemini)_` (Markdown italic) directly inline with the summary text. Per the Places API policy, this satisfies the AI-summary disclosure requirement.
- **[RISK]** Low —
  - Most current responses for SG places will lack the field; chat reply degrades cleanly (no summary line surfaces, no attribution surfaces, existing Sanctuary read still works).
  - Modest payload size growth on Place Details / searchText responses where the field IS populated.
  - No new external API call patterns; existing G4 envelope unchanged.
  - The doc-inconsistency `disclosureText` vs `disclaimerText` handled defensively.
- **[STATUS]** PROD — auto-deploys with the next Railway build.

  3. Re-run `sync-vault.js` to populate the new `generativeOverview / generativeDisclosure / generativeFlagUri` fields on existing Vault entries.
