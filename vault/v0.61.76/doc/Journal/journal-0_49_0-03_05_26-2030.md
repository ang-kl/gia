## New

### [HDR] #97 | 20:30:00 SGT 03-05-26 | v0.49.0 | n/a kb | n/a lines

- **[INTENT]** Build a canonical 125-hawker-centre vault sourced from the NEA master-list PDF (`list-of-hcs_-25-july-2025.pdf` — provided by Human Lead). The v0.48.x scrape + LLM web_search paths return centre names that may be mistyped, abbreviated, or hallucinated. Cross-referencing against the canonical 125 lets us drop fakes/dupes, normalise to NEA spelling, and build address-anchored Maps URLs (much more precise than the current `<name> + ' Singapore'` form).

- **[DESIGN]**

  1. **NEW `hawker-vault.js`** — module that fetches the PDF once, parses it with `pdf-parse`, and caches the structured 125-record list in Redis with 30-day TTL.
     - `fetchAndParsePdf()` — axios GET (responseType: arraybuffer, 20s timeout) + `pdfParse(Buffer)` + `parsePdfText` → `[{name, address, postal}]`.
     - `parsePdfText(text)` — heuristic parser. NEA's PDF lays out centres as numbered records:
       ```
       1. Adam Road Food Centre
          2 Adam Road, Singapore 289876
       ```
       Scans for `/Singapore (\d{6})$/` as the postal anchor, walks back ≤3 lines to find the numbered name. Dedupes by postal.
     - `getAllCentres(redis)` — cache-first wrapper. 30-day TTL key `nea:hawker-vault:v1`.
     - `normaliseName(s)` — lowercase, strip "Centre/Center/Market/Food/Hawker/Complex/Cooked", drop punctuation. Both inputs and vault names normalised before comparison.
     - `editDistance(a, b)` — standard Levenshtein DP.
     - `findByName(centres, query)` → `{centre, score, distance}` or `null`. Returns exact matches at score 1; substring matches scored by length ratio; edit-distance fallback at ≥75% similarity.
     - `mapsUrlForCentre(centre)` — builds `https://www.google.com/maps/search/?api=1&query=<encoded "name, address">` (vs the v0.48.1 `<name> + Singapore` form which was prone to hitting wrong matches).
     - `annotateNames(centres, names)` — bulk version for diagnostic / debug.
     - All failures non-fatal — sandbox + first-call cold start return `{ok: false, centres: []}` and callers fall back to v0.48.x behaviour.

  2. **MODIFIED `nea-scrape.js#enrichClosureRows`** — third arg `vaultCentres` (optional). When supplied:
     - Each row's name is matched via `findByName` at score ≥ 0.85.
     - On confident match: row's `name` is normalised to vault spelling; `mapsUrl` swapped to address-anchored form; `vaultMatched: true` flag added.
     - On no match: row keeps its scraped name + the v0.48.1 `<name> + Singapore` Maps URL (back-compat preserved).

  3. **MODIFIED `nea-scrape.js#getStructuredClosures`** — opportunistically pulls vault on every call. Vault unavailable → continues without (logs a warning). Returns `vaultUsed`, `vaultMatchedCount` for diagnostics.

  4. **NEW dependency: `pdf-parse@^1.1.4`** (~10 KB packed). Already battle-tested PDF text extractor. Pure JS, no native deps.

- **[REUSED]**

  - Redis client for caching — same pattern as `nea-scrape.js` cache.
  - `getStructuredClosures` integration — vault is opt-in; existing v0.48.1 callers (which pass no vaultCentres) still work.

- **[KNOWN GAPS / SCOPE CUTS]**
  - **Sandbox can't validate live PDF parse.** Parser tested only against synthetic fixtures matching the expected NEA layout. If NEA's PDF format differs (e.g. multi-column layout, embedded images for names, OCR-only PDF), the parser returns 0 records and the code falls back to v0.48.1 unanchored behaviour. Acceptable — fallback is automatic.
  - **PDF version is hardcoded** (`list-of-hcs_-25-july-2025.pdf`). NEA updates this quarterly with a new dated filename. When that happens, the URL needs a manual bump — there's no auto-discovery (NEA doesn't publish a stable "latest" alias). Mitigation: cache TTL 30d so a missed filename change shows up within a month rather than going stale silently.
  - **No /p hawker-vault diag command** — would let Human Lead inspect the parsed list inline. Defer until parser proves reliable in production.
  - **Vault loads on every getStructuredClosures call (cache-checked).** Redis hit is sub-ms but the JSON.parse of 125 records is ~1ms. Acceptable.
  - **Fuzzy match threshold is 0.85 (substring) / 0.75 (edit distance).** Tunable. If too lenient, scraped "X Hawker Centre" might match the wrong vault entry. If too strict, common abbreviations are lost. The current settings prefer false-negative (no match → falls back to unanchored URL) over false-positive (wrong match → wrong URL).
  - **No vault-side telemetry** — Pino sweep deferred to a future version.

**Prior (v0.48.x):** No master list of SG hawker centres in the codebase. Scrape + LLM paths trusted whatever name they returned.

**v0.49.0 amendment:** `hawker-vault.js` fetches NEA's quarterly master PDF, parses it to JSON, caches in Redis 30 days. Provides ground-truth 125-record list for cross-referencing.
