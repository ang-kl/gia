## New helpers / shapes in this arc

### `reviewText(r)` Places-v1 unwrap (v0.60.156 — PR #397)

Local helper defined at outer scope in `index.js` (above `handleMichelinSearch` + `extractDishes` so the cuisine-chip path can re-use it). Signature:

```js
function reviewText(r) {
  if (!r) return '';
  const t = r.text;
  if (!t) return '';
  if (typeof t === 'string') return t;
  if (typeof t === 'object' && typeof t.text === 'string') return t.text;
  return '';
}
```

Handles both:
- **Places v1 shape** — `{ text: { text: '…', languageCode: 'en' } }` (current, since the Places API migration earlier in 2026).
- **Legacy bare-string shape** — `{ text: '…' }` (defensive — no-op for any source still returning the old form).

Called at 5 sites:

| Site | File | Line (approx) | Was | Now |
|---|---|---|---|---|
| Michelin handler regex pool | `index.js` | ~6125 | `recent.map((r) => r.text \|\| '').join(' . ')` | `recent.map(reviewText).join(' . ')` |
| Michelin `v.recentReview` write | `index.js` | ~6140 | `String(recent[0].text \|\| '').slice(0, 200).trim()` | `reviewText(recent[0]).slice(0, 200).trim()` |
| `extractDishes` recent filter | `index.js` | ~9498 | `recent = v.reviews.filter((r) => r?.text)` | `recent = v.reviews.filter((r) => reviewText(r))` |
| `extractDishes` allText.map | `index.js` | ~9540 | `allText.map((t) => …)` (used to take raw `r.text`) | `allText` now built from `reviewText(r)` values |
| `extractDishes` return-`snippet` | `index.js` | ~9595 | `String(recent[0].text).slice(0, 200).trim()` | `reviewText(recent[0]).slice(0, 200).trim()` |
| `v.recentReview` fallback (cuisine-chip path) | `index.js` | ~9612 | `v.recentReview = String(v.reviews[0].text)…` | `v.recentReview = reviewText(v.reviews[0])…` |

Without this unwrap, `String({ text: '…', languageCode: 'en' })` coerces to the literal string `"[object Object]"` — a valid string, so every `typeof === 'string'` guard downstream passed it through unchanged. The v0.60.154 + v0.60.155 belt-and-braces guards stay in place but are now redundant on the happy path.

Caps: `isMichelin ? 11 : 17`. Push logic truncates the forward branch (`prev.slice(0, cursor + 1)`) then appends, then overflows oldest-first (`next.length > cap ? next.slice(next.length - cap) : next`). ### Per-criteria seen-set reset on TMA mount (v0.60.155 — PR #396)

`startSession` in `cuisine-session.js` now also DELetes every `cuisine:seen:<chatId>:*` SET key for the calling chatId (via `SCAN MATCH` + pipelined `DEL`). The per-criteria seen-set is the long-lived `cuisine:seen:<chatId>:<criteriaHash>` SET (no TTL — only cleared on explicit ↺ Start over). Wiping it on every TMA mount means a multi-week session no longer drifts into "every criteria returns zero new venues". The mount-side call (`POST /api/cuisine/session/start` fired by the TMA on `App.jsx` mount) was already there from v0.60.146 — the reset is now an additional inner step inside that handler.

The explicit ↺ Start over button still works as before (per-criteria reset only); this new path resets ALL per-criteria seen-sets at once for the chatId.

### `/api/cuisine/copy-one` plain-text retry (v0.60.156 — PR #397)

Mirrors the v0.60.145 `/api/cuisine/copy-all` hardening at the single-venue copy endpoint (~line 8024). Pattern:

```js
try {
  await bot.sendMessage(chatId, body, htmlOpts);
} catch (e) {
  console.warn('[Cuisine] copy-one HTML failed; retrying plain:', e.description || e.message);
  const plain = body.replace(/<\/?b>/g, '').replace(/&amp;/g, '&').replace(/&lt;/g, '<').replace(/&gt;/g, '>');
  try {
    await bot.sendMessage(chatId, plain, { ...htmlOpts, parse_mode: undefined });
  } catch (e2) {
    console.error('[Cuisine] copy-one sendMessage retry failed (plain):', e2.description || e2.message);
    return res.status(500).json({ ok: false });
  }
}
```

Preserves `reply_markup` on both attempts; only 500s if both fail.

### Zero-results auto-retry guard + retry CTA in `App.jsx` (v0.60.157 — PR #398)

State additions:

```js
const lastZeroRetrySnapRef = useRef(null);
const [zeroRetried, setZeroRetried] = useState(false);
```

Decision block (inserted in `runSearch` between `setQuestionDeclined(false)` and `setVenues(...)`):

```js
const isRetryCall = opts?.resetSeen === true;
const isZeroResult = Array.isArray(r.venues) && r.venues.length === 0;
const currentSig = stateSig(snap);
if (isZeroResult && !isRetryCall && lastZeroRetrySnapRef.current !== currentSig) {
  lastZeroRetrySnapRef.current = currentSig;
  Promise.resolve().then(() => runSearch(snap, anchor, { resetSeen: true }));
} else if (isZeroResult && isRetryCall) {
  setZeroRetried(true);
  setCriteriaOpen(true);
} else if (!isZeroResult) {
  setZeroRetried(false);
  lastZeroRetrySnapRef.current = null;
}
```

- **Loop-safety**: the retry path sets `opts.resetSeen=true`, which the guard checks (`!isRetryCall`) — so the recursion cannot fire a second auto-retry from within the first retry call.
- **Per-criteria scope**: the ref is keyed by `stateSig(snap)` (the existing JSON-stringified criteria signature used elsewhere in the file). The same signature can never auto-retry twice in a row; any criteria change implicitly re-arms a fresh retry budget.
- **CTA render**: a dedicated panel below the exhausted-note block, gated `zeroRetried && !loading && venues.length === 0`, with two new i18n keys (`result.noMatchAfterRetry` + `btn.resetFiltersRetry`, both EN + FR). Tapping the button: re-opens the criteria builder (idempotent), clears `zeroRetried`, clears the ref, and re-fires `runSearch(state, null, { resetSeen: true })`.
- **Microtask wrapping**: the silent retry is dispatched via `Promise.resolve().then(...)` so the current `finally { setLoading(false) }` runs first, then the retry's `setLoading(true)` re-fires the spinner cleanly (no skip / no double-spinner).

Six new tests in `__tests__/cuisine-zero-retry.test.js` pin the `decideAutoRetry` truth table (fresh zero → retry; retry-came-back-zero → showCta; already-retried same sig → noop; sig changed → fresh retry; non-zero → clear; non-zero-on-retry-path → clear). Helper is re-declared in the test file per the existing `cuisine-search-helpers.test.js` convention (test stays decoupled from the React tree).
