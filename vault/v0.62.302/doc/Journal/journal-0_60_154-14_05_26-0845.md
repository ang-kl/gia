- **[DELTA]**

  **`index.js`** (Michelin enrichment cache READ, lines ~6160–6172) — added `typeof === 'string' && .trim()` guards to the `recentReview` / `vibe` / `signatureDish` merges. Without them, a corrupt prior cache entry (where one of those fields was written as a non-string — most likely an `{}` placeholder from a prior misuse, or a future regression) flowed through to the TMA verbatim and React stringified it as `[object Object]` on the venue card. Step 5 cache WRITE refills with valid strings on the same handler call, so no separate invalidation is needed — the bad value is silently skipped on read and replaced on write within one search.

  **`web/cuisine/src/v2/App.jsx`** (loadingHint prop, ~976–984) — replaced both EN and FR strings; glyph swapped 🎩 → ✳️. New copy: EN `"✳️ Fetching the latest Michelin information. Please wait a moment."`, FR `"✳️ Récupération des dernières informations Michelin. Un instant…"`.

  **`web/cuisine/src/v2/App.jsx`** (state additions ~155, warm-start handler ~398, runSearch success ~552, FAB cluster ~1202–1264) — introduced a client-side page-history cache (`pages: Page[]`, `cursor: number`) and a `useEffect([cursor])` re-applier that swaps every per-field state (`venues`, `comboInfo`, `misrepNote`, `cookMethodPivot`, `sessionFull`, `pageStackDepth`, `michelinRemaining`, `exhausted`, `poolCount`) when the user steps through history. `runSearch` success now (a) truncates forward history via `pages.slice(0, cursor + 1)`, (b) appends the new page, and (c) advances the cursor; cap is 17 pages for normal search (≈200 venues at 12/page) or 11 pages for Michelin (≈130 entries) per the operator's targets, with the oldest page shifted off on overflow. Warm-start populates the first cached entry so a subsequent search-then-Back lands on the warm-start view rather than skipping it. TMA mount (where `startSession` is called, line ~250) also resets `pages=[]` + `cursor=0` to mirror the server-side wipe.

  Rewrote the FAB cluster JSX (~1202–1264): removed the v0.60.148 right-column `{pageStackDepth > 0 && (…)}` ⇠ button and replaced the LEFT slot (formerly just `<BackFab inline closeOnly />`) with a left cluster of `<BackFab mode={cursor>0 ? 'back' : 'close'} onBack=…>` plus, conditionally when `cursor < pages.length - 1`, a `⇢ Next` button. Right column keeps 🔍 Search + ⇡/⇣ scroll only.

  **`web/cuisine/src/v2/components/BackFab.jsx`** — additive: new optional `mode` ('back' | 'close') and `onBack` props. When `mode='back'`, glyph `⇠` and label `back` render and the click invokes `onBack()` instead of `window.history.back()`. When `mode='close'` (or legacy `closeOnly`), `🔚 end` glyph + `WebApp.close()` behavior preserved. The legacy `window.history.length > 1` heuristic is the fallback when neither prop is supplied — so any other caller (none in-tree right now) keeps its existing behavior.

  **`__tests__/michelin-cache.test.js`** — appended a new `describe('Michelin enrich-cache read — type guards (v0.60.154)')` with 6 cases that mirror the inline guard block locally: nested-object `recentReview` dropped, array `vibe` dropped, `null` `signatureDish` dropped, well-formed strings accepted, existing field values not overwritten, empty/whitespace-only strings rejected. Test count: 1728 → **1734**.

  **`package.json`** — `0.60.153 → 0.60.154` (PATCH — bug fix + UI tweak + additive client-state surface).
