## New

### [HDR] #353 | 16:10 SGT 25-05-26 | v0.61.152 — translate-review module + chat-side `💬 "…" ( 🇮🇹 translated)` render | 8 files | 1 PR | 1 build |

- **[INTENT]**
  1. Translate the picked review text into the user's device language
     so the `( 🇮🇹 translated)` suffix is literal (the displayed
     quote IS the translation, not the original).
  2. Render that translated quote in chat-side venue cards
     (`formatVenueBlock` + `formatTechniqueVenueBlock`) — the
     v0.61.151 render was JSX-only (Cuisine TMA `ResultCard.jsx`),
     leaving chat blocks unable to surface the same tag.
  3. Plumb the nationality preference into `runFreeTextSearch` so
     a user who types `italian food` in chat (not via the TMA)
     also gets the translated-quote treatment.
  4. Cache translations in Redis (30-day TTL) so repeated searches
     don't repay the Gemini call.

- **[DELTA]**
  - **`translate-review.js`** (NEW, ~140 lines). Pure module:
    - `translateReview({ text, sourceLang, targetLang, placeId,
      reviewIdx = 0, redis = null, _genAIFactory })` →
      translated string (or original on failure / src===tgt).
    - Short-circuits when `primaryTag(sourceLang) === primaryTag(targetLang)`
      (BCP-47 normalisation — `zh-CN` / `zh-Hant` / `zh-Hans` all → `zh`).
    - Redis cache key
      `translate-review:v1:<placeId>:<idx>:<src>:<tgt>`, 30-day TTL.
      Skips cache entirely when `redis.isOpen` is false (chaos test
      against Redis-flaky Railway deploys).
    - Gemini model chain: `gemini-flash-latest` →
      `gemini-2.5-flash` → `gemini-1.5-flash`. Each attempt is
      try/catch'd; on all-fail returns the original text rather
      than throwing (so the caller can decide whether to set the
      `translated` flag).
    - Output cleaner strips ```fences and surrounding `"` / `'`
      (Gemini sometimes wraps the translation in quotes despite
      the "no preamble, no quotes" instruction).
    - `LANG_NAME` map covers the same ~50 BCP-47 primary tags as
      `cuisine-review-language.SLUG_TO_LANGUAGE`. Used to build
      a readable prompt ("Translate from Italian to English"
      reads better than "from `it` to `en`").
  - **`__tests__/translate-review.test.js`** (NEW, ~140 lines, 14
    tests in 5 `describe` groups). Coverage:
    - `primaryTag` normalisation (BCP-47 subtags, non-strings,
      empties).
    - `langName` map hits + unknown-tag fallback (uppercase).
    - Short-circuit cases: src===tgt, missing target, empty input.
    - Gemini path: prompt construction (verifies Italian / English
      / source text all appear in the prompt), fence stripping,
      all-model failure → original, empty response → original.
    - Redis cache: hit (Gemini not called), miss → write, closed
      Redis → cache bypass with no exceptions.
  - **`cuisine-review-language.js`** — new
    `pickAndTranslateReview({ reviews, nationalityLang, targetLang,

    review qualifies. `translateFn` is injectable for tests so the
    helper can be unit-tested without Gemini. Defensive: an
    explicit `reviewIdx` is honoured IF it passes the rating /
    language gate; otherwise the helper scans from index 0.
  - **`__tests__/cuisine-review-language.test.js`** — +8 tests

## Amendments

- **v0.61.151 (PR #652) — half-implementation of the "translated"
  tag.** The picker selected an Italian-language review and tagged
  it with `( 🇮🇹 translated)`, but the surfaced `recentReview`
  was the raw Italian text. Operator's literal reading of the
  spec required the displayed text to BE the translation. v0.61.152
  closes the loop. The v0.61.151 backend setter at index.js:11987+
  is replaced with the new translate-aware loop; the rest of the
  v0.61.151 helper module (`SLUG_TO_LANGUAGE`,
  `getLanguageForCuisines`, `pickPreferredReview`, etc.) is
  preserved verbatim and re-used.
