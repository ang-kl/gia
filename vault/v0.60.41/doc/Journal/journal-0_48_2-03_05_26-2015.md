## New

### [HDR] #96 | 20:15:00 SGT 03-05-26 | v0.48.2 | n/a kb | n/a lines

- **[INTENT]** Fix three Human-Lead-reported bugs that surfaced once v0.48.1 deployed:
  1. The "📍 Google Maps" button on `/surprise` (and every other pick card) opens Google Maps showing the literal text `place_id:ChIJ...` in the search field, not the place pin.
  2. `/surprise` "View all picks" button uses Google Maps directions URL — renders as a **route** between picks, not as **5 markers on one map**.
  3. `/cuisine` TMA's "🗺 View all 5 picks on map" footer link sends the user to an external browser tab whose URL is `https://gia4lunch-production.up.railway.app/app/map#venues=<base64>` — Google Maps can't parse it; the user sees the long base64 URL instead of pins.

- **[DESIGN]**

  1. **`googleMapsUrl(place)` in `maps-url.js`** — switch from the broken `/maps/place/?q=place_id:<id>` form to the documented Google Maps URLs API:
     ```
     https://www.google.com/maps/search/?api=1&query=<NAME>&query_place_id=<PLACE_ID>
     ```
     Per Google docs (developers.google.com/maps/documentation/urls/get-started), `query_place_id` pins the place; `query` supplies the search-field text so the user sees the venue name, not the raw id. Reads `place.name` or `place.displayName.text` (Places New shape). Falls back to name-only search when no id, then to existing `place.url` / cid / coords.

  2. **`deliverPicks` in `index.js`** — replace `sendGoogleMapsContainer` (Google Maps directions URL, route mode) with a Telegram `web_app` button pointing at the TMA `/app/map` view. Uses `buildMapHashUrl(picks, { webhookDomain })` from `maps-url.js` to produce an absolute URL with all picks' lat/lng/name/placeId encoded in the hash. The TMA's leaflet renderer pins each pick as a marker on a single map.
     - Falls back to the legacy directions URL only when `webhookDomain` is unset (sandbox / local dev) — production always has `RAILWAY_PUBLIC_DOMAIN` set.

  3. **`web/cuisine/src/components/ResultsGrid.jsx`** — drop `target="_blank"` and `rel="noreferrer"` on the footer "View all on map" `<a>` tag. The TMA WebView was opening `/app/map` in an external browser tab (gia4lunch domain), but `/app/map` is meant to render INSIDE the TMA. Removing target="_blank" keeps the navigation in the same WebView so the leaflet map renders directly.

  4. **`/surprise` pre-flight message** — changed "Hunting up to 12 hidden gems" → "Hunting up to 5 hidden gems" to match the v0.48.1 `SURPRISE_TARGET_COUNT = 5` change.

  5. **NEA fallback button URL fix** — `runHawkerClosureLive`'s web_search-fallback path still hardcoded the old `/list-of-hawker-centres-closure-and-cleaning-schedules` URL on its "📅 NEA hawker mgmt" button row. Now reuses the same `buttonRow` (pointing at `/overview`) as the scrape-success path. Single source of truth.

  6. **Strengthened LLM prompt for `/hawker` web_search fallback** — when the scrape returns 0 rows AND we fall back to Anthropic web_search, the prompt now:
     - Explicitly references the NEA `/overview` source URL as PRIMARY.
     - Tells Claude to search for town-council reposts / news aggregators if the page itself isn't fetchable.
     - Demands ALL 6 fields per closure (was: 5 fields, durationDays optional).
     - Requires the EXACT output template (numbered blocks, summary header, citation footer, plain-text + emoji, no markdown tables).
     - Sets a floor: "aim to return at least 5 entries" (the NEA quarterly list typically has 20–60 active closures); "If you find ZERO closures, say so explicitly" — no silent empty replies.
     - Maps URL format pinned to `?api=1&query=<encoded name + ' Singapore'>`.

## Amendments

> **Recipe AU-7:** quotes prior content verbatim then appends change.

**Prior (v0.45.1 maps-url.js#googleMapsUrl):**
```js
const id = place.placeId || place.id;
if (id) return `https://www.google.com/maps/place/?q=place_id:${encodeURIComponent(id)}`;
```
That URL form makes Google Maps treat the literal text `place_id:CHIJ...` as a search query. The user sees the raw id in the search field, not a place pin.

**v0.48.2 amendment:** Use the documented Maps URL API form `?api=1&query=<name>&query_place_id=<id>`. `query_place_id` pins the place; `query` provides search-field display text.

**Prior (v0.32.0+ deliverPicks):** `sendGoogleMapsContainer` produced a Google Maps directions URL (route mode) for the "View all picks" button. With ≥2 venues, the URL renders as a sequenced walking-route, not a multi-marker map view.

**v0.48.2 amendment:** Use the TMA `/app/map` view via inline-keyboard `web_app: { url: buildMapHashUrl(picks, { webhookDomain }) }` button. The leaflet map pins each pick as a separate marker on one map.

**Prior (v0.32.0 ResultsGrid.jsx):** `<a href="/app/map#venues=..." target="_blank" rel="noreferrer">`. Inside the cuisine TMA, `target="_blank"` opens the URL in an external browser tab — user sees the gia4lunch URL with base64 hash, no leaflet rendering.

**v0.48.2 amendment:** Removed `target="_blank"` + `rel="noreferrer"`. Navigation stays in the same TMA WebView, `/app/map` renders inline.
