- **[DESIGN]**

  1. **NEW shared helper `ensureFreshLocationOrPrompt(chatId, label)`** in `index.js`. Reads cached location, returns `null` (after firing `LOCATION_REQUEST_KEYBOARD`) if stale (>5 min) or missing. When fresh, also sends a "📍 Current: <reverse-geocoded address>" header line. DRYs the pattern across `/transport` (via `sendTransportMenu`), `/surprise`, `/carpark`. Uses `reverseGeocodeAddress` (v0.52.0 helper, 24h cache).

  2. **`runSurpriseCommand`** rewritten to call `ensureFreshLocationOrPrompt(chatId, '/surprise')` at entry. Removes the inline `getUserLocation` + `bot.sendMessage(LOCATION_REQUEST_KEYBOARD)` block. Same for the `PIPELINE_TASKS_ENABLED=false` legacy branch (now uses the same shared helper).

  3. **`runCarparkCommand`** rewritten:
     - Uses `ensureFreshLocationOrPrompt(chatId, '/carpark')` (was: silently defaulted to Raffles Place when no cached location — confusing).
     - Adds the "5 carparks on one map" button mirroring `/surprise`'s `deliverPicks` pattern: `buildMapHashUrl(carparks, { webhookDomain })` → `web_app: { url: <TMA /app/map> }`. Falls back to legacy `sendGoogleMapsContainer` (Maps directions URL) when `webhookDomain` unset.

  4. **NEW `recognised-fetch.js`** — LLM-driven SG culinary-awards fetcher.
     - Replaces v0.52.0's `michelin-scraper.js` (Ferracin selectors are 6+ years stale, return 0 cards on the modern Michelin Guide site).
     - Uses Anthropic `web_search` (already wired via `llm.generate({ webSearch: true })`) with a strict prompt covering all 5 award bodies Human Lead specified: MICHELIN Star (1/2/3★), MICHELIN Bib Gourmand, Asia's 50 Best Restaurants, Asia's 100 Best Restaurants, World Culinary Awards.
     - Year scoping (`targetYear()`): SGT month → if month ≤ 5, use previous year; if June+, use current year. Never goes back >1 year.
     - Output JSON contract: `{year, awards: [{award, date, name, dishes, mapsUrl}, ...]}`. Each award category fully specified; mapsUrl pinned to `?api=1&query=<name>+Singapore` form.
     - `sortAwards()`: date DESC, then name ASC, then dishes ASC.
     - `groupByAward()`: returns array of `{award, entries}` ordered by `AWARD_ORDER` (Star 3 → Star 2 → Star 1 → Bib → Asia50 → Asia100 → WCA → others alphabetical).
     - 24h Redis cache, keyed by `recognised:fetch:v1:<year>` so a year boundary cleanly invalidates.

  5. **`runRecognisedCommand`** fully rewritten:
     - Drops location prompt (per Human Lead — "ditch entirely, just show award groupings island-wide").
     - Drops `recognised-store` dependency, drops `michelin-scraper`, drops `summariseAwards` / `RECOGNISED_FILTER_ALIASES` / `venueMatchesCategory` / `RECOGNISED_RADIUS_M` / `RECOG_TOPN`.
     - Drops the `<filter>` argument (no longer applicable — output is always the full grouping).
     - One Telegram message per award group (so each can carry its own inline-keyboard map buttons, capped to 8 per group).

  6. **DELETED `michelin-scraper.js`** and `__tests__/michelin-scraper.test.js`.

  7. **NEW `cuisines-vault.js`** — 73-cuisine catalogue parser. Reads `doc/Feature/cuisines_js.MD` (the user's `CUISINE_CATEGORIES` JS-export spec) directly via regex over its consistent structure. No re-authoring of the data into a separate MD table — single source of truth. Sync read, module-level memo cache. Exports `getAllCuisines`, `getByCategory`, `findBySlug`, `findByNameOrKeyword`, `slugify`, etc.

  8. **NEW `web/cuisine/src/v2/`** — 4th major rewrite of the cuisine TMA. Coexists with v1 chip-grid behind `?v=` query param (default `2`).
     - **`App.jsx`** — composes everything. Debounced 350ms search trigger. Inferred cuisines/filters from NL response sync back into UI state.
     - **`lib/api.js`** — POST/GET wrappers for `/api/cuisine/{catalogue, search, nl-query}`.
     - **`lib/state.js`** — URL-hash-synced filter state (`#cuisines=ramen,thai&halal=1&prices=$,$$&r=800`). Reload preserves state.
     - **`components/QuickFilters.jsx`** — `[Open now] [≤10 min walk] [Halal] [Vegetarian] | [$] [$$] [$$$]` (multi-select chips per Human Lead spec; dropped Solo-friendly / Hawker / Cafe).
     - **`components/CuisineDrawer.jsx`** — 8-category collapsible accordion. Common Here open by default; others collapsed. Multi-select max 5; over-cap dims rest. Auto-opens any category with selections. Clear-all footer.
     - **`components/MapPanel.jsx`** — Google Maps JS via `/maps-key`. AdvancedMarkerElement; user blue, venues green, focused orange.
     - **`components/ResultCard.jsx`** — name + rating + price + walk + vibe + 📍 Maps + 📋 Copy.
     - **`components/FlipPanel.jsx`** — CSS-3D flip card (rotateY 180°). Front = ResultsList; back = textarea + Submit. Auto-flips back after NL submit; "From: '<text>' [Edit]" badge persists on results.

  9. **NEW backend endpoints** in `index.js`:
     - `GET /api/cuisine/catalogue` — returns the 8 categories + 73 cuisines.
     - `POST /api/cuisine/search` — multi-cuisine OR via `pipeline.discover`; post-fetch filters for openNow / price / halal / vegetarian / walking-time.
     - `POST /api/cuisine/nl-query` — keyword-infers cuisines (max 5) + filters from free text; returns `inferredCuisines + inferredFilters` so TMA syncs UI.

  10. **MODIFIED `web/cuisine/src/main.jsx`** — dual-render via `?v=` query param (default `2`).
