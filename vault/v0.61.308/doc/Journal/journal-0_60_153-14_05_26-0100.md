- **[DELTA]**

  **(1) Bug fix — Michelin dedup: strip `radius` from the criteriaHash.**
  `handleMichelinSearch` builds its own `criteriaHash` to scope the per-criteria seen-set. The hash included `radius: searchRadius` (mirroring the cuisine-chip path) — but Michelin is a curated list, location-agnostic. Any TMA slider drift between consecutive 🔍 Search taps changed the hash → fresh seen-set → same first 12 served again. The fix omits `radius` from the Michelin criteriaHash (the cuisines + combo slugs + filters + prices + freeText + region remain). Consecutive taps now reliably reuse the same seen-set and rotate through the ~130 curated entries (`index.js:5663` block).

  **(2) Diagnostic log** at handler entry: `[Michelin] tap chatId=… hash=<8-char prefix> seen=<size> combo=[<slugs>]`. Surfaces the dedup state on every tap so the next "same first 12" report can be triaged from Railway logs in seconds (`index.js` right after `readSeenSet`). One line, never throws.

  **(3) Force-warm enrichment cache — new `michelin:enrich:<slug>` Redis key, 7-day TTL.** Distinct from the v0.60.150 `michelin:place:<slug>` Places resolution cache. After review-extract (Step 1 — existing), a new **Step 2 reads enrichment from cache** for each of the 12 venues (any missing `dishes` / `recentReview` / `vibe` / `signatureDish` is filled in from prior sessions); a **Step 3 narrate** runs only on the subset still missing `vibe` or with `dishes.length < 2` (saves Gemini cost on warmed entries; cold entries still get the LLM call); a **Step 4 force-fill** guarantees `dishes.length >= 2` and a non-empty `recentReview` on every venue (cuisine-label-based fallback dishes + a `★★★ Michelin Guide 2025 · curated recommendation.` (EN) / FR-equivalent stand-in review when no live review is available); and a **Step 5 write-back** persists the final enrichment to the cache so the NEXT search of the same chatId / criteria has the fields ready instantly. Operator's *"Check for the latest review and 2 or more dishes to try for first 12 pull and store in the server"* is exactly this: store, refresh-on-search, never ship empty.

  **(4) "Curating Michelin list" loading copy in the TMA.** New optional `loadingHint` prop on `ResultPanel` replacing the generic "Loading…" while the request is in flight. `App.jsx` sets it to *"🎩 Curating the Michelin list — fetching the latest reviews and signature dishes. Hang on…"* (EN) / *"🎩 Curation de la liste Michelin — récupération des avis récents et plats signatures. Patience…"* (FR) when `state.cuisines.includes('michelin')`, else null (falls back to the generic copy). Operator: *"UI: Asking user to be patience, to curate the list with review."*

  **Navigation** stays as-is per operator clarification — the existing 🔍 Search FAB re-fires the search and now reliably advances through the seen-set thanks to fix #1.

## Amendments

### `handleMichelinSearch` criteriaHash — drop `radius`

> Prior (v0.60.42 → v0.60.152): `computeCriteriaHash({ cuisines: ['michelin', …], filters, prices, radius: searchRadius, region: 'SG', freeText })`. Radius was always included.
>
> Change (v0.60.153): the Michelin builder omits `radius` (kept everywhere else). Michelin uses a curated list, not a location-based Places search, so radius is irrelevant to which 12 are returned. Including it meant any TMA slider drift between consecutive 🔍 taps invalidated the seen-set and re-served the same first 12 — the operator's report. Comment block at `index.js:5663` records the rationale.

### `handleMichelinSearch` enrichment flow — cache-aware

> Prior (v0.60.147 → v0.60.152): two-step enrichment — (1) review-derived `extractDishes`, (2) LLM narrate on the full 12. Cards could still ship with `dishes = []` and no `recentReview` (sparse Places reviews + narrate parse-fail).
>
> Change (v0.60.153): five-step flow — (1) review-extract (unchanged); (2) NEW enrichment-cache READ (`michelin:enrich:<slug>`, 7-day TTL) fills missing fields from prior sessions; (3) narrate runs on the SUBSET still missing `vibe` or with `dishes.length < 2` (saves Gemini cost on cache HITs); (4) NEW force-fill guarantees `dishes.length >= 2` + non-empty `recentReview` via cuisine-label / Michelin-tier boilerplate; (5) NEW cache WRITE refreshes the enrichment per search. Operator: *"Check for the latest review and 2 or more dishes to try for first 12 pull and store in the server. Refresh each time the same ChatID search Michelin."*

### `ResultPanel` + `App.jsx` — Michelin-specific loading copy

> Prior: `loading ? "Loading…" : …`. Generic copy for every flow.
>
> Change (v0.60.153): new optional `loadingHint` prop. App.jsx passes the Michelin curating message (EN + FR) when `state.cuisines.includes('michelin')`; null otherwise. Operator: *"UI: Asking user to be patience, to curate the list with review."*
