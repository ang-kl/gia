- **[KNOWN GAPS]**
  - **The variance script doesn't measure "relevance"** — only raw result counts. Places' `searchText` returns whatever it ranks highest, so the totals are upper bounds. A follow-up could pipe the results through Gemini for per-venue specialist/occasional/unrelated labels (mirroring the v0.61.275 Plan B contract). Out of scope for this patch.
  - **No bot integration.** Unlike `durian-variance`, there's no `/ver → Slavic-EE variance` button. The operator runs locally. If the data is useful, a follow-up could mirror the v0.61.260 `/ver` panel for Slavic/EE.
  - **Cost is operator-paid** — the script uses the local `GOOGLE_MAPS_API_KEY` env var, not Railway's. $0.63 per run is small but worth noting up-front.
  - **City selection is capitals-only** — for Russia / Poland / etc. there are bigger restaurant hubs (St. Petersburg, Kraków). If the operator wants broader coverage, the CITIES array is one edit.
  - **The CI guardrail won't catch *non-empty* iCloud corruption** — only literal 0-byte files. The v0.61.260-287 `durian-variance-runner.js` placeId drop was a non-empty file with a missing field; that bug class still requires unit tests or runtime asserts. Worth a follow-up: a CI lint that rejects `kept.push({...})` rows without a `placeId` key (or similar).
