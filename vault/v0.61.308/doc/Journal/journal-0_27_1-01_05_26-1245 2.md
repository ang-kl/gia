## New

### [HDR] #49 | 12:45:00 SGT 01-05-26 | v0.27.1 | n/a kb | n/a lines
- **[INTENT]** Outstanding-list item #6: re-expose buddy-share now that the per-pick `👋 Send to buddy` button was removed in v0.26.2. New `/share` slash command lists the user's last 5 picks (across `/eat`, `/cuisine`, `/surprise`) and offers a tap-to-mint-share-link affordance per venue.
- **[DELTA]**
  - **NEW** `recent-picks.js` — Redis LIST tracker per chat. `addRecent(redis, chatId, pick)` LPUSHes a trimmed pick record and `LTRIM 0 4` + `EXPIRE 86400`. `getRecent(redis, chatId)` reads the last 5. Trimmed payload mirrors the share.js shape (placeId, name, area, lat/lng, rating, url, directionsUri, primaryType, vibe, signatureDish, googleSummary, addedAt) — share-link minting uses these directly.
  - **`index.js`** —
    - `deliverPicks` and `deliverSurprise` now `addRecent(...)` fire-and-forget for each delivered pick. Never blocks delivery.
    - + `bot.onText(/^\/share$/)` handler. Reads recent picks; if empty, prompts user to run `/cuisine` first; else mints a share token via existing `saveShare(redis, ...)` per pick and renders an inline keyboard with one row per pick (`👋 <Venue Name>` truncated to 30 chars). Tap → existing `share:<token>` callback handler replies with the `t.me/<bot>?start=share_<token>` deep link.
    - + `setMyCommands` row `share — Forward a recent pick to a buddy` between `/surprise` and `/drink`.
- **[VERIFICATION (sandbox)]**
  ```
  node --check on index.js, recent-picks.js → OK
  ```
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]**
  1. Run `/cuisine` Search → 5 picks delivered to chat. Behind the scenes, `addRecent` LPUSHes each.
  2. Run `/share` → bot replies "Pick a venue to forward to your buddy (5 recent):" with 5 inline buttons, one per recent venue, labelled `👋 <Name>`.
  3. Tap a button → existing `share:<token>` callback handler replies with the `t.me/<bot>?start=share_<token>` deep link in a code block.
  4. Forward the link to a friend → buddy taps → bot's `/start share_<token>` handler renders the same Sanctuary read for them.
  5. Run `/share` with no prior picks → bot replies "No recent picks yet. Run /cuisine, /eat, or /surprise first…".
  6. Wait > 24 h, run `/share` → empty (Redis TTL).
- **[KNOWN GAPS]**
  - Recent list is per-chat, not per-user-per-bot. If multiple users are in a group chat with `gia_bot`, /share shows the union of everyone's picks. Acceptable for now (groups are out of primary scope).
  - Surprise picks lose the `dishes`/`whyOrdered`/`bookingRequired` fields when saved to recent-picks (the trimmed shape doesn't carry them). Re-rendering the surprise card via /start share_<token> will run a fresh `findSinglePlaceForPick` so the buddy sees the current Sanctuary read for that venue, but loses the original surprise framing. Trade-off: kept the trimmed payload small to keep Redis cheap.
