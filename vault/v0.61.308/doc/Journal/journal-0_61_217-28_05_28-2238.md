- **[INTENT]** Get Places API succeeding on every variance test query and on every /location <text> for non-SG.

- **[DELTA]**

  **Root cause** (revealed by v0.61.216 error-capture upgrade):

  > "Invalid JSON payload received. Unknown name 'includedRegionCodes': Cannot find f..."

  `includedRegionCodes` is a Places (New) **Autocomplete** field. `searchText` does NOT accept it — `regionCode` alone is the country-bias hint. Both call sites had been silently 400-ing:

  - **variance runner** (`place-search-variance.js` `fetchPlaces`) — 50/50 Places fails on every smoke, masked as `"Request failed with status code 400"` until v0.61.216 surfaced Google's actual error.
  - **/location <text> for non-SG** (`index.js:2140`) — 400 → outer catch → user sees "Sorry, geocoding hit an error". The other anchor paths (map-share, TMA cuisine OTHER picker) use different endpoints so map-share + cuisine picker continued working, which is why the bug went undetected end-to-end.

  **1. `place-search-variance.js`** — drop `includedRegionCodes` from `fetchPlaces` body. Keep `regionCode: cc`.

  **2. `index.js:2140`** — drop `includedRegionCodes` from the live OTHER picker. Keep `regionCode: countryCode`.

  **3. `package.json`** — `0.61.216 → 0.61.217`.

  **4. `doc/.serial-state.yml`** — commit 429→430, build 219→220, journal 417→418; re-anchored 28-05 '26 22:38 SGT.
