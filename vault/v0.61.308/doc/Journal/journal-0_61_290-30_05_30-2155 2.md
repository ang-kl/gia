# Journal — soleat v0.61.290 (fun-facts JSON → JS module port, CI vitest fix)

> Operator (30-05 '26 21:53 SGT, post-PR-#795 merge): *"merge"* — and the auto-merge of v0.61.289 surfaced a pre-existing CI vitest failure.
>
> **Root cause** (introduced in v0.61.285): `web/cuisine/src/v2/lib/fun-facts.js` had `import facts from '../data/fun-facts.json';`. Node 20 ESM rejects bare JSON imports (needs `with { type: 'json' }` attribute). Vite's browser bundler handled it fine — so the production TMA build worked from v0.61.285 onward — but vitest's Node-ESM loader failed the test suite. Auto-merge bypassed the failure because the repo's branch protection doesn't require vitest to pass.
>
> Net: **`fun-facts.test.js` was silently failing on CI for v0.61.285 + v0.61.286 + v0.61.287 + v0.61.288 + v0.61.289** — none of which I noticed because the auto-merge kept landing PRs through the red vitest.
>
> Fix: convert the data file from `.json` to a `.js` module with `export default [...]`. Now the import is a regular ESM statement that works identically in Node, vitest, and Vite. No import attributes, no createRequire-vs-browser-bundle tradeoff, no per-environment branching.
>
> Commit 504 / journal 491 / build 293, on branch
> `claude/v0.61.290-funfacts-json-to-js` off `main` at v0.61.289.
