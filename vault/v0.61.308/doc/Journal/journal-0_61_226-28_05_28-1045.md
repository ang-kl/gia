### [HDR] #427 | 10:45 SGT 28-05-26 | v0.61.226 — Social-profile row across Cuisine TMA + free-text + Copy / Copy-all | 13 files | 1 PR | 1 build |

- **[INTENT]** Surface each restaurant's official Instagram / TikTok / Facebook / X / YouTube / Threads URLs everywhere the venue renders — TMA ResultCard, per-card Copy, Copy-All, and chat free-text / `/s` cards.

- **[DELTA]**

  **Important upstream fact, established before any code change:** Google Places API (legacy AND New) does NOT expose social-profile URLs. The "Profiles" panel the operator sees in their screenshot is from Google Search's Knowledge Panel, which is not available via any developer API. Bridge: a Gemini grounded Google Search call (mirroring the `gemini-client.js` v0.58.42 fallback chain) plus strict per-platform URL regex validation against hallucinations.

  **1. `social-profiles.js`** (NEW, ~265 lines, CommonJS):

  ```js
  module.exports = {
    getSocialProfiles,           // single venue, Redis-cached
    fetchSocialProfilesForVenues, // fan-out (concurrency 4)
    attachSocialsToVenues,       // in-place assignment helper
    pickTopProfiles              // priority-ordered, max-N cap
  };
  ```

  Per-platform URL regex (Instagram, TikTok, Facebook, X/Twitter, YouTube `@-handle` / `/channel/` / `/user/`, Threads `.net` + `.com`). Redis `social:<placeId>` with 30-day TTL via `setEx`; negative caching for empty results (so we don't hammer the API for venues that genuinely have no profiles); no caching on transient Gemini failures (next call retries). Default model `gemini-2.5-flash`, 15s per-attempt timeout, full fallback chain mirroring `gemini-client.js`.

  **2. `__tests__/social-profiles.test.js`** (NEW, ~190 lines, 19 tests): URL pattern positive + negative cases (including a deliberate hallucination panel — typo domain `instagra.com`, subdomain attack `fb.evil.com`, off-path YouTube video URLs, missing `@` on TikTok / Threads), JSON parser (bare / fenced / surrounded by prose / malformed), priority ordering, cap-3 picker, Redis cache hit / miss / negative cache, Gemini total-failure non-caching, fan-out concurrency cap (assert peak-in-flight ≤ 4), regression guard on `URL_PATTERNS` shape.

  **3. `venue-templates.js` `formatVenueBlock`**: new 📱 row inserted immediately **after the 📍 maps line** (operator mid-PR direction: *"socialprofile links should be after the Google Map (📍 https://maps.app.goo.gl/x)"*). Gated by `includeContact` so T3 compact / deliverPicks still stays sparse — only T1 / T2 carry the row, matching the existing 🌐 / 📞 gating.

  ```js
  if (Array.isArray(p.socialProfiles) && p.socialProfiles.length) {
    lines.push(`📱 ${p.socialProfiles.join(' · ')}`);
  }
  ```

  URLs space-joined with ` · ` so Telegram's auto-linker creates a tappable link per URL.

  **4. `index.js` `formatTechniqueVenueBlock`** (`/s` + free-text technique fan-outs): mirrored 📱 row insertion **after the 📍 maps line**, before the Michelin annotation. Independent function from `formatVenueBlock` (historical reason — see the `escapeHtmlForTelegram` alias comment in venue-templates.js); the parallel edit is the well-known footgun called out by that comment.

  **5. `index.js` `/api/cuisine/copy-one`**: pre-render single-venue `getSocialProfiles` call assigns `venue.socialProfiles` before `formatVenueBlock`. Errors swallowed — the row simply doesn't render.

  **6. `index.js` `/api/cuisine/copy-all`**: pre-render `attachSocialsToVenues(redis, slim, { concurrency: 4 })` on the up-to-12 slim venues before mapping to blocks. v0.60.163's `packBlocksIntoChunks` handles the ~60-90 chars added per venue when most resolve a populated 📱 row.
