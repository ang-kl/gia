## New

### [HDR] #19 | 10:15:00 SGT 30-04-26 | v0.13.0 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead spec: device-agnostic location handling with conversational fallback. Universal "Sensing the vibe…" ack across all entry points. Location Validation Gate that converts hard errors into a manual-input prompt and stays locked in the original intent. Radial expansion ceiling raised 1000 m → 2000 m.
- **[DELTA]**
  - **`index.js`** —
    - + module constants `ACK_SENSING_VIBE = '🌿 Sensing the vibe…'` and `MANUAL_FALLBACK_PROMPT = "I'm having a bit of trouble pinning your exact location. Could you type the name of the building or area you are at?"`.
    - **`bot.on('location')`** restructured for §2:
      - Pending-meal consumed first; if no pending, silent return as before.
      - Universal ack sent immediately after pending confirm.
      - Coordinates validated for `Number.isFinite` on both lat/lng.
      - On any throw (missing/malformed coords, Vault crash, pickValidated crash, runFlow crash) → restore pending state via `setPendingMeal` + send `MANUAL_FALLBACK_PROMPT`.
      - Old "Sorry, I couldn't process that location." copy superseded.
      - "🌿 Sensing the sanctuary vibe — looking for X within 200m…" copy (v0.11.0) superseded by the universal ack to drop misleading "200m" wording (radial expansion can stretch up to 2000 m).
    - **`bot.onText('⛔ Use Raffles Place default')`** — uses `ACK_SENSING_VIBE`; on error replies with `MANUAL_FALLBACK_PROMPT` instead of the prior "Sorry, I can't reach my listings right now."
    - **`bot.on('message')` typed-place branch** — uses `ACK_SENSING_VIBE` (was "Looking up X…"); on geocode miss replies with `${MANUAL_FALLBACK_PROMPT}` and restores pending. Confirmed §4 lock-in behavior was already correct in v0.7.0 and is preserved.
    - **`startSanctuaryFlow`** — cached-location path now uses `ACK_SENSING_VIBE` (was per-prompt "Looking for X near your last shared spot…").
  - **`vibe-suggest.js`** — `RADIAL_EXPANSION_M` `[200, 500, 1000]` → `[200, 500, 1000, 2000]`. First Gemini candidate now retried at four progressively larger radii before falling through to Hidden Sanctuary.
  - **`package.json`** — version → 0.13.0.
- **[RISK]** Med —
  - **2000 m radial expansion** can produce picks the user has to walk 25+ minutes to. Mitigated by walk-time annotation (v0.8.0) so the user sees `· X min walk` in the header and can choose another command.
  - **Manual-fallback prompt** doubles as the geocode-miss prompt and the location-share-failure prompt. Slight ambiguity if user shares location but coords are valid (no error path). That's correct — manual-fallback only fires when something actually went wrong.
  - **`/groceries` and `/drink` flow inherits the same fallback** (§3 confirmed working) — typed text is geocoded then routed to the right `runFlow(category)` per pending state.
- **[STATUS]** PROD — auto-deploys with the next Railway build.
- **[TEST]** Manual:
  1. `/eat` → tap 📍 share location → first reply "🌿 Sensing the vibe…", picks land 5–15 s later.
  2. `/eat` → tap ⛔ default → first reply "🌿 Sensing the vibe…", picks centred at Raffles.
  3. `/eat` → type "Marina One" → first reply "🌿 Sensing the vibe…", then "Centred on Marina One.", then picks.
  4. `/eat` → location share with malformed coords (hard to reproduce naturally; force by editing message) → manual-fallback prompt + pending restored.
  5. `/eat` → type "asdfgh" → "I couldn't place asdfgh. {manual-fallback prompt}" + pending restored. Type "Chinatown" next → flow proceeds.
  6. `/groceries` → type a place name → flow stays in groceries category, not reset to food.
  7. From a far-out location → expansion now reaches 2000 m before falling through. Picks may be 15+ min walk.
