- **[KNOWN GAPS]**
  - **Escalation is single-cuisine only.** Multi-cuisine AND/OR searches keep the v0.60.116 behaviour (plain per-chatId dedup, no variant escalation). Follow-up.
  - **Four programmatic phrasings, not a curated dictionary.** `cuisineSearchVariants` builds `"<X> restaurant Singapore"` / `"best <X> …"` / `"authentic <X> food …"`. Google ranks these differently enough to surface ~20–40 non-overlapping venues each, but a per-cuisine alias / iconic-dish phrase set (e.g. Cantonese → "dim sum cha chaan teng Singapore") would do better. The `nation-overlay.js` `aliases[]` and `iconicDishes[]` arrays are the obvious source. Follow-up.
  - **Per-chatId pool cache, not shared.** Recommended a shared (criteria + coarse-area) pool for scale (≈100–1000× fewer Places calls + ~100× less Redis at 5000 users); operator chose per-chatId for now. A cron pre-warm of top-cuisine pools would bound Google calls by *cuisines* not *users* — also a follow-up. (See the Decisions table in `register-0_60_117`.)
  - **`criteriaHash` is location-independent.** Two chats searching the same cuisine+filters from different parts of SG share the conceptual "criteria" but each has its own per-chatId keys; the 50 km SG-wide `locationBias` makes Google's pool roughly SG-wide anyway, so the practical drift is small.
  - **ICA scrape, no queue counts, v0.60.101 chips** — unchanged known gaps from `journal-0_60_106`; carried by reference.

## Amendments

### `SEEN_SET_TTL_S` — quoted prior, then the change

- **Prior (v0.60.114):** `const SEEN_SET_TTL_S = 60 * 60; // 1 h — long enough that "click 5 times" stays consistent`
- **v0.60.116:** `const SEEN_SET_TTL_S = 15 * 60; // 15 min sliding` — re-tap 🔍 within ~15 min advances; >15-min idle resets the round. (Serial: this arc.)
- **v0.60.117 (current):** `const SEEN_SET_TTL_S = 12 * 60 * 60; // 12 h hygiene — never resets mid-use` — operator: "Fresh round should be after the last N places are listed regardless of TTL." The seen-set is the accumulating exclusion for the whole session; its TTL is now pure Redis garbage-collection, not the reset trigger. Resets are: ↺ Start over (`resetSeen`), or a criteria change (different hash). (Serial: this arc.)

### Cuisine exhausted note copy — quoted prior, then the change

- **Prior (v0.60.115):** `result.exhausted` = "— That's all {n} places matching these criteria. Add or change a cuisine / filter, or use 💬 Tell me, to find more. Re-tapping 🔍 just re-shows this list. —"
- **v0.60.117 (current):** "— You've now seen all {n} places I can find for these criteria, across several searches. Add or change a cuisine / filter, or use 💬 Tell me, to widen things — or ↺ start over." — because re-tapping 🔍 no longer re-shows the same list (it escalates), and the terminal note now offers a one-tap reset rather than only pointing at criteria changes. (Serial: this arc.)
