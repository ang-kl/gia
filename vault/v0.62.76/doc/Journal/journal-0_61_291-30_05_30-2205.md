# Journal — soleat v0.61.291 (cuisine-tag priority in fun-fact selector)

> Operator (30-05 '26 22:01 SGT, post-PR-#796 merge): *"merge"*. PR #796 fixed the JSON-import bug but vitest still showed 1 failing test:
>
> ```
> × pickFunFact — public selector with localStorage > returns a fact whose tags overlap the cuisine context
> AssertionError: expected [ 'hawker', 'history', 'policy', 'SG' ] to include 'laksa'
> ```
>
> This is a **real bug**, not a flaky test. The v0.61.285 selector treated all tags equally: when ctx = `{cuisines: ['laksa'], region: 'SG'}`, the `'sg'` tag matched 25-ish region-tagged facts (hawker policy, immigrant communities) AND the single `'laksa'`-tagged fact. Random selection meant the user got "Hawkers Inquiry Commission (1950)" instead of the laksa origin story 25× more often. The operator's spec was *"Search 'laksa' → modal preferentially picks one of the laksa-tagged facts"*, but the implementation didn't enforce that priority.
>
> Fix: tier the matching in `_pickFact`.
> - **Tier 1** — overlap with cuisine/community tags (i.e. tags NOT in `REGION_TAGS = {sg, my, jb, other, __none__}`). If matches found → pick from this set.
> - **Tier 2** — overlap with region tags only. Used as fallback when no cuisine match.
> - **Tier 3** — full pool. Used when no tag overlap at all.
>
