## New

### [HDR] #297 | 12:56 SGT 22-05-26 | v0.61.97 — amenity zoom tiers | ~7 kb | 4 files | 1 PR | 1 build |

- **[INTENT]** The amenity overlay layers (Attractions / Parks /
  Clinic / Police / Hospital) rendered their markers identically at
  every zoom — cluttered when zoomed out, no name when zoomed in. Give
  them per-zoom-band rendering, mirroring the train-station tiers.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/mapOverlays.js`** (+ the byte-identical
    `web/hawker/src/lib/mapOverlays.js` and
    `web/transport/src/lib/mapOverlays.js`) —
    - New exported `amenityTier(zoom)` → `'dot'` (z<12 — a tiny 9 px
      dot), `'glyph'` (z12-13 — the ~20 px icon dot) or `'label'`
      (z14+ — icon + name pill).
    - New `amenityNode(tier, bg, glyph, name)` builds the per-tier
      marker content.
    - `buildMarkers` gains a `tiered` flag; the attractions / clinics
      / police / hospitals layers are now tiered and each item carries
      its `bg` / `glyph` / `name` so `applyVisibility` can re-render
      the marker per zoom.
    - `applyVisibility` re-tiers those four layers on every call, and
      at the z14+ `label` tier demotes any label whose box collides
      with one already placed back to its `glyph`. The `zoom_changed`
      listener now re-applies all five amenity layers.
    - Parks: `buildParks` gives each park a 🌳 + name label marker
      shown only at the z14+ tier (a colliding label is hidden); the
      green polygon still marks the park at every zoom.
    - The attraction marker moves off its always-on name label
      (`attractionLabelNode`) onto the tier system; its dot colour is
      set to a visible purple (`#8E24AA`) — the old `#f4f3ef` only
      worked as a label background. `attractionLabelNode` and
      `rectPinNode` are now unused (left in place; no caller).
  - **`package.json`** — `0.61.95` → `0.61.97` (PATCH; `0.61.96` is
    PR #589, a concurrent branch).
