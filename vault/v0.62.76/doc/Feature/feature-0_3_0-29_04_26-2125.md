## §0.3.0 NEW CONTENT

### 5. New Feature — Gemini Sanctuary Summary

`/lunch` now appends a "Sanctuary read" line under each venue card, generated by Gemini from the venue's recent Google reviews. Lazy-fetched per venue, cached in Redis 7 days.

- **Source files:** `vibe-summary.js` (new), `index.js` (handler integration), `vibe.js` (passes through `places.id`).
- **Trigger:** when `/lunch` picks 3 venues, for each venue with a Google `placeId`, attempt a summary fetch.
- **Cache key:** `vibe:summary:<placeId>` — string, TTL `604800s` (7 days).
- **Model:** `gemini-3-flash` (per Human Lead direction 29-04 '26). Overridable via `GEMINI_MODEL` env var without redeploy.
- **SDK:** `@google/generative-ai` ^0.24.1.
- **Failure modes (all silent — venue card still delivered):**
  - `GEMINI_API_KEY` unset → no summary card sent.
  - `GOOGLE_MAPS_API_KEY` unset → no Place Details fetch → no summary card.
  - Place Details call fails or returns no reviews → no summary card.
  - Gemini call fails (model name wrong, quota, rate limit) → no summary card.
  - Seed listings (id=null) → skipped entirely.

### 6. Reply shape (v0.3.0)

When `/lunch` is invoked, Gia sends:

```
[text]   Gia's Sanctuary Picks
         1. <Name> ⭐<Rating> · Open now
         2. ...
         3. ...

[venue]  <venue card 1 with map pin>
[text]   🌿 Sanctuary read for <Name 1>
         • Quiet: <one short phrase>
         • Seating: <one short phrase>
         • Vibe: <one short phrase>

[venue]  <venue card 2 with map pin>
[text]   🌿 Sanctuary read for <Name 2>
         ...

[venue]  <venue card 3 with map pin>
[text]   🌿 Sanctuary read for <Name 3>
         ...
```

If a `Sanctuary read` is missing for a given pick, the venue card alone is delivered — never an error message.
