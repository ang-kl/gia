## 1. Cost sustainability

Two cost vectors: Gemini (LLM) and Google Places. Both highly cacheable because queries cluster.

### Gemini moves — likely 70–90% spend reduction

- **Query-normalized Redis cache** keyed by `sha(normalizedQuery + city + lang)`, 30–90 day TTL. Fits `freetext-classify`, R.E.D, `dessert-drink-keywords`, `cooking-methods`, `nation-overlay` — all deterministic given input.
- **Tier the models**: Haiku/Flash for first-pass classification; Gemini Pro only when confidence < threshold. ~60% of calls drop a tier.
- **Local rules first**: regex / keyword pre-filter for obvious intents ("ramen" doesn't need an LLM to classify as Japanese). LLM only on genuine ambiguity.
- **Pre-bake top-N per city** via nightly cron — pull top queries from `verbose-log`, classify once, store flat JSON. Serves the head of the distribution at zero per-request LLM cost.
- **Stale-while-revalidate**: serve cached, refresh in background only if older than threshold.

### Google Places moves — likely 50–70% reduction

- **Field-mask audit**: charge tier is per-field-group; today's calls may pull more than rendered. One audit pass.
- **Cache Place Details 30–90 days** — restaurants change address/rating slowly. Today some caching exists; verify TTL + hit rate.
- **OSM / Overpass for non-critical fields** (name, address, hours, lat/lng). Reserve Places for ratings/photos (the expensive fields).
- **Local datasets** — Singapore hawker data is on data.gov.sg and free. Replace Places for that category entirely.

### Revenue (start the meter)

- **Affiliate booking links** on each card — TheFork (EU), Klook (Asia), Booking experiences. 10–20% commission, paid only on completion. Near-zero engineering. Single biggest sustainability lever.
- **Tourism-board sponsorships** — "Tokyo Tourism Bureau · curated picks" channels. Flat-fee, low-effort.
- **Verified restaurant claims** — $5–20/mo for the restaurant to add their own photo / specials / verified-hours badge. **Must not affect ranking** — otherwise we become Yelp.
- **Pro tier** ($3/mo) — unlimited Cabinets, longer TTLs, fork analytics. Low conversion but covers heavy users.
- **Contribute page** — `soleat.net/contribute`. Optional one-off + recurring tips from users who want to chip in. See subsection below.

### Contribute page — `soleat.net/contribute`

A single dedicated landing page on the operator's own domain is the trust-best, UX-best, and complexity-lowest route for accepting contributions — better than an in-bot Stars button (users have learned to mistrust those) and better than a third-party `kofi.com/<handle>` link (no brand control).

**Why a dedicated page over in-bot payment surfaces**

- Own domain = own brand = legitimacy signal.
- Single source of truth — swap / add / retire payment methods without redeploying the bot.
- Editorial control — explain who, why, what it costs, link to roadmap and GitHub.
- Bot stays simple — one outbound link; no payment SDK, no PCI exposure, no Stars payout accounting in the codebase.
- Trackable per surface via `?src=` UTMs — prove which placements convert, prune the rest.

**Minimal v1 spec**

- One paragraph at the top: real name + photo + cost transparency ("Soleat costs ~$X/mo in Gemini + Google Places fees; every feature stays free forever; contributions are optional").
- 2–3 payment buttons:
  - **Telegram Stars** deep link (`https://t.me/$<bot>?start=tip_*` or Fragment payout URL).
  - **Ko-fi** for card / PayPal fallback (0% platform fee + Stripe ~2.9%).
  - **PayNow QR** (SG) / **DuitNow QR** (MY) — static image, zero processor fee, in-country instant. Heavily preferred over cards by the likely user base.
- Optional rolling "thanks" wall (handle + band, never amounts).
- Footer links to `/about` and the GitHub repo.
- Static HTML; deploy on Vercel / Netlify / GitHub Pages for free.

**Framing (Asia-tuned)**

The "buy me a coffee" trope is Western indie-dev culture. In SG / MY / Indonesia, "donate" reads as charity and "tip jar" reads as awkward. Two reframings that land:

- **"Top up the chef's coffee ☕"** — playful, matches Soleat's food identity, sidesteps the charity association.
- **"Help keep this free for everyone"** — collectivist framing, lands well locally.

Avoid: "Support us", "Donate", "Become a patron".

**Wiring — one helper, many surfaces**

A single `openContribute(source)` helper that calls `Telegram.WebApp.openLink('https://soleat.net/contribute?src=' + source)`. Telegram's in-app browser opens it without leaving the app.

| Surface | `?src=` value | Trigger |
|---|---|---|
| Bot persistent menu "☕ Support" | `tg-menu` | Always available, never interrupts |
| `/contribute` and `/about` chat commands | `chat-cmd` | Explicit user request |
| Cuisine TMA · settings drawer | `tma-cuisine` | Discoverable, never in-flow |
| Clipboard TMA · settings drawer | `tma-clipboard` | Discoverable, never in-flow |
| Hawker / Transport / Menu / Oversight TMA · settings drawers | `tma-hawker` / `tma-transport` / `tma-menu` / `tma-oversight` | Same — one entry per TMA |
| Post-fork soft chip (once per quarter, dismissible forever) | `fork-success` | Gratitude moment, not interruption |
| Footer of shared cabinet view (forked-from-friend surface) | `shared-view` | High-trust moment — user just received value |

**Anti-scam rules (non-negotiable)**

- Never a modal or pop-up — always passive surfaces (menu, footer, settings drawer).
- Never gate a feature — every feature works for ever, paid or not.
- One soft prompt at most per quarter per user, persistently dismissible.
- No high-pressure or scarcity language anywhere.
- Real name + photo on the page — anonymous tip jars look like scams.
- Card details never entered in chat — only on the dedicated page via the trusted processor (Ko-fi handles Stripe).

**Pre-launch checklist**

1. Register `soleat.net` (and `.app`, `.com` as defensive redirects) — secure before wiring.
2. Decide payment methods to launch with — Stars + Ko-fi + PayNow QR is the recommended trio.
3. Build the static page (one-evening job; the HTML is essentially text + 3 buttons + a QR image).
4. Wire `openContribute(source)` helper in cuisine TMA, Clipboard TMA, and remaining TMAs.
5. Add `/contribute` and `/about` chat commands.
6. Add `setChatMenuButton` entry "☕ Support" (sits alongside the planned "📋 Open Clipboard" menu entry).
7. Instrument hit-rate per `src=` so the lowest-converting surfaces can be removed.

**Open items to confirm**

1. Is `soleat.net` already registered, or does it need to be secured first?
2. PayNow / DuitNow QR included in v1, or Stars + Ko-fi only?
3. Public "thanks" wall, or strictly anonymous?
4. Recurring tier (Ko-fi Members at ~$3/mo) included in v1, or one-shot only?

### Observability

`/admin/cost` dashboard: daily Gemini + Places spend per endpoint + cost-per-query. Every new feature gets evaluated against unit economics.

## 2. Stickiness beyond the Clipboard

Clipboard is the **active-session loop** (plan → fork → revisit). The bot also needs **passive loops** — moments where it pulls the user back without the user initiating.

Ranked by impact-per-effort:

1. **Weekly digest** — opt-in "Friday: 3 picks for your weekend in {city}". Telegram channel or DM. Zero infra cost.
2. **Time-of-day nudges** — at 11am, if active this week, single-line: *"Lunch ideas around your office?"* Personalized via `location-cache`. Tap to open. High recurrence, low spam if rate-limited.
3. **"Been here" silent signal** — tap on a card = visited. Personalizes future picks. Never shown publicly (avoids the review-farm trap).
4. **Cabinet trip recap** — after a Cabinet's `dateEnd` passes, bot DMs: *"How was Tokyo? Tap to mark favourites."* Favourites already have infinite TTL — natural reuse loop into the Clipboard.
5. **External link extractor** — paste any Google Maps / Instagram / TripAdvisor URL → bot extracts venue → goes straight to catch-all. Captures research that's happening on other platforms.
6. **Calendar add** — drawer with a date → optional system-calendar reminder. One-tap *"Bella Pasta · 1pm tomorrow"*.

**Deferred** (require moderation infra): social graph, public reviewer scores.

## 3. "Credible reviewer" hyperlink in the result card

Google's review signal is collapsing (292M fake reviews removed in 2025, FTC enforcement, Local Guides perks gutted). A **curated source layer** is the differentiator — surface the reviewers your operator actually trusts, hyperlinked to their source content.

### Spec for v1 — whitelist approach

- New data file `data/credible-reviewers.json` — per-city list of trusted sources (Chubby Hubby, Daniel Food Diary, Eatbook, Le Fooding, Eater, Infatuation, individual Substacks, individual IG accounts).
- Each entry: `{ placeId, reviewerHandle, sourceUrl, quote?, publishedAt, cuisine? }`.
- Result card gets one new sub-line under the existing rating: **"Trusted: @chubbyhubby · @eatbook ↗"** — tappable; opens the source URL in Telegram's in-app browser (`Telegram.WebApp.openLink`).
- Card without any entry shows nothing extra (graceful fallback — never an empty placeholder).

### Why whitelist before user-credibility

- Solves the trust crisis immediately (curated > algorithmic for v1).
- Zero abuse surface — no fake-review-farm can game it.
- Costs operator editorial time, not engineering effort.
- Naturally evolves: when there are ~1k users, layer in "trusted by 5 of your friends" (Beli pattern).

### Open questions (parked)

1. How is the credible-reviewer list maintained — operator-curated, community-submitted with operator approval, or invite-only "ambassador" accounts who add their own picks?
2. Per-card limit — show top 3 reviewers and "+2 more"? Or always all matches?
3. When zero credible sources cover a venue, show nothing OR show *"Be the first to vouch for this spot"*?

## 4. Group-chat support

**Decision locked**: Phase A ships free with the Clipboard cycle; Phase B is held until Phase A produces measurable signal.

### Phase A — forwarded-link rendering (no engineering)

The drawer share-link infra in the locked Clipboard plan already works in group chats today. A user forwards `t.me/<bot>/clipboard?startapp=dr_<token>` into their group — anyone in the group can tap **📋 Fork to my Clipboard**. The bot **does not need to join the group**. This captures ~80% of the value with zero new infrastructure.

Implication: instrument `cb.fork.in_group` analytics so we can see how many forks happen from messages forwarded into a chat with >2 participants.

### Phase B — bot joins the group (post-signal)

Group becomes a shared editing surface: `/eat pizza` returns picks visible to all; members react with emoji to vote; `/save <venue>` adds to a shared catch-all; shared Cabinets are visible to all current members.

Gate Phase B on Phase A signal:
- ≥ 5 % of all forks come from group-forwarded share links, OR
- A clear cohort of users repeatedly forwards multiple drawers to the same group within a week.

### Ethos guardrails (non-negotiable for either phase)

- **Silent by default** — Telegram privacy mode ON; bot responds only to `/eat`, `/save`, or `@gia4lunch_bot`. Never speaks unprompted in a group.
- **Small-group only** — soft cap ≤ 25 members. Refuse to join larger groups; suggest the share-link path instead.
- **No public scoring** — group cabinets are shared editing, never shared rating. Same favourites + notes model, never stars/leaderboards.
- **Per-member opt-out** — anyone can mute or kick the bot, no friction.
- **No proactive notifications** — bot never DMs group members unbidden.

### When to ask the user (semantic triggers, not UI banners)

- **Never** at onboarding (no earned context).
- **Never** as a standing banner (growth-hack spam).
- **Always** at moments where the user's own behavior signals group intent:

| Trigger | The ask |
|---|---|
| Cabinet named with group-coded words (`night`, `birthday`, `trip`, `family`, `team`, `wedding`, `crawl`, `& friends`, possibly local terms like `makan`, `gathering`) | After save: one-time chip *"🤝 Planning with friends? Share this cabinet to a group chat."* |
| User shares a drawer for the first time | After share-link shown: *"💡 Forward this to your group chat — anyone can fork."* |
| User forks a cabinet from someone else | After fork: *"Continue planning together — share back to a group?"* |
| LLM intent-classifies the query as multi-person (`"dinner for 6"`, `"birthday spot for 12"`) | In the result toolbar: small chip *"🤝 Plan with the group"* |
| User has saved ≥ 3 venues in a cabinet and hasn't touched it for 7+ days | Gentle DM: *"Stuck on {cabinet}? Share it to a group for ideas."* (rate-limited, per-cabinet opt-out) |

### Ask-fatigue rules (non-negotiable)

- Once per cabinet, once per fork; **never** re-ask the same cabinet once dismissed.
- Track in user prefs: `seenGroupPromptFor:<cabId>`.
- Master toggle in `/settings` to disable all group prompts forever.
- Never push outside business hours in user's local TZ.

### Where to ask (UI placement, priority order)

1. Inside the Clipboard TMA — chip below the cabinet header, dismissable. Best signal-to-noise.
2. Inline with the share-link sheet — secondary "or forward to a group" option.
3. One-time DM — only for the 7-day-stale trigger above. Rate-limited.

**Do NOT ask** in: search results, cuisine TMA nav, bot menu, `/start` welcome flow.
