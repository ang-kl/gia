## 1. Reusable responsive primitives (the port kit)

**Rule N-1 — `web/_shared/lib/use-viewport.js` is the device/orientation source of truth.** `useViewport()` →
`{ deviceClass: 'mobile'|'tablet'|'desktop', orientation, isWide }`. Detection: a **coarse pointer + short-edge
≥ 768 px** = tablet; a **fine pointer + width ≥ 1024** = desktop; else mobile. `viewportTag(vp)` → the footer
cue. Self-contained (no per-TMA import) so every Mini App imports one copy.

**Rule N-2 — the fullscreen re-read is mandatory for the layout to flip.** Telegram opens the Mini App as a
**centered modal** on iPad; `requestFullscreen()` (Bot API 8.0) resizes the webview **but does not reliably fire
`window.resize`**, so `useViewport` also listens on `window.visualViewport` `resize` AND re-reads at
250/700/1500 ms after mount — else the first-open read (the small modal) sticks as `mobile`. The fullscreen call
itself lives in each TMA `tg.js`, gated to **touch tablets**: `requestFullscreen` exists + `isVersionAtLeast('8.0')`
+ `platform ∈ {ipados, ios, android}` (iPad is **`ipados`**, not `ios`) + coarse pointer +
`min(screen.width, screen.height) ≥ 768` (physical `window.screen`, not the pre-fullscreen modal `innerWidth`).

**Rule N-3 — layout dispatch by device × orientation, one shared card renderer.** `App` branches:
`landscapeTablet → full-bleed map + bottom carousel`; `portraitTablet && mapExpanded → same carousel`;
`portraitTablet → anchored map + separate scrollable list panel`; else **phones → the existing stacked layout,
untouched** (its wrapper is `display:contents` off-tablet). The **same** `renderCentreCard(c, i, glass, compact)`
feeds every mode — `glass`/`compact` flags are the only per-mode variance, so the layouts can't drift.

**Rule N-4 — the carousel: IntersectionObserver focus + responsive basis.** `CentreCarousel` snaps a
horizontal strip (`snap-x snap-mandatory`, `items-end`); an `IntersectionObserver` (root = the scroll track,
threshold 0.92) marks a card **focused (opaque)** ≥ 92 % visible, else **glass**. `basis-[82%] md:basis-[44%]
min-[1180px]:basis-[30%]` → 1 / 2 / 3 cards in focus (phone / iPad-mini / iPad-Pro+). `items-end` (not the flex
default `stretch`) keeps natural card heights so short cards don't fill a background band across the width.

**Rule N-5 — `FooterNav` gains an optional `leading` slot.** `web/_shared/components/FooterNav.jsx` renders an
app-supplied control (the 🗺/📋 map⇄cards toggle) as the first item in the same rounded cluster, before ⇣ down /
🔚 end. Default `null` — the other TMAs are unaffected.

**Rule N-6 — the map panel is layout-aware.** `HawkerMapPanel` `fill` = `absolute inset-0` full-bleed vs the
framed inline card; `expanded`/`onToggleExpand` make the ⇲ **controllable** (App owns the mode switch in the
portrait panel; the button is **greyed + disabled** where it isn't wired — landscape `fill` with no handler).
In `fill` mode the left nav cluster + `MapControls` quick-toggle row drop below the top bar
(`calc(--tg-content-safe-area-inset-top + 6rem / 4.25rem)`); the tablet panel content clears the fullscreen
top controls with the same content-safe-area inset.

## 2. Embedded-map interaction rules (all taps act on THIS map)

**Rule N-7 — card ↔ pin sync via globals + a callback.** `HawkerMapPanel` exposes `window.__giaHawker*`
globals (`FocusStation`, `ShowBusStop`, `FocusCentre`, `Highlight`) each of which `revealMap()`
(`scrollIntoView`, for the phone stacked layout where the map is above the list) then acts on the embedded map.
A centre-pin tap and a card tap both run one extracted `activateCentre(c, marker, key)` (open InfoWindow, zoom
17, transit + rings, **3-second `highlightLoc` pulse**); a card tap fires it via
`google.maps.event.trigger(marker,'click')` (freshest binding). The reverse (`onCentreTap` prop) sets the card
active **and** `scrollIntoView`s the matching card (`data-centre-card` anchor). Station/bus pills in **both** the
card and the InfoWindow call the same handlers (bus = `showBusStop` → labelled pin + live-arrivals bubble); a
2nd tap on a pill opens external Maps. The card's inner interactive elements `stopPropagation` so a pill tap
never fires the whole-card tap.

**Rule N-8 — InfoWindow chrome + auto-pan (in `ensureGreyscaleStyle` / `mapOverlays`).** Google's default
InfoWindow chrome (`.gm-style-iw-c/-d/-t` background/padding/shadow/tail + the default close button) is stripped
so only the app's rounded `infoCard` shows (fixes the "double border"); `infoCard` widened to 340 px (tall
station card wraps fewer lines) with tiny padding. `ensureInfoVisible(map, marker)` pans the map **down** when a
marker sits in the top half of the viewport so its upward-opening card clears the fullscreen top bar.

## 3. Data joins (Hawker)

`hawker-vault.js` `loadBibIndex()` joins `SG-michelin.js` `BIB_GOURMAND[]` (address = centre name) onto centres
with a **number-stripped token key** (`_bibKey` = `_normaliseHawkerName` + strip block numbers) **plus a
digit-consistency guard** (a bib address carrying a block number only tags a centre whose name contains it) —
deterministic, no fuzzy edit-distance (which mis-mapped Jurong West 505 / both Redhill entries). 19/122 tag.
Stall count/status remain the data.gov.sg GEOJSON join (37/122 coverage — Register DF-7).
