## T-63.1 — Deliberately-orphaned code, used as designed

Hawker's `portraitTabletPanel()` was un-referenced at v0.62.642 with an explicit comment: kept in the file
"so the two-panel can be restored in one line if wanted." This is exactly that restoration — one line in the
dispatcher, zero changes to the function itself, because it was already device/orientation-agnostic (a
static map-top / scroll-list-below split, not tied to "tablet" or "portrait" in its actual JSX). Deliberately
orphaning working code with a stated reason, instead of deleting it, paid off here as designed.

## T-63.2 — A dormant prop can hide a latent inconsistency until something makes it live again

Building Cuisine's equivalent surfaced O-68 (Register): `MapPanel`'s `frameHeight` prop has taken no effect
for ANY device since v0.62.655, because it's only read when `fill` is false, and `fill` had been hard-coded
true for every device since that version. The in-code comments describing a "compact ~40vh framed map" for
portrait tablets were accurate when written and have silently stopped being true since — not caught by any
test (nothing asserts on `frameHeight` reaching the DOM), not reported by the operator (a tablet screenshot
never surfaced it), just quietly dormant. It was only found because THIS entry needed `fill` to genuinely vary
again for a new case, which meant reading the prop's actual consumption path closely enough to notice its
sibling prop wasn't doing anything. General lesson, consistent with this arc's recurring theme (Technical
T-61.1, Register D-22–D-24, D-28): a prop that stops mattering doesn't announce it — only reading the
consumer's logic, not just the call site, reveals it.

## T-63.3 — Scope discipline: found ≠ fixed

O-68 and O-69 are both logged as open items, not silently patched alongside C-61, even though the fix for
O-68 would likely be a one-line `fill={!(portraitWide||staticSplitList) ...}` change very similar to what
this entry already did for phones. The reason: O-68 changes CURRENTLY-SHIPPED tablet behaviour that no one
has flagged as wrong, while C-61 only adds a new branch for a case (landscape phone) that previously always
showed the drawer with no operator complaint about breakage — different risk profiles, so different bars for
action. This mirrors the Register's own repeated caution about not fixing things the operator didn't ask for
in the same breath as things they did.
