## T-67.1 — "No historical mode" was a false constraint, not a schema limitation

v0.62.665's Journal justified deleting 2 lapsed Bib Gourmand rows with "this file has no historical/dropped-
listing mode." That was treated as a hard constraint of `SG-michelin.js`'s flat schema — but it was actually a
choice, and the wrong one: the moment a record carries an `awardYears` array rather than a single `year`
field, "historical" is just "an array with only past years and no current one." Nothing about the flat shape
prevented this — the schema had the capability the whole time; v0.62.665 simply didn't use it. This is the same
category of mistake as T-65.3/T-65.4 from two entries prior (a field whose shape becomes wrong needs re-deriving
what it can represent) — except here the shape was already correct, and the bug was in the code path that
handled the "no longer current" case, not in the data model itself.

## T-67.2 — A derived "current count" must be computed from the field that carries the year, not from array length

Restoring the 2 rows turned `BIB_GOURMAND.length` from "current count" into "current + historical count" — any
code reading that length as if it meant "how many venues hold this today" silently became wrong the moment
historical rows could exist in the same array. The fix generalises: whenever an array can hold both current and
lapsed entries side-by-side (which is now true for every Michelin dataset in this repo, both schemas), a
"current total" must filter on the year/award field, never trust `.length`. Only one call site in the entire
codebase read `BIB_GOURMAND.length` this way (`index.js`'s criteria-tile description string) — found by grepping
every `.length` read against `BIB_GOURMAND`/`STARS_*`/`ALL` before considering this correction complete, not
assumed to be the only one.

## T-67.3 — Reversing a documented decision is an append, not an edit — even under time pressure

The correction didn't touch `feature-0_62_665-...md`'s Removed Features table, `technical-0_62_665-...md`, or
`register-0_62_665-...md` — those files stand exactly as originally written, including the now-superseded "no
historical mode" reasoning. The correction is a NEW entry (this one, plus its sibling Journal/Register/Feature
files) that quotes the prior content verbatim and states what changed and why — per AU-1/AU-7. This matters
even for a same-session, same-PR, minutes-later correction: the paper trail should show that the wrong reasoning
was written down, considered, and then corrected — not make it look like the right answer was there from the
start.
