## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-59 | **Vertical rhythm is set on the card root, not per row.** The defect was six rows inheriting `1.5` because nobody gave them a class. Fixing them one by one would have left the same trap for the seventh row added later; a parent default makes the rule explicit and lets deliberate per-row values override it. | v0.62.691 |
| D-60 | **`leading-snug` (1.375), not `leading-tight` (1.25).** Tight buys ~6px more, but the app ships 8 locales including zh/ja and 1.25 risks clipping full-height CJK glyphs. Legibility across every locale outranks 6px on one. | v0.62.691 |
| D-61 | **12rem is the floor for a spacing-only reduction.** It is the largest cut that leaves every case no worse than before: at 11.5rem the worst-case card overruns by 49px against today's 44px, i.e. the "improvement" would make the bad case worse. Going below 12rem requires removing a row, not tightening space. | v0.62.691 |

## Note

The audit is the substantive part of this entry, and it inverted the framing. The operator's report
was *"there's wasted space, shrink the card"* — true, and now fixed. But the same arithmetic showed
the opposite problem on the cards nobody screenshots: a Michelin venue with wrapped rows already
overruns the box by ~44px, and the entire short tier overruns by ~36px. A fixed height with
`overflow-hidden` cannot be right for both, and the row that gets clipped first is the **toggle** —
the one control that would let the user see what was hidden.

That is why the reduction stopped at 12rem instead of the requested 10%+: it is the exact point where
helping the visible case stops making the invisible one worse. The remaining cut was available at the
cost of a row, and the operator declined it — *"dont move if you already trim off the spacing"*.

C-123 is the more transferable lesson. **Three separate operator reports** — Transport (v0.62.626),
Hawker (v0.62.627), Cuisine (today) — have now been filed against one pattern: *hide the control when
it would be a no-op*. Each was diagnosed correctly and fixed locally, in the app that was reported.
The pattern itself was never named, so it survived untouched in the third app until a user hit it
there too. The fix that finally landed in Cuisine is Hawker's, ported verbatim — including the
`z-[35]` value and the `resize` trigger, both of which were learned from bugs found *after* Hawker's
first attempt. Copying the whole fix, rather than re-deriving it, is what carried those two forward.
