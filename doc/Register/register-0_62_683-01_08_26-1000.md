| O-104 | **The v0.62.678 iOS auto-zoom guard is inert — a regression introduced by this session's own typography audit, shipped with a comment claiming it was fixed.** `styles.css` carries `input, textarea, select { font-size: 16px; }` (element selector, specificity 0,0,1); every Cuisine text input carries `text-sm` → `.text-sm{font-size:.875rem}` (class, specificity 0,1,0), which wins regardless of source order. Both rules confirmed present in the compiled bundle. So the inputs still render 14px and iOS will still auto-zoom the viewport on focus — including TellMePanel's input, which the v0.62.678 comment names as the very motivation for the guard. **Not fixed this entry on purpose:** every fix (`!important`, higher-specificity selector, or moving the inputs to `text-base`) raises those inputs to 16px, which contradicts the font size the operator has just asked to keep aligned with the location field (14px). Needs an operator decision: accept 16px inputs (loses the just-agreed parity at 14px, gains the zoom fix), keep 14px (accept iOS auto-zoom, and correct the misleading comment), or raise BOTH fields to 16px together (keeps parity, changes both). Same check is owed to the other five TMAs, which the audit applied the identical guard to. |
