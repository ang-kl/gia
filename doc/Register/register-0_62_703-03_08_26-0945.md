## Open (new this entry)

| O-140 | **The CI browser path is unproven.** Locally the harness uses the sandbox's pre-installed Chromium; on a runner it falls back to `channel: 'chrome'`. `ubuntu-latest` ships Google Chrome, but no runner can be exercised from here — **this PR's own CI is the first real test**, and a failure fails the build job rather than a side job. `GIA_SMOKE_CHROME` overrides the executable. ## Note

O-120 sat behind "real work" for eleven versions. The reason is visible in its own history: a
throwaway harness was built inside v0.62.692, v0.62.693, v0.62.694 and v0.62.699, and each time the
cost was absorbed into whatever else was being fixed, so it never appeared as a thing being paid for.
D-78 is the general form — a thing you keep rebuilding to finish other work is already a dependency
of that work.

The more useful part is D-79, and it is uncomfortable. The harness's **first two green runs were
false**. The second one especially: the stub left `initData` empty, so every app rendered its
reopen-from-Telegram lockout screen, and the run reported six passes. Cuisine painted four nodes.
Had it been committed there, it would have sat in CI looking like protection while being green
through the precise class of bug it was written to catch — because on that path the crashing
component never mounts at all.

What caught it was not review. It was putting the v0.62.692 crash back and demanding the harness go
red. That is the fourth time in four versions — D-72, D-75, D-77, and now D-79 — that the only thing
separating a real check from a decorative one was making it fail on purpose first.
