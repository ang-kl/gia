| D-63 | **A uniform-height strip measures its tallest card; it does not hard-code one.** D-51 wants every card identical AND no wasted space; a constant must be sized for the tallest card the set can produce, so every sparser card pays for rows it does not have. D-61 had already established 12rem as the FLOOR (below it, tall cards clip), so no number remained that satisfied both operator reports. Measuring satisfies both. **Supersedes the CHOICE of constant in D-51/D-61, not their reasoning** — those remain the record of why a constant was tried first, and `h-[12rem]` survives as the first-paint fallback. | v0.62.693 |

## Note

Three reports on one surface — *"reduce the height by 10% or one row"*, then *"lots of white space
below"* — and each was answered by picking a better constant. The constants were not wrong; the
approach was. D-51 (uniform) and D-61 (12rem is the floor) had already boxed the problem in from both
sides, and the second report is what made it visible: there was no number left that satisfied both.

The cheap lesson is to notice that shape earlier. When two recorded constraints pin a value from
opposite directions and a user is still unhappy, the value is not the thing to keep adjusting.

Second: O-120 is now overdue by evidence rather than argument. A throwaway harness has been built and
thrown away **three times in one session** — twice to find bugs nothing else could see (the v0.62.692
white-screen, the C-128 clone mismatch) and once to measure geometry the docs had only ever estimated.
Each rebuild cost more than keeping it would have.
