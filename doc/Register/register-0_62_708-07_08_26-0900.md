## Decisions (new this entry)

| # | Decision | Rationale |
| :--- | :--- | :--- |
| D-90 | **Validate the full value before truncating a serialised form of it, not after.** `.slice()` on a JSON string is a byte-offset cut with no knowledge of token boundaries — it can produce text that looks like a size-limited version of the data but is not valid data at all. Where a cap exists, decide keep-or-drop against the full length first; never slice a structured format's serialised output as the enforcement mechanism. | v0.62.708 |

## Note

O-144 was self-identified during the itinerary-map build rather than reported by the operator as an
observed failure — the realistic exposure window was narrow (a fully-populated venue serialises to
~1.5KB against the old 6000-char cap). It's closed here as a correctness fix for a mostly-dormant
defect: the old code's failure mode (silent, indistinguishable from "no venue was ever attached") was
the same shape as several other defects logged this arc under D-88/D-89 — a thing that looks like it's
working because nothing crashes, until the one input that exercises the edge case arrives.
