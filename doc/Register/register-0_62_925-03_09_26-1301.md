## ⚠ Corrections (new this entry) — retracting three claims in № 221

№ 221 described `doc/Register/` as abandoned since June. It was wrong three times. It merged
before the correction was ready, so this is a retraction standing next to it rather than an edit —
AU-1, and Rule N-3.

**Quoted verbatim from `register-0_62_924-03_09_26-1150.md` (AU-7):**

> "Incremental snapshot. The previous one is `register-0_62_69-13_06_26-1545.md`, dated
> **13-06 '26** — **855 patch versions** and nearly three months earlier."

> "**Roughly 155 open items and 60 decisions were opened, and in many cases closed, without ever
> reaching this folder.**"

> "## ⚠ Owed records — the home D-205 rule 3 never had"

**What is true:**

| # | № 221 asserted | Measured, by script, from the files |
| :--- | :--- | :--- |
| C-1 | Predecessor `register-0_62_69-13_06_26-1545.md`; **855 patch versions**; ~3 months | Predecessor is **`register-0_62_722-22_08_26-0620.md`** (22-08 '26) — **202 patch versions**, twelve days |
| C-2 | ~155 open items and ~60 decisions never reached this folder | The folder covers **O-1 … O-229 and O-301 … O-349, contiguously**, across 177 snapshots. `O-230 … O-300` were never *allocated*: **D-202** in № 196 records that ids are issued above the **global** maximum, and the old global max was O-304. Exactly **one** real id had never reached the folder — **D-204** |
| C-3 | D-205 rule 3 had never been executable | № 196 has carried **`## Still due (D-205 hold)`** since **22-08 '26 17:05 SGT** — the day D-205 was approved — with eleven rows already cleared through it |

### Root cause, which matters more than the three numbers

The "newest" snapshot was found with **`ls -t` — modification time.** This container cloned the
repo fresh, so every file carries the same mtime and that ordering is noise. A proxy was used for
version order, the proxy was never checked, and three confident historical claims were written on
top of it.

**Two things agreed with the false story instead of contradicting it:**

- **The guard already sorted by parsed version.** `__tests__/register-current.test.js` passed —
  against the real newest, № 196 — and that pass was read as agreement rather than as a
  disagreement with the prose beside it.
- **A mutation printed the answer.** Renaming № 221 made the budget report *"202 patch versions
  behind"*. 924 − 722 = 202 exactly. That was the true distance to the real newest file, and it was
  read as confirming the 855 story.

A guard that quietly agrees with a false claim is barely better than none. The new assertion is
therefore about **two files rather than one**: the newest snapshot must **name its true
version-predecessor**, so a lineage cannot skip a file sitting between. Run against № 221 it
**fails**, which is the demonstration.

### And the wrong figure propagated before it was caught

Two exploration agents read № 221 and quoted *"855 patch versions"* and *"roughly 155 open items"*
back as established fact — one of them in a table headed **Measured**. A false figure in a document
is not inert; it becomes a source. № 221 also merged and deployed, and `.vibe-journal` renders the
newest Register snapshot on soleat.net, so it was published before this retraction existed.
