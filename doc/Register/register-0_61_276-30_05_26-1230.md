| O-37 | **iCloud-stale-checkout silently writes empty blobs** | agent + operator | medium | Discovered v0.61.278 (`smart-place-label.js` on origin/main was the empty-blob hash `e69de29b…` even though the working tree had 164 lines of content) and reconfirmed v0.61.283 (the `/ver` variance pipeline silently dropped `placeId` for 8 patches because the source kept resolving to empty bytes inside the Places-API mapper). Root cause: macOS iCloud eviction can return 0-byte reads to Node / Git while the file's metadata still shows the original size, so a naive `git add` or `JSON.parse(readFileSync(...))` produces an empty payload that then commits / persists silently. **Mitigations already in use:** the plumb-commit pattern (`git hash-object → update-index → commit-tree`) which hashes content directly without re-reading via `git add`. **Outstanding risk:** any future bulk script that does `JSON.parse(readFileSync(...))` (e.g. variance / venue-template generators) can silently emit empty payloads on the next iCloud eviction. **Possible fixes:** (a) add a CI check that asserts every `*.js` in the repo is >0 bytes pre-commit; (b) wrap `readFileSync` in a `cat`-warm helper used by all bulk scripts; (c) move the project off iCloud Drive (operator's preference unknown — high impact). Logged here so future authors find the root cause without re-debugging. |
