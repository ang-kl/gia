## 2. Per-Feature Detail

### F-74.1 - Bold, not tags, in the nearby-eateries line (v0.62.987, #1929)
- **Behaviour:** operator, 15-11 '26: *"There is styling `<b>` in the telegram text"*. The nine `place.autoNearbyIntro`
  strings mixed Markdown underscores with HTML `<b>` and were sent as Markdown. They are now `<i>…<b>{place}</b>…</i>`
  and sent as HTML; wording unchanged.
- **Source:** `[AMD-339]`.

### F-74.2 - A place set in chat opens Cuisine on that place (v0.62.987, #1929)
- **Behaviour:** operator, 15-11 '26: after `/l Hyatt Place Johor Bahru Paradigm Mall` the Cuisine app *"doesn't run
  the first 12 around"* the hotel. The server had searched the hotel; the app lost the results by re-reading its own
  rewritten address. The chat link is now read once per page load and carries the place's name; a link with a place
  is a locked pick from the first render; the server cannot override the region the link states.
- **Operator's answers:** *"Set place wins"*, *"Chat place reaches every phone"*, *"Keep my filters"*.
- **Check:** `scripts/cuisine-deeplink-boot.mjs` opens the built app from a chat link under six conditions in CI.
- **Source:** `[AMD-339]`, `[AMD-340]`.

### F-74.3 - The chat place stays each phone's place (v0.62.988, #1930)
- **Behaviour:** a review finding on #1929, live in v0.62.987: when phone A picked a place in an app, phone B (which
  had picked nothing) went back to its own pre-chat record. The chat place is now kept under its own key, which no
  app write touches; each phone compares its own record with it, and the newer wins.
- **Operator's answer:** *"Fix it first, own release"*.
- **Source:** `[AMD-341]`, `[AMD-342]`.

### F-74.4 - `/forgetme` erases every location record (v0.62.988, #1930)
- **Behaviour:** the per-phone location records (since v0.61.363) and the new chat-place key are erased with the rest
  at once. Operator's answer: *"Yes, erase them at once"*.
- **Source:** `[AMD-341]`.

### F-74.5 - Airports for the city you are in (v0.62.989, #1931)
- **Behaviour:** operator, 12-11 '26: *"In the dropdown should have the airport name according to the cities
  selected … if I am in Jakata, what would you should do"*. In Jakarta the list is Soekarno-Hatta (CGK, 18 km), Halim
  (HLP, 12 km), Husein Sastranegara (BDO, 116 km), then Changi and Seletar, then Other cities ▸. The reader's place is
  the location each app already uses: Cuisine's search centre, else the GPS fix; the Train and Hawker apps' device
  location; else Singapore.
- **Order:** OurAirports' size rank (large, medium, small), nearest first within a rank. Three large airports that
  are domestic in practice are cited and rank with the medium ones: Itami, Tokushima, Halim. 150 other large airports
  are taken as international without a one-by-one check.
- **Ticking the row** opens the reader's first airport when it is outside Singapore (the map jumps there), else
  Changi's board as before.
- **Source:** `[AMD-343]`, `[AMD-344]`.

### F-74.6 - Flightradar24 on the Cuisine and Hawker maps (v0.62.989, #1931)
- **Behaviour:** operator: *"Train, Cuisine and Hawker"*, *"Everything, for everyone"* narrowed to *"Build with
  per-user limits, then public"*. Both maps use the Train app's layer, board and globe through one-line re-exports.
  The "Getting there: Changi Airport MRT" link is left out of both, since it focuses a station on the Train map.
- **Source:** `[AMD-343]`.

### F-74.7 - A daily flight-data allowance per reader (v0.62.989, #1931)
- **Behaviour:** operator: *"500 credits. indicate to users if used up 50%, 70%, 80%, 90%"*. A call is refused when
  the most it could cost would pass the cap; answers already cached cost the reader nothing. The warning shows once
  per threshold per day (remembered on the phone), and the used-up block ends at Singapore midnight (a review
  finding, fixed before merge).
- **Access:** unchanged; owner-only unless `FR24_PUBLIC=1`, which needs Register R-18 and its own approval.
- **Source:** `[AMD-343]`, `[AMD-344]`.
