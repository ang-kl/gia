## F-62.1 — Train's first launch: a whole-network overview, then a line pick

First-time Train users no longer land on a partially-zoomed slice of central Singapore. The map opens at
zoom **10** (the same LOD tier `fitBounds`'s own "Overview" computes) so the whole network is visible at
once; the East-West Line chip in the top bar blinks; and a popup (reusing the app's existing `Modal` shell)
asks the user to pick a line rather than silently defaulting to EWL. Picking any line — from the popup or the
top bar — stops the blink and focuses that line as before.

## F-62.2 — Station cards default collapsed

Every Train station card now opens in its "less" (summary-tile) state; tapping the name strip — or the card
becoming the active/selected one — expands it. This is a straight reversal of F-… (v0.62.645's "show details
by default"); see Register D-29 for why both instructions stand on the record.

## F-62.3 — List drawer opens at 1/4 height

Train's list-mode drawer now opens showing only the bottom quarter of the screen (drag handle to expand),
consistent with the map staying visible underneath — the same intent as Cuisine's card-height peek
(v0.62.657) expressed as a plain screen fraction instead, per how the operator phrased this particular ask.

## F-62.4 — A station-search "📍 location + nearest station" row, shared by Train and Hawker

New: `📍 You are near <station> (<distance>)` directly under the app title, with a "change" control that
opens a text search over every MRT/LRT station — by name or by code (`NS1`, `EW24`, …) — including stations
that haven't opened yet (tagged `· opens <year>`, still fully typeable). This is Cuisine's "set location /
click to change" pattern (F-… prior arcs) adapted to station search rather than address geocoding: no
external API call per keystroke, just a filter over the ~209-station list already served by
`/api/transport/stations`.

- **Train:** selecting a result focuses that station on the map and switches the focused line to match.
- **Hawker:** the same row (nearest station + search) renders in both live header layouts; selecting a
  result doesn't yet do anything Hawker-specific (Register O-64) — "apply this to Hawker too" is read here as
  UI parity, not a new cross-feature integration.
