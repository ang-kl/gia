## 0. Product overview

Soleat (*Gia4lunch* / "Gia") is a Singapore-focused dining + logistics assistant delivered as a Telegram bot, five Telegram Mini Apps (TMAs), and an Express server. A solo diner can discover where to eat — by cuisine, by dish, by cooking technique, by Michelin / Bib Gourmand recognition, or as a hidden gem — and then handle the practicalities: transport, carparks, weather, and an interactive map of the surroundings. The interface is bilingual (English / French).

§1 is the at-a-glance catalogue; §2 gives per-area detail; §3 summarises the v0.61 arc.

## 2. Per-Feature Detail

### Feature A — Cuisine discovery (`/cuisine`, Cuisine TMA)

The user picks one or more cuisines (55+), optionally applies quick filters (Halal, open-now, crowd, 🐾 Pet allowed, price tier, ♿️ accessibility), sets a location (current pin or an editable typed place), and searches. The editable LocationField sits above the map, out of the collapsed Search-criteria section, and carries a `suffix` line with the place-count / search status. The field carries its own 🔍 search trigger (the icon switches ✏️ ↔ 🔍; edit mode auto-closes after 2.5 s of keystroke inactivity). Results render as venue cards on a list + an interactive Google Map with **droplet/teardrop pins** carrying the venue's 1-based result rank (a 45°-rotated teardrop with a white border + drop shadow, the rank in a counter-rotated upright span). A client-side page-history (`⇠ Back` / `⇢ Next` FABs) scrubs previous result sets without a server round-trip. On every result load the floating 🔍 Search FAB flashes for 3 s with a flashing 👉 arrow pointing at it (the standing "tap 🔍 for more" cue). The result header reads `Results (12)` normally, and `Results (12/130)` on a Michelin search — the current batch over the curated-pool total. Searches show a loading overlay — a rotating set of six cycling titles for a fresh search ("loading random eateries…" on first run), a refresh message when only filters changed. Zero results trigger one silent auto-retry, then a `🔄 Reset filters & retry` CTA. Region modes: Singapore (20 km default) and Johor Bahru (30 km, whole-state geo-fence). The venue card carries name, cuisine label, area, hours, rating + crowd, country-currency price (+ FX), 🐾 line, travel time, Maps link, Michelin badge (✴️ in native gold), Healthier-Choice / building-awareness rows, and the Sanctuary read.

### Feature B — Free-text & cooking-method search (`/s`, free-text chat)

The query is classified (dish / ingredient / cooking-technique / cuisine / ambiguous) — deterministic dictionaries first, then a Gemini intent classifier. A dish resolves to a venue fan-out; a cooking technique resolves to a curated cuisine + a Gemini explainer + a representative dish, rendered with a country flag and a "verify" caveat. `/s` offers a guided assistance sub-menu. Every "Try" line carries only a genuine dish name (the `dish-name.js` guard).

### Feature C — Recognised venues (`/recognised`, Michelin chip)

Searches the curated `michelin-2025.js` Singapore Guide (3-star → Bib Gourmand) plus Asia 50/100 and Local-Produce lists. A criteria-scoped walk-through pages the curated pool 12 at a time; the seen-set self-resets on a filter change or after 1 h idle. Each entry is enriched and badged `✳️ Michelin · ⭐ · 2025`. The result header surfaces the walk-through position as `Results (12/130)` (this batch / the ~130-entry curated pool).

### Feature D — Hidden gems (`/hidden`)

A Gemini grounded-search call proposes lesser-known venues near the anchor; the server verifies each against Google Places (live status, real rating, distance) and rewrites the card, dropping hallucinated or out-of-band venues.

### Feature E — Hawker centres (`/hawker`, Hawker TMA)

100+ Singapore hawker centres (2025 dataset) on a map + list, with stall counts, status, and an InfoWindow per centre. Each centre carries nearby-transit enrichment (nearest MRT station + nearby bus stops) and surrounding amenity pins via the shared overlay controller.

### Feature F — Transport, carpark & weather

- **`/transport` / `/train` + Transport TMA** — live MRT/LRT service status (LTA TrainServiceAlerts), an affected-lines ticker, an engineering-closure schedule, a you-are-here card listing the nearest 3 stations. The `/transport` chat splits into Train and Bus sub-flows. The Train reply leads with "🚇 Nearest 3 Train stations · `<weather>`", lists the nearest 3 stations (search radius 5 km so MRT-sparse spots still resolve 3), shows each station's real **station code** coloured by line (e.g. `🟥 NS21 · 🟦 DT11 Newton`), hyperlinks each station name to its SMRT/SBS more-info page (resolved by an exact-then-normalised key lookup against `data/stations.json`; SBS rows deep-link to the station-specific `TrainInformation` page), and places the status block below the station rows. The Bus sub-menu ("🚌 Bus Information") and the `/transport` Bus result render the nearest bus stops: a header carries the live stop count, each stop block leads with its road name + a distance sentence, arrival rows read "🚌 Bus № …" with ETA bands spelled out in minutes, and a "📍 Refresh location" control drops the cached pin and re-runs the lookup. The Transport TMA station map toggles between a schematic PNG and an interactive Google Map of ~206 stations.
- **`/carpark`** — the nearest five carparks with live availability, plus a "📍 Refresh location" control and a count-aware "Compare all `{n}` carparks" map button.
- **`/weather`** — current conditions + the NEA 2-hour forecast.

### Feature G — Interactive map overlays (Cuisine / Hawker / Transport TMA maps)

The three map-bearing TMAs share one overlay controller (`mapOverlays.js`) and one presentational `MapControls` component, both kept byte-identical across the three apps:

- **Overlay chip layers** — a quick-toggle row + a "⋯/⋮" overflow dropdown toggle parks, attractions, carpark, exits, taxis, the train-line layer, bus stops, clinics/pharmacies, hospitals, and police. Point layers clip to a fixed overlay radius (~550 m) around the map anchor. The "⋯/⋮" overflow-menu button is the first (leftmost) control in the row; the 🎨 Colour ("Monochrome") pill renders directly after it, then the layer toggle pills.
- **Station info card** — tapping a train-overlay station marker opens the station info card (`stationInfoCardHtml`). It leads with the header — a single-line station shows its line-coloured code pill · "`<Name>` Station" + line code/name; an interchange shows one combined row of every line's code pill, then "`<Name>` Station" once. Next is a station-level **Exits** row of tappable "Exit X" labels — tapping a label toggles a detail row below it ("Exit # · `<street>` · Bus Stop № `<code>`", with Exit # and Bus Stop № panning + flashing their pin). Per-line detail blocks follow (More Info ↗ + a "🚆 First / Last Train" block, per-direction day-typed verbatim timings with ⚠️ service notes; an interchange repeats each line's code pill · name · line above its block). The footer carries a deduped Operator line + Google Map ↗. Tapping a station force-renders that station's exit pins and per-exit nearest bus-stop pins even when those overlay toggles are off, so the card's links always have a pin to focus.
- **Pins, zoom-aware** — the map has one zoom breakpoint, `z = 15`. Train stations: a 9 px line-coloured square below z15, a labelled pill above it (no exceptions — a selected/centre station obeys the threshold too). Exit pins: a compact bare identifier ("A", "12") below z15, a full white "Exit `<code>`" card above it. Bus-stop pins: a compact 🚏 below z15, a full "🚏 Bus Stop № `<code>`" card above it. Cuisine venue pins are numbered droplet/teardrop pins.
- **Exit Template** — tapping an exit pin opens the Exit Template popup: a line-coloured exit-code header, the station name, colour-coded station-code pills, and a 🎡 line of nearby named attractions (precomputed in the geo-build script).
- **Amenity pins** — venue / hawker-centre taps draw surrounding amenity pins (exits, bus stops with live arrivals, taxi stands, carparks) via the shared `attachAmenityPins` helper. Bus-stop popups lead with the road name + № code and bucketed arrival rows.
- **Map chrome** — a fixed high-contrast white-card popup palette, an in-card close, a vertical semi-transparent nav-button column (Reset / + / - / expand), a 🎨 Colour pill toggling colour ↔ greyscale base map (default colour; ON = Singapore blue, OFF = white), and an Overview viewport toggle. Train polyline opacity tracks zoom (0.2 zoomed out, 0.95 zoomed in) and mutes hard (0.1) when a station is selected, with the prev→current→next stretch of that station's line drawn fully opaque.

### Feature H — Menu & utility

The Menu TMA is the app launcher; its bottom-left FAB always renders "🔚 end" and closes the webview (the hub is always the webview entry point and has no sub-views). `/l` shares/sets location with a reverse-geocoded confirmation echo; `/clipboard` `/share` `/picks` copy/share/recall recent picks; `/legal` `/privacy` carry operator-curated disclosures; `/forgetme` erases stored data; `/start` `/language` onboard + toggle locale.

### Feature I — Owner / builder tools (hidden)

Behind `isOwnerChat`, off `setMyCommands`: `/v` opens an inline-keyboard builder menu firing the other hidden commands — `/ver` (health check, with an appended "🛠 Admin commands" keyboard), `/oversight` (Oversight TMA launcher), `/ftlog` (free-text-log dump), `/log on|off` (verbose logging).
