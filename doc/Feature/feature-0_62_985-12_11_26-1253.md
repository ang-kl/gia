## 2. Per-Feature Detail

### F-73.1 — LTA's "Ter" is Terminal (v0.62.983, #1925)
- **Behaviour:** LTA abbreviates "Terminal" as `Ter` in bus-stop names (e.g. "Kent Ridge Ter"); the address expander
  had it as "Terrace". It now reads "Terminal" in English and 终站 in Chinese, in the bot and the Mini Apps. Because
  expanded names are cached, the cache key changed to `geo:busstops:v2`, so the old spellings are not served.
- **Source:** `[AMD-331]`; operator answers *"终站"*, *"Change the key"*.

### F-73.2 — First and last bus at the tapped stop (v0.62.984, #1926)
- **Behaviour:** tapping a service in a stop's bubble draws its route and a strip; the strip now ends with today's
  first and last bus **at the stop that was tapped**, from LTA's own per-stop BusRoutes fields (cached since
  v0.62.971 as `fb` / `lb`). Today's day type comes from the server (`dayIndex`), with public holidays as Sunday,
  using the same rule as the bus-hours check. Nothing is added when the service does not run there today.
- **Live check:** on 09-11 '26 (Deepavali observed) the route answered `dayIndex: 2`, Sunday times, as it should
  (`[AMD-334]` addendum).
- **Source:** `[AMD-333]`, `[AMD-334]`.

### F-73.3 — No Flightradar24 bar over the map (v0.62.985, #1927)
- **Behaviour:** operator, 11-11 '26: *"remove FR24 label as it is an obstruction"*, answer *"Remove entirely"*. The
  bar and its ↻ are gone; refreshing planes is Hide planes then Show planes. The layer's state carries `note` (busy or
  over budget) instead of `caption`.
- **Source:** `[AMD-335]`.

### F-73.4 — Arrival time in the destination's zone (v0.62.985, #1927)
- **Behaviour:** the card and the board detail add "Arrives ≈ HH:MM {city} time · HH:MM SGT" and "{city} is N h
  behind / ahead of Singapore" (or "on Singapore time"), from FR24's ETA. The offset is worked out by `Intl` at the
  ETA itself, so summer time counts (London 7 h behind in July, 8 h in November). A flight to Singapore shows one line.
  No ETA, no zone or a plane on the ground: no line, never a placeholder.
- **Data:** each of the 4,021 airports in `data/airport-names.json` gains an IANA zone `z`, from its coordinates at
  build time with `tz-lookup` (CC0-1.0, a devDependency).
- **Cost:** a tapped plane not on the board costs one ETA call for its callsign (8 credits), kept 5 minutes.
- **Source:** `[AMD-335]`.

### F-73.5 — "On the ground" (v0.62.985, #1927)
- **Behaviour:** from the live position already in hand (the planes on the map, or the ETA answer's altitude and
  ground speed), with no request of its own. EK315 at Changi (0 ft, 14 kt) read "In the air" before.
- **Operator, 12-11 '26:** *"FR24's live arrival-time doesn't need altitude and speed"*; the check of those fields in
  a live answer was dropped, the code unchanged (`[AMD-336]` addendum).
- **Source:** `[AMD-335]`.

### F-73.6 — Flight globe (v0.62.985, #1927; first-bundle size in v0.62.986)
- **Behaviour:** operator, 11-11 '26: *"include a globe layer beside the hawker button … like hongjia repo"*, answer
  *"Small card, tap to expand"*. While a flight is selected (a tapped plane, or a board row, arrivals included) a
  🌐 Globe chip appears after 🍚 Hawker; it opens a small globe card at the top right; a tap expands it to full screen;
  drag turns it; ✕ closes. The route is a great circle, flown part solid up to the plane, the rest dashed.
- **Made from:** a port of hongjia's opener globe (same owner) and Natural Earth 1:110m land via world-atlas 2.0.2
  (ISC), licence kept in `data/land-110m.LICENSE.txt`. The component and land data load only when the globe opens;
  from v0.62.986 the geometry code does too (`globe-available.js`).
- **Source:** `[AMD-335]`, `[AMD-336]`.
