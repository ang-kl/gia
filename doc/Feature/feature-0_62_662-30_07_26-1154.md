## F-64.1 — No more silent English fallback

Before this entry, switching the app to Indonesian, Russian, German, Chinese, Japanese, or Spanish still
showed English text for a large share of the UI in Transport (43 strings), a smaller share in Hawker (4
strings), and — worst — well over half of Cuisine's UI in some languages (up to 216 strings in Russian and
German). None of this failed loudly; the `t()` helper's `entry.xx ?? entry.en` fallback made every gap look
like a deliberate design choice rather than a missing translation. All of it is now filled: every UI string
in Cuisine, Hawker, and Transport renders in the user's chosen language, not just English/French.

## F-64.2 — The new station-search row speaks every language too

`StationLocationField.jsx` (the "📍 you are near X / search a station" row added at v0.62.659) shipped with
only English and French. It now carries the same 8-locale set as its two host apps, so a Chinese- or
Japanese-language user searching for a station sees the search UI in their own language, not a mix of their
chosen locale for the rest of the app and English for this one row.
