### 4.3 A1 - Other cities' airports with FR24 terminal details (research done; nothing built)
**Answer:** the live flight board can work for other airports with some changes. **Terminal details never come for free.**
FR24 returns no terminals, schedules or delays. Changi's terminal labels come from a hand-sourced table in the repo.
- **Fixed to Changi/Seletar today:** a two-airport allow-list `AIRPORTS` (`fr24.js:29-32`) turns every other code away;
  the gate-to-terminal table is Changi-only, `{ G: 'T4', H: 'T4' }` from Wikipedia (`fr24.js:55-61`); the client has
  `FR24_AIRPORTS` / `FR24_PINS`, pin names in nine languages, an MRT link for WSSS, and tests pinning `WSSS|WSSL`.
- **Already generic:** the `/api/fr24/...` routes take `:icao`; the cache, rate and budget guards don't depend on the
  airport; the OurAirports name table already has Senai (WMKJ), Batam (WIDD), KLIA (WMKK) and Haneda (RJTT).
- **The Train map is Singapore-only in practice:** it opens on Singapore and can't zoom out past level 7
  (`MrtMapPanel.jsx:81,624`), and has no way to jump to another city. A KLIA pin would almost never be seen.
- **Terminal coordinates:** OpenStreetMap `aeroway=terminal` (ODbL, attribution "© OpenStreetMap contributors").
  Overpass is **unreachable from the cloud containers** (refused 05-11 twice and again 09-11), so coordinates must be
  fetched from another machine, with the source recorded.
- **Cost:** each board answer is cached per airport, so cost follows how often boards are opened, not how many airports
  exist. About 200 credits per board open, about 350 with ETA and gate polling; a board left open and refreshing costs
  up to about 960 credits an hour. All airports share 8 requests/min and 25,000 credits/month (30,000 after 31-12-26 on
  Explorer). It stays affordable only because the feature is owner-only.
- **Proposal (needs a spec + APPROVE):**
  - **Phase 1:** Senai (36 km) and Batam (42 km), already within the Singapore map. About 100-200 lines each, mostly data
    and tests: `fr24.js`, `web/transport/src/lib/fr24-layer.js`, `__tests__/fr24.test.js`,
    `__tests__/fr24-layer.test.js`, and a new spec.
  - **Phase 2:** KLIA, Haneda and others, after the Train map can follow the user's chosen city (separate, larger spec).
  - **Open question for you:** where the pin coordinates and gate-to-terminal tables come from. With no reachable free
    source, terminal labels would show only where a source exists, as Changi does for G and H gates.
- Sources: https://github.com/Flightradar24/fr24api-mcp ·
  https://www.flightradar24.com/blog/b2b/flight-summary-flightradar24-api/ ·
  https://wiki.openstreetmap.org/wiki/Tag:aeroway%3Dterminal · https://www.openstreetmap.org/copyright
