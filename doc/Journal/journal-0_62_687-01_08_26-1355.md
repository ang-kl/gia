### [HDR] v0.62.685 — Hawker/Train carousel audit against D-51

  so we can also standardise."*

- **[HAWKER — same bug, same fix]** Hawker's `CentreCarousel` carried the **identical six-rung

  does not have the bug this work exists to fix. Forcing 320px would drop iPad mini landscape from
  ~4.3 tiles to ~3.1: a redesign of what the app is for, not a standardisation. One genuine outlier
  found and reported rather than silently changed: **phone landscape at 164px shows ~7 tiles**.

- **[GLYPHS — three apps, three conventions]** Cuisine `⌄/⌃`, Hawker `⌄/⌃`, Transport `▾/▴`, each

### [HDR] v0.62.686 — a footer placement bug, and why the liquid glass was invisible

- **[FOOTER — the alignment class was never the cause]** Operator: *"the 'top' and 'end' are meant to
  be on the right side. let's audit them."* They were not. The control row is
  `grid-cols-[1fr_auto_1fr]` with THREE intended children, but the middle one (Criteria pill /
  Michelin pager) is gated on `criteriaSummary.length > 0 || michelinTotalPages > 1`. With neither
  present only two children render, so **CSS Grid auto-placement drops the right-hand cluster into
  column 2** — the `auto` column, sized to its own content — and `justify-self-end` aligns it to the
  end of *that* column, leaving the entire third `1fr` column empty to its right. Hence a cluster
  floating mid-row. It looked correct in the older v0.62.679 screenshots **only because a
  "Criteria (1)" pill happened to be filling column 2**. Fixed with `col-start-3`.

- **[LIQUID GLASS — structurally absent on wide screens]** Operator (desktop-1440 screenshot): the
  carousel card *"doesn't use the Liquid Glass Design that elevates traditional glassmorphism."*
  Correct. The in-focus card surface was a flat **`bg-white`** with no glass class at all; only the
  half-peeking end cards got `.liquid-glass`. On a phone that reads fine (one card in focus, the rest
  glass) — but on a wide screen **every fully-visible card is "in focus"**, so the glass design was
  effectively never rendered there. The screenshot was the design working exactly as written.
  Added `.liquid-glass-focus`: same house optics (blur 14px + saturate 1.5 + inset ring + lift) over
  a near-opaque light base.
  **Deliberately a separate class, not `.liquid-glass` + a bg utility:**
  `[data-theme="dark"] .liquid-glass` forces a dark background with `!important`, which would collide
  with the focused card's light-palette CSS-var override (`--tg-text: #1c1c1f`) and produce dark text
  on a dark fill. Owning its own background keeps that rule from ever applying. Honours
  `prefers-reduced-transparency`.

- **[HAWKER height tiers — D-51 with Hawker-sized values]** `h-[8rem]` standard / `h-[5.5rem]` short.
  Values differ from Cuisine's 13rem/7.5rem **on purpose**: Hawker's collapsed card carries 4 rows
  (name / address / stalls+status / toggle) against Cuisine's 10, so reusing 13rem would render a
  mostly-empty 208px card. The *spec* is standardised; the pixel height follows each card's content.
  Flagged to the operator with an offer to force literal 13rem lockstep if visual identity across
  apps is wanted instead.

### [HDR] v0.62.687 — the composer field: v0.62.683 matched the wrong element

- **[CORRECTION]** Operator, returning to the same field: *"follow exactly the slightly curved corner
  like the location search and the colour as well **which i raised this morning**."* The difference
  survived v0.62.683 because that pass compared the composer against `LocationField`'s **inner closed
  button** (`border border-tg-border`). The box the operator is actually looking at is the field's
  **outer surface**: `rounded-md border loc-field-surface` (`LocationField.jsx:432`, `:1356`,
  `:1431`). `.loc-field-surface` is a **named colour decision, not a theme token** — `#cbd5e1`
  slate-300 on white in light mode, yellow-400 on the card in dark — so `border-tg-border` was never
  going to land on it however the token resolved. The composer now uses that same class, so the two
  boxes cannot drift apart again. Radius already matched (both `rounded-md` — the "slightly curved
  corner"); `py-1` kept over the field's `py-1.5` so the dock height is unchanged.
  Also worth recording: the **blue** stroke in the operator's crop is not the surface colour at all —
  it is the `editBlink` accent ring or the shared focus outline sitting on top. The resting stroke is
  the slate-300. Same misreading-a-state-as-a-style trap noted in v0.62.683's own entry.

- **[DETAILS TOGGLE]** Operator: *"less spacing to the border of the button and slight lighter
  colour."* `px-2.5`→`px-1.5`, `border-tg-accent/50`→`/30`, `text-tg-accent`→`/70`. Applied to
  Cuisine and Hawker, which share the pill pattern. **Transport deliberately untouched** — its toggle
  is not a pill but inline text whose colour is computed per-station from the line colour
  (`style={{ color: stripText }}`), so these classes have nothing to attach to.
