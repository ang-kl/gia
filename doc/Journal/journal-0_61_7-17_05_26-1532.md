## New

### [HDR] #210 | 15:32:00 SGT 17-05-26 | v0.61.7 — train-line redraw (Chaikin-smoothed derived geometry) | 4 files | PR 4 of 4 | 1 build |

- **[INTENT]** The MRT/LRT polylines connect stations with hard straight segments, so the lines
  zig-zag instead of curving like the real track. Round those corners.

- **[DELTA]**
  - **`web/transport/src/data/line-paths.js`** — added Chaikin corner-cutting:
    `smoothSegment(seg, iterations)` (2 passes; a segment whose first and last point coincide
    is treated as a closed loop and stays closed — SLRT/PLRT branches) and `smoothLinePaths(paths)`
    (smooths every segment of a line-map, leaves `_meta` keys alone). `buildLinePaths` itself is
    left **pure** (raw station geometry — its unit tests are unchanged); `resolveLinePaths` now
    returns `smoothLinePaths(buildLinePaths(...))` for the derived fallback. Real LTA geometry
    (`data/mrt-line-paths.json`) is detected first and passed through **un-smoothed** — it is
    already curved.
  - **`index.js`** — `/api/transport/line-paths`'s server-side derived branch now smooths via
    `smoothLinePaths` (dynamic-imported from the transport ESM module), so the Transport map
    AND the Cuisine/Hawker "Train" overlay both get curved fallback geometry.
  - **`__tests__/transport-line-paths.test.js`** — new `smoothSegment` / `smoothLinePaths`
    cases (open segment keeps endpoints + gains points; closed loop stays closed; <3-point
    segment untouched; `_meta` preserved); the two `resolveLinePaths` fallback cases updated to
    expect the smoothed derived geometry.
  - **`package.json`** — `0.61.6 → 0.61.7` (PATCH — train-line redraw).

- **[VERIFICATION (sandbox)]**

  ```bash
  $ node --check index.js          → OK
  $ npm test -- --run              → 1924 passed (1924)   (+4 smoothing cases)
  $ npm run build:transport        → vite build OK
  ```

- **[STATUS]** STAGED → PROD on the next Railway deploy after PR 4 merges. PR 4 is stacked on
  PR 3 (v0.61.6), the final PR of the 4-PR map-UX arc.

- **[TEST]** Post-deploy, Transport TMA Google Map: the lines read as smooth curves between
  stations rather than sharp zig-zags; loops still close.

- **[KNOWN GAPS]**
  - The smoothed geometry is an *approximation* — it rounds the station-to-station corners but
    does not trace the exact track. For exact route shapes, run `node scripts/fetch-mrt-lines.js`
    on a network with data.gov.sg access (a dev machine or a Railway job) and commit the
    resulting `data/mrt-line-paths.json`; `resolveLinePaths` + `/api/transport/line-paths`
    already prefer that real geometry when the file is present (the sandbox here has no
    data.gov.sg access, so the file could not be generated in this PR).
  - This completes the 4-PR map-review arc (v0.61.4 → v0.61.7).
