### [HDR] #373 | 17:30 SGT 27-05-27 | v0.61.172 — Fix recountTrainStations + recountTrainLines schema | 4 files | 1 PR | 1 build |

- **[INTENT]** The v0.61.166 Periodical recount runs `recountAll()`
  on a 6-hour cron. Two of its 14 items have been silently failing
  since v0.61.164 because their reader fns assume a JSON shape the
  source file doesn't have. They write `n=0, source='unavailable'`
  to the history every tick, polluting the marketing-display
  `getDisplayCount` for the corresponding `{n}+` placeholders.
  Caught by an operator-initiated dry-run today.

- **[DELTA]**
  - **`count-recount.js`** (2 fns rewritten):
    - **`recountTrainStations`**: was
      `_countJsonArray('data/mrt-coords.json')`. The
      `_countJsonArray` helper recognises `Array.isArray(j)` /
      `j.features` / `j.centres` / `j[arrayKey]` shapes — none of
      which match `data/mrt-coords.json`, which is a flat object
      keyed by station name (`{ _meta, "Jurong East": {...},
      "Bishan": {...}, ... }`). Helper returned `null` → the fn
      recorded `source='unavailable'`. **Fix**: read the file
      directly, count `Object.keys(j).filter((k) => k !== '_meta')
      .length`. Returns **209** (180 operational + 29 future as of
      2026-05-10 per `_meta.schema`).
    - **`recountTrainLines`**: was iterating
      `Array.isArray(j) ? j : (Array.isArray(j?.features) ? j.features : [])`
      and parsing a singular `.code` field. Wrong shape on *both*
      axes — file is flat-object-keyed and has plural `.codes` +
      `.lines` per entry. Returned 0 → `null` → `unavailable`.
      **Fix**: iterate the same flat object, union each station
      entry's `.lines` array (`'NSL'`, `'EWL'`, `'NEL'`, etc.) into
      a `Set`. Returns **12** (10 operational + JRL + CRL future).
  - **`__tests__/count-recount.test.js`** (1 test strengthened,
    1 new):
    - The pre-existing `train-lines recount derives a small
      integer from station codes` test was guarded by
      `if (Number.isFinite(out.n))`. Because `n` was always
      `null`, the guard never fired and the assertion was never
      reached — the bug was completely masked. Fix: drop the
      guard, assert `out.source !== 'unavailable'` plus
      `5 < n < 20`.
    - New `train-stations recount counts station-name keys,
      ignoring _meta` test mirrors the same defence:
      `out.source !== 'unavailable'` plus `150 < n < 300`.
    - Count-recount test file: 12 → 13 tests.
  - **`package.json`** — `0.61.171 → 0.61.172`.
  - **`doc/.serial-state.yml`** — `commit 384 → 385`, `build 174
    → 175`, `journal 372 → 373`; re-anchored 27-05 '26 17:30 SGT.
  - **`doc/Journal/journal-0_61_172-27_05_26-1730.md`** — this entry.

- **`recountTrainStations`** — replaced verbatim. Prior body:
  ```js
  async function recountTrainStations(redis, opts = {}) {
    const n = _countJsonArray('data/mrt-coords.json');
    const source = n == null ? 'unavailable' : (opts.source || 'manual');
    await recordCount(redis, 'train-stations', n ?? 0, source, opts.notes || '');
    return { item: 'train-stations', n, source };
  }
  ```
  Reason: `_countJsonArray` doesn't recognise the flat-object shape
  of `data/mrt-coords.json` (`{ _meta, "Jurong East": {...}, ... }`).
  Replacement: read the file directly, count
  `Object.keys(j).filter((k) => k !== '_meta').length`.
- **`recountTrainLines`** — replaced verbatim. Prior body parsed
  a singular `.code` field on a `j.features` array. Reason: the
  file is keyed by station name with a plural `.lines` array per
  entry. Replacement: union every station entry's `.lines` into a
