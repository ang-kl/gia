- **[O-95 — Hawker "Copy" stays open]** `web/hawker/src/App.jsx`'s `saveToChat()` called
  `tg().close()` on success, closing the WebApp after every single copy — unlike Cuisine's
  `copyOneToChat()`/`copy()` (`ResultCard.jsx`), which never closes and instead shows "✓ Sent" for
  3s before reverting to "📋 Copy". Removed the close call; added a `sentNames` Set (same per-card-
  independent pattern as Phase E's `expandedCards`) so each card that was just copied shows its own
  "✓ Sent" for 3s. New `card.sent` i18n key across all 8 Hawker locales, same key name and EN/FR
  text as Cuisine's own `card.sent`.

- **[O-96 — glass-effect bug: root cause + fix]** Operator confirmed Hawker shows the same
  opaque-edge-card symptom as Train (not Train-only). Investigation found: Cuisine's
  `ResultDrawer.jsx` runs TWO mechanisms gated on `glassPeek = vp.isWide` — an IntersectionObserver
  `visibleSet` on tablet/desktop (multiple simultaneously-visible cards), but on PHONE it bypasses
  IntersectionObserver entirely and tracks the single centred card via `detectCentre()`: a
  synchronous `getBoundingClientRect()` geometry match re-run on every native `scroll` event, which
  cannot get "stuck." Hawker's `CentreCarousel` and Transport's `StationCarousel` had NO such phone
  bypass — both always drove `glass` purely off an IntersectionObserver `focused` Set, on every
  device. IntersectionObserver callback timing during a scroll-snap gesture is implementation-
  defined and can coalesce/delay in Telegram's embedded WebView; a dropped/delayed below-threshold
  callback left a card's index stuck in `focused`, rendering it opaque even after it had visually
  scrolled to a peeking edge position — exactly the reported symptom. **Fix:** ported Cuisine's
  dual-mode pattern into both carousels — added the same scroll-driven `detectCentre()`-style
  geometry detection, gated on a new `isWide` prop (both apps already hold `vp` from
  `useViewport()`): `!isWide` (phone) now computes `glass` from a single `centeredIdx` tracked via
  scroll geometry; `isWide` (tablet/desktop) keeps the existing IntersectionObserver `visibleSet`
  unchanged (not implicated in the bug — the reports were both phone). No CSS/opacity changes —
  `bg-tg-card/60 liquid-glass` already matched Cuisine (60%) in both apps; this was purely a
  WHICH-cards-get-glass bug, not a style bug.

- **[O-97 — header-title and card-name-size unification]**

    the carousel/landscape layout vs `text-base`/16px in the other two). Changed the odd one out to
    `text-base`, matching the other two and Cuisine's own header title.
  - Hawker's centre-card name (`text-[13px]`) and Transport's station-card name (`text-[14px]`)

    Transport's `StationCard` component gained a new `isCompact` prop (passed from both
    `renderStationCard` and the single-focused-card call site).
