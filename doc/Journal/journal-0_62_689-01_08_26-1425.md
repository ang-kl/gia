## New

### [HDR] v0.62.688 — ring labels: four points on EVERY ring, smaller

- **[INTENT]** Operator: *"let's standardise the ring (3 rings, 750m walking, #.#km (# stops),
  #.#km (# stops)) can we have labels at four corners instead of top but smaller. audit and list
  how this rings are activated."*

- **[DELTA — `web/_shared/lib/distance-rings.js`]** Two changes, one file, all three map TMAs.
  - **Bearings.** `drawRing` now always emits `[0, π/2, π, 3π/2]`. Previously a ring got a single
    NORTH label unless it was flagged `fourSide` (the outer/reach ring) or exceeded `LARGE_RING_M`.
  - **Size.** The label pill: font 11px → **9px**, icon gap 3 → 2, padding `1px 7px` → `0 5px`,
    radius 10 → 7.

- **[WHY THIS IS A CLASS OF BUG, NOT AN INSTANCE]** The file's own history already carried two
  operator reports about the *same* single-north-label default, each patched one ring class at a
  time: **v0.62.543** ("a big ring's single north label can sit far off the visible arc" → four
  labels when the ring exceeds `LARGE_RING_M`) and **v0.62.586** (Brisbane, IMG_0751 — "where is the
  four corners (N/S/E/W) labels of the outer ring", a 2.9 km ring that fell *under* `LARGE_RING_M`
  and so showed one label → `fourSide` forced four on the outer ring regardless of size). Making the
  four-point treatment universal removes the class of report rather than its next instance.
  `fourSide` and `LARGE_RING_M` are retained but no longer drive bearings — kept, with the reasoning
  above written into the file, so the two prior reports stay readable in place (AU-1/AU-7).

- **[AUDIT — how the rings are activated]** Recorded because the operator asked for it explicitly.
  There is no toggle, no overlay-layer switch, and no automatic draw: rings are drawn ONLY by an
  explicit `ringLayer.draw(centre, …)` call, and cleared by `clear()` on tap-out.

  | TMA | Ring layer exists | Drawn when | Cleared when |
  | :--- | :--- | :--- | :--- |
  | Cuisine | `MapPanel.jsx:362` | a result pin / card is focused; `results` passed, so the third "reach" ring can appear | map tap-out (`closeInfo`) |
  | Hawker | `HawkerMapPanel.jsx:332` | a hawker-centre pin or card is tapped; **no `results`** → 2 rings, never a reach ring | map tap-out |
  | Transport | **absent before this arc** | — | — |

  So the operator's "3 rings" is a Cuisine-only maximum. Hawker draws two (🚶 750 m + 🚆 2-stops)
  because it passes no result array for the reach ring to bound itself against, and Transport had no
  ring layer at all. That gap is what v0.62.689 closes.

### [HDR] v0.62.689 — station-pick inspection overlay (Hawker + Train)

- **[INTENT]** Operator: *"the Hawker Centre, when type in the road or train. you shuld place a
  temporary location (only one per each time) and then ring it and show nearby train and hawker
  centre. there should be current logic on how eatery when selected in Cuisine TMA to show the
  surrounding amenities but now instead a temporary pin, instead. interpret this request and get
  approval before build."* Then, against the interpretation: *"station-only for now, nearest 3
  hawker centres, inspection overlay only. Can this be done for Train as well?"* → *"the zoom in to
  the temporary location should be 15 (iphone and smaller) or 17 (ipad and desktop)"* → on the pin
  glyph: *"go with option 1, custom amber pin."*

- **[SCOPE, AS APPROVED]** Station picks only — **no geocoding of road names** this round.
  **Nearest 3** hawker centres. **Inspection overlay only:** the pin never becomes the search
  anchor, never changes the active region, and never re-ranks the card list. One pin at a time,
  cleared on tap-out or replaced by the next pick.

- **[THE PIN — why not 📍]** The operator first asked for *"distinct glyph (📍) in bold bright
  orangy-yellow"*. 📍 (U+1F4CD) is a **colour emoji**: the font supplies its own red artwork and CSS
  `color` cannot touch it, so that exact request is unreachable through the emoji. (U+FE0E text
  presentation would accept a colour but renders inconsistently across iOS / Android / desktop
  WebViews.) Surfaced with three options; the operator chose the custom pin. `tempPinNode()` builds
  a rotated rounded-square teardrop in **amber-500 `#f59e0b`** with a white core and an amber-600
  stroke — deliberately unlike every other marker in the codebase (hawker centres green/grey
  numbered, stations line-coloured, Cuisine results green). This also matches how every other marker
  here is already built: `stationPillNode`, `busTierNode`, `amenityLabelNode` are all styled DOM.

- **[DELTA — `web/_shared/lib/temp-pin.js` (NEW)]**
  - `TEMP_PIN_COLOR` / `TEMP_PIN_COLOR_DEEP`, `tempPinNode(label)`, `nearbyCentreNode(name, distM)`.
  - `nearestByDistance(lat, lng, items, n)` — pure haversine ranking; skips non-finite coords rather
    than sorting them to the front, does not mutate the input, returns `[]` on bad input.
  - `shortDist(m)` — `"350 m"` / `"1.2 km"`.
  - `loadAllHawkerCentres()` — one memoised `/api/hawker/centres-by-region` fetch, flattened across
    regions. It lives here because **neither host had the full list**: Hawker's App holds only the
    ACTIVE region's centres, and Transport's equivalent (`fetchHawkerCentres`) is module-private to
    its own `mapOverlays.js`. Nearest-3 must be able to rank a North centre against a Woodlands
    station, so the loader sits beside the ranking that consumes it rather than being exported out
    of one app's overlay module.
  - `createInspectLayer(map, googleMaps)` — owns the temp pin and its centre pills **as one unit**,
    so `show()` cannot leave a previous pick behind. That is what enforces "only one per each time".

- **[DELTA — Hawker]** `HawkerMapPanel.jsx`: `inspectLayerRef` built in `initMap`, cleared inside the
  existing `closeInfo` (so rings and pin die together — no stale pin can outlive its rings),
  destroyed on unmount. New global `window.__giaHawkerInspect(lat, lng, label)`, following the
  file's five existing `__giaHawker*` globals rather than inventing a second inward channel. It
  reveals the map (phone layouts stack the map ABOVE the list — the v0.62.551 lesson), pans, zooms,
  draws rings, calls `showVenueTransit`, then paints the nearest 3.
  `App.jsx`: **the two `<StationLocationField>` instances had been rendered with no
  `onSelectStation` at all since v0.62.659 — picking a station in Hawker did nothing whatsoever.**
  Both now call `inspectStation`.

- **[DELTA — Train]** `MrtMapPanel.jsx` had **no ring layer**; `createRingLayer` is imported for the
  first time here, alongside the inspect layer. New global `window.__giaMrtInspect`. Wired into the
  station field's EXISTING `onSelectStation` at `App.jsx:497` as an addition — the pick still sets
  `focusedStation`, still focuses the line, still flips PNG → Google map. The inspect call is
  deferred one tick precisely because the pick may be what creates the map panel, so the global it
  registers may not exist yet at that instant.
  **`showVenueTransit` is deliberately NOT called here** — on the Train map the picked point IS a
  station, so drawing "the nearest stations" around it says nothing.

- **[ZOOM]** `TAP_ZOOM_PHONE = 15` / `TAP_ZOOM_WIDE = 17` from `_shared/lib/map-interaction.js`
  already held exactly the operator's two numbers, so no constant was added. Both panels split on
  `matchMedia('(min-width: 700px)')` — the threshold Hawker's panel already used for its own tap
  zoom. Held in a **ref** in both, because the globals that read it are registered once (deps `[]`)
  and would otherwise capture the boot-time value forever.

- **[DISTANCE ALWAYS SHOWN]** `nearbyCentreNode` always renders the distance. Flagged to the
  operator before build and honoured here: in the outer rail network the 3rd-nearest centre can be
  kilometres out, and the 750 m walk ring must never imply it is walkable.
