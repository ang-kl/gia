## Amendments

### v0.61.52 — CR4 (journal #256) — "focus" definition expanded

Original prior text (verbatim):

> "Focus" here is the **map anchor** (viewport centre), which is the
> closest single signal that exists today across all three TMAs. It does NOT yet
> upgrade prominence around a selected eatery / focused result / active station — the
> user's CR4 listed those as ideal anchors. Adding multi-focus logic is a follow-up
> (would need each TMA to push its focus into the controller).

Appended change with rationale and serial (20-05 '26 10:00 SGT, № 265):

The deferred multi-focus logic landed in v0.61.54 (this entry, #258) — but **without**
adding a new "each TMA pushes its focus" API. Instead it composes the existing focus
signals already present in the controller: `anchor` (map viewport, all 3 TMAs),
`trainEmphasis` (Cuisine's search-result anchor), and `detailStation` (Transport's
tap-active station). This avoids invasive per-panel changes and keeps the bus-stop
de-emphasis logic self-contained in `mapOverlays.js`.
