### [HDR] #260 | 12:30:00 SGT 20-05-26 | v0.61.56 — CR6 Phase 2a bus services per exit | ~8 kb | 5 files | 1 PR | 1 build |

- **[INTENT]** Join the nearest bus stop to each station exit so the CR6 info card
  can render the `Exit B · Bus № 167, 518, …` lines (with the `Exit <label>` and
  `Bus №` map-link affordances the operator spec'd).

- **[DELTA]** (final shape — see Amendments for the superseded live-fetch design)
  - **`scripts/build-bus-services-by-stop.js`** (new) — **no network, no API key.**
    Joins two committed static LTA datasets:
    - `geoloc/LTABusStop.geojson` — full bus stop locations (5,166 stops;
      `BUS_STOP_NUM` + coords);
    - `data_realtime/BusRoutes.json` — DataMall BusRoutes snapshot (`ServiceNo`
      per `BusStopCode`).
    Output `data/bus-services-by-stop.json` = `{ stops: { <code>: { lat, lng,
    services[] } } }`. De-dupes services across directions, natural-sorts service
    numbers, and writes a `_meta.note` flagging partial-sample routes data.
  - **`scripts/build-station-info.js`** — optional bus join. For each exit, binds
    the **nearest bus stop within `BUS_NEAR_M = 80 m`** (box-filter then haversine),
    emitting `exits[].nearest_bus_stop = { code, lat, lng, services }`. The stop is
    bound regardless of whether its `services[]` is populated — the stop coords
    drive the card's `Bus №` map link, and `services[]` fills in when fuller routes
    data lands. Graceful fallback to `null` when the bus file is absent.
  - **`data/bus-services-by-stop.json`** (new, generated) — 5,148 stops.
  - **`data/stations.json`** (regenerated) — 357 of 569 exits now carry a
    `nearest_bus_stop` (the rest are genuinely > 80 m from any stop).
  - **`package.json`** — `0.61.55` → `0.61.56` (PATCH).

### [HDR] #260 — Phase 2a data source: live DataMall fetch → committed static datasets

Original prior `[DELTA]` / `[INTENT]` (verbatim, as first drafted this session):

> - **[INTENT]** Fetch services-per-stop from LTA DataMall, and join the nearest stop

Appended change with rationale and serial (20-05 '26 12:30 SGT, № 267):

The first draft used a **live** LTA DataMall fetch. Two problems surfaced: (a) the
sandbox egress allowlist blocks `datamall2.mytransport.sg` (and `data.gov.sg`) —
`403 Host not in allowlist` — so the fetch could never run here; (b) the operator
then committed static LTA datasets (`data_realtime/`, `geoloc/LTABusStop.geojson`)
and asked to relook at #551. The script was therefore renamed
`fetch-bus-services-by-stop.js` → `build-bus-services-by-stop.js` and rewritten to
read those committed files — **no network, no key, runs in sandbox CI**. The
nearest-stop rule was also simplified from "nearest stop *with services*, fallback
to next-nearest" to "geometric nearest ≤ 80 m"; the old rule collapsed to ~null
everywhere when the routes data is only a partial sample, and the stop's *location*
(not its services) is what the card's `Bus №` link needs.
