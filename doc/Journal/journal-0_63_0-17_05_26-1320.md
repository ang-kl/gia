## New

### [HDR] #206 | 13:20:00 SGT 17-05-26 | v0.63.0 — expandable maps + Transport overlays + live carpark layer | 14 files | PR C of 3 | 1 build |

- **[INTENT]** Three map-UX requests: every TMA map should be expandable; the overlay-layer
  chips (added to Cuisine + Hawker in v0.61.0) should also reach the Transport TMA; and a live
  carpark layer should join Parks / Attractions / Taxis.

- **[DELTA]**
  - **Expandable maps** — a discrete bottom-right (top-right on Transport, where the zoom
    control sits) `⤢`/`⤡` toggle on all three map panels (`web/cuisine/.../MapPanel.jsx`,
    `web/hawker/.../HawkerMapPanel.jsx`, `web/transport/.../MrtMapPanel.jsx`) grows the map
    container to `90vh` and back. New `map.expand` / `map.collapse` i18n keys in all three i18n
    tables.
  - **Overlay chips on the Transport TMA** — `mapOverlays.js` and `MapLayerChips.jsx` copied
    into `web/transport/src/`; `MrtMapPanel.jsx` gains an `overlayLayers` prop, instantiates the
    overlay controller in `initMap()` and drives it from a `useEffect`; `web/transport/src/App.jsx`
    holds the `overlayLayers` state and renders `<MapLayerChips>` below the Google-Map view.
    Transport's `i18n.js` gains the `layer.*` keys (it had none).
  - **Live carpark layer** — new `GET /api/geo/carpark` in `index.js` proxies the LTA DataMall
    Carpark Availability feed via `carpark.js` (new `allPoints()` helper), Redis-cached 60 s.
    `mapOverlays.js` (all three copies) gains a `carpark` layer fetched from `/api/geo/carpark`,
    rendered as 🅿 `AdvancedMarkerElement` markers whose InfoWindow shows `<name> — <n> lots`.
    `MapLayerChips` gains a 4th `🅿 Carpark` chip; `layer.carpark` i18n key added to all three
    apps; the `overlayLayers` state object in each App gains `carpark: false`.
  - **`package.json`** — `0.61.0 → 0.63.0` (MINOR — new feature; 0.62.0 is the concurrent PR B).

- **[VERIFICATION (sandbox)]**

  ```bash
  $ node --check index.js carpark.js     → OK
  $ npm run build:cuisine / build:hawker / build:transport  → all vite builds OK
  $ npm test -- --run                     → 1913 passed (1913)
  ```

- **[STATUS]** STAGED → PROD on the next Railway deploy after PR C merges. The carpark layer
  needs the existing `LTA_ACCOUNT_KEY` env var; when it is unset `/api/geo/carpark` returns an
  empty list and the carpark chip simply toggles nothing.

- **[TEST]** Post-deploy: each TMA map shows the `⤢` toggle; tapping it grows the map to ~90vh
  and back. The Transport TMA Google-Map view shows the four overlay chips; toggling Carpark
  renders 🅿 markers (with `LTA_ACCOUNT_KEY` configured) showing available-lot counts.

- **[KNOWN GAPS]**
  - The carpark layer depends on `LTA_ACCOUNT_KEY`; unset → empty layer (graceful).
  - `mapOverlays.js` is now duplicated across three Vite apps (no shared package); the copies
    must be edited together — flagged in the file header.
