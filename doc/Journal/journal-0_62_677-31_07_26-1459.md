_(№ 1,200 — 31-07 '26 14:59 SGT)_

## New

### [HDR] v0.62.677 — Hawker's per-centre action button now says "Copy" like Cuisine's

- **[INTENT]** Operator: *"in Hawker TMA, 'save to Chat' change to 'copy' being consistent like
  Cuisine TMA copy button."*

- **[DELTA]** `web/hawker/src/i18n.js` — the `btn.saveToChat` key's VALUE (not the key name) changed
  from "📤 Save to chat" to "📋 Copy" across all 8 locales, using Cuisine's own `btn.copyOne` wording
  verbatim per locale (en/fr/id/ru/de/zh/ja/es). Key name, the `saveToChat()` function, its
  `/api/hawker/save-pick` POST, and the app-closes-on-success behaviour are all UNCHANGED — this is
  a label-only fix, not a behaviour change (the operator asked for wording consistency, not for the
  send-and-close mechanism to become send-and-stay like Cuisine's copy). That underlying mechanism
  difference (Hawker closes the WebApp after copying; Cuisine's copy leaves it open so the user can
  copy multiple cards) is a disclosed, NOT-yet-addressed gap — see Known Gaps.

- **[VERIFICATION (sandbox)]** `node --check` on `i18n.js`; hawker `vite build` green; full
  `npm test` **3842/3842 across 152 files** (unaffected — pure string-table change).

- **[TIME ANCHOR]** Container clock `2026-07-31T06:59Z` = **31-07 '26 14:59 SGT** (TF-9).

- **[STATUS]** PR pending.

- **[KNOWN GAPS]**
  - The relabel makes the WORDING consistent but not the BEHAVIOUR: Hawker's button still closes
    the Telegram WebApp on success (`tg.close()`), while Cuisine's "📋 Copy" stays open so the user
    can copy several cards in one session. Whether that close-on-copy behaviour should also change
    to match Cuisine was not asked for this pass and is not addressed here — flagged, not guessed at.
  - A separate, larger request from the same message — glass-effect parity for Hawker/Train cards —
    was investigated in the same conversation turn but NOT resolved: both Hawker and Train already
    implement the identical `.liquid-glass` + `bg-tg-card/60` mechanism as Cuisine (verified in
    source and in the built CSS output — not a silent Tailwind opacity-drop, the exact bug class
    this repo has hit before), yet a device screenshot of Train's carousel showed the edge
    ("peeking") cards rendering fully opaque instead of glass. Root cause NOT found — reproducing
    live requires the real backend + Google Maps API data (unavailable in-sandbox), and static
    code reading did not surface an obvious defect in the `IntersectionObserver`-driven focus
    tracking. Operator was asked whether Hawker shows the same flat-card symptom (to tell whether
    the bug is shared or Train-specific) before any fix is attempted — answer awaited, not yet
    actioned.
