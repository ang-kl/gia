### [HDR] #643 | 16:10 SGT 10-06-26 | v0.62.0 — Michelin: review-fallback fix, city-scoped walk, grey-out unavailable cuisines, curated-metadata cache + refresh job | index.js + michelin-data.js + web/cuisine ×3 + scripts/build-michelin-meta.mjs + michelin-meta.json + tests | 1 PR | 1 build |

- **[A — bib-gourmand review fix]** `index.js:~9712` — the Michelin review loop did
  `if (!recent.length) continue;` (recent = reviews ≤4 months). Established bib gourmands (e.g.
  Hor Poh) have hundreds of reviews but few within 4 months → `recentReview` never set → the
  "💬 Bib Gourmand Guide … curated recommendation." placeholder. Mirrored the cuisine path's
  v0.61.390 fix: `pool = (recent.length ? recent : withText)` — a real review shows whenever
  Google has ANY review; the placeholder now appears only when there are genuinely zero reviews.
  Also added `reviews: null` to the Places-fail fallback object for shape parity.

- **[B — city-scoped walk]** `index.js:~9315` — the city branch built
  `ordered = [...inCity, ...everyOtherCity]`, so taps 1–2 drained KL then tap 3 paged into the
  appended George Town (Penang) venues → the map spanned two cities. Now `ordered = inCity` (the
  walk stays in the selected city); the other-city count rides `michelinSummary.nationRemaining`
  as a hint. Map frames one city; SG (single-region) unaffected. TMA extracts `nationRemaining`.

- **[C — grey-out unavailable cuisines (per country+city)]** New
  `michelin-data.availableCuisines(cc, city)` → the slug set with ≥1 visitable star/bib venue
  there. `/api/cuisine/catalogue` now ships `michelinCuisinesByCC` ({ cc: { all, byCity } }) for
  the venue-award-loader countries only (SG omitted — its data carries no routing-slug cuisines →
  TMA fails OPEN). TMA (`CuisineCategoryDrawer` + `CuisineDrawer` + `App.jsx`): when Michelin is in
  the selection, cuisine chips not in the country+city set — and the durian/fruit/durian-pastry
  special modes (never Michelin) — are greyed + non-tappable. Prevents the confusing ~15 s
  no-match search ("Michelin + Japanese in KL").

- **[D — curated metadata + refresh job (full curation)]** `scripts/build-michelin-meta.mjs`
  (`npm run michelin:refresh`) resolves every curated venue against Places ONCE (offline),
  capturing placeId/lat/lng/rating/price/hours/accessibility/Maps URL/website + social URLs, and
  writes the committed `michelin-meta.json` (keyed by entry id, `fetchedAt`-stamped). The Michelin
  handler now: (i) **restores the per-entry Places cache** (`michelin:place:<id>`, 24h — dropped
  in v0.60.195, which is why every tap re-hit Places ×12), and (ii) when a snapshot record carries
  a placeId, resolves details **by ID** (`FIELD_MASK_BY_ID`) — reliable, no name+city text-search
  ambiguity (which also mis-matched venues). Ships with an **empty** `michelin-meta.json` (`{}`) →
  text-search fallback is unchanged until the operator runs the refresh in a Places-keyed env, so
  no behaviour change by default; the cache restore is the immediate speedup.
