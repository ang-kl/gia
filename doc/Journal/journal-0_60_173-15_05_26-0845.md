## New

### [HDR] #140 | 08:45:00 SGT 15-05-26 | v0.60.173 Cuisine API: per-chatId Redis rate limit on 5 hot endpoints (DF-54) + 12 unit tests | 4 files, ~190 LOC net | 1 PR |

- **[INTENT]** v0.60.167's auth chokepoint stops anonymous probes but doesn't bound damage from a compromised legitimate Telegram account. DF-54 caps that risk per-chatId on the hot endpoints (the ones that incur paid-Google-Places spend or are spam vectors).

- **[DELTA]**

  **`rate-limit.js`** (new) — `makeRateLimiter(redis, { endpoint, cap, windowSec=3600 })` middleware factory. Reuses the v0.59.x Tell-Gia precedent (`tell-gia:rl:<chatId>:<hour>` INCR + EXPIRE) generalised:
  ```js
  const bucket = Math.floor(Date.now() / (windowSec * 1000));
  const rlKey = `gia:rl:${endpoint}:${chatId}:${bucket}`;
  const count = await redis.incr(rlKey);
  if (count === 1) await redis.expire(rlKey, windowSec);
  if (count > cap) return res.status(429).json({ error: 'rate_limited', endpoint, retryAfterSec });
  ```
  - chatId source: `req.tg.user.id` from the v0.60.167 chokepoint middleware (always present on `/api/cuisine/*` except in the `SKIP_INIT_DATA_AUTH=true` dev bypass case — limiter fails open there).
  - `SKIP_RATE_LIMIT=true` env bypass (strict-string check on `"true"`, mirrors `SKIP_INIT_DATA_AUTH`).
  - Redis-down → fail open (real spend still bounded by upstream auth gate + per-key budget caps DF-55 + response-cache TTLs).
  - 429 body: `{ error: 'rate_limited', endpoint, retryAfterSec }`. Logs IP + count/cap for abuse spotting.
  - Factory-time arg validation (throws on empty endpoint or non-positive cap).

  **`index.js`** — 1 import + 5 inline middleware wires at the existing route declarations:
  | Endpoint | Cap | Rationale |
  |---|---|---|
  | `/api/cuisine/search` | **60/hr** | 1 search/min avg, bursts of 10 in 5 min fit. Primary money-burner (Places searchText + Place Details + travel-times). |
  | `/api/cuisine/warm-start` | **30/hr** | Should fire once per TMA-open; 30 caps "open the TMA every 2 min" cases — also guards Places spend from runaway-mount bugs. |
  | `/api/cuisine/place-autocomplete` | **200/hr** | Higher cap because user typing fires many calls per location pick (debounced 250 ms client-side). |
  | `/api/cuisine/place-resolve` | **100/hr** | One per pick × bursts. |
  | `/api/cuisine/copy-all` | **30/hr** | Anti-spam (a Telegram message dump per call). |
  Tell-Gia's existing inline rate-limit at `index.js:10155-10174` is **left as-is** — refactoring it to `makeRateLimiter` is a follow-up cleanup (DF-61).

  **`__tests__/rate-limit.test.js`** — 12 new tests: happy-path under cap, 429 at cap+1, per-chatId keying, per-endpoint keying, `SKIP_RATE_LIMIT=true` bypass, strict-string check on the env var, missing `req.tg.user`, missing `req.tg`, Redis-closed fail-open, Redis-throws-mid-call fail-open, factory arg validation, custom `windowSec` honoured for the EXPIRE call.

  **Negative (synthetic abuse)**:

  - Wait for the hour boundary → next call passes (counter reset).

  **Dev bypass**:
  - Railway preview / local with `SKIP_RATE_LIMIT=true` → all caps no-op even when hammered.
