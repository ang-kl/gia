## New

### [HDR] #425 | 09:40 SGT 28-05-28 | v0.61.224 — Cuisine TMA map recenters to detected place anchor | 4 files | 1 PR | 1 build |

- **[INTENT]** When the user types a place name (e.g. `Geylang`, `Tiong Bahru`, `Joo Chiat`) in the Cuisine TMA's free-text box, the map view should visually move to that place at the same moment the search results pin there.

- **[DELTA]**

  **1. `web/cuisine/src/v2/App.jsx`** — single-conditional client fix in the search-response handler:

  ```js
  // v0.61.224
  if (r.placeAnchor && Number.isFinite(r.placeAnchor.lat) && Number.isFinite(r.placeAnchor.lng)) {
    setSearchCenter({ lat: r.placeAnchor.lat, lng: r.placeAnchor.lng });
  } else {
    setSearchCenter({ lat: center.lat, lng: center.lng });
  }
  ```

  Previously the client unconditionally re-anchored to the pre-search `center` (the user's original location). When the server returned a `placeAnchor` (detected via `place-detector` ladder: STB precinct → MRT → hawker → geocoded), the client ignored those coords and the map stayed put.

  **2. `package.json`** — `0.61.223 → 0.61.224`.

  **3. `doc/.serial-state.yml`** — commit 436→437, build 226→227, journal 424→425; re-anchored 28-05 '26 09:40 SGT.

  **4. (this) `doc/Journal/journal-0_61_224-28_05_26-0940.md`** — new.
