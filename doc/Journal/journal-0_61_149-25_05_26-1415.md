## New

### [HDR] #350 | 14:15 SGT 25-05-26 | v0.61.149 — Durian variety alias coverage + halal auto-off in special mode | 4 files | 1 PR | 1 build |

- **[INTENT]**
  1. Make sure the operator's named varieties (Mao Shan Wang, D24,
     Golden Phoenix, Red Prawn, Black Thorn) all surface venues
     whose Google reviews mention them, in BOTH the DURIAN mode
     (fruit sellers) and the DURIAN_PASTRY mode (bakeries selling
     variety-specific pastries).
  2. Auto-turn-off the 🕌 Halal filter when any special mode is
     selected (durian + fruits are mostly NOT halal-certified in
     SG; an active halal toggle would either yield an empty result
     list or contradict the special-mode override).
  3. Keep $ / 🆕 New / 🐾 Pet / 🟢 Open / 🥗 Veg / 🏠 Home toggles
     functional in special mode — the v0.61.126 blanket grey-out
     was too aggressive.

- **[DELTA]**
  - **`special-mode.js`** — `KEYWORDS` updates:
    - `DURIAN`: added `'golden phoenix'` to the English variety
      list. Was implicit via `'jin feng'` (Chinese 金凤 = Golden
      Phoenix). Now English-only reviewers who write *"Golden
      Phoenix"* match too. Chinese keyword `'金凤'` also added for
      symmetry.
    - `DURIAN_PASTRY`: added the full variety set (`'mao shan wang'`,
      `'msw'`, `'d24'`, `'red prawn'`, `'black thorn'`, `'golden
      phoenix'`, `'jin feng'`, plus Chinese `'猫山王'` / `'金凤'` /
      `'红虾'`). Reviews praising a specific variety in a pastry
      context (e.g. *"the Mao Shan Wang durian puff is amazing"*)
      now surface the bakery. Pastry-specific keywords
      (`'durian puff'` / `'durian cake'` / `'durian mochi'` / …)
      remain the primary qualifier; varieties are ADDITIVE signal,
      not the sole anchor.
    - The `NAME_REJECT_PATTERNS[DURIAN]` regex list (v0.61.141,
      rejects pastry-named venues from fruit-mode) is unchanged.
      The fruit-vs-pastry separation enforcement still rides on
      the existing reject patterns.
  - **`web/cuisine/src/v2/components/QuickFilters.jsx`**:
    - Removed the v0.61.126 blanket
      `opacity-40 pointer-events-none` on the whole container
      when `specialModeActive`.
    - Per-chip gating: only the 🕌 Halal chip gets the
      opacity-40 + pointer-events-none wrapper in special mode.
      Other PRIMARY chips (🆕 New, 🐾 Pet) + OVERFLOW chips
      (🟢 Open / 🥗 Veg / 🏠 Home) + the $ / $$ / $$$ price
      chips stay full-opacity + togglable.
    - `toggle(key)` early-returns ONLY when `specialModeActive`
      AND `key === 'halal'` (previously returned for any key).
    - `togglePrice(p)` no longer early-returns under
      `specialModeActive` (prices stay togglable per operator).
    - NEW `useEffect` watching `specialModeActive`: when it flips
      on AND `filters.halal` was true, calls
      `onChange({ ...filters, halal: false })` to auto-clear.
      Single-call (the hook only fires when `specialModeActive`
      transitions, not on every render).
