- **[INTENT]** One mobile screen, six options. SG entries hide
  behind two grouped submenus; Malaysia + Others + Saved Location
  surface at the top level.

- **[DELTA]**

  **Top-level keyboard** (4 rows):

  ```
  🇸🇬 Tourist Areas →                          (single, full width)
  🇸🇬 Regions →                                (single, full width)
  🇲🇾 Johor Bahru        🇲🇾 IOI City Mall
  🌏 Others              🕓 Saved Location
  ```

  Tapping a top-level row routes to:
  - **Tourist Areas →** submenu (the 10 STB precincts in 5 rows
    × 2 + 🔙 Back). Edits the current message in place.
  - **Regions →** submenu (the 5 SG region buckets in 3 rows ×
    2 with the last row single + 🔙 Back). Edits in place.
  - **🇲🇾 Johor Bahru** / **🇲🇾 IOI City Mall** — direct precinct
    pick (no extra tap). Operator preference: button reads "IOI
    City Mall" while the saved anchor label stays "IOI Resort
    City, Putrajaya" so cached references keep the descriptive
    name.
  - **🌏 Others** — reuses the v0.61.195 country picker
    (`buildCountryPickerKeyboard` → `cp:<CODE>`).
  - **🕓 Saved Location** — reuses the v0.61.197
    recent-locations LRU drawer (same data shape as `/lrecent`).

  - **`index.js`** (3 edits):
    1. **NEW `_buildTopLevelKeyboard()`** — emits the 4-row
       inline keyboard above.
    2. **NEW `_buildTouristAreasKeyboard()`** — pulls
       `precincts.getMenuDropdown().filter(p =>
       p.region==='SG' && p.source==='STB')`, renders 5×2 + Back.
    3. **NEW `_buildRegionsKeyboard()`** — same for `source==='region'`.
    4. **`sendLocationQuickPicks` rewritten** — was: 17-button
       grid built from `getMenuDropdown()` + Others row. Now:
       just sends the top-level keyboard. The lists are deferred
       to the submenu helpers.
    5. **`locpick:` callback expanded** with four new branches:
       - `menu_root` → `editMessageReplyMarkup(top-level)`
       - `menu_tourist` → `editMessageReplyMarkup(touristAreas)`
       - `menu_regions` → `editMessageReplyMarkup(regions)`
       - `saved` → renders the LRU as a NEW message (matches
         `/lrecent`'s send-not-edit pattern; user can dismiss
         the drawer without losing the quick-pick).
       Each is non-fatal on failure (catches and ignores
       `editMessageReplyMarkup` errors — most commonly fired
       when the user has already closed/edited the message).

  - **`package.json`** — `0.61.201 → 0.61.202`.
  - **`doc/.serial-state.yml`** — commit 414 → 415, build 204 →
    205, journal 402 → 403; re-anchored 28-05 '26 09:45 SGT.
