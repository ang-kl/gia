# Journal — soleat v0.60.164

> Operator: *"Can I set the location at Pontian or Desaru? Apparently, jump to the central area in Johor as set location."* Investigated, two coupled bugs:
>
> 1. **Search-center override** at `index.js:8336` (`/api/cuisine/warm-start`) + `:9048` (`/api/cuisine/search`): `const searchCenter = isJB ? JB_CBD : { lat, lng };` HARD-CODED JB CBD (`1.4927, 103.7414`) as the search center whenever `region === 'JB'`, completely ignoring the user's picked `lat/lng`. So a Pontian (`1.487, 103.388`) or Desaru (`1.546, 104.272`) pick was overwritten to JB CBD before the discover() call.
> 2. **Post-filter** at `index.js:9661` (now `:9687`): `venues = venues.filter((v) => /johor bahru/i.test(...))` required the literal string `"johor bahru"` in `v.area` or `v.name`. Pontian addresses are *"Pontian, Johor"* → fails. Desaru is *"Kota Tinggi, Johor"* → fails. Kulai is *"Kulai, Johor"* → fails. Even if (1) were fixed, the post-filter would still strip non-JB-CBD Johor results.
>
> Fix: SG-bbox-aware fallback for the search center (JB_CBD only when the supplied lat/lng is inside SG, indicating "user toggled JB without picking yet") + word-boundary `/\bjohor\b/i` on the post-filter (covers the whole state without bleeding to KL/Selangor/Pahang).

- **[DELTA]**

  **`index.js` `/api/cuisine/warm-start` (~line 8334-8339)** — added an SG bounding-box check (1.15 ≤ lat ≤ 1.50, 103.6 ≤ lng ≤ 104.1) right before the existing `JB_CBD` fallback. New logic: `searchCenter = isJB ? (insideSG ? JB_CBD : { lat, lng }) : { lat, lng }`. The JB_CBD fallback now only fires when the supplied lat/lng is inside SG (proof the user toggled JB but their GPS still reports SG → no explicit pick); outside SG (Pontian, Desaru, etc.) → trust the pick.

  **`index.js` `/api/cuisine/search` (~line 9059-9077)** — same SG-bbox-aware fallback at the main search entry. The `searchCenter` flows down into the regular cuisine pipeline AND `handleMichelinSearch` (which receives `searchCenter` as a destructured arg), so the fix propagates to both code paths through one site.

  **`index.js` post-filter (~line 9687)** — was `venues = venues.filter((v) => /johor bahru/i.test(\`${v.area || ''} ${v.name || ''}\`))`. Now: `/\bjohor\b/i`. Word-boundary keeps "Johor Bahru" matching (it contains "Johor") AND covers Pontian / Desaru / Kulai / Mersing / Muar / Batu Pahat / Iskandar Puteri / Kota Tinggi addresses (all read "<District>, Johor, Malaysia"). KL, Selangor, Pahang etc. don't contain "Johor" so the filter still excludes non-Johor MY venues per the original v0.60.152 comment intent ("we don't bleed into KL").
