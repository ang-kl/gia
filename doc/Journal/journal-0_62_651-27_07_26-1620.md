## New

### [HDR] v0.62.651 — the column count stops guessing at devices, and the grid stops throwing away the line order

- **[INTENT]** Operator, with a desktop screenshot of the Train TMA: *"Can you create dynamic awareness for
  desktop and ipad landscape version? i think desktop version can have 4 columns ? here is my problem , as a
  foreigner to singapore i wouldn't know how to read the cards if presented in columns for listing, similarly
  the card, each tap should jump to the station and blink like the cuisine tma. I haven't check the hawker tma
  in desktop mode"*

- **[1 — DYNAMIC COLUMNS]** Device-class buckets cannot answer this. An iPad in landscape (1133 px) and a
  desktop window (1440 px+) are both `isWide`, but only one has room for four readable cards — and **no device
  guess re-flows when a Telegram Desktop window is resized**. Both the Train list and the Hawker drawer list
  now use **viewport-width breakpoints**:

  ```
  grid-cols-2  ·  min-[700px]:grid-cols-3  ·  xl:grid-cols-4
  ```

  **700 px is deliberate, not Tailwind's `md` (768).** The iPad mini is **744 px** wide in portrait, and
  v0.62.650 shipped the operator's explicit request for **three** columns there — a 768 breakpoint would have
  silently broken it back to two. 700 is also `TABLET_MIN_EDGE` in `classify-viewport.js`, so the CSS and the
  JS classifier now agree on where a tablet begins.

- **[2 — THE FOREIGNER PROBLEM, the substantive one]** MRT stations are an **ordered sequence**, and a single
  column encoded that for free: reading down the list *is* travelling along the line. Two, three or four
  columns destroy it — nothing says whether to read across or down, and a visitor has no reason to know that
  EW1 → EW2 → EW3 counts along the track. The grid was silently discarding the one piece of information a
  stranger needs most.

  Fixed **without giving up the columns**:
  1. a **line-order header** above the grid — line badge, full line name, both termini with a direction arrow,
     and the stop count;
  2. an explicit **ordinal on every card** ("3/35") on the name strip.

  Together the order is readable at **any** column count, which is exactly what a width-driven grid requires.
  Rendered only where a sequence exists (the list), so the carousel is untouched.

- **[3 — TAP TO BLINK]** The jump already worked (`setCenter` + zoom 18, v0.62.634) but there was **no blink**,
  so on a busy map — and especially in LIST mode, where the drawer covers the lower half — you could not tell
  which pin the tap had landed on. Cuisine's `flashPin` is ported into `MrtMapPanel` as a `focusedStation`
  effect: a transient expanding ring in the **line's own colour**, ~1.6 s, then removed. It draws no permanent
  marker and never touches the pin layer, so it cannot interfere with `renderPins`' lifecycle. Keyed on the
  station identity, so re-tapping the same card re-flashes.
