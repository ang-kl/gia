# Journal — v0.62.717 (`/log` gets the owner gate it was already assumed to have)

_(№ 1,056 — 11-08 '26 08:50 SGT)_

## New

### [HDR] v0.62.717 — `/log` owner-gated, closing the one un-gated way into verbose mode

- **[INTENT]** Operator: *"Move `/log` to admin menu"* — after this session surfaced, while answering
  "what are the admin commands", that `/log` sat on the `/v` builder hub alongside `/ver`,
  `/oversight` and `/ftlog` but had **no `isOwnerChat` check on the typed command**.

  Read literally, "move to admin menu" would be a no-op: `/log` is *already* on the admin menu (the
  `🔍 Verbose ON/OFF` buttons). The actionable reading — and the one that matches everything else in
  the codebase — is *make it an admin command*, i.e. gate it like its menu neighbours. Three
  independent pieces of pre-existing evidence say owner-only was always the intent and only the
  enforcement was missing:
  1. `/log` is **absent from `setMyCommands`** — it has never been advertised to users.
  2. The `/v` hub's own header comment describes it as firing "the hidden owner commands (/ver,
     /oversight, /ftlog, **/log on|off**)".
  3. The `v:logon` / `v:logoff` callbacks were **already gated** by the `v:` callback family's check
     (`index.js:3293`). Only the typed path was open.

- **[WHAT WAS ACTUALLY EXPOSED]** Not nothing, and not a data leak either — worth stating precisely
  rather than either inflating or waving off. `/log on` sets one Redis key (`verbose:<chatId>`, 24 h
  TTL) that drives three surfaces **for that chat only**:
  - `🔍 step …` NL-pipeline trace messages in the user's own chat (internal pipeline structure and
    stage names);
  - `[VLOG <chatId>] …` Railway server logs for `/api/cuisine/*` + the Michelin handler — timing,
    Redis key TTLs, outbound HTTP cache headers, error stacks;
  - `[VLOG-CLIENT <chatId>] …` Cuisine TMA client telemetry.

  So: no other user's data was reachable, but any user could switch on internal diagnostics for
  themselves and generate server-side log volume on demand. An admin tool by any reasonable reading.

- **[THE FIX]** One guard clause on the `/log` handler, in the exact shape every other owner command
  uses — silent no-op plus a `console.log` naming the denied chat, never a user-visible refusal (a
  hidden command that answers "you're not allowed" stops being hidden):
  ```js
  if (!isOwnerChat(msg.chat.id)) {
    console.log(`[/log] denied chat=${msg.chat.id} (not TELEGRAM_OWNER_CHAT_ID)`);
    return;
  }
  ```

- **[COVERAGE CHECKED, NOT ASSUMED]** Before calling it done, enumerated every route into verbose
  mode rather than trusting that the typed command was the only one: `grep` for `setVerboseMode(`
  returns exactly two call sites (the typed handler, now gated; the `v:` callbacks, already gated),
  and `verbose.enable(` has exactly one caller — `setVerboseMode` itself. There is no HTTP route or
  other back door. `/api/vlog` only *receives* client telemetry; it cannot switch the mode on.

- **[HOISTING CHECKED]** `isOwnerChat` is declared at `index.js:4396`, ~1,500 lines *below* the `/log`
  handler at ~2,866. Safe on two counts, both verified rather than assumed: it is a `function`
  declaration (hoisted to module scope, not a `const` arrow), and the handler body only executes when
  a message arrives, long after module load.

- **[KNOWN GAPS]**
  - **Pre-existing verbose sessions are not revoked.** Any non-owner who ran `/log on` before this
    deploy keeps their `verbose:<chatId>` key until its 24 h TTL lapses, and can no longer turn it off
    themselves (`/log off` is now silent for them). Self-healing within a day, and the blast radius is
    their own chat, so no forced cleanup is proposed — but it is a real 24 h window and worth naming
    rather than discovering. A one-off `SCAN verbose:* → DEL` would clear it immediately if wanted.
  - **`isOwnerChat` returns `true` for everyone when `TELEGRAM_OWNER_CHAT_ID` is unset** (pre-existing,
    by design for local dev). This gate inherits that: if the var is missing in Railway, `/log` — and
    every other admin command — is open to all users. Flagged separately to the operator; **not
    verified from this sandbox**, which has no access to the deployed environment's vars.
  - **Not exercised against a live bot** — no Telegram runtime here. The `[TEST]` block above is the
    first real check.
