# Journal — soleat v0.61.186 (Cuisine TMA visibility-refetch + footer 3-way region)

> Operator after v0.61.185 deploy landed: *"location → tap 🇲🇾 IOI
> Resort City, Putrajaya but results are zero. Because the default
> Cuisine TMA is Singapore. CUisine TMA should flip but didn't, so
> the result is zero."*
>
> Root cause: v0.61.185's auto-flip lived inside a `useEffect(..., [])`
> that runs ONCE on mount. When the operator opened the TMA, set

> component → tryServerCache never ran again → pill stayed on 🇸🇬.

> `claude/v0.61.186-tma-visibility-refetch` off `main` at v0.61.185.

  - **`web/cuisine/src/v2/App.jsx`** (2 edits):
    1. **NEW useEffect** (right after the initial-mount useEffect):
       ```jsx
       useEffect(() => {
         async function refetchAndFlip() {
           if (document.visibilityState !== 'visible') return;
           const r = await fetchUserLocation();
           if (!isValidCoord(r?.lat, r?.lng)) return;
           setUserLoc({ lat: r.lat, lng: r.lng });
           if (r.region === 'JB') setState((s) => ...);
           else if (r.region === 'OTHER' || r.region === 'MY-PUT') ...;
           else if (r.region === 'SG') ...;
         }
         document.addEventListener('visibilitychange', refetchAndFlip);
         w.onEvent('viewportChanged', refetchAndFlip);
         return () => { ... };
       }, []);
       ```
       Listens for BOTH:
       - `document.visibilitychange` — fires when the TMA tab
         becomes visible (browser-level lifecycle).
       - Telegram WebApp's `viewportChanged` — fires when the
         user brings the TMA back to focus from chat (Telegram
         iOS / Android webview).
       Mirrors v0.61.185's mount-time auto-flip logic (same 3-way
       region resolution: SG / JB / OTHER-or-MY-PUT).
    2. **Footer line** — was `JB ? Johor : Singapore` (always-SG
       fallback). Now 3-way ternary: `JB ? Johor : OTHER ? Others
       : Singapore`. Picks up the v0.61.185 i18n key
       `region.others`.
