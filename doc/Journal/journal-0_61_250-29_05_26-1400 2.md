### [HDR] #451 | 14:00 SGT 29-05-29 | v0.61.250 — country → capital auto-pick | 4 files | 1 PR | 1 build |

- **[INTENT]** Both TMAs previously reset the CityDropdown to "— —"
  whenever the user changed the country flag. Operator wants the
  city dropdown to default to the country's **capital** instead,
  unless the GPS-detected city (carried in the anchor) is a city of
  the new country — in which case use that.

- **[DELTA]**

  **1. `web/cuisine/src/v2/components/LocationField.jsx`
     `OtherLocationPicker`** — collapsed the prior two
     `cityPick`-related effects (v0.61.228 reset-on-country-change
     + v0.61.243 anchor-name sync) into one unified effect:

  ```js
  useEffect(() => {
    const list = citiesForCountry(country.code);
    if (!list.length) { setCityPick(''); return; }
    // (a) anchor city is in this country's list → use it.
    const anchorName = (anchor?.name || '').trim();
    if (anchorName) {
      const hit = list.find((c) => c.name === anchorName);
      if (hit) { setCityPick(hit.name); return; }
    }
    // (b) default to first list entry (capital convention).
    setCityPick(list[0].name);
  }, [country.code, anchor?.name]);
  ```

  Capital convention: the first entry of every `CITIES_BY_COUNTRY`
  array IS the country's capital (KUL for MY, JKT for ID, BKK for
  TH, MNL for PH, BWN for BN, PNH for KH, …). This was already the
  case for all 16 countries by curation; this PR just exploits it.

  **2. `web/menu/src/components/LocationFieldMenu.jsx`** —
     mirror of the Cuisine TMA effect. Keyed on `[countryPref,
     currentAnchor?.label]` (the Menu TMA's anchor object exposes
     `label` rather than `name`). Replaces the v0.61.226
     `setCityPick('')` reset.

  **3. `package.json`** — `0.61.249 → 0.61.250`.

  **4. `doc/.serial-state.yml`** — commit 462→463, build 252→253,
     journal 450→451; re-anchored 29-05 '26 14:00 SGT.

- **[KNOWN GAPS]**
  - The "capital" inference relies on the cities.js convention
    that index 0 is the capital. If that ordering ever changes
    (e.g. a future PR sorts alphabetically), this logic silently
    breaks. A comment in cities.js could pin the convention; left
    for a future tidy-up.
  - HK / Sibu and other "GPS detects a city that's NOT in
    cities.js for that country" cases still fall through to
    branch (b) and surface the capital. That's the symptom the
    next PR (cities.js nearest-by-distance sync) addresses —
    when the anchor name doesn't match a cities.js entry, fall
    back to the *nearest* cities.js entry by haversine instead
    of the capital.
