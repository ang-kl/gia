## New

### [HDR] #81 | 02:00:00 SGT 02-05-26 | v0.39.2 | n/a kb | n/a lines
- **[INTENT]** Per Human Lead — diff for `surprise.js` supplied directly. Mirrors v0.39.1's `pipeline.js` lenient-parsing pattern: tolerate ` ```json ``` ` fences and prose-wrapped JSON in the `geminiEnrich` Gemini Flash response. Without this, a stray markdown fence around `{dishes, why_ordered, booking_required}` forced `JSON.parse` to throw, the catch swallowed it as `[Surprise] Gemini enrich failed`, and surprise cards dropped the dishes / why-ordered / booking lines silently.
- **[DESIGN]**
  1. **NEW `extractJsonObject(text)`** helper, scoped local to `surprise.js`. Mirrors v0.39.1's `extractJsonArray` shape but for objects.
  2. Trims input. If a ` ```json … ``` ` fence is present, returns the fenced content; else falls back to slicing between the first `{` and last `}` so prose-wrapped objects parse cleanly.
  3. Guards against `text` not being a string by returning `'{}'` (so the upstream `JSON.parse` never throws on a non-string and the caller's catch block doesn't swallow the diagnostic).
  4. **`geminiEnrich` change**: one line — `const parsed = JSON.parse(extractJsonObject(rawText))` instead of `JSON.parse(result.response.text())`. Same downstream contract.
- **[DELTA]** (per the user's diff)
  - **`surprise.js`** — adds `extractJsonObject` helper near the top; uses it in `geminiEnrich`'s parse call.
  - **`package.json` + `web/cuisine/package.json` + `web/menu/package.json` + `web/hawker/package.json`** — version 0.39.1 → 0.39.2.
- **[VERIFICATION (sandbox)]**
  ```
  git apply --3way /tmp/v0392.patch  →  Applied patch to 'surprise.js' cleanly
  node --check surprise.js  →  OK
  
  Smoke tests:
    extractJsonObject('{"a":1}')                  → '{"a":1}'    (bare object)

    extractJsonObject('hello')                     → 'hello'      (passthrough; upstream JSON.parse throws → enrich falls back to {dishes:[]} via existing catch)
  ```

- **[STATUS]** PROD — auto-deploys with the next Railway build. Behavioural change: `geminiEnrich` no longer drops the dishes/why-ordered/booking fields when Gemini wraps JSON in a fence or prose.
- **[POST-DEPLOY VERIFICATION]**

- **[KNOWN GAPS]**
  - **Object-only — no array fallback.** `geminiEnrich` only ever expects a single object (one venue). If Gemini ever drifts to returning an array, this still throws and the catch swallows. Acceptable: that's a different shape problem and the caller falls back gracefully to empty enrichment.
  - **No top-level-key unwrap** like v0.39.1's `{venues:…}` / `{candidates:…}` / `{results:…}`. Surprise's prompt structure is fixed; if Gemini wraps the object as `{result: {dishes:…}}`, this still fails. Add the unwrap if observed.
