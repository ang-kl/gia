# Journal — soleat v0.61.180 (disable Cuisine TMA 🔍 button on pool exhaustion)

> Closes operator's earlier complaint from the v0.61.174
> conversation: *"I insist on loading at least 5, and when there is
> only less than five, subsequent tap return zero because of the
> five near location."* v0.61.174 surfaced the exhausted state in
> the title copy but kept 🔍 tappable — a tap still fired an API
> call returning zero. v0.61.180 disables the button when the pool
> is genuinely drained.

## New

### [HDR] #381 | 23:45 SGT 27-05-27 | v0.61.180 — Disable 🔍 FAB on pool exhaustion | 3 files | 1 PR | 1 build |

- **[INTENT]** Prevent the "zero-result subsequent tap" UX gap by
  visually + functionally disabling the search button when there
  are no more venues to fetch for the current criteria. Criteria-
  change re-enables (a fresh query has its own pool).

- **[DELTA]**
  - **`web/cuisine/src/v2/App.jsx`** (1 change at the 🔍 FAB JSX,
    around line 1719):
    - Wraps the button JSX in an IIFE that computes:
      ```js
      const poolExhausted = !!finalBatch
        && Number.isFinite(knownTotal)
        && venues && venues.length === knownTotal;
      const isDisabled = loading || (poolExhausted && !dirty);
      ```
    - `disabled={isDisabled}` — button is functionally inert.
    - `opacity-40` when disabled (visual signal).
    - Localized `title` tooltip on hover:
      EN: "No more results — change criteria"
      FR: "Aucun autre résultat — modifiez les critères"
    - Flash ring (`animate-pulse`) is suppressed when disabled —
      don't draw the eye to a non-functional control.
    - `dirty` (criteria changed) override: a new query re-enables
      the button regardless of the prior exhausted state.
