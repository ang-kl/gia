  **3.0 on the newness surfaces** — they floor rated venues at >3.0, overriding the stricter 3.7

- **[DELTA — shared rule]** New **`newness-criteria.js`** — the single source of truth. Exports
  `NEW_STRICT_DAYS=109`, `NEW_FILL_DAYS=183`, `NEW_RATING_FLOOR=3.0`, `recencyBand(days)`
  (`'strict'` ≤109 / `'fill'` 110..183 / `null` >183; `null` days ⇒ `'strict'`, since absence can't
  refute), `passesRating(rating)` (null OR >3.0), `passesNewness({oldestReviewDays,rating})` (band
  ≠ null AND rating OK; **count ignored**), `isStrictNew(...)`. Pure, dependency-free; reuses
  `hidden-verify.oldestReviewDays` for the age math (no new date code).

- **[DELTA — Surface A, New pill]** `index.js` `filters.newlyOpened` block (~15557) — replaced the
  literal `NEW_MAX_DAYS=121` keep-filter with `passesNewness` (183 d ceiling + >3.0 in-block; was
  121 d, no in-block rating bar). Stamps `v._recencyBand` so the cards can group strict vs. fill;
  the `pool-floor.demoteNeverEmpty` never-empty floor is preserved (floor survivors default to
  `'strict'`). The nearest-first concentric sort (~15775) now keys on band FIRST (strict ahead of
  fill, distance the within-band tiebreak) so the 3–6 mo band only surfaces once strict can't fill
  the page — off the New pill `_recencyBand` is undefined → comparator collapses to pure distance
  (unchanged). The downstream global rating floor (~15753) is **capped at 3.0 on the newlyOpened
  path** so the stricter 3.7 default can't re-drop the 3.0–3.7 "new" venues the pill kept;
  non-New searches keep the operator's floor untouched. A clean `recencyBand` field is exposed on
  each response venue (alongside the Michelin/healthier/building annotations) for the TMA.

- **[DELTA — Surface B, /hidden]** `hidden-verify.js` — `lookupVenue` now returns
  `oldestReviewDays` alongside `oldestReviewMonths`. The newness-refute drop (survivors filter)
  is now days-based: drop when `recencyBand(oldestReviewDays) === null` (proven >183 d) **OR** the
  rated venue fails the >3.0 floor — and the old **≥300-review gate is removed** (count is no
  longer a factor; previously an old venue with <300 reviews survived). The de-claim (strip a false
  "newly opened …" line) now fires when `!isStrictNew(...)` (oldest review >109 d), unrated/no-review
  venues keep the claim. `NEW_CLAIM_MAX_REVIEW_MONTHS` / `WELL_KNOWN_REVIEW_FLOOR` marked deprecated
  (retained for reference; `void`-referenced to avoid unused churn).
