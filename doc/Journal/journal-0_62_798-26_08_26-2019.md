### [AMD-44] O-338 — the fabricated dish is removed at source, and it had been outliving the render

- **[INTENT]** Operator, verbatim: *"do o-338"* — the item filed one entry ago from their own

- **[WHY REMOVAL AND NOT A FILTER]** A filter was the tempting fix and it is the weaker one.
  `filterDishNames` — the module whose whole job is rejecting non-dishes — was run over all
  four boilerplate strings and **accepted every one**. Filtering would mean maintaining a
  denylist against text this repo generates itself. Deleting the generator is smaller and
  cannot drift. The measurement is **pinned as a test**, not asserted in prose, so if the
  filter ever gets stricter the next reader sees the premise change rather than a stale claim.

- **[THIS REVERSES HALF AN OPERATOR INSTRUCTION, AND THE CODE SAYS SO]** v0.60.153 asked that
  *"cards never ship empty"*. Some Michelin cards will now show **no `🍲` row at all**. That is
  the correct empty state and it was checked rather than hoped: `ResultCard.jsx` already ends
  that block with `return primaryDish ? (…) : null`, and the chat card already emits `''` for
  an empty list. **An absent row says *we don't know*; the boilerplate said something false.**
  The **review** half is deliberately untouched — *"★★★ Michelin Guide 2025 · curated
  recommendation"* describes where the row came from, which is true — and a test asserts it is
  still there, so scope creep fails the suite.

- **[THE PART THAT CHANGED THE SEVERITY — IT WAS NOT ONLY A RENDER PROBLEM]** `needsNarrate` is
  computed **above** the force-fill, so it correctly saw the real, short dish list. But
  `warmMichelinEnrich`'s cache **WRITE reads `v.dishes` at FIRE time**, and the force-fill
  mutated it before the fire. **On a narrate miss the fabricated names were written to Redis
  for 7 days and read back as real** on later taps — through `filterDishNames`, which as
  measured above lets them through. So the comment on that write, *"the cache stores the REAL
  narrated dishes (not the fast-path boilerplate)"*, was **true only when the narrate
  succeeded**. It is kept and amended rather than rewritten: the gap between what a comment
  claims and what the code does is the part worth seeing, and this is the second such comment
  in two entries (`user-prefs.js` was the first). Removing the boilerplate at source removes
  the poisoning as well — there is nothing fabricated left for the cache to keep.
