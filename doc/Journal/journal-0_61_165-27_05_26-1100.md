- **[INTENT]** Ship the chat surface for the v0.61.164 data layer.
  Three operator workflows the UI must serve:
  1. **Browse** — see all 14 items with their current counts.
  2. **Re-check** — run the recount fn for one item (or all 14)
     and surface the new entry.
  3. **Revert / Clear** — flip the displayed count to a prior
     entry (display-only per operator Q2 (a)) or wipe the
     history for an item.

  Owner-only — same gate as `/ver`, `/oversight`, `/ftlog`.
  No scheduler / cadence config / TMA-side string templates
  yet — those land in v0.61.166.

  - **Tap an item** (e.g. `🍽 Cuisines (70)`): panel shows

  - **⏪ Revert sub-buttons**: up to 4 prior entries appear as
    `⏪ <n>` buttons. Tap one → posts confirmation + re-renders.

  - **🗑 Clear history**: wipes the ZSET, re-renders the panel
    showing "No history yet — tap 🔄 Re-check to seed".
  - **◀ Back**: returns to the top-level grid (edits the same
    message — no new chat clutter).
  - **✕ Close**: deletes the message entirely.
  - **🔄 Re-check all** (from the top-level grid): runs
    `recountAll`, posts a summary message with all 14 results,
    re-renders the grid with updated counts.

- **[KNOWN GAPS]**
  - **No cadence config + cron** — v0.61.166. Today every
    re-count is operator-tap. The data layer + UI together
    are sufficient for ad-hoc audits; the v0.61.166 scheduler
    automates the 4-monthly / yearly cadence the operator
    described.
  - **No TMA-side string template** ("55+ cuisines in SG, JB"
    reading from `getCurrentCount`) — v0.61.166.
  - **Revert sub-buttons cap at 4 prior entries.** The 64-byte
    callback_data limit lets us encode the timestamp comfortably,
    but Telegram chokes on > 8 buttons in a single row. 4 is a
    judgment call between completeness and visual density; the
    older 7 are accessible by tapping Re-check (writes a fresh
    entry that pushes them down a slot).
  - **No undo for Clear history.** Once cleared, the 12-entry
    ZSET is gone. The operator can re-seed via 🔄 Re-check;
    earlier values are not recoverable.
  - **No back-confirmation for destructive actions.** Tapping
    🗑 Clear history acts immediately. Acceptable for an
    owner-only menu; if the operator wants a confirmation
    step, it's a one-line tweak (add a `per:clear-confirm:<id>`
    intermediate state).
