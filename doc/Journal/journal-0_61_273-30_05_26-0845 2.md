## New

### [HDR] #474 | 08:45 SGT 30-05-30 | v0.61.273 — first-paint `'__NONE__'` sentinel | 4 files | 1 PR | 1 build |

- **[INTENT]** Replace the cuisine TMA's hardcoded first-paint defaults (`state.region = 'SG'`, `state.countryPref = 'MY'`) with a `'__NONE__'` sentinel that the existing GPS auto-detect / cache-restore / hash-anchor paths promote to a real region. Pre-v0.61.273 a user in Bangkok briefly saw SG-biased pills / search results until GPS landed; now no region is highlighted until the session has an authoritative anchor.

- **[DELTA]**

  **1. `web/cuisine/src/v2/lib/state.js`** — defaults flipped

  - `region: 'SG'` → `region: '__NONE__'`
  - `countryPref: 'MY'` → `countryPref: null`
  - `writeToHash` previously skipped the hash entry when `region === 'SG'` (canonical-URL hygiene); now skips when `region === '__NONE__'`. Explicit SG picks DO get written to the hash so a refresh preserves them.

  The pill row (`App.jsx:1626`) already used `(state.region || 'SG') === r.id` for the highlight check. With the sentinel `'__NONE__'` being truthy (not falsy), the `||` doesn't apply and the comparison evaluates to `false` for all three pills — NONE highlighted at first paint. Exactly the desired UX.

  **2. `web/cuisine/src/v2/App.jsx`** — three call sites

  - `runSearch`'s `searchCuisine` body now sends `region: undefined` when `snap.region === '__NONE__'`, instead of `region: snap.region || 'SG'`. Server resolves below.
  - `handleNLSubmit`'s `nlQuery` mirror.
  - `onLocationSelect`'s `saveUserLocation` skips the `region` field when state.region is still the sentinel (so a pick during the resolve window doesn't persist `'__NONE__'` to Redis).

  **3. `index.js`** — two route changes (cuisine-search + warm-start)

  Both routes previously destructured `region = 'SG'` from the body. Replaced with:

  ```js
  const regionIn = req.body?.region;
  let region = (typeof regionIn === 'string'
                 && regionIn !== '__NONE__'
                 && /^(SG|JB|OTHER|MY-PUT)$/.test(regionIn))
    ? regionIn : null;
  // ... after csChatId / wsChatId is set ...
  if (!region) {
    // (a) Redis-cached region from /api/cuisine/set-location or /api/menu/set-location.
    // (b) coarseGate against request coords — SG inside the SG bbox, OTHER elsewhere.
    // (c) last-resort SG only if location-mode crashes.
  }
  ```

  The resolution log line is structured so prod-log analysis can compute "what fraction of requests landed without a region tag" + "what the coarseGate fallback ratio is".

  JB inference is intentionally NOT in the fallback — SG and JB share a bbox-adjacent coord space so coords-only can't distinguish them. JB requires an explicit pill pick or a cached anchor with region='JB'.

  **4. `package.json`** — `0.61.272 → 0.61.273`.

  **5. `doc/.serial-state.yml`** — commit 485→486, build 275→276, journal 473→474; reconciled with operator's parallel `technical-0_61_271-…-0830` web-app migration plan (technical counter held at 51). Re-anchored 30-05 '26 08:45 SGT.
