# Journal — soleat v0.62.22 (progressive-results Stage 2: NDJSON base→patch→done streaming, opt-in)

> Approved plan, Stage 2 of 3. Building on Stage 1's `enrichFast`/`enrichSlow` split, the slash
> route `POST /api/cuisine/search` now STREAMS its result as NDJSON when the client opts in
> (`body.stream === true`): a **base** event with the fast-only venue cards is flushed the moment
> `enrichFast` finishes (before the slow network/LLM phase), then one **patch** per venue carries
> the slow fields as they land, then a **done** event with all non-venue payload metadata. The TMA
> paints verified cards immediately and merges patches per-card. **No flag → byte-identical to
> Stage 1** (plain `res.json`). `base ⊕ patches ⊕ done` reassembles to the exact non-streamed
> payload (proven by a round-trip test + the live reader's buffered-fallback path).

> Commit 688 / journal 671 / build 422 (web/ changed). PATCH 0.62.21 → 0.62.22.

- **[INTENT]** Operator: show real places early. Stage 2 delivers the actual latency win — base
  cards on screen before the slow enrichment finishes — over the Stage-1 seam.

- **[DELTA]**
  - **`cuisine-stream.js`** — added the server base/patch split helpers: `snapshotVenue` (shallow
    clone of the fast venue state), `diffVenue(snapshot, final)` → only the fields the slow phase
    added/changed (deletes surfaced as explicit `null`), `applyPatchFields` (merge incl.
    null-delete), `assembleFinal(base, patches, done)` (reassembly for the buffered fallback +
    tests). The v0.62.20 NDJSON foundation (encode/base/patch/done + decoder + mergePatch) is now
    wired for real.
  - **`index.js`** (slash route) — `wantsStream = req.body?.stream === true`. After `enrichFast`:
    snapshot each venue, set `application/x-ndjson` + no-buffering headers, `res.write` the base
    event, flush. Run `enrichSlow` + annotations + payload build UNCHANGED. At the end (after the
    name-enrichers, so `nameLocal`/`nameReading` ride the patches too): emit one patch per venue
    from `diffVenue`, then a done event carrying every non-venue payload field, `res.end()`.
    Flushing base also defuses the 20s→502 risk — once headers are sent the deadline's degraded-200
    path is skipped (it guards on `res.headersSent`). Non-stream path: original `res.json`.
  - **`web/cuisine/src/v2/lib/ndjson.js`** (new) — ESM mirror of the pure decoder + merge helpers
    (the Vite bundle can't `require` the CJS root module).
  - **`web/cuisine/src/v2/lib/api.js`** — `postJsonStream` reads the NDJSON body via a streaming
    reader, paints base, merges patches, resolves with the full final payload. Degrades safely: a
    plain-JSON response (30s cache hit / rollback / old server) or a buffered single-blob body both
    reassemble to the identical payload. `searchCuisine` gains an optional 2nd arg
    `{ onBase, onPatch }` that opts into the stream; omitting it keeps single-shot JSON.
  - **`web/cuisine/src/v2/App.jsx`** — user-initiated searches pass `onBase` (paint venues +
    clear the first-load spinner) / `onPatch` (re-set venues). BOOT load keeps the single-shot path
    so the v0.61.409 boot-mismatch discard never flashes a half-painted list. The awaited `r` is
    still the full final payload → all post-processing unchanged.
