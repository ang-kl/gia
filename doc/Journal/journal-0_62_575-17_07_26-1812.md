### [HDR] v0.62.575 — Cuisine: folio pickers float OVER the map (fixed overlay), stop pushing it down

- **[INTENT]** Operator (IMG_0740/0741, on v0.62.573 — tested **before** the v0.62.574 remount-key
  landed): *"Still same problem and now worst, **you push down the map, why?** Is the location, tabs
  to be tested for layering challenges. Do you need to check other people how they do it. And why
  phone can be done?"* — the tabs/location/picker must be a **layer in front of the map**, and the
  map must **never be pushed down**.

- **[DELTA]**
  - **DIAGNOSIS.** The v0.62.254 design deliberately renders the two folio pickers (Cuisine & filters
    / Pick local classic) as **in-flow** folder panels that **un-fill the map and push it down**,
    leaving a black band beside the `max-w-md` left-aligned panel — that is the "push down the map"
    in IMG_0740.
  - **FIX (how other apps do it — float the UI over the map; the Hawker top-bar-over-map pattern) —
    `web/cuisine/src/v2/App.jsx`:**
    - Both folio pickers are now **FIXED overlays** at `top: headerBottom` (right under the folio
      tabs), floating **over** the map. The `.folder-drawer` surface is a **solid white** panel
      (`background:#fff !important`, **no** `backdrop-filter`) → no WebKit compositing blackout on the
      iPad fullscreen webview. The element is sized to its own box, so the map stays tappable
      everywhere outside it. Left-aligned via `pickerWidthCls` (`max-w-md`, no `mx-auto`).
    - `fill` simplified to `drawerMode === 'horizontal'` (dropped the `cuisinePickOpen/classicOpen`
      term) so the map **never un-fills on picker-open on any device** — and this matches the
      remount-key `cuisine-map-${drawerMode}` exactly (no picker-triggered fill toggle → no in-place
      resize → no remount flash). **Phone + tablet now share one code path** (answers *"why phone can
      be done?"*).
    - The portrait framed map **stays sticky while a picker is open** (removed the `!cuisinePickOpen &&
      !classicOpen` gate from the sticky wrapper) so it holds its place under the floating picker.
  - **NOTE — the orientation "map is gone" (IMG_0741)** should already be fixed by **v0.62.574**'s
    remount-key (the operator tested v0.62.573, one build behind). Asked to **retest rotation on the
    new build**.

## Amendments

### v0.62.576 — Codex P2 (same PR #1586): anchor the fixed pickers to the app container

- **[INTENT]** Codex automated review on PR #1586 (P2, commit `be99e98`): the v0.62.575 fixed pickers
  used **viewport** gutters (`left-8`), but the root is `max-w-[1600px] mx-auto px-3 md:px-6 lg:px-8`
  — so on a viewport **wider than 1600px** (desktop Telegram) the picker opened far **left** of its
  centred tab (disconnected overlay). The iPad never hits it (≤1366px); desktop does. Valid.
- **[DELTA]** `web/cuisine/src/v2/App.jsx` — each fixed picker is now wrapped in a **container-aligned
  layer** that mirrors the root exactly (`fixed left-0 right-0 max-w-[1600px] mx-auto px-3 md:px-6
  lg:px-8 pointer-events-none`), with the solid `.folder-drawer` panel inside (`pointer-events-auto`).
  The panel's left edge now equals the tab's left edge on **every** width; the map stays tappable in
  the transparent gaps.
- **[VERIFICATION]** Cuisine `vite build` green; `npm test` **3719/3719**; `package.json` 0.62.575 →
  0.62.576; `.serial-state.yml` commit 1052→1053, build 675→676 (journal counter unchanged — this is
  an amendment to this same #921 entry, one PR).
