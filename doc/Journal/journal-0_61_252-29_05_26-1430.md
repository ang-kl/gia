## New

### [HDR] #453 | 14:30 SGT 29-05-29 | v0.61.252 — Putrajaya / curated cities.js name | 4 files | 1 PR | 1 build |

- **[INTENT]** Both TMAs' GPS auto-detect (v0.61.243 Cuisine,
  v0.61.249 Menu) set the anchor label to the IATA canonical name
  (`IATA_CITIES[].name`). That worked for cities the IATA table
  names alone (KL → "Kuala Lumpur", TYO → "Tokyo"), but the IATA
  table treats KL metro as **one entry** — KUL at (3.14, 101.69) —
  while curated `cities.js[MY]` has SEPARATE entries for KL,
  Putrajaya, Shah Alam, Seremban, Malacca, Kangar etc.

  When the operator's GPS lands at Putrajaya (2.93, 101.70 — only
  22 km from KUL coords), `nearestIataCity` returns KUL → label
  became "Kuala Lumpur" — even though the curated cities.js
  Putrajaya entry already exists with the operator's intended name.

- **[DELTA]**

  In both TMAs' auto-detect, BEFORE falling back to the IATA
  canonical name, scan `cities.js[detected.countryCode]` for the
  entry NEAREST to the GPS by haversine. If it's within **30 km**,
  use that name. Otherwise fall through to the IATA canonical
  (the v0.61.243 / v0.61.249 behaviour).

  Threshold matches the v0.61.243 cached-anchor drift rule.

  **1. `web/cuisine/src/v2/App.jsx` autoDetect** — added scan +
     comment; imports `CITIES_BY_COUNTRY` from `./lib/cities.js`.

  **2. `web/menu/src/App.jsx` runAutoDetect** — same scan;
     imports `CITIES_BY_COUNTRY` from `./cities.js`.

  **3. `package.json`** — `0.61.251 → 0.61.252`.

  **4. `doc/.serial-state.yml`** — commit 464→465, build 254→255,
     journal 452→453; re-anchored 29-05 '26 14:30 SGT.
