## New

### [HDR] #205 | 13:00:00 SGT 17-05-26 | v0.62.0 — Healthier Choice + inside-a-building rows on eatery results | 11 files | PR B of 3 | 1 build |

- **[INTENT]** Eatery results should surface two new context signals: whether a venue is on
  HPB's Healthier Dining list, and whether it sits inside a sizeable building (so a result
  inside a mall reads as such, not as a lone restaurant). Both rows appear after the Michelin
  row (or standalone when there is no Michelin row).

- **[DELTA]**
  - **`scripts/build-geo-overlays.js`** — two datasets added to the converter:
    `data/healthier-eateries.json` (1,829 HPB partners from `geoloc/HealthierEateries.geojson`,
    `{name,lat,lng}`) and `data/buildings.json` (1,302 large building footprints ≥ 2,000 m²
    from `geoloc/AmendmenttoMP2014Building.geojson`, simplified rings + `sqm`). Neither is
    served by `/api/geo/overlays` — they are server-side matching datasets.
  - **`healthier-eateries.js`** (new) — mirrors `michelin-2025.js`. `isHealthierChoice(venue)`
    matches on a normalized-name token overlap **AND** ~150 m proximity (proximity guards the
    many same-named chain outlets); `annotateVenueObject` sets `venue.healthierChoice`;
    `appendHealthierChoiceLine` pushes the `🥗 Healthier Choice` chat row.
  - **`buildings.js`** (new) — loads `data/buildings.json`, bbox-prefiltered ray-casting
    point-in-polygon; `buildingAt(lat,lng)`, `annotateVenueObject` (sets `venue.insideBuilding`),
    `appendBuildingLine` (`🏢 Inside a building complex`).
  - **`venue-templates.js`** `formatVenueBlock()` + **`index.js`** `formatTechniqueVenueBlock()`
    — append the Healthier Choice + building rows right after the Michelin annotation.
  - **`index.js`** — the `/api/cuisine/search` post-loop now annotates each venue with
    `healthierChoice` + `insideBuilding` alongside the existing Michelin annotation, so the
    React TMA card and map InfoWindow render from the payload.
  - **`web/cuisine/src/v2/components/ResultCard.jsx`** — `🥗 Healthier Choice` + `🏢 Inside a
    building complex` rows after the Michelin row.
  - **`web/cuisine/src/v2/components/MapPanel.jsx`** — the two rows added to the map InfoWindow.
  - **`web/cuisine/src/v2/lib/i18n.js`** — `card.healthierChoice` / `card.insideBuilding` (EN/FR).
  - **`__tests__/eatery-annotations.test.js`** (new) — 7 cases over the matchers.
  - **`package.json`** — `0.61.0 → 0.62.0` (MINOR — new feature).
  - **Blank/white map pins** — investigated per the operator's report. The white-background
    glyph pins were a v0.60.224 experiment already reverted in v0.60.234 (merged in PR #485);
    on current `main` `cuisinePinNode()` always sets a green background and `hawkerPinNode()`
    navy/red — there is no blank-pin code path. No code change; the operator's screenshot
    predates the v0.60.234 revert.

- **[STATUS]** STAGED → PROD on the next Railway deploy after PR B merges. The data files ship
  in `data/`; the Cuisine TMA bundle ships in `public/cuisine/`.

- **[TEST]** Post-deploy: a known HPB partner eatery shows the `🥗 Healthier Choice` row in
  chat results, the `/s` flow, the TMA result card and the map InfoWindow; a venue inside a
  large building shows the `🏢` row; a non-partner standalone venue shows neither.

- **[KNOWN GAPS]**
  - `geoloc/AmendmenttoMP2014Building.geojson` is the "Amendment to MP2014" subset, not the
    full building stock, so `insideBuilding` is a positive-only hint — a missing flag does not
    prove a venue is standalone. The building name itself comes from the address Google Places
    already supplies (shown on the existing `📇` address line); the GeoJSON has no names.
  - PR C (expandable maps, overlay layers on the Transport TMA, live carpark) is still due.
