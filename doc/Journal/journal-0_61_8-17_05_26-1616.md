## New

### [HDR] #211 | 16:16:00 SGT 17-05-26 | v0.61.8 — OpenStreetMap / Overpass MRT-line-geometry fetcher | 3 files | follow-up PR | 0 builds |

- **[INTENT]** Give the project a keyless, complete source of real MRT/LRT track geometry.
  v0.61.7's redraw smooths the station-to-station fallback but does not trace the actual track;
  `data/mrt-line-paths.json` (which `resolveLinePaths()` already prefers) needs a real,
  line-attributed dataset, and OpenStreetMap is exactly that — and open (ODbL).

- **[DELTA]**
  - **`scripts/fetch-mrt-lines-osm.js`** (new) — queries the Overpass API for Singapore
    `route=subway` + `route=light_rail` relations, resolves each relation's member ways into
    coordinate polylines, maps the OSM line name → the app's line codes (NSL/EWL/CGL/NEL/CCL/
    DTL/TEL/BPL/SLRT/PLRT/JRL/CRL), and writes `data/mrt-line-paths.json` in the exact shape
    the app consumes (`{ _meta, <CODE>: Array<Array<{lat,lng}>> }`). Platform/stop way members
    are skipped; both route directions collapse onto one code. The `_meta` carries the required
    `© OpenStreetMap contributors (ODbL)` attribution.
  - **`package.json`** — `"fetch:mrt-osm"` npm script; version `0.61.7 → 0.61.8` (PATCH — adds
    a build-time script, no runtime behaviour change).

- **[VERIFICATION (sandbox)]**

  ```bash
  $ node --check scripts/fetch-mrt-lines-osm.js   → OK
  $ npm test -- --run                              → 1924 passed (1924)
  ```

  The fetch itself cannot run in this sandbox (overpass-api.de is outside the network
  allowlist) — the script is intended to be run on a dev machine or a Railway job.

- **[STATUS]** STAGED. The script ships in `scripts/`. To activate real geometry the operator
  runs `npm run fetch:mrt-osm` where overpass-api.de is reachable and commits the generated
  `data/mrt-line-paths.json`; `/api/transport/line-paths` + `resolveLinePaths()` then serve the
  real OSM geometry and the v0.61.7 Chaikin fallback becomes a pure backup.

- **[TEST]** On a networked machine: `npm run fetch:mrt-osm` → `data/mrt-line-paths.json` with
  ~12 lines and a sane segment count; commit it; the Transport map then draws lines that follow
  the real track.

- **[KNOWN GAPS]**
  - **Attribution still due:** when the OSM geometry is in use, the map UI must show an
    "© OpenStreetMap contributors" credit (the `_meta.attribution` field records the
    requirement; surfacing it on the Transport / Train-overlay maps is a small follow-up).
  - The data.gov.sg fetcher (`scripts/fetch-mrt-lines.js`) remains as an alternative keyless
    source.
