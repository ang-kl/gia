- **[INTENT]** Two unrelated items folded into one PR per operator request:
  1. Fix the Clipboard TMA's launch button on the cuisine TMA panel — it was forming
     a deep link with the wrong bot username (`gia4lunch_bot` instead of the actual
     `soleat`), so even with the BotFather short-name registered, the URL would 404.
  2. Move PR #1289's v0.70 forward-roadmap doc onto main, but trim the "Locked UI
     decisions for the Clipboard cycle" section because that work shipped in #1303
     and is no longer "upcoming."

- **[DELTA]**

  - **`index.js`** — new helper `serveTmaHtmlWithBotIdentity(res, tmaDir)` reads
    `public/<tmaDir>/index.html`, injects
    `<script>window.__BOT_USERNAME__=${JSON.stringify(botUsername || '')}</script>`
    before `</head>`, sends. Both `/app/cuisine` and `/app/clipboard` handlers now
    use it (instead of plain `sendFile`). Fallback chain on any FS failure: plain
    `sendFile` so a broken inject can't take a TMA offline. The mount call site
    for `mountClipboardRoutes` was updated to pass a lazy bot-username getter
    `() => botUsername` so the share-URL mint endpoint resolves the username at
    call time (when `getMe()` has long since cached the answer).

  - **`clipboard-routes.js`** — `mountClipboardRoutes(app, redis, getBotUsername)`
    accepts an optional third arg; the share-URL mint at
    `POST /cabinet/:id/drawer/:n/share` reads `getBotUsername() || process.env.BOT_USERNAME
    || 'gia_bot'` instead of the old hardcoded `process.env.TELEGRAM_BOT_USERNAME
    || 'gia4lunch_bot'`. New fallback chain matches index.js's own default.

  - **`web/cuisine/src/v2/App.jsx`** — the bordered Sketchbook / Clipboard panel
    button's fallback also changes from `gia4lunch_bot` → `gia_bot` (matches
    index.js's default). The primary path reads `window.__BOT_USERNAME__` which
    is now injected by the server, so on prod the URL builds with the real
    `soleat` username.

  - **`doc/v0.70_.MD`** — pulled from PR #1289's branch via
