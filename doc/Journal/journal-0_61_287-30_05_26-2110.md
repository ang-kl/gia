- **[DELTA]**

  **1. `doc/Register/register-0_61_276-30_05_26-1230.md`** — appended Open item O-37: iCloud-stale-checkout silently writes empty blobs. Documents:
  - Discovery in v0.61.278 (`smart-place-label.js` on origin/main was the empty-blob hash `e69de29b…` despite the working tree having 164 lines).
  - Re-confirmation in v0.61.283 (`scripts/durian-variance.js` dropped `placeId` for 8 patches because the Places-API mapper kept reading 0 bytes from iCloud-evicted files).
  - Root cause: macOS iCloud eviction returns 0-byte reads to Node / Git while file metadata still shows the original size.
  - Known mitigations: the plumb-commit pattern (`git hash-object → update-index → commit-tree`) which hashes content directly without re-reading via `git add`.
  - Outstanding risk: any future bulk script doing `JSON.parse(readFileSync(...))` (variance jobs, venue-template generators) can silently emit empty payloads on the next eviction.
  - Possible fixes: (a) pre-commit CI check on `*.js` file size; (b) `cat`-warm helper in bulk scripts; (c) move the project off iCloud Drive entirely.
  - Marked `medium` priority since it has already burned two patches' worth of production behaviour (v0.61.275–282 Plan B cache silent no-op, v0.61.265 onwards `smart-place-label.js` empty in prod).
