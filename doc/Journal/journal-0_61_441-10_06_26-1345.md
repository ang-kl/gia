- **[INVESTIGATION — Phase 0 gate audit, read-only]** Traced `/api/cuisine/search` (`index.js:14234 → 16200`) end to end: **18 pool-shrinking gates** between fetch and card. Verdict — over-gated, with **3 duplications + 1 ordering bug**:
  - **D1** — geographic scoping done **5×** for one intent (Places `locationBias` radius + 120 km gate + JB ≤60 km + SG ≤30 km + OTHER country-keywords).
  - **D2** — **6** independent ad-hoc anti-collapse "floors" (JB-restore, OTHER stale-pref, newlyOpened floor-to-bias, applyRatingFloor never-empty, special-mode generic fallback, removed petFriendly `<3`). No shared "demote, never empty" rule.
  - **D3** — cuisine relevance verified **3×** (name-validation gate, Gemini cache+online, special `filterByMode`).
  - **Ordering bug (= the "1 result" root)** — the ring ladder (`widenAndPick`, then at `index.js:15705`) ran **before** `applyRatingFloor` (≥3.7) + the seen/sessionSeen dedup, so a tier that "satisfied" with ≥3 rated>4 venues got gutted to 1.
  - **The 500s** — the route's single terminal `catch` (`16271`) turned **any** throw into a 500; every external await is already guarded, so these were **transient** blips (network reset / upstream 5xx / redis).
  - Operator picked scope **P1+P2+P3** (defer the geo-merge P4 + the 3-way relevance unify P5), "convert the easy floors," Gemini gate stays (routed through the floor).
