- **[INTENT]** When the set city has no curated Michelin (Fukuoka, also Yokohama/Sapporo/Hiroshima —
  pickable, uncurated), the Michelin search falls back to the national list. Operator wants that
  fallback to LEAD with the top distinctions (3★ first) so the zoomed-out batch shows the best
  awardees, still grouped by city with the per-city jump rows + the map fit-bounds across the 12
  pins.

- **[DELTA]**
  - **`michelin-data.js`** — new exported `distinctionRank(category)`: `three-star` 0 → `two-star`
    1 → `one-star` 2 → `bib-gourmand` 3 → unrecognised 9 (case/space tolerant).
  - **`index.js`** Michelin handler (~9375) — when **no set-city match** (`!michSelectedCity`) AND
    non-SG, stable-sort `ordered` by `distinctionRank(e.category)` so the national batch is
    3★→2★→1★→Bib (ties keep curated order). A *matched* city keeps its existing tier/city order; SG
    (single city) is untouched. `e.category` is the latest-year award (`latestMichCat`, already on
    every non-SG entry).
  - The TMA needs NO change: `michCityName` is set only when a city matches (`index.js:10135`), so
    Fukuoka → `michelinCity = null` → the v0.62.6 grouping renders **Case B** (per-city
    "{count}/{total} Michelin picks in {city}" rows, v0.62.12) and the v0.62.6 `fitPins` Case-B path
    fit-bounds the 12 pins. The new sort just changes WHICH 12 (top distinctions) and their order.
