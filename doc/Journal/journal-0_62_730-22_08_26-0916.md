### [HDR] The six languages went live — and what only a human reader could catch

- **[INTENT]** Operator: *"can we move to the translation"*, then, given the choice,
  *"Repair the 126 first, then apply all"*, then *"drop 1, do 2, drop 3"* (drop the

  *"delete them"* (O-197).

- **[STATE BEFORE]** 1,590 machine translations sitting in job files since 19-08, **0
  audited**, and `i18n.js` carrying **3 of 276 keys** per language. Nothing user-visible in
  any of id/ru/de/zh/ja/es despite the data existing for three days.

- **[WHAT SHIPPED]** **1,512 strings applied** across six languages. The remaining ones fall
  back to English per key, which is the behaviour every key had before.

- **[THE ARC IN NUMBERS, EACH STEP MEASURED]**

  | Step | Safe | Failing |

  | As filled by Cloud Translation | 1,458 | 132 |

  The count went **down** at the end, and that is the honest direction: each tightening
  found strings that had already shipped broken.

- **[THREE TRANSLATION RUNS, AND THE FIRST TWO FAILING IS THE POINT]** Cloud Translation's
  `format=html` cannot be made to preserve this markup. Established by running it, not by
  reasoning:

  - **Masking tags individually** — the v0.62.718 approach that produced the original
    1,590 — let the model **drop every closing tag**. 26/77 fixed, all of them items whose
    only fault was flattened newlines.
  - **Masking a whole `<code>…</code>` as one atomic protected span** still returned
    `<span translate="no"><code>/location</span>`. The closer was removed from *inside the
    protection meant to prevent exactly that*. **0/51.**
  - **Slot substitution** — replace every non-translatable run with an opaque token,
    translate bare prose, substitute the original back verbatim. **42/51.** Nothing the
    model returns can corrupt markup it never saw.

  Spacing is restored from the **source's** adjacency rather than guessed, which is what
  keeps `<b>{label}</b>.` from becoming `<b>{label}</b> .`.

- **[TWO BUGS FOUND ONLY BY READING ACTUAL OUTPUT]** A placeholder was being masked **inside
  an HTML attribute** — `<a href="<span translate="no">{gmapsUrl} ">` — invalid nesting that
  `unmask()` could not undo, so the mask leaked into shipped strings. And `&lt;place&gt;`
  was being decoded and translated into `<Ort>`, an unknown tag that makes Telegram reject
  the **whole message**. Neither was visible in a summary; both were obvious in one dump of
  a single item.

- **[THE VALIDATOR MISSED ITS OWN SUBJECT, THREE TIMES]** Each widening came after something
  had already shipped:
  - It checked only `<b>` and `<i>` — missing `<code>` and the `<Ort>` case above.
  - It used `{2,15}` for commands, so **`/l` was never examined**. Six `wake2.anotherHint`
    strings shipped as `Ketik /l<place>` and passed cleanly.
  - Its delimiter rule treated any ASCII punctuation as a boundary, so `/l<place>` passed on
    the `<`. What matters is that the source wrote `/l <place>` and the translation lost the
    space.

- **[THE GATE COULD ONLY ADD — D-204]** Three tightenings had let strings through and nothing
  could withdraw them. **Pruning added: 27 entries removed.** Two regex attempts at surgical
  removal produced a file that would not parse — one orphaned the leading comma, one ate the
  separator the next entry needed. Comma bookkeeping inside a hand-rolled splice is the wrong
  tool; the entry's language map is now parsed and the block re-emitted with separators
  generated fresh. **A quality gate that can only admit is not a gate.**

- **[P4 — THE FINDING NO STRUCTURAL CHECK COULD EVER MAKE]** Codex, reading Russian, found
  `hours.opensTodayAt` shipping as **`Премьера сегодня в {time}`** — *premiere* today, not
  *opens* today. Same in `opensTomorrowAt`. The string is **perfectly well-formed**: balanced
  markup, correct placeholder, sensible length. Every check in this repo passes it.

  This is precisely what the dropped audit existed to catch, and it is the honest measure of
  what was traded away. Corrected to `Откроется` — a reviewer's suggestion, **not verified by
  a Russian speaker**, and neither are the other ~250 Russian strings, or any of the other
  five languages.

- **[O-197 CLOSED]** `/api/i18n-translate` and `/api/i18n-audit` deleted — 129 lines. Their
  own comments called them scaffolding. Deleted rather than disabled: both spent money per
  call, and a dormant paid route behind a token gate is a standing liability once nothing
  needs it.

- **[A NUMBER CORRECTED, AGAIN]** Seven proposed keys do not exist in `i18n.js`, so their 42
  translations cannot be applied — yet they were counted among the passing. The operator was
  told **1,581**; the applied figure is **1,512**. `bot.ratelimit` is the live example:
  `botRateLimited()` is still hard-coded to English/French.

- **[VERIFICATION (sandbox)]** `node --check` clean on `index.js` and `i18n.js`.
  `npx vitest run` — **173 files / 4,208 tests, 0 failures**. `grep "/l<" i18n.js` → 0. The
  Cloud Translation key was passed per-invocation, never written to a file; the diff was
  scanned for its prefix before each push (0 hits).

- **[STATUS]** DRAFT on PR #1725. v0.62.729 reached `main` only partially — #1724 merged
  before the slot work landed, which is the fourth merge in this session to close before its
  own follow-up.

- **[KNOWN GAPS]**
  - **36 items remain on English.** Most are ja/zh where the command butts against the next
    character — Japanese and Chinese do not space between words, so the translator attaches
    the particle and the command dies. That is a property of the language, not a bug to
    engineer around.
  - **Nothing has read these strings for meaning.** The Russian finding is one instance
    caught by chance; there is no reason to think it is the only one.
  - `i18n-audit.js`, `scripts/audit-i18n-translations.mjs` and `__tests__/i18n-audit.test.js`
    are **orphaned** — no caller since the audit was dropped and the route deleted. Left in
    place: removing them is a separate destructive change (G2).
