# Journal — soleat v0.61.284 (halal-active contrast + tap-to-search hint visibility)

> Operator (30-05 '26 ~18:20 SGT, screenshot of an active Halal chip on a cyan background):
> 1. *"the halal background selected, the text should be contrast. see the picture."* — the v0.61.255 Arabic `حلال` glyph was hardcoded to `text-emerald-600`, which reads fine on the inactive `bg-tg-card` but turns into green-on-cyan when the Chip wrapper flips to `bg-tg-accent` on select.
> 2. *"i thought when i type in the location in cuisine tma like orchard, it wouldn't auto-fire, the message flush right 'tap to search 🔝' will be below the 🔍 until the user click any of the 3 search feature in cuisine tma."* — the v0.61.244 idle-hint speech bubble ("Tap 🔍 to search") was timer-gated: it cleared on every keystroke and only re-appeared after 6 s of typing pause. So the user almost never saw it.
>
> Two coordinated fixes:
>
> 1. **Halal active contrast.** When the chip is active, the Arabic glyph now inherits the Chip's active text colour (`text-tg-accent-text`, white in light mode); when inactive, the resting `text-emerald-600` is preserved.
>
> 2. **Tap-to-search hint shows immediately, persists.** The idle-hint `useEffect` no longer waits 6 s and no longer clears on every keystroke. When the user has typed ≥1 char AND the field is open, the bubble is visible. It clears on pick / clear / submit / blur (the existing `clearIdleHint()` call sites — unchanged).
>
> Mirrored in both `LocationField` (SG/JB) and `OtherLocationPicker`.
>
> Commit 498 / journal 485 / build 287, on branch
> `claude/v0.61.284-halal-contrast-and-tap-to-search-visibility` off `main` at v0.61.283.
