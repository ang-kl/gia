## New

### [HDR] v0.62.579 — Cuisine: a coarse city label ("Brisbane") no longer overrides a committed street pick ("16 Thompson Street")

- **[INTENT]** Operator (IMG_0743 + Railway logs, on deployed v0.62.577): *"why show the city name
  **Brisbane** when actually you have the **address**. Do we have this issues similar to issues of
  location in Singapore set-location and Putrajaya set-location last month?"*

- **[ANSWER — yes, same family.]** Lineage: v0.61.265 `_isCountryOnly` (client display filter — screens
  bare **country** names only) → v0.61.430 explicit-pick-wins latch → v0.62.31 `D787` server **ambient**
  guard. This is the **next uncovered case**: a **coarse city** label overwriting a finer **street**
  label at ~the same spot. The logs show it: "16 Thompson Street" committed at 10:16; on **re-open**
  the client boot device-GPS auto-detect reverse-geocoded the **city "Brisbane"**, and a **non-ambient**
  re-push slipped past `D787` (`[set-location] label="Brisbane"` at 10:45:21). No coarse-over-fine guard
  existed anywhere.

- **[DECISION]** Operator chose (AskUserQuestion) the **safer "client display only"** fix — do **not**
  touch the server cache logic.

- **[DELTA]** `web/cuisine/src/v2/App.jsx` — the **visibility-refetch** (`~L1942`) was the one hole: the
  boot auto-detect already guards with explicit-pick-wins (`~L2063`) and `tryServerCache` re-arms the
  latch (`~L1230`), but the refetch applied the server label unconditionally. Now: when an explicit
  pick is latched (`explicitPickRef`) with a committed name and the refetched label is a **coarse** one
  that **differs** from it, the **pick wins** (`D792` log) — the field no longer reverts to the city.
  Coarse = **no digit, no comma, ≤ 2 words** ("Brisbane", "Singapore", "Kuala Lumpur"); a street pick
  ("16 Thompson Street", "…, Bowen Hills") has a digit/comma so it still applies — the v0.61.266
  Menu-label restore stays intact. Bonus: holding the committed anchor stops `reassertPickAfterSearch`
  from re-pushing the city, so the **server self-heals** to the street on the next search.

- **[VERIFICATION (sandbox)]** Cuisine `vite build` green; full `npm test` **3719/3719 across 145
  files**; `package.json` 0.62.578 → 0.62.579; `.serial-state.yml` commit 1055→1056, build 678→679,
  journal 922→923, re-anchor 19:10 SGT. ⚠️ Live-only: the label-drift flow needs an on-device check
