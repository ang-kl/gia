- **[KNOWN GAPS]**
  - **JB tile #5 has a 15 km radius** to bridge the rural span
    between Pasir Gudang and Bandar Penawar. Coverage may overlap
    JB tile #4 (Pasir Gudang) — but Set-dedup handles overlap
    gracefully. If duplicate API spend bothers the operator, the
    radii can be tightened in a follow-up.
  - **Tile centres are approximate**. They were eyeballed from
    operator's geographic spec, not derived from an admin-region
    overlay. Some Singapore islands (Pulau Tekong, Pulau Bukom)
    may sit on tile edges; venues there are usually 0 anyway
    (military / industrial). If we ever care about Pulau Ubin
    (small island with ~1 makan stall), tile sg-ne is centered
    close enough to catch it.
  - **No retry per tile**. A network blip on tile-N kills that
    tile's contribution. v0.61.179's 60-s debounce gives the
    operator a clean fresh-sweep window. If this becomes a
    practical pain point, a `retries: 1` opt to `_defaultFetch`
    could be added later.
  - **`SATURATING_SLUGS` is hardcoded**. If a future Places
    update changes how a cuisine paginates (or a new niche
    cuisine becomes popular), the operator would edit this Set.
    Auto-detection ("if a single query caps, retry with tiles")
    is doable but adds ~1 round-trip per cuisine to detect; not
    worth the latency today.

## Amendments

- **`_defaultFetch` body** — was hardcoded `regionCode: 'SG'`. Now
  `regionCode: regionCode || 'SG'` + accepts optional
  `locationBias.circle` for tile-search. Old single-query callers
  unaffected (they omit both fields).
- **`countAll` routing** — was "all 48 slugs → countOne". Now:
  "8 saturating slugs → countOneTiled (15 tiles each); 40 others
  → countOne (single query)".
- **`countAll` return payload** — gains a `tiledSlugs` array
  (array of slug names that took the tiled path). Existing fields
  (ts / total / perSlug / capped / errors / pages / elapsedMs)
  unchanged.
