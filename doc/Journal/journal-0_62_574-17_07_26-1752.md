- **[DELTA]**
  - **ROOT CAUSE FOUND — `web/cuisine/src/v2/components/MapPanel.jsx` (read-only diagnosis).** The
    `fill` prop toggles ONE live map container between framed (`height: 68vh`) and full-bleed
    (`absolute inset-0`) **in place** — `mapRef.current` is created once and never rebuilt — so a
    framed↔full-bleed / orientation change is an **in-place Google Maps canvas resize**. That resize
    is what paints the map **black** on the iPad Telegram-**fullscreen** WebKit view. Hawker never
    hits it because `carouselLayout` and `portraitTabletPanel` mount **separate** `HawkerMapPanel`
    instances → the map **remounts**, never resizes. (So the earlier "backdrop-blur over full-bleed"
    hypothesis was a symptom, not the cause — Hawker uses `backdrop-blur-md` over its full-bleed map
    and renders fine.)
  - **FIX (follow hawker codes) — `web/cuisine/src/v2/App.jsx`.** Added a React `key` on `<MapPanel>`:
    `key={isWide ? \`cuisine-map-${drawerMode}\` : 'cuisine-map-phone'}`. On a tablet (`isWide`) the
    key flips with the framed↔full-bleed axis (`drawerMode`, to which `fill` reduces when `isWide`
    short-circuits the `||`), so every transition **REMOUNTS a fresh map** — no in-place resize → no
    blackout — exactly like Hawker's ⇲ expand. Phones keep a **constant** key ('cuisine-map-phone')
    so their picker-open `fill` flip stays a cheap in-place resize (phones are never fullscreen and
    never black out — no remount flash). This also makes the fill/carousel **"tabs-in-front-of-the-
    full-bleed-map"** mode stable and reachable on the tablet — the `<header>` is already
    `sticky top-0 z-30` over the `flex-1` fill map — delivering the essence of #1 **without**
    re-introducing any backdrop-blur-over-full-bleed overlay (the #1579–1582 failure mode).
  - **#2 — `web/cuisine/src/v2/components/LocationField.jsx`.** Tightened the `CountryDropdown` and
    `CityDropdown` option rows from `py-1.5` (6 px) to `py-1` (4 px) + `leading-tight`, so the OTHER
    country/city lists are denser without losing tap-target usability.
