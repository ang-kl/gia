# Journal — soleat v0.62.12 (Michelin city-jump row: bare count → count/total ratio)

> Operator (11-06), re-specifying the city-jump row copy for a mixed-city Michelin batch (e.g. KL
> set, 12 visible = 4 KL + 8 Georgetown): the row must read **"{count}/{total} Michelin picks in
> {city}"** — e.g. *"8/12 Michelin picks in Georgetown"*. This REVERSES the v0.62.6 spec, which
> explicitly forbade the ratio ("never 8/12"). All other behaviour (Case A/B map rule, set-city
> first with no row, tappable blue/italic/underlined city, group order, pagination) already shipped
> in v0.62.6 (#969) and is unchanged. Display-layer only.

> Commit 675 / journal 658 / **build 417 (web/cuisine changed)**. `web/cuisine` i18n + ResultPanel
> + new copy test. PATCH bump 0.62.11 → 0.62.12.

## New

### [HDR] #658 | 06:59 SGT 11-06-26 | v0.62.12 — Michelin city-jump row shows count/total (8/12) | web/cuisine i18n + ResultPanel + test | 1 PR | 1 build |

- **[INTENT]** Operator clarified what the city-jump row should say when the 12-card Michelin batch
  mixes cities: the count/total ratio, not the bare count. count = cards for that city in the
  current visible batch; total = the visible batch size (12). Tap behaviour, map centring (Case A
  stays on the set city; Case B fit-bounds), and group ordering are unchanged.

- **[DELTA]**
  - **`web/cuisine/src/v2/lib/i18n.js`** — `michelin.cityJump.before`:
    EN `"{count} Michelin picks in "` → **`"{count}/{total} Michelin picks in "`**;
    FR `"{count} choix Michelin à "` → **`"{count}/{total} choix Michelin à "`**.
  - **`web/cuisine/src/v2/components/ResultPanel.jsx`** — the jump-row `tn(...)` now passes
    `total: cardsToShow.length` alongside `count: g.venues.length`. The styled tappable `{city}`
    `<span>` and the `onCityJump` map pan are untouched.

- **[REVERSAL — recorded]** v0.62.6's `michelin.cityJump.before` and its journal/PR explicitly said
  the count is "never a ratio (8/12, 8/67, 8 of 67)." The operator has now chosen the count/total
  ratio (total = the 12-card batch, NOT a country/city grand total). The prior bare-count copy is
  superseded; the "never a ratio" guidance no longer applies to this row.

- **[VERIFICATION (sandbox)]** `npm run build:cuisine` green. Full suite **3292/3292** green (+3:
  new `michelin-cityjump-copy.test.js` — EN `8/12 Michelin picks in `, FR `4/12 choix Michelin à `,
  both placeholders substitute). `michelin-city-groups` (grouping/map) unaffected — 15/15 still
  green. No server change.

- **[STATUS]** PR (rides the session branch — the open #974 PR; retitled to cover this). Deploys
  via Railway on merge. Display-layer copy change — operator smoke recommended (TMA render).

- **[TEST — operator, post-deploy]** KL set + Michelin with a KL+Georgetown batch: the row reads
  **"8/12 Michelin picks in *Georgetown*"** (city blue/italic/underlined/tappable); Putrajaya set
  shows **"4/12 …"** + **"8/12 …"** rows. Tapping a city still pans the map only.

- **[KNOWN GAPS]** `total` is the visible batch size (12). On a final/short page (fewer than 12
  visible) the ratio denominator follows the actual visible count, so it could read e.g. "3/7" —
  consistent with "of the cards on screen," not the curated grand total (which the operator
  excluded).
