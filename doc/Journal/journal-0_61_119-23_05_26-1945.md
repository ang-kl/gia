- **[DELTA]**
  - **Attractions cluster radius too large — `web/{cuisine,hawker,transport}/.../mapOverlays.js`.**
    Operator's question — *"is it really 45 here? i think the radius is
    too large"* — answered itself. At z11 a 200 px tile spans
    ~7.6 km × 7.6 km in Singapore (metresPerPixelAt ≈ 38 m/px at
    lat 1.35°), which is large enough to swallow 45+ attractions in
    central SG into one `45 ⚝ here` mega-pill. `applyClusterAndDrop`
    reverts v0.61.118's low-zoom widening — `TILE_PX = 40` at every
    zoom for attractions (same grain as carpark). Individuals dominate
    at typical zoom; clusters only form where ≥7 attractions sit within
    ~1.5 km × 1.5 km. Edited canonical cuisine copy, byte-identical
    copies to hawker + transport.
  - **Transport zoom-hang past z14 — `web/transport/src/components/MrtMapPanel.jsx`.**
    The `idle` listener at `:344` called `setAnchor` on every settled
    zoom step, which re-ran `applyVisibility` (incl. the cluster pass
    over ~150 attraction markers + every other active overlay) — the
    cumulative DOM swaps + collision-checks froze the main thread when
    zooming up through z14+. Debounced to ~180 ms via a ref-held
    `anchorTimerRef`, the same pattern used for the v0.61.112
    `renderPins` debounce. Timer cleared on each new idle and on
    component unmount. Pairs with the cluster-tile fix above (smaller
    tile = less marker churn at the z14 transition).
  - **Zoom-readout `🔭 #` circle background — `web/cuisine/src/v2/components/MapPanel.jsx`, `web/hawker/src/components/HawkerMapPanel.jsx`, `web/transport/src/components/MrtMapPanel.jsx`, `public/app.js`.**
    Wraps the readout in `rounded-full px-2 py-1` with
    `background: rgba(0,0,0,0.1)` (10 % black-transparent). Operator
    said "apply to 5 TMA" — the four map surfaces are the three TMA
    map components plus the plain `/app/map`; the other two TMAs (Menu,
    Oversight) carry no embedded map.
  - **Transport station pills in front — `web/transport/src/components/MrtMapPanel.jsx`.**
    Station `AdvancedMarkerElement` at `:666` gains `zIndex: 1000`
    (mirroring the cuisine droplet's `z=1000` from v0.61.91). Past z13
    bus-stop pins escalate to full-name labels that were occluding the
    station code/name pills; raising station zIndex above the bus
    markers' default puts stations on top. Bus markers stay at the
    default low z.
