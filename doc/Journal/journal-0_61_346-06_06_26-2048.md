## New

### [HDR] #546 | 20:48 SGT 06-06-26 | v0.61.346 — Michelin search is now per-country (SG standalone + 10 loader countries); chip enables wherever a curated list exists | 5 code files | 1 PR | 1 build |

- **[INTENT]** Until now `handleMichelinSearch` read only `SG-michelin.js`, hardcoded `regionCode:'SG'`, and bailed to empty outside SG; the chip was greyed outside SG. All the curated data (MY/TH/JP/KR/CN/HK/TW/VN/MO/PH) sat unused. This wires the loader into the live search so the Michelin chip returns the right country's list, and un-greys the chip wherever a list exists.

- **[MECHANISM]**
  - **Country resolution (route):** the `/api/cuisine/search` Michelin branch now computes `michelinCountry` — SG pill → `'SG'`; OTHER picker → its ISO-2 (`requestCountry`); JB → `null` (operator: keep disabled) — and threads it into `handleMichelinSearch`.
  - **Dataset (handler):** SG → `michelin.getAll()` (the standalone list, unchanged). Other countries → `michelin-data.visitableVenues()` filtered to that country, each mapped to the handler's flat shape `{name, address, postal, category, cuisine, vegetarian, halal, city, country}`. **Edition merged across years** per the operator: every visitable venue is included once, shown at its **latest** award standing (`latestMichCat` = the category of the venue's max award year). A country with no curated list bails to an empty `venues:[]` with a reason.
  - **Places lookup:** `regionCode` and the `textQuery` builder adapt per country (SG keeps the curated name+postal disambiguation; others use `name + city`).
  - **Summary:** the `michelinSummary` tier counts are derived from the active pool (`allEntries.filter(category===…)`) instead of SG-specific constants, so the "N more to explore" pager + tier totals are correct for every country.
  - **Chip enablement (TMA):** the catalogue emits `michelinCountries = ['SG', …loader countries]` on the Michelin chip. `CuisineDrawer` computes the current country (`region`/`countryPref`: SG→SG, MY-PUT→MY, JB→JB, OTHER→countryPref) and enables the chip when that country is in the list (falling back to the legacy `regionScope` gate for any other chip). The stale "Michelin is Singapore-only" caption becomes a generic "no curated Michelin list for this location" shown only when the current country isn't covered.
