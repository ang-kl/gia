## New

### [HDR] v0.62.581 — Cuisine: the carousel no longer "selects" (rings) a card on first load

- **[INTENT]** Operator (IMG_0747, landscape carousel, deployed v0.62.580):
  - *"Why do you select a card not in focus when loading the first time."*
  - *"I thought we have repair the right and bottom margin of the eatery card. Why we have this awful
    looking card again."*

- **[DELTA — ISSUE 1 (fixed)]** `web/cuisine/src/v2/components/ResultDrawer.jsx`. On the tablet
  carousel the accent **ring** (`focused` → `border-tg-accent`) was pinned to whatever card
  **auto-centred** on load (`activeId = centeredId || focusedPlaceId || list[0]`), so a card the user
  never tapped read as "selected". Split the two states: the centred card still shows visual focus via
  the **opaque/glass** treatment (the `visibleSet` IntersectionObserver), but the accent **ring** now
  appears **only on an actual tap** — `focused={glassPeek ? (!!focusedPlaceId && placeId ===
  focusedPlaceId) : (placeId === activeId)}`. No tap yet → no ring on first load. Phones keep the
  legacy `activeId` ring (their single-card strip has no glass focus).

- **[ISSUE 2 — NOT fixed, need a single-card close-up]** The *"right and bottom margin / awful card"*
  is the long-standing known-gap **"margin left+top, none right+bottom"** (Result-card border /
  inner-margin). The horizontal card is `px-2.5 py-1.5` (**symmetric**), so the asymmetry is **not**
  the card's own padding. Candidates: the `card-scroll overflow-y-auto rounded-lg` **wrapper** clipping
  the inner ResultCard's `rounded-lg border` on the scrollbar (right) + bottom; or empty right space
  from short Cuisine content in a ~370px `basis-30%` card. IMG_0747 is a **4-card** shot, so a single
  card's edges can't be isolated — asked the operator for a **single-card close-up** (fills the screen)
  before touching it. This defect has been flagged 3× and a wrong guess regresses it, so it's worth
  the one clarification.
