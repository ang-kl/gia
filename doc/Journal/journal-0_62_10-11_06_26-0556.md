## New

### [HDR] #655 | 05:56 SGT 11-06-26 | v0.62.10 — Text Search New paginates to fill the requested count + de-dups by places.id | pipeline.js + new pagination test | 1 PR | 0 build |

- **[INTENT]** Operator agreed the "fewer results than Google Maps" shortfall is structural (Places
  API New is page-capped at ≤20/page, ~3 pages / ~60 results; Maps is richer and elastic), so the
  fix is pagination + correct field mask + dedup, **not** a bigger timeout. Operator chose (Ask-
  UserQuestion) *"page to fill the request"* — accept up to 3× the Places calls on the deep-asking
  paths to actually return what they request.

- **[DELTA]** `pipeline.js`, `discover()` Text Search New branch:
  - New pure helper **`pagesForRequest(maxResults, maxPages)`** = `clamp(max(ceil(maxResults/20),
    maxPages), 1, 3)`. The page-walk now uses it (was `min(maxPages||1, 3)`, which ignored
    `maxResults`). Effect: free-text search + AND-combo (both ask for 30) now fetch **2** pages, the
    40-result caller fetches 2, the TMA's explicit `maxPages: 3` still fetches 3, and any ≤20
    request stays at **1** page (unchanged). Exported for unit tests.
  - **`maxResultCount` → `pageSize`** on the Text Search body — `pageSize` is the Places API New
    field; `maxResultCount` is its deprecated alias. (The Nearby Search body keeps `maxResultCount`
    — Nearby New has no `pageSize`/pagination and caps at 20.)
  - **De-dup by `places.id` at the page-concat seam** — the loop previously concatenated each page's
    `places` blindly; it now filters out ids already held before appending. Google's pages rarely
    overlap, but the rule is now enforced explicitly.

- **[VERIFICATION (sandbox)]** `node --check pipeline.js` clean. Full suite **3289/3289** green
  (+6: `pipeline-pagination` — ≤20→1 page, 30→2, 41→3, clamp at 3, explicit-maxPages honoured,
  larger-of-(count,maxPages), NaN/0 defends to 1). Server-only change — no web build. The network
  `discover()` itself is unmocked (real axios), so the page-count rule is unit-tested via the
  extracted pure helper.

- **[STATUS]** PR (draft, #970 — carries this fix on top of the standing-rule v0.62.6 journal
  record; same branch). Deploys via Railway on merge. **Cost note (G4):** auto-paging raises paid
  Places Text Search calls on the deep-asking paths (free-text, AND-combo) from 1 to up to 3 per
  cold search; the 30-min `POOL_CACHE_TTL` Redis pool cache absorbs repeat taps.

- **[TEST — operator, post-deploy]** A free-text or multi-cuisine search in a dense area now
  advances through a deeper pool before the "that's all N" terminal note (≈40–50 after the
  brand/dish-tail throttle, was ≈20). No duplicate cards across the deeper pool.

- **[KNOWN GAPS]** Google's text-search ceiling is ~3 pages / ~60 raw — beyond that the API simply
  stops returning tokens, so a truly Maps-complete list still isn't attainable via this SKU (the
  v0.62.8/0.62.9 corpus experiment that aimed at that was removed by the operator as too heavy).
  The dedup at concat is by id only; near-duplicate distinct-id listings are still handled by the
  downstream brand-throttle.
