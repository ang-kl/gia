### [HDR] v0.62.659 — five requests from one screenshot-and-instruction message (Train + Hawker)

- **[INTENT]** Operator, with three screenshots (`IMG_3694`/`IMG_3695` — the Train map at zoom 11 vs 12,
  overview vs default; `FullSizeRender` — Cuisine's location row) and one message:
  > *"on load Train TMA for the first time, set to 10 like the screenshot and overview. blink the top bar of
  > East-West line. Use the common pop-up window to ask user to select a line. All cards must be in 'less'
  > state and not 'detail' state, let user open the card. If in list mode, only show 1/4 drawer. In the Train
  > TMA, Have the same location (📍 show current location and nearest station) like cuisine TMA at top left

  > station code with auto-fill for the list of 200 live train station operated today. If the train station is
  > not operating (aka don't be confuse with future station), still allow to type. Apply this to Hawker TMA

- **[READING THE ZOOM SCREENSHOTS]** `IMG_3694` (zoom 11, Johor Bahru visible, stations render as small
  unlabelled coloured dots) and `IMG_3695` (zoom 12, Singapore only, stations render as readable code chips
  "NS15"/"TE6") are a before/after of the SAME map's pin-density LOD tiers
  (`MrtMapPanel.jsx` — pill at z15+, code-chip at z12-14, plain dot at z<12). The operator's ask is literal:
  the FIRST-LOAD state should be the wide, whole-network view (the dot tier), not a partial zoomed-in slice —
  matching what "Overview" already computes via `fitBounds` over every operating station. `SG_DEFAULT_ZOOM`
  moves 12 → **10**.

- **[THE ONBOARDING FLOW]** Read together, "blink EWL" + "use the common popup to ask the user to select a
  line" describe first-visit onboarding: land on the whole-network overview, draw the eye to a suggested line
  with a blink, and let the popup do the asking rather than silently defaulting to East-West Line. The
  existing first-load popup (`popup==='status'`, auto-shown once, v0.62.602) is **superseded** by a new
  `popup==='pickline'` — reusing the SAME `Modal` shell already in `transport/App.jsx` (operator's "common
  pop-up window") — a 2-column grid of every non-future line, tap-to-focus. The EWL chip in `AffectedTicker`
  blinks (`.line-flash`, the schematic's own keyframe, already in `transport/styles.css`) via a new
  `blinkCode` prop until the user taps any chip or dismisses the popup. The status info itself is unchanged —
  still one tap away on the status chip — just no longer auto-shown.

- **[CARDS DEFAULT TO 'LESS']** `StationCard.jsx`'s `bodyOpen` flips back to `useState(false)`. This directly
  **reverses** the v0.62.645 decision ("by default show the station details, not collapse") — the operator's
  own words this time are the opposite instruction. Tapping the name strip (or making a card `active`) still
  opens it; nothing about the toggle mechanism changed, only the starting state.

- **[1/4 DRAWER PEEK]** Transport's list-mode `<BottomSheet>` had never adopted the `peekPx`/custom-snap work
  done for Cuisine at v0.62.657 — it was still on the shared component's stock `[0.14, 0.48, 0.80]` snaps,
  opening at the 0.48 (half-screen) middle snap. Changed to `snaps={[0.14, 0.48, 0.75]} initialSnap={2}` — a
  literal "1/4 of the drawer" fraction (0.75 = sheet's top edge sits 75% down the viewport = 25% visible),
  rather than Cuisine's card-height measurement (`peekPx`), since the operator's phrasing here ("1/4 drawer")
  is a screen fraction, not a card count.

- **[THE STATION-SEARCH LOCATION ROW]** New shared component,
  `web/_shared/components/StationLocationField.jsx` — a Cuisine-style "📍 \<current state\> / \<change\>" row,
  but searching the MRT/LRT station list (`/api/transport/stations`, 183 operational + 26 future ≈ 209
  stations — "the list of 200") instead of doing address geocoding. Differs from Cuisine's `LocationField.jsx`
  in exactly the way the task differs: no external Places API call per keystroke, just a substring filter over
  a dataset already on the wire. Two states:
  - **Collapsed:** `📍 You are near <nearest operating station> (<distance>)` — nearest-station ranking
    considers only `status !== 'future'` stations (a station that doesn't exist yet can't be the one you're
    standing next to); location comes from the shared `location-sync.js` (device GPS + Telegram
    LocationManager, fresher wins) — a one-shot read here, not the continuous 20 s follow-poll Cuisine/Hawker
    use elsewhere.
  - **Expanded ("change"):** a text input, substring-matched against every station's name AND its codes
    (`NS1`, `EW24`, …), **operational and future alike** — the operator's explicit clarification that a
    currently-disrupted-but-existing station ("not operating" as in a live incident) and a not-yet-built
    station ("future") are different concepts, and neither should be excluded from typing. Future stations are
    still shown, tagged `· opens <year>` rather than hidden.
  - Wired into Train (`App.jsx` `headerEl`, between the title row and the clock/status row — "top left, just
    below the Train title text") with `onSelectStation` focusing that station on the map (mirrors the existing
    `?station=CODE` deep-link resolution already in this file) and switching the focused line to match.
  - Wired into Hawker's **both** live header layouts (`carouselLayout` between the `<h1>` and the region-pill
    row; `drawerLayout`'s single title card, restructured from a one-row flex to a two-row flex-col to fit the
    new line) — Hawker's `onSelectStation` is currently a no-op (see Known Gaps): the UI is there, "apply this
    to Hawker too" is satisfied, but selecting a station doesn't yet filter or jump to anything Hawker-side.
  - **This reverses a second explicit decision**: Transport's `userLoc` geolocation was deliberately ripped
    out at v0.62.641 ("remove distance walking in train") specifically so the Mini App would stop raising a
    location permission prompt it couldn't justify. The operator's new ask — "show current location and
    nearest station" — reintroduces exactly that prompt, this time with a justification (the nearest-station
    display + search). `userLoc` itself (the vestigial always-null prop feeding `StationCard`'s distance row)
    is untouched; this is a parallel, independent geolocation read inside the new component.
