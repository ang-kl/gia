- **[DELTA]**
  - **`count-display.js`** (NEW, ~95 lines):
    - **`FALLBACK`** — frozen map of the 14 items' baseline counts,
      mirroring the prior hardcoded marketing copy
      (`cuisines: 55, hawker: 100, michelin: 170, …`).
    - **`getDisplayCount(redis, item)`** — newest history entry's
      `n` or FALLBACK; never throws. Returns 0 only for unknown
      items.
    - **`getDisplayCounts(redis)`** — `{item: n}` for all 14 items.
    - **`formatCountPlus(redis, item)`** → `'70+'`. Rounds DOWN
      to nearest 5 (for `n >= 10`) so a recount tweaking 71→73
      doesn't flicker the marketing string. Raw value for sparse
      counts (`< 10`) so a 6-line MRT system reads "6+" not "5+".
    - **`formatAllCountsPlus(redis)`** — `{item: '70+'}` map.
    - **`substituteCounts(template, counts)`** — replaces
      `{item}` placeholders in a string template. Unknown
      placeholders left intact (so `{foo}` doesn't crash when
      foo isn't an ITEM). Hyphenated keys supported
      (`{bus-stops}` → `'5500+'`).
  - **`__tests__/count-display.test.js`** (NEW, 16 tests):
    FALLBACK shape + freeze; getDisplayCount live / fallback /
    unknown / n=0 falls back; getDisplayCounts complete map +
    partial-seed mix; formatCountPlus rounding (73→70+) +
    no-rounding for n<10; formatAllCountsPlus; substituteCounts
    with hyphenated keys + unknown-leaves-intact + non-string
    template + non-object counts.
  - **`i18n.js`**: `start.intro` (EN + FR) — `50+ cuisine`,
    `over 55 cuisines`, `>100 hawker`, `plus de 50 cuisines`,
    `plus de 55 cuisines`, `plus de 100 hawker` → all replaced
    with `{cuisines}` / `{hawker}` placeholders. Comment notes
    the v0.61.169 substitution + FALLBACK contract.
  - **`index.js`** (4 edits):
    1. `/start` handler (just after `intro = t('start.intro', …)`):
       calls `formatAllCountsPlus(redis)` + `substituteCounts(intro, counts)`.

       placeholders visible) on any failure — pre-deploy the user

       `{ counts: { cuisines: 70, … }, plus: { cuisines: '70+', … } }`.
