# Journal — soleat / Gia4lunch v0.62.720

## New

### [HDR] v0.62.720 — the Gemini audit behind a Railway route, so the key never moves

- **[INTENT]** Operator, having been asked twice for `GEMINI_API_KEY` and declining:
  *"wire it behind a Railway route"*. That is a reasonable call and it was offered as
  an option, not extracted — the key then never leaves the environment that already
  holds it. The cost is the return path, and the operator is the one entitled to
  price that.

- **[DELTA]**
  - **`i18n-audit.js` (new, CJS).** `auditJob()` fills `gemini_audit` for every item
    still `unreviewed`, plus `listModels()`. Reads the instruction block from
    `scripts/i18n-translation-audit-prompt.md` at call time — the same markdown the
    chat workflow uses — so the API path and the chat path cannot drift.
  - **`index.js` — `GET /api/i18n-audit?lang=&batch=&token=`**, sibling of the
    v0.62.718 translate route, same `I18N_TRANSLATE_TOKEN` gate, same fail-closed
    posture (D-118). `?models=1` lists what the key can actually reach before
    anything is spent. Records token usage through `api-cost.recordGeminiUsage` so
    the audit shows up in `/cost` like every other Gemini call.
  - **`scripts/audit-i18n-translations.mjs` refactored onto the shared core.** The
    CLI previously carried its own copy of the prompt-loading, chunking and
    verdict-merge logic. Two implementations of an audit would eventually disagree
    and the disagreement would be invisible in the output, so there is now one.
  - **`__tests__/i18n-audit.test.js`** — 11 tests.

- **[WHY PER-BATCH, DELIBERATELY]** A full language is 265 items ≈ 11 model calls,
  which will outlive any sensible HTTP timeout. The route audits ONE batch file
  (50 items ≈ 2 calls) per request. There is intentionally **no `?batch=all`**: the
  translate route has one, and copying it here would hand back a gateway timeout
  half the time. A half-finished audit that looks finished is worse than an honest
  36 requests. This is the round-trip that `batch=all` removed, coming back — and
  it comes back because the operator chose key-stays-put over fewer round trips.

- **[VERIFICATION (sandbox)]**
  - `node --check` on `index.js` and `i18n-audit.js` — clean.
  - Route body scanned for bare module references — none (the v0.62.718 lesson:
    `fs` has no top-level require in `index.js`, and `node --check` cannot see it).
  - `npx vitest run` — **171 files / 4,181 tests, 0 failures.**
  - `package.json` 0.62.719 → 0.62.720. No `web/` change.
  - Refactor caught one real bug before it shipped: the CLI still called
    `listModels()` with no argument after the shared core made the key an explicit
    parameter — it would have died with a misleading "GEMINI_API_KEY is not set".

- **[WHAT THE TESTS PIN]** All of it is about not overclaiming. An item the model
  returns nothing for stays `unreviewed` and is counted in `missing` — silence is
  never upgraded into a pass. The summary is recomputed from the items, never
  accumulated. Already-audited items are excluded from the request body, not just
  from the count. A missing key stops the run rather than producing empty verdicts.
