- **[INTENT]** Forward `countryCode` end-to-end (TMA request body → server route → Places regionCode) and remove the silent ` Singapore` suffix in `special-mode.buildSeeds`. Phase 2 (v0.61.270) closed the WRITE side of the SSOT; Phase 3 closes the READ-AT-SEARCH side. After this PR a Cuisine TMA `state.countryPref = 'TH'` actually drives Places' regionCode for the search call — no more IP-geo fallback that biased Bangkok queries to Singapore venues.

- **[DELTA]**

  **1. `web/cuisine/src/v2/lib/api.js`**

  - `searchCuisine` signature gains optional `countryCode`; when valid ISO 3166-1 alpha-2, attached to the POST body. Only sent when present so chat-bot callers / pre-v0.61.271 bundles still work unchanged.
  - `nlQuery` signature gains optional `region` + `countryCode`; same forwarding semantics.
  - Added `'durian-pastry'` to the `specialMode` allowlist at this seam (was missing — the chip was pluggable via the slug, but the early enumeration only listed `'fruits'` / `'durian'`).

  **2. `web/cuisine/src/v2/App.jsx`**

  - `runSearch`'s `searchCuisine` call now passes `countryCode: state.countryPref` when `state.region` is `'OTHER'` or `'MY-PUT'`. SG / JB regions don't pass it (their country is implicit in the `region` tag).
  - `handleNLSubmit`'s `nlQuery` call forwards `region` + `countryCode` the same way.

  **3. `index.js` — three route changes**

  - `/api/cuisine/search` accepts a top-level `countryCode` from the request body. Validated as ISO 3166-1 alpha-2 (uppercase + regex). Stored in `requestCountry`.
  - The `searchRegionCode` resolver (~line 13538) now prefers `requestCountry` for OTHER mode instead of leaving the field `undefined` (which let Places' IP-geo lean toward SG when the Railway server was SG-hosted).
  - `/api/cuisine/warm-start` mirrors the same `requestCountry` resolution (~line 12048) so the first-pass result lights up with the right country bias too.
  - `special-mode` regionSuffix logic (~line 13772) replaces the binary `region === 'JB' ? 'Johor Bahru Malaysia' : 'Singapore'` with a three-way: JB / SG keep textual suffixes; OTHER/MY-PUT passes `''` (empty), so Places' `regionCode` + `includedRegionCodes` do the country work without the seed-suffix leak.

  **4. `special-mode.js`**

  - `buildSeeds` default changed from `' Singapore'` to `''`. The function now requires an explicit `regionSuffix` from the caller to inject a textual country suffix into the seeds. Callers that pass an empty string OR omit the opt get bare seeds (e.g. `'durian shop'`, not `'durian shop Singapore'`).

  **5. `__tests__/special-mode.test.js`** — 5 contract updates + 2 new tests

  - New: empty/whitespace `regionSuffix` is treated as no suffix.
  - New: explicit `regionSuffix: 'Singapore'` still works for opt-in callers.
  - New: `regionSuffix` supports new countries (Bangkok Thailand / Jakarta Indonesia).
