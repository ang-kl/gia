## New

### [HDR] #177 | 01:25:00 SGT 16-05-26 | v0.60.209 — Try-line dish-only guard (shared denylist) + 2-field Sanctuary read | 6 files | 1 PR |

- **[INTENT]** Two operator-flagged rendering issues. (1) The "Try" recommendation line — `🍴 Try ·` / `🍽️ Try` / `🧾` / the Cuisine TMA `🍴 try the` — was leaking generic category words (the screenshot: "Try: dishes"). Three extraction paths each rolled their own partial denylist and `dish`/`dishes` slipped past every one. (2) The Sanctuary read block was a 4-bullet `• Quiet/Seating/Vibe/Approach` body under a `🌿 Sanctuary read for <name>` header; operator wants just two `🌿`-prefixed fields and no header.

- **[DELTA]**

  **`dish-name.js`** (NEW) — single source of truth for the "is this a real dish/dessert name?" criteria:
  - `CATEGORY_RE` — anchored `^…$` denylist of ~100 category nouns (the union of the two former regexes **plus `dish`/`dishes`/`food`/`foods`/`cuisine`** — the words that leaked). Anchored so real menu items containing a category word still pass ("Dessert Platter", "Combo Set").
  - `isDishName(s)` — string, length 3–40, not a bare category word, not a trailing-stop-word fragment ("desserts which").
  - `filterDishNames(arr)` — array filter preserving order.

  **`index.js`**:
  - Top-level `require('./dish-name')` → `isDishName`, `filterDishNames`, `CATEGORY_RE`.
  - `MICH_CATEGORY_BLOCK` (Michelin path, was a local regex) → now aliases the shared `CATEGORY_RE`. Same for `CATEGORY_BLOCK_RX` (cuisine-search `extractDishes`). One denylist now governs both extraction paths.
  - `formatTechniqueVenueBlock` — the `🍽️ Try` line now renders only when `isDishName(dishPhrase)` is true (covers `/s` + free-text).
  - Michelin enrich-cache READ — `signatureDish` / `dishes` restored from a stale pre-fix cache entry now pass through `isDishName` / `filterDishNames`, so a cached "dishes" cannot resurface on the TMA card.

  **`venue-templates.js`**:
  - `formatOrderLine` (the `🧾` line — Copy / Copy to / every Telegram detail card) now filters `p.dishes` through `filterDishNames`. Render-time chokepoint: a category word can never reach a card even if an upstream path lets one through.
  - Sanctuary block in `formatVenueBlock` — dropped the `🌿 Sanctuary read for <name>` (FR: `Lecture sanctuaire pour`) header line; the block is now just the verbatim 2-line `sanctuaryRead` content.

  **`vibe-summary.js`**:
  - `summarizeVibe` prompt (EN + FR) — was "Return EXACTLY four short bullets `• Quiet/Seating/Vibe/Approach`"; now "Return EXACTLY two short lines `🌿 Quiet:` / `🌿 Seating:`" (FR: `🌿 Calme :` / `🌿 Places :`). `Vibe` and `Approach` dropped.
  - `getOrCacheSummary` cache key `vibe:summary:` → `vibe:summary:v2:` so stale 4-bullet summaries in the 7-day cache aren't served after deploy.

  **`__tests__/dish-name.test.js`** (NEW) — 39 tests: accepts real dish names, rejects bare category words incl. `dishes`, rejects fragments / bad input, `filterDishNames`, `CATEGORY_RE`.

  **`__tests__/venue-templates.test.js`** — sanctuary fixture updated to the 2-line `🌿` shape; asserts the `Sanctuary read for` header is gone.

  **`package.json`** — `0.60.208 → 0.60.209` (PATCH).

  **`doc/Journal/journal-0_60_209-16_05_26-0125.md`** — this entry (#177). **`doc/.serial-state.yml`** — `journal 176→177`, `commit 183→184`; re-anchored.
