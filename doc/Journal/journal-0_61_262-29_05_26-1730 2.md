- **[INTENT]** Three operator concerns to address simultaneously:

  1. **Precision** — 70.6% is too low; need 90%+. (Honest take: 95% is aspirational for a heuristic filter; 90% is realistic.)

- **[DELTA]**

  **1. `special-mode.js` — restaurant family in DURIAN accept list (recall fix)**

  v0.61.261 variance analysis showed **0 false positives** but **15 false negatives** — real durian sellers wrongly rejected because Places classed them as `restaurant` / `asian_restaurant` / `chinese_restaurant` / `diner`. Names like:
  - 皇后镇榴莲档 Durian Stall (asian_restaurant)
  - Durian Power Food Stall (chinese_restaurant)
  - Gerai Durian Kubur Cina (restaurant)
  - 榴心花园 DuriYen Garden - Durian Store TRX (restaurant)
  - Mr Durian (restaurant)

  Added these four types to `ACCEPT_PRIMARY_TYPES_DURIAN` AND to `STRICT_NAME_TYPES_DURIAN` (which means they're accepted ONLY when the venue name contains a durian keyword). Cuisine-specific restaurants (`italian_restaurant`, `japanese_restaurant`, `french_restaurant`, `sushi_restaurant`, `ramen_restaurant`, `pizza_restaurant`, `steak_house`, `seafood_restaurant`, `fine_dining_restaurant`, etc.) remain OUT of the accept list → "Durian Pasta Bistro" + "Sushi & Durian Buffet" still reject as expected.

  **2. `special-mode.js` — RECENCY-FILTERED REVIEW signal**

  Operator's question *"did you accurately check reviews (last 24 months) as durian are seasonal"* — direct answer: no, v0.61.257 dropped reviews entirely. Fixed by:

  - `_countRecentDurianMentions(venue)` — counts `durian` / 榴莲 / 榴梿 mentions across `venue.reviews[]` whose `publishTime` is within the last 24 months (the operator-cited window covers 2 full durian seasons: May-Jul/early-Aug + mid-Nov-Dec).
  - `CANONICAL_TYPES_DURIAN_FOR_REVIEWS` (fruit_and_vegetable_store / produce_market / fruit_parlor / wholesaler / food_store / fresh_fruit_store / food_market / farmers_market) and `..._DURIAN_PASTRY_FOR_REVIEWS` (bakery / cake_shop / pastry_shop / dessert_shop / dessert_restaurant / ice_cream_shop).
  - When `pt` is canonical for the mode AND `_countRecentDurianMentions(venue) >= 2`, accept. Catches real durian shops whose name is a VARIETY only (e.g. "Mao Shan Wang Stall") — the operator's earlier known gap that v0.61.257 acknowledged.
  - The ≥2 threshold prevents the v0.61.229 single-review loophole (one off-hand mention promoted a generic cafe). Two independent reviewers separately calling out durian is much stronger evidence.

  **3. `durian-variance-runner.js` — coverage expansion (3× more results)**

  - `LIMIT_PER_QUERY`: 8 → **20** (Places' searchText per-page max).
  - `RADIUS_M`: 8 km → **25 km** (suburban + outlying venues now in scope).
  - `MAX_PAGES`: 1 → **3** (pagination via `nextPageToken`, ~60 results per query cap that Google enforces).
  - DURIAN_PASTRY seeds widened to include `durian shake` / `smoothie` / `frappuccino` / `ice cream` / `mochi` / `kueh` / `kuih` / `pancake` / `tart` per the operator's *"drinks / snacks / thousands"* framing. ~3.5× the en-seed count (was 4, now 14); other languages expanded similarly.
  - `placeToVenue` now captures `reviews[].publishTime` + `rating` so the v0.61.262 recency filter has data to work on (was: text only).
  - `searchText` rewritten to use a paged loop reading `nextPageToken` until the cap is hit, also requesting `nextPageToken` in the field mask. Cost: ~3× more API calls per query → ~$1.20-1.60 USD per mode, ~$3 USD for both modes from `/ver` "Run Both". Still pre-approved per the v0.61.260 G4.
