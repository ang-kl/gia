## New

### [HDR] #412 | 20:20 SGT 28-05-28 | v0.61.211 — country dropdown keyboard nav | 3 files | 1 PR | 1 build |

- **[INTENT]** Make the v0.61.208 country dropdowns navigable
  by keyboard. ARIA roles + native button focus mean screen
  readers and visual focus rings work without extra bookkeeping.

- **[DELTA]**

  Behaviour added in both `<CountryDropdown>` (Cuisine TMA) and
  `<CountryDropdownMenu>` (Menu TMA):

  | Key | Action |
  |---|---|
  | **↑** | Focus previous option; wraps to last from first |
  | **↓** | Focus next option; wraps to first from last |
  | **Home** | Focus first option |
  | **End** | Focus last option |
  | **Enter** | Picks the focused option (native button onClick → `pick(code)` → `setOpen(false)` + `onChange(code)`) |
  | **Esc** | Closes the popover (unchanged from v0.61.208) |

  On open, the currently-selected option gets initial focus
  (matched by `OTHER_COUNTRIES.findIndex((c) => c.code === value)`).
  If `value` isn't in the list, the first option gets focus.

  Implementation:
  - **NEW `itemRefs` ref** — array of `HTMLButtonElement | null`
    indexed by the OTHER_COUNTRIES order. Each option `<button>`
    carries `ref={(el) => { itemRefs.current[i] = el; }}`.
  - **NEW initial-focus useEffect** — fires when `open` flips
    true. Uses `setTimeout(() => …focus(), 0)` so the popover is
    mounted in the DOM before `.focus()` runs.
  - **NEW `onListKey` handler** attached to the `<ul role=
    "listbox">`. Reads the active element index from
    `itemRefs.current.findIndex(el => el === document.activeElement)`,
    computes the next index, and calls `.focus()` on the
    target. Wraps via `(idx + len) % len` to make ↑ from the
    first option land on the last, and ↓ from last land on first.
  - **Focus styling** — option buttons gain
    `focus:bg-tg-bg focus:outline-none` so the focus highlight
    matches the existing hover highlight (no double ring).

  - **`package.json`** — `0.61.210 → 0.61.211`.
  - **`doc/.serial-state.yml`** — commit 423 → 424, build 213 →
    214, journal 411 → 412; re-anchored 28-05 '26 20:20 SGT.

- **[TEST]** Operator (post-merge + Railway redeploy + Cuisine
  TMA + Menu TMA cache bust):
  1. Cuisine TMA → 🌏 Others → tap the flag dropdown → first option
     is focused (highlighted with hover-style). If the current
     value is e.g. 🇲🇾 MY, it's the focused option.
  2. Press ↓ several times → focus walks down the list.
  3. Press End → focus jumps to last option.
  4. Press Home → focus jumps to first.

  7. Repeat on Menu TMA → same behaviour with the slightly
     different chrome.

- **[KNOWN GAPS]**
  - No type-ahead / first-letter jump (typing "J" doesn't jump to
    Japan / Johor). Out of scope.
  - The popover currently has no scroll-into-view on focus
    change. With 16 options and max-h-72 (~18rem), some focus
    moves at the bottom may scroll the list (browser default).
    If a user reports the focused option going off-screen, we
    can add `target.scrollIntoView({ block: 'nearest' })` after
    `.focus()`.
