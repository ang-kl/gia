# Journal — v0.62.691 (carousel card line spacing; the audit that preceded it)

_(№ 1,031 — 01-08 '26 16:05 SGT)_

## New

### [HDR] v0.62.691 — reduce the line spacing, then the card height

- **[INTENT]** Operator, on a device screenshot of the Cuisine carousel: *"the height of the carousel
  card can be reduced by 10% or one row, can we move one row to the expanded area.) audit all the
  carousel card spec first and feedback"* — then, after the audit was delivered: *"before we move the
  latest row of the carousel card, can we reduce line spacing height so we can shorten the height of
  the card"*. So: spacing first, row-move deferred.

- **[FINDING — the loose spacing was never a decision]** Six collapsed rows carried **no `leading-*`
  class at all** — type/★/$, meta, 💵 price, 🍱 set-meal, Michelin, and the toggle — and therefore
  inherited Tailwind preflight's `html { line-height: 1.5 }`. The rows someone had explicitly styled
  ran at 1.25 (`leading-tight`: name, native name, reading, gloss, ≈ conversion) or 1.375
  (`leading-snug`: 🍲 Try, address). Three different line-heights on one card, decided by which rows
  happened to receive a class rather than by any rule.

- **[DELTA]** `web/cuisine/src/v2/components/ResultCard.jsx`, horizontal card only:
  - **`leading-snug` on the card ROOT.** One class fixes all six unstyled rows at 1.375; every
    explicit per-row `leading-*` still wins on specificity, so nothing that WAS deliberate changes.
    `leading-tight` (1.25) was considered and rejected — the app ships 8 locales including zh/ja, and
    1.25 risks clipping full-height CJK glyphs for ~6px more.
  - **Removed the `mt-*` that doubled the flex gap.** The parent already supplies `gap-0.5` between
    every row; 💵 price additionally carried `mt-0.5`, and 🍲 Try / Michelin / address `mt-1`, and the
    toggle `mt-1.5`. Trimmed to `0 / mt-0.5 / mt-1`. **Every trim is gated on `horizontal`** — the
    vertical list has no height budget and is byte-identical.
  - **Standard tier `h-[13rem]` → `h-[12rem]`.** Short tier deliberately unchanged (see below).

- **[WHY 12rem, AND NOT LESS]** Not taste — it is the largest reduction that leaves **every** case no
  worse than before. Arithmetic from the classes, per row (font-size × line-height + margins + the
  2px gaps + 12px padding):

  | Case | Content before | Content after | Box before | Box after | Verdict |
  |---|---|---|---|---|---|
  | Typical card (the screenshot; 8 rows, no wraps) | 178px | **165px** | 208 | **192** | slack 30 → 27 |
  | Worst realistic (Michelin + name/meta/address all wrapped) | 252px | **233px** | 208 | **192** | over 44 → **41** |

  At `11.5rem` (184px) the worst case overruns by **49px**, which is *worse than today's 44px*. So
  12rem is the floor for what spacing alone can buy; anything further needs the row-move the operator
  deferred.

- **[REPORTED, NOT FIXED — the short tier is already over-subscribed]** The same arithmetic run
  against the **short** tier (`7.5rem`/120px, phone landscape) gives **~156px of content today** — an
  overrun of ~36px, meaning the ▸ toggle can be clipped off entirely, leaving no way to expand the
  card. This change improves it to ~26px over but does not resolve it. **The short tier was
  deliberately NOT shrunk**: it needs either more height or fewer rows, which is a spec decision, not
  a spacing one. Surfaced to the operator rather than silently patched.

- **[REPORTED, NOT FIXED — the conversion row orphans on the short tier]** The 💵 price row is gated
  `!isShort` (`:501`); the `≈ A$22.77–91.05` conversion beneath it (`:520`) is **not**. On a short
  viewport the card shows a converted price with nothing above it to convert. Found during the audit;
  it is also the row nominated for the deferred move to the expanded area, so fixing it in isolation
  would likely be thrown away.

- **[ALSO FOUND, THEN BUILT — Cuisine hid the ⇱/⇲ map button the other two apps show]** Operator,
  first: *"one missing cluster button on the embedded google map aka zoom in/out"*; then, confirming
  the audit's diagnosis: *"did you know the ⇱ (North West Arrow to Corner, U+21F1) and (South East
  Arrow to Corner U+21F2) ⇲ is missing in Cuisine TMA. it is to expand the embedded map like Train
  TMA and Hawker TMA"* — and approved the fix.

  All three panels render the same five-button cluster (readout · ＋ · ↹ · － · ⇲). Cuisine gated the
  ⇲ on `(!fill || onCollapse)` (`MapPanel.jsx:1108`); on a phone `fill` is true and `onCollapse`
  undefined, so it never rendered. The in-code reason — *"it would be a no-op button"* — names the
  real problem and then reaches for the wrong remedy, and it is **exactly the state Transport
  (v0.62.626) and Hawker (v0.62.627) were each bug-reported for**. Both were fixed the same way: not
  by hiding the button but by giving it a real action.

  **Hawker's fix is ported verbatim rather than re-invented** — `overlayFull` state,
  `canOverlay = fill && !onCollapse` (precisely the case that was hidden), and the gate deleted so
  the button ALWAYS renders. In the formerly-dead case ⇲ promotes the map to a full-viewport overlay
  and ⇱ returns it. Two details carried across because they were learned the hard way there:
  - **`z-[35]`, not `z-30`.** Hawker's own Codex-P2 note: the result carousel is `fixed … z-30` and
    paints LATER in the DOM, so an equal-z overlay sits BEHIND the cards. 35 clears the carousel and
    stays under the footer dock (z-40) so the footer's Map toggle remains reachable.
  - **A `resize` trigger on `[overlayFull, expanded]`.** Promoting the wrapper to `fixed inset-0`
    changes the container size out from under the Maps SDK, which otherwise keeps painting at the
    old size and drifts off-centre. Cuisine had **no** resize trigger at all before this.

- **[OPERATOR DECISIONS THIS PASS]** Two of the three deferred items were closed by instruction, not

  dropped; the spacing trim is accepted as sufficient. **(2)** *"The short tier — phone landscape -
  dont change."* — O-115 stands as a known, accepted overrun rather than an open task. Recorded so a
  later session does not "fix" either as an oversight.

- **[VERIFICATION (sandbox)]** Cuisine build green; full `npm test -- --run` **156 files / 3901
  tests** green. Compiled CSS grepped with `grep -F` on the CSS-escaped literals — `.leading-snug`,
  `.h-\[12rem\]`, `.h-\[7\.5rem\]`, `.mt-0\.5`, `.mt-1{`, `.line-clamp-2`, plus the overlay's
  `.z-\[35\]`, `.fixed`, `.inset-0` — all **EMITTED**. Both glyphs **⇱ and ⇲ confirmed present in the
  built JS bundle** (they were absent from the rendered phone UI before, though present in source —
  the gate, not the glyph, was the bug). Version string confirmed rebuilt into the bundle
