### [HDR] v0.62.671 — first slice of the M3 alignment pass: fixes that needed no decision

- **[INTENT]** Operator: *"Review UI controls and layout and visual cues using M3 standards, apply them
  immediately after audited https://github.com/material-components/material-web"* — then, mid-audit,
  narrowed the authorization: **"Only applied if I approve."** This entry is Tier 0 of the resulting
  audit: the handful of findings that are bugs/copy-drift/dead-code rather than design decisions, which
  the operator explicitly approved to proceed on ("okay, tier 0. proceed as planned"), plus one specific
  clarification on the MapControls fix direction ("the dropdown wrapper is rounded-xl" — i.e. fix the
  rows to match the wrapper, not the reverse).

- **[EVIDENCE BASE]** Two research agents ran in parallel: (1) a spec-extraction pass that shallow-cloned
  `material-components/material-web` (tag v2.5.0) and read numeric values directly from its token/SCSS
  source — touch target 48px, the 7-step shape scale (0/4/8/12/16/28/9999px), button/FAB/switch/chip/
  dialog/text-field dimensions, the 6-level elevation shadow table, 4-tier state-layer opacities, the
  full motion duration+easing token set, and the type scale — explicitly flagging which figures were
  literal tokens vs derived; (2) a codebase audit cross-referencing GIA's actual controls against those
  numbers. Headline finding: **none of the six `tailwind.config.js` files define a radius, elevation, or
  motion scale at all** — every button/chip/FAB/switch/shadow/duration in the suite is a one-off
  invented per call site, which is why the inconsistency count was so high (11 chip padding combos, 3
  button radii, 2 unrelated switch sizes, FABs at 3 diameters, ~13 handwritten shadow sets, 6 motion
  durations).

- **[USER-CORRECTED PREMISE]** The operator flagged that `BackFab.jsx` deletion needed a check: they
  recalled it appearing "only in listing mode and not scrolling within listings" in Cuisine/Hawker. Direct
  verification (import-statement grep, not just JSX-tag grep, per the audit agent's original method)
  confirmed zero imports anywhere, AND traced the actual history: a v0.62.213 operator-approved change
  (comment in `menu/App.jsx:893` and `_shared/FooterNav.jsx:6-11`) had already consolidated the standalone
  corner BackFab + a separate scroll FAB into the single `FooterNav`/`FooterDock` row every app now
  renders. Also checked whether the CURRENT footer hides during list scrolling (matching the operator's
  memory) — it does not; `FooterDock` renders unconditionally at all its call sites. The scroll-hide
  behaviour the operator recalled belongs to the pre-v0.62.213 BackFab, which itself had no such logic
  either (a static fixed-position button) — so reviving the deleted files would not have restored that
  behaviour regardless. Operator confirmed deletion after seeing this trace.

- **[DELTA]** (single commit `1ad8aa4`)
  1. **Deleted `BackFab.jsx`** in cuisine/hawker/transport/menu — confirmed-dead code from the v0.62.213
     footer consolidation, verified via import-statement grep before removal (AU-2/G2: no Removed-table
     entry needed — components, not documented Features/Decisions, and their retirement is already
     recorded in-repo via the v0.62.213 comments this entry cites).
  2. **Reconciled the BottomSheet slide duration**: the live, shipped `_shared/components/BottomSheet.jsx`
     has always used `280ms`; the unused-by-React vanilla `bottom-sheet.css` (whose JS physics helpers the
     live component borrows) still declared `340ms` under the identical easing curve — pure copy-drift.
     Vanilla file's `--gia-sheet-dur` corrected to `280ms` to match what real users have always gotten
     (the live value was left untouched — no behaviour change for any user).
  3. **Fixed cuisine's Widen switch travel**: `translate-x-[1.15rem]` (18.4px) against a 36px track / 14px
     thumb / 2px off-inset landed 1.6px short of a symmetric on-inset. Corrected to `1.25rem` (20px) —
     the thumb now sits exactly 2px from each edge in both states. A ~1.6px nudge, not a redesign.
  4. **Fixed MapControls' internal contradiction**: the `⋮` dropdown's own item rows were `rounded-lg`
     while its wrapper is `rounded-xl` — same menu, two radii. Rows now match the wrapper per the
     operator's explicit direction.
