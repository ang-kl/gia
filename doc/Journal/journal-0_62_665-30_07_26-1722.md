## New

### [HDR] v0.62.665 — the 2026 Bib Gourmand edition, and a compact multi-year field for the first time

- **[INTENT]** Operator, in a long, explicit spec: update Michelin Star and Bib Gourmand records using ONLY
  the existing structure (no new tables/schemas/history stores), add a compact `awardYears` field
  (`["'26", "'25"]`-style, newest-first, apostrophe-abbreviated), show multiple years ONLY when the SAME
  category was retained across them, never label a category change with a year it held a DIFFERENT category
  in, never write promotion/downgrade/removal commentary, and — critically — verify per-country whether
  Michelin has actually released the 2026 edition before adding `'26` anywhere, rather than inferring.

- **[WHAT GOT VERIFIED, AND WHAT DIDN'T]** Live research (WebSearch/WebFetch; most individual news-site
  fetches 403'd — genuine bot-blocking on their end, not a proxy issue, confirmed via the environment's own
  proxy-status endpoint showing zero relay failures) established, from multiple independently-consistent
  sources:
  - Singapore's **2026 Bib Gourmand** selection WAS officially announced **28 Jul 2026**: 97 establishments
    (up from 89 in 2025), 10 new, 2 dropped ("Eminent Frog Porridge & Seafood", "Soon Huat" — named
    specifically, not inferred; 89 − 2 + 10 = 97 checks out exactly).
  - Singapore's **2026 STAR selection has NOT been announced** — ceremony scheduled **04 Aug 2026**, five
    days after this edit. Per the operator's own §9 ("edition not yet released"), no star record gets `'26`
    this entry. This is the reason the whole update is scoped to Bib Gourmand only, not "Michelin 2026" in
    the broad sense the task's title suggested.
  - The 11 other countries already curated in `michelin-data.js` (MY/TH/JP/KR/CN/HK/MO/PH/TW/VN/FR) already
    carry correctly-dated 2025/2026 `awards:[{year,category}]` history from an earlier session — verified by
    spot-checking real promotion/demotion/retention cases (Malaysia's Nirwana retained bib-gourmand in both
    2025+2026; France's L'Ambroisie demoted three-star→two-star between editions) — so no data changed for
    those 11 countries. What WAS found broken: `index.js`'s flattening step for non-SG countries computed the
    correct latest `category` but silently dropped the `year`, and both TMA card renderers hardcoded a
    fallback of "2025" regardless of country — meaning already-correct 2026 data for 11 countries was
    rendering as "2025" on screen. Fixed as part of the same rendering pass (see Technical entry).

- **[THE SCHEMA DECISION]** SG-michelin.js's records had NO year field at all (a prior, deliberately-recorded
  decision — "SG-michelin.js reverted to its pre-v0.61.330 standalone form", pinned by
  `__tests__/SG-michelin.test.js`). The operator's own spec explicitly asks for "the existing award-year field
  **or the smallest compatible addition**" — read here as license to add ONE new array field
  (`awardYears`) to the existing flat record shape, not to re-couple SG into the venue-centric loader the
  earlier decision deliberately kept it out of. Every SG record (all 138, stars and Bib Gourmand alike) now
  carries `awardYears`; the non-SG venue-centric schema already had the equivalent information in `awards[]`
  — a new exported helper, `retainedAwardYears(venue)`, derives the SAME compact output shape from it (walks
  newest-to-oldest, stops at the first category change), so both systems feed one unified render contract
  without touching either system's actual data shape.

- **[THE FIELD RENAME]** `venue.michelinYear` (a single number) is retired as a SETTER everywhere in this
  entry — a single year cannot represent "'26, '25" — but kept as a READ-ONLY fallback in
  `web/clipboard/src/components/VenueCard.jsx`, since already-saved Clipboard "clip" records from before this
  change may still carry only the old field. New venues carry `michelinAwardYears` (array) instead; nothing
  new ever writes the old field again.

- **[DELTA]** (7 files)
  1. `SG-michelin.js` — `awardYears` added to all 138 records; `BIB_GOURMAND` updated for 2026 (2 removed,
     87 retained get `'26` added alongside `'25`, 10 new added with `'26` only); `formatMichelinLine` reads
     `entry.awardYears` (compact join) instead of taking a `year` parameter; `annotateVenueObject` sets
     `venue.michelinAwardYears` instead of a hardcoded `michelinYear = 2025`; schema/header comments updated.
  2. `michelin-data.js` — new exported `retainedAwardYears(venue)` helper (the non-SG equivalent derivation).
  3. `index.js` — `handleMichelinSearch`'s non-SG flattening now carries `awardYears` through
     (`retainedAwardYears(v)`); both venue-construction branches (Places-success and Places-failure) now set
     `michelinAwardYears` on the venue object sent to the TMA.
  4. `web/cuisine/src/v2/components/ResultCard.jsx` — `michelinAnnotation()` renders the compact join instead
     of a bare year; the "clip to Clipboard" payload forwards `michelinAwardYears` instead of `michelinYear`.
  5. `web/clipboard/src/components/VenueCard.jsx` — prefers `v.michelinAwardYears`, falls back to
     `v.michelinYear` for already-saved clips.
  6. `__tests__/SG-michelin.test.js` — counts updated (89→97 Bib Gourmand, 130→138 total) and
     `formatMichelinLine` expectations rewritten for the compact-year format, intentionally, plus new
     assertions locking in the 2026 update itself (retained/new/dropped spot-checks, "no star has '26 yet").
  7. `__tests__/michelin-data.test.js` — new `retainedAwardYears` describe block (promotion, debut, single-
