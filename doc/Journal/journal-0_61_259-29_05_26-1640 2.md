### [HDR] #460 | 16:40 SGT 29-05-29 | v0.61.259 — Variance CI automation | 4 files | 1 PR | 1 build |

- **[INTENT]** Collapse the Durian / Durian Pastry variance run +
  output storage to **zero manual steps on the operator's side**.
  The v0.61.258 script writes structured JSON when invoked
  manually; the v0.61.259 GitHub Action runs that script on every
  merge that changes the relevance logic and stores the JSON +
  a Markdown table back in the repo.

- **[DELTA]**

  **1. NEW `.github/workflows/durian-variance.yml`** — GitHub Action.

  ```yaml
  on:
    workflow_dispatch:           # manual trigger from Actions tab
    push:
      branches: [main]
      paths:
        - special-mode.js
        - scripts/durian-variance.js
        - scripts/durian-variance-summary.js
        - .github/workflows/durian-variance.yml
  ```

  Steps:
  - `actions/checkout@v4` with write token
  - `setup-node@v4` (Node 20, npm cache)
  - `npm install --ignore-scripts` (root deps for axios + sm)
  - Run `durian` mode → `data/durian-variance/durian-latest.json`
  - Run `durian-pastry` mode → `data/durian-variance/durian-pastry-latest.json`
  - `node scripts/durian-variance-summary.js` → `doc/durian-variance-summary.md`
  - `stefanzweifel/git-auto-commit-action@v5` commits the three
    files back to `main` with the commit message
    `'[durian-variance auto-commit] refresh JSON + table (<sha>)'`.

  The `if:` filter on the job uses `[durian-variance
  auto-commit]` as the not-self-trigger marker so the workflow's
  own push doesn't re-fire it.

  When `GOOGLE_MAPS_API_KEY` is missing from repo secrets, the
  workflow fails fast with `::error::GOOGLE_MAPS_API_KEY repo
  secret is missing. Add it under Settings → Secrets → Actions.`

  **One-time operator action** (recorded in workflow header + PR
  body): GitHub → Settings → Secrets and variables → Actions →
  New repository secret →
    `Name: GOOGLE_MAPS_API_KEY`
    `Value: <Railway-stored key>`

  After that the workflow is fully automatic.

  **2. NEW `scripts/durian-variance-summary.js`** — Markdown
     summary generator. Reads both `*-latest.json` files +
     writes `doc/durian-variance-summary.md` with:

     - **Metadata header**: last `ranAtIso`, `scriptVersion`,
       regions covered.

     - **Cross-region rollup table**:
       ```
       | Mode | Region | Places | Kept | Rejected | Precision |
       |---|---|---:|---:|---:|---:|
       | durian | Singapore | 96 | 50 | 46 | 52.1% |
       | durian | Johor Bahru | 96 | 41 | 55 | 42.7% |
       | …
       | **durian** | **ALL** | **384** | **180** | **204** | **46.9%** |
       ```

     - **primaryType frequency tables** (one per mode, top 30
       sorted desc) — shows what Places actually returned, so
       future accept-list tightenings have a data baseline.

     - **Per-query precision tables** (one per mode, every
       lang × seed × region row) — long but copy-pasteable into
       a follow-up investigation.

  **3. `package.json`** — `0.61.258 → 0.61.259`.

  **4. `doc/.serial-state.yml`** — commit 471→472, build 261→262,
     journal 459→460; re-anchored 29-05 '26 16:40 SGT.

  - The workflow runs ~120-160 Places searchText calls per mode
    on every relevant push to main. That's ~$0.40-0.55 USD per
    mode × 2 modes = ~$1 USD per qualifying merge. Path-trigger
    filter keeps it scoped (only changes to `special-mode.js`,
    the two scripts, or the workflow itself qualify).
  - If `GOOGLE_MAPS_API_KEY` isn't added to repo secrets, the
    workflow fails fast at the run step. The earlier checkout +
    setup-node + npm install steps still run (~30 s of CI time).
    Acceptable.
  - The auto-commit pushes back to `main` directly (no PR
    review). The commit message tag `[durian-variance
    auto-commit]` is the marker; if the operator wants to gate
    the auto-commit behind a PR instead, the workflow could be
    extended with `peter-evans/create-pull-request` instead of
    `stefanzweifel/git-auto-commit-action`.
