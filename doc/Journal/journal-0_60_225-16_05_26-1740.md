## New

### [HDR] #193 | 17:40:00 SGT 16-05-26 | v0.60.225 — Harden the TMA `🍲 Try ·` dish extraction + standardise the glyph | 3 files | 1 PR | 1 build |

- **[INTENT]** Operator: the `🍲 Try ·` line on the Cuisine TMA result card must carry a genuine dish/dessert name, never a leaked review fragment; if no real dish can be found, the row hides. Also: standardise the TMA Try glyph to `🍲`.

- **[REVIEW (operator asked to review before building)]** Traced the data path. The Cuisine TMA result card is served by the LLM-free `/api/cuisine/search` path; its `dishes` come from `extractDishes()` (`index.js`), a regex over the venue's last 3 Google reviews. The **Google Places API (New) does not expose menu / popular-dishes data** — the "Popular" tags in the operator's Google Maps screenshot are a consumer-app feature, not an API field. So review text is the only "from Google" dish source available. Operator decision (AskUserQuestion): **harden the regex** (not add an LLM call), and **hide the empty row on the TMA only**.

- **[DELTA]**
  - **`index.js` `extractDishes()`.** Root cause of `Restaurant Fiz and what`: the function used a **local** `TRAILING_STOPWORDS` regex that predated the v0.60.222 interrogative additions, so a candidate ending in `what` passed. Replaced the local length / category / trailing-stop-word checks with the shared `isDishName()` from `dish-name.js` (single source of truth — bounds 3–40 chars, blocks bare category words, rejects trailing-stop-word/interrogative fragments). Removed the now-dead local `TRAILING_STOPWORDS` and `CATEGORY_BLOCK_RX` consts.
  - **`index.js` venue-name guard.** `extractDishes()` now takes a second `venueName` argument; a candidate that contains the venue's own name (or vice-versa) is dropped as a leaked fragment. Mirrors the `formatOrderLine` guard added in v0.60.223. Both call sites updated to pass `v.name`.
  - **`web/cuisine/src/v2/components/ResultCard.jsx`.** The "what to order" line glyph `🍴` → `🍲` (standardised, parity with the bot-side Try lines unified in v0.60.222). The row already hid when `primaryDish` was empty (`{primaryDish && (…)}`) — so once `extractDishes` rejects the garbage, the row self-hides on the TMA exactly as the operator asked.
  - `package.json` `0.60.224 → 0.60.225`; this Journal entry (#193); `doc/.serial-state.yml` (`journal 192→193`, `commit 199→200`, `build 8→9`, `chat_counter 18→19`; re-anchored 17:40 SGT).
