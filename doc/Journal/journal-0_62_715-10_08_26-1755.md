# Journal — v0.62.715 (Cost-audit Phase C: the spend circuit breaker)

_(№ 1,054 — 10-08 '26 17:55 SGT)_

## New

### [HDR] v0.62.715 — daily-spend guard: shed optional enrichment at a hard cap, DM the owner on threshold

- **[INTENT]** Third phase of the operator-approved 4-phase cost-audit plan. Phase A made the spend
  figure trustworthy (0→~35 instrumented call sites); Phase B removed one confirmed redundant call.
  Neither ACTS on the number. The operator's original concern was cost exposure, and their follow-up
  instruction was explicit: *"remember to link to my telegram account via env.var. Start with Phase A."*
  This entry builds the thing that finally acts — a daily-spend circuit breaker that sheds the optional,
  expensive enrichment work when the day gets costly, and DMs the owner via the **existing**
  `TELEGRAM_OWNER_CHAT_ID` (the same env var already gating `/cost`, `/ver`, `/ftlog` and `/hidden` — no
  new configuration was invented for this).

- **[THE DESIGN — THREE LEVELS, ONE HARD RULE]** `spend-guard.js` reads today's combined Gemini + Maps
  USD from Phase A's now-accurate tracker and maps it to a level: `ok` (< soft), `soft` (soft ≤ x <
  hard), `hard` (≥ hard). Defaults $10 / $25, both overridable via `SPEND_SOFT_USD` / `SPEND_HARD_USD`,
  either settable to 0 to disable that level.
  **The hard rule: only OPTIONAL enrichment is ever shed.** The Places search itself, the venue cards,
  and `/cost` always run. At the hard cap the four sheddable steps are: the sanctuary 🌿 read (Anthropic
  Haiku per uncached venue), footfall (BestTime), Gemini batched dish extraction (the regex pass still
  runs, so the `🍲 Try` line usually survives), and `/hidden` (the priciest single command — grounded
  Gemini + up to 5 Places verifier lookups, uncached, with a retry ladder). A user at the hard cap gets
  a thinner card, never a refusal.

- **[TWO DELIBERATELY OPPOSITE FAILURE DIRECTIONS]** These are the decisions most worth stating plainly,
  because they look inconsistent until you name what each protects:
  - `readSpend` **fails OPEN** — if the cost read breaks, level is `ok` and nothing is shed. A monitoring
    outage must not silently degrade the product for every user at once.
  - `shouldAlert` **fails CLOSED** — if the Redis alert-latch write breaks, no alert is sent. A missed
    alert beats an alert loop DMing the operator on every request.
  Both are pinned by name in the test file so a future refactor can't quietly flip either.

- **[MUTATION TESTING FOUND TWO REAL TEST BUGS, NOT JUST CONFIRMING GREEN]** This is the part of the
  entry worth reading. Three mutations were run; the first two exposed defects **in the tests
  themselves**, which is exactly the failure mode this repo's discipline exists to catch:
  1. **Mutation "flip fail-open to fail-closed" did NOT go red.** Investigation: `api-cost.getCostSummary`
     absorbs Redis errors in its own per-date `try/catch` and returns a zeroed summary — so neither
     fail-open test ever reached `readSpend`'s own catch block. The catch was **completely untested** and
     could have been inverted unnoticed. Fixed by adding a case with a hostile client whose `isOpen`
     getter throws, which escapes api-cost's internal guards and genuinely propagates. Re-ran the
     mutation: now red.
  2. **Mutation "remove the unknown-step allow-list guard" did NOT go red.** Investigation: the test set
     `SPEND_HARD_USD=1` but left soft at its default 10 — and `levelFor` deliberately ignores a
     `hard < soft` misconfiguration, so the reading was `soft`, not `hard`. The test was asserting
     "unknown steps aren't shed" against a level that sheds nothing at all: **vacuously passing.** Fixed
     by setting both thresholds, adding an explicit precondition assert that the reading really is
     `hard`, and asserting a known-sheddable step IS shed in the same breath. Re-ran: now red.
  3. Mutation "hard boundary `>=` → `>`" went red first time (the boundary test was sound).
  Both broken tests would have shipped green and provided false assurance on the two properties the
  module most depends on.

- **[DELTA]** (4 files)
  1. `spend-guard.js` (NEW) — `thresholds()`, pure `levelFor()`, `readSpend()` (60 s in-process memo, so
     the Redis SCAN behind `getCostSummary` doesn't run per-request), `allows(step)`, `shouldAlert()`
     (Redis `SET NX EX` latch, once per UTC day per level), `formatAlert()`, `checkAndAlert()`.
     `notify` is injected rather than imported, so the module carries no Telegram dependency and is
     unit-testable in isolation.
  2. `cuisine-enrich.js` — three `allows()` gates in `enrichSlow`: dish extraction (skips the Gemini
     batch, keeps regex + cached hits), sanctuary read, footfall. Each logs when it sheds.
  3. `index.js` — `spendGuardTick()` (fire-and-forget, called AFTER a cuisine search is already served,
     never in front of one) and `hiddenBlockedBySpendGuard()` gating both `/hidden` entry points. The
     `/hidden` gate uses `checkAndAlert` rather than bare `readSpend` so an attempt that finds the day
     already capped also delivers the owner alert.
  4. `__tests__/spend-guard.test.js` (NEW) — 25 tests across thresholds, `levelFor` boundaries and
     misconfiguration, memoisation, shedding, the alert latch's per-day/per-level keying, alert copy,
     and both fail directions.

- **[KNOWN GAPS]**
  - **The cap is a brake, not a financial guarantee.** Spend is read from a ≤60 s in-process memo and
    each process holds its own; concurrent requests can overshoot the cap before any of them observes
    it. Sized for a daily budget, not for a hard billing ceiling.
  - **The USD figure inherits every Phase A caveat** — most notably the Routes `$0.005`/element estimate
    (O-172) and the handful of still-uninstrumented call sites (O-173). Spend the guard can't see can't
    trip it.
  - **Not exercised against real spend data** — no Railway/production access this session, so every
    level transition here was driven by synthetic Redis fixtures. The forced-threshold test plan above
    is the first real check.
  - **Phase D not yet built.**
