## New

### [HDR] #532 | 15:55 SGT 06-06-26 | v0.61.331 — venue-award-schema.v0_1: venue-centric loader (stable `id`, `awards[]`, year views, closed-exclusion, awardsDiff); flat-SG normalisation; empty MY table; gated manifest | 4 files | 1 PR | 1 build |

- **[INTENT]** Move the Michelin layer from a flat one-row-per-award model to a venue-centric model where a single venue owns an `awards[]` history across editions. This is the shape the regional guides need (a KL venue can be one-star in 2025 and two-star in 2026) and it powers a future "new for 2026" UI without a schema rewrite later. The loader must keep the curated SG dataset (130 flat rows) working untouched by NORMALISING it into venues at load, and accept the venue-centric per-country files as-is. `michelin/my.js` adopts the venue shape now but ships EMPTY — the operator fills the curated ~130 MY rows by hand. **No real venue data is fabricated.**

- **[MECHANISM]** The Venue shape is `{ id, city, country, name, formerNames?, address, postal?, cuisine?, vegetarian, halal, status, awards:[{year,category}] }`. `id` is a stable slug `${cc}-${iata}-${kebab(name)}` (cc = lowercased ISO-2; iata = lowercased curated-city code from cities.js; SG has no cities.js row → iata 'sg'). At load the loader: (1) validates each flat SG row against the legacy flat contract, then NORMALISES it to a venue (`flatToVenue`) with a synthesised id and a single-element `awards[]`; (2) normalises each venue-centric country row (`venueToVenue`) and validates it against the venue contract — including that its `city` exists in the curated cities table; (3) MERGES with dup detection keyed on `venue.id` ONLY — a duplicate id THROWS (both names in the message), never a silent skip; (4) runs a per-(country, year) MANIFEST count-check that is GATED on a non-empty table (empty `my.js` skips it, so boot is safe). The loader also derives a back-compat FLAT view (one row per award) so the legacy getters `getAll` / `michelinForCity` / `michelinForCountry` keep their v0.61.330 contract (130 SG rows, each with `category` + `year`). cities.js is an ES module under the iCloud-synced `web/` tree; rather than cross that boundary with a runtime ESM require at boot, the `{ city → IATA }` map for the eight guide countries is embedded in `michelin-data.js`, mirrored verbatim from cities.js v0.61.242.
