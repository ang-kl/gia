- **[INTENT]** Fix three operator-reported map defects: popup body text
  too thin/light to read; the Transport (Train) TMA map freezing on a
  two-level zoom-in; and the Attractions (⚝) overlay showing nothing in
  the three TMA maps.

- **[DELTA]**
  - **Popup legibility — `web/{cuisine,hawker,transport}/.../mapOverlays.js`.**
    The shared `infoCard()` wrapper set no `font-weight`, so every popup
    body line inherited the browser default 400 and rendered as thin
    grey text (washed out in outdoor glare). The wrapper now sets
    `font-weight:500`; `infoPalette().sub` darkened `#5a5a5a → #3c3c40`.
    Every popup across the three TMA maps routes through `infoCard()`
    (the Cuisine venue popup, the station info card `stationInfoCardHtml`,
    the Hawker centre popup, and every overlay popup), so the one change
    lifts them all. Explicit-bold name lines (600/700) are unchanged.
  - **Transport zoom-hang — `web/transport/src/components/MrtMapPanel.jsx`.**
    The `zoom_changed` listener called `renderPins()` synchronously on
    every zoom step — a full ~200-marker `AdvancedMarkerElement`
    teardown + rebuild, a polyline rebuild, and the O(N²) 8-round
    `demoteByOverlap` pass. Zooming a couple of levels quickly stacked
    those rebuilds back-to-back and froze the main thread. The
    re-render is now debounced: a ref-held `setTimeout` (~180 ms,
    `zoomRenderTimerRef`) collapses rapid multi-level zooms into a
    single rebuild after the zoom settles; the live zoom readout
    (`setZoomLevel`) still updates immediately. The timer is cleared on
    each new `zoom_changed` and on component unmount.
  - **Attractions overlay — `web/{cuisine,hawker,transport}/.../mapOverlays.js`.**
    The layer was fully wired (layer def, chip in all three TMAs, data
    from `/api/geo/overlays`) but **radius-clipped to 550 m**
    (`OVERLAY_RADIUS_M`) around the map anchor, exactly like the
    carpark / bus / parks helper layers — so on a normal TMA map almost
    no attractions fell in range, and `frameAttractions()` (v0.61.111)
    filtered its points through the same `inRadius` clip and silently
    returned on the empty set. Fix: the attractions layer is now
    **exempt from the radius clip** in `applyVisibility()` (`near = true`
    when `name === 'attractions'`) — the zoom tier (dot < z12 / glyph /
    label) handles declutter, the same way the train layer shows the
    whole station set; and `frameAttractions()` now frames the **whole**
    attraction set (finite lat/lng only, no `inRadius` filter). Toggling
    ⚝ now populates the map and frames to the attractions — the
    behaviour the operator asked to mirror "View 3 Train Stations".
  - `mapOverlays.js` edited in `web/cuisine` and copied byte-identical
    to the hawker + transport copies.
  - **`package.json`** — `0.61.111 → 0.61.112` (PATCH).
